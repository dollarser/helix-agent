# Helix Acceptance Closeout

Bind the successful build to its source, APK and installed bytes. Record which checks ran on that candidate and which reuse an unchanged baseline. For model-facing behavior, trace the effect through durable state to the next model request; a completed Turn alone cannot establish consumption.

## UI changes

- Copy-only edits: check the affected entry and display states. For changes to the default conversation layout or secondary actions, check a draft, an existing thread and a completed tool-output flow through the product event path. Hand-built rows can test the component alone. Assert placement by component role or tag: secondary details belong behind the menu, and required navigation remains discoverable when empty.
- IO-backed selectors: inspect first open and refresh. Resolve fast local lists before opening; keep the current modal and content on refresh. Distinguish unread, empty, failed and cancelled states, preserve retry, and bound the viewport for long reads. Capture native windows after the enter animation.

Use the [verification matrix](../../../docs/development/verification-matrix.md) for commands and [AGENTS](../../../AGENTS.md#verification-and-device-authorization) for authority and device status. For distribution, follow [release readiness](../../../docs/development/release-readiness.md). Keep stable conclusions in the task record; retire resolved failure attachments under the [evidence policy](../../../docs/evidence/README.md#本地原始输出的保留边界).
