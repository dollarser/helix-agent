Helix FFmpeg Ready -- Android media runtime and reproducible build materials

This archive is not an APK or a standalone Helix Tool or plugin. The ready-av1
payload is integrated into Helix Advanced through the existing PRoot/Job path.
The Android arm64-v8a binaries target API 29. They use Bionic, not Alpine/musl;
do not copy them into a PRoot RootFS and assume an Alpine executable ABI.

Profiles:
  ready: Plus features, animated WebP input, common visual filters and audio inputs.
  ready-av1: the same profile plus dav1d AV1 decoding. No AV1 encoder or AVIF claim.

No font files, network protocols, capture devices, x264/x265 software encoders,
FFmpeg GPL/nonfree/version3 components, or personal media are included.
MediaCodec wrapper presence alone does not establish device capability. The patched
ready-av1 payload has bounded Android validation, including synthetic H.264/HEVC
sync/async encode/decode checks on ONEPLUS_A6013 / API34 / ARM64 / 4KiB pages
and Helix_API_36 / API36. These checks do not certify other OEMs, API29,
16KiB-page physical devices, real-model workflows or real-device performance.
The separately identified macOS companion and earlier Plus emulator results
remain distinct evidence; neither substitutes for the integrated Android checks.

Required sources and hashes are pinned in recipe.json and metadata/input-sources.json.
The prepare command downloads the same upstream releases when needed.
Corresponding-source distribution must include the exact upstream sources,
patches and build/relinking instructions for the packaged binary. No host build directories,
system font files or model credentials are distributed in this runtime bundle.

contract.py is a pure preparation example, not an authorization or sandbox layer.
File references require host scope binding and descriptor-based access. Filters can
open additional local resources (fonts, subtitles, concat manifests); disabling
network support does not provide filesystem isolation.

HDR policy in this candidate classifies metadata and rejects unsupported pixel
operations. No HDR tone mapping, universal Dolby Vision support or color correctness
for arbitrary ICC/gain-map content is claimed. 10-bit alone is not proof of HDR.

MediaCodec async invocation used by the integrated path:
  -ndk_codec 1 -ndk_async 1 -flags -global_header -bsf:v extract_extradata
Each execution must verify codec availability, output streams,
frames, duration and final bytes. Exit code zero alone is not completion.

The packed SHA256 manifest binds the exact files. Host-test metadata binds the exact
host build, recipe and test sources. It never substitutes for Android validation,
16KiB device execution, actual APK size measurement, or real-device performance.

Helix source correction (2026-11-12): mediacodec-no-encoder-flush.patch
removes the FFmpeg MediaCodec global-header dummy-EOS/encoder-flush preflight.
Android documents flush as defined for decoders, not encoders. Both synchronous
and asynchronous encoders now extract codec configuration from real packets.
The patch and exact upstream/patched file hashes are included in recipe.json.
The original upstream archive remains unchanged; build.py verifies it and
creates a separately hash-verified patched source tree. LGPL obligations remain.
