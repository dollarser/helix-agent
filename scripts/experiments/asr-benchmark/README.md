# Mobile ASR comparison

Owner-authorized, opt-in local experiment for ADR-PLATFORM-004. This is not a product model selector or a CI device job. The production model and package versions stay unchanged. Device commands require explicit owner authorization for those devices; this runner does not start an emulator, capture microphone input, upload audio, clear data, or send chat messages.

## Method

The frozen corpus uses the first 20 rows of `google/fleurs`, `cmn_hans_cn`, `test` (CC-BY-4.0), five deterministic nominal 10 dB white-noise derivatives, the public JFK speech excerpt in whisper.cpp, three constructed Chinese→English concatenations, and two synthetic silence probes. The concatenations are not natural code switching; white noise is not a real environment recording. Corpus preparation checks 16 kHz mono and the original FLEURS frame counts. Inputs and actual staged device files must match SHA-256 before tests execute.

`score.py` calculates corpus-micro CER for Chinese, WER for English, MER (Chinese characters + English words/numbers) for constructed mixed clips, and nonempty outputs for silence. It applies Unicode NFKC, case folding and punctuation/whitespace removal; an emitted `<unk>` is one unknown unit. `--simplify` additionally reports OpenCC t2s-normalized scores, retaining strict glyph scores and raw hypotheses. Arabic numerals and written Chinese numbers are not made equivalent. No percentage is a population accuracy estimate or significance claim.

Each clip opens a new recognizer and a fresh stream. Load time therefore measures fresh recognizer initialization with the operating-system file cache left intact, not a forced cold storage read. Models are not kept resident between clips. Sherpa uses CPU/2 threads/greedy decoding; Vosk and Moonshine use SDK defaults where no equivalent supported thread option exists. Whisper uses automatic language detection. Streaming engines consume 100 ms chunks; Moonshine updates every 500 ms. Offline engines decode after the last chunk. The 0.5-second sherpa streaming tail is measured as finalization cost.

The throughput run feeds chunks without waiting. Android `computeMs` sums engine accept/finalize calls and excludes input copying, file reads, PSS queries and sleeping; `elapsedMs` also captures loop overhead. The host measures the processing loop including Python glue and cannot be compared directly as a pure hardware speedup. RTF is total processing time / original audio duration (lower is faster). The paced run uses the first three Chinese clips at real audio cadence and measures first nonempty result separately from model loading. Audio-end-to-final delay is paced elapsed time minus original audio duration, including the final chunk's decoding; raw `finishMs` is only the finalize-call cost, not a button-to-UI latency. PSS is sampled before decoding and after finalization; it is whole-process sampled memory, not a continuous peak or model-only RAM.

Moonshine must use its original SDK ORT in a separate test APK. Loading its JNI against Helix's sherpa ORT failed during preflight; this is not reported as model recognition failure. Its SDK contains unrelated capabilities that are never invoked here and are not adopted into the production APK. Vosk host and Android SDK versions differ and are recorded separately. Whisper is measured through sherpa's exported ONNX Tiny weights, not whisper.cpp; results do not establish a ranking of those inference frameworks.

## Reproduction

Generated weights, PCM, APKs, raw JSONL, log files, locks and device receipts live under ignored `build/asr/benchmark/`. The experiment's asset lock pins actual artifacts. The device runner requires Python 3.11+ and a Unix host (per-device flock). Host Python environments are isolated there; Moonshine requires a Python version supporting `str | Path` despite its older wheel metadata. No system Python files are changed.

1. Obtain the pinned model artifacts and FLEURS test Parquet in `inputs.lock.json`; extract only the runtime files listed there into `models/<id>/`. Run `prepare_corpus.py --from-parquet` with PyArrow to verify the official full-file hash and extract its first 20 audio byte values and metadata. The current run also verifies the initially recovered WAVs byte-for-byte against this full decode.
2. Run `prepare_corpus.py` with NumPy and SoundFile, then the scoring unit tests. Install pinned host dependencies in an isolated environment; run `host.py --model <id>` for sherpa models and `host_extra.py` for Vosk/Moonshine, one process at a time.
3. Create `moonshine-test.aar` from the pinned official SDK AAR excluding only its `libonnxruntime.so` files. This stripped AAR supplies compile-time API classes for non-Moonshine runs, never a Moonshine inference runtime. Preserve attribution in both archives.
4. Build `:app:assembleConsumerDebugAndroidTest` with `-Phelix.asrValidation=true -Phelix.asrBenchmark=true`, copying the result as `benchmark-test.apk`; repeat with `-Phelix.asrBenchmarkMoonRuntime=true` and copy as `moon-benchmark-test.apk`. Install the separately built independent validation main APK first. Normal builds do not include the experiment's code or libraries.
5. Explicitly run `device.py --serial <authorized-id> --models <ids> --stage`; run again with `--paced --limit 3`. `device.py` requires a successful JUnit outcome and preserves failed/partial results as failures. Use `score.py` on the successful result files with `--simplify`.

The completion evidence records actual commands, exact candidate APK/model/corpus receipts, hardware, outcomes, results and remaining boundaries. GB-scale generative models and TTS are outside this ASR measurement round; they were already excluded from the phone-default shortlist.
