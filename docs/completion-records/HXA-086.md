## 目标与任务书

任务书（`docs/development/roadmap.md` §12 `### HXA-086`）：arm64 分别在 4 KiB/16 KiB 页真机执行 python/node/git/ripgrep；Runtime 不能读主 App dataDir、共享存储或联网。增加从未打开的 Runtime 冷绑定、空闲回收再启动、后台/锁屏/Doze/低内存、强制停止、主 App/Runtime 分阶段 kill、同 jobId 不重复执行、通知停止和可选 wake lock 泄漏测试。任一 ELF、生命周期或 smoke 不兼容时阻断对该设备分发并记录最低设备集。

前置：HXA-080～085（lock/安装/IPC/runner/`code.linux.run` 全链已设备验证）；[ADR-0007](../adr/0007-companion-runtime-lifecycle.md)（已接受：冷绑定、Binder 丢失按 job id 对账绝不重放、零常驻）。**无新 ADR**——本任务是 083/084/085 已验证机制的设备矩阵扩展 + 通知停止面（决策记录见下）。

## 交付

1. **通知停止（companion，新增 `ProotJobNotification` + `ProotJobStopReceiver`）**：
   - Job RUNNING 时 companion 发**普通通知**（channel `proot-jobs`，`IMPORTANCE_LOW`，tag `proot-job-<jobId>`，通知 id 由 jobId 派生）——**不是 FGS**：084/085 不变量「job 路径零 FGS 零 wake lock」不被破坏，"任意计算不得冒充 dataSync"。`POST_NOTIFICATIONS` 未授予（API 33+）时 `SecurityException` 被捕获——Job 不受影响，只是没有可停通知。
   - 通知 STOP 按钮 → 广播 → `ProotJobStopReceiver`（manifest 导出 + `android:permission="com.helix.permission.BIND_PROOT_RUNTIME"` 签名权限保护——只有同签名主 App/测试包可触发）→ 校验 `jobId` 形状（`job_` + 12 hex）→ `ProotJobRunner.get().cancel(jobId)`。四个终态帮助方法（SUCCEEDED/FAILED/TIMEOUT/取消）统一撤通知。
   - 测试：`ProotJobNotificationDeviceTest`（3 例）——运行中 Job 有可停通知且 **STOP 动作真实取消 Job**（进程内直调 receiver seam，见决策记录 3）、自然结束无残留通知、receiver 结构性断言（导出 + 签名权限 + POST_NOTIFICATIONS 声明，查询 companion 自身包名而非 `.test` 包名）。
2. **smoke 套件（companion，新增 `ProotSmokeDeviceTest`，4 例）**：python3/node/git/ripgrep 各一条真实 Job（`/data/…/proot/bin` 下真实 ELF，081 锁定的 Alpine 3.22.5 资产）。**新鲜度契约（anti-stale）**：每条测试回显本次运行随机 token（python 经 guest env `SMOKE_TOKEN`，node/git/rg 经 sh 拼接），断言 stdout 含 token——陈旧/缓存执行不可能通过；host 侧另写 `smoke-ran-<jobId>` 标记文件并在 @After 删除。
3. **隔离套件（companion 侧，新增 `ProotIsolationDeviceTest`，4 例）**：guest 内 python 断言**读不到 companion 自身 dataDir 标记文件**、**摸不到共享存储**、**不可联网**（可达即 `sys.exit(99)` → 期望 SUCCEEDED + 无网络标记）；结构性断言 companion 包**不声明 INTERNET/存储权限**（`GET_PERMISSIONS` 标志查询，查询对象是 companion 包名——平台事实：modern API 上无标志时 `requestedPermissions` 为 null）。
4. **隔离 E2E（主 App 侧，新增 `ProotRuntimeIsolationE2eDeviceTest`，2 例）**：走 085 真实 `code.linux.run` 全链（`ProductionLinuxExecutor` + 真实 gate READY），guest 内 `cat`/`touch` 主 App filesDir 标记文件——**读：READ-FAILED + 内容断言缺失；写：WRITE-FAILED + 文件断言不存在**。真实 Journal 记录佐证（每例有 SUCCEEDED job 记录）。
5. **生命周期 E2E（主 App 侧，新增 `ProotLifecycleE2eDeviceTest`，6 例，脚本分阶段驱动）**：
   - 强制停止 companion → 真实 gate（与 085 同逻辑：`checkLocalState` + `anchorPresent`）→ `Failed`，detail 含 "unavailable" + "force-stopped"（双分支：若未处于停止态则走 SUCCEEDED 分支）；
   - 从未打开的冷绑定（force-stop 后首个 Job 经修复 Activity 冷绑）/ 空闲回收再启动（host `pkill` 后 kill 60 s 再 Job）/ 锁屏（keyevent 26）/ 低内存（`am kill` 主 App）——四个变体各跑真实 Job → SUCCEEDED；
   - 主 App 死亡中途（instrumentation 结束 force-stop 主 App → unbind → Job 变 ORPHANED）→ 按 job id 查询对账 → **ORPHANED，exitCode null，绝不重放**；
   - companion 被 host `pkill -9` 中途 → 客户端稳定结算：**`Unavailable(DEAD_OBJECT)`（持有事务的 binder 死亡）或 `Terminal(ORPHANED)`（下次轮询冷重绑 + 清扫对账——083 设计的恢复路径），二者皆稳定非成功，绝不崩溃绝不静默成功**（决策记录 4）；
   - 长 Job 期间采样 `dumpsys power` 8 次 → **companion uid 无 wake lock、无 FGS**。
6. **验收脚本 `scripts/accept-hxa-086-lifecycle.sh`**（新增）：构建安装 4 个 APK → 11 阶段（强制停止拒绝 → 冷绑定 → 空闲回收 → 锁屏 → 低内存 → 主 App 死亡 ORPHANED → companion 死亡对账 → wake lock 采样 → 同 jobId 不重复执行（`ProotJobRunnerDeviceTest#aJobIsStartedExactlyOnce`）→ companion smoke/隔离/通知三套件 → 主 App 侧隔离 E2E 整类）。脚本用 `run-as` 读 host 可读的 `LIFECYCLE-JOB-ID` 文件传递 job id（本平台上测试进程 stdout 不跨 raw instrument 流——host 标记必须走文件，设备实证）。

## 决策记录：

1. **通知停止用普通通知，不用 FGS**：任务书要「通知停止」，084/085 已设备验证「job 路径零 FGS 零 wake lock」。普通通知在 companion 进程活着时可见可点（job RUNNING 时 companion 必然活着），STOP 走签名权限广播——满足任务书且不破坏不变量。
2. **STOP receiver 导出但锁签名权限**：PendingIntent 广播目标必须可在 manifest 解析；`com.helix.permission.BIND_PROOT_RUNTIME`（083 已定义的签名权限）保证只有同签名方（主 App/其测试包）能发——任意第三方 App 无法伪造停止。
3. **停止测试走进程内 receiver seam**：真实 `sendBroadcast` 从 `.test` 进程会拉起 **companion app 进程**，其 `ProotJobRunner` 单例与测试进程的不同 → cancel 落空（Job 30 s 不终态）。生产上主 App 与 companion 各自是单进程、receiver 在 companion 进程内执行——所以测试在测试进程内直调 `ProotJobStopReceiver().onReceive(...)`（receiver 逻辑真实执行），广播送达性（签名权限导出 + 平台投递）用结构性 manifest 断言覆盖。框架投递是平台保证，不是我们的代码。
4. **companion 中途被杀的客户端结算接受双分支**：设备实证客户端轮询会**冷重绑**（083 设计的恢复路径：`checkLocalState` 非强制停止 → 重新 bind → 新进程清扫 ORPHANED），于是 `awaitTerminal` 可能返回 `Terminal(ORPHANED)` 而非 `Unavailable(DEAD_OBJECT)`。两者都是稳定、非成功、按 job id 对账的结果（ADR-0007：绝不崩溃、绝不静默成功、绝不重放）——测试断言二者的并集，KDoc 写明双分支语义。
5. **smoke 新鲜度契约**：每条 smoke 回显随机 token + host 标记文件 + Journal 记录三证，防止「测试秒过但没真跑」的假绿（本轮曾出现 1.3 s 秒过疑云，实证为真实执行 + 标记文件落在主 App filesDir 的平台事实）。
6. **最低设备集的阻断落点**：分发阻断不靠本任务新代码——081 全量 ELF `PT_LOAD` 对齐门禁（360/360 ≥ 16 KiB）+ 082 installer 按设备页大小做 ELF 对齐预检（不兼容页大小拒绝安装）+ 084 激活前 ELF 预检，三者已结构上实现「ELF 不兼容 → 阻断安装/激活」。smoke 不兼容（安装成功但工具跑不起来）的运行时阻断面 = 本任务 smoke 套件 + 085 gate（验证失败 → 非 READY → 工具不进表）。**最低设备集（真机证据）见下条缺口**。

## 真机缺口（无真机，如实停下）

- **4 KiB / 16 KiB 页真机 smoke**：两台 sanctioned 模拟器均为 arm64-v8a 4 KiB 页。4 KiB 真机的 python/node/git/ripgrep smoke 与 16 KiB 页真机的同套 smoke 均未在真机执行。结构性覆盖：081 的 360/360 ELF 对齐门禁含 ≥16384 断言（16 KiB 页的 `PT_LOAD` 对齐需求已被静态验证），082 installer 的按页大小预检会在 16 KiB 设备上对未对齐 ELF 拒绝安装——但「16 KiB 真机上跑通 smoke」仍需真机证据。
- **Doze / 安全锁屏 / 热限**：emulator-5554 无 `device_idle` 服务（Doze 不可达）、无安全锁屏（`input keyevent 26` 只能做无安全锁屏的屏幕熄灭）。普通锁屏（无 PIN）与低内存（`am kill`）已覆盖。Doze 下的行为（Job 是否继续、通知是否保留）与热降频下的 deadline 行为归真机验证。
- **最低设备集记录**：当前可记录的最低设备集 = arm64-v8a、页大小下 ELF 对齐门禁通过（模拟器 4 KiB 实证；16 KiB 静态实证）、Alpine 3.22.5 资产可安装可运行。真机（至少一台 4 KiB、一台 16 KiB arm64）的 smoke/生命周期证据取得后更新本节。
- 以上缺口的补齐不阻塞 087/088 的开发（它们不消费本任务的运行时证据），但 **086 的全量验收（含真机）在取得真机前保持「模拟器范围完成」状态**。
