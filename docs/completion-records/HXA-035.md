- 实现的契约（逐条对照任务书）：
  - **validate**：注册契约解析（未注册工具/版本 → `UNKNOWN_TOOL` 稳定拒绝，不抛裸异常）→ 实现解析（`NO_IMPLEMENTATION`）→ 参数对照注册 inputSchema（**全部违规一次上报**，fail closed，停在 capability 之前）。
  - **capability**：`CapabilityCenter.evaluate` 实时检查 descriptor 的 `requiredCapabilities`；缺失项进入 PolicyInput.missingCapabilities → 策略默认拒绝（`missingCapabilityIsAPolicyDenial`）；已授予不阻挡（`grantedCapabilityDoesNotBlockPolicy`）。
  - **policy**：HXA-033 `PolicyEngine.evaluate`，输入为可信事实集（`buildInput` 全部取自 request 的 PolicyInput 契约字段 + descriptor 的 baseRisk/operationClass/source，**不含任何工具自报字段**）；`ruleProvider` 注入 `HighSensitivityRule` 集（ADR-0005 出网门控规则在此进入管线）。
  - **approval**：仅 `RequiresApproval` 触发；binding 从**注册表契约事实**（descriptor 的 name/version/schemaHash）+ 可信 request 事实组装，`argsHash = SHA-256(CanonicalArgs.canonicalize(args))`（唯一编码器）；无 scope 调用绑 `"unscoped"` 规范 scopeRef（哈希永不为空）；先查同 Turn 拒绝集（见下），再经 `ApprovalBroker.acquire` 拿**类型化 Proof**——`Denied` 记入拒绝集，`Rejected(code)` 映射 5 个稳定码，`Approved` 才继续。
  - **timeout/cancel**：deadline = 执行开始时刻 + descriptor.timeout（硬超时时间戳交给执行器）；启动前取消 → `Cancelled`（**零副作用、不消费 proof、不执行**）；启动后取消/超时 → 稳定 `ExecutionFailed`（`CANCELLED_AFTER_START`/`TIMEOUT`，副作用状态未知按失败处理）。
  - **execute**：proof 在**执行开始瞬间**消费（`approvals.consume` 紧跟 `executionStartedAt`）——授权在效果开始时刻即花费：启动前取消永不花费；启动后失败/超时 proof 已花费，重试必须重新审批。
  - **bound result / verify**：输出先过**注册 outputSchema**（违反 → `INVALID_OUTPUT`，该工具输出永不到达模型）→ `CanonicalArgs` 规范化 → **全量输出** SHA-256 → 按 UTF-8 字节精确截断到 `maxOutputBytes`（截断时保留全量哈希，证明“是哪个输出”）。
  - **audit**：每次 dispatch **恰一个** `DispatchAuditEvent`（`finish` 是审计唯一发射点）；只有哈希（bindingHash/actionFingerprint/outputHash）与阶段时间戳、无正文；`AuditSink` 抛出异常向上传播（`aFailingAuditSinkPropagatesInsteadOfReportingSuccess`）——不可审计的 dispatch 不是成功 dispatch。
  - **同 Turn 拒绝不变式**：用户拒绝后，同 Turn 内相同高风险动作直接 `SAME_TURN_DENIED`（**不重复请求**，测试断言 broker.acquire 总调用仍为 1、执行 0 次）；参数或作用域**实质变化**改变指纹 → 允许生成新审批（两个专门测试）；新 Turn 可再问；`endTurn` 清空；拒绝集按 turnId LRU 有界（128）。
  - **先用 `time.now` 和 fake mutating tool 验证**：`time.now` 端到端走通 L0 无审批路径（`timeNowRunsTheNoApprovalPathEndToEnd`）；测试内 fake L2 `LOCAL_MUTATION` 工具（`descriptor()` + `CaptureExecutor`）覆盖审批/拒绝/消费/超时/取消/失败路径。
- 关键实现决策：
  - **action fingerprint = 绑定哈希的“实例盲”投影**：指纹 = 把 `toolCallId` 与 `uiToken` 替换为 `"action"` 哨兵后的 canonical JSON SHA-256。审批 **Proof 仍绑定精确调用**（9 字段哈希含两者）；只有“这是不是用户刚拒绝的同一个动作”的判断实例盲——否则模型换一个 toolCallId 就能绕过拒绝不变式，而真正的 UI 卡片 token 差异也不该让同一动作重弹。参数/作用域/target/session 任一变化都改变指纹。
  - **`ApprovalBroker` 只做端口**：dispatcher 保持 proof 无关（不 import storage/Room/UI）；生产 `StorageApprovalBroker`（复用 HXA-034 `ApprovalRepository.mint/consume` 的 4 条件 SQL 守卫与 24h 上限）和审批卡 UI 在 HXA-036 一并落地，与本 matrix 行（纯 JVM `:tools:framework:test`）一致。
  - **proof 在“执行开始”而非“审批通过”时消费**：启动前取消零消费（授权未用即退还）；启动后一切非成功终态 proof 已花费——“批准已被动用过一次”是保守且可审计的语义，重试必须重新审批。
  - **binding 只用注册表契约事实**：name/version/schemaHash 取自 registry 解析出的 `ToolDescriptor`，request 里不存在这些字段——调用方无法自报契约绕过哈希。
  - **单入口、段函数单返回**：`dispatch` 是唯一 public 管线入口；每段 ≤2 个 return（detekt `ReturnCount` 阈值 2 的约束下用 `when` 表达式 + `finishStop` 收敛），段间状态走每 dispatch 一个的私有 `DispatchContext`（含 `stopped` 记录，`descriptor`/`executor` 由 validate 段写入）。
  - **`orNull` 只吞注册表的 `IllegalArgumentException`**：两个注册表对未注册 (name,version) 抛同一信号；吞该类型（且不带文本）映射到稳定拒绝码是 validate 段的职责，任何其他异常原样传播（targeted `@Suppress("SwallowedException")` + 注释，AGENTS.md 禁止 catch-all 成功——这里没有 catch-all）。
- 未实现/排除：审批 UI/审批卡与审计日志页（HXA-036，`uiToken` 的生成方在 UI 层）；生产 `StorageApprovalBroker`（HXA-036，复用 HXA-034 存储守卫）；存储落库的 `AuditSink` 与审计页过滤（HXA-036）；app/agent 层接线（dispatcher 目前是框架库 + 端口，agent loop 接入在 HXA-036/037）；Tool Scheduler/并发/排他屏障/receipt（HXA-037）；executor 内部的真实超时实现由具体工具提供（本任务传递 deadline 契约）；无新 ADR（管线顺序与单入口是 doc 02 §5.3/§7.1 与 doc 11 采纳矩阵的落位；同 Turn 拒绝不变式是 doc 07 §7.3“拒绝后同动作不重复弹卡”的 dispatcher 侧执行，UI 侧在 HXA-036）。
