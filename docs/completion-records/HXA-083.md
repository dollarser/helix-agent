## 决策记录：IPC 与生命周期实现决定（无新 ADR；本任务落实已接受的 ADR-0007）

- **共享 `:runtime:proot-ipc` 模块**（而非 client/app 各自重复）：协议常量、codec、结果类型两端单一来源，防止描述符漂移；模块无 UI/框架依赖，符合"core 模块不依赖 Android UI"。
- **状态字节协议、零跨 APK 异常**（见交付 2；API 34 `readException` 语义变化是硬理由，quickjs 是 house 先例）。
- **manifest 一律 FQN 组件名**（AGP namespace 与包名分离后相对名解析陷阱，本任务实测 `am start -n pkg/.MainActivity` 类失败教训）。
- **调用方复验必须在 binder 的 `onTransact` 做，`onBind` 里做不了**（初版实现的 bug，已修复；初版曾误信 lint 提示的"onBind 携带调用方身份"并在本记录中错误宣称"设备实测携带新客户端调用身份"——**撤销该结论**）：`onBind` 是主线程消息循环派发的生命周期回调，不是入站 binder 事务，`Binder.getCallingUid()` 在无事务时返回**本进程自身 uid**（API 29 探针实测 `callingUid == 自身 uid`，跨包 bind 场景下 verify 恒 false → `onBind` 返回 null）。AOSP 源码佐证（android-10.0.0_r31 = API 29 `ActivityThread.java`）：全文无一处 `setCallingIdentity`，`scheduleBindService` 只往主 looper 投递 `H.BIND_SERVICE` 消息，框架没有任何机制把客户端身份带进 `onBind`。修复：`onBind` 无条件返回 binder；`ProotRuntimeServiceBinder` 增加 `callerVerifier: (Int) -> Boolean` 注入（service 传入 `ProotCallerVerifier.verify` 闭包，沿用 `manifestProvider` 注入模式），**每个事务**先校验（含 `TX_DEBUG_SELF_KILL`——仅通过校验的调用方可触发杀进程）、失败回稳定状态字节 `REPLY_CALLER_MISMATCH`（客户端映射 `SIGNATURE_MISMATCH`），绝不跨 APK 抛异常。签名 permission 仍是第一道门。
- **`PackageInfoFlags` 守卫是 API 33 不是 API 30**（初版写成 30，被 lint NewApi 捕获——API 30/31/32 真机将 `NoSuchMethodError`；client 与 app 两处同修）。
- **companion manifest 必须有 `<queries>` 声明两个主 App 包**（初版遗漏，修复期发现）：API 30+ 包可见性过滤会屏蔽"companion → 主 App"方向的 `getPackageInfo(GET_SIGNING_CERTIFICATES)`/`getPackagesForUid` 查询，事务侧复验将 fail-closed 拒绝一切合法调用方（本项目自己的 API 36 会话日志已出现 `AppsFilter:com.helix.runtime.proot -> com.helix.agent.developer BLOCKED`）；加上 `<queries>` 后 API 36 跨包复验通过（设备实证）。
- **客户端 ServiceConnection 必须覆写 `onNullBinding`**（初版遗漏，修复期发现）：服务 `onBind` 返回 null 时平台（至少 API 29 起）会回调 `onNullBinding` 而非 `onServiceConnected`，默认实现是 no-op——latch 永不释放，20 s 后误报 `HANDSHAKE_TIMEOUT`（把"拒绝"错报成"超时"）。覆写后立即 countDown → 稳定 `BIND_REFUSED`。同补 `onBindingDied`（API 35+ 的 `ComponentName` 形式；旧平台不回调，连接前死亡退化为 deadline 超时——仍是稳定诚实状态）。
- **死亡事务可能从客户端 `transact` 本身抛 `DeadObjectException`**（修复期设备实测发现：服务端自杀先于回复投递时，阻塞中的 `transact` 直接抛异常）：测试与调用方都要把"自杀事务抛 DeadObjectException"当作预期信号捕获，而不是让异常泄漏。
- **`INSTALL_PAGE_SIZE_BYTES = 4096`**：修复 Activity 的页大小 seam；084 以 native `getpagesize` 接管真机 16 KiB 判定（当前资产已在构建期门控 16 KiB 对齐，4096 预检是保守下界，安全）。
- **E2E 的 `EXPECTED_LOCK_SHA256` 与 082 canonical 指纹常量耦合**：跨 APK 断言"companion 报告的锁指纹 == 主 App 编译期已知值"——两个独立编译单元对同一资产真相互证。
- **AndroidJUnitRunner 线程模型**（设备期实测固化，写入测试 KDoc）：`am instrument` 下测试方法跑在 `Instr:` 线程而非主线程，主 looper 自由派发 → 简单 worker 线程 + `future.get(timeout)` 等待即安全；绝不可在主线程 `future.get()`（死锁）。
- **编排脚本而非 gradle connected 驱动阶段测试**：强制停止/卸载/宿主 pidof 观测是 App 进程无法自建的状态；脚本按 environment.md 约定方法级驱动，且对 `am instrument` 原始输出格式（`OK (1 test)`/`FAILURES!!!`/`Skipped: N`）解析——gradle 格式化文本不可依赖。
- **新鲜 `adb install` 后包处于 force-stopped 态**（平台行为，两台实测）：脚本以 `su 0 am start` 修复 Activity 代用户点击完成预热（shell 直接 start 会被 signature permission 拒；root 替代用户点击是 harness 手段）。

## 跨 APK 绑定根因与更正（初稿"平台阻塞"误诊，撤销）

初稿曾把 4 个跨 APK 绑定 E2E 方法的失败定性为"模拟器镜像 system_server 投递缺陷"。**该定性错误，现撤销**。根因是两层实现 bug + 一个 manifest 缺口（修复交接 `HXA-083-fix-handoff.md` 的探针实验 + AOSP 源码实证）：

1. **`onBind` 不携带调用方身份（主根因）**。`onBind` 是主线程消息循环派发的生命周期回调，不是入站 binder 事务；`Binder.getCallingUid()` 在无事务时返回**本进程自身 uid**。API 29 设备 `onBind` 探针日志（跨包 bind 时）：`callingUid=10520（companion 自身）myUid=10520 pkgsForCaller=[com.helix.runtime.proot] verify=false` → `onBind` 返回 **null** → 初版客户端 `ServiceConnection` **未覆写 `onNullBinding`**（默认 no-op，latch 永不释放）→ 20 s 后误报 `HANDSHAKE_TIMEOUT`。AOSP 佐证（android-10.0.0_r31 = API 29 `ActivityThread.java`）：全文无 `setCallingIdentity`；`handleBindService` 对 `onBind` 返回值**无条件** `publishService`（null 也发）——故 dumpsys `IntentBindRecord.binder=null` 记录的是"onBind 返回 null"，初稿误读为"服务未投递"。初稿证据链在此解释下全部自洽（进程 ANR trace 健康 = 返回 null 后回到 idle；其他绑定方向正常 = 其 `onBind` 无 verify→null 逻辑；初稿"设备实测 onBind 携带新客户端调用身份"的结论即 self-uid 观察本身，一并撤销）。
2. **companion manifest 缺 `<queries>`（第二层，API 30+ 包可见性）**。即使把复验移入 `onTransact`（那里才是真正携带客户端身份的入站事务），companion 侧查主 App 签名仍被 AppsFilter 屏蔽（本项目 API 36 会话日志实证 `AppsFilter:com.helix.runtime.proot -> com.helix.agent.developer BLOCKED`）→ 合法调用方恒被 fail-closed 拒绝。已加 `<queries>` 双主 App 包。
3. **客户端缺 `onNullBinding` 覆写（第三层）**。任何服务侧 null binder（拒绝）都会退化成假超时。已覆写（`onBindingDied` 同补，API 35+ `ComponentName` 形式）。
