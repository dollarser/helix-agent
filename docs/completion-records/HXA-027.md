- 实现的契约：
  - “局域网 HTTP 必须按 host:port 单独开启”（roadmap 明文 + doc 10 §2.5）：`CleartextAuthorization` 是 host+port 精确绑定的 app 层门控（7 个 JVM 测试），developer variant 的 transport 层 NSEC 提供可达性（静态 NSEC 无法表达用户输入的 LAN host——这是 transport 放行的唯一原因，真实授权边界在 app 层 + HXA-028 的 UI 风险展示/按次绑定）；consumer variant 零变化（显式 `usesCleartextTraffic="false"`、无 NSEC）；TLS 失败永不静默降级 http（HXA-025 流契约：transport 失败映射终端 `Error` 事件）。
  - “Ollama 验证文本流和 ToolCall”：设备 smoke 三测对**运行中的 Ollama**（0.33.0 + `qwen2.5:3b-instruct`）全过，证据见“手工验证设备”；过程中发现并修复两个真实缺陷（SafeCollector 跨上下文发射、Ollama arguments 形态丢失）——这正是真机 smoke 相对 JVM fixture 的价值。
  - “明确记录不支持字段”：smoke 测试 `recordsServerCapabilitiesAndUnsupportedFields` 记录——Ollama OpenAI 兼容 `/v1` 不提供 OpenAI Responses 的状态化字段（`previous_response_id` 等）；该服务协议固定 `OPENAI_CHAT_COMPLETIONS`，无 fallback（协议岛纪律，doc 10 §2.1）；能力快照以 `CapabilitySource.MANUAL` 构造（smoke 环境不做四阶段探测的持久化存储——存储接线归 HXA-028）。另记录 Ollama 的**流形态差异**（非“不支持字段”，是兼容实现）：工具调用完整 arguments 与 start 同 chunk 下发，解码器已按该形态发射（JVM 回归测试固定）。
  - “SGLang 验证文本流和 ToolCall”：**未完成——有证据的阻塞**（排障 1）：本开发机（Apple M5 Pro Mac）无法安装可运行的 SGLang（CUDA 运行时栈），已如实记录、未伪造成功；Ollama 半完整交付。
- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  1. **transport 放行与 app 层授权分离**：developer NSEC 的 `cleartextTrafficPermitted="true"` 是 transport 级权限（静态 NSEC 表达不了用户输入的 LAN host）；授权边界是 `CleartextAuthorization`（host+port 精确绑定），HXA-028 在其上加 UI 风险展示与按次绑定。lint 的 `InsecureBaseConfiguration` 用元素级 `tools:ignore` + 注释豁免（该风险是 doc 10 §2.5 明文要求的能力，非疏漏）。
  2. **NSEC 优先于 `usesCleartextTraffic` 属性（API 36 实测）**：smoke 在“属性存在 + NSEC”与“属性移除 + NSEC”两种配置下均通过 → 保留 main manifest 的显式 `usesCleartextTraffic="false"`（consumer 严格性显式化），developer 由 NSEC 放行。此前 EPERM 的真实根因是缺 `INTERNET` 权限（排障 4），非属性覆盖。
  3. **`INTERNET` 进 main manifest**：provider 连通性（provider doc §2）两 variant 都需要；app 在 HXA-027 前无任何网络代码，此前清单无此权限。普通权限，非危险权限。
  4. **`okhttp → okhttp-jvm` 替换（仅 app 模块 classpath）**：OkHttp 5 平台选择器对 Android 消费者解析 `okhttp-android`，其 manifest 要求 compileSdk ≥ 37，而本项目钉在 36（M0 基线，不升级平台）；`okhttp-jvm` 是同一库的纯 JVM 字节码构件（无 Android 特有部件），版本沿用 catalog pin（`libs.versions.okhttp`）不硬编码。provider:api 自身不受影响（JVM 消费者原生解析 okhttp-jvm）。HXA-028 生产接线复用同一替换面。
  5. **流运行在 `Dispatchers.IO`（`flowOn`）**：wire 读是阻塞的，发射必须发生在 IO dispatcher；收集方在自己的上下文收事件（flow 机制桥接）。`forEachChunk` 契约随之明确为调用线程阻塞读——callback 是 provider 向事件流发射的位置，dispatcher 跳转会破坏 SafeCollector 跨上下文检查。
  6. **smoke 是 assume 守卫的**：无本地服务 → SKIPPED（带原因），CI 无 Ollama 也绿；有服务则必须全过（不降级为 warning）。证据走 `Log.d("HelixSmoke")`（无网络内容的 tag 级日志，不违反零 secret/零正文日志纪律）。
  7. **provider 依赖仅测试作用域**（`androidTestImplementation`）：生产装配（SecretStore→`CredentialLookup`、模板→`ProviderConfig`、provider UI、EgressSummary）整体归 HXA-028，本任务不提前。

- 排障记录（真实证据，供后续参考）：
  1. **SGLang 安装不可行（阻塞证据）**：`python3 -m venv` + `pip install --dry-run sglang`（Python 3.13.13，macOS arm64）在构建依赖 `flashinfer_python` 即失败（build dependency 构建错误）；SGLang 运行时栈（sgl-kernel/flashinfer）面向 CUDA，本机（Apple M5 Pro，无 CUDA）无可用安装路径。按“不伪造成功”纪律记录为待环境项，不降级为“部分通过”。
  2. **AGP 9 变体特定 androidTest 配置不可在脚本期扩展**：`developerAndroidTestImplementation` 不存在；实际名 `developerDebugAndroidTestImplementation` 且仅在变体实现后（afterEvaluate）存在——从 afterEvaluate `dependencies.add` 触发 config-cache 序列化失败（`DefaultConfigurableFileCollection` 写缓存错误，表象像时序问题，根因见 3）。解法：标准共享 `androidTestImplementation`（对所有 androidTest 变体生效，测试作用域足够）。
  3. **依赖验证 fail-closed 的连锁表象**：`okhttp-android-5.5.0.module`（Android 变体）未注册 sha256 → `:app:packageDeveloperDebugAndroidTestResources` 依赖解析失败 → config-cache store 写入失败。解法：对 `consumer/developer × Compile/Runtime` 四个 androidTest 配置跑 `--write-locks --write-verification-metadata sha256`（release androidTest 配置不存在，AGP 只为 debug 变体建 androidTest——“not found”为预期）；随后引入 okhttp-jvm 替换（决策 4）并重写锁定，移除不再解析的 `okhttp-android` 元数据组件（fail-closed 设计下移除安全：任何意外解析该构件会直接报错而非静默通过）。
  4. **设备 EPERM 的归因纠偏**：smoke 首跑全 SKIPPED，`HelixSmoke` 日志 `SocketException: socket failed: EPERM`；TCP 层（设备侧 `nc -z 10.0.2.2 11434`）通 → 怀疑 NSEC 未生效/被 `usesCleartextTraffic="false"` 覆盖，移除属性复跑仍 EPERM；真正根因是 **main manifest 缺 `INTERNET` 权限**（app 此前无网络代码）——加权限后通过。属性移除实验被权限缺失混淆；最终补做“属性恢复 + NSEC + 权限”决定性对照：smoke 全过 → NSEC 在 API 36 优先于该属性，属性保留（决策 2）。
  5. **SafeCollector 跨上下文发射（真机 smoke 发现的真实契约 bug）**：`flow { … }` 在阻塞上下文（`runBlocking`，smoke 测试线程）收集，而 `OkHttpWireClient.forEachChunk` 内 `withContext(Dispatchers.IO)` 使发射发生在 IO 子上下文 → `IllegalStateException: Flow invariant is violated`（JVM fixture 未暴露：FakeWire 同步回调无 dispatcher 跳转；加 `flowOn(Dispatchers.IO)` 后仍未解——同 dispatcher 的 `withContext` 走 undispatched 子协程，SafeCollector 仍拒）。终解：provider 流 `flowOn(Dispatchers.IO)` + `forEachChunk` 去 dispatcher 跳转（调用线程阻塞读，调用方契约进 `WireBody` KDoc）。
  6. **Ollama 工具 arguments 形态**：原始流（curl 实抓 3 chunk）显示完整 `function.arguments`（`{"text":"probe"}`）与 id/name 同 chunk 下发，而 OpenAI 形态是增量分片——HXA-023 解码器只处理增量形态，start 片段的 arguments 被静默丢弃（设备侧首跑 `args=` 空）。修复：start 片段同样经 `emitArguments` 发射 + 用捕获的原样流做 JVM 回归测试；修复后设备侧 `args={"text":"probe"}`。
  7. **AGP 9 androidTest 源集命名**：flavor 大写化——`app/src/androidTestDeveloper/`（`developerAndroidTest` 不被识别，smoke 不编译）。
  8. **`InsecureBaseConfiguration` lint 错误**（app lint `abortOnError`+`warningsAsErrors`）对**有意**的 cleartext NSEC 报 error → 元素级 `tools:ignore` + 注释说明风险接受理由（决策 1），非模块级 lint.xml 放宽（避免掩盖 consumer 侧同类问题）。
  9. **detekt 圈复杂度**：start 片段 arguments 处理使 `handleToolCallFragment` 复杂度 15>14 → 提取 `emitArguments` helper 回落到 ≤14（两处调用点语义不变）。
- 决策记录：不适用（本任务未新增 ADR）。形态选择（NSEC transport 放行 + app 层 `CleartextAuthorization` 边界分离、okhttp-jvm 替换、`flowOn(IO)` 流语义、smoke assume 守卫、依赖仅测试作用域）均为 doc 10 §2.1/§2.5 与 ADR-0006（developer 即直接分发主 app）明文纪律下的可逆实现落位，无 ADR 触发条件。proposed ADR-0008/0009 不受影响。
