- 实现的契约：
  - 契约解释（已记录）：架构文档 §5.2 的 Turn 状态图未画出 §5.3 串行多调用规则所需的边。Provider 协议要求同一响应的每个工具调用在下次模型调用前必须拿到结果，因此一个响应含 N>1 个调用时，记录完第 i 个结果后必须直接进入第 i+1 个调用（而非回到 BUILDING_CONTEXT）；预算检查发生在每次提交模型调用之前，因此 BUILDING_CONTEXT 也必须能进入 FAILED。这三条边对 core:model 的 `TurnState` 是**严格增量**修改（不改任何既有边），`StateMachinesTest` 全矩阵守卫；若评审不认可该解释，这 3 条边及本模块相应测试是替换点。
  - §5.2/§5.3：完成（FinalText 保留 provider finish reason；`null` 保持 null）、拒绝（Refusal → COMPLETED，finish reason 默认 "refusal"；拒绝是合法完成而非错误）、工具结果回填后重新进入 context/model 循环（ResultsRecorded → BUILDING_CONTEXT → ContextReady → 新模型调用）、多工具调用串行执行、审批拒绝是合法 ToolResult（记录 Denied + deniedCalls + 重新入循环，模型可调整计划）。
  - usage 语义：未知 usage 绝不按 0 计（架构文档 5.3 引文）——缺失字段用保守字节估算（4 字节/token，向上取整）；同调用多次 usage 按字段 last-wins 合并、responseBytes 取 max；报告 total 优先于推导和。
  - 预算：每次提交模型调用前检查 step/modelCalls/input 估算/累计 total（先估算后提交，失败即 FAILED，`ErrorCode.POLICY`、retryable=false、`safeDetails={"limit": <name>}`）；provider 报告的 input/output 超过单调用上限 → FAILED，`ErrorCode.INTERNAL`（providerViolation）；`StartModelCall.maxOutputTokens = min(budget.maxOutputTokens, maxTotalTokens − 提交后已用)`。
  - 模型失败：CallFailed 在 WAITING_MODEL（committed 匹配）或 RECEIVING_MODEL（active 匹配）→ FAILED 并保留部分 responseBytes；过期/不匹配的失败事件忽略；ProtocolError 终态 → FAILED。
  - 取消：任何活 phase（非终态、非 CANCELLING/INTERRUPTED）可 CancelRequested → CANCELLING + CancelInFlight；RUNNING_TOOL 时记录不确定候选（在跑调用 id）；CancelFinished → CANCELLED（finish reason "cancelled"），可携带最终不确定性。
  - 进程中断：非终态 → INTERRUPTED；RUNNING_TOOL 在跑调用为不确定副作用；CANCELLING 保留已记录候选；WAITING_APPROVAL 无不确定性（未执行）；`UncertainToolCallResolved` 必须先解决不确定性才能 `TurnResumed` → BUILDING_CONTEXT；恢复时未执行的响应调用记录为 `Failed(INTERRUPTED)` 且**不重放**（副作用不明确的重审归 HXA-015）；`TurnDiscarded` 仅从 INTERRUPTED/CANCELLING → CANCELLED（"discarded"）。
  - 不变量：FAILED⇒有 error；COMPLETED/CANCELLED⇒有 finish reason 且无 error；非终态两者皆无；committedCallId/activeCallId 互斥且与 phase 一致；reducer 只持有标识符与有界元数据，不接触正文（正文归协调器/持久化层）。
