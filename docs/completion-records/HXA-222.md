# HXA-222：设备内本地模型一等 Provider

日期：2026-09-28。完成范围：Provider contract、Room v1、private-process llama.cpp、模型资产与管理 UI、完整主机 gate，以及所有者授权的 API36 consumer 定向验证。真实 4B 固定多步任务通过；不代表任意 GGUF、真机性能或发行验收。工作树尚未提交。

决策记录：[ADR-PROVIDER-001](../adr/provider/001-models-and-connection.md) accepted；遵循 [ADR-AGENT-001](../adr/agent/001-turn-coordination.md) 的 durable lifecycle，不新增 Agent loop、Dispatcher 或权限路径。

## 交付

- provisioning、transport、auth、residence 正交建模。OnDeviceLocal 不含 endpoint/protocol/secret；Ollama/LAN/loopback 仍是 Network。Room 继续开发期 v1 baseline。
- LocalModelProvider 通过有界 Binder/PFD 请求非导出的 `:model_runtime`；llama.cpp JNI 为 CPU backend，不启动 HTTP server。单常驻模型、单 generation，资产只读 handoff；取消须确认 executor exit 或进程死亡，重启不重放旧调用。
- llama.cpp 固定 commit `7fe450e19305b828c199d602c23a8337aaa1f03b`，MIT 许可证随 APK；模型权重不打包。显式 HTTPS/hash/size 下载，Range 边界、配额、校验与原子发布，卸载/删除及 Room 重建后资产重新登记。
- 默认 4096 context、2 threads、greedy；上下文可调 1024–32768，受模型及可用内存约束。metadata/probe/generation 共用配置，加载失败可降低 context 重试。资源预检拒绝超预算；截断输出保留 Usage 并返回 LOCAL_OUTPUT_LIMIT，不执行部分 ToolCall。
- 模板 grammar 辅助语法，真实 text/tool probe 判断工具能力。工具调用仍由 Harness 校验、授权、执行及持久化；grammar、probe 与 COMPLETED 都不能替代业务正确性断言。
- opt-in 合成测试保存逐轮请求、JNI JSON、事件、Room 轨迹及产物，失败路径也保留证据；不增加生产会话 prompt 日志。修复重复清理 Provider 覆盖原始异常的夹具问题。

## 保留边界

- 0.6B/1.7B 的同类聚合任务失败仍有效；4B 的一次固定任务通过不证明泛化可靠性。首轮 4B 未在时限内结束，原始异常又被清理异常覆盖，完整保留失败记录。
- 旧 PROTOCOL 未保存原始 native reply，不声称唯一根因已经定位。当前取证不包含模板后 token 流或隐藏推理。
- 真机温升、长时间持续负载、OEM 行为、真实远端 Provider 同题对照均 not requested。模拟器内存预检不是通用容量保证；CPU 任务延迟仍高，首版为生成完成后缓冲返回。
- HTTP 续传边界、资产完整性有 host 测试；此次真实权重由 host 下载及 ADB 注入，未做 Android HTTP 下载端到端设备验收。
- 保留已有 Workspace/Memory/HXA-227 修改；未改动 Dispatcher/permission/effect owner，未 commit、push、merge 或发布，不代表 main/远端 CI 已通过。

## 2026-09-28 P3 安装产品化补充

后续剩余工作计划在不重开 HXA-222 runtime/Agent scope 的前提下补齐安装产品层。Models 页现在默认展示两项固定版本公开 GGUF：Qwen3 0.6B Q4_K_M（兼容性证据）与 Qwen3 4B Instruct 2507 Q4_K_M（固定多步任务已通过）；每项同时提供 pinned ModelScope / Hugging Face revision、文件名、字节数、SHA-256、Apache-2.0 许可证与已验证上下文说明。显示名不参与资产身份。

安装共用新的 `LocalModelDownloader`：生产手动导入仍要求直接 HTTPS 且不跟随跳转；精选来源只允许各自 HTTPS host family 的重定向。下载前同时检查 `ModelAssetStore` quota/count 与 Android `StorageManager.getAllocatableBytes()`；峰值预算包含剩余 transfer、完整 verified publish 和 16 MiB reserve。200 对已有 partial 重新开始，精确 206 才追加；错误 Content-Range/hash/完整坏 partial fail closed 并清理，取消/IO 中断保留可续传 partial，已校验重复安装不再发网络请求。

安装成功后 `ProviderService` 立即复用既有 connection probe 与 capability probe；verified asset 即使 probe 失败也保留供重试。只有用户明确点击“用于当前会话”才调用现有 Session model selection，作用于当前会话 future turns，不改其它 Session、全局默认或远端 Provider。

P3 真实 Android E2E 使用已由 HXA-222 校验的 0.6B GGUF 作为 host 受控 HTTP fixture，经 `adb reverse` 进入 API36 developer。最终版本由外层调用者真实取消安装 coroutine，而不是由 progress callback 伪造失败：首请求 `200`，约 4.8 MiB 后 `cancelAndJoin()`；第二请求 `Range: bytes=4808704-`，fixture 返回精确 `206`。随后完成 SHA/GGUF 原子发布、ON_DEVICE_ASSET Provider 注册、真实 Binder/JNI connection + capability probes，并验证只更新当前 Session。最终源码对应 1/1 passed；同一最终 APK 的安装 UI + 既有 Session model contract 定向回归 3/3 passed。完整证据见 [P3 本地模型安装](../evidence/development/p3-local-model-install-2026-09-28.md)。

该补充不改变 CPU backend、真实模型能力结论、真机未验边界，也不把 4B 一次固定任务通过升级为普遍推荐；P5 才建立性能/任务质量基线。

## 2026-09-28 P4 首次成功联合旅程

P4 不重开 HXA-222 runtime，而是在 P3 安装产品层之上做跨模块 first-success 验收。owned API36 developer 从清空 app data 开始，通过同一 local install/probe orchestration 安装 pinned GGUF，使用 `ChatService.createSession` 建立唯一当前会话与 managed Workspace，仅开放 `write`/`read`，真实模型写入固定 `first-success.txt` 并读回；`write` 自动登记 durable artifact。完成后 setup 主动 `Process.killProcess`，verify instrumentation 在不同 PID 中只读恢复。

Qwen3 0.6B Q4_K_M 的 bounded 对照在第一 model call 消耗 1307 input / 512 output tokens 后以 `LOCAL_OUTPUT_LIMIT` 失败，0 tool calls；这被记录为模型任务质量/效率边界，没有修改 production。随后使用此前已通过固定工具任务的 Qwen3 4B Instruct 2507 Q4_K_M，同一 fixture 成功：Turn `COMPLETED`，`write`/`read` 各 1 次且均 `COMPLETED`，3 个 model calls、6 条 persisted messages，artifact SHA 与 Workspace 文件一致。

重开验证确认 PID 改变但 Session provider/model、Workspace id/revision、Turn terminal、conversation messages、tool timeline、artifact 行与文件内容均恢复；额外等待 2 秒后 turn/model-call/tool-call/message 数量完全不变，`duplicateSideEffect=false`。P4 因此证明产品组合闭环，而不是扩大 4B 的普遍质量/性能结论。详见 [P4 设备证据](../evidence/development/p4-first-success-journey-2026-09-28.md)。
