## 修改文件

**`:tools:android`（新模块源码，纯 JVM 端口 + Context-backed 实现；此前仅占位 `gradle.lockfile`）**：

- **`AndroidSystemBridge.kt`**（新）：`AndroidSystemBridge` 端口接口——**纯 JVM**（接口与 outcome 均无 Android 类型），4 个方法 `openUri`/`clipboardRead`/`clipboardWrite`/`share`。返回小、有界、无 null 的视图对象（逻辑缺失值发 `""`）：`OpenUriOutcome(status,url,reason)`（`OpenUriStatus { OPENED, REFUSED, NO_HANDLER, ERROR }`）、`ClipboardReadOutcome(status,text,length,truncated,reason)`（`ClipboardReadStatus { READ, REFUSED, ERROR }`）、`ClipboardWriteOutcome(status,length,reason)`（`ClipboardWriteStatus { WRITTEN, REFUSED, ERROR }`）、`ShareOutcome(status,reason)`（`ShareStatus { SHARED, NO_HANDLER, ERROR }`）。`internal const MAX_CLIPBOARD_READ = 4_000`（clipboard 读上限，工具输出 schema 与 impl 共享同一常量）。端口对页面/系统条件绝不抛异常，只有编程错误才抛。
- **`AndroidSystemBridgeImpl.kt`**（新）：Context-backed 生产端口。`openUri`：先跑纯 JVM 方案门 [isHttpUrl]（非 http(s) → REFUSED `scheme`，**绝不构建或启动任何 intent**），再建 `ACTION_VIEW` + `CATEGORY_BROWSABLE` 经 [IntentLauncher] 启动 → OPENED/NO_HANDLER/ERROR。`clipboardRead`/`clipboardWrite`：先 [ForegroundProbe] 可见前台闸门（非前台 → REFUSED `not-foreground`），再驱动**真实**系统 `ClipboardManager`（读经纯 JVM `boundClipboardText` 截断到 4 000 字、`length` 保留原长、`truncated` 标记）/ `setPrimaryClip` 写。`share`：建 `ACTION_SEND`（`text/plain`、`EXTRA_TEXT`、可选 `EXTRA_SUBJECT`）经 `Intent.createChooser` 包装成 `ACTION_CHOOSER` 启动 → SHARED/NO_HANDLER/ERROR，**Helix 绝不替用户挑目标**。纯 JVM 助手 [isHttpUrl]（方案恰为 http/https 且 host 非空、unparseable → false）与 [boundClipboardText]（超 `maxChars` 截断 + `truncated`，`length` 恒为原长）。两个可注入 seam：[ForegroundProbe]（生产默认 `ActivityManagerForegroundProbe`，`getRunningAppProcesses` 读自身进程 importance）与 [IntentLauncher]（生产默认 `ContextIntentLauncher`，非 Activity Context 须 `FLAG_ACTIVITY_NEW_TASK`）。
- **`AndroidSystemTools.kt`**（新）：4 个 `object`（`AndroidOpenUriTool`/`ClipboardReadTool`/`ClipboardWriteTool`/`AndroidShareTool`）+ `AndroidSystemTools.registerAll`。每个 `descriptor()`：`baseRisk = L2`、`operationClass = EXTERNAL_ACTION`、`executionTarget = LOCAL_ANDROID`、`origin = BuiltInOrigin`、`requiredCapabilities = emptySet()`、`timeout = 30s`；`executor(bridge)`：fail-closed 映射（见「实现的契约」1）。输入上限：`MAX_URL = 2048`、`MAX_SHARE_TEXT = 10_000`、`MAX_SHARE_SUBJECT = 512`、`MAX_CLIPBOARD_WRITE = 4_000`；模型可见错误 `MAX_DETAIL = 512`（截断，审计保留原文）。幂等性：`clipboard.read`/`clipboard.write` = IDEMPOTENT，`android.open_uri`/`android.share` = NON_IDEMPOTENT。

## 实现的契约

1. **4 个工具都是端口的薄 fail-closed 映射**（doc 09 §5.3/§5.4、与 HXA-062/063 的 `browser.*` 同一原则）：工具 `execute` 解析（已 schema 校验的）参数、调用**恰好一个**端口方法、把闭合状态枚举映射成稳定 `ToolExecutorResult`——`OPENED`/`READ`/`WRITTEN`/`SHARED`/`REFUSED`/`NO_HANDLER` → Completed（携带稳定 status，REFUSED 的 `reason` 是策略类别如 `scheme`/`not-foreground`），`ERROR` → Failed（`bounded(reason)`），取消 → Cancelled，**绝不一律回「成功」**。参数缺失/越界 = `Failed`（`sideEffectFree`）。
2. **`android.open_uri` 只打开**（doc 09 §5.3）：纯 JVM 方案门 [isHttpUrl] 在**构建任何 intent 之前**运行——非 http(s) URL 绝不到达 launcher（`file:`/`javascript:`/`market:`/`tel:`/`intent:`/opaque `http:foo`/空白/不可解析一律 false）。有效 http(s) 经 `ACTION_VIEW` + `CATEGORY_BROWSABLE` 打开，OS 挑 handler，**Helix 绝不在 handler 内导航或跟随到另一个 app**。设备测试 `openUriRefusesNonHttpSchemesWithoutLaunching` 断言 4 个非 http(s) 方案的 `launcher.lastIntent` 恒为 `null`（未构建/未启动）。
3. **clipboard read/write 按可见前台限制**（doc 09 §5.3）：两个操作在 [ForegroundProbe] 报告非可见前台时都 REFUSED `not-foreground`；读经纯 JVM `boundClipboardText` 截断到 4 000 字（`length` 恒为原长、`truncated` 标记，让模型知道剪贴板比所见更长）；**空剪贴板是成功读到空文本**（READ + `text=""`），不是错误。
4. **`android.share` 分享输入先预览 + 绝不替用户挑目标**（doc 09 §5.4、doc 02 §5.4）：只建 `ACTION_SEND`（`text/plain`、`EXTRA_TEXT`、可选 `EXTRA_SUBJECT`）经 `Intent.createChooser` 包装成 `ACTION_CHOOSER` 启动——**由用户选目标 app，Helix 绝不替用户挑**。「分享输入先预览」由 **L2 审批卡**满足（见「决策记录」3）：4 个工具都是 L2 EXTERNAL_ACTION，生产 dispatcher 的 L2 审批卡在用户批准前渲染完整规范参数（分享文本 + subject）。blank subject 省略 `EXTRA_SUBJECT`。
5. **输出无 JSON null**：4 个工具的 Completed 输出 schema 合规，逻辑缺失值发 `""`、未写入 length 发 `0`（`AndroidSystemToolsMappingTest.everyCompletedOutputCarriesNoJsonNulls` 全覆盖）。
6. **纯 JVM 端口/助手 + Context-backed 实现的测试分工**：`isHttpUrl` 与 `boundClipboardText` 是纯 JVM（JVM 单测独立钉住边界）；安全控制（前台门、方案门、chooser 构建）住 Context-backed 实现，经注入 `ForegroundProbe`/`IntentLauncher` seam 在设备验真实系统调用 + 前台/方案闸门。

## 决策记录：

1. **纯 JVM 端口 + Context-backed 实现（端口是安全边界、工具只做薄映射）**：与 HXA-062/063 的 `browser.*` 同一原则。4 个工具只解析参数 + 把闭合状态映射成 `ToolExecutorResult`；真实 `Intent` 构建 / `ClipboardManager` 读写 / 前台判定都在 `AndroidSystemBridgeImpl`。这把工具层做成可 host 单测（27 例 fake bridge），设备测试再驱动真实系统服务——安全关键逻辑住可复现、可回归的层。
2. **`isHttpUrl` 方案门在构建任何 intent 之前运行**：非 http(s) URL 绝不到达 launcher。纯 JVM 门（方案恰为 http/https 且 host 非空、unparseable → false）保证 `file:`/`javascript:`/`market:`/`tel:`/`intent:`/opaque 一律不构建/不启动 intent（设备测试断言 `launcher.lastIntent` 恒为 null）。这是「`android.open_uri` 只打开」的硬化——`open_uri` 绝不在 handler 内导航或跟随到另一个 app，有效 http(s) 交给 OS 挑 handler。
3. **分享「先预览」由 L2 审批卡满足、不做独立预览 UI**（doc 02 §5.4）：4 个工具都是 L2 EXTERNAL_ACTION，生产 dispatcher 的 L2 审批卡在批准前渲染完整规范参数（分享文本 + subject）——这正是「分享输入先预览」。另建预览面会与审批卡重复。`android.share` 只建 `ACTION_CHOOSER` 包 `ACTION_SEND`，Helix 绝不替用户挑目标 app。
4. **clipboard 读/写经可注入 `ForegroundProbe` 按可见前台闸门**：生产 `ActivityManagerForegroundProbe` 用 `getRunningAppProcesses`（deprecated 但唯一自包含、无 Activity/无 receiver 读自身进程 importance 的方式）在非可见前台时拒绝读/写。probe 是 seam，使设备测试能确定性地验两个状态而不依赖 flaky 的模拟器前台态。
5. **读上限 `boundClipboardText`（4 000 字）抽成纯 JVM**：JVM 单测独立钉住边界（5 例，含恰好等于上限不截断、超长截断 + `truncated` 标记、显式上限），且被端口读路径共享，使输出文本永远在工具输出 schema 之内；`length` 恒为原长，让模型知道剪贴板比所见更长。
6. **设备/JVM 测试分工（读回往返 + 上限归 JVM）**：库的 `connectedDebugAndroidTest` 在后台合成 test app 里跑、无可见 Activity；API 29+ 对非前台 app 的 `getPrimaryClip` 脱敏为空，故设备侧 clipboard **读回往返天然 flaky**。所以设备测试验真实写路径（`setPrimaryClip` binder 调用）+ 前台闸门 + 真实 intent 构建（`open_uri` `ACTION_VIEW`、`share` `ACTION_CHOOSER`/`ACTION_SEND`）；读上限 + 映射归 JVM。与 M6 一贯的「JVM 验机制 / 设备验 on-device fail-closed + 真实系统服务」分工一致。
7. **无新 Capability / 无新权限**：可见前台控制是端口实现运行时闸门，不是 capability；clipboard/Intent/share 都无需 manifest 权限。4 个工具 `requiredCapabilities = emptySet()`（不引入 capability 探测门），风险由 L2 + 审批卡 + 运行时闸门承接。
8. **detekt 高返回/吞异常/泛型 catch 点用针对性 `@Suppress`**（最小作用域、附一行说明）：端口实现里「每守卫一个返回」与「把系统异常吞成稳定 ERROR outcome」是 fail-closed 语义本身；`isHttpUrl` 的 unparseable→false + 早返回、`ActivityManagerForegroundProbe` 的 deprecated API + 早返回、各工具 executor 的每守卫返回，均按仓库既有 `@Suppress` 惯例处理（见 `BrowserTools.kt`）。

## 风险或后续任务

- **前台探针用 `getRunningAppProcesses`（deprecated）**：它是唯一自包含（无 Activity、无 receiver）读自身进程 importance 的方式，且至少总会报告调用方 app。若未来 Android 移除它，seam（`ForegroundProbe`）允许换用基于 Activity 生命周期的探针而不动工具层。
- **clipboard 仅文本**：图片/URI/HTML 剪贴板类型不在范围。若出现真实需求，在端口实现加 clip 类型处理（工具 schema 会相应变化）。
- **`open_uri` 依赖 OS 挑 handler、无自定义 intent filter**：非 http(s) 由纯 JVM 门拒绝；有效 http(s) 交给 OS 解析。Helix 不管理 deep-link / 不处理自定义 scheme。
- HXA-065（通知和日历）开工时：通知 app allowlist/time window；Calendar 先草稿再 commit；权限关闭返回 `PermissionMissing`（roadmap M6 / HXA-065）；与本任务的 `:tools:android` 无共享执行路径（不同模块、不同安全边界，通知/日历是各自的新端口）。
