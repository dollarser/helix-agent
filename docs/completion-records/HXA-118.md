# HXA-118 完成记录：Codex 第三方侧载 OAuth 登录生命周期

**日期**：2026-09-05

**状态**：代码与自动化设备验收完成；真实账号端到端登录未通过，Codex adapter 仍不可用、
未注册。本结论不表示 OpenAI 官方支持 Helix，也不表示订阅模型可调用。

## 实现与边界

- `com.helix.runtime.cli` 的用户可见 Activity 生成 PKCE/state，使用固定
  `https://auth.openai.com` origin 与 1455/1457 loopback callback。
- access/refresh/id token 与 account id 只写入 Runtime UID 的 Android Keystore 加密 vault；
  Binder/status 不返回 token、code、verifier、email 或 account id。
- token response 限制 64 KiB；修复了把短响应误判为 EOF 的读取错误。登录前以无凭据无效
  grant 验证 token endpoint，首次系统 DNS 成功结果只在同一 transport 内缓存五分钟、最多八项，
  不固定 IP、不持久化 DNS。
- 覆盖 state/path/code、超时、失败分类、token 轮换、永久 refresh 失效、logout、vault 加密与
  redacted status。本 HXA 没有模型请求、Provider/Tool/Job 注册或外部 credential 导入。
- 访问日期 2026-09-05：OpenAI 官方说明 Codex CLI 使用 ChatGPT 登录并在本地保存凭据：
  https://help.openai.com/en/articles/11381614-api-codex-cli-and-sign-in-with-chatgpt ；适用条款：
  https://openai.com/policies/terms-of-use/ 。未发现第三方复用 Codex CLI OAuth identity 的公开授权。

## 真实账号与已知限制

- API 36 `Helix_M9_API_36`、arm64-v8a 上浏览器多次成功到达 `Helix login complete` callback；
  authorization code、state 与 token 从未输出到记录或主 App。
- token exchange 多次显示安全类别 `dns`，未保存凭据。模拟器曾出现损坏的 DNS/ICMP 时延状态；
  重启并指定宿主 DNS 后，无凭据 endpoint probe 可稳定得到预期 HTTP 4xx，但真实登录仍未取得
  `LOGGED_IN` 证据。随后加入登录前 endpoint preflight 与有界 DNS cache，尚无新的真人授权结果。
- OpenAI 网页在高频重复登录后出现 `Invalid authorization step` 与通用错误；这不足以判定账号风控。
  不再重复消耗授权事务。真实登录、refresh 和真人 logout 证据均缺失。
- verification matrix 明确真人登录单列，缺失不阻止代码级验收；因此 HXA 完成仅表示受限登录
  生命周期实现及自动化门禁成立。adapter 必须保持 `NOT_REGISTERED`。
