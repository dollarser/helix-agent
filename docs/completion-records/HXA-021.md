# HXA-021 完成记录

- 目标：内部 ModelRequest/ModelEvent（roadmap HXA-021）：纯 Kotlin contract 支持文本、图像引用、工具 schema、reasoning、tool arguments delta、usage、finish/refusal/error；Agent Core 不依赖厂商 DTO。
- 前置任务/commit：`4a8a548`（“HXA-020：SecretStore 与 Provider 配置（M2 首个 HXA）”）。
- 修改文件：
  - core:model（新增，纯 JVM 共享内核——core:agent 仅依赖 core:model，契约必须落在这里 Agent Core 才能消费；零新依赖）：
    - `ModelRequest.kt`：
      - `ModelRole`（SYSTEM/USER/ASSISTANT/TOOL）、`ReasoningEffort`（OFF/LOW/MEDIUM/HIGH，vendor 中立——adapter 映射到原生旋钮或按 capability `reasoning=false` 丢弃）。
      - `ImageReference(ref: ArtifactRef, mediaType)`：图像走 HXA-010 不透明引用（字节在 content store，由 adapter/transport 解析——契约永不携带内联图像数据）；mediaType 封闭 allowlist（png/jpeg/webp/gif）。
      - `ModelMessage(role, text, images, toolCallId, toolName)`：角色/内容规则构造期强制——text 非空白且无 NUL（\n\t 等 C0 是合法文本，代码块场景）、长度界 256 KiB；images 仅 USER 角色且每消息 ≤4；TOOL 消息必须携带 `toolCallId: ToolCallId` + `toolName: ToolName`（vendor API 以 call id 键控工具结果，doc 02 §5.3）；其余角色两者必须为 null。
      - `ModelToolSchema(name: ToolName, description, inputSchemaJson)`：description 非空白 ≤1024 无控制字符；`inputSchemaJson` 必须是被共享严格解析器（ADR-0001 解码纪律）接受的 JSON 对象且 ≤256 项——adapter 自行重编码为 vendor 形态。
      - `ModelRequest(model, messages, tools, temperature?, maxOutputTokens?, seed?, stopSequences?, reasoning)`：model 1..256 无空白/控制字符；messages 1..512 且**最后一条必须是 USER 或 TOOL**（请求不得以 assistant/system 收尾）；tools 0..64 名称唯一；temperature 有限 0.0..2.0；maxOutputTokens ≥1；stopSequences ≤4 条、1..64 无控制字符。无 secret、无 provider 配置、无 transport 字段——纯模型语义。
    - `ModelEvent.kt`：
      - `ModelErrorCode` 封闭 8 类（TRANSPORT/TIMEOUT/HTTP_ERROR/AUTH/RATE_LIMITED/SERVER_ERROR/PROTOCOL/CONTENT_FILTER），KDoc 给出到 `ErrorCode` 12 类的映射（TRANSPORT/TIMEOUT→NETWORK、HTTP_ERROR/SERVER_ERROR→EXECUTION、AUTH→PROVIDER_AUTH、RATE_LIMITED→PROVIDER_RATE_LIMIT、PROTOCOL→VALIDATION、CONTENT_FILTER→POLICY）。
      - `ModelEvent` sealed（doc 02 §6.1 的 9 变体全保留）：`TextDelta/ReasoningDelta`（非空、无 NUL、≤64 KiB）、`ToolCallStarted(index, id: ToolCallId, name: String)`、`ToolArgumentsDelta(index, jsonFragment)`、`ToolCallFinished(index)`、`Usage(inputTokens?, outputTokens?)`（null=未报告，绝不按 0，doc 02 §5.3）、`Refusal(safeReason?)`（合法完成而非错误，对齐 core:agent `ModelTerminal.Refusal` 语义）、`Error(code, retryable)`（流终止事件）、`Completed(finishReason?)`（null 时 Agent Loop 规范为 "stop"，HXA-011 契约）。流级顺序规则（index 引用、finish 闭合、每流至多一个终止事件、参数片段完成时一次性 parse）写进 KDoc，由各 adapter fixture 测试执行（HXA-022/023/024）。
    - 测试 `ModelRequestTest.kt`（14 个）、`ModelEventTest.kt`（9 个）：角色/图像/工具结果规则、文本 NUL/空白/超长、最后消息角色规则、消息数/工具数边界（含恰好等于上限的合法断言）、schema JSON 对象性（5 种非对象输入拒绝 + 257 项超限拒绝）、temperature NaN/Inf/越界、stop 序列上限、model id 规则；delta 边界、ToolCallStarted 的 charset 违反（vendor id 含空格）在构造期失败（不产生部分事件——adapter 转 `Error(PROTOCOL)`）、Usage 负值拒绝、Refusal/Completed 安全字段边界、ModelErrorCode 封闭集 8 值断言。
  - Room schema：零变化（本 HXA 纯契约类型，无持久字段）。
  - 文档：本文件、`docs/development/status.md`、`docs/development/verification-matrix.md`（HXA-021 行按实际落位补 `:core:model:test`——契约落位 core:model 共享内核，任务书写于模块落位之前，与 HXA-020 同一先例）。
- 实现的契约：
  - roadmap HXA-021 逐条：文本（ModelMessage.text + TextDelta）、图像引用（ImageReference，不透明 ArtifactRef + 封闭 mediaType）、工具 schema（ModelToolSchema，ToolName + 严格 JSON 对象）、reasoning（ReasoningEffort 请求侧 + ReasoningDelta 事件侧）、tool arguments delta（ToolCallStarted/ToolArgumentsDelta/ToolCallFinished 三事件族，index 键控）、usage（Usage，null 语义）、finish/refusal/error（Completed/Refusal/Error + ModelErrorCode）。
  - doc 02 §4：`stream(request: ModelRequest): Flow<ModelEvent>` 的两个参数/返回类型现在存在（`ModelProvider` 接口本身含 `listModels/validateConfiguration`，属 HXA-025 能力探测范围——本 HXA 不加该接口，避免引入占位的 catalog 类型）；“Agent Core 不依赖厂商 DTO”——core:agent 仅依赖 core:model，契约类型全部在 core:model，无任何 vendor 字段形状。
  - doc 02 §6.1：`ModelEvent` 9 变体逐一对应（字段类型仅两处收紧，见下）。
  - doc 02 §5.3：Usage 未知不按 0（nullable + KDoc）；Completed null 规范 "stop"（与 HXA-011 reducer 既有契约一致）。
  - doc 10 §2.1：“所有网络协议先转换为内部 ModelRequest/ModelEvent，Agent Loop 不读取供应商 JSON”——HXA-022/023/024 的 adapter 输入/输出类型就绪。
- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  - **契约落位 core:model**（而非 provider:api）：模块图 `core:agent → core:model`（唯一依赖），Agent Core 要消费事件流就必须能看见契约；provider:api 同样依赖 core:model，adapter 不受影响。与 HXA-020 的共享内核落位一致。
  - **两处类型收紧（doc 02 §6.1 的 `String` → 值类）**：`ToolCallStarted.id: String` → `ToolCallId`（构造期 charset 校验，vendor id 越界在构造期失败而非流中段——adapter 转 `Error(PROTOCOL)`；同时使流事件 → core:agent `ModelToolCall(ToolCallId)` 映射全函数）；`ModelMessage.toolName: String?` → `ToolName?`（工具结果必须指名注册表中的工具，可审计）。收紧与 core:agent 既有契约（`ModelToolCall.toolCallId: ToolCallId`、`toolName: ToolName`）对齐，不是新决策。
  - **图像不内联**：`ImageReference` 只持不透明引用 + mediaType——与 HXA-010 的“引用不透明、内容由 ContentStore 解析”纪律一致；base64/url 形态是 adapter 的 vendor 编码细节（HXA-022+）。
  - **schema 用规范 JSON 文本而非引入公开 JSON 类型**：core:model 尚无公开 JSON 类型（internal `JsonNode` 是 ADR-0001 存储编解码器）；公开 JSON 模型是更大的设计决策，本 HXA 用“严格解析器 + 文本”守住边界，adapter 侧编码自主。
  - **流级规则不入构造器**：单事件无法验证的顺序不变量（index 闭合、终止唯一性）只能由流消费端/adapter 执行——写入 KDoc 作为契约，HXA-022/023/024 fixture 落地测试；构造器只验单事件不变量（fail-closed）。
  - **不建 `ModelProvider` 接口**：其 `listModels/validateConfiguration` 返回类型（catalog/check 结果）属 HXA-025；现在加接口即引入占位类型（AGENTS.md 禁止 placeholder）。
  - **数据类别清单（doc 10 §2.6 出网审计输入）不在本契约**：EgressSummary/数据类别是 ADR-0005 Safety Profile 执行层（后续 Provider/Policy 任务）的契约；HXA-021 按 roadmap 行范围（文本/图像/schema/reasoning/delta/usage/finish-refusal-error）收口。
