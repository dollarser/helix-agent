## 目标

roadmap M6 / HXA-067：

- 「使用系统语音识别 Activity/Service 能力将用户主动录音转为可编辑草稿」；
- 「不后台常驻监听、不自动发送给模型」；
- 「覆盖 unavailable/denied/cancel/error 和前后台转换」；
- 「本任务先按系统 locale 启动识别，用户仍可在系统识别 UI 中修改；后续由 HXA-069 统一资源化，并把识别默认语言接到当前 App locale」。

本任务把这四条落地为**用户主动触发、可编辑、绝不自发**的语音草稿路径：点「语音」→ 前置能力门（无识别器 → 瞬时提示、不 launch）→ 系统识别 Activity（系统 UI 录音、用户可当场改字）→ Activity 返回 → 纯 `VoiceInputMapper` 把结果映射成 4 态 → `Draft` 的 inert 文本**追加**进 composer `input`（**绝不自动发送**，发送是独立显式按钮，与 HXA-056 分享草稿同一「本地草稿绝不自发」先例）。**denied/error 与 cancel 的区分**受平台限制：Activity 结果无错误码，故三者对 Helix 不可区分、统一收敛为无害 `Cancelled`（不产草稿、不发送、不报错），具体原因由系统 UI 呈现——这是对「覆盖 unavailable/denied/cancel/error」的诚实落地（`Unavailable` 由前置门覆盖；denied/cancel/error 合并为 `Cancelled`，见「决策记录」）。

## 修改文件

**`:app` 应用源码（纯 JVM 决策 + Android seam 分层）**：

- **`app/src/main/kotlin/com/helix/app/voice/VoiceInputMapper.kt`**（新，纯 JVM）：`object VoiceInputMapper`——无 Android 类型、无副作用，host 可单测。
  - `RESULT_OK: Int = -1` / `RESULT_CANCELED: Int = 0`（把 `Activity` 结果码**镜像为纯 int**，使本对象不依赖 `android.app.Activity`）。
  - `sealed class Outcome { data class Draft(text); object Cancelled; object Unavailable; object Available }`。`Draft` 只携带 **inert 文本**（无 send 信号 / flag / companion），消费者只能把它放进可编辑输入、无法据此发送。
  - `preCheck(available: Boolean): Outcome`——前置能力门：`true`→`Available`、`false`→`Unavailable`（launch 前判断）。
  - `mapResult(resultCode: Int, results: List<String>): Outcome`——**仅** `RESULT_OK` 且有非空转写时取首个非空 trim 成 `Draft`；其余（cancel / 无匹配 / 失败 / 未知码 / 空 / 全空白）一律 `Cancelled`。
- **`app/src/main/kotlin/com/helix/app/voice/SpeechRecognitionLauncher.kt`**（新，Android seam）：`class SpeechRecognitionLauncher`——
  - `isAvailable(context): Boolean = SpeechRecognizer.isRecognitionAvailable(context)`（真实系统能力查询）。
  - `buildIntent(context): Intent`——`ACTION_RECOGNIZE_SPEECH` + `FLAG_ACTIVITY_SINGLE_TOP` + `EXTRA_CALLING_PACKAGE=packageName` + `EXTRA_LANGUAGE_MODEL=LANGUAGE_MODEL_FREE_FORM`；**不 set** `EXTRA_LANGUAGE`/`EXTRA_LANGUAGE_PREFERENCE`（按**系统 locale** 启动）。
  - `mapResult(resultCode: Int, data: Intent?): Outcome`——从真实 `Intent` 提取 `EXTRA_RESULTS`（`ArrayList<String>`，index 0 = 最佳匹配；`data==null`→空列表、绝不抛）→ 委托纯 `VoiceInputMapper.mapResult`。
  - 无 mic 权限、无 `createSpeechRecognizer`、无 `setRecognitionListener`、无录音——Helix 从不直接持麦克风，录音由系统识别 UI 完成。
- **`app/src/main/kotlin/com/helix/app/ui/ChatScreen.kt`**（改，+63 行）：composer 行加「语音」`TextButton`（testTag `chat-voice`，`enabled=!isSending`）+ 瞬时 `voiceNotice` `Text`（testTag `chat-voice-notice`，**仅**不可用时显示「语音识别不可用」，无路径/无细节）。`rememberLauncherForActivityResult(StartActivityForResult)` 收回结果 → `speech.mapResult(result.resultCode, result.data)` → `Draft` 经 `LaunchedEffect(voiceDraft)` **一次性**追加进 `input`（读当前 `input` 闭包，绝不读 stale 值；一次性后置 `voiceDraft=null`）、`else`（cancel）**no-op**。点「语音」先 `VoiceInputMapper.preCheck(speech.isAvailable(context))`：`Available`→清 notice 并 `voiceLauncher.launch(speech.buildIntent(context))`；`Unavailable`→置 notice、**不 launch**。识别文本只进 `input`、**绝不自动发送**（复用 HXA-056 分享草稿的 inert 草稿先例）。

## 实现的契约

1. **纯 JVM 决策 + Android seam 分层**（与 M6 工具「端口是边界、薄映射」同一分层）：`VoiceInputMapper`（纯 int 结果码 + `List<String>` 入、`Outcome` 出、无 Android 类型）承载全部判定，host 单测 9 例；`SpeechRecognitionLauncher` 只承担 Android 副作用（查能力、建 intent、提取 `EXTRA_RESULTS`），设备测试 7 例驱动真实 seam。
2. **用户主动触发、系统 UI 负责录音**（roadmap「用户主动录音」「不后台常驻监听」）：无 `createSpeechRecognizer`/listener/mic 权限/录音；录音发生在系统识别 Activity 内，Helix 只在 Activity 返回时收回转写，故**无后台常驻监听**。
3. **可编辑、绝不自动发送**（roadmap「转为可编辑草稿」「不自动发送给模型」「用户仍可在系统识别 UI 中修改」）：系统识别 UI 让用户当场改字；收回的文本经 `Draft`（**只含 inert 文本**）追加进 composer `input`，发送仍是独立显式按钮——`Draft` 结构上无 send 信号，无法被语音路径触发发送（HXA-056 同一「本地草稿绝不自发」先例）。
4. **unavailable 由前置门覆盖**（roadmap「覆盖 unavailable/…/error」）：launch 前 `preCheck(speech.isAvailable(context))`，无识别器→瞬时 notice、**不 launch**（不崩溃、不发误导错误）。
5. **denied/cancel/error 诚实收敛为无害 `Cancelled`**（roadmap「覆盖 …/denied/cancel/error」，受平台限制）：Activity 结果**无 error-code extra**（android-36 javap 核验），故用户取消 / 无匹配 / 识别失败对 Helix 不可区分，统一 `Cancelled`（无草稿、不发送、不报错），具体原因由系统识别 UI 直接告知用户——**绝不**用「假成功」或伪造错误码冒充可区分的状态。
6. **按系统 locale 启动**（roadmap「本任务先按系统 locale 启动识别」）：`buildIntent` 不 set `EXTRA_LANGUAGE`/`EXTRA_LANGUAGE_PREFERENCE`（设备测试断言二者为 `null`）；识别默认语言接 App locale 归 HXA-069。
7. **前后台转换安全**（roadmap「覆盖 …和前后台转换」）：`rememberLauncherForActivityResult` 在进程/Activity 重建后仍正确收回结果；`mapResult` 对 `data==null`（纯取消无 data intent）不抛；`LaunchedEffect(voiceDraft)` 一次性应用草稿、读当前 `input` 闭包。

## 决策记录：

1. **选 Activity（`ACTION_RECOGNIZE_SPEECH`）而非 `SpeechRecognizer` instance/Service API**：roadmap 明确要求「用户仍可在**系统识别 UI 中修改**」——只有 `ACTION_RECOGNIZE_SPEECH` Activity 提供用户可编辑的系统识别 UI，且**无需** `RECORD_AUDIO` 权限、Helix 不直接持麦克风（满足「不后台常驻监听」）。代价是 Activity 结果无错误码（见决策 2），但「可编辑系统 UI + 无 mic 权限」是 roadmap 的硬约束，故选 Activity。
2. **denied/cancel/error 收敛为无害 `Cancelled`（平台无错误码，android-36 javap 核验）**：`SpeechRecognizer` 无 `errorResultCodeFromStatus`、`RecognizerIntent` 无 error-code extra——Activity 结果只有 `RESULT_OK`/`RESULT_CANCELED`。故用户取消 / 无匹配 / 识别失败三者对 Helix **不可区分**，统一 `Cancelled`（无草稿、不发送、不报错），具体原因由系统识别 UI 直接呈现。这是**诚实**落地：绝不伪造可区分的错误码、绝不用「假成功」/误导错误冒充状态。`unavailable` 由前置门单独覆盖。
3. **纯 JVM 4 态 `VoiceInputMapper` + Android `SpeechRecognitionLauncher` seam 分层**：判定住纯 JVM（`int` 结果码 + `List<String>` 入、`Outcome` 出，`Activity` 结果码镜像为纯 int），host 单测 9 例；Android 副作用（查 `isRecognitionAvailable`、建 intent、提取 `EXTRA_RESULTS`）住 seam，设备测试 7 例。与 M6 工具「端口是边界、薄映射」同一分层，使 4 态判定可脱离设备回归。
4. **能力门用「一致性」断言而非固定值（镜像差异实测发现）**：预想两台验证镜像都无识别器，实测发现 **API 36 镜像装有语音识别 app**（`isRecognitionAvailable`=true）、**API 29 无**（=false）。设备测试若硬断言 `assertFalse(isAvailable)` 会在 API 36 上误挂；故改为断言 `preCheck` 与**线上** `isAvailable` 查询一致——两台镜像恰好覆盖 `false`/`true` 两条真实路径，比固定值更强。`preCheck(true)`/`preCheck(false)` 的纯映射另由 `VoiceInputMapperTest` 单测钉死。
5. **复用 HXA-056 分享草稿先例：inert 草稿、绝不自动发送**：识别文本经 `Draft`（**只含文本、无 send 信号**）追加进 composer `input`，发送是独立显式按钮——结构上语音路径**无法**触发发送，与 HXA-056「本地草稿绝不自动发送」（ADR-0014 §5）同一原则。`LaunchedEffect(voiceDraft)` 一次性应用、读当前 `input` 闭包（不读 stale）、用完置 null。
