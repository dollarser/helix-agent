# HXA-228：Conversation-first Shell 与 Session Context Control

日期：2026-09-27。分支 `refactor/clean-slate-engine`。本任务在 HXA-220/223 的 TurnEngine durable-owner 边界和 HXA-226 的 UI authority 基础上，把默认产品路径从 Session-list-first 收敛为 Conversation-first，并冻结 Session config / Composer context contract。

## 交付

### 1. Conversation-first launch / history

- 正常启动优先恢复显式 target / last viewed conversation；否则创建 ephemeral new-conversation draft；
- 默认页面直接可输入，不再先展示 full Session list；
- Search / All conversations 成为 secondary history route；
- Drawer 收敛为 New / Search / Current / Recent / All conversations；
- 仅打开 secondary route 不会把空 draft 写进 Room。

对应冻结 checkpoint：

```text

7b3a42f0  refactor(policy): align session permission presets
537dd3a7  refactor(ui): make conversation history secondary
```

### 2. Session config 从 App-global 状态拆出

旧 `RunControlStore` 是全 App 单例，直接作为 Session Settings authority 会导致不同会话互相串 Mode。最终 contract：

```text
RunControlStore
    = 新会话 defaults

SessionRunControl
    = durable per-Session snapshot

SessionDraft.control
    = ephemeral draft snapshot

Turn
    = admission-time snapshot
```

新增 `session_run_controls`。修改 App defaults 不 retroactively 修改已有 Session；修改 Session config 不 retroactively 修改 active Turn。

### 3. Permission clean-slate v2

Session permission preset 已按 ADR-PERMISSIONS-001 收敛为：

- `APPROVAL_REQUIRED`
- `WORKSPACE_TRUSTED`
- `FULL_ACCESS`
- `READ_ONLY`
- `CUSTOM`

`READ_ONLY` 不再借名表示 ask-before-change；Session permission 是固定 snapshot，修改 defaults 只影响新 Session。Expert / Skill / Connector binding 均不能授予 permission。

### 4. Session Settings

真实 secondary route：

```text
conversation/settings
```

当前 Session authority：

- Expert
- Mode
- Model
- Permission
- Skills
- Connectors

全局 authority 保持：

- Models → Provider/account/endpoint；
- Extensions → Skill/Connector install/config；
- Settings → App defaults；
- Session Settings → 当前 Session binding/snapshot。

打开 Session Settings 本身不会 materialize ephemeral draft；只有执行需要 durable identity 的配置操作时才 materialize。

### 5. Composer context workbench

Composer 底部保持 Mode / Model / Permission 高可见状态，`+` 按生命周期分组：

```text
添加到本次消息
  Camera
  Photos
  File
  Reference conversation

配置此会话
  Mode
  Expert
  Skills
  Connectors
  Session settings
```

没有真实 backend 的 Memory 不显示；长期 Markdown Memory 仍属于 HXA-230。

Camera 经 FileProvider 写入 app-private `files/attachments/camera/` 后继续调用统一 `stageAttachment(uri)`；Photos/File 也复用已有 staging / normalization / artifact / credential / egress pipeline，没有第二条附件处理链。

### 6. ExpertProfile

新增 `session_experts`，一个 Session 最多一个 primary Expert。

Expert 只包含行为配置：

- display name / instruction；
- 可选 recommended Skill / Connector / Mode；
- 不能提升 permission；
- 不能启用 Tool；
- 不能绕过 approval / policy / model selection。

关键冻结链：

```text
Session Expert
  → Turn admission
  → turn_runtime_records.expertProfileJson
  → 本 Turn 后续所有 model/tool rounds
```

因此 Session Expert 在 Turn A 运行期间从 A 改为 B 时，Turn A 继续使用 admitted A；只有后续 Turn B 使用新 Expert。

Prompt section 使用 `PromptSource.USER_CONFIGURATION` / USER trust，并显式声明 Expert 是 behavior guidance，不是 authority。

### 7. Other conversation Reference

Reference 没有把 live `sourceSessionId` 指针交给 Turn。Composer 只保存轻量选择；真正 submission 时冻结 bounded snapshot：

```text
Composer selection
  → submission
  → existing summary 或 bounded recent messages
  → immutable content + SHA-256
  → accepted SessionInput
  → USER message_reference_snapshots
  → model context
```

新增：

- `message_reference_snapshots`
- SessionInput 的 reference content-addressed fields
- `ConversationReferenceIntent`

Queue 与 Steer 都携带已冻结的 ContentStore reference，因此排队期间源会话继续变化、归档或删除都不会改变已接受输入；active Turn 不持 live Session pointer。

模型上下文把引用包在 `UNTRUSTED_CONVERSATION_REFERENCE` 中，明确它只是 quoted context，不能作为 authority / permission / approval / policy。

Reference 被归类为 `HIGH_SENSITIVE_CONVERSATION_REFERENCE`，发送前走 per-send egress confirmation，且 credential guard 会扫描冻结正文。

### 8. Export / privacy / GC

clean-slate Room v1 baseline 从 46 表增至 **48 tables**：

- `session_experts`
- `message_reference_snapshots`

不新增 migration；pre-release 内部旧 schema 不兼容。

Session export 的边界：

- Expert 是 Session configuration，与 permission/run-control 一样不进入 conversation export；
- Reference 是实际 model-visible history，新增 `conversation_reference` record，并导出其 frozen content 与 provenance edges。

ContentStore GC / privacy deletion 的引用计数包含 `message_reference_snapshots.contentRef`，所以删除源会话不会回收仍被目标消息引用的冻结正文；删除目标会话后可正常回收。

### 9. Message action presentation

Copy 保持原 icon；Edit & resend / Fork 改为 edit / branch icon，保留：

- 48dp touch target；
- TalkBack contentDescription；
- `chat-edit-*` / `chat-fork-*` identity；
- HXA-213/215 durable semantics。

决策记录：HXA-228 冻结“Conversation-first Shell + per-Session config + admission-time Turn snapshot + submission-time immutable Reference”的产品/运行边界。Session config 不成为第二 Turn owner；Expert/Skill/Connector 只提供 behavior/capability binding，不能授予 permission；Other-conversation Reference 只以冻结内容进入历史，不保留 live source Session pointer；长期 Memory 继续由 HXA-230 单独实现。
