# HXA-077 完成记录

日期：2026-09-05

## 结论

HXA-077 完成。官方 Java SDK `1.3.1.Final` 的 JVM record/serialization 与两种 Client
构造可用，但严格 Android R8 因 `java.net.http.HttpClient` 缺失而按预期拒绝；没有通过
`-dontwarn`、删测试或放宽协议边界制造绿色结果。生产方案保持 accepted ADR-0018：稳定
`A2aClientFacade` 后使用工程已有的 OkHttp + kotlinx.serialization 最小 A2A v1.0 Client。

## 验收证据

- JVM：官方 SDK fixture 与最小 facade 3 个 transport/boundary fixture 全绿。
- 严格 R8：官方 SDK 以固定 `missing-java.net.http.HttpClient` 原因拒绝；最小方案在
  `minApi=29` 生成 `programJars=8 dexBytes=15544 methodIds=169 classDefs=36`。
- Android：独占 API 29 / API 36 arm64-v8a 模拟器各 3/3，通过 JSON-RPC、HTTP+JSON、
  SSE、取消、`Last-Event-ID` 同 Task 重连、1 MiB、Bearer、HTTP 401、TLS failure、
  cleartext 门禁、非法 JSON 与超限拒绝。
- release/R8：consumer/developer unsigned APK 均成功；分别为 39,710,490 / 40,014,278
  bytes，方法引用总数为 190,228 / 191,675。App 数字是合入后总量，不伪称 A2A 独占
  增量；隔离候选成本以上述严格 R8 数字为准。
- 许可证：`extensions:a2a` runtime closure 已由 lockfile 固定；Kotlin stdlib、OkHttp、
  OkHttp SSE、Okio、kotlinx serialization/coroutines、JetBrains annotations 的对应 POM
  均声明 Apache-2.0。官方 SDK 同为 Apache-2.0，但仅保留在 Spike，不进入生产依赖。

## 设备期修复

1. OkHttp 5.5 的 Android variant 需要 compileSdk 37，而工程固定 compileSdk 36；Spike
   改为与 production `extensions:a2a` 一致地替换为 `okhttp-jvm`，避免以升级 compileSdk
   掩盖候选边界。
2. 取消用例的本地 HTTP fixture 原先把客户端在请求头完成前主动断开误报为服务端失败；
   fixture 现在识别被取消的第三个请求，生产取消语义未降级。

## 决策记录：

- 继续采用 accepted ADR-0018 的最小 Client；官方 SDK 仍不进入 production。
- Android variant 明确锁定 `okhttp-jvm`，不为候选升级 compileSdk。
- App release 数字只报告合入后总量；A2A 独占成本使用隔离严格 R8 结果，避免伪造增量。
- HXA-077 完成只代表 JVM/R8、专项模拟器、unsigned release 和依赖许可证闭包通过；
  不扩大为物理真机或 M12 发布验收。

## 保留边界

物理真机、真实外部 Agent、后台进程回收、签名 APK 与最终完整 SBOM/notice 属于发布
门禁，不属于本地 Spike 已完成证据。HXA-078/079 仍需各自完成生产功能级设备验收。
