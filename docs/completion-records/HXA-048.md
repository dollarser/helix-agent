## 各子项处理

### 1. ChatService turn 模型 —— 核实并统一为每会话模型 + 补 JVM 单测骨架

- **核实并发真相**：代码此前只有一个**全局** `activeTurnJob: Job?`（整个 App 同一时刻只有一个 turn 在跑）外加按 turn 的 `turnCancels`，而 `turnGate` 的 KDoc 声称"每会话只有一个 active turn"。真相是：会话 B 的 send 在会话 A 的 turn 运行期间会被 `if (activeTurnJob?.isActive == true) return` **静默丢弃**，违反 send 路径依赖的"send 绝不能凭空消失"不变量。
- **统一为明确的每会话模型**：抽出纯量 `SessionTurnAdmission`（按 `sessionId` 的 `ConcurrentHashMap<sessionId, ActiveTurn(job, turnId)>`，job 完成时**身份守卫**自删，一个被取代 turn 的过期完成永远不会误删后继 turn）。`ChatService` 侧：
  - `launchTurn` 的准入改为**按会话**判定——只有当**本会话**已有 in-flight turn 才拒绝；另一会话的 turn 不再让本会话的 send 消失。
  - `stop()` 只取消**当前打开会话**的 in-flight turn（`sessionTurnAdmission.activeTurn(openSessionId)` 拿 Job + turnId，取消对应 `turnCancels` 与该 Job），不再误停别的会话。
  - `turnCancels`（按 turnId 的 `ConcurrentHashMap`）及其在 terminalize 的清理**保持不变**。
- **补单元测试骨架**：`SessionTurnAdmission` 是纯量（无 storage / provider / coroutine-context 引用），可在 JVM 单测——而重量级 `ChatService`（具体 Room-backed 依赖、无 Robolectric）无法在 JVM 构造。新增 `SessionTurnAdmissionTest`（5 用例）直接测该纯量，与仓库既有"测抽出的纯量而非重服务"的模式一致（同 `BatchTurnRuntime`/`ChatHistoryBuilder`）。逐会话并发/取消的端到端行为仍归设备列（仪器测试）。
- **新增文件**：`SessionTurnAdmission.kt`（main）、`SessionTurnAdmissionTest.kt`（test）。`ChatService.kt`：删 `import kotlinx.coroutines.Job`、把 `activeTurnJob` 字段换成 `sessionTurnAdmission`、改 `launchTurn` 准入与 `stop()`。

## 决策记录：关键取舍与理由

1. **核实后统一为每会话模型，而非保留全局单 turn**：`turnGate` 的 KDoc 与"send 绝不能消失"不变量都要求每会话一个 active turn；全局单 `activeTurnJob` 会让另一会话的 send 静默丢弃。统一为按 `sessionId` 的准入后，会话 B 的 send 不再被会话 A 阻塞，行为与文档一致。
2. **抽纯量 `SessionTurnAdmission` 承载并发真相，重 `ChatService` 不动**：`ChatService` 依赖具体 Room-backed `HelixStorage`/`ProviderService`/`ToolPipeline`，无 Robolectric 无法在 JVM 构造，直接给它写 JVM 单测不可行。把"每会话至多一个 in-flight turn + 身份守卫自删 + 按会话 stop"抽成无外部依赖的纯量，是补上"目前缺失的 ChatService 单元测试骨架"的唯一可落地路径，也与仓库既有测试模式一致。逐会话端到端并发/取消仍由设备列仪器测试覆盖，不在此用 JVM 假造。
3. **身份守卫自删，防过期完成误删后继 turn**：`invokeOnCompletion` 里用 `=== active` 比对——被取代的旧 turn 完成时不会删掉已接管该会话的新 turn 条目。这是 per-session 模型在"一个 turn 结束、下一个已开始"交接瞬间的正确性关键，有专门用例覆盖。
4. **`WorkspacePath` 是纯死代码，删而非保留**：生产无引用、只被一个镜像测试和一个 oracle 名引用；`FileScopePath` 才是 doc 10 要求的唯一模型可见路径类型。删除 + 收敛 KDoc/文档，消除"两种路径类型"的误导，不改变任何生产路径。
5. **子项 2/4 记录并维持现状，不提前优化**：`usageBytes` 全量 walk、`listDir` 物化-再分页在当前目录规模/使用场景下都产出正确结果，改成有界/增量统计属过早优化，且会引入复杂度。按 roadmap 的"仅当成为实际瓶颈/实际场景才改"，记录边界、留待触发条件出现。
6. **两项不改动项显式写进记录与 status**：`canResumeTurn`/`wakeAllowed` 与空 `tools/*` 占位是审查判定有意保留的 seam/占位，不进本任务；显式记录防止后续实现者当死代码删掉。
