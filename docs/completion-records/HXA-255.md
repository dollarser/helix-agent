# HXA-255：权限页面外发规则应用接口

日期：2026-10-10。Owner request：继续完成架构/测试维护审查剩余工作；按现有授权逐项实施、验证和提交，不新增权限能力。本项应用接口/主机/API36双渠道验收完成。

决策记录：[ADR-PERMISSIONS-003](../adr/permissions/003-dispatch-and-audit.md)追加既有外发规则应用服务、取消/失败及已提交事实不回滚的Decision history；不新增授权来源。

## 范围

外发规则校验、固定TTL与APP scope绑定、仓储读写放入应用服务；页面仅持有窄行模型和表单/操作状态，MainActivity/设置页不传递仓储。保留Advanced渠道/档位入口、精确Provider/MCP目标、撤销、持久重载、现有testTag与错误反馈。取消和致命错误传播，无message错误不得冒充加载中。写入已提交但随后读取失败时如实显示读取错误，不声称回滚。

依据 accepted ADR-PERMISSIONS-003，沿用原仓储/PolicyEngine owner和schema。参考[Android UDF及生命周期](https://developer.android.com/topic/architecture/recommendations)、既有审查中的OpenCode Client边界；只采用窄状态/动作接口，不引入依赖框架或复制竞品代码。

## 验证

新JVM应用接口覆盖读投影、有效创建/撤销、非法目标/端点拒绝、读/写失败、取消/致命错误与已提交后读取失败。保持现有Advanced UI/仓储/Policy断言，默认构建全仓test/detekt/spotless、两渠道Debug lint/App/AndroidTest编译及source gates。设备验证按继续原授权任务的范围使用自有API36，不借用日常实例；不改模型推理，不为结构变化消费模型额度。真实手机及性能关闭不在本切片验收中。

实际结果：新JVM5项每渠道通过；默认构建全仓JVM、静态、两渠道Debug lint/App/AndroidTest通过；新增UI用例修正后再次编译/静态/Developer lint通过。API36 Developer4/4（原真实Room/Activity1、读取失败/新草稿边界2、实际拼音1），Consumer3/3（规则不可达/固定Standard2、实际拼音1），自有进程关闭。源门禁与staged检查通过后提交。

完整命令、制品身份、首次规范origin断言与输入框标签断言失败见[本轮证据](../evidence/development/egress-application-interface-2026-10-10.md)。Activity重建不等同进程死亡；API29/OEM/真机/长稳和卡顿黑屏不由此关闭。剩余审查继续测试桥与ChatService，不以一项完成结束整个授权工作。
