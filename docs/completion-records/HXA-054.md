## 实现的契约

1. **点 1 无限循环**：`while(true){}` 全默认 limits（10 s wall，deadline 自 execute 起始含 bind 时间）→ 稳定 TIMEOUT（service deadline 中断应答，或 client 在 deadline+1 s 宽限后合成）；实测 elapsed 见验收证据（API 36 10.1 s 量级）。中断提前路径（小 deadline = 用户级 limits 设置，非模型参数）由既有 `JsExecutionControlTest.watchdogTimeoutEndsInfiniteLoopAndReclaims`（1.5 s → TIMEOUT）与 `interruptTransactionEndsInfiniteLoopAsInterrupted`（显式中断 → INTERRUPTED）覆盖，本任务未重复。主进程存活 + 新实例恢复执行。
2. **点 2 内存**：64 MiB 堆 OOM 用 HXA-052 固定安全的 32 MiB 数组 fill（1600 万循环在 API 29 SIGSEGV，永不作测试源——status.md 已固定事实）。两台设备 OOM 表面形态按固定事实断言：API 29 → `<empty message>`（caught-null 原样重抛形态）；API 36 → 含 `out of memory`（wrapper 前缀子串存活）。主进程存活 + 后续执行 SUCCESS（OOM 是隔离实例内的 JS 级错误，service 进程存活并正常应答后由系统回收）。
3. **点 3 输出洪泛**：远超 256 KiB 的输出（2 MiB 字符串 / 1 MiB 大对象）经 PFD 输出通道 → 有界失败 OUTPUT_LIMIT：**输出文件保持 0 字节**（wrapper 边界检查在任何字节落盘前抛出）、结果无输出字节、detail 有界（≤2048）且含 marker + 实测长度；主进程内存无明显异常（后续执行 SUCCESS 即证据）。256 KiB 恰好边界 SUCCESS（262144 字节经 PFD 读回）、+1 字节（262145）→ OUTPUT_LIMIT（client 全链路视角断言状态与 detail；wrapper 层字节边界归 HXA-052）。
4. **点 4 eval/fetch/require**：生产链路上**真实调用尝试**（调用而非 typeof 探测）全部 fail-closed：`fetch`/`require`/`XMLHttpRequest`/`WebSocket`/`java`/`android` 调用 → JS_ERROR（ReferenceError 类，detail 带 wrapper 前缀 + 点名全局）；eval 直接/括号/间接 + `new Function` → JS_ERROR 且 detail 含引擎 `eval is not supported`。与 HXA-052 19 例 wrapper 层断言兼容（同状态、同前缀语义），全部尝试后主进程存活 + 下一次执行 SUCCESS。
5. **点 5 进程崩溃**：复用既有 debug crash seam（BuildConfig.DEBUG ∧ FLAG_CRASH_INJECTION 双门，HXA-053 生产路径恒不设置；未新增任何 seam）→ client 稳定 CRASHED（elapsed ≈ 250 ms seam 量级，**不重放**到 10 s deadline、无假成功、无未处理异常）。设备证据：daemon 观察线程 10 ms 轮询 `:helix_js` PID，崩溃后观察到的隔离 PID 从 `runningAppProcesses` 进程表消失；主进程（测试自身进程）PID 存活；下一次执行（新 instance name）SUCCESS 且不复用崩溃 PID。若观察窗口错过短命 PID，CRASHED 结果本身来自 `DeadObjectException`（内核 binder-death 信号）——实例进程确实死亡。logcat 关键行见验收证据。
6. **点 6 Binder 大输入**：256 KiB 边界源（PFD）+ 2 MiB 边界输入（PFD）全链路成功往返，大数据值校验（输入：len + 末 64 字符与宿主侧 pattern 构造逐字节比对；源：字面量长度回读——截断即破坏字面量 fail-closed）；合法 3 MiB 输入超默认 2 MiB 上限 → REQUEST_REJECTED（client 预检 `exceeds maxInputBytes`，**不产生实例**）；>64 KiB inline 且无 PFD 通道（直接 binder）→ 服务端 fail-closed REQUEST_REJECTED（`use a source PFD` / `use an input PFD`），绝不静默截断。
7. **点 7 取消竞态**：三种竞态各收敛到稳定终态——(a) cancel vs bind → {CANCELLED, INTERRUPTED}；(b) cancel vs 执行中 → {CANCELLED, INTERRUPTED}（绝不 SUCCESS）；(c) cancel 在结果就绪后 → SUCCESS（迟到 cancel 不抹掉完成）。50 轮/竞态提高命中率，每轮有界等待（deadline + 宽限），类级 900 s Timeout 兜底。**同一 execution 绝不执行两次**：每轮恰一个终态结果（client 不重试/不盲放）+ 一次性槽位设备侧探测（同实例第二次 EXECUTE → REQUEST_REJECTED `already used`；实例已回收则同名 rebind 是新实例新 PID，亦非重放）。JVM 侧终态收敛分类（11 状态穷举映射、取消收敛集、CRASHED/UNKNOWN 不确认零副作用）由 `JsStatusConvergenceTest` 经真实 tool executor + fake JsExecutor 覆盖。
8. **点 8 verified artifact**：client 采信 PFD 输出为成功结果的**前提是 size + SHA-256（宿主侧独立重算）+ 输出契约**校验通过。正常路径 E2E：200 KiB PFD 输出，测试宿主侧重算文件 SHA-256 == 结果声明、size 一致、回读字节与文件逐字节一致、input hash 独立可复算（`outputSha256Hex` 可独立复算 = auditable artifact 的宿主侧落点，§4.8 审计字段同源）。失配路径（hash/size/契约任一失配 → 稳定 UNKNOWN 不采信）：真实 service 不会声明不符的 hash，设备链路无法构造失配——按任务要求用 JVM 注入点（从 client 提取的纯函数 `JsOutputArtifact`）覆盖全部失配分支，**未加新生产 debug seam**。
9. **§10 剩余 QuickJS 项**：Unicode/NUL 字节（字符串含 NUL + ZWJ 组合 emoji）输出方向 round-trip 字节精确（输入方向归 HXA-052）；深 JSON 嵌套输出方向 200 层与宿主侧构造逐字节一致（输入方向 300 层归 HXA-052）；循环对象 → wrapper marker 语义 → OUTPUT_LIMIT fail-closed（既有 JVM `JsResultJsonEncoderTest` 覆盖 raw 编码器环拒绝，本任务首次设备侧固定引擎真实消息）。

**新固定的引擎事实（本任务设备测试发现并修正）**：Zipline 1.27.0 / QuickJS 2021-03-27 build 中，`JSON.stringify` 环引用结构抛的 TypeError 消息是裸的 **`circular reference`**，而非 HXA-052 假设的 V8 措辞 `Converting circular structure to JSON`（该措辞不存在于 QuickJS 二进制——strings 佐证；两台设备实测 detail == `circular reference`）。HXA-052 的 `CIRCULAR_RESULT_MARKER` 是**从未被设备验证**的假设常量（052 只以 JVM 固定了常量值本身），导致 service 的环引用 → OUTPUT_LIMIT 重分类分支实际不可达（环引用结果被分类为 JS_ERROR）。HXA-054 将常量修正为设备固定措辞并重分类恢复可达——这是 HXA-054 攻击测试直接暴露并修复的最小生产修正（同属本任务范围，非 HXA-053 记录的两个范围外缺陷）。
