## 前置与范围

前置：HXA-044（SAF 受限导入/导出管线 + 反谎报防御 + 原子发布 + 临时文件回收）、HXA-046（文件管理 UI 门面 `FileManagerService`）、HXA-057（persisted SAF tree scope：`SafGrantStore` + 每次使用实时复核 + 只读浏览后端）。

任务书（`docs/development/roadmap.md` §9B，`### HXA-058`）：在文件管理器接通 HXA-044 的受限 import/export pipeline——导入使用 `ACTION_OPEN_DOCUMENT`/`ACTION_OPEN_DOCUMENT_TREE` 的用户选择复制到 Workspace，导出使用 `ACTION_CREATE_DOCUMENT` 或用户已授权 tree，把 Workspace 快照流式写出；UI 必须展示来源、目标、名称、大小、冲突策略、进度、取消和最终结果；导入/导出是明确的文件管理动作，不自动创建聊天消息、不自动发给 Provider，也不扩大 Agent scope；覆盖同名冲突、部分流、大小谎报、磁盘满、目标撤销、取消、进程回收、原子性和临时文件回收；导出后重新读取/校验可得证据时才显示 verified，否则只报告平台确认的实际结果。

**交付**：① 单文件导入（`OpenDocument` picker → `input/`）、整文件夹导入（`OpenDocumentTree` picker → 有界枚举 + fail-closed 名称规划 → `input/<结构>/`）；② 导出（`CreateDocument` picker 或 HXA-057 已授权 SAF tree，WRITE 实时复核后 create-document + 流式写出 + 平台大小复核 + **字节级重读校验**）；③ 冲突策略四选（ASK 默认/SKIP/RENAME/OVERWRITE，导入 OVERWRITE 先移回收站）；④ UI：来源、目标、名称、大小、进度、取消、逐项目最终结果（成功/冲突/跳过/已取消/失败 + 细节 + 已校验标记 + 临时文件回收行）；⑤ 失败矩阵覆盖（见下）。**导入/导出是文件管理动作**：不创建聊天消息、不调 Provider、不触碰 Agent scope。

## 实现的契约

**UI 契约（任务书逐条）**：来源（文件/文件夹；Workspace 相对路径或 SAF scope 显示名）、目标（`input/` 或新文档或"SAF 来源/子目录"）、名称（净化后的目标名/逐项目来源→目标）、大小（来源自报/已写字节）、冲突策略（ASK 默认/SKIP/RENAME/OVERWRITE，**绝无默认覆盖**）、进度（单文件 `done/total` 字节；文件夹 `第 n/total 个文件`；导出 `done/total` 字节）、取消（`SafCancelToken` 接入管线，取消即终态 CANCELLED）、最终结果（逐项目状态+细节+`（已校验）`标记+临时文件回收行）。导入/导出全程不创建聊天消息、不发 Provider、不扩大 Agent scope（纯文件管理动作，UI 直达管线，无 Tool/Policy/Approval 路径）。

**失败矩阵覆盖（任务书 → 测试映射）**：

| 失败模式 | 覆盖测试 |
| --- | --- |
| 同名冲突 | JVM facade 单文件 ASK/SKIP/RENAME/OVERWRITE + 树内逐文件 ASK + 树导出 ASK/SKIP/RENAME/OVERWRITE（含"OVERWRITE 复用现有文档"断言）；设备 `SafTreeDestinationDeviceTest`（同名 FAE / overwrite 复用 / 歧义 fail closed）+ `exportToATreeWithASameNameUnderAsk`（冲突后原字节不变）；UI 四策略行 |
| 部分流 | JVM 取消导出（目标留 128KiB..全量之间的部分字节——content URI 不可截断）+ 设备 `exportCancelledMidCopyIsReportedCancelled`；verifier 截断重读测试 |
| 大小谎报 | JVM 谎报导入（fail closed 0 发布）+ 设备 `importSingleUnderReportedSizeFailsClosedPublishingNothing`（`under` 文档）+ 导出谎报目标（`liar` sink → FAILED，verified=false） |
| 磁盘满 | 流中断 IOException 路径（JVM dying-stream 导出 + 目标不可写）——真实 ENOSPC 不模拟（决策 8）：管线对流中断的 fail-closed 行为（无假成功、无临时残留）即磁盘满的表面形态 |

| 取消 | JVM 预取消导入 / 树导入分界（tick 前完成、tick 后取消）/ 导出取消；UI 取消按钮 |
| 进程回收 | 每次操作前 `reclaimTempFiles` + 崩溃遗留 `.helix-tmp-*` 被回收（JVM + 设备 `aCrashedLeftoverTempIsReclaimedByTheNextTransfer`，`TransferResult.reclaimedTempFiles` 计入并显示）——真实进程中途 kill 不在进程内模拟（决策 8，先例 HXA-056） |
| 原子性 | 拒绝/取消 0 发布（`AtomicFileWriter.cleanup == 0` 断言）；导入只在 EOF 精确大小复核 + MIME 重探测通过后原子 rename 发布（HXA-044 既有，本 HXA 复用不重写） |
| 临时文件回收 | 同上 seam + UI 回收行（>0 时显示） |

## 设备阶段：验证中缺陷（仲裁会话发现并修复，全部随本 commit）

1. **【生产】`ContentResolverSafTreeLister.children()` 空游标 fail-open**：平台在 authority 无 provider 应答时 `ContentResolver.query` 返回 **null 游标（不抛异常）**；原实现 `cursor?.use` 把 null 当"无子节点"→ 静默返回空树，违反自身 KDoc 契约。修复：null → `SafTreeEnumerationLimit`（设备 logcat 实锤）。
2. **【生产】`ContentResolverSafTreeDestination.children()` 同型空游标洞**：null 游标 → 冲突判定无法做出。修复：null → `FileNotFoundException`（fail closed，绝不假设"无同名"）。
3. **【fixture】两个 in-APK 树 provider 的 create-document insert URI 形态**：`DocumentsContract.buildDocumentUriUsingTree(treeUri, docId)` 实为 `treeUri.buildUpon().appendPath("document").appendPath(docId)` → **`tree/<root>/document/<parent>` 4 段**（logcat 实锤 API 29/36），原 fixture 只匹配 2 段 `document/<parent>` → insert 全部落空。`ExportSinkTreeProvider` 与 `TransferTestDocumentsProvider` 均修复。
4. **【fixture/architecture】app 模块 androidTest provider 跨 uid 不可达**：app 模块 instrumentation 运行在 **app 进程**（`com.helix.agent`），而 androidTest manifest 注册的 provider 属于 **test 包**（`com.helix.agent.test`，不同 uid）——`exported=false` 时 app 进程 `SecurityException: not exported from UID`；且 test 包进程一旦崩溃，全部 query 静默降级。
5. **【fixture/architecture】test 包进程无 Kotlin stdlib**：app 模块 androidTest APK **不含 kotlin-stdlib**（AGP 即使显式 `androidTestImplementation(kotlin("stdlib"))` 也不 dex 进 test APK——依赖解析出 JVM 变体且打包排除，dexdump 实锤；feature 模块 test APK 含 stdlib 故其 Kotlin provider 无此问题）。Kotlin provider 在 test 包进程 `attachInfo` 时 `NoClassDefFoundError: kotlin/jvm/internal/Intrinsics` 崩溃（logcat 实锤）。修复：`TransferTestDocumentsProvider` 重写为**纯 Java**（`app/src/androidTest/java/`，仅依赖框架类；test 类仍在 app 进程运行、stdlib 由主 APK 提供，故只有 provider 需 Kotlin-free）；provider `exported=true`（test APK 永不分发，无生产面）。
6. **【fixture】OpenableColumns 列名错误**：`OpenableColumns.SIZE` 实为 **`"_size"`**、`DISPLAY_NAME` 实为 **`"_display_name"`**（下划线前缀）——原 fixture 用 `"size"/"display_name"`，按名读取的 metadata reader/size re-check 永远取 -1/null（症状：导入名静默降级 `imported-file`、谎报大小用例误 COMPLETED、export 永不可 verified）。修复：fixture 列改用 `OpenableColumns` 常量。
7. **【测试架构】API 30+ 无法为 in-APK fixture provider 铸造持久化 WRITE**：`takePersistableUriPermission` 需先有临时 intent grant（平台规则，API 29 允许而 API 36 拒绝——设备实锤）。修复：facade 测试新增 `WritableOverrideCheck` seam（`real.verify(treeUri)?.copy(writable = true)`——liveness/authority/rootDocId/readable 全部保持真实，仅强制 write 位）；**写门 fail-closed 侧仍由真实 check 无 seam 设备验证**（`exportToATreeWithoutAWritePermissionFailsClosed`）。UI 导出正向 verified 回合改投 facade 层（WRITE 事实全真实），UI 层验证**只读 grant 经全 UI 路径被拒且树 0 写入**。
8. **【生产】文件管理器工具栏/预览动作行溢出 → 尾按钮零宽不可点**：1080px 门设备实测 `导入` 按钮 `size=0×148`、预览 `导出` 按钮 `size=0×148`（真实用户同样点不到，非仅测试问题）。修复：FilesScreen 工具栏拆三行（排序 / 视图 / 动作）、预览 confirmButton 拆两行——各按钮恢复真实宽度（设备复测 `152×105` 且 dialog 正常打开）。
9. **【review 发现，有意不改】`ContentResolverSafTreeReader`（HXA-057）存在同型空游标模式**，但生产路径上每步读取前都先经 `ContentResolverSafTreeCheck` 实时复核 liveness（null 游标 ⇒ grant 失效 ⇒ fail closed），洞被上游治理——保持不动，此处记录以免后续读者误判为漏修。

## 未实现范围（显式）

1. **真实 ENOSPC（磁盘满）不模拟**：以流中断 IOException 路径覆盖 fail-closed 语义（决策 8）。
2. **真实进程中途 kill 不模拟**：以崩溃遗留临时文件回收 + 每次操作前 `reclaimTempFiles` 覆盖（决策 8，先例 HXA-056）。
3. **OS 系统 picker（文档/文件夹/新建文档选择器）不做设备驱动**：点击到 picker 的往返由 `ActivityResultContracts` 标准能力承担（项目先例）；picker 回调之后的全链路（导入管线 / 导出管线 / 落树校验）由设备测试覆盖。
4. **导入不持久化 tree grant**：`ACTION_OPEN_DOCUMENT_TREE` 是一次性 grant（导入把字节复制进 app-private workspace 后即不再需要外部引用）；持久化授权树**只**服务 HXA-057 的只读浏览与**导出**目标（WRITE 实时复核）。
5. **SAF 写后端（浏览树内的通用写变更）仍未实现**——本 HXA 的"导出到授权树"是任务书明确要求的受限写路径（create-document + 管线写出），不扩大 HXA-057 的只读浏览边界；`FileManagerService` 对 SAF scope 的变更入口仍 fail-closed（`SAF 来源为只读`）。

## 决策记录：关键取舍与理由

1. **复用 HXA-044 管线，只加 `onProgress` 尾参**：管线本身（准入上限/流中硬上限/EOF 精确复核/MIME 重探测/净化/原子发布/临时回收）不动、不放宽；`importDocument`/`exportFile` 末尾追加可选 `onProgress` 参数（默认 no-op），既有调用方与既有测试零改动。文件管理器只做"UI → 门面 → 管线"的接线与结果映射，不复制任何防御逻辑。
2. **planner 歧义语义：目录只计一次、文件逐条计数**：若目录节点也按文件计数，任何多文件共享的子目录都会误报"歧义"——目录是路径前缀不是命名冲突。净化后 (父目录, 子名) 键（NUL 分隔，净化器剥掉全部控制字符故无碰撞）计数 >1 ⇒ 双方（及其全部子孙）整体跳过且**每个被跳过的文件都有可见 skip 项**（绝不静默省略、绝不猜测）。
3. **create-document 用 `resolver.insert(buildDocumentUriUsingTree(...), {mime, display_name})`**：compile SDK 36 的 `DocumentsContract` stub 没有 5 参 `createDocument` 重载；该 insert 与 `createDocument` 的内部实现是**同一个操作**（对父目录文档 URI 的 insert + MIME/显示名 values）。设备测试固定其真实语义（新文档创建、写入可见、metadata 回报）。
4. **verified = 字节重读证据，绝不外推**：平台确认（写入完成 + 目标自报大小复核）与字节级校验是两档，分别报告（`sizeVerified` vs `verified`）。`SafExportVerifier` 要求"读满且仅读满"（少=截断、多=目标含未导出字节）+ SHA-256 相等；任何证据缺失 → false，UI 降级到"仅平台确认"文案。这直接实现任务书的"重新读取/校验可得证据时才显示 verified"。
5. **导出到授权树先 WRITE 实时复核再写**：`SafTreeScopeService.resolve(scopeId, WRITE)`（HXA-057 的 7 步复核，含 `persistedUriPermissions` 写权限判定）在任何字节写出前执行——只读 grant/撤销 grant/URI 变化全部 fail closed 且 0 写入（设备测试 `exportToATreeWithoutAWritePermissionFailsClosed` 断言 0 字节）。
6. **picker 往返不进设备测试（项目先例）**：OS 系统 picker 是非受控组件，设备测试从 picker 回调之后开始（`FileManagerTransfers` 门面 + 真实管线 + in-APK provider）；UI 测试覆盖对话框全要素与"对话框 → 结果面板"的点击链路（导出用例用真实 `SafGrantStore` grant + `takePersistableUriPermission` 构造可写授权树）。
7. **设备测试的持久化 WRITE 权限用 `takePersistableUriPermission`（设备阶段修订）**：原计划同进程 take 后与生产 `persistedUriPermissions` 读同一持久化集合；设备阶段实锤 **API 30+ 拒绝为无临时 intent grant 的 URI 铸造持久化权限**（API 29 允许）——in-APK fixture provider 拿不到持久化 WRITE。修订：facade 测试用 `WritableOverrideCheck` seam（`real.verify(treeUri)?.copy(writable = true)`，liveness/authority/rootDocId/readable 全部真实，仅强制 write 位）；**fail-closed 侧（无写权限 → 0 写入）仍由真实 check 无 seam 设备验证**；UI 层正向 verified 回合因此改在 facade 层验证（WRITE 事实全真实），UI 测试验证只读 grant 经全 UI 路径被拒且树 0 写入（见"验证中缺陷"7）。
8. **磁盘满/进程 kill 用替代证据（与 HXA-056 同口径）**：进程内无法安全地制造真实 ENOSPC 或杀掉自己的进程；fail-closed 的可观察语义（流中断 → 无假成功、无临时残留、目标可能留部分文档且被如实报告）由 dying-stream/损坏目标测试覆盖，进程回收由崩溃遗留临时文件回收测试覆盖。
9. **未接线 fail closed**：`FileManagerService` 的 `transfers` 束可选（`null` 兼容既有测试/调用），但 null 时三个传输入口返回显式 `FAILED "导入/导出未接线"`——绝不静默成功或假装完成。
10. **ADR 状态**：不适用——本 HXA 不形成新架构决定：文件管理器的导入/导出是用户驱动的文件动作（非模型 ToolCall，不经 Policy/Approval），复用 ADR-0012 capability-first 下既有的"用户动作可授予 scope"边界；HXA-044 的管线契约（fail-closed、原子、模型不透明）与 ADR-0014 附件边界均未被触及或放宽；无新 proposed ADR。
11. **（设备阶段新增）test 包内的 ContentProvider 必须 Kotlin-free**：app 模块 androidTest 的 provider 运行在 test 包自己的进程（`com.helix.agent.test`），其类路径只有 test APK——而 app 模块 test APK 不含 kotlin-stdlib（设备实锤 `NoClassDefFoundError: kotlin/jvm/internal/Intrinsics`），provider `attachInfo` 即崩、test 包进程随后不可用。故 `TransferTestDocumentsProvider` 用纯 Java 编写；feature 模块 test APK 含 stdlib，其 Kotlin fixture 不受此限。
12. **（设备阶段新增）平台 `ContentResolver.query` 空游标语义 = "无 provider 应答"**（不抛异常）：一切按 children 查询的生产读取端（list/destination）必须把 null 游标当 fail-closed 信号而非空集合；已修 lister + destination 两处，并记录 `ContentResolverSafTreeReader` 的同型模式由上游 `SafTreeCheck` 治理（"验证中缺陷"9）。
