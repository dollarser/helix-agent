    - `ResponsesSse.kt`：`internal class ResponsesSseParser`——增量 SSE 解析器（WHATWG 契约）：
      - 任意字节边界拆包：行中、字段中、多字节 UTF-8 序列中均可切断；尾部不完整序列最多缓冲 3 字节等待下一 chunk。
      - 逐字节 UTF-8 解码（无平台解码器依赖）：序列长度判定、续字节校验、**组装后** code point 做 overlong/越界检查（2→≥0x80、3→≥0x800、4→≥0x10000 且 ≤0x10FFFF）；坏字节 → 解析失败。
      - 行尾 LF/CRLF/裸 CR；`:` 注释行；`field: value` 仅剥一个前导空格；无 `:` 的裸字段 = 空值；多 `data` 行以 LF 连接；空 `event` 类型（含裸 `event` 字段）→ `message`。
      - `feed(chunk)` 返回已完整事件；`finish()` 在流尾派发仍携带 data 的挂起事件（宽容尾），截断的半行按 spec 丢弃（由解码器终止守卫转为可重试 `Error(PROTOCOL)`）。
      - 有界防护：单行 ≤1 MiB、单事件 data ≤8 MiB，超限即失败（不可控输入不得无界增长）。
    - `ResponsesStreamDecoder.kt`：`public class ResponsesStreamDecoder`——vendor SSE 事件 → `ModelEvent` 映射（doc 10 §2.1：Agent Loop 不读 vendor JSON）：
      - 每流至多一个终止事件；`response.completed`（status `completed`）→ 可选 `Usage` + `Completed`（finish reason：含 function call 则 `tool_calls` 否则 `stop`）。
      - `response.failed` / 流中 `error` 事件 → `Error`，vendor code 映射：`rate_limit_exceeded`→RATE_LIMITED(retryable)、`server_error`→SERVER_ERROR(retryable)、`content_filter`→CONTENT_FILTER、`invalid_request_error`→PROTOCOL、未知码→SERVER_ERROR 但 **retryable=false**（fail-closed，Agent Loop 不得盲目重发）。
      - 内容过滤两段式：`output_item.done`（`incomplete_details.reason=content_filter`）只置 `pendingRefusal` 不发事件；`response.incomplete`（响应级 reason 权威）发 `Usage` + `Refusal("content_filter")`（合法完成，doc 02 §6.1）；只发 item 级信号的服务端由 `finish()` 补发 Refusal；`max_output_tokens` → `Completed("length")`。
      - 无终止（流结束/断流）→ `Error(PROTOCOL, retryable=true)`（连接级故障，重试可能成功）；已终止事件后再现受理事件、非法 JSON、缺必填字段 → `Error(PROTOCOL, retryable=false)` 且解码器停止产出。
      - `output_index` 作工具事件 index（vendor 分配、每 item 唯一，界 0..1024）；单响应工具数 ≤32（与 core:agent `ModelTerminal.ToolCalls` 同界）；vendor call_id 越 `ToolCallId` charset → 整流失败（不产生部分事件，HXA-021 契约）。
      - 未知事件类型一律忽略（前向兼容）；诊断字段 `failure` 只含异常类名/vendor 字段名，不含 vendor 载荷。
      - vendor 事件内违约以内部 `ProtocolViolation` 抛出、由 `handle` 单点收敛为唯一的 `Error(PROTOCOL)` 事件——解码器对外永不抛异常（vendor 数据是攻击面）。
    - `ResponsesRequestEncoder.kt`：`public class ResponsesRequestEncoder(imageResolver: ImageResolver)`——`ModelRequest` → 无状态 `input` 数组请求体（doc 02 §6.2 stateless，不用 `previous_response_id`——Ollama 兼容，doc 10 §2.5）：
      - SYSTEM/USER/ASSISTANT → `message`（content parts：assistant `output_text`，其余 `input_text`）；TOOL → `function_call_output{call_id,output}`。
      - USER 图像经注入的 `ImageResolver`（`ImageReference` → `ImagePayload.Base64/Url`）解析为 `input_image`（data URL 或公共 URL）；URL 校验非空白、无控制字符；resolver 抛 IAE 原样上抛（fail-closed，无占位）。
      - `tools`（`parameters` 由严格解析器校验为 JSON 对象后逐字嵌入）、`temperature`/`max_output_tokens`/`seed`/`stop`/`reasoning.effort`（`name.lowercase()`，OFF 省略）仅在设置时出现。
    - `OpenAiResponsesAdapter.kt`：`public class OpenAiResponsesAdapter(imageResolver)`——协议岛门面：`requestBodyEncoder`（无状态，可复用）+ `newDecoder()`（每流一个新解码器）。HTTP transport（endpoint/Authorization 取自 HXA-020 ProviderConfig/SecretStore、重定向、非 2xx→`Error` 映射、超时）属 HXA-025，本模块无 HTTP 依赖。

- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  - **协议岛与 transport 分离**：本模块只做请求编码 + 流解码（纯字节进、内部事件出）；endpoint/Authorization/重定向/非 2xx 映射/超时全部留给 HXA-025（`ModelProvider` 接口 + `OkHttp` 届时进入依赖）。非 2xx 响应体不是 SSE 流，KDoc 明确禁止喂给解码器。
  - **retryable 二分语义**：流无终止/断流 = 连接级故障 → `PROTOCOL(retryable=true)`；已终止后事件、非法 JSON、缺字段、charset 越界 = vendor 输出违约 → `PROTOCOL(retryable=false)`。未知 vendor error code → `SERVER_ERROR(retryable=false)`（fail-closed，未知不重试）。
  - **两段式 refusal**：item 级 `output_item.done(content_filter)` 只置位、响应级 `response.incomplete` 权威发事件——匹配 vendor 实际事件序（避免把 item 级信号当终止而误杀后续合法的 usage/incomplete 事件），同时 `finish()` 兜底最小化服务端。
  - **SSE 尾语义**：`finish()` 宽容派发“有 data 但缺尾随空行”的挂起事件（良构事件的常见省略）；截断半行按 WHATWG 丢弃——两条路径分别落为 Completed（若恰好是终态事件）或可重试 `Error(PROTOCOL)`。
  - **vendor 违约走内部异常单点收敛**：`ProtocolViolation` 只在 `handle` 内被捕获并转为唯一 `Error(PROTOCOL)` 事件——对外零异常（vendor 数据是攻击面），同时避免每个 handler 重复终止逻辑。
  - **detekt 定点豁免（2 处，均有注释理由）**：`ResponsesStreamDecoder` 类级 `@Suppress("TooManyFunctions")`（函数数 = 10 个 vendor SSE 事件处理器 + 访问/emit 助手，拆分多类只增加间接层）；`handleOutputItemAdded` 函数级 `@Suppress("ThrowsCount")`（每个 throw 是独立 vendor 契约违约，fail-closed 要求首个即停）。沿用 HXA-020 `fromStorage` 定点豁免先例。

- 排障记录（真实证据，供后续参考）：
  - UTF-8 overlong 检查首版作用在“截断 leading 值”上（组装续字节之前），全部多字节字符误判失败 → 改为组装完整 code point 后统一做 `cp >= minCodePoint(length) && cp <= 0x10FFFF` 检查。
  - `minCodePoint(4)` 首版写成 `0x10_0000`（=0x100000，多一位十六进制）导致 4 字节序列全部失败 → 改 `0x1_0000`；诊断手段为临时 println 打印 `cp/min/valid` 三分量布尔值后删除。

  - content_filter 拒绝事件序首版把 item 级 `output_item.done` 直接当 Refusal 终止 → 后续合法的 `response.incomplete` 被终止守卫判为违约 → 改两段式（item 级置位、响应级权威）。
  - Kotlin raw string 中 `\\` 是字面双反斜杠（不是转义），JSON fixture 用 raw string 构造会破坏转义 → 所有含引号的 fixture 改显式字符串拼接 + `jsonStr()` 助手（拼接形态同时满足 MaxLineLength 120）。
