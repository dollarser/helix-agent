# HXA-094：Root 依赖与授权生命周期验收

日期：2026-09-17。状态：completed（Root 专项范围）。验收基线 `50ff7432` 加本次具名 Root 改动，在 `codex/hxa094-095-acceptance` 独立工作树完成；不代表并行 main 的全量集成验收。

## 决策记录：

沿用 [ADR-RUNTIME-004](../adr/runtime/004-root-service.md)。catalog、tools/root lock 和 Maven 验证元数据使用 libsu core/service 6.0.0；JitPack exclusiveContent 仍仅允许该 group，没有升级依赖或扩大仓库源。

Root 管理器修改策略会拒绝未来请求，不保证主动杀死已开放 shell。本轮验证的撤权链为：真实 grant/CONNECTED → 用户在 Mask 改拒绝 → 生产 onAppBackgrounded 失权/关闭 → 新的显式请求 DENIED。没有把管理器策略变更冒充即时被动撤权事件，也没有用宿主 adb 的 Root 替代 App 授权。

## 修复与交付

- 新增真实 App 的前后台与两阶段进程重建验收。App 通过设置页申请 Root，host 时间线仅观察其 su、Binder 返回的 RootService PID 与清理结果。
- 修正 Compose 虚拟时钟轮询、后台页面不可见时的状态读取、恢复前台 Intent 的身份/启动标志以及 teardown 使用 Application context，避免 UI 假停滞和 ActivityScenario 失去跟踪。
- App 重建使用一次安装、两次 `am instrument`；setup 硬杀进程，verify 保留 marker。不能用会卸载数据的两次 Gradle connected 运行代替。
- 时间线明确跟踪可重挂父进程的 RootService PID；验证窗口必须有活进程样本；清除上轮中断的阶段标记；包缺失连续至少五次且超过六秒才报错。不扫描或杀死其他 App 的 su。
- 撤权等待只在显式 revoked profile 开启，最长 30 分钟；超时必须失败，不能算 skip/pass。用户切到 Mask 后，必要时返回 Root 测试页面再继续，操作步骤见运行脚本。
