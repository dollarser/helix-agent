## 目标与任务书

任务书（`docs/development/roadmap.md` §12 `### HXA-085`）：每次审批；仅 Advanced 且 Runtime 已单独安装、启用并由用户完成过签名/协议/ABI 零 Job 验证时进入工具表，进程预先存活或用户手动打开不是条件，被动 Registry 刷新不得重新绑定。每次执行在批准后重新握手。禁止 Android 主进程 shell、真实 Workspace mount、网络包安装和 secret inheritance；Advanced 或 LAN scope 均不能给 PRoot 增加 INTERNET。UI 区分未安装、未验证、需更新、被禁用/强制停止、连接失败和执行中断；"修复 Runtime"只在用户点击后打开 companion 恢复入口，恢复后重试创建新的 ToolCall/approval/jobId。

前置：HXA-080/081/082/083/084；架构文档 [local-code-execution §6.5/6.6/6.7](../architecture/local-code-execution.md)；[ADR-0007](../adr/0007-companion-runtime-lifecycle.md)（已接受，冷绑定/零常驻/修复入口）与 [ADR-0012](../adr/0012-capability-first-advanced-grants.md)（已接受，generic L2 恒绑 exact ToolCall）。**无新 ADR**——本任务实现上述已接受 ADR 与架构文档既定决定（决策记录见下）。

## 交付

1. **`code.linux.run` Tool（`:app` developer flavor，新增 `LinuxRunTool`）**：
   - **Descriptor**：`CODE_EXECUTION` / base risk `L2` / `ExecutionTargetType.LOCAL_PROOT` / `BuiltInOrigin` / `Idempotency.NON_IDEMPOTENT` / `timeout = 120 s`（Job 预算 60 s + 客户端等待宽限 60 s）。**schema 无网络开关——Runtime 无 INTERNET 权限，Advanced 与 LAN scope 都不能给它联网（§6.1 产品边界）**，"联网：否" 只在审批卡呈现。
   - **输入**（model 可见面，全部上限在 `parsed()` 强制——tool schema 子集不含 `maxProperties`，上限不入 schema）：`argv`（1..256 项）与 `script`（≤8192 字符）**恰一**；`cwd` 严格单段名（`[A-Za-z0-9_-]`，不得 `.`/`..`）；`environment` ≤64 条透传（值筛选在主进程执行前经 084 `ProotEnvScreen` 三重拒绝，理由绝不含值）；`files`（workspace 模型引用，≤64 个，**快照复制**进输入归档，基名去重，单文件 ≤1 MiB，真实 Workspace 目录绝不挂载）；`output`（可选 workspace 模型引用，只接收验证后的 `result.txt`）；`timeoutSeconds` 1..60（只可降不可升，缺省 60）。
   - **审批边界**：`parsed()` 发现审批 deadline 已过期 → `ParseFailure`（该调用必须作为**新 ToolCall** 重新审批——任务书"恢复后重试创建新的 ToolCall/approval/jobId"的结构性落点之一）；审批绑定的是 exact argv/script/参数快照，从不绑定活进程。
   - **每次审批**：generic L2 无任何 Trusted Workspace/batch/auto-run 通路（ADR-0012）——E2E 用真实 `PolicyEngine` 断言 STANDARD profile 下 `Deny(ISOLATED_RUNTIME_REQUIRES_ADVANCED)`（Advanced profile 放行即走正常 approval 解析）。
2. **`ProductionLinuxExecutor`（同文件）**——批准后每次执行的全链（**每次执行重新握手**：084 `ProotJobClient` 每事务冷绑定，绝不复用活连接、绝不因绑定失败回退主进程 shell）：
   gate（每执行现算，零绑定）→ 每调用 scratch 目录（`call-<hex>`，`finally` 删除）→ 输入归档（**经 `WorkspaceArtifactStore` 读**——containment 由 store 强制；缺失/空/超限 → 稳定 `INPUT_BUILD_FAILED`；空文件集是合法空快照）→ 环境筛选（主进程，SecretStore 值按执行时刻现读）→ `ProotJobSpec`（**wire `deadlineMs` 是相对预算**——companion 以 `createdAt + deadlineMs` 为 kill deadline，故传剩余审批窗口 `coerceIn(1_000, 3_600_000)`，watchdog 恰在审批绑定的 deadline 处杀进程组）→ PFD（输入 READ_ONLY / 输出 CREATE|WRITE|TRUNCATE）→ `submit`（Unavailable → 稳定原因：`LOCK_MISMATCH` → `NEEDS_UPDATE`（"需更新"），其余 → `UNAVAILABLE_<CAUSE>`（"连接失败"））→ 取消检查 → `awaitTerminal`（剩余窗口 +30 s，`shouldContinue` 接取消信号）→ 终态映射（非 SUCCEEDED → `Failed("the job ended <STATE> (exit code N)", "JOB_<state>")`，如 `JOB_FAILED`；`AwaitOutcome.TimedOut` → `INTERRUPTED_TIMEOUT`（"执行中断；按 job id 对账，未重放任何内容"））→ `ZipJobExtractor` 重验输出归档（**提取器交付的 manifest 哈希 == 已验证终态记录 `outputManifestSha256`**，否则 `OUTPUT_HASH_MISMATCH`）→ 可选结果导入（`result.txt` ≤1 MiB；**对提取器交付的 `Extraction.manifest` 逐条重验 sha+size**（defense in depth 叠加整 manifest 哈希），只把验证后的字节经 store 写入 `output` 引用的**自身 region**（`input|work|output` 首段判定 + store 强制 containment）→ `Completed`（`state`/`exitCode`/`stdout`/`stderr`（1 MiB 尾截断）/`outputImported`/`outputSha256`）+ `auditDetail`（`jobId`/`executionId`/`inputSha256`/`outputManifestSha256`/`deadlineMs`）。
   - **`result.txt` 缺失/超限 = SUCCEEDED 无导入**（`outputImported=false`）——Job 成功了，只是没交付结果文件；这是发现（finding）而非失败，双流仍完整回报。
   - **绝不重放**：binder 丢失只按 job id 查询/对账或报稳定 `INTERRUPTED`（ADR-0007）；零 FGS、零 wake lock。
3. **可用性 gate 与工具表准入（developer `ProotToolModule` + consumer 空实现，同 FQN flavor 切换）**：
   - gate 四态：`READY`（已安装 ∧ 已启用 ∧ 用户**完成过**零 Job 签名/协议/ABI 验证——以持久化 anchor 存在为准，`ProotRuntimeSupervisor.anchorPresent()` 新增 seam）/ `NOT_INSTALLED`（未安装）/ `DISABLED_OR_FORCED_STOPPED`（被禁用或强制停止，含 `SIGNATURE_MISMATCH`）/ `NOT_VERIFIED`（未验证）。"需更新" 在执行期以 `LOCK_MISMATCH` 稳定出现。**进程预先存活与手动打开修复入口都不是准入条件**；被动 Registry 刷新绝不重新绑定（注册是构建期静态的，gate 只影响执行与 UI 状态行）。
   - `verifyNow`（仅用户点击 Settings 按钮）：冷绑定零 Job 验证并持久化 anchor（用户动作，非启动/切换副作用）；`openRepair`（仅用户点击"修复 Runtime"）打开 companion 修复入口。
   - consumer flavor：`AVAILABLE=false` + no-op `registerTools`——**Standard（consumer）构建里该工具不存在**，与 developer-only 的 PRoot 资产分发一致。
4. **审批卡（`ApprovalCardUi`）**：PRoot 分支展示**完整** `script`（或 argv 全量拼接）+ `codeSha256` 短摘要；输入来源行 = 引用的模型引用列表 +「N 个文件，快照复制，不挂载真实 Workspace」（无输入时显式无输入）；限制行 =「超时 N s（进程组 kill）· 输出上限 8 MiB · 联网：否（Runtime 无 INTERNET 权限）」；`online=false`。
5. **Settings（`SettingsScreen`，Advanced 且 flavor `AVAILABLE` 才渲染）**：PRoot Runtime 区块——状态行（已验证/未安装/未验证/被禁用/强制停止 + 离线执行域与无 INTERNET 声明）、"验证"（off-main 线程执行 `verifyNow`，busy 守卫）与"修复 Runtime"（`openRepair`，仅用户点击）按钮。
6. **接线**：`AppContainer` init 在 QuickJS 注册之后调用 `ProotToolModule.registerTools(...)`（developer 真实 / consumer 空实现）。

## 决策记录：Tool 编排决定（无新 ADR）

- **工具名 `code.linux.run` 而非裸 `bash`**：roadmap 任务标题为 "`bash` Tool"，实现取与 `code.javascript.run`（HXA-053）平行的命名空间名——CODE_EXECUTION 类工具同族、审批/审计/Policy 文案一致；"bash" 语义由描述与审批卡完整命令承载。`bash` 作为公共短名的映射归工具短名接线（roadmap 既有约定），不在本任务改动。
- **进入工具表的准入 = 构建 flavor（developer）+ 每执行 gate**：任务书"仅 Advanced 且 … 时进入工具表"在现有 Tool 框架（注册先于任何运行时状态）下的落法——注册是静态的，**gate 与 Policy 双门在每次执行时强制**：STANDARD 由 `ISOLATED_RUNTIME_REQUIRES_ADVANCED` Deny（真实 PolicyEngine 设备断言），未验证/未安装/被禁用由 executor gate 稳定拒绝。UI 的"未安装/未验证/被禁用"状态行让用户在执行前就知道结果；这比"从工具表移除"更诚实（模型可见 ≠ 可执行），且避免 Registry 动态增删（任务书明令禁止被动刷新重绑定）。
- **wire `deadlineMs` = 剩余审批窗口（相对预算）**：084 runner 的 watchdog 以 `createdAt + deadlineMs` 为 kill 点（设备验证），故主进程传 `deadlineEpochMs - now`（钳制到 1 s..1 h wire 界），保证 **companion 杀进程组的时刻 == 审批绑定的 deadline**，而非"提交后 1 小时"。初稿曾误传绝对 epoch（被 wire 钳制到 1 h——语义错误，设备期修正）。
- **`result.txt` 缺失 = SUCCEEDED 无导入（finding 不是 failure）**：guest 命令成功但没写结果文件（或结果超 1 MiB 导入上限）时，Job 本身是成功的，双流（stdout/stderr 有界回报）仍完整交付；把"没有可导入文件"映射为失败会掩盖真实成功并诱发模型重跑副作用调用。
- **输出导入只认验证后的 `result.txt`，且只进引用自身 region**：Runtime 从不写 Workspace——唯一回传通道是输出归档中显式的 `result.txt`，经提取 manifest 逐条 sha/size 重验 + 整 manifest 哈希对已验证终态记录，再经 store 写入 `output` 引用首段判定的 region（`input|work|output`）；store 的 containment/region 一致性双重强制。模型可指向 `work/` 或 `output/`，但不能越出首段 region 或写入 `.helix/` 内部。
- **环境筛选在主进程、每执行现读 SecretStore**：084 `ProotEnvScreen` 是纯 JVM 筛选器（secret 名 pattern / 已知值 / 认证形状，理由绝不含值）；SecretStore 值在每次执行时经 `storage.secrets` 现读（别名→值），Runtime 全程零 SecretStore 能力——secret inheritance 由构造不可能（guest env = 筛选后 spec 环境 + 固定项，主进程环境不继承）。
- **"恢复后重试 = 新 ToolCall" 的两处结构性落点**：(a) 审批 deadline 过期 → `parsed()` 直接 `ParseFailure`（必须重新审批）；(b) 每次执行构建全新 `ProotJobSpec`（新 jobId/executionId）——companion 侧 084 的"重复 jobId → Duplicate 绝不二次启动"是对账 backstop，不是重试通道。
