    - `Idempotency.kt`：`IDEMPOTENT`/`NON_IDEMPOTENT`。KDoc 钉死重试语义归属（doc 02 §7.2/doc 11 有界技术重试规则）与不确定时默认 `NON_IDEMPOTENT`（误判 IDEMPOTENT=静默双重效果，误判 NON_IDEMPOTENT 只损失一次人工重试）。

- 实现的契约（逐条对照任务书）：
  - BuiltIn/MCP 工具来源：`BuiltInToolSource`（代码固定名集，运行期不可扩展自模型输出）+ `McpToolSource`（单 server 快照→descriptor，溯源绑定 serverId/protocolVersion/hints）。
  - 稳定 name/version/schema hash：`ToolName`/`ToolVersion`（core:model HXA-010 既有值类）+ `schemaHash`（规范序列化+SHA-256，键序不变、语义敏感、`\u0000` 无歧义拼接）。
  - `ToolOperationClass`：契约字段+`visibleFor` 效果类过滤（Plan 视图只出 READ_ONLY，测试用 L0 风险的 LOCAL_MUTATION 证明风险检查不替代）。
  - 风险：`baseRisk: RiskLevel`（契约字段；动态风险评估归 HXA-033）。
  - 限额：`timeout`（≤24h 框架上限）+`maxOutputBytes`（≤8 MiB 框架上限）——契约的一部分而非运行期调参（dispatcher 强制归 HXA-035）。
  - 统一 `Capability`：`requiredCapabilities: Set<Capability>` 直接用 core:model 统一枚举（能力状态描述 app 能做什么，永不替代 per-call Tool Policy）。
  - execution target：`executionTarget: ExecutionTargetType`（目标种类；具体目标实例绑定归 HXA-035）。
  - MCP annotation 不能降类：结构性保证——`McpToolSpec.operationClass` 是 Helix 显式参数（唯一决定分类的面），`serverProvidedHints` 只进 `McpOrigin` 审计位，**无任何代码路径**让 hint 参与分类；MCP 工具 READ_ONLY 在 spec/源/descriptor 三层构造拒绝。
  - 重复注册失败：registry（name,version）唯一，重复=IAE 且注册表不变。
- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  1. **schema 用 kotlinx `JsonObject`**（doc 02 §7 字面形状）：provider 模块 1.9.0 既有 pin 复用，`tools:framework` 以 `api` 作用域暴露（`ToolDescriptor` 公共面含 `JsonObject`）；传递性使已依赖 `:tools:framework` 的 `:extensions:mcp`/`:extensions:skills` lockfile 同步 +5（无新组件、无新版本）。`core:model.internal.Json` 是 internal 且其 KDoc 明示参数 canonical 编码归 Tool 框架——本任务的 schema 规范式独立于它（HXA-031 再实现参数侧的更严格版本）。
  2. **单点强制**：origin/命名空间一致性与 MCP 非 READ_ONLY 只在 `ToolDescriptor` 构造器强制一次；源与 registry 不重复同类检查（registry 只拥有唯一性规则）——避免三处消息漂移，测试按强制点覆盖。
  3. **MCP 工具效果下限=NETWORK 而非“至少非 READ_ONLY”**：MCP 调用必然出站到 server，设备视角效果至少 NETWORK；因此 Helix 自己也不能把 MCP 工具声明为 READ_ONLY（若将来出现纯本地代理的 MCP server，用 BUILT_IN 源或扩展 origin 语义，属后续设计）。
  4. **visibleFor 只暴露每 name 最新版本**：模型工具表是“当前 API”视图；旧版本存在于注册表供审批绑定解析（`resolve(name, version)`），但不出现在新工具表。
  5. **`\u0000` 哈希分隔符**：规范式中不出现原始 NUL 字节（kotlinx 把控制字符转义为 ASCII `\uXXXX`），拼接双向无歧义（input/output 角色互换必换 hash，有测试）。
  6. **`McpToolSource` 快照语义**：一次 `listTools` 快照内每工具名恰一条（重名=协议违规 fail-closed）；版本演化走新的 source 实例 + registry 的 (name,version) 演化路径。

- 排障记录（真实证据，供后续参考）：
  1. **kotlinx `JsonLiteral` 是 internal**：sealed `JsonElement` 公共分支止于 `JsonPrimitive`（覆盖 `JsonNull`）——canonicalizer 的 `when` 用 `is JsonPrimitive` 兜底（编译器 exhaustive 检查报错定位）。
  2. **kotlinx 1.9 API 形状**：`parseToJsonElement` 是 `Json` 成员（包级扩展已移除）；`.jsonObject` 是需 import 的扩展属性——测试初版两处未解引用，对齐 provider 模块既有用法修复。
  3. **check-lockfiles 门禁语义**：脚本自身对 29 模块跑 `dependencies --write-locks`（比 `test` 多解析 `runtimeClasspath` 并归一化配置列表），首跑把 `:extensions:mcp`/`:extensions:skills` lockfile 一并写入（它们依赖 `:tools:framework`，`api` 传递可见性）——提交门禁归一化后的全部 3 个 lockfile，二跑通过；这是门禁设计意图（lockfile 以全量解析为准），非意外漂移。
  4. **MCP 命名 128 总长约束**：`ToolName` 总长 ≤128 → serverId+toolName 合计 ≤123；测试“64+64 边界”组合超限（133）暴露端点取值错误，修正为 64+59（恰 128）。
