## 目标

roadmap M6 / HXA-063「Browser download」+ doc 09（`architecture/android-platform-capabilities.md`）§3.4：

- 「下载必须限制协议、重定向、文件大小、MIME 和目标」；
- 「禁止把下载的 APK/DEX/JAR/SO 自动执行或安装」；
- 「下载到 Workspace/SAF；不自动打开或执行 APK/DEX/JAR/SO」。

本任务把 HXA-060 的策略类 `BrowserDownloadPolicy`（已存在、已有 9 例单测）落地为**模型可调用、可审批、可审计的稳定工具契约**：`browser.download` 工具解析 `url`（+ 可选 `suggestedName`）、经纯 JVM 端口 `BrowserToolBridge.download` 委托纯 JVM `BrowserDownloader`，对真实 `HttpURLConnection` 手动逐跳解析重定向、经策略闸门（协议/重定向/文件类型/声明大小/文件名）、把字节上限流式写入共享 Workspace。本任务**不做** SAF 目标（依赖 HXA-057/058 的 SAF scope 接线，见「未实现/明确排除」）。

## 修改文件

**`:core:workspace`（JVM 模块，共享 Workspace 存储）**：

- **`WorkspaceArtifactStore.kt`**（改，+`writeArtifactStream` 与私有 `CappedDigestOutputStream`）：新增**上限流式写入** `writeArtifactStream(path, region, expectedBytes, maxBytes, sourceInto)`——在 `AtomicFileWriter` 的 temp 之上包一层 `CappedDigestOutputStream`（`delegate` + `MessageDigest` + `maxBytes`），调用方经 `sourceInto` lambda 边写边流；每 `write` 累计已写字节并喂 SHA-256，一旦累计超过 `maxBytes` 即抛 `AbandonedWrite.LimitExceeded`（temp 删除、**不发布**、无半成品）；写成功才原子 rename 并返回带 `sizeBytes`+`sha256` 的记录。这是本任务为「边下边写、服务器可能少报 length 也要守上限」新增的地基——既有的 `writeArtifact` 是「先拿到全量 bytes 再一次性原子写」，无法承载上限流式。
- 私有内聚类 **`CappedDigestOutputStream(delegate, digest, maxBytes)`**：上限流式守护 + 流内 SHA-256，超限抛 `AbandonedWrite.LimitExceeded`。

**`:tools:browser`（纯 JVM 工具契约/端口）**：

- **`BrowserToolBridge.kt`**（改）：端口新增 `fun download(url: String, suggestedName: String): DownloadOutcome` + 有界、**无 null** 视图对象 `DownloadOutcome(status, fileName, finalUrl, reference, sizeBytes, sha256, contentType, reason)`（逻辑缺失值发 `""`）+ 闭合状态枚举 `DownloadToolStatus { SAVED, REFUSED, TIMED_OUT, ERROR }`。端口对**网络/策略条件**绝不抛异常，只有编程错误才抛。

**`:feature:browser`（生产执行器）**：

- **`BrowserDownloader.kt`**（新）：纯 JVM 下载执行器（**无 WebView、无主线程**，故整条生产路径可 host 端到端单测）。`download(url, suggestedName)`：
  1. 非 http URL → REFUSED `url`；
  2. **手动解析重定向**（`instanceFollowRedirects = false`，逐跳把 `Location` 解析为绝对 URL 并**逐跳再校验**为绝对 http(s)；非 http 跳 / 环路 `redirect-loop` / 超 `MAX_REDIRECTS = 5` 即 REFUSED，网络 `IOException` 上抛由 fail-closed 处理）；
  3. 目标名优先级 **Content-Disposition（`filename*` RFC 5987 优先于 `filename=`）> `suggestedName` > URL path > `"download"`**，每个候选都经策略清洗；
  4. 经 `BrowserDownloadPolicy.evaluate` 闸门（协议/后缀/MIME 前缀/声明 size/文件名）→ `Denied` → REFUSED（reason 类别 `url`/`type`/`size`/`name`）；`Save` → `ensureLayout` + `writeArtifactStream`（`maxBytes = BrowserDownloadPolicy.MAX_DOWNLOAD_BYTES` = 100 MiB）把响应体上限流式写入 `output/<name>`；
  5. 结果映射：`SocketTimeoutException` → TIMED_OUT；`AbandonedWrite.LimitExceeded` → REFUSED `size-exceeded`；任何其它网络/磁盘/配额 `Exception` → ERROR。**任何失败都不发布**（store temp 删除）。
  - 常量：`MAX_REDIRECTS = 5`、`CONNECT_TIMEOUT_MS = 30_000`、`READ_TIMEOUT_MS = 30_000`（每 socket 空闲期限）、`DOWNLOAD_CHUNK_SIZE = 64 KiB`。
- **`BrowserToolBridgeImpl.kt`**（改）：新增字段 `private val downloader = BrowserDownloader(workspaceStore, scopeId)` + `override fun download(url, suggestedName) = downloader.download(url, suggestedName)`（`browser.download` 无主线程 hop，纯 HTTP + Workspace I/O，工具可直接在后台 dispatcher 运行）。

## 实现的契约

1. **`browser.download` 是端口的薄 fail-closed 映射**（doc 09 §3.4、与 HXA-062 的 11 个 `browser.*` 同一原则）：工具 `execute` 解析（已 schema 校验的）`url`/`suggestedName`、调用**恰好一个**端口方法 `download`、把闭合 `DownloadToolStatus` 映射成稳定 `ToolExecutorResult`——`SAVED`/`REFUSED` → Completed（携带稳定 status，REFUSED 的 `reason` 是策略/传输类别），`TIMED_OUT` → TimedOut，`ERROR` → Failed，**绝不一律回「成功」**。参数缺失/越界 = `Failed`（`sideEffectFree`）。
2. **协议与重定向都逐跳 fail-closed**：顶层 URL 与**每一跳**重定向都 re-validate 为绝对 http(s)（auto-follow 禁用、手动解析），非 http 跳、环路、超 5 跳都是 REFUSED——一个把下载重定向到 `file:`/`javascript:` 的恶意服务器无法绕过协议闸门。设备测试 `aNonHttpUrlIsRefusedWithNothingPublished`/`aJavaScriptSchemeUrlIsRefusedWithNothingPublished`（生产入口）+ JVM 测试 `aRedirectToANonHttpSchemeIsRefused`/`aRedirectLoopIsRefused`/`aRedirectChainOverTheLimitIsRefused` 钉住。
3. **文件类型闸门：APK/DEX/JAR/SO（+jni）与 Android 包 MIME 一律 REFUSED，且绝不打开或执行**（doc 09 §3.4「禁止自动执行或安装」）：`BrowserDownloadPolicy.evaluate` 对后缀（`apk`/`apks`/`dex`/`jar`/`so`/`jni`）与 MIME 前缀（`application/vnd.android`/`application/x-dex`）拒绝为 `UNSAFE_TYPE` → REFUSED `type`。且 `BrowserDownloader` **只保存、从不打开/执行/安装**任何落盘文件（无 `ACTION_VIEW`、无 `PackageInstaller`、无 dex 加载）——文件只进入共享 Workspace 供模型以 model-safe reference 读取。
4. **大小闸门：声明上限 + 流式硬上限双保险**（doc 09 §3.4「限制文件大小」）：策略层先拒 `contentLength > 100 MiB`（REFUSED `size`）；但**服务器少报/谎报 length 时**，`writeArtifactStream` 的 `CappedDigestOutputStream` 在流内累计、一旦实际写入超过 `maxBytes`（100 MiB）即抛 `LimitExceeded` → REFUSED `size-exceeded`，temp 删除、不发布。字节上限在两种情况下都守住。
5. **文件名闸门 + 优先级**：目标名经策略清洗（长度 ≤ 128、去掉路径分隔符/危险字符、后缀复检）；优先级 Content-Disposition（`filename*` > `filename=`）> 模型 `suggestedName` > URL path > `"download"`。恶意 disposition 只能给一个「提示」，经策略清洗/闸门后才可用，无法夹带路径。JVM 测试 `theSuggestedNameIsUsedWhenThereIsNoDispositionOrPathName`/`theUrlPathNameIsUsedWhenThereIsNoDispositionOrSuggestedName`/`theDefaultNameIsUsedForABareHostUrl` + SAVED 用例（disposition 优先）钉住。
6. **落共享 Workspace `output/`、模型只见 model-safe reference**：下载写入 `output/<name>`（`WorkspaceLayout.OUTPUT` 区域，scope 配额内）、原子发布（temp rename）、记录 `sizeBytes`+`sha256`；模型见 `scope:<id>:output/<name>` 的 model-safe reference + 尺寸 + SHA-256，**从不**见裸路径。`ensureLayout`（幂等，app bootstrap 已建布局）保证 `output/` 区域目录存在（`writeArtifactStream` 要求 target 父目录存在）。
7. **超时与传输失败 fail-closed**：连接/读 socket 空闲期限（各 30 s）到 = TIMED_OUT；任何网络/磁盘/配额失败 = ERROR。两种都**不发布半成品**（store temp 删除、无原子 rename）。JVM 测试 `anUnreachableHostIsAnErrorWithNothingPublished` 钉住 ERROR 无发布。
8. **输出无 JSON null**：Completed 输出 schema 合规，逻辑缺失值发 `""`、未落盘 size 发 `0`（`BrowserToolsMappingTest` 全覆盖）。
9. **纯 JVM 执行器可 host 端到端测试**：`BrowserDownloader` 无 WebView、无主线程，故 `BrowserDownloaderTest` 用真实 `HttpURLConnection` 对本地 `ServerSocket` + 真实 `WorkspaceArtifactStore` 端到端跑全生产路径（重定向解析、策略闸门、上限流式写入、SHA-256）——这是「把安全关键逻辑放进可单测的纯 JVM 层」的落地（与 HXA-062「端口是安全边界」一致）。

## 决策记录：

1. **新增纯 JVM `BrowserDownloader` 执行器（而非在 `BrowserToolBridgeImpl` 里直接写）**：`browser.download` 是「纯 HTTP + Workspace I/O」，不需要 WebView、不需要主线程。把执行逻辑放进纯 JVM 类，使**整条生产路径**（真实 `HttpURLConnection` 重定向解析 + 真实 `WorkspaceArtifactStore` 上限流式写入）能在 host 上用本地 `ServerSocket` 端到端单测（11 例）——这是把安全关键的下载逻辑放进可复现、可回归的纯 JVM 层的落地，与 HXA-062「端口是安全边界、工具只做薄映射」同一条原则。`BrowserToolBridgeImpl.download` 只是一行委托。
2. **手动解析重定向（`instanceFollowRedirects = false`）、逐跳 re-validate**（而非依赖 `HttpURLConnection` 的 auto-follow）：auto-follow 会静默跟随到非 http scheme 或进入重定向循环，无法在中途对每一跳施加协议闸门。手动解析把每跳都过 `BrowserDownloadPolicy.isHttpUrl`（绝对 http(s)）+ 环路检测（visited 集合）+ 跳数上限（5），使「把下载重定向到 `file:`/`javascript:`/内网」的恶意服务器被 REFUSED 而非静默跟随。
3. **大小闸门用「策略层声明上限 + 流内硬上限」双保险**（而非只信 `Content-Length`）：服务器可少报/谎报 `Content-Length`，只查声明值会放行超限流。故策略层先拒 `contentLength > 100 MiB`（快路径），`writeArtifactStream` 的 `CappedDigestOutputStream` 再在流内累计、超 `maxBytes` 即抛 `LimitExceeded`（REFUSED `size-exceeded`、temp 删除）——两种情况都守住 100 MiB 字节上限。
4. **新增 `:core:workspace` `writeArtifactStream` 上限流式写入（而非复用 `writeArtifact`）**：`writeArtifact` 需要调用方先拿到全量 bytes 再一次性原子写，无法承载「边下边写 + 上限 + 流内 SHA-256 + 服务器少报 length 也要守上限」。新增 `writeArtifactStream`（temp 之上包 `CappedDigestOutputStream`、超限抛 `LimitExceeded` 删 temp 不发布、成功才原子 rename 记 size+sha256）是共享 Workspace 层的地基能力，下载是首个消费者，且对其它「大文件边流边写」场景通用。
5. **`Save` 分支先 `ensureLayout` 再 `writeArtifactStream`**：`writeArtifactStream` 的底层 `AtomicFileWriter.writeAtomicStream` 要求 target 父目录（`output/` 区域目录）**已存在**，但 store 的写入方法本身不建区域目录（`SafImportPipeline` 是显式 `createDirectories` 的先例）。`ensureLayout` 幂等（app bootstrap 已建布局），故在执行器里先调它使执行器自足——不依赖调用方是否已 bootstrap，也保证 host 端到端测试（裸 temp 目录 store）能走 SAVED 正路径。
6. **设备测试只验 fail-closed（非 http scheme 拒绝），SAVED 全字节路径归 host JVM**（而非在设备起 loopback HTTP 服务器）：Android app 进程**不能 bind 监听 socket**——`new ServerSocket(0)` 抛 `SocketException: EPERM (Operation not permitted)`，故 on-device 无法起 hermetic loopback HTTP 服务器（这也是既有所有 browser 设备测试用 `data:` URI 的原因，而下载路径不接受 `data:`）。故设备测试聚焦 on-device 特有的契约——**生产** `BrowserToolBridgeImpl.download` 入口对不可信 scheme（`file:`/`javascript:`）fail-closed REFUSED 且无发布；SAVED 的精确字节 + SHA-256 + 重定向解析 + 策略闸门在 host JVM 端到端验证（`BrowserDownloaderTest`）。与 HXA-060/061/062 的「JVM 验机制 / 设备验 on-device fail-closed」分工一致。
7. **`browser.download` 落共享 Workspace `output/`、模型见 model-safe reference（而非直接回裸路径或落 SAF）**：与 HXA-062 screenshot、HXA-044 文件物化同一条「模型只见 `scope:<id>:<path>`、从不见裸路径」的边界；SAF 目标（用户显式选位）依赖未实现的 HXA-057/058 SAF scope 接线，故本任务只做 Workspace 目标。
8. **detekt 高返回/吞异常/泛型 catch/长方法点用针对性 `@Suppress`**（而非重构掉 fail-closed 分支）：仓库既有惯例（HXA-060/061/062 同法）——`BrowserDownloader.download` 的「每守卫一个返回」与「网络异常被吞成 ERROR outcome」是 fail-closed 语义本身；`resolveRedirects` 的多 throw（每类拒绝一个稳定 reason）与 while+try+分支的深度是重定向逐跳再校验的固有结构；`BrowserDownloadTool` 的 descriptor/execute 因 8 字段输出 schema 天然偏长；`MiniHttpServer` 测试助手的空 catch 是有意忽略客户端中断/已关闭 socket。均按仓库既有 `@Suppress` 惯例加在**最小作用域**并附一行说明。

## 风险或后续任务

- **SAF 目标待 HXA-057/058**：`browser.download` 当前一律落 app-private 共享 Workspace；「模型下载落到用户经 SAF 树显式选位」需 persisted SAF tree scope 接线（HXA-057/058，未实现）。届时可在端口/执行器上加目标选择（Workspace vs SAF grant），复用同一套协议/重定向/MIME/size 闸门与 `writeArtifactStream`。
- **100 MiB 是硬上限、无分片/续传**：单文件下载超 100 MiB 直接 REFUSED `size-exceeded`；无断点续传、无并发多下载。若真实负载出现更大的合法资源需求，需产品决策是否放宽上限或引入分片。
- **MIME/后缀闸门是黑名单、非穷尽**：`BrowserDownloadPolicy` 靠后缀（`apk`/`apks`/`dex`/`jar`/`so`/`jni`）+ MIME 前缀（`application/vnd.android`/`application/x-dex`）识别可执行/可安装类型；一个用非标准后缀/MIME 的可执行文件可能漏判为可保存。**这是有意的纵深防御而非唯一防线**——执行器**只保存、从不打开/执行/安装**，故即便漏判一个可执行文件，也只是把它作为不可信数据存进 Workspace，不产生执行风险。若真实负载出现漏判，扩充 `BLOCKED_SUFFIXES`/`BLOCKED_MIME_PREFIXES`（`BrowserDownloadPolicyTest` 会因触发词漂移先挂门禁）。
- **纯 HTTP（`HttpURLConnection`）不做 TLS 指纹固定/证书固定**：下载经系统 `HttpURLConnection` 的标准 TLS 校验；不引入自签证书固定（pinning）。这与 HXA-060 的 WebView 浏览器一致（用系统 TLS 栈）；若后续需要对特定 origin 证书固定，归后续安全加固。
- HXA-064（分享、Intent 和剪贴板）开工时：实现分享输入先预览、`android.open_uri` 只打开、clipboard read/write 按可见前台和风险限制（roadmap M6 / HXA-064，矩阵 `:tools:android` unit + device）；与本任务的 `browser.download` 无共享执行路径（不同模块、不同安全边界）。
