- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  - **endpoint path = API root 语义**（HXA-025 `WireModelProvider.wireUrl` 既定）：模板 path 只到 API root（`/v1`、`/compatible-mode/v1`、`/api/paas/v4`、空串），协议资源路径由 adapter 追加；测试 `endpointPathsAreApiRootsNotResourcePaths` 保证模板 path 不内嵌 `responses`/`chat/completions`/`messages`/`models` 资源段——防止模板与 adapter 双重拼接。
  - **无固定 host 的模板 `defaultEndpoint = null`**（generic-openai/sglang/vllm）：占位符不是合法 endpoint（`NormalizedEndpoint.parse` 拒绝），null 是唯一诚实表示；UI 引导（SGLang 默认 path `/v1`、vLLM 默认端口 8000）进 notes。
  - **DeepSeek 端点不带 `/v1`**：官方 Quick Start 的 OpenAI `base_url` 是 `https://api.deepseek.com`，curl 示例直接 POST `https://api.deepseek.com/chat/completions`——第三方教程常误写 `/v1`，以官方文档为准（若带 `/v1` 会 404）。
  - **OpenRouter 只带 `X-Title`**：OpenRouter 归因头中 `X-Title`（应用名）是模板能安全预填的；`HTTP-Referer` 需要应用 origin URL，Helix 目前没有公共 web origin——模板不虚构 URL，留用户自定义头（HXA-028 的头编辑面）。
  - **模板是数据，不是代码路径**：catalog 是纯常量对象（无构造依赖、无 IO、无 Android），app 侧（HXA-028）把模板 + 用户输入组装成 `ProviderConfig` → 构造 HXA-025 的具体 provider 类；本任务不新增 provider 类（三个协议 adapter 已覆盖全部 15 模板——P1 全部复用 `OPENAI_CHAT_COMPLETIONS` adapter）。
