## Phase 1：设备测量（`ImageNormalizationDeviceProbe`，4 例/设备 × 2 台，EXIT=0）

新增 `app/src/androidTest/kotlin/com/helix/app/vision/ImageNormalizationDeviceProbe.kt`（TAG `HELIX_VISION_PROBE`），在两台模拟器（Helix_API_29 API 29 / Helix_API_36 API 36，arm64-v8a，4 KiB page；环境无 API 34 镜像 / x86_64 镜像 / 物理低内存设备——与 HXA-050~054 同一取证口径）测量并固定了以下事实：

1. **`decodeLadderReportsTheDeviceMemoryBoundary`**：1→32 MP 实心 JPEG 解码阶梯，同时报告 JVM HEAP 上限与 NATIVE 内存（`ActivityManager.MemoryInfo`）。固定事实：**Bitmap 像素在 native 内存，不在 JVM heap**——API 29 模拟器 JVM heap 仅 48 MiB 却成功解码 32 MP（≈128 MiB native）；API 29 native totalMem=1999 MiB / low-memory threshold=216 MiB，API 36 totalMem=2472 MiB / threshold=216 MiB（`LADDER_RESULT maxDecodedMp=32`）。
2. **`forgedSofHeaderFailsClosedWithoutKillingTheProcess`**（解压炸弹不变量）：伪造 JPEG SOF 声称 30000×30000（0x7530）。固定事实：**SOF 头可伪造且 `inJustDecodeBounds` 会信任它**（`headerForgeryVisible=true`，bounds 探针报告 30000×30000），但**完整解码返回 null**（`decode=NULL_SAFE`，~1 KiB 文件不产生大图、进程存活）；65535² 则在 bounds 阶段即被平台拒绝（-1×-1）。→ 头尺寸永远不可信：字节预算门先于一切解码执行（见 `VisionLimits.MAX_INPUT_BYTES`）。
3. **`exifOrientationAndMetadataStripBehavior`**：EXIF orientation=6 的 1000×500 JPEG。固定事实：**`BitmapFactory` 不自动应用 EXIF 方向**（解码得 1000×500 未旋转）→ 归一化器手动旋转；**`Bitmap.compress` 重编码剥离全部 EXIF**（orientation/GPS/comment 全失）→ 隐私剥离就是重编码本身。
4. **`base64BudgetArithmeticForNormalizedOutputs`**：q90 编码 4096×4096 → 72 KiB raw / 97 KiB base64，远低于 per-image 预算 → 预算常量有充分余量。

所有值固定到上述测量证据 + Provider 文档上限的**更严者**（Provider 证据抓取于 2026-09-03）：

| 常量 | 值 | 依据 |
| --- | --- | --- |

## 决策记录：本任务内的可逆实现选择（无新 ADR）

1. **视觉探测的封闭规则**：第 5 阶段以 1×1 保留探针图（`helix:vision-probe`）发极简视觉请求；Completed **或 Refusal** 终态证明端点接受图片（vision=true，Refusal 意味着请求形态被接受），任何 Error 终态使阶段失败——探测只凭「看到成功完成」证明视觉，400 图片拒绝与 5xx 一样保持 vision 未确认，由手动声明（ADR 第二来源）兜底。
2. **绑定对象是归一化 artifact**：`message_attachments` 行绑定**归一化 artifact**（id + 其 SHA-256）而非 raw 文件——离开设备的字节才是 egress 披露与重验的对象；raw artifact 保留注册（本地保存/预览）但不被消息绑定。历史重建/重试/恢复从绑定重推 `ModelMessage.images`，每次请求构建全量重验（存在 + hash + magic + 预算），miss 整 turn fail-closed。
3. **图片源 = app 侧单一来源 + 协议侧独立 resolver**：三协议保留各自独立的 `ImagePayload`/`ImageResolver` 类型（不共享协议代码，ADR-0014/既有契约），但都委托同一个 app 侧 `VisionImageSource`；`ProviderFactory` 以 **supplier** 注入（stream 时解析）以解除与容器属性声明顺序的耦合（验证中 NPE 的修复）。
4. **归一化在暂存时执行**（而非发送时）：失败即刻可操作（固定中文文案点名 4096px/12 MP 限制），发送路径只做重验；归一化失败保留条目（本地可用）+ 发送阻塞，绝无裸 base64 回退（ADR-0014 §4）。
5. **VisionLimits 取值**：端上包络取 API 29/36 模拟器测量证据（native 216 MiB 阈值、SOF 伪造可见性）与 Provider 文档上限（Anthropic 10 MB b64/8000 px/32 MB 请求、OpenAI 4 MB data URL）的**更严者**并留余量；模拟器 32 MP 解码成功不构成放宽依据（真机矩阵未做）。
