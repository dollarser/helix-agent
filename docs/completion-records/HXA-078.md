# HXA-078 A2A Agent 配置、发现与快照（完成记录）

- 日期：2026-09-05
- 前置任务：HXA-077（commit `dc91f1b`）
- 状态：完成

## 目标

交付默认禁用的 A2A Agent 配置、SecretStore alias 认证、公开/扩展 Agent Card 获取、
v1.0 接口协商、有界 provider/capability/mode/Skill 快照，以及用户逐项启用和快照变化
失效；不实现 A2A Server、webhook、OAuth/mTLS、gRPC、custom binding 或 v0.3 降级。

## 实现和复核的契约

- 新 Agent 只能以 disabled 状态登记；endpoint 规范化且只接受 HTTPS 或精确 literal
  loopback fixture，Room 仅保存 Secret alias，不保存 bearer。
- 公共 Card 请求不发送认证；只有 Card 明确声明 extended Card 且配置了 alias 时，才从
  Android Keystore 取 bearer 并绑定 `A2A-Version`、tenant 和所选 interface。
- 只选择同 origin 的 v1.0 `JSONRPC` / `HTTP+JSON`；v0.3、gRPC、required extension、
  redirect、跨 origin、重复 Skill、非 JSON 与超限 Card 均 fail closed。
- Card 与每个 Skill 使用 canonical JSON SHA-256；用户只可启用已审阅快照里的精确
  Skill。Card hash 变化会禁用 Agent 和全部 Skill；同 Card 下 interface/binding/version/
  tenant/mode/Skill hash 任一变化都不能保留该 Skill 的 enablement。
- production `A2aAppService.testConnection` 在持久化新快照后同步刷新 Registry 和 executor；
  若变化导致存储侧撤销，内存中旧 `a2a.<agent>.<skill>` 也立即移除。

## 验证中修复

发现一个生产失效窗口：Card 变化会正确禁用 Room 中的 Agent/Skill，但已注册的旧 A2A
Tool 仍留在进程内 Registry，直到重启或手动 disable。修复后 `testConnection` 每次根据
持久化后的真实 enabled 状态替换或清空该 Agent 的 descriptor、executor 和 bridge；
没有放宽 hash、approval 或长期规则绑定。
