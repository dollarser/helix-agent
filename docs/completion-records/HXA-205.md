## 契约与交付

决策记录：能力准备是**对持久事实的只读投影**，不新增第二套恢复状态机。`CapabilityReadiness.project(...)` 按用户目标（对话 CHAT / 文件 FILES / 浏览器 BROWSER / Linux 运行时 LINUX）聚合现有服务——模型连接、Workspace、所需系统能力（如 `Capability.WEB_BROWSING` 授权）、Runtime 状态——返回缺项与**按目标**的下一动作（配置模型 / 验证 Runtime / 修复 Runtime）。被动进入页面不拉起 Runtime、不登录、不安装，只刷新本地事实；用户点击初始化/验证/修复才冷绑定。四目标各自保留独立身份（`ReadinessGoal`、`RuntimeReadiness`、`ReadinessState`、`ReadinessItemKind`、`ReadinessActionKind`），绝不解析任意错误字符串猜副作用。LINUX 目标由 **flavor AND profile** 双重门控：consumer 构建按 ADR-0005 仅 STANDARD（`switchTo(ADVANCED)` 是 fail-closed 拒绝），故 consumer 永不暴露 LINUX 目标；developer 在 ADVANCED 下才显示（无 Runtime 安装时状态为 NOT_READY 但目标可见）。没有模型配置时，手动文件与浏览器仍可达，不等待模型设置。沿用 HXA-204 的结构化错误与恢复展示，不复制第二套状态或自动扩大权限；修复入口可取消/不可用时保持视图可恢复，不盲目自动继续。
