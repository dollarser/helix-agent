## 范围（对应 `docs/development/roadmap.md` HXA-043）

- **store 侧（`core:workspace` `WorkspaceArtifactStore` 新 seam）**：
  - `copyFile`：冲突策略显式——已存在的目标（文件**或**目录）未带 `overwrite` 一律拒绝；带 `overwrite` 写入目录仍然拒绝。目标 scope 配额在写之前预检（拒绝时不落任何字节、不产生 temp）；支持跨 scope 复制；源文件永不被修改。
  - `moveFile`：同 scope = 单次 `ATOMIC_MOVE` 优先的 rename（配额预检不需要，usage 只会减少）；跨 scope = **先发布后删除**（目标 scope 配额预检 → 原子写入目标 → 再删源），admission 失败绝不丢源。
  - `moveToTrash` / `restoreFromTrash` / `purgeTrashEntry`：删除 = rename 进 `.helix/trash/<entryName>`；entry 名自描述且**可逆**（`<13位毫秒>-<8位hex uuid>__<编码后的原相对路径>`，`%`→`%25`、`/`→`%2F`，无 sidecar 元数据文件）；恢复与物理清空是**两个独立操作**，两者都拒绝任何非 trash entry 的引用（含 trash 目录下命名不合法的外来文件）；restore 时原路径被占用则 fail-closed（保留 trash entry）。
- **工具侧（`tools:files` `FilesMutateTools`）**：
  - `files.copy` / `files.move`（`NON_IDEMPOTENT`）/ `files.delete`（`IDEMPOTENT`），全部 `LOCAL_MUTATION`、`baseRisk L2`（逐次审批）、`BuiltInOrigin`。
  - region 准入只允许 `input/`/`work/`/`output/`（`.helix/` 内部不可寻址）；失败消息一律 sanitized 稳定串；真实路径绝不进入参数/输出/失败文本（doc 10）；cancel 信号短路为 `Cancelled`。
  - `files.delete` 不物理删除：移入 trash 并返回 model-safe 的 `trashRef`（`scope:<scopeId>:.helix/trash/<entryName>` 模型引用，非真实路径）。
  - `AppContainer` 注册三个工具（生产工具表）。
- 回归测试：`WorkspaceMutateOpsTest`（16 用例：copy 冲突/覆盖/目录拒绝/缺失源/region 强制/配额预检、move 同/跨 scope/配额拒绝不丢源、trash 命名 round-trip（含 `%`/`%2F`/空格路径）、restore 占用拒绝、purge 回收 usage、非 trash 引用拒绝）、`FilesMutateToolsTest`（15 用例：descriptor 契约、输出 schema 合规、跨 scope、region 拒绝、无真实路径泄漏、cancel、配额）。

## 决策记录：关键取舍与理由

1. **三个工具一律 `baseRisk L2`（逐次审批），fail-closed**：[产品需求](../product/requirements.md)第 214～216 行要求 copy "L1/L2，跨 scope 或覆盖时提升风险"，但 `:core:policy` 当前没有 per-call/per-argument 的风险升级机制（风险只来自 descriptor 的 `baseRisk`）。统一 L2 是现有机制下**永不比需求更便宜**的 fail-closed 选择——一次本可 L1 的简单 copy 也要付 L2 审批。per-call 升到 L3 的完整语义留待 policy 引擎支持 per-argument 升级后立项（`docs/development/status.md` Known limitations 已记）。
2. **跨 scope move 是非原子的 publish-then-delete，而非 rename**：跨 scope 无法跨文件系统边界 rename。顺序保证目标 scope 的配额预检与发布都成功后才删源，因此 admission 失败**绝不丢源**（回归：`aQuotaExceedingCrossScopeMoveLeavesTheSourceIntact`）；反过来"先删后写"在配额拒绝时会静默丢数据。
3. **trash entry 名自描述、可逆、无 sidecar**：`<13位毫秒>-<8位hex uuid>__<编码原相对路径>`（`%`→`%25` 再 `/`→`%2F`，严格逆编码，未识别的 escape 拒绝）。恢复/清空都先对 `TRASH_ENTRY_NAME` 正则校验，拒绝一切非 trash entry 引用；restore 时原路径已占用则 `FileAlreadyExistsException` fail-closed、entry 保留（不覆盖新文件）。
4. **不提供 model 侧 restore/purge 工具**：PRD P1 工具列表只有 `files.copy`/`files.move`/`files.delete`；恢复与物理清空保持为 store seam，由文件管理 UI（HXA-046 的 trash 面）驱动。模型无法绕过 UI 直接恢复或清空回收站，`files.delete` 也永远拿不到物理删除路径。
5. **幂等性**：copy/move = `NON_IDEMPOTENT`（结果依赖可变源；跨 scope move 非原子，重放可能半完成）；delete = `IDEMPOTENT`（单一确定效应：把文件移入 trash；对已不在原路径的文件再次调用是"未找到"而非二次副作用）。
6. **`files.delete` 返回 model-safe `trashRef`（scope 模型引用）**：`scope:<scopeId>:.helix/trash/<entryName>`，真实路径不外泄（doc 10）；调用方拿到的是引用而非可操作句柄——恢复/清空只能走 UI。
