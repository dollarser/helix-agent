## 范围（对应 `docs/development/roadmap.md` HXA-049）

任务书要点：按 accepted [ADR-0014](../adr/0014-session-attachment-materialization.md) 完成附件基础闭环——聊天页系统文件选择器 / 待发送附件卡 / 复用 HXA-044 `SafImportPipeline` 把一次性 `content://` URI 复制到当前会话 app-private Workspace（单文件导入**不要求** persisted SAF tree grant）；增加 Artifact 与消息附件关系、schema migration、hash 快照、重启恢复、取消和孤儿清理；每条用户消息最多 4 个附件、单文件仍受 10 MiB 上限约束。首批只把经 MIME / 扩展名 / 有界字节 probe 一致确认的 UTF-8 txt/md/csv/json 作为文本附件，以带来源、`UNTRUSTED` 标记和哈希的有界 context item 进入模型请求，超限内容保留 Artifact 引用并由 `read(offset,maxBytes)` 分块读取。其余类型统一返回 `UNSUPPORTED_ATTACHMENT_TYPE` + 封闭 category，不做解析 / 渲染 / OCR / 媒体解码 / base64 进上下文 / Provider upload。发送前扩展 egress disclosure/binding，绑定精确 Provider/origin/Artifact hashes；用户只选择附件或系统分享进入会话时不得自动发送。

## 实现

分四层，依赖方向保持 `core/model ← feature/files ← app`（`ForbiddenContentGuard` 在 `:app`，故凭据扫描器以 lambda 依赖注入 `feature/files` 的门，门本身无 app 依赖）：

### 1. `core/model`：封闭分类模型（新增）

- `AttachmentCategory`：封闭 5 值 TEXT_ENCODING / DOCUMENT / AUDIO / VIDEO / OTHER——刻意"每类"而非"每格式"，新增 unsupported 文件不新增错误码；HXA-055 前图片落 OTHER。
- `TextAttachmentKind`：TXT / MARKDOWN / CSV / JSON——形状标签，不是"理解"声明。
- `AttachmentClassification`（sealed）：`TextAttachment(kind)`（唯一可物化分支）/ `UnsupportedAttachment(category)`（永不解析/解码/OCR/渲染）。
- `AttachmentPurpose`：`message_attachments` 绑定的用途（本里程碑为 REFERENCE）。

### 2. `feature/files`：导入、分类、物化、发送门（纯函数 / 无 app 依赖）

- `AttachmentClassifier`：只信 `ContentProbe.Result`（从磁盘字节重探测）；MIME / 扩展名仅作"选标签"，永不信任内容。UTF-8 且扩展名为四支持扩展名之一 → `TextAttachment`；否则 `UnsupportedAttachment`（best-effort category 标签）。常量 `MAX_ATTACHMENTS_PER_MESSAGE=4`、`MAX_ATTACHMENT_BYTES=10 MiB`。
- `SafImportPipeline`（HXA-044 既有管线泛化）：新增可选 `targetRelativePath`（附件落 `input/attachments/<id>/`）与 `maxImportBytesOverride`（附件用 10 MiB 上限，区别于 256 MiB 的 SAF 导入上限）；在**准入通过后**于拷贝时创建有界父目录（被拒的导入不在磁盘留痕），非附件导入仍走扁平 `input/<name>` 路径与既有 isDirectory 守卫。
- `AttachmentImporter`：包装上者，把源 metadata（size/mime/fileName）与 `targetRelativePath` 交给管线。
- `AttachmentMaterializer`：fail-closed 再校验——以导入时 `boundSha256` 为**唯一**可信事实，物化时重读磁盘重算 SHA-256：字节变化→`Tampered`、缺失/不可读→`Unavailable`（均 fail-closed 阻断）；分类也从磁盘字节经 `ContentProbe`+`AttachmentClassifier` **重派生**（不信任导入期标签，只能降级为 unsupported，不能提升为可物化）。Text 视图有界到 `MAX_INLINE_TEXT_BYTES = ContentProbe.SAMPLE_BYTES = 8192` 字节（恰是 probe 已确认的 UTF-8 区，绝不跨到未确认字节），`sha256` 绑定**整文件**，`truncated` 标记是否前缀。
- `AttachmentSendGate`（纯函数）：对每个 staged 附件物化 + 用 DI 的 `credentialScan` 扫**整文件**（不止内联视图——整文件经 `read(offset,maxBytes)` 全量出网）；任一 unsupported / snapshot-broken（tampered/missing）/ credential → fail-closed，按 staged 顺序返回"第一个问题附件"。

### 3. `core/storage`：schema migration + 关系表

- `MIGRATION_3_4`（v3→v4）：`CREATE TABLE message_attachments`（messageId, artifactId, ordinal, purpose, boundSha256）+ 2 索引；Room 快照 `4.json` 落 androidTest assets，`RoomGuardAndConfigTablesTest` / `RoomMigrationFixtureTest` 校验。**不动 `MIGRATION_1_2` 主体**（另一并行会话所有）。
- `MessageAttachmentRepository`（新增）：`Binding(artifactId, purpose, boundSha256)` + `bind(messageId, bindings)`（校验 ≤4 / 非空 / 64 位小写 hex，`ordinal` = 列表序，随消息 CASCADE）+ `listByMessage`（ordinal 升序即物化序）。

### 4. `app`：staging / admission / egress binding / 模型注入

- `AttachmentStagingSupport`（新增）：把导入产物登记为待发送（`resolveWorkspacePath` 由 `AppContainer` 注入 `resolveFileScopePath` 强约束，消费端只在门内使用真实路径）；每会话 ≤4 由门内权威复核。
- `AttachmentSendAdmission.admit`（纯函数，单一切入点）：先跑附件门（非 Ready → `Blocked`，不进 egress），Ready 后跑 egress disclosure；`CredentialDetected` 映射 `Egress(Rejected, reason)`——与"输入框里打凭据"同类的**拒绝**，永不 Proceed/Confirm，匹配内容不回显。每个附件作为 `FileText` 源映射 `HIGH_SENSITIVE_FILE_TEXT`，任何附件都强制逐次确认、绝不自动放行。
- `EgressDisclosure`：`OutgoingContent.FileText` 现携带 名称/类型/大小/sha（`sourceLabel` 是展示标签，非真实路径）；`EgressSummary.attachments` 供 `DisclosureDialog` 逐条渲染 ADR-0014 §5 的出网文件枚举。
- `AttachmentContext.buildUserMessageContent`（纯函数）：用户文本 + 每附件一个 `【附件 i/n · 名称】` 块（来源标签 + `UNTRUSTED_MARKER` + 整文件 SHA-256 + 工作区相对分块读取路径）；**无附件时原样返回**（纯文本发送零回归）。
- `ChatService`：`stagedLock` 串行化所有 staged 列表变更；`StagedAttachmentEntry` 带 `sessionId`（会话切换复核 + 权威上限复核，防并发越限）；`pendingEgress` + `pendingAttachmentIds` 把本次确认**同时**绑定到精确出网目标和被枚举的附件集合；`confirmSendNow` 复核目标漂移后委托 `confirmStagedSend`（附件集漂移也阻断"重新发送"），发送只清**被批准的**附件集（不误删并发新暂存件）并 `refreshScreen` 立即清屏上 chip；`retryStagedFor` 重试前解析该 turn 消息→`message_attachments`→artifact→工作区路径，对 bound SHA-256 再校验（篡改/删除 fail-closed 不建新 turn）。
- `TurnCoordinator`：`start` 现接受 `attachments: List<Binding>`，在 turn 事务内把绑定写到该 turn 的消息行（附件-only 发送也建一行消息来承载绑定）。
- `AppContainer`：组合 `AttachmentStagingSupport`（复用共享 `featureFiles.importPipeline` 的 importer、源 metadata 读取器、app workspace scope、`resolveFileScopePath` 强约束的 `resolveWorkspacePath`）并注入 `ChatService`。

## 决策记录：关键取舍与理由

1. **`feature/files` 门不依赖 `:app`，凭据扫描器依赖注入**：`ForbiddenContentGuard` 在 `:app`，依赖方向不允许 `feature/files` 反向依赖它。故门以 `credentialScan: (String) -> String?` 注入，`ChatService` 传 `ForbiddenContentGuard::reasonFor`；纯门可 JVM 共测、不拖 app/Room。
2. **`AttachmentMaterializer` 以导入时 `boundSha256` 为唯一可信事实，物化时全量重算 + 从磁盘字节重派生分类**：不信任导入期标签/快照之外的任何事实。文件变化→`Tampered`、缺失→`Unavailable`（fail-closed 阻断）；分类从磁盘重派生意味着陈旧或被改的标签只能把文件**降级**为 unsupported，不能提升为可物化——ADR-0014 fail-closed 的核心。
3. **内联视图有界到 `ContentProbe.SAMPLE_BYTES`(8192)，但 `sha256` 绑整文件**：probe 只确认前 8192 字节是有效 UTF-8，内联视图恰好压在该已确认区，绝不跨到 probe 未确认的字节（防"UTF-8 前缀 + 二进制尾巴"被当全文内联）；整文件仍经 `read(offset,maxBytes)` 分块可达，绝不 base64 进上下文。
4. **门扫整文件而非只内联视图**：整文件都会经 `read(offset,maxBytes)` 出网，凭据可能在 8 KiB 内联边界之后，故 `credentialScan` 吃整文件（受 10 MiB 导入上限约束）；`Admission.guardText` 再对内联视图做第二次 net，双保险。
5. **`CredentialDetected` 是"拒绝"不是"确认"**：与输入框凭据同类，映射 `Egress(Rejected, reason)`，永不 Proceed/Confirm，匹配的凭据内容不回显（只回 guard reason）。
6. **确认同时绑定出网目标 + 附件集**：只绑目标会让"弹框枚举了 A、但 B 在导入中完成、确认时 A+B 一起出网"绕过 ADR-0014 §5 的逐条枚举。故 `pendingAttachmentIds` 记录弹框枚举的确切 artifact-id 集，`confirmStagedSend` 要求与当前 staged 集完全一致（漂移→"附件列表已变化，请重新发送"，不重弹框、不建 turn）；发送只清被批准集，防误删并发新暂存件。
7. **重试前对 bound SHA-256 再校验**：ADR-0014 要求"发送、重试、恢复"都复核。重试解析该 turn 用户消息→`message_attachments`→artifact→工作区路径，对 bound 快照重算，任何解析/门失败→`Unavailable`/非 Ready→fail-closed 不建新 turn。
8. **纯文本路径零回归**：`buildUserMessageContent` 无附件原样返回；空 staged 的 confirm 走与附件前完全相同的 `launchTurn` 路径；纯文本 egress 决策字节级不变（`EgressDisclosureTest` / `AttachmentSendAdmissionTest` 回归锁定）。
