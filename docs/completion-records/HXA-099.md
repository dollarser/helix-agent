# HXA-099 模式、预算与资源降级运行控制（完成记录）

- 日期：2026-09-05
- 目标：为 Chat/Plan/Act/Goal 提供可解释且可持久化的运行入口与有界 `TurnBudgets`，并把 Android 前后台、低内存和热状态接入 HXA-037 `resourceGate`；UI 选择不得降低 ModePolicy、Policy、Approval、审计或 Goal budget accounting。
- 前置任务/commit：HXA-037、HXA-039、HXA-040、HXA-068、HXA-089；worktree/base `0309cd0846e1a7fd0af3488549cb83a6be2e88b8`。
- 修改文件：`app` 的 `runcontrol`、Chat runtime、Compose Chat/Settings UI、Android/JVM 测试和三套字符串资源；`core:policy` 的可信 Chat opt-in/Mode 动态风险重检；`tools:framework` 的 Dispatcher 透传与回归测试。
- 实现的契约：每个 Turn 在创建 durable Turn 前快照 Mode、Chat tools opt-in 和预算；工具表按 ModePolicy 收窄，但每次调用仍由 Dispatcher 重新计算动态风险并执行 Policy/Approval/审计。Chat 默认零工具且仅显式 opt-in 的 READ_ONLY/L0，Plan 仅 READ_ONLY 且动态风险不高于 L1；Act/Goal 不获得额外 authority。模型调用数、每调用输入/输出 token、Turn 总 token 和工具步数均有硬上限；provider 未报告 usage 时使用保守字节估算。配置损坏 fail closed 到 Chat/零工具/有界默认值，活动 Turn 期间拒绝切换。资源 gate 每次 scheduler admission 读取 Activity 生命周期、`ActivityManager.MemoryInfo.lowMemory` 和 `PowerManager.currentThermalStatus`，正常为 2，后台/低内存/中度及以上热状态为 1；它只能低于构造期并发上限，不能提高上限、重排或取消已批准调用。
- 未实现/明确排除：本任务没有改变持久 Goal reducer/accounting，也没有把普通 Goal Mode Turn 伪装成持久 Goal；durable Goal usage/recovery 属 HXA-102。没有新增权限、依赖、Tool、写能力或 M11 工作。没有伪造物理设备低内存/热限制；24 小时、Doze、真实热限制和 OEM 资源矩阵留给 HXA-103。
- 自动测试：新增 13 个 JVM 测试，覆盖配置默认/重建/损坏/极值，模型调用与 token 边界/溢出，低内存/后台/热状态恢复，Chat/Plan 动态风险重检，以及 Plan/Goal 仍走同一 Dispatcher/Approval；新增 3 个 Android 测试，覆盖真实 Activity 前后台、平台 memory/thermal 采样、四 Mode 解释入口、Chat opt-in 和预算 UI 重建。规定 JVM 矩阵共 857 tests（Consumer app 271、Developer app 278、core agent 165、framework 143），0 failed/0 skipped；补充 core policy 102 tests，0 failed/0 skipped。
