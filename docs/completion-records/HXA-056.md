# HXA-056 完成记录：文本/图片附件端到端硬化与发布边界（M5A 第二任务）

**前置任务/commit**：`9ecf979`（HXA-055 图片输入与 Provider 视觉能力，分支 `hxa/m5a-image-input`）；本记录随 HXA-056 独立 commit 提交，同分支。
**状态**：完成。roadmap §9A HXA-056 全部范围落地：fixture E2E（发送/流式/Tool Loop/历史恢复/脱敏）、`ACTION_SEND`/`ACTION_SEND_MULTIPLE` 本地草稿（绝不自动发送）、失败矩阵（grant 失效/篡改/重复发送/Provider 切换/能力快照变化/请求过大/解压炸弹/取消/进程回收）、UTF-16/PDF/PPT/DOC/音频/视频/未知二进制统一稳定拒绝、泄露检查（无原始 URI/绝对路径/正文/base64 入日志/Room/audit/用户可见错误）、三 adapter golden + 1 真实 vision endpoint smoke（本地 SGLang，环境明确记录）、用户说明更新。

## 目标

用固定 fixture 把「附件消息从暂存到出网」的整条链路在真设备上回归硬化，并关闭发布边界：分享输入只进本地草稿、绝不自动发送；不支持的类型稳定拒绝且无任何解析/解码/upload 副作用；诊断与持久化不泄露敏感材料。

## 验证中缺陷（已修复，随本 commit）

1. **`FilesScreenTest.previewsTextFileWithHashInfo` 竞态（既有，基线 `9ecf979` 复现）**：SHA 信息行在预览文本之后才由 IO 协程赋值，测试在文本出现后立即读 SHA 行 → 负载设备上 flake。修复 = 补 `waitTag("files-info-sha")`（测试 bug，非生产缺陷；生产侧预览先于信息面板呈现属正常 UX）。
2. **E2E 夹具会话未打开**：`newFixture` 只建会话不 `openSession` → 暂存全部「当前没有打开的会话」。修复 = 建会话（绑定 provider）+ `openSession`。
3. **vision 门读 DB 快照而非测试状态行**：夹具把探测快照写进 `ProviderTestStatusStore`（行存储）而视觉门读 `provider_configs.capability_snapshot` 列。修复 = seed 时把快照写入 spec 列（row save 幂等：新进程夹具跳过已存在行）。
4. **ScriptedSseWire `script()` 语义**：初版替换整个 canned 列表，第二次发送取不到响应。修复 = 追加语义（按调用顺序消费）。
5. **观察到的低频 flake（未根因定位，留档）**：全量套件双设备并行负载下，`AttachmentE2eDeviceTest.unsupportedTypesAreStablyRefusedWithoutSideEffects` 在 API 29 出现过 1 次「暂存协程 30 s 无状态变化、无异常」（blocked/pending 恒空，wire 0 调用）；`FilesScreenTest` 同类 IO 延迟 flake 修复 wait 前亦在两台设备出现。诊断手段（await 周期状态日志 + 超时线程堆栈 dump + fixture scope 的 `CoroutineExceptionHandler`）曾定位到「无协程异常、无状态更新」，堆栈 dump 未在复现窗口捕获到卡点。清理后保留 `CoroutineExceptionHandler`（静默协程死亡 → logcat 可见），移除其余诊断代码。提交前连续 10 轮全量（consumer 5 + developer 5）× 双设备全绿，频率约 1/12 全量轮次；若复现，按记录中的诊断方法重建（await 周期日志 + `Thread.getAllStackTraces` dump）。

## 决策记录：本任务内的可逆实现选择（无新 ADR）

1. **Kotlin KDoc 中的 `/*` 序列是 lexer 陷阱（平台事实，本任务实测）**：KDoc 注释里写 `image/*` 会让 `/*` 开启嵌套块注释，解析器报 `Missing '}'` + EOF `Unclosed comment`，且 `--rerun-tasks`/`:app:clean` 均无法绕过（源码即损坏）。规则：Kotlin 注释中永不写 `/*` 序列（含 MIME 通配），改写为 "image MIME families" 等表述。manifest XML 无此问题（XML 注释语义不同）。
2. **egress disclosure 是附件门，不是逐消息门**：无暂存附件的纯文本 `send` 直接 `launchTurn`（不弹披露、不过视觉门）；有暂存附件才走披露+重验+视觉门。E2E 用例按此语义断言（第二次纯文本发送直接完成）。
3. **取消后的恢复路径是重发而非 retry**：`retryTargetFor` 只取最新 FAILED turn（用户主动 stop 不是失败，不给 retry 目标）；E2E 用例据此断言 CANCELLED 终态 + 重新导入 + 新发送。
4. **草稿会话 provider-free + 单发绑定**：`分享草稿` 会话创建时不带 provider（UI 显式绑定才产生 egress 目标）；`bindProvider` 的 `providerId IS NULL` 行数门禁使「已绑定会话换 provider」结构性不可达（不是运行期检查）——绑定后切换 Provider 只能新建会话，egress 目标永不偷换（ADR-0014 §4 披露绑定语义）。
5. **Compose 测试 API 三事实（BOM 2026.06.01 实测）**：v1 `AndroidComposeTestRule(activityRule) { r -> r.scenario.onActivity { ... } }` 可用（v2 工厂无 intent/scenario 重载）；`assertTextEquals` 同时比对 `Text` 与 `EditableText`，空 TextField 的 Text 是占位符、EditableText 是 `""`——空值断言须读 `SemanticsProperties.Text`；`ComposeTimeoutException` 直接继承 `Throwable` 而非 `Exception`（catch 用 `Throwable`）。
6. **root `testDebugUnitTest` 不覆盖 app 模块**：app 有 consumer/developer 变体，其 JVM 测试任务名是 `testConsumerDebugUnitTest`/`testDeveloperDebugUnitTest`，root 聚合任务名不匹配即跳过。验证矩阵口径 = root 任务 + 两个 app 变体任务显式并跑（本记录已按此执行）。
7. **夹具的 `SafSourceOpener` 对未知 URI 抛错即 grant 失效等价物**：`requireNotNull(sourceFiles[uri])` → 管线映射为 `SOURCE_UNOPENABLE` 固定文案；不另造 content provider 故障注入（既有 HXA-044 矩阵已覆盖真实 grant 撤销的设备路径，全量套件随回归）。
