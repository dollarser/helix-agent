## 目标

按 Agent Skills 规范解析 `SKILL.md` frontmatter；Discovery catalog 只暴露 name、description、source 和完整内容 hash。官方 `skills-ref` 仅作兼容 fixture，不进入 production runtime。

## 实现的契约

- 必需 `name`/`description`，可选 `license`/`compatibility`/`metadata`/`allowed-tools`；严格 UTF-8、YAML mapping、无 alias/重复 key/递归 key/非标量 key，并对文件、frontmatter、字段、集合与嵌套深度设上限。
- name 按官方规范使用 Unicode 小写字母、数字与单连字符，NFKC 规范化后再校验/输出/匹配目录；拒绝大写、非法字符、首尾或连续连字符和 64 字符越界。
- 未知字段保留为不可信数据，但不进入 `SkillCatalogEntry`，不能授予 Tool、Capability、Approval 或文件访问。
- content hash 覆盖原始 `SKILL.md` 精确字节；catalog 只含 metadata/hash/source，不含正文、路径、`allowed-tools` 或扩展字段。

## 官方 fixture

fixture 固定到 Agent Skills 官方仓库 commit `69ef37e9424c0a7ea9dd2293b559e43ec8176379` 的 `docs/specification.mdx`、`skills-ref/tests/test_parser.py` 与 `skills-ref/tests/test_validator.py`，覆盖最小/可选 frontmatter、中文/俄文 name、NFKC 分解形式及非法命名。`skills-ref` Apache-2.0 代码没有作为产品依赖或打包资产。

Helix 有一项有意差异：官方参考 validator 当前把未知 top-level 字段报错；本项目按既有架构契约保留未知字段但视为不可信，且 Discovery 不披露它们。该差异不扩大权限。
