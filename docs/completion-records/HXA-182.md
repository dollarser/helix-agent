# HXA-182: 大类职责继续收敛与文件传输恢复

日期：2026-09-10（2026-09-09 开始）。分支：`codex/phone-chat-polish`。未提交、推送或合并 main。

## 实现

- `FileManagerService` 从 1037 行收敛到 750 行：`FileManagerPreview` 承担有界文本/图片预览、元数据与分享暂存；`FileManagerTrash` 承担回收站查询、恢复、清空；公开服务入口与结果类型保持。
- `ChatService` 从 1867 行收敛到 1811 行：协议错误/终态到当前语言文案的映射由 `ChatStatusLabels` 负责。单会话准入、草稿/附件、取消及 Turn 生命周期保留原服务归属，不为行数拆出互相引用的状态副本。
- `ManualTransferJournal` 在 app 私有 noBackup 保存版本化操作 ID、scoped 路径、阶段和内容指纹；写入先同步文件，再原子替换。复制/移动/改名进入管线前持久记录，发布前保存内容指纹，源删除前保存阶段。失败清理有歧义时保留记录，不静默丢失操作线索。
- `ManualTransferRecovery` 重新读取日志和实时权限，按观察到的临时/目标/备份内容恢复：发布前恢复旧目标并清理暂存，使用户可重新发起；发布后核实目标，保留剩余源文件，绝不盲目重放删除。改动目标、备份冲突、权限失效或未知记录版本明确失败并保留现场。组件内传输和恢复串行。
- 文件首页和目录页均有“传输恢复”入口，展示待恢复来源/目标、空状态、结果及错误。恢复由用户显式操作；主页面启动不会自动写存储。
- 树指纹检查保留逐节点/分块取消检查；正常取消/失败沿用原有清理和真实部分结果。

决策记录：[ADR-0042](../adr/0042-manual-transfer-recovery-journal.md)（accepted，所有者明确授权持久操作记录与中断恢复，部分扩展 ADR-0041）。纯职责提取不改变其他架构契约。

## 边界

- 不承诺字节偏移续传、断电事务、自动后台队列或跨 Provider 原子事务。移动恢复可能保留部分源文件，界面明确提示自行核实整理。
- 现有 picker 导入/导出和旧版无日志暂存不在恢复日志管线内；不猜测并删除历史文件。目标或备份已变化的情况保留人工检查，不自动覆盖。
- JVM 使用 NIO/故障注入；跨进程设备恢复覆盖 Workspace 的发布边界，已有 SAF 用例继续验证真实 DocumentsContract 适配，但不能冒充所有云盘厂商、所有中断阶段的设备验收。
- 未操作真机、未使用其他人启动的模拟器、未扩大 Agent scope；JNI/Binder 系统根因、长稳、账号与发行门禁仍单列。
