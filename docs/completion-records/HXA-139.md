# HXA-139 完成记录

- 目标：改善 Grok Device Code 的可复制性和可诊断性，并按当前 OpenAI 官方协议新增 Codex Device Code 登录兼容流。
- 前置任务/commit：HXA-138 / `404989f`；accepted [ADR-0021](../adr/0021-third-party-subscription-protocol-adapter.md)。
- 实现：Grok code/URL 独立复制，Android 13+ 剪贴板敏感标记；`ineligible_tier`、`unknown_tier`、`access_denied`、`expired_token` 和严格协议失败分别显示且不含 token。Codex 保留 HXA-118 loopback，新增官方 `deviceauth/usercode`、`deviceauth/token`、`codex/device`、server-returned PKCE 校验和 OAuth token exchange；15 分钟总期限内只重试无副作用 poll 的网络失败，不重放不明确的 token exchange。Codex code/URL 同样可独立复制。
- 缺陷根因：最初把 Codex request/poll/exchange 的网络错误都显示为 token exchange；阶段化后定位到 poll。OpenAI poll 可长时间保持响应，Helix 的 45 秒 call timeout 会误终止整次登录；成功 body 的通用有界读取还会先等待 64 KiB 或 EOF。修复为 poll 网络失败在总期限内继续、403/404 pending 不读取 body、成功 JSON 分块且在完整对象可严格解析时结束，仍保持 64 KiB 上限。
- 自动测试：JVM 44/44；独占 `Helix_M11_Test_API_29`（API 29，arm64-v8a，`emulator-5602`）19/19；独占 `Helix_M11_Test_API_36`（API 36，arm64-v8a，`emulator-5604`）19/19。覆盖固定 origin/endpoint、attempt bounds、server PKCE 配对、pending/网络恢复/过期/交换失败不落盘、前台剪贴板只含选中的 code 或 URL。API 29 首轮剪贴板测试因 Android 10 后台读取限制得到 null，改为可见 Activity 内验证后通过；生产按钮始终在可见 Activity。
- 真人证据：`emulator-5600` API 36 arm64-v8a。前三轮逐步定位 poll body/长轮询 timeout，最终修复版在一次 poll timeout 后继续并完成 token exchange；UI 显示登录完成，`subscription-codex.enc` 为 Runtime UID 私有 `0600` 文件。未读取 token 内容、未调用模型。Grok code/完整 URL 的两个复制按钮均在同机显示成功；既有 Free 账号资格负向证据仍由 HXA-138 保留，本任务以 typed JVM 测试验证精确映射。
