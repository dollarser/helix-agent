# HXA-073 MCP stdio bridge（完成记录）

- 日期：2026-09-05
- 前置任务：HXA-072（commit `8321697`）、HXA-084（已随 M8 合入）
- 状态：完成

## 交付范围

- `extensions:mcp` 新增 stdio 协议层：server command 以不可变 argv 锁定并计算 SHA-256 指纹；客户端请求使用 JSON Lines，服务端 stdout 只接受 UTF-8、逐行、`jsonrpc=2.0` 的 response/error/notification，反向 request、日志噪声、坏 UTF-8、超长行和超预算输出全部稳定拒绝。
- `app` developer 变体新增真实 `McpStdioJobBridge`：请求正文只进入输入快照，不进入 argv；command 指纹进入输入 manifest 并在输出归档中重验；调用只经 `ProotJobClient` 冷绑定提交、查询、取消和对账，不回退到主 App shell，也不盲目重放。
- PRoot Job wire 升级到 protocol v3，增加严格相对 `stdinRelativePath` 与独立 `maxStderrBytes`；Runtime descriptor 的封闭能力集加入 `stdio`。
- Runtime runner 在 stdout、stderr 任一预算触发时立即杀进程组。stderr 只作有界诊断，不进入 JSON-RPC 语义。
- 环境变量继续经过既有 allowlist/Secret 三重筛选；未新增权限、网络通道或持久凭据。

## 验证中发现并修复

- 最初 stderr 达到 cap 后仅停止读取，子进程仍可运行到自然退出；现由 capture 命中预算的回调立即杀整个子进程组，定向测试从约 60 秒收敛到秒级。详见 [输出预算必须终止进程组](../bug-fixes/2026-09-05-proot-output-cap-kills-process-group.md)。
- Gradle 的 companion instrumentation 会在结束时卸载目标 APK，导致后续跨 APK 套件全部按“companion 未安装”跳过。最终验收显式安装 APK 并保留其 active RootFS，再运行主 App 套件；完成记录只采用 `skipped=0` 的最终 XML，不把 skip 当绿灯。
