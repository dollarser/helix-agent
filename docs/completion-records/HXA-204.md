## 契约与交付

决策记录：跨执行域错误恢复是**对持久事实的只读投影**，不新增第二套恢复状态机。七类错误（认证 AUTH / 网络 NETWORK / 能力缺失 CAPABILITY / 用户拒绝 USER_REJECTED / 预算 BUDGET / 执行失败 EXECUTION_FAILED / 结果未知 RESULT_UNKNOWN，外加无错误的 NONE）由现有 Tasks/Turn/Goal/文件/Runtime 的结构化状态投影而来，绝不解析任意错误字符串猜副作用。五类操作各自保留独立身份与准入，**不统一叫 resume**：重连与补权限只导航到修复面（用户修复后自己发起新调用，绝不重发）；查询结果只对账停放副作用（developer 只读巡检 parked proot 调用，consumer 直接刷新事实），从不重放 turn；继续 Goal 走 Goal 自己的显式 continue（必须绑定 goalId/objective 身份，无身份不渲染）；新调用重试走既有 retry（执行时重查全部门禁）。保留 ADR-AGENT-006 的普通预算失败"从已有结果继续"（创建新有界 Turn）、大结果只读分页与模型/显示分离，不改恢复旧调用。用户取消渲染无自动继续操作；认证/网络修复不重新激活旧批准。面板按钮绑定稳定身份（turnId:操作），执行时经 mutex+busy 键**重新检查准入**——渲染与点击之间落定的迟到成功结果、重复点击、别处已做的修复都会令操作失准即 no-op。恢复原因行（recovery-reason）只对 RESULT_UNKNOWN 与 CANCELLED 两类给出恢复专属文案；AUTH/NETWORK/CAPABILITY 的阻塞原因由 turn 自身错误区呈现，面板不重复。

## 边界与遗留

- 四象限旅程通过 ≠ 全产品套件通过：本轮只跑 204 类 + ChatStopProgress/ToolResultRead 回归 + TaskJourneyDeviceTest；全量套件验收属于 206。206 用户路径证据（断网/过期认证/重启后对账/修复能力后由用户继续）已在本批积累（见 `build/batch-b/206-scenario-journal.md`），206 不提前关闭。
- 真实账号未用：断网/过期认证/权限撤销/未知结果均为 fixture（loopback provider + 种子 turn），不借 fixture 宣称真实账号验收；真实账号/远端缺口独立记账，不阻塞无依赖的本地切片。
- Runtime 专属场景仅 developer：查询结果的只读 proot 巡检只在 developer APK 生效（consumer `ProotToolModule.AVAILABLE=false` 时直接刷新持久事实，不巡检）；consumer 无 Runtime 专属场景。
- 记录时点 Host 上另有并行设备测试会话在用模拟器（端口 5670/5672 循环）；本任务四象限用 5554/5556/5558/5560，runner 对已占 serial 拒绝复用（安全失败），不冒充他人模拟器、不 kill 非自有设备。
- 环境注记（本轮发现与修复，供后续任务复用）：
  - 恢复面板的重连/补权限导航必须在主线程驱动（ChatService 服务在 IO scope）：`withContext(Dispatchers.Main.immediate)` 跳主线程再 `navController.navigate`，否则 settings 栈项生命周期错乱、Activity 销毁抛 IllegalStateException。
  - Compose `ComposableNaming`：带非 Unit 返回值的 @Composable 须小写命名；`@Suppress("FunctionName")` 压的是 detekt 的同名规则、压不住这条（规则 id 不同）。私有返回 String 的 composable helper 用 `operationLabel` 这类小写名。
  - 恢复原因行（recovery-reason）只对 RESULT_UNKNOWN/CANCELLED 渲染；AUTH/NETWORK/CAPABILITY 的原因由 turn 错误区呈现，设备测试勿断言该行（首轮 fixture 曾误断言，已修正）。
  - 矩阵 runner 要求 `--output` 目录不存在（exist_ok=False）：重跑前先清/归档上一轮 output 目录，否则 FileExistsError。
