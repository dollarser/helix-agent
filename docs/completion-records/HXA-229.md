# HXA-229：Model-authored Agent Activity Presentation

日期：2026-09-27。分支 refactor/clean-slate-engine。本任务在 HXA-228 冻结 Conversation/Session input-config contract 后，把 Tool timeline 的第一层语义从 deterministic ToolPurpose 主路径收敛为 model-authored intent + Harness-owned truth，不改变 Tool executor、effect classification、permission/approval、result truth 或 AgentLoop owner。

## 交付

### 1. Typed presentation contract

新增 ToolCallPresentation.modelIntent。modelIntent 仅为 display metadata：

- 最大 160 字符；
- 单行；
- 禁止 C0/C1、Unicode format 与行/段分隔符；
- 允许中英文；
- 不授予 permission；
- 不改变 Tool schema 业务语义；
- 不参与 effect classification / approval / execution；
- 不表示 verified success/failure。

缺失或非法 intent 不拒绝合法 ToolCall，而是回退到既有 ToolPurpose.text(...)。

### 2. Model-facing reserved metadata

所有实际暴露给模型的 ModelToolSchema 统一增加可选字段 __helix_intent。该变换只发生在 model-facing schema：

ToolDescriptor business schema → FileToolArguments model projection → ToolPresentationMetadata.augment(...) → Provider request encoder。

业务 registry / MCP / Skill / custom-tool schema 本体不需要知道 presentation metadata。

边界：

- 原业务 properties 已占用 __helix_intent → fail closed；
- 原业务 required 占用 reserved key → fail closed；
- reserved metadata 不加入业务 required；
- additionalProperties=false 的工具仍可通过 augmented schema 显式接受该 optional field。

System prompt 仅在当前请求存在可见 Tool 时加入 tool.presentation guidance，要求模型生成简短目的说明，并明确该字段不是 authority/result。

### 3. 单一 strip boundary

Provider 仍按各自协议解析普通 ToolCall；Harness 在 `prepareModelCalls` 中一次性执行 `ToolPresentationMetadata.extract`，随后 `BufferedModelToolCall` 分开承载 stripped args 与 typed presentation；单调用入口采用同样边界：

- 提取并 sanitize modelIntent；
- 在业务 validation/canonicalization 前移除 __helix_intent；
- validator / permission / effect classification / dispatcher / executor / MCP / Skill 只看到业务参数。

因此 tool_calls.argsJson 保存 stripped/canonical business args，argsHash 对 stripped business args 计算；malformed business JSON 仍走原有 invalid-arguments fail-closed 路径；presentation metadata 非法时只丢弃 presentation，不修复业务参数。

### 4. Sanitization / redaction

模型 intent 在持久化前经过 presentation boundary：

- blank → fallback；
- 超过 160 chars → fallback；
- multiline / control char → fallback；
- ForbiddenContentGuard 命中的 credential-like 内容 → fallback；
- 明显 pre-execution result/authority claim，例如 done / succeeded / 已成功完成 / 已通过 / 无需审批 → fallback。

过滤是有界 shape/prefix 防护，不是对任意自然语言的真实性证明；任何通过过滤的文本仍只按普通文本显示，不获得执行/审批权威。

Conversation export 中 modelIntent 作为 body field 再经过已有 SessionExportSanitizer，因此 export redaction contract 与其它人类可读正文一致。

### 5. Durable persistence / reopen

clean-slate Room v1 的表数量仍为 48；本任务只给 tool_calls 新增 nullable modelIntent TEXT。没有新增 migration，也不兼容 pre-release old internal schema。

设备测试实际关闭并重新打开 HelixStorage，验证 COMPLETED / AWAITING_APPROVAL / DENIED / FAILED / NEEDS_REVIEW 的 intent、args 与 state 可恢复；不同 intent/state 不改变相同业务参数的 argsHash。此项是数据库 reopen，不宣称额外执行了 OS kill/relaunch。

### 6. Provider history 不回灌 presentation args

ChatToolMessageEncoder 直接消费入口已 strip 的 business arguments，不再次提取 presentation。下一轮模型请求仍保持各 Provider 的 tool-call identity/pairing，但历史 arguments 不携带 __helix_intent。

已覆盖：

- OpenAI Chat Completions；
- OpenAI Responses；
- Anthropic Messages。

modelIntent 的 durable source 是 tool_calls.modelIntent，而不是把 presentation field 冒充业务参数永久塞回 protocol history。

### 7. Intent-first Tool timeline

collapsed 第一行优先显示 valid modelIntent；缺失时依次回退 ToolPurpose.text(...) 和 generic ToolPurpose fallback。第二层继续显示 Harness tool/status/duration；修正 live/persisted projection 合并时丢失已有 duration 的问题。没有新增 duration 持久化契约，reopen 后不编造缺失的耗时。

expanded 保留：

- Intent；
- Tool；
- Command / Arguments；
- Result；
- Harness Status；
- Call ID；
- approval card；
- PRoot recovery/detail entry。

没有新增 per-result LLM summarizer，也没有 activity adjacency grouping。

### 8. Harness truth 不受 intent 覆盖

专项验收覆盖：

- safe + mutation ToolCall 同 batch，各自带 model intent；mutation 仍进入 AWAITING_APPROVAL，deny 后为 DENIED，executor 未运行；
- safe call 仍按原 policy 完成；
- NEEDS_REVIEW / acknowledged UNKNOWN ToolCall 可保留 model intent，但 durable state、ToolResult 和 review decision 继续由 Harness 决定；
- intent 不能把 UNKNOWN / FAILED / DENIED / PENDING 变成成功展示。

决策记录：[ADR-AGENT-001 §15](../adr/agent/001-turn-coordination.md) 冻结“模型生成行为语义，Harness 证明执行事实”。Reserved presentation metadata 仅存在于 model-facing schema 与独立 durable presentation field；它在业务 validation/permission/effect/dispatcher 之前 strip。第一阶段只支持 per-call modelIntent，不引入 activity grouping，也不启动额外 LLM 结果总结。
