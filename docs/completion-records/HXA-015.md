- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  - **三层落位**：纯决策（core:agent `RecoveryCoordinator`）/ 存储配对（core:storage 查询 + `withTransaction` + 类型安全写入）/ 可执行接线（`:app` `RecoveryCoordinatorApp` + `HelixApplication` 启动触发）。由验收矩阵的三行命令与模块依赖约束唯一确定（core:agent↛Room、core:storage↛core:agent）。
  - **持久化事实为决策输入**：死进程内存态（`TurnState`/`Goal` 域对象）不可得，决策从 doc 9.1 行（`turns.state` + `tool_calls.state` + `goals.state`）推导；`PersistedTurn` 的“至多一个 RUNNING”init 校验把串行执行不变量做成损坏检测（fail-closed 抛错，不静默挑选）。
  - **不确定副作用源 = 死亡时 RUNNING 的调用**：与 reducer `afterProcessDeath`（取在途队首）逐形态对齐并有跨层一致性测试；AWAITING_APPROVAL 从未执行 → 非不确定（用户审批流可继续）；PENDING 排队 → 停泊但不构成不确定源。
  - **存储层 goal 停泊字段**（`state=PAUSED`、`currentWakeMillis=0`、保留 `nextCheckpoint`）与 `GoalReducer.afterProcessDeath` 的域语义同构；域↔`StoredGoal` 的完整映射与 GoalFlow 归后续 agent runtime 任务（本 HXA 的恢复语义已在两层各自测试中闭合）。
  - **恢复幂等**：INTERRUPTED 非终态 → 重扫可见但决策 NoAction；已停泊 goal/run 不再命中扫描条件。fixture 断言第二次 pass 零写入零审计（审计表计数不变）。
  - **审计约定**：`actor="recovery"`；correlation 取被描述对象（turn→sessionId、goal→goal.correlationId，与 HXA-014 fixture 约定一致）；id 用 UUID（跨启动唯一）；payload 为有界 ID 的固定字段序 JSON（ID 字符集 `[A-Za-z0-9_-]`，无注入面）。
  - **app 启动触发**：后台单线程 + 有理由的宽捕获（维护任务边界，非吞错：全量 Log.e、Error 不吞、下次启动重试）；空库（如既有 connected 测试环境）上是快速 no-op，不干扰 GoalReminder/MainActivity 既有设备测试（实测同跑 6/0）。
  - **`HelixStorage.open/close`**：Room 类型保持在 core:storage 内部（`:app` 连 `RoomDatabase` 超类型都不可达，编译期强制边界）。
