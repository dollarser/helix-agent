- **`app` main（共享）**
  - `files/FileManagerService.kt`（新）：nio-pure 用户文件门面，包住 `files.*` 工具所用的**同一个** `WorkspaceArtifactStore`（containment / 原子发布 / 配额同一套边界）与**同一个** `ScopeRootResolver`。方法面：
    - **来源标识** `sources()`：Workspace（恒在、可写）+ developer 的已启用 all-files 根（本里程碑只读）。
    - **浏览/排序** `list(scopeId, path, SortKey)`：目录优先，名称/时间/大小排序；workspace 根隐藏 `.helix/`（trash 有专属面板）。
    - **预览** `previewText` / `previewImageBytes`；**信息** `fileInfo`（MIME / 大小 / mtime / 真实 SHA-256，超 64 MiB 省略 hash）。
    - **变更** `rename` / `copy` / `makeDirectory` / `nextAvailableName`：显式冲突、**绝不默认覆盖**；非用户区域目标 fail-closed（这是 all-files 根只读的机制）。
    - **trash** `trash` / `listTrash` / `restore` / `purge` / `emptyTrash`：复用 store 的 `moveToTrash` / `restoreFromTrash` / `purgeTrashEntry`，并反解 entry 名（`encodeTrashPath` 的精确逆）供展示/恢复。
    - **批量** `batchMoveOrCopy` / `batchTrash`：冲突策略（ASK / SKIP / RENAME / OVERWRITE）+ 逐项进度回调 + 协作式 `shouldCancel`（取消的项记 SKIPPED"已取消"，已完成项不回滚），产出部分失败清单。
    - **分享** `realFileFor`：唯一返回真实 `File` 的方法，供 FileProvider 造 `content://` URI；该 `File` 瞬时被 OS 分享消费，从不渲染 / 落日志 / 进模型上下文（doc 10 约束模型侧面，不约束 OS 分享）。
  - `ui/FilesScreen.kt`（新）：Compose 屏——来源 chips + 当前来源标签、面包屑导航、列表/网格视图、多选 + 批量操作条、文本/图片预览 + 信息面板、重命名/复制/移动对话框、冲突询问对话框（询问/跳过/重命名/覆盖）、新建文件夹、trash 面板（恢复/永久删除/清空）、长操作进度条 + 取消、分享。
  - `allfiles/AllFilesSource.kt`（新）：developer 向文件管理器暴露的根（`af-<key>` scopeId + 显示名）；consumer 无。
  - `AppContainer`：新增 `fileManager`（与工具管线**共享** `workspaceStore` + `scopeRoots`）。
  - `MainActivity`：`files` 路由（原诚实空态）接入 `FilesScreen(container.fileManager)`。
  - `AndroidManifest.xml` + `res/xml/file_paths.xml`（新）：unexported FileProvider（`grantUriPermissions`），roots = `workspaces/`（app 私有）+ external（developer all-files）。
- **`app` per-flavor**：`AllFilesModule.allFilesSources()`——developer 返回"已启用且 live grant 在"的根（授权被撤销 / 禁用则不出现，文件管理器从不会展示它实际解析不了的 scope）；consumer 恒空。

## 决策记录：关键取舍与理由

1. **nio-pure 用户门面、无 per-call 审批门**：文件管理器是**用户直接操作自己的文件**（不是模型 ToolCall），所以这里没有 doc 09 §4.3 的逐次审批门——审批约束的是模型 ToolCall，不是用户操作自己的文件。它包住与 `files.*` 工具**同一个** containment/原子发布 store 和**同一个** scope 边界，故用户文件管理器与模型工具寻址同一套受约束的 store，安全属性不因"用户路径"而放宽。
2. **all-files 根本里程碑只读**：区域守卫（`WorkspaceLayout.regionOf` + `isRegion`）天然把非 workspace 布局（all-files 根的相对路径不是 `input/`/`work/`/`output/`）的变更 fail-closed 拒绝——浏览/排序/预览/分享可用，重命名/复制/移动/trash 隐藏。这是"即使获 all-files 授权，也只读、绝不覆盖公共存储"的可被用户推理的边界（呼应 HXA-045 的封闭根目录决定）。
3. **SAF scope 接线 + 导入/导出 UI 显式推迟**：HXA-044/045 完成记录曾把"persisted SAF tree grant 接入 scope 解析 + 用户侧导入/导出 UI 动作"预期到 HXA-046；但 roadmap 的 HXA-046 任务书（路径 / 来源 / 排序 / 多选 / 预览 / 冲突 / 长操作 / trash / 分享，无权限可完整用 Workspace）**不含** SAF。按既定范围决定，本 HXA 精确交付 roadmap 行；SAF scope 接线与导入/导出 UI 作为后续跟进（见状态文档已知限制），不混入本 commit。
4. **禁止默认覆盖**：`rename`/`copy` 目标已存在且未带 `overwrite` 返回 `FileOpResult.Conflict`，由 UI 弹"询问"对话框（询问/跳过/重命名/覆盖）；批量里 `ASK` fail-closed 为 `SKIPPED`，用户拿到的是**部分失败清单**而非静默覆盖。
5. **trash 往返复用 store seam**：`trash`/`restore`/`purge` 直接调 store 的 `moveToTrash`/`restoreFromTrash`/`purgeTrashEntry`；entry 名用 `TRASH_ENTRY_NAME` 正则 + `decodeTrashPath`（`encodeTrashPath` 的精确逆）反解出原相对路径供展示/恢复；`listTrash` 对反解失败的坏 entry 名 `mapNotNull` 跳过（fail-closed，不崩面板）。
6. **长操作进度/取消是真实的**：`batchMoveOrCopy`/`batchTrash` 逐项回调 `progress(done, total)`、逐项前查 `shouldCancel()`；UI 用 `AtomicBoolean` 传取消标志（跨 `Dispatchers.IO` 线程安全）。取消的项记 SKIPPED"已取消"，已完成项不回滚（每项是独立原子操作），状态行如实报告"完成：成功 N，跳过/失败 M"。
7. **分享经 unexported FileProvider**：`realFileFor` 返回真实 `File` → `FileProvider.getUriForFile` 造 `content://` URI，`ACTION_SEND` + `FLAG_GRANT_READ_URI_PERMISSION`（接收方得到 scoped read-only 授权，不是 app 的整个文件系统）；MIME 用 bounded prefix probe 设置。`file_paths.xml` 根 = `workspaces/`（app 私有）+ external（developer all-files）。真实 `File` 瞬时被 OS 分享消费，从不渲染 / 落日志 / 进模型上下文。
8. **`StatInfo.mtimeEpochMillis`**：时间排序与 doc 09 `files.stat` mtime 字段都需它；路径不存在为 -1。这是本次对 `core/workspace` 的唯一改动（纯增量字段，既有 `files.stat` 调用方向后兼容）。
9. **测试隔离修复**：设备 `setUp()` 原只删文件不删目录，导致 `createsFolderAndExposesShare` 建的 `work/newdir` 泄漏进下一个测试（`sortsByNameAndSizeSwitchesViewAndMultiSelects` 的排序断言看到 newdir 排最前而失败）。改为清空三个用户区域（文件 + 子目录）+ trash 再重建布局——设备测试顺序不保证，每个测试必须不留残迹。
10. **UI 工具条拆两行**：原单行 7 个按钮在窄屏手机上溢出，把尾部"新建文件夹"按钮裁成零宽（设备测试点不到——真实手机 UX bug）。拆成"排序行" + "视图/操作行"。另：重命名输入框**起空 + 自动聚焦**（对预填且未聚焦的字段 `performTextInput` 不可靠）。
