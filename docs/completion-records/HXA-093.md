- 预算契约：session 默认与发布硬上限仍为 5 分钟/30 次动作，调用方只能选择更小的正预算；每个进入 controller 的节点/全局动作尝试先扣减，失败、拒绝和未知 token 也计数，不能用失败请求绕过预算；第 10、20 次完成后进入 `CHECKPOINT` 暂停，第 30 次后以 `ACTION_BUDGET_EXHAUSTED` 关闭 session、前台通知和全部 token。每次 checkpoint 只接受当前 allowlisted package 上的一次显式用户确认，未暂停时的连续确认返回 `NOT_PAUSED`，不会预存或升级为自动允许。
- 敏感目标契约：固定拒绝 Settings/permission controller/package installer/SystemUI/Magisk/APatch/KernelSU package；package segment 含 bank/wallet/payment/password/authenticator/biometric 时保守拒绝；即使用户把系统 Settings 加入 allowlist，snapshot 仍返回 `SENSITIVE_UI`。动作期再次检查 password/API 34+ data-sensitive 和节点 text/contentDescription/viewId/className；支付、转账、购买、发送、发布、删号、授权、允许安装、开启 Root，以及 password/passcode/PIN/OTP/CVV/验证码/卡号等输入语义返回 `SENSITIVE_UI`。规则只作用于目标节点，fixture 的 `Display options` false-positive control 仍可点击。
- 停止/恢复契约：service 动态监听 `ACTION_SCREEN_OFF`，熄屏锁定边界立即以 `DEVICE_LOCKED` 停止；snapshot/action/resume 还会实时检查 `KeyguardManager.isDeviceLocked`。权限中心不再只相信进程内 service 引用，而是在每个能力入口读取当前 `Settings.Secure` enabled component；系统 grant 被撤销时立即清 session/token/notification/service 引用并返回 disabled/disconnected。真实 `am force-stop` 后进程和 active notification 必须消失；新进程不恢复 process-local session，旧 token 不能执行。
- 自动测试：`:tools:automation:testDebugUnitTest` 共 35 例（HXA-092 时 31 + 当前新增 4）；新增覆盖 0/超过 30 的动作预算拒绝、10/20 步独立 checkpoint、重复确认不能 bank、较小预算耗尽、password/data-sensitive/denied package 动作期复验、支付 click 与 OTP set-text 拒绝，以及固定/分类敏感 package。
