- 实现的契约：
  - doc 02 §5.4 契约全量：输入 = 持久化会话/Turn 快照 + Provider capability；输出每项含 `sourceType/sourceId/trust/contentRef|contentHash` + 估算 token；裁剪顺序确定性且有测试（契约/当前指令/未完成调用完整参数/审批上下文与对应结果保留，旧消息按时间裁剪）；工具 JSON 与审批摘要不截断；超限 ToolResult/文件 → 有界 summary + Artifact 引用/hash；Secret 永不进入；六类内容源标 `UNTRUSTED`。
  - doc 02 §5.3 预算条款：输入预算取用户配置与 Provider capability 更严者（请求级校验）；无法准确 tokenizer 时用保守字节估算（`TokenEstimator`，HXA-011 同一常量与语义）、未知 usage 不当作 0（最小 1 token、总和精确可审计）。
  - doc 07 §7：Context item 带 sourceType/trust/sourceId；确定性裁剪；当前 ToolCall 完整参数、审批上下文和对应 ToolResult 不做字符级截断；Secret 永不进入模型 Context。
  - roadmap 测试清单逐项落地：不可信来源、超预算（两种形态：可裁剪裁剪/不可裁剪 fail-closed）、稳定排序、多工具结果、token usage 缺失。
  - 模块边界（AGENTS.md）：全部在 `core:agent` 纯 JVM（无 Room/OkHttp/QuickJS/MCP SDK/Ktor）；不透明引用只用 HXA-010 `ArtifactRef`；“fake repository”以快照装配实现——构建器是请求纯函数，测试用 fake 源组装 `ContextBuildRequest`，core:agent 不引入任何 repository/存储依赖（真实快照取自 `:core:storage` 的装配属后续 agent runtime 任务）。
- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  - **纯函数落位**：`build(request)` 无状态无 I/O（`object ContextBuilder`），快照由调用方装配——与 core:agent “纯 JVM、无 Room” 边界一致，且让装配/裁剪可在 JVM 全量测试（verification-matrix 的 HXA-016 行仅 `:core:agent:test`）。
  - **retained 标志由 Turn 状态导出**：哪些项是“当前用户指令/未完成调用/审批与对应结果”只有 Turn 状态知道（HXA-011 reducer 已持有 pending/approval 语义）；构建器接收标志并自身额外保护 SYSTEM/MODE_POLICY（契约不依赖调用方自觉）。v1 相关性代理 = recency（快照时间序），显式文档化以便 v2 换相关性策略。
  - **32 KiB 内联 / 2 KiB summary 两个命名常量**：无现成规范值（存储层 summary 仅要求非空白）；取可测试、可审计、保守的常数并写入 KDoc，后续调整只改这里与测试。
  - **全文项 hash 由构建器计算 + 提供须一致**：让每次装配产出的 `contentHash` 都是对最终进入请求内容的真实绑定（审计可重放验证）；summary 项的 hash 指向全量内容（与 `tool_results.contentRef` 的 HXA-014 文件+hash 先校验语义同构）。
  - **fail-closed 优先**：信任错标、ref 无 hash、hash 错配、超界内容、retained 超预算、预算不满足“更严者”、id 重复——全部构造/构建期抛错，不静默降级（AGENTS.md：“不得从 catch-all 返回成功”的装配层体现）。
