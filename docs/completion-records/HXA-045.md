## 范围（对应 `docs/04-roadmap-and-backlog.md` HXA-045）

任务书原文：「实现说明页、系统设置跳转、`Environment.isExternalStorageManager()` 验证和 Helix roots。即使获系统权限，scope 外路径仍拒绝。」doc 09 §4.1 流程：说明 → 跳 `Settings.ACTION_MANAGE_APP_ALL_FILES_ACCESS_PERMISSION` → 验证 grant → 用户选根目录 → 每次 ToolCall 仍走 scope/risk/审批。

- **`feature:files-allfiles`（纯 JVM，模块骨架已在 M0/M1 基线 `e5e3558` 建好）**：
  - `AllFilesSystemProbe`（fun interface）：`Environment.isExternalStorageManager()` 的**实时** seam——生产实现在 app 层调静态 Android API（guarded 到 API 30+），测试注入 fake；结果纯 boolean，**每次调用重读、绝不缓存**（缓存会让用户在系统设置里撤销后 UI 仍继续提供根目录）。
  - `AllFilesRoot`（data class）+ `AllFilesRootCatalog`（object）：固定、有界、**封闭**的 7 个公共存储目录（`download/documents/pictures/music/movies/podcasts/dcim`）。`scopeId(key) = "af-" + key`（合法 `FileScopePath` scope id，模型只见它）；`byKey` fail-closed。**无任意路径入口**（目录浏览器归 HXA-046）。
  - `AllFilesRootsStore`：启用根目录的持久注册表——原子写 JSON、确定性 `af-<key>` scopeId、损坏/版本错误隔离（rename 到 `.corrupt-<clock>`，从不删除）后从空启动、加载时逐条对封闭目录重验（篡改条目丢弃）、重新启用重解析路径但保留原始启用时间、`resolveScopeRoot` 仅对已启用根返回真实路径。
- **`app` developer flavor（`app/src/developer/.../allfiles/AllFilesModule.kt`）**：活的系统 probe（真实 `Environment.isExternalStorageManager()`）、roots 注册表（`filesDir/workspaces/all-files-roots.json`）、fail-closed scope resolver（非 `af-` / 无 grant / 根未启用 → null）、同意屏（诚实说明 + 实时系统状态 + 系统设置跳转 + 有界根目录列表；根目录 toggle 同时 gated 在 ADVANCED profile 与 live grant）。
- **`app` consumer flavor（`app/src/consumer/.../allfiles/AllFilesModule.kt`）**：no-op seam——`AVAILABLE=false`、`resolveScopeRoot` 恒 null、`render` 空操作；**不引用任何 `:feature:files-allfiles` 类型**（`developerImplementation` 约束）。
- **`app` main（共享）**：
  - `AppContainer`：`init{}` 调 `AllFilesModule.init(context)`；scope resolver 的非 app 分支改为 `AllFilesModule.resolveScopeRoot(scopeId) ?: throw ScopeNotAvailable`。`af-<root>` scope 只在 developer + 系统授权 + 根启用时解析，真实路径**只在下游 containment 检查消费、从不交给模型**（doc 10）。
  - `MainActivity`：`permissions` drawer 目的地在 `AllFilesModule.AVAILABLE` 时渲染 `AllFilesModule.render(profileStore)`（developer），否则保留诚实空态（consumer）。
- **`app` developer manifest**：声明 `MANAGE_EXTERNAL_STORAGE`（**仅 developer flavor**），带 `tools:ignore="ScopedStorage"` 与接受风险注释（内部、非 Play 构建；Play 分发的 consumer 变体从不声明此权限）。
- **root `build.gradle.kts`**：`:feature:files-allfiles` 增 `:core:workspace` 项目依赖（scope-id 合法性）+ `implementation` kotlinx-serialization Json（store 的 `JsonElement` API，与 `:feature:files` 同一 pinned 版本）。
- **测试**：
  - `feature:files-allfiles` 单测：`AllFilesRootsStoreTest`（11 例）、`AllFilesRootCatalogTest`（3 例），全绿。
  - 设备测试：`app/src/androidTestDeveloper/.../allfiles/AllFilesDeviceTest.kt`（6 例）——对**真实**平台证明 fail-closed scope 边界契约。

## 决策记录：关键取舍与理由

1. **封闭根目录目录（closed bounded catalog），而非浏览器**：HXA-045 用固定的 7 个公共存储目录作为 Helix roots；任意路径浏览归 HXA-046。封闭集合正是"即使有 `MANAGE_EXTERNAL_STORAGE`，scope 外仍拒绝"这条属性**可被用户推理**的前提——agent 只能寻址用户明确启用的、彼此独立的根 scope。
2. **`af-<key>` 作为 scope id（doc 10：模型只见 scopeId）**：模型看到的是 `scope:af-<key>:<relative>`，从不见真实路径；`af-<key>` 是合法 `FileScopePath` scope id。真实路径只在 `AppContainer` 的 scope resolver 内解析，且只被下游 `resolveFileScopePath` 的 containment 检查消费。
3. **`developerImplementation` 约束下的 per-variant seam**：`:app` 只对 developer 变体依赖 `:feature:files-allfiles`（`developerImplementation`），故共享 `src/main`（scope 解析 + 导航）只能看到一个**变体中立**的 `AllFilesModule` 对象（同 FQN：developer 实现 / consumer 空操作）。consumer 空操作刻意不引用任何 feature 类型——`verify-variant-boundaries.sh` 门禁守住该边界。
4. **roots 接入工具的 scopeRoots 解析**：`AppContainer` 的非 app scope 分支由"一律抛 `ScopeNotAvailable`"改为先试 `AllFilesModule.resolveScopeRoot`。对非 `af-` scope 行为逐字节不变（返回 null → 仍抛），对 `af-<root>` 只在 developer+授权+启用时解析——共享路径零行为变化，仅在 developer 变体新增 all-files scope 能力。
5. **SAF scope 接线不在本 HXA**：沿用 HXA-044 决策记录第 6 条"接线只到适配层"约定——把 persisted SAF tree grant 接入 scope 解析、以及用户侧导入/导出 UI 动作归 HXA-046。本 HXA 只交付 all-files scope。
6. **同意屏读 probe 而非 capability center**：同意屏的实时系统状态直接读与 scope resolver **相同**的 `AllFilesSystemProbe`（一次纯系统查询，UI 线程安全）。刻意**不走** capability center：`CapabilityCenter.check` 会经阻塞 Room 写插入一条执行期 `capability_grants` 审计行（doc 9 §1），绝不能在主线程跑，也不能只因用户打开此屏就触发。
7. **`render` 小写 + `@SuppressLint("ComposableNaming")`**：member composable 在 Compose lint 下要求 PascalCase，但 ktlint（`function-naming`）与 detekt（`FunctionNaming`）都要求 member 函数小写；共享路由调用 `AllFilesModule.render`，故小写胜出，加 `@SuppressLint("ComposableNaming")`。同一注解并加 `@SuppressLint("UseKtx")`：设置跳转用 `Uri.parse` 构造 `package:` Uri（本代码库惯例，`:feature:files` 同样；`:app` 刻意不依赖 `core-ktx`，故 KTX `toUri` 不是可行替换）。
8. **developer manifest 权限 + `tools:ignore("ScopedStorage")`**：`MANAGE_EXTERNAL_STORAGE` 只在 developer flavor 声明（内部、非 Play 构建，合法管理公共存储），`tools:ignore` 记录接受的 Lint `ScopedStorage` 风险；Play 分发的 consumer（Play-distributed）变体从不声明此权限，故 Play 策略检查不受影响。声明此权限本身**不授予** agent 任何能力——即使系统授权开着，文件工具也只能寻址用户明确启用的 `af-` 根，且每次调用仍过 scope/Policy/审批。
9. **既有 4 个 M3 设备测试失败：收口 + 另立跟进**：`./gradlew :app:connectedDeveloperDebugAndroidTest` 全量套件**红**（54 例 / 4 失败 / 5 跳过），4 个失败全是 **HXA-036** 交付的审批/审计设备测试——`ApprovalFlowDeviceTest` 的 B1/B2/B3（`profileSwitchDoesNotChangePendingDecisionOnDevice` / `deniedActionIsNotRepromptedOnDevice` / `stopWhilePendingCancelsTheDispatchOnDevice`）+ `ui/AuditScreenTest` 的 `auditPageShowsRedactedRowsAndFiltersByTool`（见 HXA-036.md:34,36）。失败签名 `IllegalStateException: no pending card for <callId>` 位于测试自身 seed helper（`approvalIdOf`/`seedDeniedDispatch`），是审批卡 seed 竞态。**非 HXA-045 引入的证据**：(a) 这 4 个测试属 HXA-036 交付物；(b) HXA-045 的 diff（allfiles 模块、`AppContainer` 的 `af-` 分支 + `init`、`MainActivity` 的 `permissions` 路由、developer manifest、root 依赖）不触及审批流/审批卡/审计屏任何代码路径；(c) 同一次运行中 HXA-045 自己的 `AllFilesDeviceTest` 6 例 0 失败，反证未破坏共享路径。**决策（用户已定）**：HXA-045 收口（只修 HXA-045 自己文件的门禁问题）；全量套件**如实**报"红因既有"（不伪造、不隐藏）；4 个失败另立跟进单，**不在** HXA-045 commit 内修其他 HXA 的测试。
