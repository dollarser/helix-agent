## 目标

roadmap M6 / HXA-068：

- 「为 ADR-0012 保留的高敏出网规则提供类型化持久化、列表、创建、到期和显式撤销 UI」；
- 「仅 developer/Advanced 可创建，consumer/Standard 永远不提供入口」；
- 「规则严格绑定 Provider/MCP ID、规范 origin、数据类别、scope 与固定期限（1h/24h/7d/30d），不含通配符/滑动续期/Tool Approval Proof/'全部允许'」；
- 「接入 Dispatcher 的 `ruleProvider`，覆盖进程重启、到期、时钟回拨、撤销、切回 Standard、Provider/MCP/schema/origin/scope 变化和并发读写，现有逐次审批在 store/UI 不可用时保持 fail closed」。

本任务把这四条落地为「**存储层强不变量 + 单一 fail-closed 闸门 + 引擎侧窗口判定 + ADVANCED-only UI**」的分层：存储/构造期拒绝任何非 SENSITIVE / 非四固定 TTL / 无 scope / 通配符目标 / 非规范 origin；`LiveEgressRules` 只把「当前 ADVANCED 且可读」的规则集交给引擎；引擎 `isLiveFor` 用实时时钟判窗口 + 精确绑定匹配（任一字段变化即重新逐次审批）；UI 仅在 ADVANCED 渲染。

## 实现的契约（验收焦点）

- **有界 & 类型化**：规则只可能是「SENSITIVE + 四固定 TTL 之一 + 强制 scope + 精确 Provider/MCP ID + 规范 origin」；通配符 / 空白 ID / 非规范 origin / 非 SENSITIVE / 非四固定 TTL / 无 scope **在构造期即不可表示**（值类型 + `init` 不变量）。
- **fail-closed 闸门（ADR-0012）**：Profile 切到非 ADVANCED → 零规则（consumer 同一分支）；存储抛异常/损坏行 → 零规则。窗口/时钟回拨判定在引擎 `isLiveFor`（`createdAt <= now < expiresAt`），回拨像到期一样 fail closed。
- **精确绑定匹配**：引擎仅在 ADVANCED + SENSITIVE egress 下用 `rules.firstOrNull { it.isLiveFor(egress, category, input.scope, now) }`；任一绑定字段（target/origin/category/scope）变化或窗口失效 → 重新逐次审批（`EgressApproval` 给出 per-call 文案）。匹配的规则以 `EgressApproval(null, matchedRule)` 上浮为审批卡的 **BOUNDED 规则**（`aLiveAdvancedEgressRuleReachesTheBrokerSoTheCardShowsABoundedRule` 覆盖 broker→卡片路径）。
- **进程重启重水化**：规则经无损 `UserScopeCodec` + fail-closed `NormalizedEndpoint.parse` 重水化，重水化规则 `==` 实时请求 scope/origin；`EgressRuleUiTest` 的 recreate 回合 + `RoomMigrationFixtureTest` 的 v5 漂移相等 + 迁移链落地共同覆盖。
- **显式撤销 + 无滑动续期**：`revoke` 立即删行；引擎只读不改，窗口不因调用发生而移动（重批 = 新规则）。
- **入口门**：`EgressRuleSection` 仅 ADVANCED 渲染；consumer 无入口（设备 absence 断言）。

## 决策记录：

1. **`UserScopeCodec` 与 `UserScope.toScopeRef` 刻意分家（无损 vs 有损）**：`capability_grants.userScopeRef` 存的 `toScopeRef` 是有界但有损的引用（丢 SAF 显示名、root 会话起始时间等展示字段）；而高敏规则存储必须重水化成与实时请求 scope **`==` 相等**（Policy Engine `scope == scope` 精确匹配，任一字段变化即重新门控），丢字段会静默破坏匹配、放过错误出网。故新规则存储用独立无损 codec round-trip 每个子类型的全部构造字段，`decode` 对任何畸形/控制字符污染 fail-closed 返回 `null`（规则永不匹配，绝不误匹配）。
2. **窗口/时钟回拨判定放引擎 `isLiveFor`，不放 `LiveEgressRules`**：`current` 只把「ADVANCED 且可读」的完整绑定集交给引擎；`createdAt <= now < expiresAt` 用**实时时钟**在每次评估判，使时钟**回拨**（`now < createdAt`）像到期一样 fail closed。若把窗口判定挪进 loader，回拨设备可能在一次读取后错误地长期放行——判定留在引擎则每次评估都重算。
3. **单一 fail-closed 闸门 + 双重非 ADVANCED 短路**：`LiveEgressRules.current` 在**读存储之前**先看 profile（非 ADVANCED 直接 `emptySet()`，连 loader 都不跑——`profileTakesPrecedenceOverTheLoader` 断言 loader 未被调用）；引擎侧 `egressApprovalDetail` 再对非 ADVANCED 短路（`input.profile != ADVANCED → 无规则匹配`）。两层任一即足够 fail closed，双层是纵深防御（consumer 构建永不 ADVANCED，故两层对 consumer 同向）。
4. **UI 创建入口的 fail-closed 只补值类型未覆盖的两处接缝**：空白/通配符 ID 由 `ProviderId`/`McpServerId` 值类型构造期拒绝、非规范 origin 由 `NormalizedEndpoint.parse` 拒绝、非 SENSITIVE/非四固定 TTL 由构造器拒绝——UI 层不重复实现这些不变量，只把用户输入喂给 `withDuration`，让既有值类型/构造器成为唯一权威。
5. **ADVANCED-only 渲染 + consumer absence 设备断言**：`EgressRuleSection` 只由 `SettingsScreen` 在 ADVANCED 下渲染，consumer/Standard 代码路径根本不引用它；`EgressRuleConsumerAbsenceTest` 用 `egress-*` testTag 全不存在做**正向缺失**断言，防止未来误把入口漏进 consumer。
6. **切回 Standard 隐藏但不删规则（ADR-0012 profile 切换 fail closed 不擦存储）**：profile 切换只影响**是否自批**（闸门），不触碰存储；用户切回 Standard 再切回 ADVANCED 仍看到原规则（若未到期）。`EgressRuleUiTest` 末尾断言「Standard 下段隐藏 + `repo.all().size == 1`」。
7. **中文文本暂不资源化，留 HXA-069**：为避免与 HXA-069 的硬编码扫描/翻译键门禁在同一里程碑内互相干扰，本任务的 `EgressRuleSection` 可见文本保持硬编码中文（与 M0 壳层现状一致），统一资源化作法归 HXA-069（roadmap 已把「M0 壳层中文 Compose 文本资源化」划给 HXA-069）。
