- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  1. **屏态=持久化的投影**：`ChatScreenState` 每次变更由 `refreshScreen` 从 Room 重读派生（消息/turn/重试目标），内存只存 in-flight 增量（`activeTurn.streamingText`）与门控挂起（`pendingSend`/`pendingDisclosure`）——“订阅持久化状态”的字面落位，进程重建后 UI 与库一致。
  2. **suspend 面全在服务**：`ProviderService`/`ChatService` 公共面凡触 Room/网络/Keystore 均 `withContext(workScope)` 或 `workScope.launch`（UI 线程安全直调）；Room 读永不在 gate monitor 内（`launchTurn` 的 snapshot 读在 `synchronized` 外——协程纪律）。
  3. **终端 Error 事件的 UI 语义**：HXA-025 流契约下收集方只见事件不见异常——终端 Error 事件必须持久化 FAILED+安全标签+错误码（此前 WIP 把它当 COMPLETED，审查发现修正）；唯一例外通道是收集侧 `catch`（意外边界→INTERNAL+“请求失败，请重试”）。
  4. **重试=新 turn 重发同一 USER 行**（doc 02 §5.2 显式动作非自动重放）；`rowsForTurn` 解决“失败 turn 之后已有更新 turn”时历史不再以 USER 结尾的 `require` 边界（被重试 turn 的 USER 行重排末尾）。
  5. **`terminalize` 用 turn 自有 session**（非当前 open session）：用户流式中返回列表，in-flight turn 继续跑完并把 assistant 行写回原会话（设计意图=turn 不死于导航）。
  6. **provider_snapshot 列是信息性 JSON**：三字段用户可控（displayName 可含引号）→ 最小 JSON 转义后插值（不裸拼不信任文本）。
  7. **测试隔离缝**：`resetDeterministicUiState` 补 `closeSession()`——`ChatService` 进程级状态跨仪器测试类存活，developer 套件中先跑的 `OllamaUiRoundTripTest` 遗留 open session 使后续 `ProviderFlowTest` 落在陈旧会话（`chat-new-session` 节点不存在）——consumer 套件无该测试故独绿（排障 1）。
  8. **secrets 门禁的 fixture 长度纪律**：guard 正则下限 16 < 扫描器下限 20 → 测试 fixture 取 17 字符（过 guard 不过扫描）；AKIA/RSA 头由字符串片段拼装（guard 与扫描模式同形，源码永不出现完整字面量）。
