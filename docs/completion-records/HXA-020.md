- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  - **类型落位**：封闭词表（protocol/residence/endpoint/headers/alias）放 core:model 共享内核——core:storage 只依赖 core:model，不反向依赖 provider:api；`ProviderConfig` 类型化领域值放 provider:api（provider 领域语义）。adapter（HXA-021+）将收到已解析的 `ProviderConfig` + 从 SecretStore 解析出的明文 secret 值。
  - **规范存储**：endpoint 存 `normalized.full`、headersJson 存重编码的排序规范 JSON——行内永远是对称可解析形态，`fromStorage` 是唯一的恢复边界（ADR-0001 风格：解析失败即 IAE，不静默修复）。
  - **residence 保守分类**：裸公网 IP 归 `CUSTOM_REMOTE_UNKNOWN`（不是 PUBLIC_CLOUD——无法判断用途）；主机名判定用私有 DNS 后缀+单标签规则而非解析 DNS（parse 期零 I/O）；全数字标签按合法主机名接受（DNS 语义，非 parse 语义）。
  - **headers 凭据块列表过度近似**：子串匹配会误伤（`X-Keyboard-Layout`），接受该假阳性——凭据通道零容忍优先于便利性，且规则文档化可审计。
  - **Keystore 布局**：单主密钥 + 每 alias 独立加密文件（而非 Keystore 存 secret 值——Android Keystore 不存任意秘密值，只存非导出密钥）；主密钥 reset 后旧密文不可读，`get` fail-closed 是设计行为（不降级、不静默重建）。
  - **`SecretAlias` 字符集即文件名安全集**：把路径穿越防御前移到构造期，SecretStore 的目录布局无需二次校验。
  - **`save`/`overwrite`/`delete` 三原语**：重复 id 的 `save` 走 ABORT 约束冲突（设备测试断言 `SQLiteConstraintException`）；覆盖必须显式 `overwrite`；`delete` 缺失即 IAE（不幂等）——与 HXA-014 仓库守卫风格一致。
  - **verification-matrix 行更新**：原 HXA-020 行未含 `:core:model:test` 与 `:core:storage:connectedDebugAndroidTest`（任务书写于模块落位之前）；按实际测试落位补全，其余行不动。
