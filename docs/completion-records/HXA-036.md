- 关键实现决策：
  - **卡从请求时刻可信事实渲染**：`DispatchFacts`（descriptor/args/请求时刻 profile/egress）在 dispatch 前注册，`onApprovalCard` 只读事实——卡不可能与 binding 哈希漂移；profile 切换后卡仍显示请求时 profile。
  - **有界规则仅展示**：`boundedEgressRule` 不进 9 字段哈希、不参与指纹、不产生任何凭证——规则被 ADR-0005 定义为出网放行机制而非 Approval Proof，卡片只负责让用户看见“这次出网由哪条有界规则覆盖、何时失效”。
  - **broker 卡片投递 fail closed**：sink 未安装 `deliver` 抛错（卡不渲染=不可批准=dispatch 失败传播），不静默吞。
  - **审计页 StateFlow + generation**：`filterState = (filter, generation)`——StateFlow conflate 相等值，用户“清空后再设同一过滤”必须重载；generation 单调计数打破 conflation。`recent(200)` 有界 + 内存过滤=页永不全表加载（security doc §10）。
  - **`publishToolRow(card=null)` = 保留既有卡**：结果行更新不抹掉审批卡——卡随终态（APPROVED/DENIED/CANCELLED/FAILED + 终态文案）永久留在时间线。
  - **`correlationId = toolCallId`**：审计行与工具行一对一可关联（设备测试经此断言）。
  - **composition 零 `.value` 读**：所有 StateFlow 经 `collectAsStateWithLifecycle()`（lint error 规则）；阻塞 Room 只发生 IO scope（`AuditLogService` 构造注入 scope）。
