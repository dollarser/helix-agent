# HXA-136 完成记录：订阅登录入口与真实对话验收

日期：2026-09-06

## 结果

- developer 的 Codex Subscription 受管理 Provider 行增加“管理订阅登录”入口；主 App 只在用户点击后验证
  Runtime 已安装、启用且同签名，并用固定显式 `ComponentName` 打开 `CodexLoginActivity`。
- 可见 UI 启动允许 Android 从 force-stop 状态恢复 Runtime；它不 bind Service、不提交 Job、不读取登录态。
  Runtime 缺失/禁用/签名不符均返回安全的 unavailable，consumer seam 返回 `NOT_SUPPORTED` 且不展示受管理 Provider。
- API 36 arm64-v8a 上使用用户在 Runtime UI 完成的真实 Codex 登录，从 Helix 普通 `ChatService`
  创建 Session 并发送固定小型请求，`gpt-6-astra` 返回精确 `HELIX_OK`；Turn 为 `COMPLETED`，只有一个
  model-call。prompt SHA-256 为 `f9fcdfbfe36d6e1d02cd0f8c2e258dce817787a95ff4669c1de027f2855d683e`。
- 初次真实验收失败的根因是通用 Responses encoder 写入 `max_output_tokens`，而 HXA-127 已证明消费订阅
  endpoint 对该字段返回 HTTP 400。修复仅在 Runtime 的订阅线协议适配层省略该字段；Helix 内部仍使用
  统一 `ModelRequest`，普通 Chat 的 token 上限没有被解释为凭据、Tool Approval 或额外能力。
- 首次编排脚本未启用 fail-fast，曾在 instrumentation 失败后错误打印成功标记；该输出作废。最终命令使用
  `set -euo pipefail` 并明确检查 `OK (1 test)`，本记录不引用作废标记。

## 生命周期、安全与设备边界

- API 29 `emulator-5602` 与 API 36 `emulator-5604` 均为 arm64-v8a 独占 AVD；Runtime force-stop 后入口
  各 1/1 通过，Activity 可见且 `dumpsys activity services` 无持续 `ConnectionRecord`。
- Runtime 缺失分支在两台设备各 1/1 返回 `RUNTIME_UNAVAILABLE`；安装后再执行 force-stop/打开分支。
- API 36 的真实两次 Job（连接探测和普通对话）均为 `SUCCEEDED`、模型 `gpt-6-astra` 且已 reconcile；
  每个 Job 目录最终只剩 redacted `record.json`，request/event 正文已删除。未读取、记录或复制 vault、token、
  account id；主 App 不持久化这些数据。
- 人工 OAuth/Device Code AVD 必须设 `hw.keyboard=yes` 并使用 `-no-snapshot-load` 或 `-no-snapshot`
  冷启动。本次 API 36 的 `hardware-qemu.ini` 确认为 `hw.keyboard = true`；仅用 `-no-snapshot-save` 会继续
  加载旧的无键盘快照。该排障已写入 `docs/development/environment.md`，本机 AVD 配置不进入 Git。
- consumer/store、官方支持、Claude/Grok/Copilot 模型调用与动态模型目录不在本 HXA；后续必须独立推进，
  无付费或端到端证据时保持未核实。
