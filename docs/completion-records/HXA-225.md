主要行为：

- Agent 可以主动读取已授权工作目录中的图表、截图或照片，不再要求用户把文件重新附到消息。相对路径使用请求冻结的目录，绝对路径、任意 URL 和 scope 越界不放行。
- `browser.screenshot` 的保存行为保留；满足视觉条件时同时提供归一化产物。没有视觉或准备失败时明确返回未呈现说明，不因视觉失败重复截图或伪称模型看过。
- 只有可信工具执行结果的类型化 sidecar 能建立视觉绑定，不扫描任意 MCP JSON/Base64 作为像素上传指令。普通 `read` 仍是文本/字节读取。
- 复用已有 Artifact 和 message_attachments，没有新增 Room 表；继续上一轮 50-table v1 baseline，`composer_drafts` 不存在。本轮没有重建用户数据库。
- 工具文件权限与模型出网确认分开；具体图片、哈希、Provider 配置、实际模型、会话、Turn 和消息共同绑定。拒绝/超时不上传；同一有效确认可短期复用，不能授权其他图片或其他 Turn。
- 旧图片不永久常驻上下文；被拒绝、超窗或无视觉时用类型化 `ToolImageOmission` 投影成明确提示。canonical 工具正文不被改写，压缩匹配仍检查正文和调用身份，预算计入实际提示。
- 最终像素按实际长度上限＋一字节探测读取，校验同一份字节的哈希/MIME；文件增长、截短、同大小篡改、停滞流和取消均不能造成无界读取或错误上传。
- 现有订阅图像入口改为逐请求解析，不再依赖全局 session 指针；Runtime 接收验证后的不可变快照，同引用不同字节拒绝，不把本机披露对象作为 IPC 权限传递。

## 竞品核验结论

- 借鉴 Codex 专用 `view_image` 和 Claude Code Read 的视觉内容路径，不把 Base64 文本当视觉输入。
- 修正旧 ADR：当前 Responses 官方 SDK 明确允许图片/文件工具输出，因此不再与 Chat Completions 一律使用合成消息。
- OpenCode V2 当前附件文档区分 read 归一化与直接附件；Helix 共享已有归一化器是自己的选择，损坏图不回退原始上传。
- 手机竞品仅用于产品/平台边界参照，没有将未核验的内部像素授权机制写成事实；没有复制竞争项目代码。

一手来源、访问日期与不采用的行为保留在 ADR/使用说明，不把公开文档当实机性能证据。
