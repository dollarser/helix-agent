- 实现的契约（逐条对照任务书）：
  - **平台生成 footprint，只并行无冲突 READ_ONLY**：`EffectFootprint.from(descriptor, canonicalArgs, extractor)` 全部输入是可信事实；非只读/未知/Root/Accessibility 恒排他；READ_ONLY 间按资源键+origin 判冲突（JVM 10 测试 + 设备 3 组断言）。
  - **默认并发 2 / 硬上限 4 / 门只降不升**：构造 `require 1..4` + `min(max, gate())`（JVM 上限/门控/超限拒绝测试 + 设备门控真机计时）。
  - **完成乱序、回填按 call sequence**：`BatchResult` 按槽位结算 + `TOOL_RESULT` 行按 call 顺序持久化 + 下一请求只从持久化行重建（JVM 回填顺序 + 设备 900ms/40ms 乱序 + 重载重建 8 测试）。
  - **queue/approval/execution/verification timing、decision source、attemptId 持久审计**：`DispatchAuditEvent` 全阶段时间戳（含新增 `queuedAt`）+ `decisionSource` + `attemptId` → `audit_events` 18 键 payload（app 单元 + 设备 queuedAt≤startedAt、attemptId=1 断言）。
  - **取消**：未启动项 durable `Cancelled`+审计 `CANCELLED_BEFORE_START`（JVM + 设备）；已启动项 `CANCELLED_AFTER_START` 稳定错误、副作用未知按失败（HXA-035 既有 + 设备单失败测试）；每槽位必有终态（null 槽结算 `Cancelled`）。
  - **receipt 一次性且 NOT_PENDING 稳定**：SQL 原子守卫（answer/cancel/supersede）+ 状态检视五 reason（设备 8 测试全矩阵）；**不能代替 Approval Proof**——类型层（`ReceiptResult` 与 `ApprovalProof` 无转换 API）+ schema 层（独立表、零审批列）双封闭。
  - **有界技术重试**：仅 `sideEffectFree` 确认 + 同 envelope + 活检查重跑 + 同记录重铸（不重上卡）；reMint 每 binding 一次性（SQL refund 守卫）；target/scope/origin/权限变化=新 ToolCall（envelope 校验在重试门）；无 escalation/主进程 fallback API（框架 8 测试）。
  - **测试矩阵**：确定性顺序/屏障/公平性/预算/取消/进程恢复（重载重建）/`model-visible ⇔ persisted`（strict 重建 + 只从持久化行回填）全覆盖。

- 关键实现决策：
  - **footprint 归 framework、只吃可信事实**：模型输出（参数）只经规范化进入资源键提取器，`operationClass/risk/lane` 全部来自注册表契约——“并发由平台从规范化效应决定，永不由模型/MCP/Skill 自报”在 API 形状上落位。
  - **重试在 dispatcher、调度器只管准入/排序**：dispatcher 持有 proof+broker+活检查，scheduler 对重试无感知（一次 `dispatch` 调用内部重试）——重试语义与并发语义正交，且“同/更强隔离”由同 envelope 重跑活检查保证。
  - **`reMint` = 同记录退款+重铸**：`refundByBinding` 单条 UPDATE 守卫（`consumedAt IS NOT NULL AND decision='APPROVED'`）使双重退款在 SQL 层结构不可能；重铸走 HXA-034 `mint` 同一拒绝链（窗口过→null→原始失败终结，不降级为重上卡）。
  - **重试审计同一 bindingHash/actionFingerprint**：重铸凭证的 hash 是**记录**的 binding hash（=presented hash），carried 进重试 ctx 使两次审计行可关联到同一次用户决定。
  - **assistant 工具步持久化模型原始参数串**：`TOOL_CALLS` 行 content=原始 JSON 数组串（`arguments` 字段=原始串），strict 重建逐字还给 provider 编码器——回放字节稳定，`model-visible ⇔ persisted` 不需要二次规范化。
  - **调度器测试暴露的三个真实 bug（记录为证据）**：① 池任务捕获扫描循环变量→stale 索引 AIOOBE 杀死池线程、future 永不完成、协调线程死转（按值捕获修复）；② footprint 在任务启动时才占槽→准入扫描超发并发（3>2）+ 值相等删除误删同形 footprint（改准入时占位 + 按索引删除）；③ `CompletableFuture.anyOf().join()` 在全部 pending future 皆失败时抛 `CompletionException`→协调循环必须把失败当作正常步进（重写为 signal-future 等待，首个终态即唤醒）。
  - **SKIPPED_DEPENDENCY 未触发（v1）**：`ToolScheduler` 无依赖等待路径（依赖编排属 HXA-105 后期），`BatchResult` 形状已为未来保留 `error` 位。
  - **门控 v1 = AppContainer 常数**：`resourceGate: () -> Int` 构造 seam 就位（设备测试动态 2→1 验证只降不升），低内存/后台/热限制的实信号采集属后续 HXA。
  - **`MAX_TOOL_ROUNDS_PER_TURN=8` 常量**：fail closed（超预算=turn FAILED 安全标签，不静默截断）；完整用户可配 TurnBudgets 属后续 UI HXA（core:model `TurnBudgets` 已存在）。

- 未实现/排除：低内存/后台/热限制的实信号门控（seam 已就位，信号采集后续 HXA）；用户可配 TurnBudgets UI（常量 8 轮，fail closed）；依赖编排/workflow（HXA-105 + proposed ADR-0009 范围，v1 不实现）；Plan/Goal 模式工具入口 UI（mode 仍 ACT 硬编码）；QuickJS/PRoot lane 真实执行器（lane 键契约与串行化已测试，执行器归各自 runtime HXA）。
