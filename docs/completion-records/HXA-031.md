    - `ToolSchemaValidator.kt`（新）：值验证器（doc 02 §7.1 管线“JSON Schema 验证”步的实现）——`validate(schema, value)` 返回 sealed `ToolSchemaValidation { Valid; Invalid(reasons) }`，**收集全部违规**（每条约束一条 reason + JSONPath 定位，dispatcher HXA-035 可直接回给模型，不打地鼠）。语义：`type` 至少匹配一声明类型（`integer` 只匹配整数数值，integral double 如 3.0 算 integer）、`enum` 结构化深等、object（required 存在性/properties 逐名递归/additionalProperties 三态）、array（items 逐元素+minItems/maxItems）、string（minLength/maxLength 按 **Unicode code point** 计——4 字节 emoji=1 非 UTF-16 的 2，pattern **无锚**匹配=JSON Schema 语义）、number/integer（min/max 含界、exclusive 不含界、double 比较）。畸形 schema（注册期本应拦下）在验证期**失败关闭**（报 invalid 而非静默跳过约束）。

- 实现的契约（逐条对照任务书）：
  - object/array/string/number/integer/boolean：类型检查+各自结构 keyword 全实现（含 integer⊂number 语义、integral double 判整）。
  - enum：结构化深等，非空数组，条目是值（含 null/对象/数组字面量）。
  - required：存在性检查，路径定位报告。
  - additionalProperties：false（禁额外）/true（放行）/subschema（额外属性递归验证）三态。
  - min/max：minLength/maxLength（code point）+minimum/maximum/exclusiveMinimum/exclusiveMaximum+minItems/maxItems 全家族，注册期界交叉检查（min≤max）。
  - pattern：ECMA 风格无锚匹配，注册期 256 字符上限+可编译+嵌套无界量词拒绝。
  - unknown keyword 拒绝注册：子集门在 `ToolDescriptor` 构造器（input+output 双查）——构造即拒绝，注册必然拒绝；越类型 keyword 与未知 keyword 分消息报告。
- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  1. **注解 keyword 允许且忽略**（`description`/`title`/`default`/`examples`/`$comment`）：工具 schema 需要 per-property `description` 喂模型表，标准 JSON Schema 的注解 keyword 本就被校验器忽略——忽略不是执行，与“unknown keyword 拒绝”不矛盾（拒绝的是**约束性**未知 keyword）。
  2. **无 `type` 的 schema 允许全部类型 keyword 的联合**：约束按值形态生效（值是 string 才查长度）——比“无 type 只许 type/enum”更宽容且语义一致，未知 keyword 仍全拒。
  3. **`pattern` 双重有界**（长度 256 + 嵌套无界量词启发式）：MCP server 可自报 schema，验证线程是 ReDoS 暴露面；启发式只拦经典 `(a+)+`/`(.*)*` 形（有界 `{n,m}` 不误伤——`([a-z]{1,3})*`/`(\d+){2}` 允许），KDoc 声明非完备（不跟踪字符类/转义/选择）。
  4. **值验证返回结构化 `Invalid(reasons)` 而非抛异常**：模型参数不合法是正常流（HXA-035 要回给模型完整错误），不是框架故障；注册期 schema 检查才用 IAE（与 HXA-030 fail-closed 风格一致）。
  5. **kotlinx 1.9.0 的 JsonPrimitive 公开面只有 `isString`/`content`**：`isNumber`/`isBoolean` 不存在（成员或扩展都没有）——`ToolJsonPrimitives` 从规范字面量 content 派生种类，isString 守卫挡住字符串 "true"/"123"（kotlinx `longOrNull` 会解析字符串 content，不守卫即类型洞）。
  6. **参数 canonical 编码不属本 HXA**：任务书只交付 schema 子集；审批哈希的参数编码归后续审批工作（KDoc 已澄清归属，避免 HXA 编号误挂）。

- 排障记录（真实证据，供后续参考）：
  1. **kotlinx 1.9.0 无公开 `isNumber`/`isBoolean`**：`JsonPrimitive` 公开面只有 `isString`/`content`（javap 核实；`longOrNull`/`doubleOrNull`/`boolean` 是包级扩展）——初版按“成员”假设写 import 全 unresolved；且 `longOrNull` 会解析字符串 content（`"3"`→3），不守卫就是类型洞 → `ToolJsonPrimitives`（isString 先守卫）解决，provider:api capability codec 的 `require(!primitive.isString)` 先例同语义。
  2. **keyword 分发先于类型上下文检查**：初版 `when` 把 `minLength` 等 leaf 检查排在上下文检查前——`{"type":"object","minLength":1}` 被 generic 非负整数检查吞掉、零违规（测试抓到）；重构为“上下文门先行”（contextKeys→ALL_SUBSET_KEYWORDS→unknown 三级判定），越类型 keyword 与未知 keyword 分消息。
  3. **checkCrossBounds 的 `?: return` 链**：`doubleOf(x ?: return) ?: return` 对 `Double?` 做 `>` 被编译器拒（nullable receiver 禁 `>`）——改显式 null 判定。
  4. **Kotlin raw string 里的 `$`**：JSON key `$ref`/`$id`/`$comment` 与 `$schema` 在 raw string 中触发插值/无效 JSON——测试侧用 `${'$'}` 拼接；`"\$comment"`（普通字符串）在 main 侧正确转义。
  5. **`assertEquals(emptyList(), …)` 类型推断失败**：JUnit4 重载下 `emptyList()` 无类型 → 改 `assertTrue(….isEmpty())`（12 处）。
