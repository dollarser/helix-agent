## 目标与任务书

任务书（`docs/development/roadmap.md` §12 `### HXA-084`）：Job copy、argv/显式 shell script、cwd/env allowlist、timeout/process-group cancel、bounded stdout/stderr、output archive/hash。任务自定义 env 对名称 secret pattern、已知 SecretStore 值和认证来源做拒绝测试，Runtime 不获得 SecretStore 能力。以 `executionId/jobId` 原子维护有界 journal/terminal commit；重复 jobId 不重复启动。journal 首版上限 128 条/1 MiB metadata：active 与未对账 terminal 不因额度静默删除，额度满则拒绝新 Job；已对账 payload 立即删除、tombstone 最多留 7 天；未对账 terminal 最多保留 30 天，之后只留 evidence-expired marker 并使主 App 停泊 `INTERRUPTED`。Binder 断连后只查询/对账，匹配 input hash 的 terminal proof 才可恢复结果，否则停泊 `INTERRUPTED`。实现前后台状态机：任意计算不得冒充 `dataSync`；没有合法 FGS 类型时退后台暂停/取消。若真机证明确需 wake lock，只在用户可见 FGS 的 RUNNING 窗口限时持有并覆盖全路径释放。

前置：HXA-080/081/082/083；架构文档 [local-code-execution §6.5/6.6/6.7](../architecture/local-code-execution.md)；[ADR-0007](../adr/0007-companion-runtime-lifecycle.md)（已接受）。**无新 ADR**——本任务实现已接受的 ADR-0007 与架构文档既定决定。

## 交付

1. **Job 协议与类型（`:runtime:proot-ipc` 扩展）**：`ProotJobSpec`（`executionId`/`jobId`（`job_`+12 hex）/`ProotJobCommand.Argv` 与 `ProotJobCommand.Script` 互斥/`relativeWorkingDirectory` 严格单段名/已筛选 env ≤64 条/`deadlineMs`/`maxOutputBytes`/`inputManifestSha256`，构造器全量闭包校验）、`ProotJobRecord` + 严格 codec（`schemaVersion` 闭集、未知 key 拒绝、state/字段一致性——SUCCEEDED 必须带 `exitCode`，ORPHANED/INPUT_INVALID 绝不携带、terminal commit = canonical committedBody 的 SHA-256）、`ProotJobWire`（Parcel 手工编组 + 两端强制同序 + PFD 传递）、协议码扩展（`TX_JOB_SUBMIT/QUERY/CANCEL/RECONCILE` = `FIRST_CALL+2..+5`；`REPLY_JOB_ACCEPTED=4/DUPLICATE=5/REJECTED=6/NOT_FOUND=7/STATE=8/UNAVAILABLE=9`）、`ProotJobHandler` 接口 + `ProotJobSubmitResult`（Accepted/Duplicate/Rejected；PFD 所有权在一切结果下移交 handler）。服务端 `ProotRuntimeServiceBinder.handleJobTransaction`：零跨 APK 异常，任何 `ProotIpcException`/通用异常 → 稳定 `REPLY_JOB_REJECTED(INVALID_SPEC)`。
2. **archive 原语（`:runtime:proot-core` 扩展）**：`JobManifest`/`JobManifestCodec`（canonical 编码、parse 全量 fail-closed）、`JobPath`（词法 traversal/绝对/drive-letter/空段拒绝）、`JobArchive` 限额（路径长/总字节/manifest 上限）、`JobZipWriter`（manifest 先行、逐条流式哈希、`close()` 要求 written==expected 全等）、`ZipJobExtractor`（自研 central-directory 扫描先行拒绝 symlink/非常规条目——JDK `ZipEntry` 不暴露 unix mode，symlink 请求的唯一载体）、`ZipCentralDirectoryScan`（EOCD/CD 手写解析，LE 校验）。
3. **companion runner（`:runtime:proot-app`，新增 `ProotJobRunner` 单例 + `ProotJobStore`）**：
   - **journal**（`ProotJobStore`，companion 是唯一 journal 写者）：每 job 一目录 `jobs/job_<12hex>/record.json`（tmp+fsync+rename）；**128 条 / 1 MiB metadata 额度**——active 与未对账 terminal 绝不因额度静默删除，额度满拒绝新 Job（`JOURNAL_FULL`）；已对账 payload **立即删除**（tombstone ≤7 天）；未对账 terminal ≤30 天后只留 `evidenceExpired` marker。
   - **生命周期**：submit（jobId/executionId 任一重复 → `Duplicate` 现有记录，绝不二次启动；PENDING 落盘 → 单线程 jobExecutor 异步执行）→ 输入 PFD→`input.zip`→`ZipJobExtractor`（失败 → `INPUT_INVALID`，payload 立即删除）→ manifest sha 对账 → RUNNING → 启动 → bounded 等待（deadline+30 s 兜底）→ terminal。
   - **启动链（设备实证，见「SELinux 平台事实」节）**：`setsid → /system/bin/linker64 → <inst>/bin/proot -r <inst>/rootfs -b /dev -b /proc -b <jobTmp>:/tmp -b <workspace>:/workspace -w /workspace …`，env 全量 `clear()` 后仅注入 spec 环境 + 固定项（`LD_LIBRARY_PATH=<inst>/bin/lib`、`PROOT_LOADER=<nativeLibraryDir>/libhelix_loader.so`（哈希对锁校验副本）、`PROOT_TMP_DIR=<jobTmp>`、缺省 `PATH`）。
   - **exec 可执行副本**：loader 以应用 native 库形式随 APK 发行（`jniLibs/arm64-v8a/libhelix_loader.so`，`extractNativeLibs=true` 安装即落 APK 安装目录 = `apk_data_file` 上下文——appdomain 对 app_data_file 的 `execute_no_trans` 被 SELinux 拒绝、对 apk_data_file 被授予）；每次 Job 启动前校验该副本与 081 锁验证的 `bin/loader` 同哈希，失配 fail-closed（单一真相仍是锁）。
   - **watchdog 与取消**：`scheduleWithFixedDelay` 250 ms tick（lint `DiscouragedApi` 实证 `scheduleAtFixedRate` 在 cached 进程恢复时会突发补跑，已改 delay 语义）；deadline 命中/`cancel` → **进程组 kill**（`kill -9 -<pid>`，setsid 保证 pgid==pid，设备验证全树含 guest 子进程死亡）+ `/proc` 后代 BFS 双保险；`childPid` 经类层级私有字段反射（android.jar 任何 API 级均无 `Process.pid()`，API 36 `java.lang.Process` 为无字段抽象标记类——libcore 实现子类保留私有 `pid` 字段，设备验证）。
   - **bounded 捕获**：stdout/stderr 共享预算（`AtomicLong`，`maxOutputBytes`），超限 → `OUTPUT_LIMIT_EXCEEDED`；终态输出归档 = workspace + `stdout.txt`/`stderr.txt`（截断标记）+ canonical manifest，`JobZipWriter` 写入客户端提供的 output PFD（`AutoCloseOutputStream`）；SUCCEEDED 但输出不可交付 → 降级 FAILED；非 SUCCEEDED 终态落 `failure.txt` 证据（state/exit/outputDelivery/stderr 尾 1 KiB，换行扁平化）。
   - **孤儿清扫**（service 重启/job 线程入口）：PENDING/RUNNING 记录若宿主 `/proc` 证 pid 已亡 → `ORPHANED`（无 exitCode）；仅当持久化 `(pid, starttime)` 双证匹配才允许进程组 kill——重用 pid 绝不被触碰。
4. **客户端（`:runtime:proot-client`，新增）**：
   - **`ProotEnvScreen`（纯 JVM，无 Android 依赖）**：env 筛选器。默认 allowlist（`HOME`/`PATH`/`LANG`/`LC_ALL`/`TMPDIR`/`TERM`/`USER`/`SHELL`）+ 任务显式加名；拒绝规则按固定优先级：secret 名 pattern（`KEY|TOKEN|SECRET|PASSWORD|PASSWD|AUTH|COOKIE|CREDENTIAL` 大小写不敏感，**即使显式加名也拒绝**）→ 已知 SecretStore **值**比对（改名也拦住）→ 认证结构形状（`Bearer `/`Basic `/`Authorization:` 前缀、PEM private key 材料）→ allowlist。拒绝理由只含变量名、**绝不含值**（理由会被记录/持久化）。Runtime 全程不获得 SecretStore 能力——筛选发生在主进程，companion 只见筛选后结果。
   - **`ProotJobClient`**：每事务冷绑定（ADR-0007；`ProotRuntimeSupervisor.openConnection`/`closeConnection`）；`submit`（PFD 所有权约定：已投递由服务端全结果关闭；未投递——bind 拒绝/dead binder——客户端关闭）；`query`/`cancel`/`reconcile`；`awaitTerminal`（轮询到 terminal/evidenceExpired→`Interrupted`/unknown/超时；`shouldContinue` 回调支持退后台提前停止）；`DeadObjectException`→稳定 `DEAD_OBJECT`，线格式异常→`PROTOCOL_MISMATCH`，**绝不让异常穿越客户端边界**。Binder 断连后只查询/对账、绝不盲目重放（ADR-0007；terminal proof 恢复由调用方按 `inputManifestSha256` 匹配，不匹配停泊 `INTERRUPTED`——客户端 `AwaitOutcome.Interrupted` 即该停泊点）。
   - **前后台纪律**：客户端与 runner 均**不启动任何 FGS、不持有 wake lock**；任务书「任意计算不得冒充 `dataSync`」在此以结构性方式满足（本模块零 `ForegroundService` 引用）。退后台暂停/取消由调用方（HXA-085 `bash` Tool 编排）经 `awaitTerminal` 的 `shouldContinue`/`cancel` 执行；wake lock 问题留给 HXA-086/088 真机证据决定。
5. **`:app` 跨 APK Job E2E（新增 `ProotJobE2eDeviceTest`，developer androidTest）**：主 App 侧打包输入归档（`JobZipWriter`）→ PFD → `ProotJobClient.submit` → 轮询 `SUCCEEDED` → `ZipJobExtractor` 重验输出归档（manifest sha == 记录 `outputManifestSha256`）→ `reconcile`（对账时间戳落、payload 即删、proof 留存）；重复 jobId → `Duplicate` 不重启动；未知 jobId → 稳定 `Unknown`；env 筛选在 wire 前拒绝 secret（边界断言）。

## SELinux 平台事实与启动链根因（设备实证，M8 关键平台结论）

1. **app 私有目录不可 exec**（API 36 设备 dmesg/logcat 实证）：`avc: denied { execute_no_trans } for path=/data/data/com.helix.runtime.proot/files/runtime/inst_*/bin/proot scontext=u:r:untrusted_app tcontext=u:object_r:app_data_file tclass=file permissive=0`。普通 `execute`（mmap/dlopen）**是**授予的——只有 `execute_no_trans`（execve 且换域）被拒。AOSP `private/app.te`（android15-release）同源：appdomain 对 `app_data_file` 无 execute 授权，对 `apk_data_file` 有 `x_file_perms`（execute + execute_no_trans，注释 "Allow apps to read/execute installed binaries"）。**推论**：untrusted_app 域永远不能 execve 自己的 app 数据文件；能 exec 的可写存储位置只有 APK 安装目录。
2. **PRoot 的 loader exec 无法用 `LD_PRELOAD` 拦截**：PRoot 通过 `PTRACE` 把 tracee **在途** execve 系统调用的路径参数改写为 `$PROOT_LOADER`（`src/execve/enter.c` 的 `translate_execve_enter`；loader 本身是 load-script mmap 加载器，从不自 exec guest 二进制）。在途 syscall 不再经过 libc 的 `execve` C 函数，故 `LD_PRELOAD` 符号替换对 loader exec **永远不触发**（设备实证：装载 hook 后 `execve("/bin/sh"): Permission denied` 原样复现）。曾按 Termux termux-exec 模型实现 `exec_hook.c`（`system_linker_exec` 式路由），验证无效后**整体移除**（不保留死代码）。
3. **最终启动链（设备实证可执行）**：
   - 应用侧：`/system/bin/setsid`（/system，可 exec）→ `/system/bin/linker64`（linker 是 mmap 而非 execve 目标——绕开 `execute_no_trans`）→ `<inst>/bin/proot`（app_data，mmap 合法）。
   - guest 侧：PRoot 改写后的 tracee execve 指向 `PROOT_LOADER=<APK 安装目录>/lib/arm64/libhelix_loader.so`（`apk_data_file`，execute_no_trans 授予）→ loader mmap guest 二进制并跳转。
   - 该链在 API 29/36 双模拟器实证：guest 内 `git 2.49.1`/`python3 3.12.14`/`node v22.23.2` 可执行，workspace 绑定与文件写入正常，setsid 进程组 kill 全树死亡（ALL_DEAD 实证）。
   - 参考：Termux 执行环境（https://github.com/termux/termux-packages/wiki/Termux-execution-environment）、PRoot master 源码（loader 协议、tracee-side execve 改写）。
4. **次级平台事实（固化）**：`LD_PRELOAD` 目标文件缺失时链上**每个** exec 都致命失败（`CANNOT LINK EXECUTABLE`）——故 hook/前置库路径必须先验证存在；APK 的 `extractNativeLibs` 默认（on-demand）下 native 库**不会**落为文件（lib 目录为空），`jniLibs` 需要文件形态时必须 `useLegacyPackaging=true`；android.jar 任何 API 级无 `Process.pid()`；`scheduleAtFixedRate` 受 lint `DiscouragedApi` 反对（cached 进程恢复补跑）。

## 决策记录：runner 实现决定（无新 ADR）

- **loader 可执行副本走 `jniLibs` 而非运行时拷贝**：APK 签名保护 + 安装目录 `apk_data_file` 是唯一 appdomain 可 exec 的落点；每次 Job 前与 081 锁哈希交叉验证（单一真相 = 锁；副本 = 可执行镜像）。不加入 081 锁（新 084 组件，APK 签名即信任基础，与文档 line 397 "PRoot/CLI Runtime 通过正常签名 APK 更新" 一致）。
- **`LD_PRELOAD` exec hook 实现后移除**：设计正确（只路由 runtime-root 路径、musl guest 忽略 preload、APK 签名保护）但**平台机制使其不可达**（在途 syscall 改写，见平台事实 2）——移除而非保留，避免误导后续维护者。
- **journal 额度满 = 拒绝新 Job 而非淘汰**：任务书明文「active 与未对账 terminal 不因额度静默删除」；128 条/1 MiB 是首版上限，拒绝是 fail-closed 语义。
- **`awaitTerminal` 的 `Interrupted` 结果 = 主 App 停泊点**：evidenceExpired（30 天）或 proof 不匹配时客户端只交付 `Interrupted(record)`，停泊 `INTERRUPTED` 的状态机归 HXA-085 编排（本 HXA 不预造 goal 状态机）。
- **watchdog 用 `scheduleWithFixedDelay`**：lint `DiscouragedApi` 的论据（cached 进程恢复时 `AtFixedRate` 突发补跑数百/数千次）对本场景是真实风险——tick 幂等性靠 delay 语义 + deadline 判断天然保证。
- **测试 JVM 复现优先**：Android-only 缺陷（页大小/SELinux/反射 pid）走设备；纯逻辑缺陷（双哈希测试 helper、archive 语义）先 JVM 复现再修——本任务两次受益。
