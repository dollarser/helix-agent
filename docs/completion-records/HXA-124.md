## 目标与交付

项目所有者要求从调研材料出发，在新 worktree 设计并实现 connector 概念与插件迁移。

- `extensions/skills/.../connector/ConnectorPackage.kt`：有界 ZIP/JSON reader，Codex/Claude 插件与通用 MCP/Skills 导出结构适配，跨平台差异诊断，稳定内容 hash。七项新增 JVM 测试覆盖格式、认证剥离、stdio/SSE/专有 app 差异、多 Skill、hash、路径冲突、symlink、炸弹、取消。
- `app/.../connector/ConnectorService.kt` 与 `ConnectorSection.kt`：系统文件 picker、预览/展开 Skill 文件清单与有界正文、安装记录、独立 bearer、连接测试/工具选择、Skill 开关、移除及重新创建 service/进程后的恢复。
- `McpAppService`：在旧 executor 开始网络流程前及准备发送工具调用时重新检查激活实例，停用或替换后不复用旧引用。
- `core/storage`：更新既有 MCP authAlias 并同时禁用；仍只保存 alias，无数据库 schema 变化和 migration。
- `scripts/export-codex-mcp.py`：Python 3.11+ TOML → 脱敏 MCP JSON，两个测试；不提取环境/平台登录态，不执行命令，拒绝覆盖已有输出。
- `scripts/accept-hxa-124-connectors.sh`：显式指定设备，安装本分支 consumer APK 与测试 APK，跑六项专项测试及两个独立进程的恢复阶段；解析 instrument 的测试结果而不是只依赖 adb exit code。
- [设计与迁移指南](../architecture/connector-portability.md)：技术结论修正、来源证据等级、兼容矩阵、认证与 Runtime 分期。

## 权限、数据与许可证

无新增依赖、权限、网络代理、执行域或第三方源码；复用既有 Commons Compress、JSON、Skill validator、MCP SDK 与 SecretStore。MCP credential 值不随导出/导入写入 package 或 Room；只在用户输入后进入 SecretStore。所有工具继续复用 Dispatcher/Policy/Approval/审计。

## 明确限制与后续工作

- 没有真实第三方测试账号，未验证 Codex/Claude/WorkBuddy/QwenWork 的商业连接器登录、服务权益和业务调用；国内平台私有格式仅按调研样本构造 fixture。
- 第一版仅直接迁移 HTTPS Streamable HTTP 与 Skill；stdio/CLI、OAuth、平台 app ID、hooks/rules/agents、完整 TOML 的手机端导入仍不支持。Codex TOML 用桌面导出脚本转换。
- 源 Skill 的宿主工具名不静默重写，脚本不会在安装时执行。大 catalog 的工具搜索/按轮 schema 加载仍为后续任务。
- 新安装禁用；同 hash 的既有共享 Skill 保持既有用户状态。组件开关不是 connector 级跨存储原子事务。安装中断可留未启用快照；更新并存，不覆盖旧版。
- 移除保留 Skill snapshot 和 disabled MCP 配置行；不撤销厂商侧 consent，不撤回已送达的远端操作。App 启动不自动重连 MCP。
- 合并时需核对 AppContainer/Settings/MainActivity/roadmap/status 的 M10/M11 并行改动；收尾发现 CLI 分支使用 ADR-0022，本分支已改为 ADR-0023；未来合并前仍需复核编号与并行改动。
