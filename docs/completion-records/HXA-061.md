## 修改文件

生产（`feature/browser/src/main/kotlin/com/helix/feature/browser/`，模块无独立 build 文件，配置集中在根 `build.gradle.kts` 的 `:feature:browser` 分支）：

- **`snapshot/BrowserSnapshotScript.kt`**（新）：固定版本化 JS 提取脚本。`EXTRACT` 是编译期常量、自包含 IIFE、只读（无 bridge / 无网络 / 无 cookie 或 storage 读取、无 DOM 变更），自行执行有界约束：`MAX_NODES=400`、`MAX_TEXT=200`、`MAX_VISITED_ELEMENTS=20000`；结果带 `v`（`SCRIPT_VERSION`）、`truncated`、`nodes`。密码字段值**绝不**读出（发 `null`）。页面内容从不被内插进脚本文本（脚本与页面数据完全分离）。
- **`snapshot/SnapshotBinder.kt`**（新，纯 JVM）：把固定脚本的原始 JSON 结果绑定成 `BrowserSnapshot`，是**唯一的信任边界**。页面（doc 09 §3.4 UNTRUSTED）可损坏/截断/谎报自己的 DOM，故脚本自己的有界约束**不是**信任边界——binder 逐字段、逐上界、逐 node index 再校验，任何漂移都 fail-closed。所有结构化访问走安全 cast（`as? JsonObject` 等），类型违规是 fail-closed 结果而非抛出的异常。fingerprint 与 node token 都在**受信宿主**铸造，页面无法伪造。
- **`snapshot/SnapshotToken.kt`**（新，纯 JVM）：node token 的铸造/解析/校验。token = base64url(JSON)，携带绑定；宿主是唯一铸造者**兼**校验者。`validate` 按绑定顺序（tab → origin → generation → fingerprint → TTL）检查、**首个失败胜出**，每个非 `Valid` 结果都是 fail-closed 拒绝。
- **`snapshot/BrowserOrigin.kt`**（新，纯 JVM）：origin 派生。只处理 URL 策略已准入的 URL；`data:` → 常量 `data:opaque`（spec 的 opaque origin，避免比较两个不同 opaque URL）、`about:blank` → `about:blank`、http(s) → `scheme://host[:port]`（大小写折叠、丢弃默认 80/443）。
- **`snapshot/BrowserSnapshot.kt`** / **`snapshot/UntrustedWebContent.kt`**（新）：`BrowserSnapshot`（tabId/url/title/origin/navigationGeneration/fingerprint/mintedAtMillis/truncated/nodeCount/nodes）与 `SnapshotNode`（index/tag/role/text/value/href/name/token）；`UntrustedWebContent` 是包裹所有页面派生文本的类型化「不可信数据」标记（网页内容标记不可信的落地形式）。
- **`BrowserController.kt`**（改）：新增 `snapshot(id, onResult)`（无 settled 页面的 tab fail-closed 为 `NO_PAGE`）、`latestSnapshot(id)`、`verifyNodeToken(id, token, nowMillis)`；成功 snapshot 存入每 tab 的 `snapshots` map，导航命令（navigate/goBack/goForward/reload）与 `closeTab`/`clearHistory`/`destroy` 时清除（旧 snapshot 的 token 随导航失效）；构造函数注入 `clockMillis` 供 token TTL 的确定性测试。
- **`webview/WebViewTabHost.kt`**（改）：新增 `evaluateSnapshot(onResult)`——执行固定脚本 `BrowserSnapshotScript.EXTRACT`（本 feature 唯一运行的 JS，doc 09 §3.4）并回传原始结果串；两道守卫保证恶意/卡顿页面可安全评估：`SNAPSHOT_TIMEOUT_MS=5s` 期限（页面可阻塞自己的主线程，超期合成 null 结果，永不挂住调用方）+ per-request generation 计数器（丢弃超期/销毁后到达的迟到回调，陈旧页面结果永不归因到新请求）。

## 实现的契约

1. **固定、版本化 JS 是唯一执行的脚本**（doc 09 §3.4）：`WebViewTabHost.evaluateSnapshot` 只评估 `BrowserSnapshotScript.EXTRACT` 这一个编译期常量；模型/宿主都无法提交任意脚本。脚本自包含、只读，自身执行 `MAX_NODES`/`MAX_TEXT`/`MAX_VISITED` 有界约束并对超限页面置 `truncated`。脚本测试（`BrowserSnapshotScriptTest`）钉住：JS 字面量 = Kotlin 上界、带版本、自包含 IIFE、不触碰任何特权面（bridge/网络/cookie/storage/DOM 变更）、密码字段特殊处理。
2. **宿主 fail-closed 再校验，页面有界不是信任边界**（doc 09 §3.4）：`SnapshotBinder.bind` 逐字段/逐上界/逐 index 复核脚本结果——版本缺失或非数值 = `MALFORMED_RESULT`（结构性畸形），版本不匹配 = `VERSION_MISMATCH`，`truncated` 非布尔 / `nodes` 缺失 = `MALFORMED_RESULT`，`nodes > MAX_NODES` = `OVER_BUDGET`，非连续 index / 未知 role / 异常 tag / 超大或非字符串字段 = `MALFORMED_RESULT`；null/blank = `NO_RESULT`，非对象 JSON = `UNPARSEABLE_RESULT`，无 origin = `NO_ORIGIN`。所有结构化访问走安全 cast：类型违规是 fail-closed 结果，**不是**抛出异常（页面不能靠畸形载荷打崩 binder）。
3. **fingerprint 与 token 在受信宿主铸造**：fingerprint = 对**整棵树**做长度前缀大端编码后的 SHA-256（无歧义、确定性），在宿主对页面产出的**原始**数组计算、早于 token 铸造；node token 是 base64url(JSON) 携带绑定，宿主是唯一铸造者。页面或模型能读到并回放 token，但宿主在用时逐绑定复核，回放的 token 在页面导航、跨 origin、DOM 变更（新 fingerprint）或超 TTL 的那一刻即失效（doc 09 §3.3 失效语义）。
4. **node token 校验顺序：tab → origin → generation → fingerprint → TTL，首个失败胜出**；每个非 `Valid` 判定（`MalformedToken`/`WrongTab`/`StaleOrigin`/`StaleGeneration`/`StaleFingerprint`/`Expired`）都是 fail-closed 拒绝。`verifyNodeToken` 对 tab 的**活状态**（当前 origin、`navigationGeneration`、宿主最后一次 snapshot 的 fingerprint）校验，token 自身声明的任何内容都不单独可信。
5. **密码字段值绝不读取**：固定脚本对 `type=password` 字段发 `value: null`（合法 null，非畸形）；binder 将 null 视为可选字段的合法取值（非 `MALFORMED`）。设备测试 `aPasswordFieldValueIsNeverRead` 证明宿主永不见到密码串。
6. **网页内容一律不可信**：snapshot 里所有页面派生文本（text/value/href/name 与 url/title）都包在 `UntrustedWebContent` 里——一个惰性、有界、仅数据的类型，不承载任何指令语义（doc 09 §3.4「指令不构成 Tool 授权」）。敌意/指令式长文本设备测试证明它 round-trip 为长度上限内（`MAX_TEXT`）的惰性数据。
7. **恶意/卡顿页面可安全评估**：`evaluateSnapshot` 用 `SNAPSHOT_TIMEOUT_MS` 期限 + generation 计数器双守卫——页面阻塞自己主线程时超期合成 null（→ `NO_RESULT`，永不挂住），迟到/销毁后的回调被丢弃（陈旧结果永不归因到新请求）。设备测试 `aHostileHugeDomIsBoundedToTheNodeCap` 证明 600 节点的敌意 DOM 在有界时间内（<15 s）快照为恰好 `MAX_NODES` 且 `truncated`。
8. **导航使旧 token 失效**：导航命令与关闭/清除路径清除 `snapshots` map；`navigationGeneration`（HXA-060 地基）在每次 committed 导航自增，使旧 token 因 `StaleGeneration` 失效。设备测试 `aTokenGoesStaleAfterNavigation`（`StaleGeneration`）与 `aTokenBoundToAnotherTabIsRejected`（`WrongTab`）钉住。

## 决策记录：

1. **binder 作为唯一信任边界、宿主重铸 fingerprint/token**（而非信任脚本的有界输出）：doc 09 §3.4 明确页面是 UNTRUSTED，脚本在其 JS 上下文运行，恶意页面可损坏/截断/谎报自己的 DOM。因此脚本的 `MAX_*` 是**性能/DoS 防护**，不是信任边界；宿主 `SnapshotBinder` 独立逐字段复核并把 fingerprint 与 token 铸在宿主侧，页面无法伪造。这是「页面有界 ≠ 宿主可信」的落地，与 HXA-060 下载「声明长度不是信任边界、`copyWithCap` 逐字节再查」同一条 fail-closed 原则。
2. **密码字段发 `null`（而非空串/占位）**：`null` 在 binder 里是可选字段的合法取值（`readString(required=false)` 对 null 返回 `Ok(null)`），既能表示「密码字段不读值」又不触发 `MALFORMED`，且与空文本框的可区分（空框可发 `""`）。这是「密码值绝不读取」的可测落地。
3. **token 校验顺序 tab→origin→generation→fingerprint→TTL、首个失败胜出**：绑定越靠前的越根本（tab 都错就不必看 origin），且稳定的顺序让「多项错时返回什么」可预测、可单测（`checkOrderIsTabOriginGenerationFingerprintTtl`）。
4. **fingerprint 用长度前缀大端编码再 SHA-256**（而非直接哈希拼接的 JSON）：字段值可含任意字节，长度前缀消除「`["a","bc"]` 与 `["ab","c"]` 撞码」这类歧义，保证确定性且对内容敏感（`theFingerprintIsDeterministicAndContentSensitive` 钉住）。
5. **`data:` 绑定到常量 `data:opaque`**（而非完整 data URL）：spec 里 data 文档是 opaque origin；用常量使两个不同 data 页面的 token 仍能靠 origin+generation 绑定正确失效，且不会把（可能含敏感的）完整 data payload 写进 token。
6. **detekt 高返回/吞异常点用针对性 `@Suppress` + catch 收窄**（而非重构掉 fail-closed 分支）：仓库既有惯例（HXA-060 `BrowserController.saveDownload`/`streamToDocument`、`BrowserUrlPolicy.evaluate` 同法）——fail-closed 的「每守卫一个返回」与「解析失败静默回 null」是**语义本身**，不宜为绕开规则而合并分支；catch 从 `Exception` 收窄为具体类型（`SerializationException`/`URISyntaxException`）以同时满足 `TooGenericExceptionCaught`。

## 风险或后续任务

- **fingerprint 失效依赖重新 snapshot**（见「未实现」）：原地 DOM 变更须再 snapshot 才转 `StaleFingerprint`，否则只 TTL 兜底。HXA-062 的工具「动作前重新 snapshot」的设计使这一窗口在实际 click/type 路径不可达；若未来出现「不重新 snapshot 就动作」的工具，需重新评估此窗口。
- **5 s 快照超期合成 null**：极慢页面在 5 s 内不返回脚本结果会被判 `NO_RESULT`（fail-closed），可能误伤超大/卡死页面——但这对「恶意页面可安全评估」是**期望**行为（宁缺勿挂）。若真实负载下常见误报，可将 `SNAPSHOT_TIMEOUT_MS` 提为可配置，但默认保持有界。
- **语义节点白名单**：`VALID_ROLES`（link/button/field/image/heading/interactive）与 `TAG_PATTERN` 是宿主侧的封闭集合；新增角色/tag 需同步脚本与 binder（`BrowserSnapshotScriptTest` 会因字面量漂移先挂门禁）。
- **无浏览器 UI 消费 snapshot**：本任务只暴露 `BrowserController.snapshot`/`verifyNodeToken` 与数据模型，UI 尚不呈现 snapshot（HXA-062 起才有 click/type 的可视/可操作节点）。
- HXA-062（Browser actions）开工时：实现 `:tools:browser` 的 `browser.*` 工具（open/navigate/back/forward/reload/find/click/type/scroll/screenshot），click/type 只能消费本任务铸造的 node token 并先 `verifyNodeToken`（`Valid` 才可动作）；导航或 DOM 变化后旧 token 自动失效（本任务已铺好 origin/generation/fingerprint 绑定）；密码/验证码/支付字段拒绝落地为工具层守卫。
