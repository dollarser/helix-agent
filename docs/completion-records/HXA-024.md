# HXA-024 完成记录

- 目标：Anthropic Messages adapter（roadmap HXA-024）：实现 Messages streaming、`tool_use/tool_result`、stop reason 和错误映射；测试 tool result 顺序约束。
- 前置任务/commit：`66b01f4`（“HXA-023：OpenAI Chat Completions adapter”）。
- 修改文件：
  - `provider:anthropic`（新增源码，纯 JVM 库模块，模块图 `provider:anthropic → provider:api + core:model` 不变，与 HXA-022/023 协议岛同构、零共享代码）：
    - `AnthropicSseReader.kt`：`internal class AnthropicSseReader`——独立实现的增量 SSE 读取器：
      - Anthropic 用 `event:` + `data:` 成对帧（`message_start`/`content_block_start`/`content_block_delta`/`content_block_stop`/`message_delta`/`message_stop`/`ping`/`error`），无 `[DONE]` 令牌（`message_stop` 类型事件标记流结束）——与 Chat Completions 的 data-only 帧不同，读取器交付带类型的 `(type, data)` 事件对。
      - 与兄弟适配器同一字节纪律：任意边界拆包（行中/多字节 UTF-8 序列中，尾部最多缓冲 3 字节）、逐字节 UTF-8 解码（组装后 code point 做 overlong/越界检查）、LF/CRLF/裸 CR、`:` 注释、`event:` 设定下一帧类型（缺省 `message`）、多 `data` 行以 LF 连接、`id/retry` 与未知字段按 spec 忽略。
      - `finish()` 宽容派发“行完整（换行终止）但缺尾随空行”的挂起事件；截断半行按 WHATWG 丢弃（解码器终止守卫转为可重试 `Error(PROTOCOL)`）；坏 UTF-8/1 MiB 超长行/8 MiB 超量 payload → 解析失败。
    - `AnthropicStreamDecoder.kt`：`public class AnthropicStreamDecoder`——Messages 流 → `ModelEvent` 映射：
      - `message_start` → 记住 `message.usage.input_tokens`（不立即发 Usage，与兄弟适配器一致：Usage 随终止块一次发出）；
      - `content_block_start`：`tool_use` 块（`id`+`name`，id 经 `ToolCallId` charset 校验、单响应 ≤32 个、块 index 界 0..1024、重复 start 失败）→ `ToolCallStarted`（以 content block index 为键）；`text`/`thinking` 块静默跟踪；未知块类型（含 `redacted_thinking`）忽略（前向兼容），其 delta/stop 一并忽略；
      - `content_block_delta`：`text_delta`→`TextDelta`、`thinking_delta`（vendor 字段是 `thinking` 不是 `text`）→`ReasoningDelta`、`input_json_delta`→`ToolArgumentsDelta`（按块 index 键控的增量 arguments）；**顺序约束**——delta 落在未知/已停止块 index、或 delta 种类与块种类不符（如 tool 块上的 `text_delta`）→ 整流失败；
      - `content_block_stop`：停止 `tool_use` 块 → `ToolCallFinished`；
      - `message_delta` 是终止块：所有 content block 必须已停止（否则失败）；先校验 `stop_reason` 再发任何事件（fail-closed：畸形终止不泄漏部分 Usage）；发 `Usage(inputTokens 来自 message_start, outputTokens 来自本块; 缺省透传 null)` 后发终止：`end_turn`/`stop_sequence`→`Completed("stop")`、`max_tokens`→`Completed("length")`、`tool_use`→`Completed("tool_calls")`、`refusal`→`Refusal("refusal")`（合法完成）；未知 reason → 失败；
      - `message_stop` 标记 vendor 流结束，不是终止事件：`message_delta`（终止）后到达的 `message_stop` 是 vendor 正常顺序（放行）；终止后其他受理事件、`message_stop` 之后（终止前）的任何受理事件 → `Error(PROTOCOL, false)`；
      - 无终止（流结束/断流，含半行 JSON 截断，无论是否收到 `message_stop`）→ `Error(PROTOCOL, retryable=true)`；
      - `ping` 与未知事件类型忽略（前向兼容）；
      - `error` 事件错误映射（`error.error.type`）：`overloaded_error`/`api_error`→`SERVER_ERROR(retryable=true)`、`rate_limit_error`→`RATE_LIMITED(retryable=true)`、`invalid_request_error`/`not_found_error`→`PROTOCOL(false)`、`permission_error`→`AUTH(false)`、未知→`SERVER_ERROR(false)`（fail-closed）；
      - 非 2xx HTTP 错误是 transport 层（HXA-025）的映射面，不是 SSE。
    - `AnthropicRequestEncoder.kt`：`public class AnthropicRequestEncoder(imageResolver)`——`ModelRequest` → Messages 请求体（与两个 OpenAI 形态的差异逐一对应）：
      - 顶层 SYSTEM 消息离开 `messages`，成为顶层 `system` 字段（多条按序以空行连接）；
      - USER 无图 → 字符串 content；带图 → 块数组（`text` 块在前 + 每图一个 `image` 块：`source.type` `base64`（`media_type` 取自 `ImageReference` 封闭允许表）或 `url`）；ASSISTANT → 字符串；
      - **`tool_use/tool_result` 顺序约束**：连续 TOOL 消息合并为**一条** user 消息，content 为 `tool_result` 块数组（`tool_use_id` = 内部 call id、`content` = 结果文本、按原始消息顺序）——Anthropic 要求严格角色交替，一轮 assistant 工具调用的多个结果属于同一条 user 消息；编码器校验：首条非 system 消息必须是 user、合并后序列严格交替 USER/ASSISTANT（TOOL run 计为 user 轮）——任何违例（首条非 user、连续同角色、工具结果不紧跟 assistant 轮）以 `IllegalArgumentException` fail-closed；
      - tools 用扁平 `input_schema` 字段（非 function 嵌套），schema 经严格解析器校验为 JSON 对象后逐字嵌入；
      - `max_tokens` 线上**必填**：`maxOutputTokens` 为 null 时发 `DEFAULT_MAX_TOKENS = 8192`（可逆实现选择）；
      - `reasoning` 映射 `thinking` 预算：LOW/MEDIUM/HIGH → 1024/4096/16384，clamped 到 `max_tokens - 1024`；不可行组合（预算 < 1024）抛 `IllegalArgumentException`（fail-closed，绝不静默丢弃用户请求的推理）；
      - `seed` 不发送：Messages API 无 seed 参数（记录为 HXA-025 capability snapshot 的能力缺口）；`temperature`/`stop_sequences` 按需出现；`stream` 恒 `true`。
      - 内部契约不能携带 assistant 的 `tool_use` 块（HXA-021：工具关联只在 TOOL 消息上）——编码器忠实编码结果侧；含 TOOL 消息的 vendor 请求只有在运行时请求构建器（M2 后段，从持久化 ToolCall 补上配对 assistant 轮）供给后才在线上有效，KDoc 明确记录该边界。
      - stateless（doc 10 §2.5）：每次请求携带完整会话；body 无 secret（`x-api-key`/`anthropic-version` 头由 transport 加，HXA-025）。
    - `AnthropicAdapter.kt`：门面——无状态 `requestBodyEncoder` + 每流 `newDecoder()`；KDoc 明确协议岛纪律：本协议失败绝不静默切任何其他协议，协议由 provider 配置（`ANTHROPIC_MESSAGES`）固定。

- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  - **零共享的协议岛**：roadmap 明文独立实现——`AnthropicSseReader` 是本模块自有的 typed-event SSE 实现（与 HXA-022 的 Responses 读取器同构、与 HXA-023 的 data-only 读取器不同）；`ImagePayload`/`ImageResolver` 是本包内等价边界（`Base64(value)` 单字段形态对齐 HXA-023 约定，`media_type` 取自 `ImageReference` 封闭允许表）。不为此引入跨 adapter 依赖。
  - **单 Usage 事件随终止发出**：Anthropic 把 usage 拆在两处（`message_start.message.usage.input_tokens` + `message_delta.usage.output_tokens`），解码器合并为一个 `Usage(input, output)` 随终止发出（缺失透传 null）——保持“每流一个 Usage、Agent Loop 不得把未知 usage 当 0”（doc 02 §5.3）的消费面不变。
  - **`message_stop` 不是终止事件**：终止是 `message_delta`（或 `error`）。`message_stop` 只标记 vendor 流结束：终止后到达是正常顺序（放行），终止前到达后任何受理事件 → 失败，流在无终止时结束（无论是否收到 `message_stop`）→ 可重试 `Error(PROTOCOL)`。
  - **终止先校验后发射**：`message_delta` 先验证 `stop_reason` 再发 Usage/终止——未知 reason 的畸形终止不泄漏部分 Usage 事件（fail-closed，fixture 覆盖）。
  - **未知块类型前向兼容忽略**（含其 delta/stop），未知事件类型忽略（与 HXA-022 事件词汇的前向兼容纪律一致）；但已知块类型上的**种类不符 delta** 是顺序约束违例，必须失败。
  - **编码侧顺序约束 fail-closed**：Anthropic 要求严格角色交替，内部契约（HXA-021）不能表达 assistant 的 `tool_use` 块——编码器对 TOOL 消息只做结果侧编码并强制交替/首条 user 约束（IAE，带明确诊断）；配对 assistant 轮由运行时请求构建器（M2 后段，持久化 ToolCall 带完整 arguments）供给。不在此 HXA 扩大 core:model 契约（越出任务允许模块）。
  - **thinking 预算映射与 fail-closed**：LOW/MEDIUM/HIGH → 1024/4096/16384，clamped 到 `max_tokens - 1024`；不可行（< 1024）抛 IAE——不静默降级用户请求的推理（HXA-021 KDoc 承诺的 Anthropic native knob 落位）。
  - **`max_tokens` 必填**：null 时发 8192 默认值（可逆选择，KDoc/记录均标注）。
  - **detekt 定点豁免（3 处，均带注释理由）**：解码器类级 `@Suppress("TooManyFunctions", "ReturnCount")`（函数数 = vendor 事件词汇 + 块/emit 助手）；`startToolBlock` `@Suppress("ThrowsCount")`（空标识/charset/fan-out 三个独立违约）；`handleMessageDelta` `@Suppress("ThrowsCount")`（开放块/缺 reason/未知 reason 三个独立违约）。沿用 HXA-020/022/023 定点豁免先例。
  - **测试框架 JUnit 4**（`org.junit`）：模块约定的 `jvmTestDependency = junit4`（4.13.2），kotlin.test 不在 classpath——与已提交 HXA-022/023 测试同框架；`assertEquals(message, expected, actual)` 参数序与 kotlin.test 不同，`assertThrows`（4.13）替代 `assertFailsWith`。
