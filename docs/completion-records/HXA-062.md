## 目标

roadmap M6 / HXA-062「Browser actions」+ doc 09（`architecture/android-platform-capabilities.md`）§3.3/§3.4：

- 实现 open/navigate/back/forward/reload/find/click/type/scroll/screenshot（本任务实现全部 10 个 + snapshot 工具接线，共 11 个 `browser.*`）；

**`:feature:browser`（生产，实现端口）**：

- **`BrowserToolBridgeImpl.kt`**（新，544 行）：生产 `BrowserToolBridge`，把 11 个端口方法执行到主线程 `BrowserController`。**线程桥**：工具在后台 dispatcher 运行、`BrowserController` 是 main-thread-only，故 `onMain`（同步，post 到主 looper + latch 阻塞）与 `onMainAsync`（post 一个 kickoff、其 completer 在主线程被回调、异步评估期限高于 controller 内部期限，使慢页面在桥期限之前先表现为 settled 的 NO_PAGE/空结果 → 干净 TIMED_OUT）。每方法 fail-closed：未知 tab = NO_TAB、陈旧 token = STALE_TOKEN、敏感字段 = REFUSED（宿主 `SensitiveFieldClassifier` 权威于固定脚本——只有**两者都**判正常才 PERFORMED）、内部期限 = TIMED_OUT。`screenshot` 的捕获在主线程、写盘有意在主线程外，任何捕获/保存失败（配额/磁盘/坏路径）fail-closed 为 ERROR，字节绝不半公开。

## 实现的契约

1. **11 个 `browser.*` 工具是端口的薄 fail-closed 映射**（doc 09 §3.3）：每个工具 `execute` 解析（已 schema 校验的）参数、调用**恰好一个**端口方法、把闭合 outcome 映射成稳定 `ToolExecutorResult`——拒绝（`denied`/`refused`）、陈旧 token（`stale-token`）、未知 tab（`NO_TAB`）、超时（`TIMED_OUT`）都映射成**非成功**结果（Completed 携带这些稳定 status，或 Failed/TimedOut），绝不一律回「成功」。参数缺失/越界/畸形 = `Failed`（`sideEffectFree`）。安全工作在**端口**（WebView/token/策略边界），工具只塑形模型面向契约。
2. **固定、版本化动作脚本是唯一被执行的动作**（doc 09 §3.4）：`BrowserToolBridgeImpl.runAction`/`scroll` 只评估 `BrowserActionScript.click`/`type`/`scroll` 三个编译期常量之一；模型/宿主都无法提交任意脚本给 WebView。脚本自包含、只触碰自身 document，自身执行与 EXTRACT 一致的有界 walk；`type` 文本以 JSON 字符串字面量注入（唯一被内插的值，`BrowserActionScriptTest.theTypeTextIsInjectedAsAJsonStringLiteral` 钉住引号转义）。
3. **敏感字段双闸门，宿主权威**（doc 09 §3.3 密码/验证码/支付字段拒绝）：click/type 的执行路径有**两道**闸门——固定脚本内嵌的 JS 闸门 + 宿主 `SensitiveFieldClassifier.classify` 对脚本回传字段属性的再分类。只有**两者都判 Normal** 才 PERFORMED；任一判敏感即 REFUSED，reason 是类别（`password`/`payment`/`one-time-code`）。宿主是权威（页面可谎报自身字段属性，脚本闸门可被页面数据绕过，宿主分类器在**受信**侧对脚本回传的**原始**属性独立复核）。设备测试 `sensitiveFieldsAreRefusedAndOrdinaryFieldsPerform` 证明密码/支付字段拒绝、普通字段/按钮执行。
4. **动作前 node token 再校验，导航/DOM 变化/TTL 使旧 token 失效**（doc 09 §3.3）：click/type 只消费 HXA-061 铸造的短期 node token，动作前经 `BrowserController.verifyNodeToken` 对 tab 的**活状态**（origin/`navigationGeneration`/snapshot fingerprint/TTL）复核，非 `Valid` 即 fail-closed 拒绝（`STALE_TOKEN`，reason 是具体失效原因如 `stale-generation`）。导航（generation 自增）或原地 DOM 变化（fingerprint 变化）或超 TTL 都使旧 token 失效。设备测试 `anOldTokenIsStaleOnTheActionPathAfterNavigation`（`stale-generation`）钉住。
5. **未知 tab / 无 settled 页面一律 fail-closed**：指向不存在 tab 的动作 = NO_TAB；无 settled 页面（loading/错误页/未导航）的动作 = 无页面（click/type 表现为 token 失效、scroll 报 NO_PAGE、screenshot 报 NO_PAGE），永不 crash 或发出假捕获。设备测试 `anActionOnAnUnknownTabFailsClosedAsNoTab`、`screenshotOfAnUnattachedWebViewFailsClosedAsNoPage` 钉住。
6. **截图仅 Helix WebView、落 Workspace、模型只见 model-safe reference**（doc 09 §3.3）：`browser.screenshot` 捕获 tab 自己的 WebView（`capturePagePng`，仅 sized settled 页面）、经 `WorkspaceArtifactStore.writeArtifact` 写入共享 Workspace（`output/browser-<uuid>.png`）；模型见 model-safe Workspace reference（`scope:<id>:<path>`）+ 尺寸 + SHA-256，**从不**见裸路径。任何捕获/保存失败（配额/磁盘/坏路径）fail-closed 为 ERROR，字节绝不半公开。
7. **网页内容不可信贯穿动作路径**：动作脚本回传的字段属性（tag/type/autocomplete/name/placeholder）与节点文本都按不可信数据处理——脚本只把它们当作**分类输入**（敏感字段闸门）或**有界输出**，从不授权任何事；`type` 的文本虽由模型提供，但注入固定脚本前以 JSON 字符串字面量转义、且目标字段已过敏感字段闸门。
8. **线程安全**：工具在后台 dispatcher 运行、`BrowserController` main-thread-only，`BrowserToolBridgeImpl` 用 `onMain`/`onMainAsync`（post 主 looper + latch）桥接；`BrowserController.tab(id)` 读**发布的** StateFlow（非 main-thread-only 状态机），使桥可在主线程外读活 tab 状态。设备测试全部从（非主线程的）instrumentation 线程直调桥，与真实工具执行器同构。
9. **输出无 JSON null**：Completed 输出 schema 合规，逻辑缺失值发 `""`、未解析 node index 发 `-1`（`BrowserToolsMappingTest` 全覆盖）。

## 决策记录：

1. **新增 `:tools:browser` 承载工具 + 纯 JVM 端口，而非把工具直接写进 `:feature:browser`**：`:tools:*` 是工具契约/executor 的家（`time.now`/`files.*`/`code.javascript.run` 皆然），`:feature:*` 是实现/平台细节的家。工具是「解析参数→调端口→映射 outcome」的薄层，放 `:tools:browser` 让模型面向契约与 WebView 实现解耦；`:feature:browser` 实现端口并对真实 WebView 执行固定脚本。这是「工具塑形契约、端口是安全边界」的落地。
2. **端口返回闭合 outcome 枚举、工具做 fail-closed 映射（而非端口抛异常）**：端口对**页面/模型条件**绝不抛异常（未知 tab/陈旧 token/敏感字段/超时都是稳定的 outcome 值），只有编程错误才抛。这样工具能把每种失败**可审计地**映射成稳定 `ToolExecutorResult`（拒绝/陈旧/未知/超时各有稳定 status），绝不冒充成功——与 HXA-053 `code.javascript.run`「11 状态闭合、绝无假成功」同一条原则。
3. **敏感字段用**宿主 + JS**双闸门、宿主权威**（而非只靠脚本或只靠宿主）：doc 09 §3.3 要求密码/验证码/支付字段拒绝。脚本在其 JS 上下文运行、页面可谎报自身字段属性绕过脚本闸门，故宿主 `SensitiveFieldClassifier` 在受信侧对脚本回传的**原始**字段属性独立复核；只有两者**都**判 Normal 才执行。JS 闸门的存在是纵深防御 + 让脚本自足（无宿主时脚本自身也拒绝），但权威在宿主。
4. **动作脚本只 click/type/scroll 会动作，且严格复刻 EXTRACT 的 walk 边界**（而非另写一套寻址）：click/type 要把 `nodeIndex` 映射回**同一个**元素，必须与 snapshot 的 EXTRACT 用**完全一致**的有界 walk（`MAX_NODES`/`MAX_VISITED` 与 Kotlin 常量一致），否则 token 的 nodeIndex 会映射到错误元素。`BrowserActionScriptTest.theJsBoundsMatchTheKotlinBounds` 钉住「JS 字面量 = Kotlin 常量」，单边漂移即挂门禁。
5. **`type` 文本以 JSON 字符串字面量注入固定脚本**（而非字符串拼接/转义函数）：脚本是固定版本化常量、只有 `type` 文本是被内插的值；把它序列化成 JSON 字符串字面量（引号/反斜杠转义）使恶意文本无法逃逸脚本结构，脚本仍是一个可静态审计的固定片段（doc 09 §3.4 只执行 Helix 自有版本化脚本）。
6. **back/forward/reload 的 outcome 只报告事件、桥随后读结算状态**（而非等 WebView 同步给出 committed url）：WebView 的导航是异步的，committed url/origin 要等 load 结算才可知；让 controller 只回「moved/no-change」、由桥在 `settle` 后读取发布的活 tab 状态，避免在主线程阻塞等待导航、也让「无历史/仍在加载」有干净的 no-change 语义。
7. **screenshot 捕获在主线程、写盘在主线程外、失败 fail-closed 为 ERROR 不半公开**：WebView draw 必须主线程；磁盘写有意离主（不占主线程）。任何捕获/保存失败（配额/磁盘/坏路径）都 fail-closed 为 ERROR 且字节绝不半公开——与 HXA-044/046「原子物化、失败不留半成品」一致；模型只见写成功后的 model-safe reference + 尺寸 + SHA-256。
8. **detekt 高返回/吞异常/泛型 catch 点用针对性 `@Suppress` + `error()`**（而非重构掉 fail-closed 分支）：仓库既有惯例（HXA-060/061 的 `BrowserController`/`SnapshotBinder`/`BrowserUrlPolicy` 同法）——fail-closed 的「每守卫一个返回」与「main-hop 超时被吞成 TIMED_OUT outcome」是**语义本身**，不宜为绕规则合并分支；`onMain` 必须 catch `Throwable`（主线程块可能抛任何异常、要在主线程外重抛）故 `@Suppress("TooGenericExceptionCaught")`；`onMainAsync` 的 main-thread 断言从 `throw IllegalStateException` 改 `error()`（detekt `UseCheckOrError`，语义不变——`error()` 抛同样的 `IllegalStateException`）。

## 风险或后续任务

- **动作前必须重新 snapshot**（token 生命周期）：click/type 只认**最近一次** snapshot 的 token；HXA-061 已说明原地 DOM 变更须再 snapshot 才改 fingerprint。本任务的所有工具在动作路径都经 `verifyNodeToken` 对活状态复核，因此「不重新 snapshot 就动作」只会得到 fail-closed 的 STALE_TOKEN（安全），但**模型**须理解「陈旧 token → 重新 snapshot」的契约（工具输出携带稳定 `stale-token` status 与具体 reason 提示）。
- **敏感字段分类是模式匹配、非穷尽**：`SensitiveFieldClassifier` 与 JS 闸门靠 `type`/`autocomplete`/名称模式识别密码/支付/验证码；一个用非标准 `name`/`autocomplete` 的支付字段可能漏判为 Normal。这是**有意**的（误拒普通字段比漏拒敏感字段代价更高，且双闸门 + 宿主权威已是纵深防御），但非穷尽——若真实负载出现漏判，扩充 `PAYMENT_NAME`/`OTP_NAME`/`INPUT_TAGS` 触发词（`SensitiveFieldClassifierTest` 与 `BrowserActionScriptTest` 会因触发词漂移先挂门禁）。
- **`browser.find` 局限**：只在最近 snapshot 的**有界**语义节点上做子串匹配（非全文/非正则/非隐藏节点），最多 50 条；大页面 find 的结果受 snapshot 的 `MAX_NODES` 截断影响。
- **截图仅 WebView、本设备 harness 只验 NO_PAGE**：SAVED 正路径由 JVM 映射测试 + core:workspace `writeArtifact` 测试钉住；真实 sized WebView 的 SAVED 捕获归后续真机/设备矩阵（本 harness 的 WebView 脱离窗口，无法产出 renderable 页面）。
- **`:tools:browser` 与 `:feature:browser` 坐标冲突**：已用 `:tools:browser` 的 `group = "com.helix.tools"` 解决（同 `:tools:files` 的 HXA-042 手法）；若未来再引入第三个 project 名 "browser" 的模块须沿用同一 group 消歧。
- HXA-063（Browser download）开工时：实现 `browser.download`（URL/重定向/MIME/size/name/target policy，下载到 Workspace/SAF；不自动打开或执行 APK/DEX/JAR/SO），复用本任务的 `:tools:browser` 端口与 `:feature:browser` 的 URL 策略/流式下载地基（HXA-060），download 的 outcome 亦走闭合枚举 fail-closed 映射。
