### 1. 设备测量（`ProotGitSpikeDeviceTest`，6 例，真实 084 Job 管线）

设备：emulator-5554（API 36）/ emulator-5556（API 29），均 arm64-v8a 4 KiB 模拟器。
ADR-0008 的验证条款允许"API 29/36、arm64 真机**或代表性设备**"——本环境无 arm64 真机，
模拟器即代表性设备（与 080~087 一致）；4/16 KiB 页真机与最低设备集真机证据沿用
HXA-086 的真机缺口记录，**不做假绿**。

| 项目 | 小仓库（64×8 KiB ≈ 552 KiB 工作树） | 中仓库（512×32 KiB ≈ 16 MiB；guest init+add+commit+gc） |
| --- | --- | --- |
| 输入归档 | 31,056 B / 13–46 ms | 312,373 B / 13–46 ms（fixture 高压缩比；不可压缩载荷 ≈ 16.8 MiB，仍在 084 限额内：≤128 MiB/≤4,096 文件/单文件 ≤64 MiB） |
| guest 操作耗时 | ≈251–255 ms | ≈1.3–1.5 s |
| 输出归档 | 44,876 B / 83 文件 | 336,608 B / 542 文件 |
| `.git` 规模 | init 后 17 文件 / 108–212 KiB | `git gc` 后 28 文件 / 204–364 KiB（**pack 后对象 DB 相对工作树很小——首版预算按 pack 后形态表达**） |

- **进程死亡/对账**：job id → 恰好一个稳定终态记录（幂等查询、无重放）；输出是整归档
  边界（SUCCEEDED 必有完整可解包归档，无半解包树）+ 086 宿主 kill → ORPHANED 稳定终态
  → "静默半仓库" 无落点。
- **损坏恢复**：损坏 loose tree 对象 → `git fsck --full` 报告 `bad sha1 file:
  .git/objects/62/…`，从不静默判净。**平台事实**：`git fsck` 报告损坏时**可退出码 0**
  → 结构化执行器必须解析 fsck 输出文本，不能只看退出码。
- **攻击面证据**（快照携带恶意仓库内容 × 首版命令集 status/diff/log/init/add/commit）：
  - 无防护：`post-commit` hook 在 commit 时**被执行**；`.gitattributes` 的
    `filter=evil` clean 命令在 `add` 时**被执行**（且清空文件内容 = 进入快照的静默
    篡改通道）；alias **不展开**（结构化子命令不走 alias 表）；submodule 不递归/不克隆
    （离线 + 无 submodule 命令）；credential helper 不触发（首版无远程命令）。
  - 有防护（每次调用 `-c core.hooksPath=/dev/null`）：hook 抑制（HOOK_INERT），首版
    命令集全成功；**filter 仍执行**——hooksPath 防护无法中和 attribute filter。
- **guest 平台事实**：Alpine 3.22.5 rootfs 的 `/bin/sh`（BusyBox ash）**不支持
  `$(...)` 命令替换**（backtick 可用）；git 2.49.1 正常。

### 2. 三路径比较（Spike 结论，供所有者决定）

1. **主 App Workspace 权威仓库 + 每操作完整原子事务**：全部组件已在现有 084/085 管线内
   设备验证（归档/限额/对账/损坏/攻击面）；中仓库每操作往返 ≈ 0.3–17 MiB 归档 + 秒级
   guest 时间（模拟器）；**不引入新 IPC/新挂载面/新依赖**。超 084 归档限额的仓库
   fail-closed 拒绝。**推荐为首版路径。**
2. **Runtime 私有目录权威仓库**：guest git 操作成本与路径 1 相同（已测量），节省的只是
   每操作 zip 往返；但需要**新的 bind 面 + 新的跨 uid 仓库事务协议**（设备实证：084 Job
   模型中 guest 只能看到 job 快照，私有目录对 guest 不可达），且把仓库纳入 companion
   卸载/更新/删除语义（087）。成本显著高于收益，首版不推荐（保留后续选项）。
3. **主 App 引入 Android Git 库**（候选调查，**未引入依赖**）：
   - **JGit**（Eclipse，纯 Java，EPL-2.0 OR GPL-2.0-with-classpath-exception；Maven
     Central 最新 `7.7.1.202607240634-r`，2026-07-24）：无 native ABI 负担，但新增供应链
     依赖 + 体积 + 与 guest git 的**双实现语义分叉**；需单独 Android 性能/体积证据。
   - **libgit2**（`v1.9.7`，2026-08-13，GPL-2.0-or-later OR MIT 双许可）：C 库需
     arm64-v8a NDK 构建 + JNI 绑定层，native ABI/构建链负担最大。
   - 两者都不解决路径 1 已验证的原子性（仓库仍在主 App 侧）。首版不推荐（保留后续选项）。

### 3. 首版拒绝/禁用策略（记录在 ADR-0008，非授权）

- 每次调用 env：`GIT_CONFIG_GLOBAL=/dev/null`、`GIT_CONFIG_SYSTEM=/dev/null`、
  `GIT_TERMINAL_PROMPT=0`、`GIT_PAGER=cat` + `-c core.hooksPath=/dev/null`；
- **宿主侧仓库预扫描（fail-closed 拒绝）**：`.git/config`/`.gitattributes` 含
  `filter`/`diff`/`merge` 命令配置时拒绝 `add`/`commit`（filter 是 hooksPath 无法中和的
  静默篡改通道——设备实证）；
- 白名单子命令 + `--` 路径守卫；`reset --hard`/`clean` 等破坏命令**不进入首版**；
  shell 模板避开 `$(...)`（guest ash 约束——设备实证）；
- 仓库完整性以 fsck **输出文本**为准（退出码不可信——设备实证）；
- `clone/fetch/pull/push`/凭据/credential helper/SSH agent 全部不在首版（companion 零
  INTERNET 权限结构上排除联网 Git；远程 Git = 未来新的联网执行域 ADR）；
- 候选 Tool schema（非授权）：`code.git.run`（Advanced-only；`status/diff/log` L1 只读
  候选 / `init/add/commit` L2 写仓库候选；scope = 选定 Workspace 根；与 `code.linux.run`
  相同的审批语义；审计 = 子命令 + 仓库根 + 输入快照 sha + 输出 diff 摘要）。
  Standard 不暴露任何 Git 配置（Helix 原生历史/diff/回收站不变）。

## 决策记录：

1. **Spike 用真实 084 Job 管线测量，不在宿主 JVM 模拟**：归档/对账/损坏/攻击面的证据
   必须经过真实 binder/PFD/PRoot 链（084 契约），否则"路径 1 可行"无设备证据。
2. **路径 1 为首版推荐（非授权）**：唯一"零新面"路径——全部原子性/限额/对账语义已被
   084/085/086 设备验证；路径 2 的新 bind 面 + 新协议成本 > 其节省的 zip 往返；路径 3
   的双 git 语义分叉 + 供应链负担无对应收益。
3. **filter 预扫描是强制项**（不是可选项）：设备实证 hooksPath 防护无法中和
   `.gitattributes` filter，且 filter 能把文件内容**清空**后写入快照——这是结构化
   `add/commit` 唯一未被 env/`-c` 防护覆盖的执行面。
4. **fsck 退出码不可信**（设备实证：报告 `bad sha1 file` 时退出码 0）：完整性判定解析
   输出文本——写进 ADR 的强制策略，避免首版实现犯"只看退出码"的错误。
5. **guest ash 的 `$(...)` 缺失**是首版命令模板的平台约束（backtick 可用）：记录为
   设备事实，模板生成器必须遵守。
6. **ADR 保持 proposed**：本 Spike 提供证据与推荐，接受/修改/拒绝由所有者决定
   （ADR-0008 的 Deciders: pending 语义不变）；在此之前 Job-local Git 维持"单次离线
   Job 内的 git 工具"定位。
