# HXA-223：Post-clean-slate Core Boundary Convergence

日期：2026-09-26。分支 `refactor/clean-slate-engine`。基线 checkpoint：`7d7f9053`。本任务承接 HXA-220/HXA-221，只收敛 Core Engine / Session orchestration 边界与竞态防护，不新增产品能力。

## 交付

### A. Turn stale-state / R4 收口

- `TurnDao.updateState` 从 `WHERE id = :id` 收紧为 `id + expectedState + expectedStepCount` compare-and-set。
- `TurnRepository.updateState` 在 CAS 返回 0 时 fail closed，旧 state 或同 state 下旧 stepCount 快照都不能覆盖已经前进的 durable Turn。
- 没有新增 version column、event sourcing、第二状态机或第二 durable truth。
- 新增 `TurnRepositoryTest`：覆盖 stale-state 覆盖和同态 stepCount 前进后的旧快照覆盖。
- 生产 writer audit 结论：UI/Compose/Chat projection 无直接 Turn state mutation；durable admission/cancel/review/terminal/recovery 均从 TurnEngine-owned boundary 进入，`TurnCoordinator` 仅保留 AgentLoop model/tool round checkpoint 写入。

**R4 最终裁决**：旧实现没有证明当前生产必现“双 owner 同时写终态”的 race，但底层 repository 确实允许 stale snapshot 覆盖 durable state，且新增 writer 很容易重新触发该类问题。采用最小 CAS 防护关闭该风险，不扩大为全局 revision/event-sourcing 设计。

### B. Engine lifecycle owner 收口

- startup recovery 从 `app/recovery/RecoveryCoordinatorApp.kt` 迁入 `app/engine/TurnRecovery.kt`；生产启动只经 `TurnEngine.recoverOnStartup()`。
- 新增 `TurnSettlement`：Engine-owned final durable transaction 统一提交 assistant terminal text、Turn terminal、open ModelCall terminal 与 GoalRun settlement。
- 为 Steer-vs-final-answer 保留原 Room 线性化，`TurnSettlement` 提供 `settleInTransaction`；Coordinator 只传 immutable `TurnTerminalCheckpoint`。
- 新增 `TurnReviewParking`：Engine-owned UNKNOWN batch parking 负责 Turn→`NEEDS_REVIEW`、Goal→`BLOCKED` 与 review audit；Coordinator 只传 `TurnReviewCheckpoint` 并在 durable commit 后更新 process-local phase。
- cancel/review resolution/admission 继续由既有 TurnEngine collaborators 拥有。
- `GoalRunCoordinator.start()` 的生产 caller graph 只有 `TurnAdmission`；其内部 `TurnCoordinator.start()` 是 Goal admission 的原子协作者，不构成第二 runtime admission seam。

### C. Session safe-boundary orchestration

新增 `SessionWorkScheduler`，把“一个 Turn 如何结束”与“Session 接下来运行什么”分离：

```text
Turn durable terminal
        ↓
live owner release boundary
        ↓
SessionWorkScheduler
    ├─ pending user Queue → user work first
    └─ no pending input → eligible Goal continuation
```

- Queue 用户输入优先于自动 Goal continuation。
- GoalContinuationDriver 仍是 process-local activation/handoff，不是 durable truth。
- review/unknown/non-completed Turn 会 disarm automatic continuation。
- duplicate wake 通过同一 submission mutex + Room/live re-read 收敛，不靠 UI busy state 判定。

### D. Chat / input application boundary

新增 `SessionInputDeliveryCoordinator`，承接已经 accepted 的 SessionInput 运行时交付：

- queue eligibility；
- provider/model/control revalidation；
- attachment materialization；
- queued Turn launch；
- Steer draft preparation。

ChatService 继续拥有用户-facing submit/confirm/disclosure/composer/projection，但不再内嵌 Session next-work algorithm，也不拥有 Turn terminal/review durable truth。

当前文件规模仅作为观察值，不作为重构目标：ChatService 仍是较大 application facade；本任务没有为了减少行数制造同义 facade 或新 Gradle module。

### E. Test fixture boundary

历史 AndroidTest 大量直接用 `TurnCoordinator` 构造 durable terminal/review 状态。为避免 50+ 测试重复装配完整 TurnEngine，保留明确标注的 fixture-only bridge：

- `settleFixtureTerminal`
- `parkFixtureForReview`
- `completeResponseOrContinueFixture`

生产 `app/src/main` 除这些方法定义外无调用；bridge 内部仍委托 Engine-owned `TurnSettlement` / `TurnReviewParking`，不是兼容生产路径或第二 owner。

决策记录：HXA-223 冻结“TurnEngine = durable/live Turn lifecycle owner；TurnCoordinator = one Turn 内 model/tool round execution context；SessionWorkScheduler = safe Turn boundary 后的 next-work arbiter；Room = durable truth；Chat/UI = application command + projection”的边界。后续不得因新增 Workspace、本地模型、Subagent 或 UI 功能把 terminal/review/recovery/Session continuation 重新塞回 ChatService 或创建第二 AgentLoop。

## 最终 caller graph

```text
UI / Chat projection
        ↓ commands
Application submission / SessionInputDelivery
        ↓
TurnEngine
  ├─ TurnAdmission
  ├─ TurnExecutionDriver
  ├─ TurnSettlement
  ├─ TurnReviewParking / TurnReviewResolution
  ├─ TurnRecovery
  ├─ TurnLiveRegistry
  └─ TurnObservationHub
        ↓
AgentLoop
        ↓
TurnCoordinator
  └─ model/tool/compaction round checkpoints only

Turn terminal + owner release
        ↓
SessionWorkScheduler
  ├─ Queue
  └─ Goal continuation

Room = durable truth
```

```text

```
