## 契约与交付

决策记录：复用现有 `PlanReviewService` 与 `PlanExecutionBinding`，不新建 Plan Engine。执行路径 `ChatService.executeApprovedPlan` 跳 `Dispatchers.IO`（与同文件的 reviewPlan/approvePlan/revisePlan 一致），让 Compose 审阅对话框能驱动执行而不在主线程做 Room I/O。网络隔离按所有者决定移出本轮范围：保留共享 UID Runtime，不新增统一禁网或离线 Shell 开关，不为已撤下要求拒绝 Shell，与 HXA-209 一致（见[隔离 PRoot 可行性](../evidence/development/isolated-proot-feasibility-2026-09-16.md)）。本任务不新增或修改授权 ADR，只在 HXA-209 的会话授权下验证 Plan 执行联动。

- 提交→审阅→执行/修改/拒绝：READY 计划在任务看板审阅对话框经生产按钮执行，计划转 EXECUTING、evidenceRef 指向执行 goal；恰好一个 goal 绑定被审阅版本的精确 hash（不重复建 goal、版本不漂移）；该 goal 的 turn 归属执行会话；成功执行关闭审阅面。修改退回 DRAFT（可再驱动），补全执行/修改/拒绝决定集。
- 不重复执行：重复点击被按钮 busy 态挡下；re-drive 返回同一已绑定 goal；版本漂移的 binding 被拒；未批准计划被拒；进程被杀后恢复不重放执行、re-drive 返回同一 goal。
- 授权联动（HXA-209）：Plan 批准不自行 mint 工具 proof；在会话授权下，预设允许的操作免卡、ASK 动作仍询问、DISABLED/DENY 拒绝；不把"每个 L2 再出卡"写成验收要求。
