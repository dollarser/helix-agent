## 交付与使用

输入按会话保存，切会话、旋转、返回重开和普通应用主进程死亡后恢复。Provider/模型未就绪、非法输入、出网确认取消、会话忙或其他准入拒绝均保留原稿。发送捕获文本、附件、revision 和 clientRequestId 的不可变快照；只有已持久接收且仍匹配的回执清空该稿，旧会话或旧版本回执不能清掉新输入。

运行中仍可编辑下一份草稿，但发送按钮服从既有 busy gate。聊天和 Tasks 使用渲染时稳定 Turn ID 停止；先持久 CANCELLING 再传递取消，结束与停止竞争呈现真实终局。工具等待/执行、压缩和模型流边界均对账，不把未知副作用写成成功取消。

附件恢复重新核验 artifact、hash、类型和尺寸；已接收附件稿先结算回执，不重新挂载已消费附件。修订稿保留 HXA-215 的目标、附件和请求身份，普通 composer 不覆盖；修订回执只由 editor 确认。旋转、确认清理、附件同步和 editor 关闭的竞态由短本地锁及不可取消结算覆盖。

## 实现不变式

- `ConversationDraftBuffer` 串行自动保存、显式发送、回执和附件同步；同一不可变 intent 可复用已持久快照，不因 revision 差异用相同 request ID 重复写入。
- 真正的文本/附件修改生成新 clientRequestId。CAS 失败重载持久状态；被接受的旧快照不能复活，也不能清除不同身份的新稿。
- `ChatService` 在既有 submission gate 内查询普通及修订回执，保证确认副作用、暂存附件清理和回执可见性有一致顺序；不盲重放请求。
- 初始化先结算已接收回执，再恢复当前仍存在的附件。恢复 effect 只在附件初始化完成后参与动态同步；ack、load 和本地状态提交不会在 effect 取消时留下半结算状态。
- 持久 CANCELLING 与后续模型/工具/压缩阶段在 Room 事务边界协调。已完成工具结果保留，取消后不再创建下一次模型调用。
- 修订确认触发的消息刷新不能取消 editor 关闭；用户主动关闭保留修订稿，可返回列表并从同一消息重开，应用重启仍按契约恢复。

整合接口和生命周期边界见[交接说明](../development/hxa-214-core-handoff.md)。

## 边界

普通应用恢复通过模拟器 host 对主 PID 发送 SIGKILL，不代表 App Root 或物理 OEM 能力。恢复旅程覆盖持久草稿、已接收不重发和预置 CANCELLING 的幂等对账；不冒充“点击停止瞬间杀进程”的全部 OEM 时序，真实点击停止由独立 UI 竞态测试覆盖。

loopback Provider 不是真实外部账号。196/199物理设备、125/126真实服务账号、订阅实付、发行签名/渠道、长稳和真实16 KiB设备仍按各自任务保留。本任务没有发布；HXA-216 的 Queue/Steer 必须用其独立设计、迁移、设备和进程恢复证据交付。
