- 实现的契约：
  - 架构文档 §5.1 模式边界表 + “Plan 只允许 `operationClass=READ_ONLY`，不能用 `baseRisk <= L1` 代替这个判断”；modes 文档 §6.1 模式语义表与 `PlanArtifact` 结构、§6.2“原计划 hash 写入运行记录”。
  - 契约解释（已记录）：modes 文档 6.1 的 Plan“风险可为 L0/L1”与架构文档 §5.1 的“仅 READ_ONLY”合读为：Plan 的双重门 = `operationClass == READ_ONLY`（主判断）且 `dynamicRisk ≤ L1`（上限）。READ_ONLY 工具因动态风险因素（如读取 secret/联系人）升到 L2/L3 时在 Plan 被拒；而 L1 的写文件/HTTP/页面动作因 operation class 被拒（与文档示例“L1 的新建文件、HTTP 请求和页面动作仍不可用”逐字对应）。
  - 契约解释（已记录）：`PlanStep` 字段在文档中未给出，取最小结构化形式 `title + description`（均为有界非空白文本）；`PlanArtifact` 按领域值归入 `core:model`（与 `TurnBudgets` 同模式：public 类型 + 基于 internal canonical JSON 的存储编码，HXA-014 Room `plans`/`plan_steps` 表可直接持久化），模式策略（行为逻辑）归 `core:agent`——任务验证命令 `:core:agent:test` 不受影响，core:model 新增文件为严格增量（未改任何既有 core:model 文件）。
  - Act/Goal 的“按 Policy 开放”实现为模式层 `Allowed`（无额外限制），KDoc 明确 `Allowed` 只是“可进入工具表”，不是执行授权：每次调用仍走完整管线（schema、动态风险、Policy、审批）。
