# HXA-226：UI / IA 第二轮收敛

日期：2026-09-26。分支 `refactor/clean-slate-engine`，实现基线 `a015222d`（HXA-223 Core owner freeze）。本任务只调整 UI / application navigation / presentation authority，不修改 Turn/Tool/Goal durable owner、权限判定、Provider wire protocol、Workspace binding 或 Runtime 执行语义。

## 交付

### D1. authority / route graph 最终裁决

本轮没有沿用旧 UI 方案直接改视觉，而是重新读取真实 `ShellDestination`、`GroupedNavigation`、`MainActivity`、Settings/Extensions/Capabilities/Readiness/Permissions 与 Conversation/Composer 调用链。确认旧问题的核心是 **一个能力存在多个完整 primary home**：Capabilities 与 Permissions 重复管理系统授权，Settings 又重复嵌 Provider、Extension、Runtime、Safety/Permission 与 defaults。

最终 primary authority：

| 能力 | 唯一 primary home |
| --- | --- |
| Session list / conversation | Conversations / Sessions |
| Tasks / Artifacts / Files / Git / Browser / Terminal | Work |
| Provider / model connection | Models & connections |
| Skill / Connector / Marketplace | Extensions |
| task readiness / capability status / Runtime | Setup & readiness 的 focused child pages |
| system grants / Safety / Root / Automation / Session permission / LAN / Egress | Settings / Permissions & safety |
| Language / Turn defaults / Goal defaults | Settings / App & agent defaults |
| Audit | Settings / Diagnostics & audit |

最终 Drawer 只保留 primary routes：

```text
Conversations
  sessions

Work
  tasks
  artifacts
  git
  files
  browser
  terminal

Configure
  models
  extensions
  setup

Settings
  settings
```

consumer 的 primary drawer route 从旧 **12** 项收敛到 **10** 项；developer flavor 在 Terminal 可用时为 **11** 项。旧 `capabilities / readiness / permissions / audit` 不再是 Drawer 目的地，也没有保留内部 route alias。

secondary routes：

```text
setup/readiness
setup/capabilities
setup/runtime

settings/defaults
settings/permissions
settings/permissions/system
settings/audit
```

primary route 使用 Drawer top action；secondary route 使用 Back，并按真实 back stack 回到 landing/context。新增 `SecondaryRoutes.kt` 统一 secondary route identity/title。

### D2. Settings / Configure authority 收敛

`SettingsScreen` 从“所有配置 section 的长列表”改为三个 landing：

- App & agent defaults；
- Permissions & safety；
- Diagnostics & audit。

focused pages：

- `ModelsConnectionsScreen`：唯一完整 Provider/model connection 管理；
- `ExtensionsScreen`：唯一完整 Skill/Connector/Marketplace 管理；其 tab 改为 `rememberSaveable`，Activity recreation 后保持 Manage/Marketplace 上下文；
- `SetupScreen`：Readiness / Capabilities / Runtime landing；
- `RuntimeSetupScreen`：PRoot + bundled runtime；
- `PermissionsSafetyScreen`：Safety profile、Root/Automation、Session permission、LAN/Egress，并 deep-link 到 Android system permissions；
- `AppAgentDefaultsScreen`：Language、RunControl、Goal defaults；
- `AuditScreen` 只作为 `settings/audit` secondary route。

Settings landing 不再直接嵌 Provider、Skill/Connector 或 Runtime。

### D3. Conversation navigation 与 Composer 第二轮

Chat 导航从万能 `onProviders` 拆成语义明确的：

- `onModels`；
- `onAgentDefaults`；
- `onPermissions`。

Recovery 也从单个 `recoverySettingsNavigation` 拆为 `RecoveryRepairNavigation(models, permissions)`：

- RECONNECT → Models；
- GRANT_PERMISSION → system permissions。

Header 复审后保留 Drawer 与 Back-to-Sessions，因为二者层级不同：前者是全局导航，后者是 Sessions list/detail 内部返回，不是重复 primary action。

Composer 从“独立 toolbar + input + 独立 Stop 第三行”收敛为一个圆角容器：

```text
┌────────────────────────────────┐
│ message input                  │
│ voice attach [mode model ⋯] ◼ ▶│
└────────────────────────────────┘
```

- Mode + model 保持 inline primary context；
- Reasoning / context / compact 继续进入原 options sheet；
- Stop 从独立第三行移入同一 action row；
- **实现中重新核对 HXA-216 后纠正了原设计：活跃 Turn 的 Send 是 Queue/Steer 入口，不能被 Stop 替换。** 因此运行时 Stop + Send 同排并存，空闲时只显示 Send；Queue/Steer、pending confirmation、attachment、Goal 语义不变。

### D4. Readiness / Capabilities 只读投影与 repair deep link

Readiness 不再自己执行 PRoot verify/repair/rebaseline：

- ADD_MODEL → Models；
- VERIFY_RUNTIME / REPAIR_RUNTIME → Setup / Runtime。

Capabilities 保持 live capability status/read model，但管理动作只 deep-link 唯一 authority：

- notification/calendar/accessibility → Android system permissions；
- root → Permissions & safety；
- runtime → Setup / Runtime；
- MCP → Extensions；
- notification 的 Test action 保留，因为它是 capability verification，不是第二权限管理入口。

因此 `Capabilities` 不再成为系统 grant 的第二管理页。

### D5. IA regression contracts

新增/更新测试把 IA 本身作为契约：

- `ShellRepositoryTest` 精确断言 primary route set/order（consumer 10 / developer 11）；
- `GroupedNavigationDeviceTest` 断言旧四个 Drawer tag 不存在；
- 新增 `IaAuthorityDeviceTest`：Settings landing 不得出现 Provider/Connector/PRoot 完整管理 surface，Models/Extensions/Setup/Permissions 各自拥有对应完整 surface；
- `AppUiTestSupport.navigateTo` 通过真实 landing 进入 secondary route，不提供旧 route alias；
- `ConversationTopBarDeviceTest` 区分 primary Drawer 与 secondary Back；
- Readiness/Capabilities/Provider/Permission/Root/Egress/Language/RunControl 等现有 AndroidTest 路径迁到新的唯一 authority；
- Composer 布局契约更新为 mode/model/options 与 voice/attach/Send/Stop 位于输入容器底部 action row，并继续断言 active Turn 的 Send + Stop 同时可达。

生产静态审计最终为：

```text
ShellDestination.Capabilities/Readiness/Permissions/Audit callers = 0
recoverySettingsNavigation = 0
onProviders production callback = 0
legacy navigation-group-extensions = 0
```

## 决策记录

决策记录：本任务不新增 ADR。它在 HXA-223 已冻结的 application/runtime owner 边界内完成 UI authority 收敛；唯一新增的产品级 IA 裁决是“一个能力一个 primary home，其他入口只做 contextual shortcut/deep link”。实现过程中根据 HXA-216 既有 Queue/Steer 契约修正了原先“运行时 Send 替换为 Stop”的视觉设想：活跃 Turn 必须同时保留 Send 与 Stop，因此没有为了视觉简化改变执行语义。
