# HXA-227：统一轨迹级 Agent Eval 与失败归因

日期：2026-09-27。交付范围为离线 evidence v1、三套 fixed eval adapter、八类设备轨迹的确定性测试入口、host boundary baseline 和 A/B aggregator。不修改生产 AgentLoop、Dispatcher、授权、effect owner 或 UI 策略。设备与真实 Provider 本轮均 not requested；不是全量设备 baseline 的通过记录。

决策记录：沿用 accepted [ADR-AGENT-001](../adr/agent/001-turn-coordination.md) 的 durable truth、UNKNOWN/review 与 successor 契约；不新增运行时决策。Workspace 调研只完善 proposed ADR-WORKSPACE-004，不构成实施接受。

## 交付

- `evals/trajectory/evidence-v1.schema.json` 与 `scripts/agent_eval.py`：版本化 identity/outcome/trajectory/cost、必需证据校验、失败 taxonomy、hash 校验和未知指标 coverage；源码 manifest 覆盖指定目录 tracked/untracked 内容，制品身份另记。
- `scripts/run-agent-eval.py`：离线 fixed/JUnit 规范化、JSON/Markdown 分组报告、baseline/candidate 对照；不启动设备、模型或网络。重复 case、缺 verifier、错误/缺失制品、未知控制条件不能制造 PASS 或可比 delta。
- File/Browser/Goal 三套原 producer 保留 raw JSON 和原 verifier，新增实际 session durable 计数；现有 runner 额外生成统一报告。协议形状、隐私投影和失败边界通过 host fixture 测试；真实模型执行未在本任务请求。
- `core-device.json`：Queue、Steer、Cancel/UNKNOWN、Review、process-death recovery、Goal、Compaction、Tool failure recovery 八类 case 的精确 method selectors。复用真实 Harness/Room 测试；新增 UNKNOWN 赢过 durable cancel 和失败 read 回填后换工具的反例。后者验证实际 TOOL error backfill，不仅检查模型声称恢复。
- `host-boundaries.json` 与 `run-agent-eval-host.py`：八组 JVM 边界断言，强制新执行、保存 XML/source manifest/环境与 JSON/Markdown baseline；不把它们冒称完整设备轨迹。
- 详细使用、指标分母、兼容读取和 A/B 控制规则见 [Agent Eval 文档](../development/agent-eval.md)。普通缺陷修复不以“已有 eval 先失败”为前提，补对应 regression evidence 即可。
