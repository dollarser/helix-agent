- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  1. **类型落 core:policy 而非 core:model**：doc 02 §3 模块图 `core/policy` = “风险、审批、授权作用域”，scope/grant/resolver/center 全属授权作用域；`Capability` 枚举留 core:model（doc 09 §2 明示“定义于 core:model”）；`:tools:framework → :core:policy` 依赖 HXA-030 时已预置，零 build 变更。
  2. **类型级上限与产品默认分离**：scope 类型只做结构性/安全上限（ref 1024、TTL 60min、maxActions 10000 等），产品默认值（Root 10 分钟无活动失效、automation 30 动作/5 分钟、Advanced 硬上限）归调用方/Policy Engine（HXA-033），类型不硬编码产品决策。
  3. **recorder 失败 fail closed（传播异常而非吞掉）**：无法审计的能力检查不算成功（AGENTS：不从 catch-all 返回成功）；存储故障会阻塞执行时检查直到修复——审计优先于可用性，与 HXA-014 起的安全姿态一致。
  4. **诚实 UNAVAILABLE 优先于“检测到 su”**：Root/Accessibility 在无集成/无服务时报 UNAVAILABLE（能力不存在），不是 DENIED（用户拒绝）更不是 GRANTED——doc 09 §6.2 明令禁止；Accessibility 探测用通用 meta-data 查询而非硬编码未来类名，服务落地后零改动生效。
  5. **设备测试只驱动授予方向**：Android 对“可见应用被授予的运行时权限被撤销”会直接杀该应用进程（logcat 证据 `Killing <pid>:com.helix.agent (adj 0): permissions revoked`），instrumentation 进程跑在应用 uid 下——撤销方向在设备上必然杀死测试自身。授予方向在设备证（真实生产栈），撤销方向在 JVM 证（core:policy 翻态测试证的是同一个不变式）。
  6. **设备审计用隔离数据库**（ProcessRecoveryTest 既有模式）：全套件运行时 Espresso 测试后应用进程仍驻留并持有共享 Room DB，第二进程不得再开同一文件（曾致进程被杀/运行中断）。

- 排障记录（真实证据，供后续参考）：
  1. **Kotlin 接口不做 SAM 转换**：初版 JVM 测试用 lambda 实现 `CapabilityResolver`/`CapabilityGrantRecorder`（“Interface ... does not have constructors”）——SAM 仅对 Java 接口；改显式测试 helper 类。
  2. **接口伴生常量不进实现类作用域**：`RootSessionScope` 里裸用 `MAX_ROOT_SESSION_TTL_MINUTES`（接口 companion 成员不被实现类继承）→ 显式 `UserScope.` 限定。
  3. **scope ref 上限只在 `toScopeRef()` 生效**：构造成功、调用才拒——40 包 scope 的测试抓到（构造不抛）；移到 init 期强制（装不进审计列=结构性非法，构造即拒）。
  4. **SAF tree URI 空 document**：`content://auth/tree/`（`/tree/` 后无内容）初版放行 → 补 `substringAfter("/tree/").isNotBlank()` 检查。
  5. **设备全套件运行中断**：初版审计测试用 `HelixStorage.create(context)`（共享 DB）——全套件运行时应用进程驻留（WorkManager/Espresso 拉起）持库，测试进程再开 → 进程被杀、run 中断（单独跑 9/9 通过、全套件必挂的对照实验定位）；改 `HelixStorage.open` 隔离库（ProcessRecoveryTest 模式）后仍挂，见下条。
  6. **撤销运行时权限杀死 instrumentation 自身**：logcat 铁证 `Killing 6131:com.helix.agent/u0a227 (adj 0): permissions revoked` → `Crash of app com.helix.agent running instrumentation`——Android 对被撤销权限的可见应用直接杀进程，instrumentation 跑在应用 uid 下必然陪葬；且无 FATAL EXCEPTION（不是 JVM 崩溃，是 AMS 杀进程，logcat crash buffer 为空）。平台约束不可绕过（adb `pm revoke` 同机制且破坏矩阵命令自包含性）→ 设备测授予方向、JVM 测撤销方向（同一不变式）。
