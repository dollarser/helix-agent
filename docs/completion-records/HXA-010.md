## HXA-010 完成记录

- 目标：在 `core:model` 实现领域 ID、错误和执行目标：value classes、Turn/Tool/Execution/Goal 状态机、RiskLevel、统一 `Capability`、`ToolOperationClass`、`TurnBudgets`、不含文件 I/O 的不透明 `ArtifactRef`、`HelixError`、`Clock`、`IdGenerator`、`ExecutionTargetDescriptor`、`ToolExecutionEnvelope`；纯 Kotlin 测试序列化和非法输入。
- 前置任务/commit：HXA-001～003（M0，见 [M0 完成记录](../m0-completion-record.md)）。仓库当前没有 Git commit（全部文件未跟踪，按交接约定不主动提交），无 commit 可引用。
- 修改文件：
  - 生产代码（新增，`core/model/src/main/kotlin/com/helix/core/model/`）：
    - `Identifier.kt`：内部校验（长度 1..64、`[A-Za-z0-9_-]`）、`IdGenerator` 接口、`RandomIdGenerator`（32 位小写 hex，SecureRandom 可注入）。
    - `Identifiers.kt`：22 个领域 ID value class（SessionId、MessageId、TurnId、ModelCallId、ToolCallId、ToolResultId、ApprovalId、ExecutionId、ArtifactId、AuditEventId、ProviderId、RuntimeInstallId、PlanId、GoalId、GoalRunId、McpServerId、SkillId、ExecutionTargetId、OperationId、CorrelationId、ScopeId、WorkspaceId），构造时校验、`toString()` 返回裸值。
    - `Sha256.kt`：64 位小写 hex value class；`fromHex` 归一化大小写，构造器只接受小写。
    - `ToolIdentity.kt`：`ToolName`（1..8 段点分层，每段 1..64 位 `[A-Za-z0-9_-]` 且字母/数字开头，总长 ≤128）、`ToolVersion`（Int ≥ 0）。
    - `ArtifactRef.kt`：不透明引用（1..128，`[A-Za-z0-9._:-]`，无路径分隔符，无文件 I/O）。
    - `TurnState.kt`：12 状态 + 完整 `canTransitionTo` 规则 + 进程死亡映射（非终态 → INTERRUPTED，CANCELLING/INTERRUPTED 除外）。
    - `ToolCallState.kt`：9 状态（DENIED 与 COMPLETED 区分；NEEDS_REVIEW/INTERRUPTED 为 parked）+ 转移与进程死亡规则。
    - `ExecutionState.kt`：7 状态 + 转移与进程死亡规则。
    - `GoalState.kt`：8 状态；进程死亡仅 RUNNING → PAUSED（持久 park，恢复必须显式）。
    - `Risk.kt`：`RiskLevel`（L0..L3，L2/L3 需要审批，default-deny L3）、`Capability`（与 [09-android-platform-capabilities.md](../09-android-platform-capabilities.md) 第 2 节一致的 7 值枚举）、`ToolOperationClass`（与 [02-architecture-design.md](../02-architecture-design.md) 第 7 节一致的 6 值枚举）。
    - `TurnBudgets.kt`：maxSteps/maxModelCalls/maxInputTokens/maxOutputTokens/maxTotalTokens + 校验 + `stricterWith` 逐元素取 min + 确定性存储编码。
    - `HelixError.kt`：12 个 `ErrorCode`（与架构文档第 13 节稳定错误类别一致）+ `HelixError(code, userMessage, retryable, safeDetails, correlationId)`，safeDetails 键/值严格校验（≤16 项、键 1..64、值 1..1024、无空白/控制字符）。
    - `Clock.kt`：`Clock` 接口 + `SystemClock`（UTC）。
    - `ExecutionTarget.kt`：`ExecutionTargetType`（LOCAL_ANDROID/LOCAL_QUICKJS/LOCAL_PROOT/LOCAL_CLI_RUNTIME）+ `ExecutionTargetDescriptor`（协议版本 ≥1、displayName ≤128、attributes ≤16 项）。
    - `ToolExecutionEnvelope.kt`：`ExecutionLimits`（正 Duration + 正 maxOutputBytes）+ `ToolExecutionEnvelope`（协议版本、executionId/targetId/toolName/toolVersion/descriptorHash/inputRef/inputHash/limits/approvalProofRef(可空)/correlationId/artifactManifest，拒绝重复 manifest 引用）。
    - `internal/Json.kt`：手写严格 canonical JSON 编码器/解析器（固定字段序、map 键排序、64-bit 整数、紧凑分隔符、严格解码；详见 ADR-0001）。
  - 测试（新增，`core/model/src/test/kotlin/com/helix/core/model/`）：`TestAsserts.kt`（JUnit4 无 Kotlin 版 assertThrows 的本地 reified 辅助）、`IdentifiersTest`、`IdGeneratorTest`、`ValueTypesTest`、`StateMachinesTest`（12×12 Turn 全矩阵 + 其余状态机全矩阵 + 进程死亡规则）、`EnumsContractTest`（枚举值集合守卫）、`TurnBudgetsTest`、`ExecutionTargetTest`、`ToolExecutionEnvelopeTest`、`HelixErrorTest`、`ClockTest`、`internal/CanonicalJsonTest`（internal 包内直接测试解析器）。
  - 构建：根 `build.gradle.kts` 为 `jvmLibraries` 集合统一添加 `testImplementation(junit4)`（version catalog 已有的 4.13.2，无新版本/新仓库）；重写 13 个 jvm 模块的 `gradle.lockfile`（core/model、core/agent、core/policy、core/workspace、extensions/mcp、extensions/skills、provider 六个、tools/framework、tools/files）。
  - 文档：本文件、[ADR-0001](../adr/0001-canonical-json-storage-encoding.md)（HXA-010 交付时为 proposed，2026-08-31 二次收口后 accepted）、`docs/implementation-status.md`。
  - 最小附带修改：`app/src/main/kotlin/com/helix/app/MainActivity.kt` 的 `HelixApp` 增加**函数级** `@Suppress("LongMethod")`（M0 遗留的 Compose 长函数，detekt 门禁在整仓运行时暴露；未放宽项目级规则，未改行为）。
