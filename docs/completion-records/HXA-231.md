## 交付

| 范围 | 实际变化 |
| --- | --- |
| 单一事实源 | ToolRegistry/ToolBindingStore 原子保存 descriptor、executor、可信 owner、稳定实现 revision 和 incarnation；深冻结发布契约；删除独立实现注册表和 PluginToolBinding |
| 全部来源迁移 | Built-in 在容器开放前成对注册；Plugin 全量候选一次发布；MCP/A2A 按 owner 原子替换/移除；测试夹具不再反射改实现表 |
| 生产请求闭环 | 实际 ModelRequest 工具面 → ModelToolBindings/BindingRef → 参数解释 → Scheduler footprint → ApprovalBinding → executor；禁止旧请求查最新同名实现；空工具面和未曝光名称拒绝 |
| 审批与撤销 | 稳定 owner/revision 进入审批哈希；进程 incarnation 不进入稳定批准身份；审批等待/排队后复验，替换与启动线性化；不消费无效旧证明、不假撤销已发生副作用 |
| 持久可追踪 | 现有 RequestContextManifest 单独记录实际曝光名称/绑定；三种 Provider wire 不包含该元数据；业务 args/modelIntent 的既有隔离保持 |
| 发布与资源 | 冲突或持久准备失败保留旧集合；准备不锁住读者/准入；禁止递归发布；MCP/A2A 启用在事务中提交，A2A 保持 content → Room 锁顺序；Registry 无旧实现历史链 |
| 发现连续性 | 精确名称优先、名称匹配优于纯描述；零命中保留仍可用窗口并清理失效项；不增加 64-tool 上限、不扩大权限 |

绑定变化产生明确的执行前拒绝，模型可以重新发现后发起新调用；不要求用户手动修复绑定，不自动重放写入。权限、审批、执行限制、effect owner 与 UNKNOWN 事实仍由原有执行管线负责。
