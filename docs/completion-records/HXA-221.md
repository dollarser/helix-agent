# HXA-221：Pre-release Clean-slate Baseline Cleanup

日期：2026-09-26。分支 `refactor/clean-slate-engine`。本任务在 HXA-220 Engine 边界稳定后执行，目标是把尚未正式发布的 Helix 重新定义为第一个长期维护 baseline，不为旧内部开发版本保留 migration/adapter 双路径。

## 交付

### Room baseline

- `HelixDatabase` 当前版本重置为 **1**；当前 KSP/Room schema export 只保留一个 `1.json`。
- baseline schema：**45 张表**，Room identity hash：`7c0724fd984a4127d7a4233e24b05a11`。
- 删除生产 `ALL_MIGRATIONS`、`MIGRATION_N_M` aliases、1→31 migration 注册和 migration-only helpers。
- 删除旧 1..31 schema fixtures 和 migration-only Android tests；新增 fresh-create baseline contract，验证 `PRAGMA user_version=1`、foreign keys、关键表和 Turn indexes。
- 删除不再需要的 Room migration-testing dependency，并通过 `--write-locks` 重新计算 `:core:storage` 锁状态。
- **没有**加入 `fallbackToDestructiveMigration` 或双 schema runtime。旧开发安装数据库不受支持，需清数据/重装。

### Internal compatibility cleanup

- Connector：删除旧 `filesDir/connectors` JSON/skill snapshot 导入、`legacy:$id` identity fallback、`legacyConnectorIdentity` 与一次性 `connector_catalog_state` 表；当前安装必须携带 canonical identity/revision/sessionScoped。
- Provider：`ProviderTestStatusStore` 收敛到固定 8 字段 canonical line format；field 8 始终为模型列表 JSON 或 literal `null`，不再接受/写入 pre-HXA-059 7 字段格式。
- Goal criteria：删除冗余 persisted `satisfied` boolean；删除已被 ADR-0040 supersede、仅用于历史 goal rows 的 Criterion binding/verification/pending-review 类型、codec 与 test oracle。
- Chat：删除 production `send(text)` convenience 与 rejected-send 的旧 composer `shareDraftText` 回填；所有 Android tests 迁到 test-only typed `ChatSubmission` helper。
- Tool-result history：当前 persisted envelope 的 `status` / `summary` 改为必需字段，不再为旧内部行补 `UNKNOWN` / 空 summary。
- App resource diagnostics 不再运行历史 migration workload，改用当前 schema open/write/reopen/close baseline workload。
- 当前 entity/repository/audit 注释删除已失效的旧 migration/legacy 叙述。

明确保留：
- Android API level 行为；
- Provider wire / OpenAI-compatible / OAuth/vendor 兼容；
- 当前文件导入导出协议；
- malformed/corrupt persisted data 的 fail-closed 防御；
- marketplace 内置 code-review skill 对“backward compatibility / schema migrations”的通用代码审查能力。

决策记录：项目尚未正式上线，因此旧 Helix 本地数据库/API/内部行格式不构成产品兼容承诺；本任务不新增 ADR，而是执行 HXA-220 后确认的 clean-slate 产品前提。真实平台和外部协议兼容继续受现有 ADR/产品契约约束。
