# HXA-079 A2A Task Tool bridge 与恢复（完成记录）

- 日期：2026-09-05
- 前置任务：HXA-078（commit `6ae13ac`）
- 状态：完成

## 目标

把用户明确启用的远端 A2A Skill 注册为独立的网络 Tool，经现有
Dispatcher/Policy/Approval/Audit 管线执行；支持 SendMessage、SendStreamingMessage、
GetTask、CancelTask 与 SubscribeToTask，并以持久 Task 关联保证断线、取消和进程死亡后
只对账原 Task、不新建 Message 重发。

## 实现和复核的契约

- `A2aToolSource` / `ToolOrigin.A2aOrigin` 与 MCP 独立，名称固定为
  `a2a.<agent>.<skill-slug>`；远端声明不能降低 NETWORK 分类或冒充 MCP。
- 固定输入 schema 只接收有界 task、structured data、最多 4 个本地 Artifact 引用、
  期望 output mode 与 stream 开关。实际序列化请求仍受 2 MiB 总 wire ceiling。
- ChatService 从可信 descriptor 生成 A2A egress facts；首发、origin/contract/sensitivity
  变化进入既有 checkpoint、Policy、Approval 与脱敏 Audit 路径。
- Room 持久化 `toolCallId ↔ taskId/contextId/cardHash/skillHash/inputHash/event sequence/eventId`。
  已存在关联只允许 GetTask/Subscribe/Cancel；送达不明确且无 taskId 时停在
  `NEEDS_REVIEW`，再次执行也不能 SendMessage。
- text/data 作为 `UNTRUSTED_A2A_CONTENT` 返回；结构化本机动作只能是数据，不能反向调用
  Tool。远端 URL 不自动下载；Raw Artifact 限制为 1 MiB，复制到确定性 Workspace 路径后
  由本地重新计算 SHA-256 并登记引用。

## 验证中修复

专项恢复测试发现，已完成 Task 再次对账会重复写同一路径并再次登记 Artifact，触发
`artifacts(sessionId, relativePath)` 唯一约束；同时首次写入的 A2A 子目录尚未确保存在。
现在导入在进程内串行化：首次安全创建确定性输出目录并登记；后续按会话和路径查找既有
记录，重新验证远端 bytes、Room size/hash 和磁盘文件 size/hash 全部一致后复用原
`artifactRef`。任何文件篡改、快照变化或重复登记均 fail closed，不覆盖、不降级。
