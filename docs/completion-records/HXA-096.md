# HXA-096 Root L3 控制台（完成记录）

- 日期：2026-09-05
- 目标：检查当前产品是否存在必须依赖任意 Root shell 的明确需求；只有必要性成立时才实现仅 developer UI、L3、逐次完整审批且不进入普通模型工具表的 `root.exec`。
- 前置任务/commit：HXA-095 非真机实现范围；M9 集成 commit `247fd7e`。
- 修改文件：`docs/development/m9-root-exec-decision.md`、`scripts/verify-variant-boundaries.sh`、`tools/root/src/test/kotlin/com/helix/tools/root/RootToolsTest.kt`、`tools/root/src/androidTest/kotlin/com/helix/tools/root/RootToolsRootlessDeviceTest.kt`。
- 完成结论：当前已批准产品用例均可由 HXA-095 的五个参数化高层 Root 工具覆盖，没有实现任意 Root shell 的必要性；按路线允许的分支，`root.exec` 保持不实现。该结论不新增 descriptor、executor、通用命令 Binder 协议或控制台。
- 机械门禁：Root wire request 没有 command/script/secret 字段；Root Registry 只允许 `root.status`、`root.file.read`、`root.package.info`、`root.process.list`、`root.log.read`；variant boundary 脚本发现 developer APK 含 `root.exec` 字符串即失败；JVM 与 rootless device 测试均断言 descriptor 缺席。
- 自动测试与验收：M9 非真机综合验证执行 Spotless、detekt、Root/App 双 flavor 单测与 assemble，以及 docs/i18n/lockfile/Secret/ADR/variant boundary 门禁，全部 exit 0；API 29/36 Root rootless device suites 均 0 failed。详细命令和计数见 `docs/development/m9-non-device-progress.md`。
- 手工验证设备：`Helix_M9_API_29`（API 29）与 `Helix_M9_API_36`（API 36）专用 AVD；本 HXA 的验收对象是 `root.exec` 缺席，不以模拟器冒充 rooted 执行证据。
- 权限/数据/许可证变化：无；没有新增 Root 命令能力、权限、数据流、依赖或许可证。
- 决策记录：`docs/development/m9-root-exec-decision.md`；与 accepted ADR-0019 的“只有明确产品必要性时才评估 `root.exec`”一致，不形成新的跨模块架构决定。
- 风险或后续任务：未来若出现高层参数化工具无法满足的具体需求，必须重新授权并重新评审命令/路径范围、L3 审批、输出限制、失权/crash 恢复和 rooted 真机攻击矩阵；本完成记录不能作为未来自动实现授权。
