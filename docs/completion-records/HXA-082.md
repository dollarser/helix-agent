## 交付

1. **纯 JVM tar 流式读取器 + Zip Slip 防护（`:runtime:proot-core`）**：`TarStream`（512 字节块流式解析；typeflag 白名单 `'0'`/`'\0'` 常规文件、`'5'` 目录、`'2'` symlink + GNU `'L'`/`'K'` 长名续块；成员上限 256 MiB/10 万条；payload 64 KiB 流式拷贝，绝不整体缓冲；结尾零块消费保证调用方读满全流以哈希整档）+ `TarPathSafety`（纯词法校验，绝不对宿主解析 symlink：成员路径拒绝 NUL/换行/反斜杠/`..`/空段，前导 `/` 按 tar 约定剥离；symlink 目标词法深度判定——绝对目标按 PRoot chroot 语义以树根为基准，`..` 越过树根即 fail-closed；悬空目标合法，`/proc` 等由 PRoot 运行时绑定）。
2. **安装器状态机（`:runtime:proot-core` `RootFsInstaller`）**：全程持 `state/install.lock` 排他文件锁（同 JVM 二次触发报告为 held 而非崩溃）→ 启动即清扫孤儿（stale `.partial-*` + 未被 active/rollback 引用的 `inst_*`）→ 解压+哈希验证到 `.partial-<rand>/<inst_id>` → 放置 PRoot 二进制（逐文件 ≤64 MiB 门）→ **结构 smoke**（必需路径存在性 `NOFOLLOW_LINKS` + 全树 ELF `PT_LOAD` 对齐预检，按调用方传入的设备页大小；不执行任何 native 代码）→ 写 `manifest.json`（内嵌 lock 完整性重算，HXA-080 codec）→ promote（rename 进 `runtime/`）→ **原子激活**（`active.json` 先写、`rollback.json` 次之，tmp+fsync+rename+目录 fsync；旧 rollback 目录在两份激活文件都重写之后才删除）→ 删除 `.partial`。任何阶段失败：前一版本完好无损、`.partial` 清除、失败阶段与原因回填 `InstallOutcome.Failure`。`activateRollback` 原子交换 active/rollback（HXA-087 消费，交换前校验两版本目录与 rollback manifest 均存在）。

4. **锁定语义修正（随本任务生效）**：`alpine-rootfs` 组件的 `sha256`/`size` 改为锁定**原始 tar**（`f15c9434…` / 137,287,680 B）——AGP 资产管线自动展开 `.gz` 并以 `.tar` 条目存原始字节（HXA-081 缺陷 4 记录的平台行为），设备端读到的正是这些字节；`§6.4` 步骤 5 的"再次验证 SHA-256"因此对**设备实际读取的字节**闭环。gzip 存档（`500594df…` / 50,955,376 B）降级为纯构建产物，仅在构建日志记录。`scripts/deterministic_tar.py` 与 `build-proot-assets.sh` 相应改为以 raw tar 为权威产物（raw tar 逐字节可复现已实测：generate/verify 双跑一致）。

## 决策记录：安装器实现决定（无新 ADR）

1. **lock 锁定对象 = 原始 tar（语义修正，本任务核心决定）**：AGP 资产管线自动展开 `.gz` 并以去后缀名存**原始字节**（HXA-081 已实测并记录的平台行为），设备端 `assets.open` 读到的恰是 raw tar；`§6.4` 步骤 5"解压前再次验证 SHA-256"只有锁定 raw tar 才对设备实际读取的字节闭环。上游 URL（`.tar.gz`）保留为来源真相，gz 哈希（`500594df…`）降级为构建日志证据。代价：lock 的 size 字段从 48.6 MiB 变 131 MiB（语义不变：仍是"设备将解压的完整存档"的完整性锚点）。raw tar 的确定性（`deterministic_tar.py` 同参数）保证该哈希可复现——generate/verify 双跑逐字节一致已实测。
2. **`state/` 位于 `runtime/state/`（版本无关）**：激活指针（`active.json`/`rollback.json`/`install.lock`）必须有跨版本稳定路径，原子切换才有意义；这是对 §6.3 目录示意（state 随版本目录）的显式偏离，理由写入 `RootFsInstaller` KDoc。
3. **单遍流式解压，绝不整体缓冲**：设备测试进程 heap 上限 201 MB（实测 OOM 后固化），137 MB 存档与 51 MB 单文件（`usr/bin/node`）都只允许 64 KiB 缓冲流过；APK 资产流惰性打开、哈希与解压同一遍完成（`TeeDigestStream`）。
4. **崩溃序固定：promote → `active.json` → `rollback.json` → 最后删旧 rollback 目录**：任一点崩溃，指针永不指向缺失目录；旧 rollback 目录的删除严格晚于两份激活文件重写。旧 rollback 删除失败静默容忍（下次启动清扫兜底）。
5. **`pageSizeBytes` 由调用方传入**：安装器不做 native 页大小探测（`getpagesize` 归 HXA-084 runner 的所有物）；设备测试从 `System.getProperty("page.size"|"page_size")` 取值，缺省 4096（两台模拟器均 4 KiB 页）。
6. **smoke = 结构性，不执行 native 代码**：必需路径（`bin/busybox`、`bin/sh`、`usr/bin/{bash,python3,node,ripgrep,git}`、`etc/{os-release,passwd}`）以 `NOFOLLOW_LINKS` 判存在 + 全树 ELF `PT_LOAD` 对齐按页大小预检。真实 rootfs 的 `bin/sh -> /bin/busybox` 是**绝对** symlink，宿主上悬空——宿主解析（`File.exists` 默认跟随）必然误杀，故结构性判定一律 `NOFOLLOW_LINKS`（这也是 PRoot chroot 运行时的真实语义：链接在树内解析）。
7. **tar typeflag 白名单 = `'0'`/`'\0'`/`'5'`/`'2'` + `'L'`/`'K'` 续块**：硬链接/设备文件/FIFO/socket/`A` 增量等一律 fail-closed（rootfs 存档不需要，接受面越小攻击面越小）。根成员（`/`、`./`、`/./`——真实 Alpine 存档首条目即 `/./`）归一化为 `""` 且只允许目录。
8. **ELF 预检读有界前缀（64 KiB）**：实测全部 360 个 ELF 的 phdr 表末端最大 680 B；`e_phoff` 落在前缀之外即报 `e_phoff out of bounds` fail-closed（拒绝"无法验证"而非放行），51 MB 的 node 永不整体入内存。
9. **`java.nio.file.Paths.get` 而非 `Path.of`**：`Path.of` 在 API 33 以下是 `@SystemApi`，API 29 设备 `NoSuchMethodError`（验证中缺陷 6，API 36 先绿、API 29 暴露）；`Paths.get` 为 API 26+ 公开 API。调用点附注释锁定。
10. **代码形态服从门禁阈值**：detekt/ktlint 对 object ≤10 函数、throws/return ≤2、嵌套 ≤4 的硬约束促使状态机拆分——`RootFsInstaller`（安装管线 10 函数）/ `InstallState`（状态文件机制 10 函数，含激活写/交换）/ `TarReader`（块解析 10 函数）+ 文件级私有助手（`writeBinaryCapped`/`copyCapped`/`headerField`/`headerOctal`）。两处 `@Suppress` 均附理由注释：`TooGenericExceptionCaught`（fail-closed 阶段边界，任何异常类型都是合法安装失败且必须映射为 `Failure(stage)`）、`SwallowedException`（同 JVM 双锁异常无诊断价值，null 即信号）。
11. **无新 ADR**：安装器全部语义（`.partial`、防 Zip Slip、smoke、原子激活、一版 rollback）为架构文档 `local-code-execution` §6.4 步骤 5-8 规范文本的直接实现；lock 锁定对象修正是该平台行为（AGP 展开）下的规范闭合，未改变任何 ADR 决定。

## 验证中缺陷

1. **（真实存档）首成员 `/./`**：真实 Alpine 存档第一条目是 `"/./"`（根目录带 `.` 段），归一化前报"空路径段"。修复：`normalizeMemberPath` 对根形态（`/`、`./`、`/./`）返回 `""`，且 `validatedMember` 规定 `""` 只允许目录成员。
2. **（设备 smoke）`File.exists()` 跟随 symlink**：真实 rootfs `bin/sh -> /bin/busybox` 为绝对目标，宿主上悬空 → "missing rootfs path: bin/sh" 误杀。修复：smoke 必需路径与 ELF 遍历一律 `LinkOption.NOFOLLOW_LINKS`（同时防止经由 symlink 扫描宿主文件）。
3. **（测试设计）`checkLockFingerprint` 曾是重言式**：`sha(x) != sha(x)` 恒假。修复：改为真实 encode→parse 往返比较（与 080 canonical 指纹同路径）。
4. **（设备 OOM）`readBytes()` 137 MB**：设备测试进程 heap 增长上限 201 MB（`Failed to allocate a 137287696 byte … growth limit 201326592`）。修复：存档哈希改 64 KiB 分块流式；篡改测试改 `CorruptingInputStream` 在飞翻转 1 字节（不落地、不整档缓冲）。
5. **（smoke OOM 风险）51 MB `usr/bin/node` 整体读取**：ELF 预检原实现 `readBytes` 整个文件。修复：有界 64 KiB 前缀 + `e_phoff` 越界 fail-closed（缺陷 8 记录）。
6. **（API 29）`Path.of` NoSuchMethodError**：API 36 模拟器先绿、API 29 暴露 `No static method of(Ljava/lang/String;[Ljava/lang/String;)…`。修复：`Paths.get`（缺陷 9 记录）。
7. **（测试构造）`ByteBuffer.wrap(arr, off, len)` 不是切片**：wrap 全数组且 position=off，`putLong(0, v)` 写到了数组头、冲掉 ELF magic（"magic clobbered" 之谜）。修复：`wrap(arr).putLong(0x20, v)` 绝对偏移写入。附带发现：081 时代两个 ELF 负向测试对非 ELF 输入也是"通过"（align=0/machine=null 同样触发拒绝）——作为 smoke 路径测试仍有效，但 ELF 解析正确性由新增的 `e_phoff` 越界测试 + 真实存档设备测试补齐。
8. **（Kotlin/平台小坑一批）**：`FilterInputStream` 构造参数非属性（`upstream` 自命名）；类体内不允许 `private const val`（改 `val`）；spotless ktlint 120 列（设备测试 3 处换行）；`no-consecutive-comments`（EOL 注释不得紧跟 KDoc——理由并入 KDoc）。
9. **（门禁）detekt/ktlint 阈值严于预期**：`TooManyFunctions` 在 **=11** 即触发（阈值 11 的语义是"上限 10"）；另有 `ThrowsCount`/`ReturnCount`/`NestedBlockDepth`/`CyclomaticComplexMethod`（=15 触发）/`MaxLineLength`/`SwallowedException`/`UseCheckOrError`/`LoopWithTooManyJumpStatements`。修复方式全部为结构化重构（合并同类失败为单一 problem 判定、抽取文件级助手、错误状态记录 + 循环外统一抛出），未放宽任何门禁配置；仅 2 处带理由 `@Suppress`（决策 10 记录）。
