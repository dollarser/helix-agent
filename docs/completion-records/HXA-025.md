    - `ModelProvider.kt`：doc 10 §2.1 统一 provider 契约——`interface ModelProvider { val descriptor: ProviderDescriptor; suspend fun listModels(): ModelCatalogResult; suspend fun validateConfiguration(): ProviderCheckResult; fun stream(request: ModelRequest): Flow<ModelEvent> }` + `ProviderDescriptor`（id/displayName/protocol/model/endpoint，`residence` 由 endpoint 派生）。KDoc 固定两条纪律：协议由配置固定（失败不切协议）；`stream` 的流契约是**全总**的（transport 失败映射为终端 `Error` 事件，绝不把 IOException 抛给收集方）。
    - `ProviderResult.kt`：`ModelCatalogResult`（`Listed(models)`（1..1024 唯一 id、控制字符拒绝）/ `Unsupported`（无 list 端点的服务，如官方 Anthropic API）/ `Failed(code, detail, retryable)`）+ `ProviderCheckResult`（`Ok` / `Failed`），detail 一律 `boundedDetail`（≤512，剥换行，永不带 secret/payload）。
    - `ProviderCapabilities.kt`：doc 10 §2.4 快照——`ProviderCapabilities(streaming, toolCalls, parallelToolCalls, vision, reasoning, jsonSchemaOutput, maxContextTokens, source)` + `CapabilitySource { PROBED, MANUAL }`；`toJsonString` 固定字段序的规范 JSON（`maxContextTokens` 数字或显式 `null`，source 按枚举名）；`parse` 是存储列（`provider_configs.capability_snapshot`，HXA-020 既有列）的严格恢复解析（ADR-0001 纪律：键集必须完全一致、布尔只认 JSON 字面量、数字字符串不算数字、未知 source/缺键/非 JSON → IAE fail-closed）；`withManualSource()` 是“手工 override 必须标记”的类型化落位（值保留、来源改标 MANUAL，UI 据此显示“手动声明”）。
    - `CredentialLookup.kt`：`fun interface CredentialLookup { fun lookup(alias: SecretAlias): String }`——凭证在**请求时**经注入的查找器解析（HXA-020 Keystore 后端的接缝；provider 模块纯 JVM 不依赖 Android 存储模块）；查找失败必须抛，请求绝不在缺凭证时发出。
    - `wire/Wire.kt`：协议无关 HTTP 接缝（公开 API 只有这一层，OkHttp 类型不外泄）——`WireRequest(method/url/headers/body)`（方法白名单 GET/POST/HEAD、GET 无 body、header 名 token 校验、大小写不重名）、`WireBody { suspend bytes(); suspend forEachChunk(suspend onChunk); close() }`（suspend 回调让 provider 流可直接从 chunk 回调 emit；消费方必须在 `finally` close）、`WireResponse(status, headers, body)`、`WireClient { suspend open }`（连接级失败以 `IOException` 传播）；`mapHttpStatus`——非 2xx → 封闭失败类的**唯一**映射面（三个 adapter KDoc 预留的 HXA-025 映射落位）：401/403→AUTH(false)、408→TIMEOUT(true)、429→RATE_LIMITED(true)、500/502/503/504→SERVER_ERROR(true)、**501 Not Implemented→SERVER_ERROR(false)**（端点不实现该 API，重试无意义）、其他 4xx→PROTOCOL(false)、其他 5xx/未知→SERVER_ERROR(false)（fail-closed 不重试）、2xx 传入 → ISE（防误用）。
    - `wire/OkHttpWireClient.kt`：OkHttp 实现（`implementation` 依赖，接缝之后）——阻塞 exchange 跑在 `Dispatchers.IO`（`open` 是协程友好包装；read timeout 约束卡死对端）；响应体上限 8 MiB（超限 `IOException`，SSE 解码器另有 per-line/event 界）；body 拥有连接直到 `close()`（幂等）；**零日志**（body 可能含会话内容、header 可能含凭证——doc 02 §6.2 零 secret 纪律）；KDoc 明示取消语义（收集方取消后读到下一 chunk 边界即停并 close，read timeout 是硬界）。
    - `WireModelProvider.kt`：协议 provider 的共享 transport 骨架（`abstract class`，实现 `ModelProvider`）：
      - `stream`：encode → 凭证/header 解析（**在 transport try 之外**——缺凭证/header 冲突是配置错误，原样传播，绝不伪装成 transport 错误）→ open → 非 2xx 经 `mapHttpStatus` 发单一终端 `Error` → 2xx 走解码器 `feed` 循环（chunk 回调内逐事件 emit，增量语义保持）→ `finish`；body 恒 `finally close`（含取消路径）；`SocketTimeoutException`→`Error(TIMEOUT, true)`、其他 `IOException`→`Error(TRANSPORT, true)`（两 catch 块分离，定点 `@Suppress("SwallowedException")` 带 KDoc：异常被**有意**转换为终端事件，`Error` 无 detail 字段、cause 类已编码进错误码）。
      - `listModels`：`modelsPath()` 为 null → `Unsupported`（零请求）；否则 GET → 非 2xx/IO 失败映射 → 2xx 经 `parseModelIds`（OpenAI 兼容 `{"data":[{"id":...}]}` 严格解析：非 JSON/非对象/无 data 数组/条目无 id → PROTOCOL(false)，四违约各自独立诊断）；body 恒 close。
      - `validateConfiguration`（连接测试 phase 1）：有 list 端点 → 委托 `listModels`（一次带认证的廉价调用）；无 list 端点（官方 Anthropic API）→ **最小流**（1 条 user 消息、`maxOutputTokens=8`）完成 transport+auth+流契约三合一检查。
      - `wireUrl`：endpoint 的 API root（`path`，如 `/v1`）与协议资源路径（`responses`/`chat/completions`/`messages`/`models`）拼接；**规范形式**——scheme 默认端口省略（`https://api.anthropic.com` 不带 `:443`）、IPv6 字面量加方括号；endpoint path 语义在 KDoc 写明（catalog 模板 HXA-026 按此预填）。
      - `headersFor`：用户 allowlist 头 + 协议 auth 头 + `Content-Type: application/json` 三层合并，**大小写不敏感冲突 = 配置错误**（IAE）——用户头覆盖 auth 头是凭证 bug，fail-closed；`Content-Type` 由协议独占。
      - `resolveCredential(credentials, alias)`：顶层公开函数（不放类内，控制类函数数；adapter 模块经 `provider:api` 公开面调用），空白凭证 IAE。
      - 文件级私有 helper（`ioFailure`/`ioFailureCheck`/`parseListObject`/`ModelListParse`）同理由类移出。
    - `ModelStream.kt`：协议岛的两侧接缝——`fun interface RequestEncoder { encode(ModelRequest): String }`、`interface StreamDecoder { feed(ByteArray): List<ModelEvent>; finish(): List<ModelEvent> }`。三个 adapter 的既有 encoder/decoder 类各加一行接口实现（`override` 修饰符），零逻辑改动。
    - `CapabilityProbe.kt`：doc 10 §2.4 四阶段连接测试编排——`probe(provider): ProbeOutcome`，phase 函数按序短路（首个失败阶段即停，后续阶段不执行，`ProbeOutcome.Failed(phase, code, detail, retryable)` 携带阶段号）：

      2. `listModels`（`Unsupported` 计为通过——不是每个服务都暴露 list）；
      3. 最小文本流（1 条 user 消息、`maxOutputTokens=16`、合法终端 = `Completed` 或 `Refusal`；`Error` 终端/无终端 → 阶段 3 失败）；

- 关键实现决策（均为可逆实现选择，不触发 ADR）：
  - **自有 Wire 接缝 + OkHttp 实现**：公开 provider API 只暴露 `WireRequest/WireResponse/WireClient`（协议无关），OkHttp 以 `implementation` 藏在接缝后（adapter 模块与 app 公共面不见 vendor HTTP 类型）；app 构造 `OkHttpWireClient` 注入（HXA-028）。接缝不引入第二个 HTTP 库（ktor 已在 catalog 但归其他任务面，不重复）。
  - **`suspend`/`Flow` 契约需要 coroutines**：doc 10 §2.1 接口签名即 `suspend`/`Flow`——`kotlinx-coroutines-core 1.10.2` 是文档契约的必需依赖（AGENTS.md“任务明确需要才可加依赖”的“明确需要”即此；catalog 原本没有 coroutines，新增版本 pin 1.10.2 与 Kotlin 2.3.21 配套）。`WireBody` 回调设为 suspend 使 provider 流能从 chunk 回调直接增量 emit（不整流缓冲）。
  - **endpoint.path 是 API root**：`NormalizedEndpoint.path`（如 `/v1`）+ 协议资源路径（`responses`/`chat/completions`/`messages`/`models`）；wire URL 规范形式（默认端口省略、IPv6 方括号）。模板预填归 HXA-026（Ollama 模板 `http://127.0.0.1:11434/v1` → `.../v1/chat/completions` 即此语义）。
  - **phase 1 双语义**：有 list 端点 → 带认证 GET（廉价）；无 list 端点 → 最小流（`maxOutputTokens=8`）三合一。避免 Anthropic 这类无 list 服务只能靠 401 探测。
  - **501 不重试**：`Not Implemented` 表示端点不实现该 API（协议/路径错配），重试无意义——与 500/502/503/504 的瞬态类区分（映射表 fixture 逐值覆盖）。
  - **未实测能力保守默认**：probe 只声称实测过的 `streaming`/`toolCalls`；其余字段 `false`/`null`（用户可经 `withManualSource` 覆盖并自动标记 MANUAL）。
  - **detekt 定点豁免（2 处，均带 KDoc 理由）**：`WireModelProvider.stream` `@Suppress("SwallowedException")`（连接异常**有意**转为终端 `Error` 事件，`Error` 无 detail 字段、cause 类已编码进错误码——不是吞异常）；文件级 `parseListObject` `@Suppress("ReturnCount")`（三个 fail-closed 返回各对应一个 vendor 违约）。其余 10 项 detekt 发现全部按重构消化（函数拆分、多 catch 块分离、`require` 替代 throw、helper 移出类控制函数数、循环单跳转改写），未新增类级豁免。
  - **真 socket 测试用 JDK HttpServer**：`com.sun.net.httpserver`（JDK 17 自带）起本机 ephemeral 端口测 OkHttp 传输（分块/上限/拒绝），不引入 MockWebServer 依赖、不触外网。

- 排障记录（真实证据，供后续参考）：
  - `libs.okhttp` type-safe accessor 陷阱：catalog 同时有 `okhttp` 与 `okhttp-sse` 别名时，`libs.okhttp` 是**命名空间访问器**（无 `.get()`，Kotlin 脚本里解析成无 `get` 的类型 → `Unresolved reference ... receiver type mismatch: ExtensionContainer.get`）；`libs.findLibrary("okhttp")` 在 precompiled 脚本里不存在（`libs` 是 accessor 不是 `VersionCatalog`）→ 加叶子别名 `okhttp-wire` 走 `libs.okhttp.wire`（与 `libs.okhttp.sse` 同命名空间）。
  - verification-metadata 与前三任务不同：本任务**确实新增** 5 个组件 sha256 条目（okhttp/okio/coroutines 首次进入解析图），不是零漂移。
  - `emitAll(List)` 不存在（需要 `toListFlow`）→ 直接 for 循环 emit；且 `forEachChunk` 回调最初是非 suspend 函数式接口 → 流内无法 emit（“Suspension functions can only be called within coroutine body”）→ `WireBody.forEachChunk/onChunk` 改 suspend（OkHttp 实现内部 `withContext(Dispatchers.IO)` 包住阻塞读，回调在 IO 线程被 suspend 调用，emit 合法）。

  - kotlinx-serialization 1.9 的 `JsonPrimitive` 数值/布尔访问器（`long`/`boolean`/`longOrNull`）是**包级扩展**需显式 import；`isLong`/`booleanOrNull` 不存在；`longOrNull` 对数字**字符串**会解析（`"131072"` → 131072）——严格解析需先 `isString` 拦截；`put(key, Boolean/Long/String)` 便捷重载不存在（只有 `JsonElement` 重载）→ 一律 `JsonPrimitive(...)` 显式包装；`JsonObject` 存 JSON `null` 时 `obj[key]` 返回 `JsonNull` 而非 Kotlin `null`（解析需双判）。
  - JUnit 4 两个陷阱（第三次踩，记录固化）：(a) 表达式体测试 `fun x() = runBlocking { ... assertThrows(...) }` 当最后一句是 `assertThrows`（返回异常值）时函数返回类型非 void → `InvalidTestClassError: Method should be void`，改块体；(b) `assertThrows` 的 `ThrowingRunnable` 是非 suspend SAM，不能直接调 suspend 函数 → 内部再包一层 `runBlocking`。
