## 范围（对应 `docs/development/roadmap.md` HXA-044）

- **`core:workspace` 新 seam**：
  - `AtomicFileWriter.writeAtomicStream(target) { out -> ... }`：流式版本的原子发布（temp + `channel.force` + 目录 fsync + `ATOMIC_MOVE`）。流由 writer 拥有——回调只写不关，writer 负责 fsync/close/rename；**任何**失败（含中途 abandon）temp 删除、不发布。
  - `AbandonedWrite`（RuntimeException 开放基类）与 `AbandonedWrite.Cancelled` / `AbandonedWrite.LimitExceeded`：大流取消/超限的**类型化**中断，在 rename 之前逃出 writer，调用方可与 I/O 失败区分。
- **`feature:files` 平台适配层（全新模块源码）**：
  - `SafImportPipeline`：SAF 文档导入 workspace `input/`，对谎报 provider 全链路 fail-closed（决策记录第 2 条）；`SafSourceMetadata`（size/MIME/displayName，全部不可信输入）、`SafSourceOpener`、`SafImportLimits`（默认 256 MiB / 1 GiB 配额）。
  - `SafExportPipeline`：workspace 用户 region（`input/`/`work/`/`output/`，`.helix/` 永不）导出到用户选择的 SAF destination；分块拷贝 + 逐块取消 + 写后 destination 报大小复核。
  - `SafGrantStore`：persisted tree grant 注册表（原子写 JSON、确定性 model-legal scopeId、损坏隔离、撤销 sweep，决策记录第 4 条）。
  - `SafNameSanitizer`：恶意 display name 消毒（分隔符→`_`、控制字符剔除、200 上限、`imported-file` fallback）。
  - `ContentResolverSaf*` 五个生产 adapter：metadata reader（`OpenableColumns` 查询 + `getType`）、source opener（`openInputStream`）、destination opener（`openOutputStream` "w"）、destination verifier（写后 SIZE 查询，失败=未知）、grant probe（tree 根 query 成败=撤销检测）。
  - `SafCancelToken`：最小协作式取消令牌（工具层 `CancelSignal` 的一行适配，平台层不依赖工具层）。
- **`app`**：`AppContainer` 新增 `FeatureFiles` 适配器束（grant 注册表 `filesDir/workspaces/saf-grants.json`；导入/导出管线经与文件工具相同的 `scopeRoots` 指向 app 私有 workspace，导入落 `input/`）。
- **设备测试（矩阵设备列）**：`feature/files/src/androidTest` 内建 in-APK **恶意 ContentProvider**（`LyingContentProvider`：谎报 size/MIME/displayName、无大小的大流、拒绝访问、grant 存活/撤销两类 tree、诚实报大小的 export sink），`SafAdaptersInstrumentedTest` 10 用例驱动**真实** `ContentResolverSaf*` adapter 走真实 `ContentResolver` 路径——恶意 provider 的防御在真机上证明，而非 mock。

## 决策记录：关键取舍与理由

1. **导入 = 复制到 app 私有 workspace `input/`，`content://` URI 绝不进入模型层**：PRD 明确"SAF scope 默认复制到应用私有目录处理"。管线产出物只有 `scope:<scopeId>:input/<name>` 模型引用（doc 10：模型只看到 scopeId）；真实路径、`content://` URI 都不出现在 outcome、失败文本或后续模型输入中。
2. **provider 的 size/MIME/displayName 一律不可信（doc 07），三重防御**：(a) admission——reported size 超上限或超 workspace 配额 headroom 时**在读取任何字节前**拒绝；(b) streaming——每块检查取消 + 硬上限 `min(maxImportBytes, 配额 headroom)`，provider 少报实际多送时中途中断、temp 删除；(c) EOF——实送字节数必须与 reported size 精确一致，不一致视为撒谎：刚发布的文件删除后拒绝（`STREAM_SIZE_MISMATCH`）。MIME 从不信任，发布后用 `ContentProbe` 对真实字节重探；display name 先过 `SafNameSanitizer` 才成为文件名（`../../etc/evil\0name` → `.._.._etc_evilname`）。设备端 10 用例（in-APK 恶意 provider + 真实 ContentResolver）逐一证明。
3. **中断用类型化异常逃出 writer，而非布尔返回值**：`AbandonedWrite.Cancelled/LimitExceeded` 在 `writeAtomicStream` 的 rename 之前抛出 → temp 删除、文件不发布，调用方（导入管线）据此映射到 `CANCELLED` / `STREAM_LIMIT_EXCEEDED` 稳定结果，且与 `IOException`（→ `IO_FAILURE`）天然可区分。流的所有权归 writer（回调只写不关，fsync/close/rename 由 writer 完成）——这是 KDoc 契约，`ClosedChannelException` 回归测试锁住。
4. **grant 注册表：确定性 scopeId + 损坏隔离 + 逐条防篡改**：scopeId = `saf-` + `sha256(treeUri)` 前 12 hex——同一 tree 恒得同一 id，且是合法 `FileScopePath` scope id（模型只看到它）。注册表原子写（`writeAtomic`）；损坏/版本错误的文件**隔离**（rename 到 `.corrupt-<clock>`，从不删除）后从空启动，不崩 app；加载时逐条重验 `deriveScopeId(treeUri) == scopeId`，篡改过的条目（把 tree 别名的到别人的 scope id）被丢弃；撤销检测 = 对 tree 根的真实 query 探测，sweep 只移除不再应答的 grant（provider 卸载/权限撤销/用户撤销都表现为 query 失败 → 读作"不再已授权"，fail closed）。
5. **导出限定用户 region + 部分文档如实上报**：region 门与 HXA-043 mutation 工具一致（`.helix/` 内部永不可寻址）；拷贝分块 + 逐块取消检查，取消时 destination（content URI）无法从本侧 truncate，outcome detail 明确报"destination 可能持有部分文档"而非假装干净；写后 destination 自报大小与实写字节复核，不一致 = `SIZE_VERIFICATION_MISMATCH`（谎报的 destination 与谎报的 source 同样不可信）。
6. **接线只到适配层，不碰工具/审批语义**：本 HXA 交付 `AppContainer.featureFiles` 适配器束；把 persisted SAF tree grant 接入文件工具的 scope 解析、以及用户侧导入/导出 UI 动作，归 HXA-045/046。不新增 model 工具、不改 Approval/Policy 语义，模型侧可见面零变化。
