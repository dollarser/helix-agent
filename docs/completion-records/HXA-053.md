## 修改文件

生产（`runtime/quickjs/src/main/kotlin/com/helix/runtime/quickjs/tool/`）：

- **`CodeJavascriptRunTool.kt`（新增，369 行）**：
  - `fun interface JsExecutor { execute(JsExecuteParams, JsCancellation?): JsExecutionResult }`——同步有界、不重试的执行 seam；生产由 `JsExecutionClient(context)` 适配（AppContainer），JVM/设备测试注入 fake 返回 canned `JsExecutionResult`（`JsExecutionResult`/`JsExecutionLimits` 构造纯 JVM、不触 Parcel）。
  - `object CodeJavascriptRunTool`：`NAME="code.javascript.run"`、`VERSION=1`；`descriptor()` = operationClass **CODE_EXECUTION**、baseRisk **L2**（与 bash/mutation 同级的逐次精确审批，**无 auto-approve 路径**）、executionTarget **LOCAL_QUICKJS**、idempotency **NON_IDEMPOTENT**、requiredCapabilities 空、origin **BuiltIn**、timeout 45 s（框架硬上限，高于客户端 ~16 s 最坏 wall）、maxOutputBytes 256 KiB+16 KiB。
  - **inputSchema 只暴露 `code`（string，maxLength 262144=256 KiB 码点）+ `input`（type 联合 [object/array/string/number/integer/boolean]，可选）；`required=["code"]`、`additionalProperties=false`——limits/timeout/memory/source/output 一律不出现为模型参数**（模型无法抬高；executor 恒施加 `JsExecutionLimits.DEFAULTS`，隔离后端再施加一次）。
  - `executor(runner)`：cancel 前置检查 → 读 `code`（缺失/非串 → 稳定 Failed，非 success）→ `input` 缺省 = null（无输入）/ 存在 = `CanonicalArgs.canonicalize` 恰一个 JSON 文档 → `executionId=UUID`（一次性隔离实例、回收异步；id 不入审批 hash）→ `runner.execute` → `mapResult`。
  - **11 状态映射**（catch-all 绝不返回 success）：SUCCESS→`Completed{result,outputBytes}+auditDetail`；TIMEOUT→`TimedOut`；CANCELLED→`Cancelled`；INTERRUPTED/OOM/JS_ERROR/OUTPUT_LIMIT/REQUEST_REJECTED/BIND_FAILED→`Failed(sideEffectFree=true)`；CRASHED/UNKNOWN→`Failed(sideEffectFree=false)`。detail 有界 512 字、绝不含代码正文。
  - `executionDetail()` 构建 §4.8 **脱敏** JsonObject：status、sourceSha256、sourceBytes、inputBytes、inputSha256、outputBytes、outputSha256、limits{timeoutMs,memoryBytes,maxSourceBytes,maxInputBytes,maxOutputBytes}、isolated(serviceUid>=0)——**只有 hash/size/limit，绝不 body**。

## 限制与后续（HXA-054 入口）

- **如何触发该工具**：Act/Goal 模式下模型可请求 `code.javascript.run`，args 仅 `{code: string, input?: <JSON 值>}`；consumer 变体 STANDARD 固定，L2 逐次精确审批（通用 L2，无 Trusted Workspace / 批量复用 / auto-approve）。审批卡见"代码/命令"行 + 独立代码执行块（完整代码块可复制/搜索、输入来源、联网：否、执行限制、代码 SHA-256 短摘要）。
- **E2E 入口**：`ChatService.dispatchToolCall(toolCallId, turnId, "code.javascript.run", argsJson)`（每调用一条；在 worker 线程，broker 阻塞等用户决定）；审批 `approveApproval`/`denyApproval(approvalId)`；结果回填读 `storage.toolResults.byToolCall(id)`（`readContent`）或 `Succeeded.result.payload`（`{result,outputBytes}`）；审计读 `storage.auditEvents.recent(n)` 的 `redactedPayload.executionDetail`。设备测试即走此入口（`CodeJavascriptRunDeviceTest`）。
- **审计字段（§4.8 脱敏）**：`status`、`sourceSha256`（=SHA-256 完整 code，进 ApprovalBinding → 改 1 字符即失效）、`sourceBytes`、`inputBytes`、`inputSha256`、`outputBytes`、`outputSha256`、`limits{timeoutMs,memoryBytes,maxSourceBytes,maxInputBytes,maxOutputBytes}`、`isolated`——只 hash/size/limit，无 body；缺省 present-null。
- **已知时间/边界点（HXA-054 攻击与 E2E 注意）**：limits 为固定 `JsExecutionLimits.DEFAULTS`（wall 10 s / 堆 64 MiB / source 256 KiB / input 2 MiB / output 256 KiB），**模型无法经 args 调整**（schema 无 limits 参数），故"设小 deadline 触发 TIMEOUT"无法经工具参数做——TIMEOUT 映射在 JVM 层以 fake client 固定，设备层 TIMEOUT 需用会跑满 10 s wall 的真实代码触发；设备 JS_ERROR 用 `throw new Error(...)` 触发。QuickJS 单实例一次一执行，隔离进程回收异步（Binder death 为主信号）。
- **发现（范围外，已记录待跟进）**：`ToolScheduler` 的跨批 waiter 只监听本批 future——两个**并发**且互斥的**独立** `scheduleBatch` 会死锁（第二批 waiter 等自己的 future，而释放槽的是另一批的 future）。生产不变量下 turn 串行、批不重叠，故该缺陷潜伏、HXA-053 不触碰（修归框架后续）。S5 因此按生产 Act 模式（一次一调用、批内串行）验证真实后端的单并发串行，批内 lane 串行由 `:tools:framework` 调度器 JVM 测试覆盖。
- HXA-054 的 JS 攻击套件（`eval`/`Function`/包裹逃逸的 host 边界已在 HXA-052 固定 19 例）、代码编辑器 UI、limits 用户设置 UI 均不在本任务范围。
