# HXA-147 移动任务交互调研与实施范围

日期：2026-09-08。依据官方文档核对交互行为，不声称已经实际操作竞品；不复制第三方实现。下面的移动端取舍是 Helix 的设计判断。

## 官方参考与取舍

| 参考 | 文档可确认的行为 | Helix 的适用方式 |
| --- | --- | --- |
| [Claude Code Desktop](https://code.claude.com/docs/en/desktop) | 输入区可选择模型/权限模式，运行时可停止或补充指示；会话保存自己的上下文 | 当前模型、模式、运行状态和停止操作保持容易找到；不引入文档中云端/SSH执行或其权限模式 |
| [Cursor Agent](https://cursor.com/docs/agent/overview) | Agent 完成多步工作，任务中提供变更审阅和 checkpoint | 工具结果、完成证据与下一步操作贴近原任务；保留 Helix 的显式对账，不将 checkpoint 解释成可撤销任意手机副作用 |
| [Android Compose lists](https://developer.android.com/develop/ui/compose/lists) | Lazy 列表按可见区域布局，可保存滚动状态、使用稳定 item key 并控制滚动 | 根据用户是否正在跟随最新内容决定滚动；模型内容增长不能把正在阅读历史的用户拉走 |

## 当前问题与实施顺序

1. 首次使用说明含旧 ADR/FR 编号和“规则未来提供”的过时说法。改为当前可见功能与配置入口；区分单次发送确认和既有规则，保持原 Policy。
2. DisclosureDialog 的 text slot 原先并列发出明细 Column 和说明 Text。改为一个有间距的可滚动 Column，确认/取消按钮保持独立；长附件列表必须能滚动查看，说明和操作不能重叠。
3. 当前聊天 LazyColumn 没有绑定列表状态或内容跟随。新增明确的跟随最新内容/历史阅读状态，处理流式增长、终态替换、工具结果、打开会话与键盘变化；历史阅读保持原位置，回到底部为显式操作。
4. 长 Goal、Provider/模型标识占据主要视口。默认紧凑摘要，全文有可达入口，状态和主要动作不被挤掉；不得只裁掉用户需要辨认的目标或模型。
5. 统一会话/任务导航、模式和Provider设置、审批/停止/重试/暂停恢复、空状态与加载。优先消除同一状态使用不同动作或不同标签的歧义。

## 验收

每次改动先按实际影响验证，最终按 HXA-147 roadmap 汇总双发行包、API29/36、小屏、大字体、可访问性和中英文。滚动验收包括完整末行可见、用户上翻保持、显式回到底部、流式结束和会话切换。长确认内容应能逐项滚动查看且按钮始终独立可操作；`assertIsDisplayed` 仅证明部分可见时，另查节点边界和实际截图。

本调研不批准新的自动执行能力，不改变 ADR-0004/0012/0028 的 Continue、授权或完成证据语义。当前研究与第一组修改不代表 HXA-147 完成。
