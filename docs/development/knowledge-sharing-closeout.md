# 知识库管理与分享收尾

## 范围

Owner 授权完善知识库与分享已有闭环。沿用本机 Room、Compose、现有 Provider 和标准工具管线；不接入新云服务、不执行设备操作、不提交或推送。终端/Provider 之前的修复及独立 HTML 原型工作不属于本次变更。

## 实现

- 来源列表支持应用内选择文件导入，沿用既有接收、原件复制、大小限制和提取流程；不申请长期 URI 权限、不自动上传。最多八个文件，过量或无权限以失败状态报告。
- 来源详情和多选列表提供确认删除。先持久化 `DELETING`，再清理该来源私有目录，最后删除索引/记录；中断后的启动继续清理。文件清理失败不伪报成功。批量逐项执行，不能宣称事务式全部成功或全部回滚。已有笔记与问答保留固定引用。
- 笔记删除、生成和引用刷新共用原有 mutation 边界；运行中的生成和过时编辑快照不能被删除。笔记删除在事务中清理 FTS、引用关联和问答的 savedNoteId，保留问答本身，之后用户可明确再次保存问答为新笔记。
- 来源变化/缺失时显示固定引用已过时。用户确认后才替换引用；刷新核对笔记、旧引用及来源快照，正文保留、笔记回到草稿、生成建议清除。缺失或处理中来源拒绝刷新，不部分改写。
- 已保存笔记可经系统文件选择器导出 Markdown，包括保存状态、正文、固定引用片段、来源、接收时间和内容 hash；不导出未审阅生成建议。未保存编辑须先保存。该导出不是包含原件的整库备份，也没有声称支持自动还原。
- `knowledge.search` / `knowledge.read` 是成组只读工具，沿用 Dispatcher。独立用户开关默认关闭，执行前后重核，撤销或取消后不返回数据；工具/资料本身不能开启授权。搜索最多十六条、片段 512 字符；读取正文最多 12000 字符，返回 hash、截断、状态和笔记固定引用。不给原始路径、SQL 或任意 URI 入口，不返回未审阅生成建议。开启后，工具返回的资料会进入当前会话模型；不自动把全库注入提示词。
- Agent 文件分享、普通私有文件和绑定工作区分享采用独立运输副本，内容嗅探 MIME 来自副本，避免源内容变化造成类型/内容错位。工作区改为流式复制，保留原 32 MiB 上限；Agent 保留八文件、总 20 MiB 上限；普通私有文件仍有 512 MiB 上限。共用缓存总额 512 MiB，仅清理严格命名、超过一天的自有副本，不跟随符号链接，不淘汰年轻的已交接副本。取消/失败清理未交接副本。
- SAF 继续使用已有受控、最大 512 MiB 的平台复制适配，不为了统一缓存而额外复制一份大文件。root 特权读取边界不变。系统分享保留 ClipData 与临时只读 URI 授权；chooser 打开不表示其他 App 已读取、送达或入库。备忘录仍是用户选择目标的 handoff；没有 IMA/腾讯文档真实连接器，不放置伪保存入口。

## 明确边界

整库原件备份/还原、OCR、向量语义检索、同步账号与云端直存不在本轮实现内。跨 App 分享目标的实际读取、系统选择器交互、进程死亡时的 Room 恢复和真实模型消费需独立设备/服务验收；本轮不复用历史设备通过记录作为新实现通过证据。

## 针对性回归覆盖

本轮新增十五个 JVM 用例：知识库工具七项（关闭时拒绝、取消前拒绝、读取中撤权不交付、查询长度/额外参数、拒绝路径冒充 ID、删除项失败、正常搜索及 schema）；运输缓存六项（源修改后副本稳定、上限失败清理、不交接取消、过期清理不跟随符号链接、拒绝目录穿越、长显示名称不突破文件名限制）；Markdown 两项（固定来源/状态与排除生成建议、多行引用及无来源手写笔记）。既有文件管理测试加强为副本不随源改变。

四项 Room 回归已加入 AndroidTest：删除索引/引用而保留来源、过时删除不丢新编辑、显式引用刷新与缺失来源原子拒绝、删除已保存问答笔记后解除标记并允许用户再次保存。这里只列编译用例范围，不声称这些设备测试已经运行。
