## Shared workspace contract

Document-first and public placement are independent. Owner's final decision fixes knowledge, notes, imported originals and attachments to shared storage. There is no location-mode setting, sensitivity classifier or per-save privacy question. App-owned MediaStore Files under Documents avoids a first-use directory dialog. Credentials, Agent memory, conversations, historical evidence, approvals and execution facts remain private. Adopting existing external documents or a whole folder uses existing SAF and persisted grant verification only when needed. Public placement does not grant Agent access or upload permission. Never derive a POSIX path from a URI or request all-files permission. A failed shared save must not silently retarget to a private content store.

Open content remains externally editable. Reads recheck live access and content; writes require the previously observed content hash and preserve conflicting content. Renames and deletion must be reflected by catalog rebuild. MediaStore replacement stages a pending row, verifies bytes and persists a private publication receipt before exposing the new row and removing an unchanged prior row. Recovery reconciles that original operation; changed content is retained rather than overwritten. Neither MediaStore nor SAF promises cross-app compare-and-swap or filesystem-level replacement atomicity. Private staging/receipts are operational state, not a second content authority. Shared paths are under `Documents/Helix/library/` with no package subdirectory. Queries still require the current OS owner package; a common directory does not authorize taking over another channel's files. Reinstall does not confer ownership of previous rows; no automatic old-database import or file adoption.

## Platform evidence

[Android shared document access](https://developer.android.com/training/data-storage/shared/documents-files): the picker grants a selected URI tree without broad storage permissions; persisted access can be lost after move/deletion, and provider flags determine supported operations. [MediaStore](https://developer.android.com/training/data-storage/shared/media) supports app-owned shared output without adopting arbitrary existing documents. Neither URI is universally a POSIX path. Public storage is not an absolute confidentiality guarantee, and uninstall/reinstall does not imply ownership of previous MediaStore rows.

## Plan content and approval evidence

The Room `plans` row retains the title index, exact content revision/hash, state and approval evidence; `plan_steps` and duplicate editable body columns are removed. Unapproved content changed or deleted outside the repository cannot be silently approved. Approval reads and verifies the identified content, then records its immutable canonical snapshot in the same transaction as the review state/audit. Failed/rolled-back plan insertion may leave an unapproved document; it never mints execution eligibility. Reconciliation can accept only that exact ID/body, not a changed orphan. Referenced plan deletion refuses before deleting its content.

## Bounded delivery audit

| Content | Implemented location / authority | Remaining boundary |
| --- | --- | --- |
| Knowledge and notes | Shared `Documents/Helix/library/notes/<id>.md`; Markdown body plus current metadata comment | No old Room reader/import; no automatic old-library adoption |
| Collected material | Shared `library/sources/<id>.md`, keeping raw text, extracted text, summary and processing state distinct | File projection is bounded; not a large-catalog performance guarantee |
| Imported originals and material attachments | Shared `library/originals/<source-id>/`, original bytes/type, referenced from source metadata | This does not publish private conversation attachment staging/history |
| Conflicting pending saves | Private publication receipts; explicit recovery saves a new shared note and retains proposed file in shared `library/recovered/` | Dismiss does not save, overwrite or delete |
| Agent memory | Existing private `files/memory/` Markdown, unchanged authority | Content-selection experiment is independent of storage; no new strategy claimed |
| Plan proposals | Private `<content-store-name>-plans/plans/<id>.json` | Room retains hash/revision, immutable approved content and execution/approval facts; no mutable duplicate proposal body |
| Conversation/attachment evidence and answer provenance | Existing private session/content storage; private `agent-library-history/library/answers/` and `origins/` documents | These are private Agent history, not ordinary shared source material |
| Ordinary workspace output | Original file in the existing authorized native/SAF workspace; DB registers reference/hash | No forced ZIP, transfer, new copy authority or automatic upload |

Two distinct recovery capabilities must not be conflated. **Existing SAF workspace reauthorization is implemented**: the Files picker preserves OS flags, `AppFileServices` persists only a real system grant, and `FilesScreenActions.grantTree` refreshes the same opaque scope. Revocation/provider/root mismatch fails closed. A fresh bounded JVM test proves revoke → explicit regrant → registry reopen restores only the same selected scope; resolver/service suites passed 18 tests. This is a controlled grant seam, not actual OS-picker acceptance or a newly minted permission. No new system authorization or device operation was performed.

**Explicit old-library restore is implemented** in the Knowledge more menu. The user chooses the old `library` folder once. `LibraryRestoreTree` only reads that selected tree using the actual OS-granted result; it never persists or manufactures permission. `KnowledgeLibraryRestore` validates current-format Markdown identities, bounded content and original attachments before publication. It imports into the current package-owned shared namespace, preserves logical note/source IDs and frozen source links, rebinds original-file references, and rebuilds the current catalog/search. It does not change the selected source, link a second live backend, import a Room database/private history, or enable Agent access. The UI explicitly says the original stays unchanged and is not synchronized. This is a one-time import, not takeover of another MediaStore owner's rows.

Identical already-restored content is reused; conflicting IDs/bytes are never overwritten. Missing attachments, malformed/empty selections, revoked access, changed input and storage failure do not return success. Partial publication retains the verified files and reports incomplete; explicit retry verifies/reuses the same content rather than deleting or duplicating it. Unfinished extraction/deletion states become incomplete content, never automatic resumed effects. Cancellation is checked before publication steps. Existing per-file publication receipts remain the recovery mechanism; no parallel migration system was added. Imports are bounded to 1024 entries/64 MiB observed bytes, 16 MiB per original, and the existing 4 MiB text/32 MiB catalog constraints. Normal new-library saves still require no picker. No actual old library, reinstall or new permanent OS grant was touched.

## Shared metadata is not workflow authority

The follow-up security review found that `KnowledgeService.recovery` treated editable shared source states as instructions: DELETING could resume deletion, and QUEUED/EXTRACTING could resume extraction at startup. This path is removed. Startup now marks unfinished work INCOMPLETE without fetching or deleting; the user explicitly retries or deletes. Original content is retained. Storage failure remains visible, and explicit startup retry only refreshes/normalizes state. Private publication receipts retain their existing recovery role; no new workflow framework or compatibility reader was added.

Explicit extraction retry verifies the current document hash against the selected snapshot. Original reads/opening/extraction must resolve within that source's own original directory. A cross-source reference cannot borrow another source's files. Fresh capture eligibility comes from the current private import result, never an editable shared QUEUED flag. Duplicate reuse verifies the incoming text/URL and actual attachment bytes; changed shared fingerprints/targets cannot discard or retarget a new user import. These checks do not grant Agent permissions or automatically upload content.
