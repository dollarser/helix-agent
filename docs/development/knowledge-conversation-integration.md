# 知识库与会话引用接入

日期：2026-10-25。范围是 Owner 已评审原型的 Android 接入；不改变 v0.0.7 发布，不引入新的聊天引擎、同步、向量服务或 OCR。

本文记录 2026-10-25/26 的实现与验收。当前引用已采用按需读取元数据契约，内部库版本固定为 1；不得从下文历史 FULL/EXCERPT 或迁移过程恢复旧实现。现行规则见 [知识库 ADR](../adr/workspace/007-local-knowledge.md)，当前能力见 [status](status.md)。

## 实现边界（当时）

- 知识、笔记、资料是内容类别；新问答使用现有会话，旧资料问答仅保留只读记录和显式保存。`KnowledgeNote.kind` 与保存/核对/模型生成状态分离，既有笔记保留内容与核对状态，默认 NOTE。
- 新建笔记先在可恢复编辑器中编辑，显式保存才入库；放弃不创建空记录。已保存笔记可整理为可编辑知识候选，取消不入库，保存创建独立未核对知识，保留原笔记和冻结来源。这不是自动模型总结，未新增模型调用。
- `KnowledgeReferenceService` 提供有界选择和版本核查；UI 不直接读 DAO。输入框沿用现有会话工具栏、＋菜单、模型/语音/发送，知识引用与会话引用分别可发现。阅读页通过应用命令写入原会话草稿，不自动发送，不改权限或 Agent 知识库开关。
- `KnowledgeReference` 固定类型、身份、正文摘要、实际文本、范围、完整性和显式保留版本状态。FULL 是实际全文，EXCERPT 是开头最多 1800 字符；八条、总正文 24000 字符上限，不是 token 保证，也不是任意文本选区。超限拒绝，不把关联原件递归发送。
- 草稿、发送确认与接受后的队列都复用既有 `ChatSubmission`/`SessionInput`。发送前和确认时检查变化；已接受输入交付固定快照，不以原文变化修改它。敏感文本确认和凭据检查沿用原入口。模型正文用明确不可信区块，不授予工具权限。
- 消息历史从已消费输入获取固定引用，原资料更新或删除不改历史。手动编辑仅修改用户正文，保留引用，不自动重发或建分支；本条引用发送后仍可能被后续会话历史使用，不承诺自动遗忘。

## 数据与删除旧路径

主库 v1→v2 增加输入引用 JSON；资料库 v2→v3 增加类别、原笔记快照及回答来源身份。使用 Room 加法迁移，不清聊天、账号或资料。精确的已发布 v1 身份通过现有启动检查后迁移；其他未知预览仍需原有显式确认，不能自动重置。

测试改为共享 `core/storage/src/androidTest/assets/` 的权威导出，删除 App 内独立的旧 schema 副本，避免错误地把历史同版本号 schema 当作已发布迁移基线。不保留旧字符串拼接式知识引用入口。

## 前序：知识库管理与分享收尾

本页保留知识库/分享初版与后续收尾证据；正文中“不在本轮”的备份、检索等并非当前产品限制。现行内容权威与能力见 [知识库 ADR](../adr/workspace/007-local-knowledge.md) 和 [备份 ADR](../adr/workspace/008-content-backup.md)。

### 范围

Owner 授权完善知识库与分享已有闭环。沿用本机 Room、Compose、现有 Provider 和标准工具管线；不接入新云服务、不执行设备操作、不提交或推送。终端/Provider 之前的修复及独立 HTML 原型工作不属于本次变更。

### 实现

- 来源列表支持应用内选择文件导入，沿用既有接收、原件复制、大小限制和提取流程；不申请长期 URI 权限、不自动上传。最多八个文件，过量或无权限以失败状态报告。
- 来源详情和多选列表提供确认删除。先持久化 `DELETING`，再清理该来源私有目录，最后删除索引/记录；中断后的启动继续清理。文件清理失败不伪报成功。批量逐项执行，不能宣称事务式全部成功或全部回滚。已有笔记与问答保留固定引用。
- 笔记删除、生成和引用刷新共用原有 mutation 边界；运行中的生成和过时编辑快照不能被删除。笔记删除在事务中清理 FTS、引用关联和问答的 savedNoteId，保留问答本身，之后用户可明确再次保存问答为新笔记。
- 来源变化/缺失时显示固定引用已过时。用户确认后才替换引用；刷新核对笔记、旧引用及来源快照，正文保留、笔记回到草稿、生成建议清除。缺失或处理中来源拒绝刷新，不部分改写。
- 已保存笔记可经系统文件选择器导出 Markdown，包括保存状态、正文、固定引用片段、来源、接收时间和内容 hash；不导出未审阅生成建议。未保存编辑须先保存。该导出不是包含原件的整库备份，也没有声称支持自动还原。
- `knowledge_search` / `knowledge_read` 是成组只读工具，沿用 Dispatcher。独立用户开关默认关闭，执行前后重核，撤销或取消后不返回数据；工具/资料本身不能开启授权。搜索最多十六条、片段 512 字符；读取正文最多 12000 字符，返回 hash、截断、状态和笔记固定引用。不给原始路径、SQL 或任意 URI 入口，不返回未审阅生成建议。开启后，工具返回的资料会进入当前会话模型；不自动把全库注入提示词。
- Agent 文件分享、普通私有文件和绑定工作区分享采用独立运输副本，内容嗅探 MIME 来自副本，避免源内容变化造成类型/内容错位。工作区改为流式复制，保留原 32 MiB 上限；Agent 保留八文件、总 20 MiB 上限；普通私有文件仍有 512 MiB 上限。共用缓存总额 512 MiB，仅清理严格命名、超过一天的自有副本，不跟随符号链接，不淘汰年轻的已交接副本。取消/失败清理未交接副本。
- SAF 继续使用已有受控、最大 512 MiB 的平台复制适配，不为了统一缓存而额外复制一份大文件。root 特权读取边界不变。系统分享保留 ClipData 与临时只读 URI 授权；chooser 打开不表示其他 App 已读取、送达或入库。备忘录仍是用户选择目标的 handoff；没有 IMA/腾讯文档真实连接器，不放置伪保存入口。
