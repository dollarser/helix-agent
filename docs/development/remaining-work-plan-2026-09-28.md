## 1. 判断与依据

当前重点应从架构扩张转向“安装后能完成任务、失败后能恢复、结果和数据可解释”。Core Engine、Workspace、Activity presentation 与 Eval 已有交付，不重新拆引擎或重做 UI IA。降低配置门槛不等于把产品改成全民助手；继续服务开发者与 Android 效率用户，允许不懂模型格式的用户完成基础任务。

本轮核对 README、status、roadmap、全部开放任务、相关 ADR 与完成记录，未进行全产品逐行代码审计。以下“待核查”是验收/产品覆盖问题，不能直接宣称实现缺失或已有缺陷。

截至本快照，`tasks/` 中正式开放的 HXA 有 **7 项**：120、121、122、123、125、126、190。前三项外部服务工作（125/126/190）和四项发行工作（120/122/121/123）之外，还有已交付功能的剩余边界、新提出的产品化需求和未排期候选；它们不是零剩余工作，也不能混计为全部必须完成才能使用。

依据入口：[产品需求](../product/requirements.md)、[产品策略假设](../product/market-users-and-commercialization.md)、[公共验收规则](verification-matrix.md)、[完成记录索引](../completion-records/index.md)。外部政策、下载服务接口和模型版本在实际实施时重新核验，本计划不构成当日渠道合规结论。

## 3. 本地模型产品化

### 3.1 模型下载与安装

现状：HXA-222 有 direct HTTPS URL、SHA-256、大小手工输入与资产管理；没有 ModelScope/HF 模型目录或完整一键安装体验。当前 Android HTTP 下载端到端未验，真实权重实测采用 host 下载和 ADB 注入。见[交付边界](../completion-records/HXA-222.md)。

建议首版范围：

- 内置小规模、明确版本的精选清单，列出任务适用性、量化、下载大小、预计运行内存、来源/许可证和实测范围；0.6B/1.7B 当前失败不能标为“Agent 推荐”，4B 一次通过也不能标为普遍可靠。
- 用户选择 ModelScope/HF 来源；自动解析精确文件、版本、大小与校验信息。跨源切换只复用相同资产身份，不能把同名文件当相同内容。首版聚焦公开、单文件、兼容 GGUF；登录受限仓库、多分片和任意模型格式另行评估。
- 产品主流程为“下载并配置”：空间预检、进度、暂停/取消/续传、断网重试、校验、原子发布、自动登记 Provider、加载和真实能力测试。网络重定向/临时地址/来源元数据需按服务协议设计，不直接放开任意重定向。
- 配置完成后明确显示“用于当前会话”；不悄悄切换其他会话或全局模型。自动能力测试包含在用户可见的安装动作中，失败保留已验证权重并给出重试/卸载入口。
- 空间需求说明包含临时下载与发布额外占用；存储不足不能通过删用户文件解决。下载中离开页面、应用重开、重复点击与残片清理要有明确行为，不仅是一个进度条。
- 手填 URL/hash 表单保留为高级导入。安装失败尽量保留草稿与已下载内容，不阻断手动文件管理或其他可用 Provider。

验收重点：至少一条真实 Android HTTP 下载→配置→真实任务；另以受控服务覆盖 Range 被忽略、错位区间、hash 不符、断网/取消、空间不足、重复安装和进程恢复。测试结果分别标记真实来源与注入失败，不把一种当成另一种。

### 3.2 性能、资源与模型质量

现有参考：4B Q4_K_M 约 2.50 GB 文件，API36/8 GiB 模拟器/CPU 2 threads/8K 时采样 PSS 约 3.58 GiB，固定任务约 14 分 46 秒。0.66 token/s 是包含输入处理的有效输出速率，尚无独立 decode 指标，不能据此下手机性能结论。

- 先记录 load、prefill tokens/time、decode tokens/time、首响应、每轮总耗时、PSS/RSS、取消至 executor exit；区分冷/热加载、上下文长度与运行设备。
- 检查重复历史处理、KV/prefix 复用机会、线程/batch 与输出缓冲的真实成本；有瓶颈证据后逐项优化，复用必须绑定正确模型、模板和上下文，不能引入跨会话历史污染。
- 用户可见进度与真实状态先完善；逐 token 输出作为测量后的独立切片，不能为了“快一点显示”执行未完成的 ToolCall。
- 将单一 CSV 题扩为少量固定用例：中文指令、文件修改、多步工具、失败纠正、停止、长上下文；固定数据与独立 oracle，记录失败，不无限重试直到成功。
- 模型/量化/采样候选用同任务对照；推荐配置同时考虑完成率、延迟和内存。OOM 可建议较短上下文或其他模型，由用户明确选择，不自动把私密请求切到远端。
- 真机温升、持续负载、后台/锁屏和 OEM 内存行为在获授权后单列；不把模拟器结果当成默认手机最低配置。GPU/NPU 先调研实际收益和兼容成本，暂不列为首版必做。

发行前还应准备三件容易遗漏的事：

1. **数据承诺**：开发期 v1 重建何时结束、正式版保留哪些数据、失败升级如何恢复；账户凭据与普通备份分别处理。不能把会话 JSONL 导出宣称为全量可恢复备份。
2. **支持流程**：已知限制、错误反馈模板、用户可主动提供的脱敏诊断、模型来源/许可证说明、版本与问题定位。模型权重不入 APK 不代表无需核对推荐分发的许可证条件。
3. **真实用户试用**：围绕少量文件/网页/代码任务，观察独立完成率、配置步骤、失败恢复、延迟和理解成本；先小范围、主动反馈，不默认建设生产遥测或引入支付/会员系统。将可量化目标写入对应任务后再实施。
