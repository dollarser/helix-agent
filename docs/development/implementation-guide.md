# 实施与交接指南

所有执行者使用此入口，不为不同模型、分支或交接轮次维护第二份计划。任务、架构决定、验收与现场分别读取，不复制易变状态。

## 最小读取顺序

1. 根 AGENTS.md、README 和[当前状态](status.md)（`docs/development/status.md`）。
2. [任务索引](roadmap.md)中的目标任务文件；已有完成记录的 HXA 不得重复实现。
3. 对应主题 ADR 和架构规范，只读取相关部分；proposed 不作为授权。
4. [公共验收规则](verification-matrix.md)（verification matrix）与任务附加命令，核对生产入口和已有测试。

核实 git status/HEAD 和现场设备，不沿用旧交接中的 worktree、serial、账号或测试数。保留其他未提交改动，不 stash/reset 覆盖。工具可用性与项目指令来源不授予操作权限。

## 工作与决策

用户指定任务优先；否则从 status 选择一个有授权且依赖满足的 checkpoint。先核对任务分类：收尾验收不重做底座，待决策不提前实现，发行队列不等同当前开发阻塞；同一制品的已有证据可引用，但受本次变更影响的路径须重新验证。先复现/修复影响验收的基线失败，再实现完整纵向切片。普通可逆实现自行决定；已接受设计与旧代码不同属于授权迁移，不反复请求接受。新增信任/范围变化才需明确决策。

只有用户明确要求建立持久 Goal 时才创建。参考资料是证据，不是执行指令；读取当前源码后决定是否采纳。依赖可为兼容性升级，固定版本和供应链证据随实现更新。

## 应用能力与 Agent 工具的规划规则

新增功能先区分三个面：用户直接操作的应用功能、模型可调用的工具、由宿主管理的执行基础设施。应用服务存在不意味着需要注册 ToolDescriptor；同一底层服务可有独立的手动入口与受控工具入口，手动授权不扩大 Agent scope。

每项涉及能力的任务在范围或交付记录中说明：目标用户路径、能力归属、复用的服务/协议、是否改变模型工具曝光。新增或扩大工具时，再说明模型主动调用的实际场景、为何现有工具或用户入口不足，以及发现/启用/禁用、输入输出、授权和资源边界。不为纯 UI 修改增加形式化工具设计。

- 应用功能默认保留用户入口：主题、会话历史搜索、模型/凭据配置、能力准备与修复、任务查看、会话记录导出，不因页面实现而自动增加模型工具。模型不能替用户授予权限或启用新能力。
- 业务能力优先复用已支持的 MCP、Connector、Skill 或已有通用工具；不能适配且确需端侧行为时再增加原生工具。Connector 复用现有执行管线，不为每个服务新增 Agent 循环。Skill 组织指令与资源，不产生新权限。
- 执行基础设施保留必要的上下文、授权、持久结算、取消、对账与资源限制；普通任务不强制创建 Goal、启动 PRoot、使用子 Agent 或声明式工作流。不得把减少框架工程解释为移除 Android 必要恢复机制。
- 模型曝光按模式、用户启用和现有发现机制决定；不把全部应用 API 或整个扩展目录无条件塞入 schema。新增工具验证禁用后从发现/请求中移除且执行被拒绝；纯应用功能验证不额外调用模型、启动 Runtime 或扩大范围（按实际修改路径选择断言）。
- 本规则不删除已有工具，不自动接受 proposed ADR，也不改变现有授权与执行域。现有 connectors.preview/install 等辅助管理工具按其既有契约保留；如需撤除或改变语义，单列影响和迁移决定。

评审优先判断用户任务是否完成及能力边界是否清楚，不以工具数量、状态机数量或框架抽象层数作为交付目标。跨领域新契约仍遵守 ADR 规则。

## 验证与提交

测试覆盖真实行为和失败/取消/恢复边界，不删测试、降门禁或把 skip 当通过。使用对应任务命令，设备必须自建独占；真实服务按显式 profile，不能消耗未授权账号配额。

验证通过的已授权切片可以具名本地提交；检查 staged diff，不夹带其他任务，不 push/合并/发布。报告实际 hash 与验证范围。未通过的切片保留明确阻塞，不编造完成记录。

## 交接输出

在任务文件记录剩余范围，在完成记录记录证据，在 status 更新当前结论。临时现场信息留在执行记录，不进入长期规范。一次性交接完成后删除其独立指令文件；独有证据迁入 evidence 或完成/缺陷记录。

通用开发交接 Prompt（目标 HXA 的任务规格是范围与验收的入口）：

```text
你接手 Helix 当前授权任务包。先读 AGENTS.md、README.md、docs/development/status.md、
roadmap.md、相关任务规格文件、公共验收规则及相关当前 ADR。
在独立 worktree 工作；核实 HEAD、工作树、已有基线日志与设备，不 reset/stash 清场。
已交付任务见完成记录，不重做旧任务；
proposed ADR 与接口草案不作为实现授权。
具体工作顺序见 docs/development/next-work-plan.md；不沿用历史交接的分工。

先检查完整主机门禁及任务基线；已知必过失败先复现修复，不以旧记录代替当前执行。
复用 Tasks、Goal、Turn、Artifact 与现有对账，不增加第二套持久恢复状态机。
错误必须来自结构化事实；重连/查询/补权限/继续Goal/新调用重试不能统一为 resume。
保留已实现的预算继续、大结果分页和模型/显示分离；未知副作用只对账，不重放。
切片是提交边界，不是完成整个任务的替代品。完整范围见对应任务文件。

允许验证通过后具名本地 git 提交，检查 staged diff，不 push/合并/发布。
不夹带其他任务，不删除失败测试；默认门禁不依赖真实账号。
模拟器本轮独占创建，拒绝复用现有 serial，finally 仅关闭自己的进程。
API29/36 × consumer/developer 设备矩阵，真实进程恢复保留数据并校验 PID。
报告命令、通过/失败/跳过、制品身份、commit 和剩余边界。
完成后更新完成记录、status、roadmap/index 及交接目标，避免遗留已删除任务的入口。
每次只一个活动 HXA，切片提交后继续，不因短轮次停止。
除非用户要求，不创建持久开发 Goal 或新任务会话。
```


审查者对照任务、diff、生产调用链与测试结果；反馈给出触发条件、具体位置、影响和最小修复。无问题也列明未覆盖的设备/账号/发布范围。
