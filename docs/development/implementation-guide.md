# 实施与交接指南

统一执行入口；工作范围、长期决定、验证证据与现场分别读取，不为不同模型或交接轮次维护第二份计划。

## 最小读取顺序

1. 读取根及适用目录的 [AGENTS.md](../../AGENTS.md)、README 产品摘要和[当前状态](status.md)（`docs/development/status.md`）的当前工作/下一步。
2. 用户已指定任务时直接读对应 HXA 或请求；只有需要定位时才查[任务索引](roadmap.md)。已有完成记录的 HXA 不得重复实现；纯文档整理不新建 HXA。
3. 按领域读有效 ADR 的相关正文及变更来源、必要架构章节，区分 accepted 范围与 proposed 设计。
4. 代码结构复用 [CodeGraph 导航](context-navigation.md)，已知小修改直接读当前源码；查调用方、共享状态及相关测试，确定[公共验收](verification-matrix.md)（verification matrix）与任务附加门禁。

核实 HEAD/工作树和用户提供的现场结果，不继承旧 worktree、serial、账号或测试数；保护并行修改，不 reset/stash 清场。图查询和文档都是线索，不能替代当前源码、契约或操作授权。

跨会话接续或复盘时，先按项目与主题定位相关用户消息，再读完成记录和必要工具证据；会话摘要只用于导航。分别记录明确偏好、当前任务授权、助手建议和已执行事实，并以当前源码/有效 ADR 排除过时结论。用户在同一仍持续的任务中已给出的授权不重复询问；独立新任务不自动继承旧设备、账号或发布许可。本地检索索引与历史摘记放 `docs/local/`，长期指南只吸收可复用结论。

## 工作与决策

用户指定任务优先；否则从 status 选择已授权且依赖满足的工作。区分实现、收尾验证、待裁决和发行输入，已有证据仅在相同基线/未受改动影响时适用。强制门禁失败与相关用户报告缺陷需复现修复，不能以旧绿色代替当前验证。

普通可逆实现自行完成，已接受设计与旧代码不同属于授权迁移；新增信任/范围变化才需明确决定。切片须形成完整纵向交付，不能以单测或一个子步骤完成替代整个请求。只有用户明确要求建立持久 Goal 时才创建。

功能/重构取舍与停止条件看[开发策略](feature-refactor-strategy.md)，技术卡看[Harness](../architecture/harness-refactor-plan.md)，发行依赖看[就绪条件](release-readiness.md)。依赖升级若为兼容/维护必需，仍固定版本并更新供应链证据。

## 应用能力与 Agent 工具的规划规则

先区分用户直接操作、模型工具、宿主执行基础设施。应用服务不自动变成 ToolDescriptor；同一服务可以同时有手动入口与受控工具入口，手动授权不扩大模型 scope。

涉及新增能力时说明用户路径、领域归属、复用服务/协议和是否改变模型曝光。新增工具还需说明模型调用场景、现有能力为何不足、发现/启停、输入输出、权限和资源边界；纯文案/UI 修改不强加一份工具设计。

| 类型 | 保留原则 |
| --- | --- |
| 手动应用功能 | 主题、历史、模型/凭据、组件准备、任务查看、导出保留用户入口，不因页面存在就新增模型工具 |
| 业务能力 | 优先复用 MCP/Connector/Skill/通用工具；确需平台行为再增原生工具，不能为每服务造 Loop；Skill 不授予权限 |
| 执行基础设施 | 保留上下文、授权、持久结算、取消、对账和资源限制；普通任务不强制 Goal、PRoot、子 Agent 或 Workflow |
| 工具曝光 | 模式/用户启用/发现决定曝光，不塞入所有 API；禁用后发现与调用都不可达，来源描述不授权 |

已有 connectors.preview/install 等工具沿当前契约；撤除或改语义需明确影响。评审以用户结果和边界为准，不按工具数、状态机数或层数验收。

## 验证与提交

验证范围取自当前请求/HXA 和公共规则，先定向后完整适用门禁。**文档改动跑文档、链接和语义一致性检查，不默认编译双渠道 APK；代码交付按对应任务执行源检查、JVM/静态分析、APK/测试 APK 等必要门禁。** 这不是放宽既定强制检查或删除失败测试。

GitHub CI 始终 host-only。模拟器、真机和真实服务各需当前明确授权；未要求记 `not requested`，已要求但未完成记 `pending`，通过/失败只来自实际运行。编译测试 APK 不等于设备通过；被要求的设备验收未完成时不得宣布对应 acceptance 完成，独立主机结果可以如实交付。

提交、推送、合并和发布分别核对当前授权；具名提交前检查 staged diff，不夹带其他任务。实现/文档授权不自动包含 Git 操作。报告真实代码/制品身份，保留失败、跳过、未知和未覆盖条件。

涉及制品的收尾先确认成功构建及实际安装对象，再核对被要求的用户旅程。结果按“执行事实、独立效果、持久记录、实际消费”分开；模型声称完成或工具返回成功不能代替文件内容、目标应用状态或下一请求结果。复用证据时说明哪些输入与制品仍相同；失败构建遗留 APK 不计作新候选通过。具体诊断与现有汇总工具见[调试手册](debugging-playbook.md)。

## 按需复用的工作流与 Skill 候选

以下是可提炼的两个入口，当前由本指南和既有脚本承接；本轮没有新建 `.agents/skills/`。它们不增加任务、验收矩阵或操作权限。只有重复使用证明独立 Skill 能减少漏项时，才将短入口提炼到项目技能目录，并链接此处的权威流程。

| 候选 | 触发与最小输入 | 执行步骤 | 停止条件与输出 |
| --- | --- | --- | --- |
| `helix-acceptance-closeout` | 用户要求候选收尾或检查证据是否充分；输入当前 HXA/请求、改动归属、候选与适用验证授权 | 核对成功构建和来源 → 确认实际候选 → 复用已有 runner/解析器处理获准验证 → 核对实际效果与消费 → 清理本任务资源 | 来源不明或构建失败时停止候选验收并保留 INVALID；条件不足按 not requested/pending/failed 区分。输出写入既有 evidence 与 `build/<task>/`，列出实际范围和剩余边界 |
| `helix-contract-change-review` | 身份、授权、生命周期、路径、结果或插件贡献契约发生变化；输入目标、适用 ADR、差异和生产入口 | 找事实 owner → 查询现有代码图/源码 → 追踪持久化、恢复、控制、UI、模型结果及 fixture 的共同假设 → 明确替换/删除对象 → 选择跨边界反例 | 关键语义未裁决或缺真实消费者时说明具体缺口，完成可独立检查部分；不为假想需求搭框架。输出为现有 ADR/HXA 的具体修订建议和证据位置 |

脚本承担确定性工作：APK/输入指纹、方法身份与终态解析、统计和资源归属检查，复用 `build-release-apks.sh`、`run-owned-emulator.py`、`instrumentation_junit.py`、`summarize-owned-runs.py` 等现有入口。设计判断包括证据是否适用、正确性是否改变、何时扩大范围、何时停止。不要把这些判断改成机械总数或固定重试次数，也不要让 Skill 自动取得设备、账号、删库、提交或发布权限。删除与运行环境故障按调试手册逐项诊断，不封装成通用“一键修复/清理”。

## 交接输出

范围/剩余工作留在任务，当前结论在 status，结果在完成记录/evidence。临时执行现场不进入长期规范；不为每个模型维护一份 handoff。通用交接只需：

```text
当前目标、授权与明确不做的范围：
起始 HEAD / 工作树改动归属 / 当前相关文件：
有效契约、变更理由、必要调用链与测试入口：
已完成入口切换 / 旧路径删除 / 仍未完成或受阻部分：
保留的机制、改变的策略、模型实际收到的结果与不确定性：
实际验证命令、源码/制品身份、通过/失败/跳过及证据位置：
设备/模型/账号状态与下一步必要输入：
当前仍在运行的本任务 Job（实际查询，无则说明）：
```

接手者按最小读取顺序核对持续任务的有效授权与新增范围，不因换会话重复询问同一授权，也不将历史独立任务的许可当作当前许可；保护原执行身份、实际适用的预算和 UNKNOWN，不把重连/查询/授权/新调用都称为 resume。多个无重叠切片仅在归属和共享契约清楚时并行。

审查者从实际 diff、生产调用链与测试核验，指出触发条件、位置、影响和最小修复；即使未发现问题，也说明设备、账号、模型和发布的未覆盖范围。
