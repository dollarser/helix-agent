# HXA-214：发送回执、草稿保留与停止一致性

分类：进行中（P0，所有者已授权核心切片）。核心实现、验证与剩余 UI 接线见[交接说明](../hxa-214-core-handoff.md)；本任务尚未关闭。前置：现有会话/Turn/取消基线通过；不依赖 HXA-215/216/217。设计方向见 proposed [ADR-AGENT-008](../../adr/agent/008-user-input-delivery.md)，本任务只修复既有行为，不启用新队列或改变 Goal 新输入契约。

## 问题与用户结果

发送准入失败后草稿仍在；异步回执不能清掉新输入或其他会话内容。运行时允许准备下一条草稿；显式停止在聊天和 Tasks 呈现相同“取消中→真实结算结果”，过期按钮不误停新任务。

## 允许模块与边界

`app/chat`、`app/ui`、对应资源及测试；仅必要时调整 `core/agent` 的 submit/cancel 结果契约与 `core/storage` 的既有幂等/取消持久接口。复用现有 clientRequestId、turnGate、取消/恢复和草稿存储；不新增 Agent Tool、工作流、Provider 协议、队列表或 Goal 行为迁移。

不得将“运行中可编辑草稿”写成“运行中可发送”。216 交付前仍明确限制发送，保留停止按钮；不能让新 send 跳过 busy gate。所有新用户文案 base/en/zh-rCN 同步。

## 实施切片

1. **回执**：send 返回明确 Accepted / PendingConfirmation / Rejected，捕获 session、revision、clientRequestId 和附件快照。只有持久接收后清空同版本输入。重复点击同意图去重；不通过服务内临时字段代替 UI 回执。
2. **草稿**：按会话保留输入，确认取消/Provider 不可用/忙/校验错误可继续编辑。前台切会话、旋转及进程重建不清掉已承诺保存的稿；密码/token 不额外落到诊断日志。
3. **停止**：聊天、Tasks 与 AgentRuntime.cancel 收敛到稳定 Turn ID 取消入口。CANCELLING 先持久化再发信号；工具等待/执行取消保持逐调用结算，未知副作用不写成成功取消。保留 Goal 显式停止解除续跑、独立 Job/PTY 所有权语义。
4. **收口**：loopback 与实际 UI/进程恢复验证，清理重复取消分支；不顺带开始216。

## 范围与验收要求

完整产品验收须包含 `ChatSubmissionReceiptDeviceTest`、`ConversationStopConsistencyDeviceTest`、`ConversationDraftRecoveryDeviceTest`。核心切片先在已有附件 fixture 中验证回执，新增第三类验证存储关闭重开；前两类与普通应用恢复旅程仍待实现，不可报零用例通过。

- Provider 不可用、无模型、出网拒绝/取消、输入非法、会话忙分别保留正确稿；确认后只发一次。
- A 会话发出异步请求后切 B；旧回执不得清 B。用户修改同一草稿后旧回执不得清新版。
- UI 连点、旋转、返回重开；运行中输入可编辑，尚不承诺自动交付。
- 聊天/Tasks 对同一目标取消结果一致；重复停止、旧 Turn ID、结束与停止竞态、审批/工具批取消。
- 普通应用真实主进程死亡：草稿重建、已接收消息不重复、取消意图可对账且不重放工具。Room close/reopen 仅算存储测试。

修改 storage 时追加 `:core:storage:testDebugUnitTest :core:storage:assembleDebugAndroidTest`，scope214 执行相应设备/迁移类；不为本任务无故做 schema 迁移。验收边界遵守[公共规则](../verification-matrix.md)。
