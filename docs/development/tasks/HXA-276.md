日期：2026-10-11；更新：2026-10-12。状态：已交付，主机与授权 API36 双渠道有界验收 passed。优先级：P2。依赖：HXA-272、HXA-274；HXA-275 为推荐前序，非 Browser 执行器前置。

Owner request：2026-10-12 继续完成剩余工作，允许模拟器、既有真实模型与分阶段本地提交；按单一合理目标实现设计，不兼容旧版。当前顺序由 [status](../status.md) 维护。

共同设计基线：直接替换所涉旧入口，不做旧版本、旧数据库、旧会话或旧批准迁移，不保留双写/双注册和兼容 adapter。开发期存储沿用现行 baseline 规则；历史证据保留原含义。原执行身份、权限、取消结算和渠道边界继续有效。

## 当前代码与缺口

[BrowserTools](../../../tools/browser/src/main/kotlin/com/helix/tools/browser/BrowserTools.kt) 原本经 ToolVisionServices 从 [DefaultAppContainer](../../../app/src/main/kotlin/com/helix/app/DefaultAppContainer.kt) 注册 12 个内置工具；[BrowserController](../../../feature/browser/src/main/kotlin/com/helix/feature/browser/BrowserController.kt) 已有标签与 Activity-owned WebView 生命周期。此卡只改变贡献归属、内容和会话选择，执行与视觉能力复用当前实现。

## 范围与验收要求

1. 建立宿主已知的 Browser native contribution，目标模块 `:extensions:browser` 保存 manifest、工具贡献和网页任务 Skill；App composition root 注入现有 BrowserToolBridge 与 ToolVisualPreparation。插件不持有 Activity/WebView，不创建独立浏览器 server。
2. 将 12 个工具统一生成为 `ToolBinding` 并使用 Browser 的 `PluginOrigin`；替换直接 `BrowserTools.registerAll` 的 built-in 发布，只有一个 owner。公开 `browser.*` 名称可沿用当前领域契约，内部旧注册/批准身份不做转换。
3. Browser 作为双渠道捆绑能力进入已有插件目录和会话面板；新会话默认集合包含 Browser，用户可在现有入口取消选择。选择不拉起 WebView、不批准网站访问，也不强制其他插件使用 MCP。
4. 手动浏览、书签、历史和用户导航继续由浏览器功能负责；Agent 来源关闭只撤下其后续工具准入，不能关闭正在手动浏览的标签。
5. 接入 HXA-272 的 Skill 内容路径及 HXA-274 的 host/组件状态；无 Activity host、页面失效、取消和视觉不可用必须返回真实原因。
6. 直接删除旧发布入口和对应内置来源假设，更新 native 作者样例。旧版会话默认值、旧批准和旧数据库迁移不属于交付物。

## 交付

2026-10-12 建立 `:extensions:browser` 单一贡献，12 个工具全部使用 Browser PluginOrigin，删除旧 built-in 发布入口及各工具注册助手。首次安装默认新会话选择 Browser；用户修改的默认值在重新发布时保留，不追溯修改已有会话。现有 Skill 内容与就绪状态接线，host 不可用按实际事实呈现，选择不创建页面或批准网站。

双渠道设备验证实际选择后 snapshot 执行、撤销后 TOOL_DISABLED、手动标签继续可用、重建无 host；真实 WebView 截图经持久工具历史、明确像素披露与请求编码回流，独立核对 1080×2400 红绿像素。共享引擎覆盖实际 DOM 操作、敏感字段、导航失效及 owner 替换。像素测试使用离线请求编码，不宣称真实视觉模型推理；本卡未调用真实模型，也未更新日常 APK。HXA-277/278/279 仍独立推进，未以本卡通过关闭其验收。
