## 2026-10-24 历史裁决（由下方实施记录接续）

现有 `HttpFetchTool` 是 http.fetch 原始响应；知识库的有界提取也不等于通用 web_search/web_fetch 已交付。保留两者实际用途，新搜索来源和模型引用闭环仍未实现。

这是独立能力/验证队列，不是所有结构重构的启动或完成条件。本轮只调整计划，未实施代码或补做设备/服务验收。

## 范围与验收要求

独立能力队列 P2（按实际用户任务可单独提升），按两个独立切片交付；不让搜索服务采购/账号条件阻塞可离线验证的网页正文读取。

| 切片 | 动机、范围与依赖 | 完成标准与不确定项 |
| --- | --- | --- |
| Fetch | HTTP 原文不足以支持引用阅读；286 契约后补正文、来源、内容类型与有界读取，复用现有网络治理 | HTML/文本/重定向/超大/乱码/动态页面夹具通过，来源能回查；抽取质量需真实页面对照，不承诺登录/JS 页面完整正文 |
| Search | 任务需要查找未知资料；286 契约加明确 provider/凭据/许可配置 | 结构化命中、失败/配额/空结果及引用流程通过；真实服务调用另授权，费用、地区可用性与条款是实施输入 |

非目标：不内置第二浏览器、不把搜索页面抓取冒充搜索 API、不替用户订阅付费服务、不为每个网页自动额外总结。provider 选择未定时只阻塞 Search 实接，不阻塞 Fetch、主机夹具或结构重构收口。

1. 实现职责明确的 web_search/web_fetch；保留 http.fetch 的原始 HTTP 语义。搜索结果提供 URL/标题/有界片段，fetch 提供来源明确的正文与截断，不隐含额外模型总结。
2. 先对照 DSH、Claude Code、Gemini 的实际契约选择一个可运行搜索来源，记录 API/凭据/费用与网络约束；无配置时明确不可用，不将浏览器搜索页面或假结果冒充搜索服务。
3. 处理重定向、内容类型、大小/超时、正文提取及动态/登录页面限制；复用既有网络权限与响应边界，网页正文始终是不可信外部内容。
4. 配套资料研究 Skill，以检索 → 读取 → 引用为完整任务；引用必须支持答案，不把搜索片段当已读全文。

### 2026-11-07 Fetch 实现检查点

所有者授权完成后续内容。本次新增 `web_fetch`，保留 `http.fetch` 原始响应用途；不放宽 Provider/MCP 的 `NormalizedEndpoint`。

- `tools/android` 的 `WebFetchTransport` 使用既有 OkHttp 5.5.0 与 `SsrfAddressPolicy`。网页 URL 保留 query、移除 fragment，禁止 userinfo；每跳固定全部 DNS 结果，重验实际 peer 与初始/当前 scope，拒绝 HTTPS 降级。无 Cookie、认证、代理、自动重定向或隐式连接重试。
- HTTP 解压后读取最多 1 MiB 加一个截断探测字节；独立 30 秒整次预算与固定取消观察器关闭 active call。平台 DNS/HTML 解析不能承诺即时中断，原执行槽持续占用至物理返回，返回后不得继续发送或消费失效内容。
- jsoup 1.24.1 仅解析已经取得的字节，不调用其网络 API；MIT 许可随应用打包，版本/锁/校验已固定。正文最多 60,000 UTF-16 单元且不拆代理对，返回实际最终 URL、标题、提取模式、正文 SHA-256、截断和解码丢失事实。hash 只代表返回文本，不是完整网页版本。
- 非成功 HTTP、非文本、无可读正文分别报告；不执行脚本、不绕登录，也不把页面宣称的 canonical URL 当真实来源。
- 首轮命令 `./gradlew :tools:android:testDebugUnitTest --tests '*WebFetch*' --tests '*HttpFetch*'` 41 项零失败，日志 `build/web-fetch-focused.log`。这是实现检查点，不是最终门禁；独立审查要求简化候选正文评分和补充边界验证，仍在收口。
- Search 服务、真实网页抽取质量对照、真实模型下一请求消费及设备验证尚未由这批主机测试证明。不得将初版测试计为 HXA-290 整体完成。

### 2026-11-08 Fetch 收口审查

- 正文选择固定优先第一个 `main` / `role=main`，其次第一个 `article`，空候选回退 body；不对嵌套候选反复全文评分，也不声称通用可读性算法或浏览器可见性。多个文章位于 main 时一并保留。
- 在选择/去除节点前检查整棵 DOM 的 50,000 节点预算，隐藏/导航子树同样计入。解析本身仍由 1 MiB 输入边界约束，解析后和遍历期间检查取消/截止时间。
- 有界输入的提取文本先归一化首尾空白，再进行 UTF-16 安全截断；新增恰好正文上限、边界 emoji、多文章、空 main、隐藏节点预算、相对重定向/循环及 active body 取消回归。
- 本轮未运行 Gradle 或设备命令，最终主机回归由共享构建队列执行；此前 41 项通过不能证明此次收口后的源码。Search、真实网页质量与模型消费仍保持上述未验边界。

### 2026-11-08 Fetch URL 与编码边界补正

- OkHttp 接受但 origin 规范拒绝的 host 在 DNS 前转为稳定 `invalid-url`，不泄漏 `NormalizedEndpoint` 构造异常；初始 URL 必须有明确 HTTP(S) scheme/authority。重定向先检查原始 Location 的长度、控制字符、反斜线和空 userinfo，再解析相对路径并重验目标与 HTTPS 降级。
- 仅读取无编码、identity 或 OkHttp 单层 gzip 解码后的正文。网络拦截器在自动解压前检查全部 Content-Encoding 字段，拒绝 br、deflate、逗号堆叠与重复字段；正文读取前再拒绝残留非 identity 编码，避免压缩字节误报 read。错误状态/非文本正文不消费，保留原结果分类。
- 新回归覆盖非法 host 的 DNS 前失败、工具失败映射、重定向原始边界、编码拒绝与 gzip 损坏、identity/单层 gzip、16 MiB 高压缩正文的解压后 1 MiB 保留边界，以及 main/role=main 与隐藏区域/body 回退选择。
- 此次仍未运行 Gradle 或设备命令，待共享构建队列对最新源码执行 `:tools:android:testDebugUnitTest --tests '*WebFetch*' --tests '*HttpFetch*'` 和相关静态门禁；不沿用历史 41 项测试作为新改动通过证据，不包含缓存优化。

### 2026-11-08 公共网页正文抽查

- 忽略目录内的手动 Java harness 复用已编译生产 `PinnedWebFetchTransport`、`WebFetchDocuments` 与真实 resolver，以 Standard / 空 LAN scope 读取 example.com、IANA reserved domains、RFC 9110 文本，三者均为实际 HTTP 200；没有代理、账号、权限绕过或固定离线门禁中的联网测试。
- example.com 的 156 字符 body-text 与实时 HTML 唯一正文段落逐字/hash 对齐。首轮 harness 错把标题当正文预期，保留失败记录；一次有界复查确认标题只在 head，不是提取丢失，不修改生产代码或弱化正文断言。IANA main-text 包含预期标题及多语言域名表；RFC 文本包含 HTTP Semantics，60,000 字符截断如实标记。
- 抽查观察到 IANA 文本保留较多布局空白、RFC 纯文本保留开头 BOM；未声称浏览器呈现或通用质量验收。忽略证据 `build/validation/continue-delivery/web-fetch-public/summary.md` 索引实际 URL/status/title/片段/hash/截断、初始失败与核对记录。仅证明这几个公共页面的本地主机读取与提取，不证明实际下一模型请求消费或设备效果。
