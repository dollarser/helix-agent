Memory 已有受控 list/search/read/write、全局/项目作用域与内容冲突校验。`MemoryContext.render` 当前最多两域，每域摘要前 1000 字符预载；这不是“无法读取后续内容”或“没有检索”的证据。知识库原件/核对笔记与 Memory 的用途、存储、隐私和注入资格不同，不因 Markdown 共性合库。

## 范围与验收要求

### A：P1 可选内容共同预算接缝

依赖 286-A 的来源/用途快照，ChatRequestAssembler 只设一个写入者。先保护必要指令、当前输入、合法 call/result 组及输出预留，再对目录/激活 Skill/Memory/资源作共同窗口下的可选投影，附估算成本、选择/省略/截断原因及受控重读标识。已有有界 tool schema 曝光不等于模型总窗口预算；不截断半个调用组，不把实际 token 与字节估算混淆。

验收：小窗口/多插件/多次压缩、内容替换和撤权后，实际请求仍保留必要约束、原来源/版本、配对顺序和重读入口；必要内容超窗明确失败。不默认改变 Memory 默认加载策略，不依赖 287/288 整项完成；当前消费者接通且可解释即停止。

### B：P2 有界策略实验，不自动批准生产替换

| 项目 | 约束 |
| --- | --- |
| 对照 | 现行摘要前缀，与“短索引/资源标识＋现有 search/read 按需读取”比较；每次只改变一个变量，冻结用户任务、模型/参数、内容版本和授权 |
| 样本 | 含第 1000 字之后关键事实、多主题/无关记忆、明确冲突/过期版本、小窗口、遗漏读取和取消/失败；不把答案预填提示、固定工具路线或反复跑到成功当收益 |
| 观测 | 实际请求内容、原约束/来源保持、任务正确性、调用/额外发现次数、token/时延及失败；区分“可读取”与“模型确实读取” |
| 预算与服务 | 预先约定有限轮次/总耗时；只使用当次获准配置，无配置则主机夹具与协议测试，不新增付费/账号或检索平台 |
| 退出 | 只有明确改善且无授权/恢复/必要信息回归才另行决定默认策略；无收益、样本不足或模型波动则保留现状，记录未决，不无限扩轮 |

非目标：向量库、自动 Memory Agent、全历史自动提取、强制模型读日志、自动业务补救、按竞品固定比例切上下文。日志全局关键词搜索和知识库备份/SAF 同步属于其他独立能力，不混入此实验。
