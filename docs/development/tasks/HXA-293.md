## 范围与验收要求

1. 保持唯一 ContextCompiler，宿主提供有界、带来源/版本/信任/成本口径的内容快照；Memory 的最小读取/写入端口归内容域，Markdown 为唯一正文，不放进通用执行器。
2. 复用 HXA-285 已交付的引用/压缩快照一致性；历史、Skill、Memory、资源与工具结果保留配对和来源，不建第二份可变历史或不同步索引。
3. 诊断能解释被选择/未选择内容及估算成本，区分实际 token、Schema 字节估算和窗口余量；不恢复累计 Turn/Goal token 截断或固定工具数上限。
4. 先分离结构接缝与策略行为，再按冻结样本比较检索/排序、Memory 渐进加载和上下文预算策略。每次改变一个可解释变量，没有收益保持原默认。
5. 保持 Memory 开关、Project 归属、内容 hash 冲突、不可信内容及隐私边界；向量库、后台 Memory Agent 和自动提取不在本任务范围。

6. 快照输入与成本统计按运行身份隔离，不依赖全局可变当前上下文；未来父子用量归集不意味着共享上下文窗口、审批或可写能力。来源内容版本与路径身份分开，过期异步结果不能冒充最新正文；沿现有快照/Workspace 契约实现，不预建 child context 管理器。

## 验证入口

- 交错编译两个运行的不同模型/工具/Memory 快照，验证内容与用量不串扰；同路径内容更新、旧异步结果、scope 撤销不得覆盖当前快照。父子功能未实现仍不记通过。

- 扩展现有 ContextCompiler、Memory Store/工具和 Room checkpoint 测试，覆盖关闭/撤权/项目变化、来源损坏、压缩配对、引用一致性与取消。
- 按授权使用同任务、模型、制品和判分做有界对照，记录任务成功、来源正确性、输入/输出用量、耗时与人工介入；旧 A6/B6 无稳定收益结论继续保留。
- 开始实施时定位现有测试入口并按改动选择回归；目标契约可替换旧实现镜像断言，权限、持久原子性、取消、真实退出与恢复反例不得丢失。设备/服务须核对当次授权与配置，本轮未执行。
