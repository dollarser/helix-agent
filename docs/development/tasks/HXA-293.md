## 范围与验收要求

分为 A（近期 P1：内容端口与共同预算）和 B（P2：Memory/选择策略），不合成一次难以归因的大改。A 不等 287 整项完成，但用 286 的来源/成本契约并复用 287 对应快照接缝；B 以 A 和固定样本为前置。

| 切片 | 范围与完成标准 | 非目标与不确定项 |
| --- | --- | --- |
| A | 为必要指令、当前用户输入、有效 call/result 组和输出预留空间；目录、近期工具、Skill、Memory、资源按模型剩余窗口分配可选预算；沿 299 诊断解释各段选择/省略与重读入口。小窗口、多插件和多次压缩后配对/来源/约束正确 | 不截半个工具调用组、不伪称估算 token 是实际 token、不照搬竞品固定比例。不同 Provider 的 schema/图片成本估计需校准，必要内容仍超窗则明确失败 |
| B | Memory 由固定摘要前缀逐步变为短索引及相关条目按需读；任务事实投影沿已持久来源，不从模型摘要制造“完成”。单变量对照成功率、原约束/来源保留、成本与耗时，证据不足保留默认 | 不加向量库、后台 Memory Agent 或自动全历史提取；项目 MEMORY.md 文件访问与应用 Memory 数据管理分开。相关性排序、图片/结果选择收益仍须实测 |

285 的引用/压缩一致性和 299 的成本诊断已经实现；本任务补统一预算、细分插件贡献与内容选择，不能把这些旧缺口再次列为待修。模型摘要质量和确定性恢复事实分别验收。

1. 保持唯一 ContextCompiler，宿主提供有界、带来源/版本/信任/成本口径的内容快照；Memory 的最小读取/写入端口归内容域，Markdown 为唯一正文，不放进通用执行器。
2. 复用 HXA-285 已交付的引用/压缩快照一致性；历史、Skill、Memory、资源与工具结果保留配对和来源，不建第二份可变历史或不同步索引。
3. 诊断能解释被选择/未选择内容及估算成本，区分实际 token、Schema 字节估算和窗口余量；不恢复累计 Turn/Goal token 截断或固定工具数上限。
4. 先分离结构接缝与策略行为，再按冻结样本比较检索/排序、Memory 渐进加载和上下文预算策略。每次改变一个可解释变量，没有收益保持原默认。
5. 保持 Memory 开关、Project 归属、内容 hash 冲突、不可信内容及隐私边界；向量库、后台 Memory Agent 和自动提取不在本任务范围。

6. 快照输入与成本统计按运行身份隔离，不依赖全局可变当前上下文；未来父子用量归集不意味着共享上下文窗口、审批或可写能力。来源内容版本与路径身份分开，过期异步结果不能冒充最新正文；沿现有快照/Workspace 契约实现，不预建 child context 管理器。

## 具体优化对象与收益验证

ToolDiscoveryWorkset 的近期 Schema 64 KiB / eager MCP 16 KiB 是曝光字节策略，MemoryContext 的每域摘要前 1,000 字符是预载策略，均不代表模型总窗口预算。A 用分项快照协调可选内容和重读入口；B 再替换固定摘要前缀的选择策略。303 的发现配套闭包是新基线，预算裁剪不能把一个已选配套组拆碎或重新纳入已撤销工具。

基线和新策略分别记录当前请求的必要/可选段成本、输入输出实际用量、压缩次数、来源与约束保持、任务结果、耗时和人工介入。采用相同样本单变量比较，不用字节减少推导模型完成率提升；必要内容不能为降低成本而静默丢弃。模型质量测试、Provider 协议夹具和确定性快照/恢复各自报告。
