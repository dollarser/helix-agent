> **复审纠正（2026-09-18）**：原提交 `4621666c` 称「M3 `MaterialTheme` 已默认跟随系统」被复审退回——该表述不成立（material3 1.4 裸 `MaterialTheme {}` 默认固定浅色）。下方交付记录描述的是**修正后**的实现：Compose 侧显式 `HelixTheme` 接线 + 窗口侧 `values-night` + 具名测试新增「真实渲染 Compose 颜色」面（共 **6 面**）。

- 统一**跟随系统**的深色/浅色，**两侧都显式接线**（复审纠正：material3 1.4 的 `MaterialTheme` composable **并不**读取系统夜间模式——裸 `MaterialTheme {}` 落到静态 `LocalColorScheme` 默认，即 `lightColorScheme()`，是**固定浅色**；已对照 material3 1.4.0 字节核验：无任何 material3 类引用 `isSystemInDarkTheme`/`uiMode`）：
  - **Compose 侧（复审退回的核心缺陷，本轮新增）**：`app/src/main/kotlin/com/helix/app/Theme.kt` 的 `HelixTheme` 在两个组合根（首启提示 + 主壳）显式按 `isSystemInDarkTheme()` 选 dark/light colorScheme；`MainActivity` 两处入口改用 `HelixTheme`。对话框是树内 M3 `AlertDialog`，随这两个根一起翻转，无需逐一改动扩展组件。
  - **Android 窗口侧**：`app/src/main/res/values-night/themes.xml`：`Theme.Helix` 父 `android:Theme.Material.NoActionBar`（深色平台主题，避免 Compose 绘制前的浅色闪现），status/nav 栏 `#FF1C1B1F`（M3 深色 surface）+ `windowLightStatusBar=false`（深栏浅图标），严格对应浅色基线 `values/themes.xml`（`#FFF9F9` + `windowLightStatusBar=true`）；
  - `runtime/cli-app/src/main/res/values-night/themes.xml`：developer 订阅/登录面（native-View 壳）`Theme.Helix.Subscription` 的**窗口/系统栏**同款深色（`colorAccent #D0BCFF`、`#FF1C1B1F`、`windowLightStatusBar`/`windowLightNavigationBar=false`）；其 View 内容色为本轮**残留边界**（见证据）。
