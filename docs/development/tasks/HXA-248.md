## 范围与验收要求

承接 HXA-236 原执行观察/控制与 Harness §8.7。只在从启动起具有稳定 Binding、日志和已批准后台 lease 的 Linux Job 上提供等待模式。AUTO 最多等待 15 秒：终态时收取同一原结果，未终态时返回同一 originalCallId；BACKGROUND 保留立即返回接受回执的既有契约。等待方式不更改已批准命令、执行身份、Workspace、scope、owner、凭据或 deadline。不升级缺乏后台资格的 `code.linux.run` one-shot，不取消再启动。

所有初始提交继续唯一 Dispatcher 的 schema→policy/权限→审批→deadline runner/实际执行资源路径；有界等待复用现有观察服务及物理 query lane。提交接受不是任务成功，UNKNOWN 不重放；取消等待不伪称执行已停止。快速收取复用原输出授权检查、校验、receipt 和 lease 结算。用户提前释放等待的按钮单独在下一检查点实现。

## 实现参考与取舍

核对 Codex 官方源码固定提交 [`2351d9e1`](https://github.com/openai/codex/blob/2351d9e1b608e6f9d9a3699b71d7eb39ee41cfa4/codex-rs/core/src/unified_exec/mod.rs) 及同提交 process_manager：等待时长与稳定进程身份分离，原控制与输出保留；[Claude Code 后台 Bash](https://code.claude.com/docs/en/interactive-mode#background-bash-commands) 区分任务句柄、等待释放和取消。采用职责原则，代码独立实现。Helix 保留 15 秒观察上限、既有 Runtime lease/Android 生命周期、物理容量和持久事实；不采纳桌面无限后台、扩大租期或沙箱回退。
