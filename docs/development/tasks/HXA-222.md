# HXA-222：On-device Local Model Provider

分类：已规划，暂缓实施。长期语义以 [ADR-PROVIDER-001](../../adr/provider/001-models-and-connection.md) 与 [ADR-AGENT-001](../../adr/agent/001-turn-coordination.md) 为准。本任务已获本地模型“一等 Provider、可驱动完整 Agent loop”的设计授权；当前重构主线期间只冻结接口方向，不启动生产代码、native runtime 或模型资产开发。

## 范围与验收要求

目标是让设备内模型与远端/订阅 Provider 使用同一 `ModelProvider`、`ModelRequest` / `ModelEvent`、capability probe、AgentLoop、Dispatcher/Policy/Approval/Audit 体系。

必须满足：

- 本地 Provider 有显式、可验证的 `ON_DEVICE_LOCAL` residence；
- 不伪造 loopback HTTP endpoint，不要求 cleartext host:port 授权；
- endpoint / HTTP wire protocol 只属于网络 Provider，本地 Provider 的类型不能构造出“假 endpoint + 假 protocol”；
- 本地 Provider 的工具能力只由真实 capability/eval 决定，不因运行位置被硬编码禁用；
- local backend 的错误、取消、stream terminal 与远端 Provider 使用同一归一化合同；
- 模型资产在 app 私有存储，完整性、配额、用户触发下载与删除必须可验证；
- native/runtime 崩溃或 OOM 不能伪造成成功，不能绕过 TurnEngine lifecycle；
- 不新增第二套 Agent loop、权限或 Tool dispatcher。

当前预留原则：现有重构不得把 `ModelProvider`、TurnEngine、capability/eval 或权限体系进一步绑死到“必须有 HTTP endpoint”的假设；若重构触及 Provider 公共边界，只允许做不阻碍未来 endpoint-free local Provider 的通用抽象，不以 HXA-222 名义提前实现本地模型功能。

## 启动条件

只有当前 clean-slate 重构主线完成架构复审、剩余 ownership/竞态问题收口并形成新的稳定 checkpoint 后，才将本任务从“已规划”切换为“进行中”。启动时先重新审查 Provider contract 的最新 caller graph；本文件记录方向，不授权在重构期间提前扩展产品功能。

## L1 — Provider transport contract（强模型）

把当前“Provider 必然等于 HTTP endpoint”的契约拆开：

- 新增类型化 Provider transport/location：网络 transport 持有 `ProviderProtocol + NormalizedEndpoint`；本地 transport 为 `ON_DEVICE_LOCAL`，不持有 endpoint/protocol；
- `ProviderDescriptor` / `ProviderConfig` 从 transport 派生 residence；
- `provider_configs` baseline schema 明确持久化 transport kind，网络 protocol/endpoint 可空但由 repository 严格验证组合；
- network adapters 只能接 network config；local backend 只能接 local config；
- `ProviderFactory` extension seam 支持 local backend，不通过 `WireClient`；
- cleartext / egress disclosure / binding prune 对 local provider 不走网络路径。

## L2 — Local provider + fake backend contract（强模型）

新增 local provider 模块/API seam：

- backend 提供 exact model catalog、metadata/capabilities、validate、stream；
- `LocalModelProvider` 把 backend 事件归一成现有 `ModelEvent`；
- host fake backend 覆盖 text、reasoning、tool call、usage、terminal、cancel/error；
- 用现有 AgentLoop/Provider probe 测试证明 local provider 可以驱动完整 loop，不新增特殊 Agent 分支。

## L3 — Native inference runtime

首选 llama.cpp + GGUF，但 Runtime 细节不写进 Provider 语义：

- arm64-v8a CPU baseline；GPU/NPU 是后续优化，不作为首版前置；
- JNI 或 private-process runtime 必须有明确 ownership/cancel/crash contract；
- 工具调用结构化输出使用 grammar/schema 约束时仍需经过现有 schema validator；
- 内存/热/上下文容量成为 capability/eval 证据，不由模型名猜测。

若 native 依赖/构建体积需要独立风险切片，先完成可测试 runtime port + fake backend，再接真实 engine；不得用 loopback HTTP 伪装完成。

## L4 — Model asset lifecycle

模型不进入 APK：

- 用户显式选择/下载；
- app-private model store；
- resumable transfer、SHA-256、原子 publish；
- 可见大小/状态/删除；
- quota/空间不足/部分下载/校验失败 fail closed；
- 不把 Workspace/SAF 文件默认当可执行模型资产。

## L5 — UI / probe / full-loop validation

- 本地 Provider 可创建、选择 exact model、查看 residence/capabilities；
- 本地 Provider 不显示网络 egress/cleartext repair；
- capability probe / model metadata 与远端使用同一 UI 语义；
- fake backend host tests 覆盖完整 Agent loop 工具调用与恢复边界；
- 真实 native 性能/热/内存/模型任务 eval 只有 owner 明确要求设备验证时执行。

## 不在本任务

- 不启动 HXA-210 Workspace binding（ADR-WORKSPACE-004 仍 proposed）；
- 不改变远端 Provider wire protocol；
- 不通过本地模型扩大 Tool 权限；
- 不把 local model 限制为摘要/标题等辅助调用；
- 不 push/merge/release。
