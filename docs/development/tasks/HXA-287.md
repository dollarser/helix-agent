## 范围与验收要求

1. 将原 B 与 E 合为一个实施目标：UI/通知/浮窗通过统一应用命令和持久投影；AppAgentRuntime 不再回调宽 ChatService，工具批次应用服务不依赖 ChatScreenState、R 或审批卡类型。
2. 完整 Turn 领域宿主覆盖准入、driver、模型/工具循环、审批、停止、park/review、终态和恢复；去除对 Android/Room Entity/HelixStorage 的直接依赖。保留唯一 Loop、Engine 和 Dispatcher，不新增第二 writer 或远程平台。
3. 按 286 已定义的调用/Job/ExecutionResource/产物身份、四个完成条件及取消/reconcile 语义，在现有 journal/store 上定义原子领域命令，由 Room 实现；保留 Steer/最终答复、首 ModelCall/step、GoalRun/Turn 和停止竞态的事务边界，不暴露通用 DAO 或跨层事务 lambda，不先按猜测的 Job 语义固化存储。
4. 287-A 先以 fake model/executor 和可重载持久端口夹具走通“统一入口 → 完整 Turn → 工具回传 → 结算/恢复”的最小纵切，包含无 UI 审批、停止与模型 call/result 配对。与 288-A 集成时接真实执行后端及最小 Room 适配；之后扩展全部原子生命周期/恢复命令。每条生产路径切换时删旧入口，不把纯夹具通过或服务提取当作完整宿主交付。
5. 按现阶段单一开发库基线设计，不新增旧开发版本迁移链。当前版本进程死亡恢复、在途身份和 UNKNOWN 仍须正确；安装/清库不是本任务文档授予的数据操作权限。

6. 单一 Loop/Engine 指同一实现和每个运行的唯一权威，不是全局只允许一个运行。状态、上下文、取消和结算使用显式归属；不新增全局 activeTurn/cwd 或当前页面状态依赖。保留原同会话 admission；父子调度不在本轮上线。
7. 保持参数准备、execution-start 屏障、持久结算与后置通知的顺序；外部回调不在 Room 事务/准入锁内执行，通知失败不重新解释已提交结果。未来 hooks 必须接这些明确边界，不直接修改领域状态。
8. 上下文正确性随 287-A 接线：来源/内容版本、当前授权投影、不可变请求和调用结果成组/原顺序回填由同一持久事实重建；取消或重载不读取另一页面/运行的快照。不等待 293 才验证这些约束，本任务不调整检索/摘要策略。

## 与 HXA-288 的共同集成

287-A 与 288-A 分别完成后，用一条现有文件/只读执行路径接入真实 Room，验证执行开始、调用返回、结果提交与模型回填；再按 288 的领域顺序迁 Mobile Use、PRoot 等实际适配。287 完整 Room/恢复覆盖可在共同接缝稳定后继续，不等待所有插件迁完；288 领域适配也不以 287 整任务完成为启动条件。两者最终完成均须引用同一次生产集成的适用证据，不把整任务状态互设为前置。

## 验证入口

- 287-A 用可控制 executor 注入 crash/reload：开始屏障前失败零启动、外部效果后落盘前保留 UNKNOWN 且不重放、提交后通知失败不重复执行/结算；重载后 call/result 按原身份成组，旧 Turn 不复活。夹具须从保存的事实重建宿主，不能只重置 UI 或复用原内存对象。
- 迟到取消回调、大输出/未收尽输出、插件缺失/撤权在最小纵切和后续真实适配阶段持续验证；不能留到 294 才第一次验证。fake executor 不证明实际进程、Room 事务或设备恢复通过。

- 两个普通会话/无页面运行交错推进，停止 A、切换页面或晚到 A 回调不能污染 B；仍验证原同会话准入约束。后置通知失败不重复结算、不持锁等待；无需实现子 Agent 或 hook runner。

- 同一组领域行为断言在纯 JVM 完整 Turn 宿主与真实 Room 适配分别运行，覆盖幂等 submit、Queue/Steer、审批、取消/结算竞态、Goal 联动和重建恢复。
- 无页面订阅仍能执行、待审批和停止；只由 UI 做本地化/导航。主机内存实现通过不能代替 Room 事务或设备进程死亡验证。
- 开始实施时定位现有测试入口并按改动选择回归；目标契约可替换旧实现镜像断言，权限、持久原子性、取消、真实退出与恢复反例不得丢失。设备/服务须核对当次授权与配置，本轮未执行。
