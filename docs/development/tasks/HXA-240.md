## 当前实现与目标

在 `runtime:proot-app` 中内置同一份 SHA 固定的 Ready-AV1 Android/Bionic 载荷，经 PRoot 显式绑定 Android 系统路径和本 APK 原生库目录，由 guest `ffmpeg` / `ffprobe` 薄入口通过系统 linker 原样转发 argv。它不是 Alpine/musl 构建；不重装 RootFS、不复制第二套 FFmpeg、不新建 Service/JNI/Agent/调度引擎。Bash、前台/后台 Job、手动 PTY 复用各自既有入口和生命周期。

原 `runtime/media` 与其专用接线已撤回，草稿存于 ignored `build/hxa240/retired-media-runtime/` 仅作历史。Standard/consumer 不包含此次 FFmpeg/PRoot 载荷，既有图片与视觉能力不变；Advanced-only 不代表新媒体逻辑绕过现有权限。

## 范围与验收要求

- 精确候选 `ffmpeg-9.0.2-ready-av1-arm64-v8a.zip`；构建校验完整 ZIP/逐文件/组件清单、复制许可/来源/NOTICE。原生完整载荷与实际 APK 增量继续对照 25,000,000 bytes。设备无联网下载可执行代码。
- 参数不是五种预设：多输入/输出、滤镜图、字幕/字体、流选择、编码和流复制由模型使用 FFmpeg 原生 CLI 表达。未编入网络/编码器不会因为有 Bash 而出现；MediaCodec 仍是设备条件能力。
- PRoot 使用共享应用 UID，不是安全或凭据沙箱。新增绑定仅为公开 Android 系统路径和 APK 自身原生载荷/用法材料，不额外映射应用凭据目录，不改变权限预设或审批身份。
- 输入快照通过既有 WorkspaceArtifactStore 流式读取，解除旧 1 MiB 预览配额误用，但仍受 Job 已有单文件 64 MiB / 总归档 128 MiB 约束；不将素材整份读进内存。输入命名规则不静默变更。
- 仅将原成功任务归档中显式 `output/` 下的文件发布到应用托管 `output/jobs/<jobId>/`，按原 session/turn 注册。多个输出不再挤进 result.txt。重收取核对原身份与哈希，不覆盖用户修改、不重放命令；归档与媒体语义验收是不同事实。
- 原短命令、后台租期、进度/日志、取消/真实退出、原任务查询与结果确认保持既有通道；不新增媒体全局锁，不因文件竞争阻止无关任务。
