## 范围与验收要求

| 顺序 | 责任与范围 | 验收与停止条件 |
| --- | --- | --- |
| 286-A / P1 | 复用现有来源与内容快照，给必要指令、目录、激活正文、readiness 分配独立类型/用途；来源身份、版本/内容 hash、资格、预算口径与受控重读入口明确。先覆盖现有 docs/插件和 MCP 目录，不先设计所有 hook | 用新测试插件证明同类内容接入不改宿主插件 ID 条件；与旧生产请求做结构/内容对照，必要指导和来源不丢，停用/替换不继续注入，取消/重载不串运行 |
| 286-B / P1 | 将现有 instructions/readiness 通过同一投影传给唯一 ContextCompiler，删除被替换的拼接和特判；与 293-A 共用同一快照，不建平行目录 | 实际发送请求、诊断和恢复引用同源；保留发现配套的同来源/撤权/循环/预算反例；接口符合目标、当前消费者接入且旧路径删除后停止 |

实现前先检查现有 ContextSourceSnapshot（历史行）、PromptSnapshot（系统段）与 Skill 内容事实；不要把插件正文硬塞成历史行，也不为同一内容再建持久库。只增加当前消费者缺少的最小贡献值类型，字段/命名不冻结。

依赖：可直接以当前 Registry、SkillRepository 和 ContextCompiler 为基线，不先实施整个 287/288。286-A 快照形状稳定后才能并行消费它；ChatRequestAssembler 的写入所有权须与 293-A 协调。真正运行依赖只为现有消费者定义，不能将发现配套升级为授权或自动执行条件。

最终 Provider 文本序列化仍是合法边界，目标是单一有来源的投影，不是消灭所有字符串；不保留新旧内容双轨。

非目标：通用可执行 hooks、任意历史重写、第二套工具注册/权限、自动安装/选择、强制模型下一步、所有未来元数据统一化。独立短名与领域命名沿当前契约，不重做已完成工具迁移。

## 共同契约与退出条件

沿[工具契约](../../adr/tools/001-descriptor-contract.md)和[Turn 协调](../../adr/agent/001-turn-coordination.md)，Turn/call、Job、资源 generation、artifact 与内容 URI 不混同；调用返回、实际退出、输出收尽、持久提交分别按实际后端表达。沿现有 accepted ADR 和已交付 owner，不为字段齐全制造空 Job 或账本。只在实际消费者证明缺失时扩字段。
