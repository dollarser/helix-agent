## 范围与验收要求

1. 建立模型侧工具目录：规范名、用途、输入与单位、结果、前置工具、来源、运行条件及副作用；统一英文动作描述与 Schema 字段，UI 保持本地化。保留 read/write/edit，新增 glob/grep 与 web_search/web_fetch 的契约由所属任务实现。
2. 扩展现有贡献/发现元数据，复用单一 Registry/Binding；工具、Skill、Resources、readiness 和依赖引用同一来源事实。依赖只影响发现配套，不安装插件、不自动授权，不让远端声明提高常驻优先级或可信度。
3. 将 Mobile Use 默认曝光、单独发现 ui.screenshot、坐标动作三条路径纳入统一依赖契约；禁止依赖闭包绕过禁用、模式、撤销或跨来源错误绑定。缺失依赖有明确原因。Owner 后续收尾已在旧入口补齐默认及单独截图发现的 ui.device/frame 配套，见[追加记录](../../evidence/development/pre-refactor-finish-2026-10-15.md#竞品对照追加收尾)；本任务迁移并保留这些回归，不重复修复，也不以局部修复宣布贡献协议已交付。
4. 把所涉插件 ID/工具名特判替换为可信、可校验的贡献声明；检测缺失、循环、来源冲突和过大依赖集合。保留 Android/原生/MCP 的实际差异，不引入通用 execute(action,args)。
5. 按完整路径同步 Schema、实现、内置 Skill、系统提示、界面与测试，删除所替换的旧 DTO、执行别名、双注册及兼容桥。外部插件名称只作检索线索，当前外部格式适配继续保留。

   2026-10-16 [文件提示审查](../../evidence/development/file-prompt-review-2026-10-16.md) 发现的读取哈希缺口已由 Owner 追加 [HXA-296](HXA-296.md) 在当前路径修复，不再等待本重构：显式有界 `read(includeSha256=true)` 同流返回完整哈希，编辑核对已读字节和写前版本，发布后异常保留未知效果。本任务迁移已交付的双渠道路径，保留完整文件/窗口/工具结果身份区分、大小与取消限制及版本变化反例；不取消 hash 检查，不依赖 Standard 终端，不保留旧错误说明。精确验收范围归 296 的记录。

6. 扩展约束见 [方案 §23.9](../../architecture/harness-refactor-plan.md#239-后续扩展约束)：贡献中的工具、内容、Agent/hook/LSP 声明和可运行支持分开，不要求每组件拥有工具或 Runtime；原参数准备/校验/授权/开始/结算/通知阶段清楚。当前只迁真实消费者，不建通用 hooks 框架。

## 共同契约与退出条件

2026-10-16 会话追加：与 [HXA-295 B/C](HXA-295.md) 共同定义目标会话/操作范围、可信用户与模型委托输入来源、授权版本、历史游标/快照和投递 receipt，长期规则归 [AGENT-001 §17](../../adr/agent/001-turn-coordination.md#17-会话查询与管理)。295 A 的本会话/引用查询是已有消费者，迁移时保留范围反例；跨会话功能不反过来成为本任务启动前置。能力目录不授予目标访问权，不为未来 create/send 注册占位工具。

以下事实在 286 定义并以现有消费者及契约夹具核对，287/288 实现时沿用；不另建执行平台或状态账本，类型名不冻结最终代码命名。

| 契约 | 286 必须明确的责任与判据 |
| --- | --- |
| 身份与归属 | turnId 由 TurnEngine/持久准入建立，toolCallId 由原模型调用建档；jobId/executionId 仅由实际异步执行路径建立并关联原调用。长期 ExecutionResource 的 resourceId/实例 generation、生命周期 owner 与控制调用分开，可跨调用持有。artifactId 由原产物发布路径建立并保存来源/内容身份及引用。各自创建、保存、引用与清理的 owner 明确；MCP 内容 URI 不等于执行资源句柄，任何 ID 都不授予权限 |
| 四个完成条件 | 调用返回表示本次调用/观察得到何种 outcome；进程或实际 executor 退出由原执行 owner 证明；输出收尽由原输出通道的 EOF/游标/完整性证明；结果落盘由原领域命令提交证明。四者可先后发生，未收尽、截断和未落盘明确表达；无进程/流的工具标明不适用，不伪造 Job 或 POSIX exit code |
| 取消与迟到事实 | cancel requested、后端 confirmed、实际退出分别记录；确认受理不能冒充已退出或副作用回滚。迟到结果只对原 call/job/resource generation 对账，不覆盖新实例或重复结算；退出前不释放其仍占用的容量 |
| 当前版本重启 reconcile | 区分开始屏障前、外部效果后落盘前、落盘后通知前的中断。按原持久身份查询、收取/ACK，不能确认的效果保留 UNKNOWN，不重放命令/点击；旧 Turn 不复活，新模型工作按原 successor 准入。重复 reconcile 不产生新业务动作 |
| 资源与产物清理 | Runtime/executor 报告真实存活、退出及输出通道事实；插件/宿主 owner 管引用与 lease，最后有效引用和实际使用结束后清理；产物库按原引用/GC 规则回收。进程死亡可使句柄失效，清理失败保留诊断，不以页面关闭、Turn 终态或缺少回包判定可删 |
| 上下文正确性 | 模型输入的来源/内容版本、授权投影、运行身份与 call/result 配对从 286 固定，287 的首个完整 Turn 即验证重载后的同源重建和原顺序回填；检索、排序、摘要质量等策略优化留给 293，复用现有 ContextCompiler/285 事实 |

退出时须有身份/责任映射、四个完成条件和取消/恢复时序的契约夹具，以及原子存储命令所需事实；287 不再按尚未定义的 Job/资源语义固定持久接口。这里定义轻量契约，真实 Room、执行核心与插件接线分别由 287/288 验收。

## 验证入口

- 从本阶段积累跨层反例：取消请求与确认分离、旧 generation 迟到、输出未收尽、未知外部效果不重放、插件缺失/替换、快照配对。286 验证契约与开始前拒绝，287/288 分别补宿主、真实持久与执行接线证据，294 只做冻结后的整体回归。

- 补参数改变后旧批准不可用、前置拒绝零启动、未知组件不会生成可执行工具/自动安装的反例；依赖与发现元数据不得改变授权。

- 扩展现有 Registry、ToolDiscoveryWorkset、请求装配与插件贡献测试，验证默认/单独发现/撤权/替换/零命中、依赖失败及跨会话隔离；不新增固定工具数门禁。
- 每种工具只曝光一份规范 Schema，实际请求保存完整绑定；改名不能继承旧批准。后续有界模型对照分开记录改名、参数描述和新增能力收益。
- 开始实施时定位现有测试入口并按改动选择回归；目标契约可替换旧实现镜像断言，权限、持久原子性、取消、真实退出与恢复反例不得丢失。设备/服务须核对当次授权与配置，本轮未执行。
