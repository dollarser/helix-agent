# HXA-232：自主恢复与最小人工介入

分类：进行中。2026-09-29 所有者授权自主恢复；当时优先于 R1。R1 后续已单独交付，本任务的剩余验收和下文边界保持开放，实时顺序只看 [status](../status.md)。

## 契约

Harness 处理确定性恢复与资源边界，模型处理策略调整；除必要授权审批外，不把技术恢复责任转交用户。无法恢复时明确报告未完成与已有成果。用户 Stop、只规划、权限撤销及总额度保持有效；不能无限重试、重放未知副作用或由模型猜测覆盖执行事实。

## 范围与验收要求

2026-09-30 所有者追加授权：QuickJS 默认隔离、用户原生总开关；结构化反问（单选/多选/自由文本，普通输入准入，不替代审批）；大段内置提示词迁移到随 APK 打包的资源。该次追加授权将原生原型与手动压缩修复一并纳入主机集成验证，当次不含 R1；R1 后续另获授权并交付，不由此扩大本任务范围。

- [ ] QuickJS 总开关执行前校验、授权撤销、重新开启不复用旧授权；任意原生 API 的共享 UID 边界明确。
- [ ] 反问问题/回答身份持久化，支持重开、重复提交、跳过与独立附件草稿；不能将答案当授权。
- [ ] 内置大段静态提示文本抽离；实时事实与权限逻辑留在代码，加载条件/信任级别保持一致。

- [ ] 自动化取消周期性人工确认，已授权目标经新快照验证后自动恢复；新目标仍需授权。
- [ ] Goal 局部窗口耗尽在原总额度内自动续跑；无进展先反馈策略警告，再有界收尾，不要求人工维修。
- [ ] UNKNOWN 经原执行器对账和只读检查进入自主恢复；无法证明的副作用保留未知。恢复准入持久去重，旧执行仍在运行时不重复执行。
- [ ] 订阅/PRoot 结果查询与收集自动驱动；网络失败、队列投递和进程重开有明确自动恢复或结束路径。
- [ ] 配置与数据外发所需授权收敛到统一审批；旧恢复 UI 不再承担启动恢复的必要职责。
- [ ] 更新提示词、相关 ADR 与状态索引，保留事实、授权与用户停止边界。

## 验证入口

主机：automation 与双渠道 unit，双渠道 lint/debug APK/AndroidTest APK，spotlessCheck、detekt、check-all.sh --source、git diff --check；使用共享 host slot。设备仅在本轮明确授权后执行定向 API36，未执行不得写通过。

覆盖重复通知、重开、用户停止、权限撤销、预算不足、模型不可用、部分副作用及恢复失败。记录完成率、非审批介入、重复副作用和恢复成本；不能仅用不出现按钮证明完成。

## 交付

2026-09-30 本轮已实现全部上述代码路径：QuickJS 原生总开关、结构化反问、提示词资源化、自动化恢复、Goal 局部额度续跑、无进展收尾、空响应重试、原 Runtime 结果回收、UNKNOWN 只读核查、原 Goal 预算归属、队列重验证/明确失败与统一授权交互。见[主机收口证据](../../evidence/development/quickjs-questions-host-2026-09-30.md)。

后续所有者于 2026-09-30 明确授权模拟器验证：API36 / arm64 双渠道各 **57/57 passed**，覆盖原生网络/文件/API、撤销与重新开启、超时取消、持久只读恢复/Stop、反问自由回答、Goal、重新生成、工具与外发审批以及附件回执重建。修复原生异常跨 JNI 的传递问题，旧测试夹具按当前契约修正；中间失败及逐类结果见[设备证据](../../evidence/development/hxa232-api36-2026-09-30.md)。
