## 固定源码复核：许可证与资源边界

执行 `python3 scripts/debug/2026-09-20/inspect-termlib-source.py` 下载上述固定 commit，源码归档 SHA-256 为 `c0a9a6e2f24e88cace413aa6d9ea9ddabe8d30c43fbf6e449ea86c2e411fddbc`。脚本校验固定哈希后仅解包到忽略的 build 目录；归档变化必须复核，不自动接受新哈希。

- 固定源码 `lib/src/main/cpp/CMakeLists.txt` 明确把 bundled libvterm 静态编入 JNI 库；根 LICENSE 为 Apache-2.0，`libvterm/LICENSE` 为 MIT（Paul Evans）。正式采纳时需同时保留两份许可证/归属；本轮未增加生产依赖或宣布完成完整供应链验收。
- `TerminalTextDecoder` 按字节累积分片，普通 OSC/标题每条上限 1 MiB，已解码剪贴板内容每条上限 16 MiB；超限丢弃整条直到结束。键空间固定为 OSC、两个标题属性和剪贴板，不随任意 OSC command 无限增长。`onClipboardCopy=null` 阻止应用复制，但**不阻止此前的解析与累积开销**。197 不需要 OSC 自动复制；组件设备 spike 必须量测这种输入，并验证剪贴板不变，不能把回调为空当作资源验收。
- `TerminalEmulatorImpl` 滚动历史限制 1000 行；resize 只检查正数，没有最大行列限制，历史行数不等于总字节上限。接线需约束实际视口行列及输入批次，并量测长输出和 resize 下的内存。
- `TerminalDispatcher` 使用无容量上限的 `ConcurrentLinkedQueue`；Compose 按键/粘贴经该队列，粘贴还生成单个输出批次。这是输入积压需要验证的路径。不能误写为所有 PTY 输出都会进入该队列：公开 `writeInput` 是同步解析，显示快照另有 `damagePosted` 合并。应用适配层应采用单读者和有界传输，不为每个输出片段再启动无限 coroutine/队列；PTY drain 与显示缓冲的关系仍按 ADR 的非阻塞、有缺口可见要求设计。
- Native OSC 52 查询不读取剪贴板；selection-set 已由 libvterm 解码后交给 Kotlin。图片默认 Off 不等于关闭其他 OSC。设备验证须分别覆盖输出驱动 OSC、人工复制、中文分片和长粘贴。

当前结论：组件仍为候选，不能仅凭 1000 行历史或 ELF 对齐宣布可直接接线。下一切片先完成 SDK 兼容与 Android 私有 Runtime 内 PTY 可行性，再用有界输入/输出的组件 spike 取得证据。上述发现不改变已接受的单个手动 PTY 范围，也不添加 Agent 自动输入接口。

### Ctrl-C 与继承信号状态

探针 v8 新增真实终端输入 `0x03`：先确认前台进程组切换，再验证命令退出码 130、命令 PID 消失、原 shell/env 保留及最后 EOF 回收。API29/36 各 **1/1**，构建、运行和关闭均 exit 0，证据 `build/hxa197-pty-api29-v8`、`build/hxa197-pty-api36-v8`；固定 APK 哈希和完整过程见上述探针 README。这次重新覆盖原基础项，不将两个版本相加冒充更多测试。

v6 修复读取次数被错误用作超时；v7 真实 Ctrl-C 只回显但不中断。v8 在子进程 fork/exec 之间重置信号处理与 mask 后通过，父 JVM 不变；生产适配必须处理宿主信号继承，不能仅凭 setsid/controlling TTY 判定交互成立。该对照未分别隔离 handler/mask；仍不证明 PRoot shell、后台子进程清理或产品 UI 已验收。

### 锁定 PRoot 交互 shell 补验

进一步复用当前生产安装器、锁定 RootFS/PRoot 资产和签名 APK 中 loader，在探针自己的 UID/私有目录内安装并运行 Alpine `/bin/sh -i`。PRoot-v3 构建通过，API29/36 各 **1/1**，相同 APK，独占模拟器正常退出；证据目录、SHA 与命令见探针 README。此版本重新覆盖基础 TTY、中文、状态保持、resize、真实 Ctrl-C、前台命令回收和 EOF，不与系统 shell 旧版本叠加计数。

设备证据明确 tracer PID 不等于交互 shell 前台组；必须依据 `tcgetpgrp` 区分提示符与前台命令，不能仅比较 fork 返回 PID。所有 fork 前路径/环境构造有长度限制，子进程恢复信号状态。当前仅映射探针临时 Workspace、关闭行编辑，不证明真实产品目录映射、交互编辑/REPL、后台子进程或渲染组件；下一步继续这些剩余门禁，再接生产会话服务。

### 正常行编辑与真实 Python REPL

后续 repl-v1 已去掉关闭行编辑的探针设置：真实退格字节修改 shell 命令并验证执行输出；包内 `python3 -q` 分次接收赋值、中文打印与 Ctrl-D，验证变量保持、结果 42、返回原 shell 后环境仍在，再 EOF 退出。不是一次性脚本模拟 REPL。API29/36 同 APK 各 **1/1**，同时覆盖前述 resize/Ctrl-C，构建和 owned emulator 关闭均成功；日志、哈希与复现参数见探针 README。此前“关闭行编辑”仅描述历史版本。

本证据推进 PTY/程序交互可行性；尚无终端 Compose 界面、Android IME 或截图验收。后续重点是后台子进程退出/隔离、组件渲染和有界传输，再完成真实 Workspace 与租期契约及生产服务接线。

### 后台作业关闭与其他 session 隔离

close-v3 增加独立关闭用例，API29/36 各 **2/2**，相同 APK 与正常关闭证据见探针 README。在提示符后启动实际后台 `sleep`，验证它位于当前 PTY session 的不同作业组；关闭后后台 PID 与 tracer 都消失，独立 session 的哨兵进程保持存活。哨兵不是生产 Job owner，生产交叉回归仍待做。

现场失败揭示：SIGKILL tracer 组留下后台作业；SIGTERM tracer 组也未在 3 秒内结束。成功探针先按活 tracer 的内核 session 枚举/重查并终止作业组，让 tracer 收尾，之后确认退出。**生产不能沿用“一个 group kill 回执就释放占用”的假设**；稳定身份绑定、异常死亡、并发派生及强制关闭升级需进入正式实现和验收，当前扫描探针不是生产清理算法。不将本证据扩大到主动另建 session 的程序或任意后代。
