## 范围与验收要求

1. 实现 286 定义的公共契约：调用返回、实际执行退出、输出收尽、结果落盘分别有判据，并关联原 Job 状态与产物发布。同步工具无需变成 Job；MCP/HTTP、原生回调与进程分别保留真实完成/错误/取消语义，不伪造 POSIX 退出码，手势派发不等于业务成功。
2. launch/observe/collect/cancel 绑定原 executionId/generation/session/turn/call；停止等待、取消执行、收取和 ACK 各自表达，不重发命令、不续租、不用同名工具重新绑定。
3. 类型化产物来源、用途与引用，区分内部观察、交付文件、模型视觉输入；保存、展示、实际发送分别留事实。替换所涉 toolName/JSON 字段推断，不建立第二产物库。
4. 288-A 先以受控同步、异步/观察实现验证执行核心；与 287-A 用现有文件读取、受控副作用路径和最小 Room 共同验证生产接缝及三个崩溃窗口，再按 Mobile Use → 既有 PRoot Job 逐领域接线和验收，MCP/HTTP 适配按其真实语义验证。每条完成路径统一结果回填并删除重复 DTO、具体 executor 类型分支和旧完成入口；不以所有插件已迁完作为核心集成前置。
5. cancel requested/confirmed 与实际退出分开；取消/逻辑超时/Turn 终态不释放未退出物理槽或仍被使用的插件资源。原 owner 负责输出 drain/完整性，应用负责持久结算，资源 owner 与产物库各按引用完成清理；进程已退出但输出未收尽不可假报完整。原引用释放、未知效果、当前版本重启 reconcile 和 GC 保持现有事实来源，UNKNOWN 不盲重放。QuickJS/PRoot/Root 的真实隔离范围不变。

6. 调用身份与长期资源句柄、控制权和真实存活分离；按真实资源 owner 的期限/引用释放，不能一律随 ToolCall 或 Turn 结束销毁。不同消费者/项目的隔离由显式身份保证，不把句柄当授权。进程死亡可使句柄失效，不承诺自动恢复内存或重放输入。
7. Direct/Observation/Launch-then-observe 只描述当前接线；控制长期资源可走普通具名调用，不强迫持久终端/LSP 变成一次性 Job。保留按具体不可重入资源协调，禁止引入全局 Agent/终端互斥；本轮不新增终端输入或语言服务。

2026-10-16 接续 HXA-297：复用同 Turn 的 modelCallId/callIndex、持久 ordinal/时间与工具批次消息；保持拒绝/取消来源及非模型调用空来源。引用 GC 复用已有索引与单候选发布锁；类型化产物/执行完成语义仍需本任务完成。

优先级 P0：先执行核心和联合 Room，再逐领域。302 已交付手动终端输入/原实例重连/停止及非调试子进程身份可见性修复；迁移保留这些回归，不新增模型输入、不重做终端 UI。资源 owner 必须能说明哪些事实可重建、哪些句柄随进程失效；不得因读取 `/proc` 暂不可见、Binder 断开或没有回包就推定执行未发生。真实退出证据因后端而异，尚不能观察的外部效果明确 UNKNOWN，不能为了字段齐全编造确认。

本任务不包含常驻 stdio 产品、自动安装 CLI 或凭据隔离升级；这些候选只验证现有资源接缝可承接，具体条件见 [Harness §23.12](../../architecture/harness-refactor-plan.md#2312-插件管理与提示审查接续)。每个领域完成时同时核对原子结果提交、引用和待 ACK，产物保存/模型发送/用户成果展示分别证明。

## 替换对象与领域验收

| 当前实现 | 本任务目标 |
| --- | --- |
| ToolDispatcher 的 JobObservationExecutor / JobLaunchWaitExecutor 具体类分支 | 执行形态、效果事实和完成条件由明确契约表达，删除类识别式调度及失败推断；不增加第二 dispatcher |
| JobLaunchWaitExecutor 从 output JSON 提取 originalCallId | 内部类型化执行/Job 引用先绑定原调用；JSON 只作为模型侧结果投影，不承担内部身份传输 |
| ToolVisualFeedback 按 ui.screenshot、FileHistoryPaths 按工具名和 JSON key 判断用途 | 以有来源和用途的产物/资源事实生成模型及 UI 投影；文件标题保持文件名、详情保留完整来源，不修改执行身份 |
| LinuxInputSnapshot 扁平化与顺序后缀、LinuxRunTool 单层 cwd | 以明确源→目标映射、工作副本和路径校验完整替换；默认执行模式依据目标决定，不兼容旧命名或目录限制 |

Mobile Use 紧随最小 Room 联合集成，早于泛化所有后端：同一会话授权 → 新观察 → 动作 → 新观察/事实回填 → 停止及重建。覆盖动作后落盘前 UNKNOWN 不重放、旧 generation/节点/手势凭据拒绝、其他会话不能借用授权；锁屏/断连/模型失败不当作手动撤销授权。主机用受控插件后端验证，实际 Android 服务/浮窗/运行恢复另按当轮授权验证；主机通过不等于设备通过。

[HXA-304](HXA-304.md) 补齐原 Job 收集的模型可读 stdout/stderr、不可用/截断事实及空产物目录的真实表达。迁移须验证“原执行已成功”和“模型实际收到结果”两个边界，保留重复收取不重跑、失败导入按原 receipt 重试的反例；不要求保留当前 JSON 字段、预览 helper 或具体类。

每条路径迁移时立即删除被替换入口和调用者，294 复核无遗留；不得把所有删除留到最终整体验收。
