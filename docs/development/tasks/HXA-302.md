### 图片误读追加诊断

Owner 随后要求优化误读，并确认服务为 SGLang / Qwen3.8 27B；后续检查 safetensors 确认权重为 BF16，纠正此前 FP16 描述，服务信息为 `dtype=auto`、`quantization=null`。已提供启用 EAGLE/MTP 的启动命令，具体版本、各计算/缓存的运行精度与模型 revision 尚未核验。该追加沿用本任务的合成图、已授权模型和日常模拟器范围，不改变生产图片默认值或启动架构重组。

直接调用同一接口也复现误读；原样 Helix Developer Debug 旅程本轮 1/1 通过，故保留历史失败并将总体结论限定为 OCR 不稳定。原图/双倍尺寸的交错小样本分别 2/3、3/3 正确，服务报告图片 token 从 220 增至 880，尚不足以证明全局放大值得采用。正式测试保留原图与原准确性断言，增加显式 `imageScale=2` 诊断入口、规范化尺寸校验及独立模型准确性日志；原来的预览/历史检查仍必须通过。详见同一[验收记录](../../evidence/development/ui-experience-2026-10-16.md#图片误读追加诊断)。

最终完整主机门禁 exit 0，双渠道测试 APK 编译与静态检查通过；新增测试源码的日常 Developer 原图识别失败但预览通过，2 倍图旅程 1/1 通过。测试 APK、截图及转发已清理，原失败保留；准备了仅关闭 MTP 的服务端候选，因没有服务器执行连接尚未运行，不能宣称后端问题已修复。没有提交、推送或发布本轮追加改动。
