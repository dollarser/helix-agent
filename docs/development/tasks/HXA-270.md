# HXA-270：Mobile Use 悬浮审批与等待状态

日期：2026-10-10。Owner报告微信任务打开后一直“正在处理”，要求把审批也放到悬浮窗、方便交互且合理布局。

## 范围与验收要求

仅增加可信原生悬浮审批入口、等待状态同步与查看会话的非取消导航。审批来自请求时的同一 ApprovalCardUi，原 Conversation/Turn/call/approval 身份保持；每次只能本次批准或拒绝，仍由持久调用状态和既有 StorageApprovalBroker/Dispatcher 核实、一次消费、过期及取消约束。FULL_ACCESS 不增加逐动作审批，明确 DENY 不绕过。禁止模型、脚本或外部插件自动批准；原生窗口在锁屏、接管、取消、失效任务和物理操作期间仍不可操作。

宿主将待审批发布给已安装且原会话已选择的对应原生插件，允许第一次调用执行前显示卡片。插件拥有布局；宿主通用接口只投影显示事实及提交明确用户决定，不提供 DAO/执行旁路。缓存不作为权限、恢复或持久状态，进程死亡不重启旧任务。

## 设计依据与取舍

参考 [Copilot Studio inline review](https://learn.microsoft.com/en-us/microsoft-copilot-studio/human-supervision-computer-use)：在活动位置展示等待指示与单次人工响应。本项目继续由确定的 Policy/Approval 管线请求审批，不采用其依赖模型触发监督的授权方式，不复制代码。Android 本地悬浮窗保留不抢焦点/触摸区域边界，审批内容可滚动，批准/拒绝留在内容滚动区域之外，长参数展开查看。

查看会话不等于接管：待审批卡上的“查看会话”只导航，运行状态的“回会话”及“接管”保留原停止语义。按钮绑定显示时的导航模式，审批同时结束也不会把查看详情误变成取消。后台等待标志在审批注册和实际执行开始时更新，避免 RUNNING_TOOL 不变而继续显示“正在处理”。
