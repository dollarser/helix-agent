日期：2026-10-11。状态：实现、主机、双渠道有界API36及Developer真实Qwen通过；其他OEM/长稳边界开放。优先级：P1。依赖：无新增前置任务；复用已交付 R1/R3 与现有 SkillRepository。

Owner request：依据 Agent 插件架构调研、Helix 优化方案与当前代码拆分开发任务并更新计划；所有者追加要求按合理目标架构设计，不兼容旧版。本卡登记未来实现范围，本轮只完成计划，不代表代码或功能验收。执行顺序由 [status](../status.md) 维护。

共同设计基线：单一目标实现，旧入口随对应切片直接替换；不做旧版本、旧数据库、旧会话或旧工具批准迁移，不留双写、双注册与兼容 adapter。开发期存储沿用现行 baseline 重建规则；历史证据仍按原版本解释。原执行身份、权限、取消结算和渠道边界继续有效。

## 当前代码与缺口

核验基线为 `9dbdfece933d2f82c004fe1c5fb8648fe3ac5c66` 加当时工作区。[PluginRegistry.selectedRuntimes](../../../extensions/plugin/src/main/kotlin/com/helix/extensions/plugin/PluginRegistry.kt) 以 `hasPublishedTools` 过滤插件；[instructions](../../../extensions/plugin/src/main/kotlin/com/helix/extensions/plugin/PluginExecutionContext.kt) 从已曝光 descriptor 反查并拼接 bundled Skill。零工具插件因此不能通过这一路径激活。portable Skill 已有 [SkillRepository](../../../extensions/skills/src/main/kotlin/com/helix/extensions/skills/SkillRepository.kt)，不再建立第二套内容库。

## 范围与验收要求

1. 在现有 Plugin catalog 与 SkillRepository 之间建立统一内容贡献接点：APK 捆绑、包内与独立 Skill 都引用不可变内容快照；工具发布、Skill 可用、会话选择分别投影。纯 Skill 包不要求提供 native runtime 或占位工具。
2. 将 native bundled Skill 纳入同一 list/read/resource 路径；保留可定位的来源、包/组件 owner、内容 hash。相同名称不同来源不能覆盖；同一内容多归属按现有引用规则处理，包内 Skill 不借独立全局开关绕过选择。
3. 替换 `PluginBundledSkill` 正文专用通道及按 descriptor 反查的注入路径；[ChatRequestAssembler](../../../app/src/main/kotlin/com/helix/app/chat/ChatRequestAssembler.kt) 消费统一贡献快照，Core 不感知外部 manifest。每次请求仍核对当前选择与已提交 revision。
4. 迁移 Mobile Use 的 Skill 内容注册。必要的短操作指导由同一上下文编译入口表达；此卡先完成内容与选择正确性，长正文切分、缓存与成本策略由 HXA-278 承接。
5. 提供一个零工具流程插件 fixture，覆盖发现→选择→读取→调用已有工具→输出草稿。可使用合成聊天分析场景；现有 `extensions/chat-reply` 为独立 WIP，先核对归属，不依赖或覆盖其未交付实现。
6. 补充纯 Skill 与 native 贡献的最小作者样例，样例使用生产读取器；旧 native Skill 注入入口、对应旧 fixture 直接替换。
