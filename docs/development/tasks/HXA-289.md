## 范围与验收要求

独立能力队列 P2（按实际用户任务可单独提升），动机是让两渠道不借 Shell 也能定位文件和正文。已有 read/write/edit、读取 hash 和写前版本校验由 296 交付；本任务只补定位能力并迁名称搜索，不建设代码索引、向量库、LSP 或桌面文件系统旁路。286 对应契约稳定即可交付，不等待 287/288 全部完成。

1. 实现独立 glob/grep 工具：前者按路径模式找文件，后者查文件正文；整合旧 files.search 的名称匹配职责，不保留等价执行别名。
2. Standard 与 Developer 通过既有 Workspace/授权目录访问，不依赖 Bash、Root 或 PRoot；模型参数不拼成 Shell 命令。
3. 明确字面量/正则、大小写、搜索根、排除规则、编码、二进制处理、行号/上下文与分页/截断；有界扫描可取消，不把截断或读取失败表述为全局不存在。
4. 更新文件整理/仓库阅读 Skill 和描述，结果能回到 read 核对，路径身份、符号链接和撤权规则继续适用。

5. 搜索定位保留 Workspace 来源、内容身份/可用版本和范围单位，沿现有有界 hash/快照机制支持读回核对；扫描中变化或无法确认版本明确反馈，不强制全目录预先哈希。环境路径映射由可信适配器负责，不在 Core 硬编码主机/PRoot 路径或 LSP 协议类型。

## 验证入口

目录发现接续（2026-10-24 需核实差距）：先核对现有选择器过滤，再补确实缺少的来源辨认，使用项目/会话名称、相对子目录、可用状态区分大量/同名来源，完整引用在详情；不删除/搬移旧目录，不因选择而授权。模型搜索结果须带可重新读取的资源/工作副本身份和可确认版本，跨环境同名不能只返回 basename；标题只显示文件名不改变结果定位契约。完成标准含重名跨环境、失效/撤权、cwd 改变后从原命中读回准确字节；结构归 [第 23.3.1 节](../../architecture/harness-refactor-plan.md#2331-目录资源与执行环境)，不新增路径别名表。

- 完成标准：模型能从 glob/grep 的有界、带来源结果进入 read 核对并完成实际定位任务；截断、部分失败和空页不能冒充全量无结果。主机先用同一套普通文件/授权目录夹具，两渠道实际 Document Provider 行为按当次授权单独验证。
- 不确定项：SAF Provider 的遍历/元数据成本、正则实现的时间上界与分页期间目录变化。先测局部实现，不为兼容所有 Provider 预建全盘索引；无法形成稳定游标时明确快照/重新扫描语义。

- 补同路径文件内容变更、不同 Workspace 同名、搜索后撤权与环境映射错误；陈旧行号/片段不可直接用于后续修改，先重新读取。无需安装语言服务器。

- 文件夹具覆盖嵌套目录、Unicode、空结果、二进制/编码、大文件、正则资源边界、路径越界、授权撤销与取消；断言结果可读回，不写实现镜像测试。
- 冻结找文件/定位条款任务，按授权进行双渠道及模型验证；新增搜索能力的收益不归因于改名。
- 开始实施时定位现有测试入口并按改动选择回归；目标契约可替换旧实现镜像断言，权限、持久原子性、取消、真实退出与恢复反例不得丢失。设备/服务须按当前 AGENTS 核对范围与配置；本段是原验收要求，实际执行见下方日期记录。

## 2026-10-26 当前实现与契约

原生 `glob` / `grep` 替换模型 `files.search`，无旧工具别名。文件管理 UI 的名称筛选仍是有效功能，不因删除模型入口而移除。两渠道共用 WorkspaceArtifactStore 的 list/stat/openRead，参数先绑定请求目录，再由原权限分类及 Dispatcher 执行，不依赖终端。

- glob 按相对路径匹配 `*`、`?` 和独立 `**` 段；其他字符为字面量。默认大小写敏感，可显式 ignoreCase。点文件包含在内；exclude 最多八个模式，匹配目录则剪枝。仅返回文件。
- grep 是明确的 `grep -F` 字面量搜索，query 不跨行；本片不开放正则，拒绝 regex 参数，不用存在失控回溯风险的 JVM 正则或引入新依赖冒充有界执行。UTF-8、单文件 256 KiB、累计读取 8 MiB；二进制/非 UTF-8/超限文件列入跳过计数。返回一基行号、最多 240 字预览和同一完整读取流的 SHA-256；定位不是后续写入许可，修改前仍须 read 重验。
- 单次遍历至多 20000 项、每页最多 100 命中，沿原 deadline/cancel；不跟随符号链接。输出带原 scope 路径、glob 的未知内容版本、grep 的已读内容哈希，未读/跳过/截断和 complete 分开。
- offset 是有界重新扫描，不是目录快照或长期稳定游标；仅结果页溢出提供 nextOffset。目录变化可使页移位，遇扫描/读取上限须缩小根或模式。空的不完整结果不证明不存在，源内容变化或撤权后不能沿旧行号直接修改。

验证和实际模型边界见[本轮收尾](../../evidence/development/native-search-and-knowledge-closeout.md)。未引入全文索引、语义检索、工作区新映射或新的权限授予路径。

## 2026-11-12 真实 SAF 与自主定位接续

- Standard／Developer 在日常 API36 模拟器的独立 `.asrvalidation` 包通过系统 DocumentsUI 授权新建的合成目录，实际 ExternalStorageProvider 上验证 glob／字面量 grep，不再用旧名称筛选或 NIO 夹具冒充。覆盖 Unicode 嵌套同名、分页、特殊字符字面量、原 scope 读回和完整流 SHA-256、同路径内容变化、二进制跳过导致不完整空结果、scope 撤销拒绝及重新授权；原目录双向同步／冲突回归同时通过。每渠道一项集成测试，零跳过。测试结束释放精确 URI 授权并移除自建子树／空目录。
- 修复最后一次 Provider 调用返回后的取消／deadline 结算：空目录最后一次 list 在截止或取消之后返回，旧实现会错误报告 `Completed/complete`。新增两项 JVM 回归先在旧实现失败，再以最终 checkpoint 修复；不声称能够强制中断不合作的 Provider 或提前释放物理执行容量。

- 原始红／绿回归、双渠道构建与安装哈希、设备 JUnit 位于忽略的 `build/saf-native-20261112/`，模型诊断在 `build/file-location-model-20261112/`。首次设备启动因构建未选择隔离 runner，在测试执行前失败；纠正参数后双渠道通过，没有据此改产品逻辑。

## 2026-11-16 自主验收与搜索专项分离

真实 Luna 文件定位已完成：通过实际文件读取取得初始提示中不存在的随机证据，答案有持久执行结果及后续模型消费支撑。旧用例同时要求 glob、grep 都命中目标，导致业务 Turn 完成但专项覆盖断言失败；未调用某工具不能据此判断工具故障。

- `FileLocationModelDeviceTest#autonomouslyLocatesCurrentReleaseEvidence`：`fileLocationModelAcceptance=true`，保持自然任务提示，允许任意搜索策略；以完成的 Turn、实际成功读回且模型消费的随机证据、准确路径及 Rollback 答案验收，不要求 glob/grep。
- `FileLocationModelDeviceTest#consumesGlobAndGrepResultsToLocateEvidence`：`fileLocationSearchToolsAcceptance=true`，在提示中明确要求 glob 与 grep 分别命中目标并经 read 核对；保留原有搜索完整性、成功执行和实际消费断言，不以自主任务的成功替代专项覆盖。
- 证据分别记录 `turnCompleted`、`taskPassed`、`searchCoveragePassed` 与 `acceptancePassed`，`completed` 表示当前测试验收完成，避免将断言失败误读为业务未完成。离线证据反例覆盖未调用工具、未回填结果、错误 callRef、提示预置答案、未完成 Turn 和不完整答案。
