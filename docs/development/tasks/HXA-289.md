## 2026-10-24 当前裁决

当前 `FilesSearchTool` 仍为有界名称子串的 files.search；glob/grep 是尚未交付的新能力，不是恢复文件读写的架构缺陷。目录选择器已有过滤/来源显示在实施前逐项复核，未核实部分不直接登记为缺失。

这是独立能力/验证队列，不是所有结构重构的启动或完成条件。本轮只调整计划，未实施代码或补做设备/服务验收。

## 范围与验收要求

独立能力队列 P2（按实际用户任务可单独提升），动机是让两渠道不借 Shell 也能定位文件和正文。已有 read/write/edit、读取 hash 和写前版本校验由 296 交付；本任务只补定位能力并迁名称搜索，不建设代码索引、向量库、LSP 或桌面文件系统旁路。286 对应契约稳定即可交付，不等待 287/288 全部完成。

1. 实现独立 glob/grep 工具：前者按路径模式找文件，后者查文件正文；整合旧 files.search 的名称匹配职责，不保留等价执行别名。
2. Standard 与 Developer 通过既有 Workspace/授权目录访问，不依赖 Bash、Root 或 PRoot；模型参数不拼成 Shell 命令。
3. 明确字面量/正则、大小写、搜索根、排除规则、编码、二进制处理、行号/上下文与分页/截断；有界扫描可取消，不把截断或读取失败表述为全局不存在。
4. 更新文件整理/仓库阅读 Skill 和描述，结果能回到 read 核对，路径身份、符号链接和撤权规则继续适用。

5. 搜索定位保留 Workspace 来源、内容身份/可用版本和范围单位，沿现有有界 hash/快照机制支持读回核对；扫描中变化或无法确认版本明确反馈，不强制全目录预先哈希。环境路径映射由可信适配器负责，不在 Core 硬编码主机/PRoot 路径或 LSP 协议类型。

## 验证入口

目录发现接续（2026-10-24 需核实差距）：先核对现有选择器过滤，再补确实缺少的来源辨认，使用项目/会话名称、相对子目录、可用状态区分大量/同名来源，完整引用在详情；不删除/搬移旧目录，不因选择而授权。模型搜索结果须带可重新读取的资源/工作副本身份和可确认版本，跨环境同名不能只返回 basename；标题只显示文件名不改变结果定位契约。完成标准含重名跨环境、失效/撤权、cwd 改变后从原命中读回准确字节；结构归 [§23.3.1](../../architecture/harness-refactor-plan.md#2331-目录资源与执行环境)，不新增路径别名表。

- 完成标准：模型能从 glob/grep 的有界、带来源结果进入 read 核对并完成实际定位任务；截断、部分失败和空页不能冒充全量无结果。主机先用同一套普通文件/授权目录夹具，两渠道实际 Document Provider 行为按当次授权单独验证。
- 不确定项：SAF Provider 的遍历/元数据成本、正则实现的时间上界与分页期间目录变化。先测局部实现，不为兼容所有 Provider 预建全盘索引；无法形成稳定游标时明确快照/重新扫描语义。

- 补同路径文件内容变更、不同 Workspace 同名、搜索后撤权与环境映射错误；陈旧行号/片段不可直接用于后续修改，先重新读取。无需安装语言服务器。

- 文件夹具覆盖嵌套目录、Unicode、空结果、二进制/编码、大文件、正则资源边界、路径越界、授权撤销与取消；断言结果可读回，不写实现镜像测试。
- 冻结找文件/定位条款任务，按授权进行双渠道及模型验证；新增搜索能力的收益不归因于改名。
- 开始实施时定位现有测试入口并按改动选择回归；目标契约可替换旧实现镜像断言，权限、持久原子性、取消、真实退出与恢复反例不得丢失。设备/服务须核对当次授权与配置，本轮未执行。
