### 接线前必须覆盖的边界

- 调度器当前只保留 ToolCall 执行期间的互斥。异步 start 返回后，后台 Job 的未知文件/代码效果不能随着调用槽位释放而消失；复用持久 Job 身份与统一效果准入，覆盖跨 Turn、跨会话和主进程重启，不另造业务工作流。
- Goal 的 `remainingExecutionMillis` 是运行时窗口。后台命令提交须扣除快照、连接与排队耗时，且在 Turn 已返回后继续受其已分配预算约束；不能通过重新查询续租。
- Goal 的当前 TIME heartbeat 与后台 Job 的存活区间可能重叠。接线须明确持久预算预留和结算归属，既不漏掉 Turn 返回后的执行，也不把重叠区间重复计费；不能简单把整个租期再加到已有 Goal 时间上。未知副作用恢复与既有 Goal 完成标准保持。
- 现有结果恢复只识别同步 `bash`/`code.linux.run`，并检查 Turn/ToolCall 的恢复资格。异步启动成功必须与 Job 最终成功分开，按原绑定查询、导入与取消，不把 start 的成功回执当作执行终态。
- 已补客户端绑定耗时扣租期，低于最小窗口时不提交。机制与证据见[本轮 Runtime 修复](../../bug-fixes/2026-09-18-runtime-streaming-terminal-and-lease.md)。三项生产接线仍待实现，不能仅注册 start/status/cancel 后宣告完成。

## 2026-09-19 Goal 后台时间账本

既有用量表增加 `TIME_LEASE` 类型，不新增表或另一套 Goal 状态机。租期最多预留 30 分钟并受 Goal 剩余时间限制；同一 run 的普通 TIME 与 TIME_LEASE 不可同时占用计时权，调用方必须显式转移原窗口。部分 checkpoint 使用累计观察时长，减去已结算值后再增加 Goal 用量；重复/较旧观察不重复收费，终态释放未消费容量。观察到的取消超时仍完整记录，不静默截断。

普通 Turn 终态不再把仍 pending 的后台时间预留按进程死亡处理，Goal run 保持待结算；原 Job 结算后再次调用既有 `GoalRunSettlement`，沿原来的完成/暂停标准收口。进程死亡恢复则一次性消耗未知工作的剩余预留，不累加离线墙钟、不重复收费或重启命令。用量、预留和审计仍在同一 Room 事务内；失败回滚两边。字段语义已在 `GoalUsageReservationEntity` 注明，表结构不变。

## 2026-09-19 原 Job 控制准入

`ExecutionOwnership.controlExecutor` 为宿主提供绑定控制执行器：仍由 Dispatcher 的 executor guard 获得准入，不能直接执行；可信 resolver 先校验原身份，有持久 owner 时仅匹配的 generation 可查询/取消。无 owner 的历史查询也占用普通执行许可。跨宿主实例、外来 owner、取消和查询异常都不释放原占用；结算清除身份后，当前许可退出前仍拒绝其他执行。普通工具不因名称、只读分类或模型参数获得豁免。

`DetachedJobControl.create` 连接 Room 的 `resolveDetached` 与真实 Runtime query/cancel，输入使用可信当前会话和原调用 ID，返回有界执行事实及 `settlementPending`。再次核对返回的 job/execution/inputHash，不重跑、不续租、不导入产物、不因进程终态自动清除占用。输入原绑定不存在或属于其他会话时，在访问 Runtime 前拒绝。

**接线范围**：这是可执行的宿主控制组件，尚未注册为模型工具或接入 Tasks。异步启动、Goal 预算与最终产物结算须整合后才可宣称后台产品功能完成。

## 2026-09-19 异步启动执行器

`DetachedJobLaunch` 复用现有 `LinuxInputSnapshot`、环境筛查与授权复查接口，准备输入后由宿主回调持久化原绑定并分配预算，再转移当前调用的独占执行身份，最后通过真实 `DetachedJobClient` 提交。返回 accepted 只表示接收，不表示执行完成，不自动继续 Goal。租期同时扣除快照、宿主准备、占用落盘、PFD 打开和客户端绑定耗时，不能通过提交阶段延长已分配窗口。

宿主临时目录只保存输入快照，提交后清理；输出接收端使用 `/dev/null`，最终归档仍由 Runtime 的既有结果存储持久化并按原 Job 查询和校验。确认未启动的拒绝先调用宿主拒绝结算，再通过原活跃启动许可释放占用；该许可退出前其他执行仍不能进入。未知、非法或不识别的返回保留原占用并要求核对原调用，不重放命令。

接线审查修正 Runtime 返回语义：提交交接给 runner 后发生异常，返回 `REPLY_JOB_UNAVAILABLE`，不能把可能已经执行的 Job 伪装成拒绝启动；交接前失败仍可返回明确拒绝。通用 `INVALID_SPEC` 不作为释放宿主占用的无副作用证明。

**当前边界**：执行器已有真实 Runtime 启动/产物获取的设备验证入口；预算 prepare/reject 仍是必须由宿主接入的回调，尚未连接真实 Goal 计时器，也没有模型工具注册、Tasks 展示和产物最终导入结算。测试使用现有同步参数解析器驱动执行器，不能据此宣称新的后台工具契约已交付。
