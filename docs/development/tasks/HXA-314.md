# HXA-314：最小定时 Agent 生命周期

## 范围与验收要求

Owner“帮我完成上述工作”包含定时 Agent；在知识库检索问答、确认式自然语言提醒后继续本阶段。真机手测延后，不是取消开发。保留已有资料、配置和版本，不 push/发布，不启动整套 Harness 重构。

- 用户明确选择已有会话，输入任务/固定时区/一次或日周月日历，核对模型目标、会话当时上下文、工作区、权限/工具范围和预算后保存/启用；不自动创建用户任务。首版仅 PLAN 只读分析/检索，保留现有闭合元数据准入，不授权文件写入或外部副作用；不支持订阅 CLI。
- Room 持久规则/revision、发生三元组、冻结授权及每次新 attempt；时钟只提供三元组，重复/过时/提前事件不能重复执行。绑定结果会话，不跟随前台；通过现有 AgentRuntime/Dispatcher，模型输出或来源资料不授予权限。
- 每次模型请求（含压缩）重新核对原模型/传输目标、实际工作区快照、工具绑定及当前权限配置；配置变化需重新确认。规则级最大运行时长显式确认（初始 120 秒可编辑，没有统一两分钟硬上限），预算纳入授权 hash 和发生快照，编辑只影响未来发生项；单次请求输出上限 2048 token、最多 32 条启用规则；不虚构累计调用次数预算。
- 近似 WorkManager 唤醒，系统可延迟。迟到超过 15 分钟记录并跳过，重复按原日历推进，无补跑风暴；忙会话跳过。暂停未来与停止当前是两个动作；真实 executor 退出前不释放容量，不宣称取消回滚效果。
- 进程重启只观察已有 Turn/审计事实，INTERRUPTED/UNKNOWN 不自动重试。显式重试用新 attempt，仍归原发生/范围/会话；活动执行、未决副作用和 NEEDS_REVIEW 不能绕过。WorkManager 没有模型重试策略。

## 验证入口

先格式/静态，后双渠道 JVM、storage、lint、Debug/AndroidTest/R8 与源码门禁。日常 API36 ARM64 用隔离数据库、合成任务验证确认前无效果、时钟去重、范围变化、错过/忙/恢复、当前执行取消与物理退出、新 attempt 重试、前后台结果归属及 UI。真实已配置内置 Qwen 仅合成安全任务，不读取私人材料或执行外部副作用。真机延后；不清数据、不改时间/权限、不录音或播放。

## 交付
