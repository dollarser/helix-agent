# HXA-230：Markdown-native Hierarchical Agent Memory

分类：已规划 / 条件实施。格式、Memory tool 与 global scope 可先设计；完整 project auto-memory 在稳定 Project identity 前不得把 `directoryRef` 临时固化为永久 identity。建议 HXA-227 baseline 后实施，以便量化 Memory 对 Agent 轨迹的真实影响。详细调研见 `docs/research/agent-memory-and-activity-presentation-2026-09-26.md`。

## 背景

CodeBuddy、Claude Code、OpenAI Sandbox Agents 等都把长期 Agent knowledge 组织为 Markdown / text artifacts，并普遍区分 global/user、project 与 session/transcript。

Helix 应采用 Markdown-native memory，而不是在 Room 中保存一份与 Markdown 竞争的语义正文。

## 范围与验收要求

本任务建立 Markdown-native Global/User + Project Memory 的文件布局、受限 Memory tools、progressive disclosure 与可重建索引；不把 conversation transcript、Turn/Goal state 或 Room 正文当作长期 Memory。完整 Project auto-memory 只有在稳定 Project identity 可用后才启用。验收要求是 Memory 可直接人工查看/编辑、跨会话持久、scope 不串项目、Context Builder 有界注入、索引可重建，并能使用 HXA-227 baseline 对开启/关闭 Memory 做 A/B。

## 核心原则

1. **Markdown 是 semantic source of truth。**
2. Room/索引只做可重建 metadata/search cache。
3. Global/User Memory 与 Project Memory 分层。
4. Session/Turn/Goal durable state 不是第三份长期 Memory。
5. Progressive disclosure：summary → MEMORY.md index → relevant topic。
6. Model 可以主动维护 Memory；写入必须可见、可编辑、可删除。
7. 工具/网页/MCP 内容不能未经判断直接 durable 写入，防 memory poisoning。
8. Project Memory identity 不先绑死当前 `directoryRef`。

## A — Layout

默认 app-private：

```text
memory/
  global/
    memory_summary.md
    MEMORY.md
    user.md
    feedback.md
    references.md

  projects/
    <project-id>/
      memory_summary.md
      MEMORY.md
      architecture.md
      decisions.md
      workflows.md
      pitfalls.md
      references.md
```

以后可增加 raw extraction/consolidation 目录，但不作为首版必须。

默认不自动修改 git repo。

## B — Markdown format

Topic file 可使用 YAML frontmatter：

```markdown
---
name: Provider architecture
description: Stable provider/runtime decisions for Helix
type: project
updated_at: 2026-09-26
---

- On-device llama.cpp is a LocalInferenceRuntime backend.
- Do not model direct local runtime as localhost HTTP.
```

首版 type 至少参考成熟实践：

- user；
- feedback；
- project；
- reference。

## C — Scope

### Global/User

适合：

- 跨项目稳定偏好；
- 用户明确反馈；
- 一般工作习惯；
- 全局安全/工作流偏好。

### Project

适合：

- 架构决定；
- build/test 命令；
- 项目坑点；
- 项目长期工作背景；
- 已验证环境事实。

例如 JDK17/PRoot assets 属于 Helix Project Memory，不属于 Global。

## D — Progressive disclosure

Context Builder：

1. 有界加载当前 scope 的 `memory_summary.md`；
2. 根据用户请求/当前 project 选择 relevant topics；
3. 必要时再打开 `MEMORY.md` 或 topic file；
4. 每次最多注入有界数量/字节，不全量 preload。

首版可以先用 lexical search + frontmatter + recent/verified weighting；embedding 后续再做。

## E — Memory tools

建议内建受限 tools：

```text
memory.list
memory.search
memory.read
memory.write
memory.edit
memory.delete
```

这些工具只操作 memory root，不等同任意 filesystem 权限。

模型可以：

- 用户明确“记住”时立即写；
- 发现稳定 project lesson 时主动写/更新；
- 修正 stale memory；
- consolidate MEMORY.md。

Global auto-write 默认比 Project 更保守，可由设置分别控制。

## F — Auto extraction / consolidation

首版优先“主 Agent 主动写 Memory”，因为它最理解当前任务和纠正。

后续可增加：

- turn/session end sidecar extraction；
- raw memories；
- consolidation；
- dedup/stale cleanup。

参考 OpenAI Sandbox Memory 的 extract → raw → consolidate 和 Cursor sidecar pattern，但不要求首版一次完成。

## G — Index / Room

允许可重建 index：

```text
scope
projectId
path
title
type
description
contentHash
mtime
lastIndexedAt
```

正文不复制进 Room 形成另一份 canonical content。

索引删除后可从 Markdown 全量重建。

## H — Project identity

完整 Project Memory 必须依赖稳定 `ProjectMemoryScopeKey`。

HXA-210 / ADR-WORKSPACE-004 未稳定前：

- 不用 directory path hash 作为长期契约；
- 可先交付 global memory；
- 可交付 project-memory API/layout，但 production project auto-write 保持 disabled；
- 稳定 ProjectId 到位后再打开。

## I — UI

Session `+ → Reference → Memory` 只有 HXA-230 backend 可用时显示。

Memory 管理至少支持：

- Global / Current Project 切换；
- 搜索；
- 查看 Markdown；
- 编辑；
- 删除；
- auto memory 开关；
- 查看来源/更新时间（如有）；
- export/import。

## J — 安全

- memory content 是 untrusted context，不获得 Tool permission；
- 从网页/Connector/MCP 提取的 memory 保留 source/trust 信息；
- 不记 secret/credential；
- global auto-memory 防止 project-specific contamination；
- project memory 默认不跨项目；
- 删除同步更新 index/cache；
- prompt injection 不能直接写 durable memory，至少需要 Agent memory policy 判断。

## 验证入口

- Global/Project Markdown 物理隔离；
- MEMORY.md/topic files 可直接人工编辑；
- index 删除后可重建；
- Context Builder 不全量注入；
- explicit remember → durable Markdown；
- project lesson 不进入 global；
- global preference 在多个 project 可读取；
- Memory 不改变 Tool permission；
- stale memory 可编辑/删除；
- project identity 未就绪时 fail closed；
- Memory 开启前后的 HXA-227 fixed eval 可做 A/B。

## 交付

- Markdown memory root/layout 与 YAML frontmatter contract；
- Global/User Memory 首版；
- Project Memory scope API 与 fail-closed Project identity seam；
- `memory.list/search/read/write/edit/delete` 受限工具；
- `memory_summary.md` / `MEMORY.md` / topic progressive-disclosure Context Builder；
- 可重建 metadata/search index，不保存竞争性正文；
- Memory 管理 UI 与 auto-memory scope 开关；
- HXA-227 baseline 上的 Memory off/on A/B 证据；
- 完成时写 `docs/completion-records/HXA-230.md` 并更新 status/roadmap/index。

## 非目标

- 不把 conversation transcript 改成 Memory；
- 不用 Room 作为正文 canonical store；
- 不自动 commit Memory 到用户 repo；
- 首版不引入向量数据库依赖；
- 不借 Memory 实现 HXA-210 Workspace；
- 不把 Memory 当权限/事实证明。
