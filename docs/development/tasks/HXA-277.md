# HXA-277：原生插件资源归属与停止释放契约

日期：2026-10-11。状态：已排期，未开工。优先级：P2。依赖：HXA-276 的真实 Browser 贡献；已有 HXA-235 提供安装与引用规则，外部设备补验不是主机前置。

Owner request：依据两份插件研究文档和当前代码更新开发计划；按单一合理目标实现设计，不兼容旧版。本轮只登记任务，未实施或验证功能。当前顺序由 [status](../status.md) 维护。

共同设计基线：直接替换所涉旧入口，不做旧版本、旧数据库、旧会话或旧批准迁移，不保留双写/双注册和兼容 adapter。开发期存储沿用现行 baseline 规则；历史证据保留原含义。原执行身份、权限、取消结算和渠道边界继续有效。

## 当前代码与缺口

[HelixPlugin / PluginRegistry](../../../extensions/plugin/src/main/kotlin/com/helix/extensions/plugin/PluginRegistry.kt) 有内容、工具、scope 和呈现接点，没有统一的实例注册释放契约。Browser、Mobile Use、MCP 已有各自生命周期，不应由接口缺项推断所有资源都未清理。R3 安装提交和共享快照引用由 HXA-235 已实现。

## 范围与验收要求

1. 围绕 Browser/Mobile Use 的实际引用、监听器、任务呈现和连接，列出宿主服务、插件贡献实例、会话与调用的资源 owner。保留 Activity 的 WebView 所有权和宿主的系统授权所有权。
2. 为确实持有资源的原生贡献提供可释放注册句柄及明确的使用引用；无资源的纯 Skill 不创建空实例。只提取当前两个消费者实际需要的最小 port，不引入通用服务定位器或依赖求解框架。
3. 按顺序处理：撤下新准入→原调用按原身份结算→最后引用释放→实际清理完成。取消请求不等于 executor 已退出；停用一个消费者不关闭仍被使用的共享后端。
4. 对旧实例回调、并发启停、初始化局部失败、清理失败和宿主重建定义确定结果；清理失败保留定位事实，不能报告已回滚外部副作用或让旧实例修改新实例。
5. 跨插件工作流继续由 Skill/Agent 调用原工具；可信共享服务携带原会话、目标与调用上下文。复合工具不得绕过 Dispatcher 直接执行另一插件的 executor。
6. 只提供本卡所需的类型化结束/撤销通知，写明顺序、超时和错误；替换重复的非归属回调。不建立任意脚本 hooks、Cordis 容器或每插件 server 管理器。
7. 按真实调用链记录四类事实的 owner 和释放条件：TurnEngine live owner、ToolScheduler 调度/观察槽位、Executor/Runtime 实际容量及原执行身份、插件/宿主共享引用。原 Runtime 保持退出与结果权威，插件消费其事实；不新增执行注册表、取消协议或第二份 Job/Turn 状态机。调度等待完成、Turn 终态、页面销毁均不能单独证明实际执行退出或关闭共享资源。

## 实施切片顺序

1. HXA-276 的真实 Browser 贡献接线后，盘点其与 Mobile Use 的资源引用、具体 owner 和现有退出/对账事实；无资源的组件不创建实例。
2. 接入最小注册/使用句柄，原 Scheduler、ExecutionOwnership 和 Runtime 继续负责各自边界；只为原生贡献补引用与停止释放接点。
3. 逐项替换生命周期回调，处理新准入撤销、在途调用与最后引用释放；保留准确实例身份和迟到回调拒绝。
4. 覆盖跨层取消/退出、共享消费者和清理失败；完成后 HXA-279 复用该 owner/引用契约，不建立平行观察生命周期。

## 契约与既有任务分工

2026-10-11 已明确 ADR 归属并同步 accepted 决定：[ADR-CONNECTORS-003 §11](../../adr/connectors/003-ownership-and-installation.md#11-原生实例共享资源与释放hxa-277)拥有通用实例、共享资源、句柄及停止释放规则；[ADR-PLATFORM-002](../../adr/platform/002-browser-lifecycle.md)拥有 Browser View/观察引用，工具准入沿用 [ADR-TOOLS-001](../../adr/tools/001-descriptor-contract.md)。[Harness §15.5](../../architecture/harness-refactor-plan.md#155-生命周期与引用释放)保留执行接线说明。HXA-235 继续拥有持久安装、旧快照引用、取消更新、卸载和进程死亡验收；本卡拥有新增原生实例/共享服务释放。相交 fixture 只维护一份，结果分别引用，不重做 R3 或自动关闭它的完整设备矩阵。

系统分层复核追加的四类 owner 边界见 [ADR-AGENT-001](../../adr/agent/001-turn-coordination.md) 与[源码分析](../../research/modules/01-architecture-and-execution-engine.md#9-2026-10-11-分层复核与优化承接)；HXA-238 的实际执行容量及 HXA-236/248 的 Job 观察/等待机制继续复用，不重新立项。

## 验证入口

实施时运行本卡涉及的现有主机回归、全仓 source/JVM/静态检查及双渠道 Debug lint、APK、AndroidTest APK 编译，具体命令沿用[公共验收](../verification-matrix.md)。下列设备/模型场景是后续验收要求，本次均为 **not requested**；只能在当轮明确授权后执行，缺少输入不伪报通过，也不阻塞无依赖的主机工作。

- 主机可控实例覆盖重复启停、同名新实例、迟到回调、两个消费者共享、在途撤销、初始化失败和清理失败；证明最后使用者退出前资源未关闭。
- 对实际 executor 尚未退出的取消场景，容量和资源引用均保持，退出后仅释放一次；失败不能被 catch 后报成功。
- 使用既有可控 Runtime/执行 fixture 覆盖“等待结束但原 Job 在运行”“Turn 已结算但 executor 尚未退出”“UI 已销毁但另一消费者仍持有引用”；分别断言调度槽位、执行容量、原身份与插件引用，不能只检查 Future/Job.isActive 或一个 busy 布尔值。
- 后续设备验收覆盖 Browser owner 替换、Mobile Use Stop/接管/会话切换及有界资源计数；限定任务/API/渠道，不用短跑推导长稳。
- 完成时每种实际持有资源有 owner 和释放证据，无备用旧生命周期或通用 hook 执行旁路。
