# HXA-278：Skill 渐进装载与上下文失效一致性

日期：2026-10-11。状态：已排期，未开工。优先级：P2；策略效果需独立证据。依赖：HXA-272、HXA-273；推荐 HXA-275 后冻结格式和样例；技术上不依赖 HXA-276/277。

Owner request：依据两份插件研究文档和当前代码更新开发计划；按单一合理目标实现设计，不兼容旧版。本轮只登记任务，未实施或验证功能。当前顺序由 [status](../status.md) 维护。

共同设计基线：直接替换所涉旧入口，不做旧版本、旧数据库、旧会话或旧批准迁移，不保留双写/双注册和兼容 adapter。开发期存储沿用现行 baseline 规则；历史证据保留原含义。原执行身份、权限、取消结算和渠道边界继续有效。

## 当前代码与缺口

现有 [PluginExecutionContext.instructions](../../../extensions/plugin/src/main/kotlin/com/helix/extensions/plugin/PluginExecutionContext.kt) 拼接 bundled Skill；[ChatRequestAssembler](../../../app/src/main/kotlin/com/helix/app/chat/ChatRequestAssembler.kt) 与 [PromptEnvironmentSections](../../../app/src/main/kotlin/com/helix/app/chat/PromptEnvironmentSections.kt) 将其加入请求。HXA-272 先统一来源，此卡才改变正文装载、内容分层和失效策略。现有 R2-A/ContextCompiler 与 HXA-252 的工具发现提示不重做。

## 范围与验收要求

1. 冻结同一代码/模型/任务的基线，区分目录、必需短指导、已激活正文、按需资源和历史引用；为 Mobile Use 与 Browser 提供可读的短入口和独立长参考资料。
2. 元数据用于发现，正文经统一 Skill 读取/显式激活装载；同一任务同一快照避免无意义重复。复用现有 ContextCompiler、内容 hash 与历史，不新增第二份上下文或 Skill 状态库。
3. 更新、停用、选择撤销和目录清空后，后续候选及自动注入正确失效；在途请求和历史保留原身份，不能承诺模型忘记已见内容。
4. 压缩/恢复时保持当前任务必要指导与准确版本引用；缺失、版本变化或预算不足时明确诊断/重读，不静默读同名最新内容。
5. 保留每次 UI 操作需要的短规则，移出长例子；直接替换生产旧全文注入路径。对照使用固定基线制品/fixture，不在生产保留双实现或兼容开关。
6. 以相同任务比较完成率、无效工具调用、发现往返、输入 token 与耗时；未获真实模型输入时完成主机正确性和候选准备，效果项保留边界，不提前称为收益。

## 契约与范围边界

这是 R2-B 内容策略增量，2026-10-11 已同步 accepted [ADR-SKILLS-001](../../adr/skills/001-authoring-and-installation.md) 的装载/失效/压缩规则，[Harness §16](../../architecture/harness-refactor-plan.md#16-contextcompiler-与可独立运行的-agent-core)保留上下文接线说明；不顺带改 tools.search 排名、16 项窗口、64 hard cap、模型编码或审批。只有实际对照支持的策略才计为收益交付。

## 验证入口

实施时运行本卡涉及的现有主机回归、全仓 source/JVM/静态检查及双渠道 Debug lint、APK、AndroidTest APK 编译，具体命令沿用[公共验收](../verification-matrix.md)。下列设备/模型场景是后续验收要求，本次均为 **not requested**；只能在当轮明确授权后执行，缺少输入不伪报通过，也不阻塞无依赖的主机工作。

- 扩展 SkillRepository/Tools、[ContextRequestTest](../../../app/src/test/kotlin/com/helix/app/agent/ContextRequestTest.kt) 与上下文编译回归：空目录、重复装载、同名不同 hash、停用/更新、压缩失败/恢复、预算不足和用户调用资格。
- 新请求不再次自动注入失效正文，历史 tool-call 配对和引用不被删除或改写；压缩模型也遵守原出网与预算规则。
- 后续模型对照至少覆盖纯流程草稿、Mobile Use、Browser 三类合成任务，预先固定重复次数与成功判据，保留每轮失败、分母和所有人工介入；测试账号/设备另按当轮授权。
- 正确性与策略收益分别记账。若收益未证实，保留测量结论，不宣称“减少 token 即提升成功率”。
