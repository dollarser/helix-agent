# HXA-217：请求上下文清单与 JSONL 可追踪性

分类：待决策（P2，规格完成，未实施）。前置：proposed [ADR-AGENT-010](../../adr/agent/010-request-context-manifest.md) 接受；HXA-211 导出基线与 HXA-216 的输入/请求身份契约。216之前可做只读格式评审，最终功能验收必须包含实际 steer，不用虚构 input IDs 代替。

## 用户结果与范围

在一次模型调用详情中查到该次请求用了哪些消息、摘要、工具目录和输入，区分准备、启动、完成与未知状态；导出的 JSONL 包含同一证据。气泡展示保持简洁；清单不冒充完整 wire request 或模型理解证明。

允许模块：`app/agent`、`app/chat`/既有调用详情与会话导出、`core/model`/`core/storage`、导出解析器/测试；Provider 只提供 adapter 标识和 loopback 验证。禁止收集认证字段、持久复制全部提示/图片、上传遥测或添加 Agent 调试 Tool。

## 实施切片

1. **版本与存储**：定义逻辑清单、ModelCall 引用/生命周期映射、缺失/不完整/淘汰状态；旧数据迁移保持“未采集”。正文独立 ContentRef，审计只带有界索引。
2. **捕获位置**：最终压缩/附件物化/容量准入后、Provider 前记录；普通生成、摘要请求和 steer 首次接入都覆盖，来源 IDs/顺序不可从调用结束后的数据库倒推。
3. **配额与删除**：1 MiB 单条/64 MiB 总量及极限来源列表；仅淘汰已终结调用的诊断正文，清单失败不单独阻断合法请求。删除会话和引用清理无悬挂/误删原消息。
4. **详情和 JSONL**：按需查看，不展开到正常聊天；扩展格式版本、记录类型及兼容解析，明确 prepared/started 与远端确认区别、旧版缺失/淘汰提示。
5. **对照验收**：实际 loopback 请求与清单一一核对，恢复/故障/导出全链闭环。

## 范围与验收要求

新增 `RequestContextManifestDeviceTest`、`RequestManifestExportDeviceTest`、`RequestManifestRecoveryDeviceTest`；补 JSONL parser 版本兼容单测。这些均为待实现要求。

- 普通多轮、工具批、附件、压缩摘要、fork/编辑后发送、Queue/Steer 的来源顺序与真实请求一致。
- 三类 Provider 的逻辑数据与序列化请求正确对应；不把 adapter 包装差异说成清单错误，不宣称哈希可还原全文。
- pending 输入未使用时不标已纳入；同一输入多次作为历史使用有不同 modelCallId，首次消费不重复。
- 旧数据无清单、单条超限、总体淘汰、磁盘写失败、导出中删除/取消，准确显示缺失且不损坏消息与执行结算。
- Token/Secret/认证头/含凭据地址不落清单、日志、JSONL；附件只引用/hash，不复制字节。
- 实际进程在 prepared/started/终局之间死亡，对照服务端捕获与本地状态，unknown 不伪装已完成或自动重放。
- 四象限真实导出 UI、JSONL 独立解析、旧版本容忍/未知版本拒绝规则、配额与会话删除。
