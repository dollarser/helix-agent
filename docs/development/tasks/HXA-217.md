# HXA-217：轻量请求来源记录与 JSONL 可追踪性

分类：待决策（P2，轻量版规格完成，未实施）。前置：proposed [ADR-AGENT-010](../../adr/agent/010-request-context-manifest.md) 接受；HXA-211 导出基线与 HXA-216 输入/请求身份契约。格式和成本评审可提前，最终验收必须包含真实 Queue/Steer，不用虚构 input IDs 代替。

## 用户结果与范围

通过导出记录核查某次请求实际采用的消息、修订输入和压缩检查点。请求时保存最小依据，读取时按引用组合内容；普通聊天不展示协议。首期只做内部只读查询和 JSONL，不开发调用详情页，不保存完整请求正文。

允许模块：`app/agent`、`app/chat` 既有会话导出、`core/model`/`core/storage`、导出解析器/测试；Provider 仅用于请求对照验证。禁止新增 Agent Tool、详细诊断开关、遥测、独立配额服务和后台淘汰系统。

## 实施切片

1. **格式与成本先行**：冻结版本、ModelCall 关联、有序消息/角色与 input IDs、压缩检查点及历史边界；复用既有配置、估算、用量与附件引用。测量典型会话、最大合法来源列表和至少 100 次调用重复历史 ID 的编码字节、累计占用与读写耗时。记录实测后确定单条字节/条目上限，不沿用未经测量的 1 MiB/64 MiB 配额。若累计成本不可接受，先收缩采集或评审简单保留策略。
2. **捕获与持久化**：最终组装/压缩/附件物化/准入后、Provider 前采集，覆盖普通生成与摘要调用。优先随 ModelCall 保存紧凑元数据或关联行，不强制独立制品。引用具体不可变消息版本；不从事后数据库倒推来源。输入消费沿用 216，不增加另一套记账。
3. **只读查询和 JSONL**：导出最小来源引用与现有事实关联，按需解析已有内容，不重复持久化或导出正文。规定 schema 版本和兼容规则；区分完整、不完整/省略、旧版未采集及原内容不可用。完整来源记录不意味着完整请求可重建。
4. **故障与对照**：超限明确标记，写失败不单独阻断合法请求；删除会话清理元数据，引用不延长原内容保留期。复用 ModelCall 终局，清单落盘不证明请求发送或远端收到，不自动重放。

## 延后与不做

调用详情页面、完整工具目录/系统提示快照、adapter 版本、全面 schema/附件/生成段指纹和逐段转换映射均延后；只有具体排错需求才另行设计按需详细诊断。首期不能据此宣称完整工具目录取证。HTTP 字节存档、重复正文和敏感凭据收集不在范围。工具裁剪结果只能作为来源级证据，不展示为已逐字完整发送。

## 范围与验收要求

新增 `RequestContextManifestDeviceTest`、`RequestManifestExportDeviceTest`、`RequestManifestRecoveryDeviceTest`，补格式与上限单测；名称是待实现测试要求，不代表已有能力。

- 普通多轮、工具批、附件、压缩摘要、fork/修订后发送和真实 Queue/Steer 的有序来源与 loopback 逻辑请求一致；被修订的旧输入和旧回答不误列为有效来源。
- 三类 Provider 按各自序列化形式核对来源，不要求逻辑清单等于 wire bytes。摘要直接来源与被摘要覆盖的输入可区分；pending 未使用不标使用，多次引用不重复消费。
- 最大合法来源与至少 100 次调用的空间/耗时测量，单条边界及超限状态测试；不无界加载正文或构造诊断数据。测量依据与上限选择写进完成记录。
- 旧记录无清单、缺失源消息/检查点/附件、磁盘写失败、导出中删除/取消均不伪造内容、不损坏消息或执行结算；查询不延长原文生命周期。
- Token/Secret/认证头/含凭据地址不落新增清单、日志或 JSONL；正文只由原有导出记录提供，附件不复制字节。
- 采集前后及进入 Provider 后的真实进程中断，对照服务端捕获与 ModelCall 状态，不把本地记录当远端确认，不自动重放。
- 四象限已有导出 UI 与 JSONL 独立解析、旧版本容忍/未知版本拒绝规则、会话删除及恢复通过；不新增专用详情 UI 验收。
