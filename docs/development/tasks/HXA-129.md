# HXA-129：Connector 安全替换、安装归属与会话启停

分类：待决策。当前是否执行见[实施状态](../status.md)。

前置条件：接受 proposed [ADR-CONNECTORS-003](../../adr/connectors/003-ownership-and-installation.md)。复用 HXA-124、HXA-207 与 HXA-212 的已有安装、配置及市场入口，不重做扩展闭环。

## 范围与验收要求

生产实现未开始。本轮明确两条交付线：安全替换与安装归属、每会话独立启停 Connector。后者为必要功能；不引入代码 Diff、多阶段 journal、多层 scope 继承或版本回滚 UI。

按以下切片实施，每项记录真实证据后再继续：

1. **提交方案与归属**：列出安装写入及生产读取入口，选定单一权威提交事实；区分稳定包身份、版本 hash、独立用户和包引用。验证同名不同包不互相替换，移除包不撤销其他归属。旧数据无法确定归属时保守保留；若采用 Room，先明确 schema、迁移和允许模块。
2. **安全替换**：完整准备后发布，提交前失败保留旧内容、配置及凭据；提交后恢复只重试清理。覆盖重复请求、预期旧版本冲突、空间不足、取消及运行中旧引用。仅在不能从清单推导时增加最小恢复记录，不建设通用 journal 引擎。
3. **更新与修复入口**：显示版本、作者说明及简短组件变化；沿用用户点击更新和现有配置流程，不增加强制 Diff 审查。未变绑定保留登录，变化目标不得复用旧 token；继续支持用户降级和原有 Skill/端点启用契约。
4. **会话独立启停**：持久化稳定 Connector 身份的会话选择；新会话复制默认值，后续互不影响。提供会话能力面板，接通 Skill/工具曝光、读取和执行前校验；维持组件就绪、工具禁用与权限规则。覆盖共享来源、运行中关闭、待审批调用、已发送结果结算及重启恢复；普通与 Goal Turn 一致。更新保持选择，卸载/同名重装不错误继承。
5. **故障与迁移验收**：在准备中、提交前及提交后清理前注入失败/强杀，检查新 PID 恢复；核对独立安装、两包共享、凭据变化、旧记录迁移与幂等结果。不能以普通安装后重启代替安装中故障验收。

范围：app 的 connector/marketplace/mcp 安装接线、会话能力面板及上下文/执行准入接线、extensions/skills、相关测试/docs；core/storage 仅在切片一明确必要元数据和迁移后纳入。保持现有授权和公共工具接口，不扩展执行引擎。

## 验证入口

### 实施准备：提交事实与读取接线

以下为源码审查后的实施建议，不改变 ADR 的 proposed 状态。首切片优先选 Room 作为唯一已提交安装事实源，文件只承载不可变内容；接受设计时明确 core/storage 元数据范围。迁移版本在实施基线确定后分配，不预占 HXA-216 正在使用的 schema 版本。

最小元数据包含稳定 connectorId、可信来源/packageId、当前内容 hash、完整组件清单及 revision；引用准确 SkillKey，并区分独立安装与包引用。提交事务核对预期 revision/hash 后发布安装记录及引用，内容验证和准备在事务外完成。旧 Connector JSON 迁移后不能继续成为第二权威；未知归属保守保留。首切片接通新安装、重复请求、列表和归属删除，不将其单独宣称为完整安全替换。

| 现有入口 | 必须落实的变化 |
| --- | --- |
| MarketplaceService.install/findInstalled/status | 从名称匹配转为可信包身份；不同 hash 不再先卸载旧安装 |
| ConnectorService.install/list/remove、ConnectorInstallationService.installedId | 同一身份内去重；不凭全局相同 hash 认领其他安装；候选提交前不曝光 |
| SkillRepository.scanSnapshots/registerSnapshot/remove | 扫描只发布已提交引用；删除按独立/包归属与运行中引用判定 |
| ConnectorService.prepareEndpoint/testOAuth/remove | 不按端点数组下标继承登录；仅完整目标及认证绑定相同才保留凭据 |
| McpAppService | 复用 captured bridge 身份校验；旧调用按原配置结算，引用释放后清理 |

Secret 不进入安装元数据。准备失败保留旧绑定，提交后清理按引用幂等重试；单文件原子移动不能代替跨注册记录、MCP 配置及凭据的提交一致性。

### 实施准备：会话选择的可信接线

会话 Connector 选择必须持久化；当前 SkillRepository 的 SESSION override 仅在内存，GLOBAL 才写盘，不能直接作为此功能的持久事实。新会话复制默认集合，SessionFork 在现有事务内复制选择快照。更新保持安装身份，卸载后同名新安装不得继承。

复用 HXA-209 的 SessionPermissionService 查询链，将 Connector 来源可用性叠加到 schema 曝光与 Dispatcher 执行检查，不覆盖工具禁用或授权预设。ChatRequestAssembler.modelTools、McpToolDiscovery.visible/search、Skill 目录及读取必须使用一致的来源过滤；独立安装或至少一个已选包提供的准确 SkillKey 才有可用来源，再叠加组件启用规则。

SkillTools.list/read/readResource 当前从工具参数读取 sessionId，接线时改以 ExecutableToolCall.sessionId 为可信身份，保留公共参数格式兼容。MCP 连接前准入和实际工具发送前分别核对当前选择；现有 onSend 在连接建立之后，不能把该检查描述为“没有发生任何网络活动”。待审批及未发送调用失效后正常结算，已发送调用保持原绑定完成。

### 实施准备：测试分工

复杂提交协议、迁移、凭据绑定及执行准入由主实现者负责；明确接口后，会话面板、已有入口接线及确定性测试可独立并行。不要让多个实现者同时修改同一迁移或提交协议。

回归至少覆盖 ConnectorDeviceTest、ConnectorInstallationDeviceTest、MarketplaceDeviceTest、SkillInstallationDeviceTest、SkillToolsDeviceTest、McpToolDiscoveryDeviceTest、SessionPermissionDeviceTest 和 SessionForkDeviceTest。新增专用安装边界 runner；现有 accept-hxa-124-connectors.sh 的 consumer 安装后重启不足以证明双 flavor 安装中恢复。新增测试类和命令随实现落地，不把本节列出的计划计作执行证据。

[公共验收规则](../verification-matrix.md)规定默认/外部测试边界。新增故障用例及设备 runner 目前未交付，实施时必须补齐实际类名、完整命令和非零执行结果。
