## 范围与验收要求

### A：本轮首版

- 通过宿主具名工具读取当前会话状态、分页历史、搜索、按哈希重读正文/用户分享的引用快照，以及条件重命名当前会话。保留已有 UI 创建、分支、归档/恢复、搜索和 Queue/Steer。
- 原 Dispatcher 注入调用身份；查询限定有效 USER/ASSISTANT TEXT，含仍保留的压缩前历史，排除系统/工具轨迹和 superseded。不提供模型指定 caller session；已知外部 ID 不扩大范围。
- 既有 Room/ContentStore 是唯一事实，引用永不回源；有界分页/搜索明确剩余和不可读内容。重命名仅改 title，CAS 与原 active call 同一 SQL；通知失败不伪装数据库失败。
- 更新随包提示与文档；按需发现，不新增常驻 UI 提示、运行框架、插件或授权表。

### B：重构中的受控跨会话查询与管理

依赖 HXA-286 的身份/权限契约、HXA-287 的统一应用命令与真实 Room 接线；不等待 293 检索策略。实现前复核 A 的实际交付，不为保留旧类名建立兼容层。

- 持久用户选择的目标和操作范围，读历史/改元数据/投递分别授权；同项目、源快照、FULL_ACCESS 与 ID 不是通行证。范围变化、撤销和披露绑定在调用及返回边界校验。
- `list/status/history/search/read/rename/archive/restore` 的模型入口与用户 UI 共享应用命令/查询，清理替代的宽服务入口、DTO 和双写。不得将用户全库 UI 搜索未经限定地直接暴露给模型。
- 游标绑定目标、查询和内容版本；列表不加载全文；归档不停止/撤权/删除。继续保留引用快照语义和原附件访问边界。

### C：创建与明确投递

依赖 B 的范围解析及 287 的完整 Turn、原输入持久接线；本机执行沿 288 实际资源边界，不再建 SessionRunner。

- 创建和开始工作分开，创建有持久去重回执；新会话不会复制来源授权、运行句柄或 pending approval。
- Queue/Steer 通过可信来源类型保留源 session/Turn/call 与目标 scope；模型转发不伪装用户输入。Steer 对 `expectedTurnId` 作 CAS，终态后新的任务创建新 Turn，不复活旧 Turn。
- 已受理/排队/进入上下文/运行/终态分别回执。重复 receipt 不重复执行；取消观察者不释放实际运行容量；目标当前授权与用户准许的委托范围共同约束实际操作。
- 不含远程电脑、子 Agent 递归、自动互相唤醒、永久删除或第二套审批/历史 owner；这些不作为本任务完成前置。
