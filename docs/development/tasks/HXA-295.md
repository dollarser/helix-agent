### C：创建与明确投递

依赖 B 的范围解析及 287 的完整 Turn、原输入持久接线；本机执行沿 288 实际资源边界，不再建 SessionRunner。

优先级 P2。依次验收 C1 幂等创建、C2 Queue 到新 Turn、C3 CAS Steer 到指定活动 Turn；每片可独立关闭，不以全量双向委托作为第一次验证。完成标准包含“目标已受理但源回包丢失”后重复提交返回原 receipt、目标终态/Steer 竞态明确拒绝、未知外部效果不重放。模型委托和用户直接输入分别保留来源及授予范围；不确定项是目标忙碌/归档时的交互呈现，不能通过自动恢复或隐式换目标解决。

- 创建和开始工作分开，创建有持久去重回执；新会话不会复制来源授权、运行句柄或 pending approval。
- Queue/Steer 通过可信来源类型保留源 session/Turn/call 与目标 scope；模型转发不伪装用户输入。Steer 对 `expectedTurnId` 作 CAS，终态后新的任务创建新 Turn，不复活旧 Turn。
- 已受理/排队/进入上下文/运行/终态分别回执。重复 receipt 不重复执行；取消观察者不释放实际运行容量；投递须有用户明确授予的目标投递许可；进入目标后按目标当前授权和正常审批执行，不再求来源权限交集。
- 不含远程电脑、子 Agent 递归、自动互相唤醒、永久删除或第二套审批/历史 owner；这些不作为本任务完成前置。

### C1 实施补充（2026-11-12，已完成有界验收）

会话访问编辑器中单独保存来源会话的创建许可，默认关闭，与目标读取/管理授权无关。`session.create` 经过原 Dispatcher 与普通 LOCAL_MUTATION 策略，且在事务内复核原活动调用、创建许可及取消/截止。它调用与 UI 相同的 SessionCatalog 创建命令，仅创建空会话及默认状态，不指定 Provider、不开始 Turn、不复制来源配置、授权、项目或运行资源，也不自动授予对新目标的读取、管理或投递权限。

来源会话与 requestKey 唯一标识持久回执；同 key/规范化标题返回原创建 ID 和首次调用来源，不同标题冲突。会话和回执同事务提交，回执写入失败整体回滚；丢失源回包或服务重建不重复创建。目标后续被删除也不重新建对象；回执只是首次受理事实，不代表目标仍存在。撤销创建许可后，不通过旧回执重新披露目标。新增 JVM 与真实 Room/SessionCatalog 测试，运行结果随本轮门禁记录。

C2/C3 已按下节补齐持久模型来源和投递权限；没有将当前用户 Queue/Steer 入口直接暴露为模型工具。

### C2/C3 实施补充（2026-11-12，已完成有界验收）

`session.queue` 与 `session.steer` 使用独立的目标任务投递许可，和读历史/改元数据分别保存。Queue 由原输入队列创建新 Turn；Steer 必须匹配 `expectedTurnId`，沿原活动 Turn 的配置/Provider 快照和原子追加边界，结束/更换/配置变化明确拒绝，不转为 Queue。授权的目标状态查询提供有限的活动 Turn ID/状态，不因此披露历史、目录或 Provider。

`session_inputs` 保存不可由模型指定的 MODEL_DELEGATION 来源、源会话/Turn/call、requestKey 和授权 revision；原输入记录仍拥有受理、排队、追加、请求开始和终态关联。独立来源-key 回执指针只保存去重身份，目标/输入删除后仍保留 tombstone，不另建状态机。相同 key 和精确投递类型/目标/Turn/文本返回原回执，冲突拒绝；已受理后的通知失败或源等待取消不伪称投递失败。

原子接受与原子追加均复核授权版本，投递后按目标权限执行。模型输入不生成用户 Goal/Skill/审批权限，不能通过编辑、Queue/Steer 转换或重试变为直接用户输入；必要时由用户明确重新发送。来源在用户可见消息/待发送项、模型上下文、历史工具和分支保留。明确授予的第三目标仍可使用，不整体收紧目标权限；通过持久来源链阻止返回祖先会话的循环，并对损坏/超限链失败关闭，不自动派生、互相唤醒或转发结果。

新测试包含原应用 Engine/Room/本地模型服务的 Queue 与 Steer 路径、目标普通权限执行、来源 Goal 隔离、响应丢失后重复请求、终态竞争、撤销、重开数据库、tombstone 和来源投影。测试编译、主机执行、设备实际运行分开记录；未将确定性模型夹具称为真实模型质量验收。
