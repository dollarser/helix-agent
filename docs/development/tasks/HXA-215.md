# HXA-215：用户消息编辑与分支重发

分类：待决策（P1，规格完成，未实施）。前置：proposed [ADR-AGENT-009](../../adr/agent/009-edit-and-resend.md) 接受、HXA-213 fork 和 HXA-214 回执能力进入实施基线；不依赖 HXA-216 的输入队列。

## 用户结果与范围

已发送 USER 消息可“编辑并重发”，取消不改原会话；确认创建不含旧输入及其后续内容的新分支并发送修改内容。运行中的来源继续独立执行，界面明确说明；不隐式停止、不回滚文件。编辑普通草稿不建分支，编辑已交付历史才建分支。

允许模块：`app/chat` fork/草稿/发送，`app/ui` 与资源，`core/storage` 的引用、编辑提交映射与必要迁移，对应测试。必要协议/领域值放 `core/model`；不改 Runtime、工具授权、Provider adapter 或执行账本。沿用 fork 新会话默认权限；不复制 Goal、Job 或审批。

## 实施切片

1. **前缀计划**：扩展 fork 为明确的 inclusive/exclusive 两种边界；原入口行为不变。第一条消息允许空前缀，适用摘要必须严格在目标前；完整工具批校验和读取上限保留。
2. **编辑提交**：独立编辑草稿与 editRequestId，来源/输入指纹/revision/新会话映射持久化；创建和保存待发意图原子完成。重复回执、失败重试、进程恢复均复用分支。沿214回执衔接发送，不另造出网准入。
3. **UI**：USER 行提供入口、编辑/取消/提交、附件修改、新分支导航和失败修复；无持久 ID 的流式内容不提供编辑。双会话导航不得被迟到结果劫持。
4. **验收**：实际 Provider 请求验证无旧输入/未来信息，进程与附件生命周期回归。

## 范围与验收要求

新增 `MessageEditBranchDeviceTest`、`MessageEditResendFlowDeviceTest`、`MessageEditRecoveryDeviceTest`，全部为待实现要求。

- 首条 USER、中间 USER、fork 继承 USER、附件输入；修改或取消后源消息/执行记录不变。
- 目标已被后续摘要覆盖时不复用污染摘要；不同摘要位置、工具批边界、损坏后缀、资源超限明确结果。
- loopback 抓实际请求：包含修改文本，排除目标旧原文、旧回答、未来工具结果和未来摘要。
- 同 editRequestId 双击/网络失败/重试/实际进程死亡只产生一个分支和一条替代 USER；ID 内容冲突拒绝。
- 出网确认取消、Provider 故障、源任务仍运行、切会话、删除源会话后附件引用仍有效。
- 副作用不回滚；不继承 Goal 自动运行或审批。原 fork 及压缩/附件回归仍通过。
