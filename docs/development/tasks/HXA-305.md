## 范围与验收要求

- 保持单 APK、非导出 `:proot` 私有进程及现有 Advanced 授权边界。PRoot 是实现细节，用户入口称“Linux 运行环境”；不增加启用开关、下载源、发行版选择或独立 Runtime 安装流程。
- 首次获准的新 Linux 作业或人工终端启动可展开内置资源。进入设置、能力查询、启动应用、切换 Profile、查询/恢复旧作业均不安装、不执行；不改变 Standard 能力边界，不自动提升权限模式。
- 缺少环境可按需准备；已有环境损坏、丢失激活记录或版本不匹配不得静默重装。并发首次使用共享一次安装；失败如实返回，作业取消/超时在准备后再次检查，物理占用保留到执行器退出，不重放原命令。
- 删除手动验证记录及新基线确认接口。状态读取实际激活记录、清单、版本和必要文件，握手绑定当前安装版本。“已准备”是安装状态，不代表具体命令、模型或媒体端到端通过。
- 设置概览只展示状态和“环境详情”；管理页按状态给出准备、检查安装、更新或修复。重装、恢复上次环境、删除及开源许可集中到“维护与详情”。维护保持任务/终端占用保护；删除只有一次最终确认，取消不改变状态。
- 重装/更新明确环境内自装内容不合并；已有一次恢复副本机制保持。删除只作用于环境目录及其中的作业结果，已保存工作区文件保留。环境/旧版本/作业及临时输出清理不沿目录符号链接删除外部内容，残留不得报告已清理。内部诊断留在详情中。

## 一手资料与采用点

- [Claude Code Advanced setup](https://code.claude.com/docs/en/setup#verify-your-installation)：普通使用与 `doctor` 诊断分开，安装方式决定更新方式。采用按需诊断；Helix 的版本由 APK 打包决定，不新增独立自动下载或更新器。
- [Termux PRoot-Distro](https://github.com/termux/proot-distro#commands)：区分安装、重置、删除，明确容器内数据的影响。采用明确动作和删除范围；不引入多发行版、镜像仓库或其命令行无确认删除行为。
- [Android 设置设计](https://developer.android.com/design/ui/mobile/guides/patterns/settings)：清楚的名称、简洁状态、分组与次级信息。采用状态优先及按需维护，把许可保留在可发现的详情入口。
