## 范围与验收要求

优先级 P1。当前 SDK snapshot 只提供部分资源/Prompt 元数据，Helix facade 没有完整正文/模板/分页端口；要补的是从发现到实际消费的闭环，而非再建 MCP 客户端或重做已交付认证。先交文本读取与来源验证，再在 288 相应产物接缝就绪后交二进制；不等待所有 Runtime 迁移。

1. 补 list_mcp_resources、list_mcp_resource_templates、read_mcp_resource 一致入口，支持分页、模板参数化读取、明确 URI/来源与内容类型。
2. 复用现有 SDK facade、连接生命周期、认证与 Dispatcher 治理；Resources 元数据与实际正文分开，读取不伪装成服务端 tool call。
3. 校验 URI/模板来源、会话绑定、撤销/重连与结果引用；有界文本和二进制走相应内容/产物路径，不让资源正文、模板或外部 Prompt 成为系统指令。
4. 未声明或不支持 Resources 的服务正常显示能力边界；Prompts 执行、stdio 运行和 MCP Apps 仍不随本任务启用。

当前源码入口补充：McpClientSession 仅有 snapshotMetadata/callTool，尚无资源正文读取接口。先补会话内 list/read/templates 的有界契约和实际 SDK 接线，再接来源/内容/产物；不能将元数据发现记作内容读取，也不需要为此替换既有连接、认证或整个 MCP client。

## 验证入口

资源身份接续（2026-10-17，待实施）：MCP URI 绑定实际 server/连接来源及可确认内容版本，与 Workspace ResourceRef、下载 artifact 和执行资源句柄分开。`file://` 等 URI 也不能未经适配映射直接变成本机 cwd 或打开任意路径；显式物化沿 [§23.3.1](../../architecture/harness-refactor-plan.md#2331-目录资源与执行环境) 的来源/目标/授权契约。验证不同 server 同 URI、重连/撤权、内容变化及二进制已保存但发布失败，不让模型或远端元数据自己指定可信 environment。

- 完成标准：同一实际连接上列举/模板/读取的身份和分页一致，模型下一请求得到可核查正文或明确不可读事实；仅 `listResources` 成功不能通过正文验收。
- 不确定项：目标服务是否支持 Resources/templates、SDK 暴露的分页/通知行为以及二进制类型。先用可控协议夹具固定契约；缺少真实服务是待验输入，不标为已通过，也不重开 Notion/Linear 结案。
- 常驻 stdio、包内 CLI/账号服务属于 [方案 §23.12](../../architecture/harness-refactor-plan.md#2312-插件管理与提示审查接续) 的另行候选，本任务不借资源读取启用它们；已有 `McpStdioJobBridge` 也不是常驻会话完成证据。

- 使用本地协议夹具覆盖空列表、cursor、模板、错误来源、断连/撤权、过大正文和二进制；验证实际下一请求拿到内容而非仅元数据。
- 设备/真实服务按新任务授权与指定服务验证；已有 OAuth 测试不作为前置重跑，认证修复仅由新复现触发。
- 开始实施时定位现有测试入口并按改动选择回归；目标契约可替换旧实现镜像断言，权限、持久原子性、取消、真实退出与恢复反例不得丢失。设备/服务须核对当次授权与配置，本轮未执行。
