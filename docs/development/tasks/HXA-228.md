# HXA-228：Conversation-first Shell 与 Session Context Control

分类：已规划，建议作为 HXA-226 后的下一条产品/UI 主线；完成后先推进 HXA-229 模型生成的 Agent Activity Presentation，再由 HXA-227 建立冻结后的统一轨迹 baseline。基线为 `2187f05d` 以及 `docs/evidence/development/hxa226-simulator-verification-2026-09-26.md`。详细设计见 `docs/research/conversation-first-session-workbench-2026-09-26.md`；Memory/Activity 竞品调研与长期裁决见 `docs/research/agent-memory-and-activity-presentation-2026-09-26.md`。

## 背景

HXA-226 已把 Drawer / Settings / recovery authority 收敛为“一个能力一个 primary home”，模拟器验证未发现由 HXA-226 引入的行为回归。当前剩余的产品问题不再是一级菜单过多，而是 Conversation 仍以“Session list/detail”思维组织：

- App 正常启动进入 Sessions route，但无 open session 时先展示全屏会话列表；
- full Session list 仍承担默认落点，而不是历史管理；
- Composer `+` 只处理附件，Expert / Skill / Connector / reference / Session permission 还没有统一上下文入口；
- 当前 Session permission preset 的 `READ_ONLY` 实际 mutation=ASK，名称与用户心智不完全一致；
- Message action 的 Copy 已图标化，但 Edit & resend / Fork 仍是长文字动作。

本任务将 Helix 收敛成真正的 Conversation-first mobile agent workbench，同时保持 HXA-220/223 的 Engine owner 与 HXA-226 authority 不变量。

## 范围与验收要求

### A — Conversation-first 启动与历史导航

正常启动顺序：

1. explicit notification/deep link/share target；
2. 有效 `lastViewedSessionId`；
3. 否则创建 ephemeral new-conversation draft。

要求：

- App 启动直接落到可输入的 Conversation，不先经过 full Session list；
- new draft 首次提交才 durable persist；
- last viewed 只是 UI navigation preference，不是 Turn truth；
- Drawer 顶部提供 New conversation / Search / Recent / All conversations；
- full Session list 作为 history secondary page 保留 search/archive/restore；
- Conversation header 删除与 Drawer history 重复的常驻 “Back to Sessions”。

### B — Composer `+` sheet

`+` 必须按生命周期分组：

```text
添加到本次消息
  Camera
  Photos
  File
  Reference
    Memory      # 只有真实 backend 存在时显示
    Other conversation

配置此会话
  Expert
  Mode
  Skills
  Connectors
```

Model / Permission 继续保持高可见 session state；Mode 当前值也可保持 compact chip，chip 与 `+ → Mode` 打开同一 selector。

### C — Session settings

Header `⋯ → Session settings` 是当前 Session config 的完整 authority，至少包含：

- Expert；
- Mode；
- Model；
- Permission；
- Skills；
- Connectors；
- 以后可接 Memory / Workspace；Memory backend 归 HXA-230，本任务只有 backend 存在时才显示入口。

全局 authority 保持：

- Models 管 Provider/account/endpoint；
- Extensions 管 Skill/Connector install/config；
- Settings 管默认 permission/safety；
- Session settings 只做当前 Session binding/snapshot。

### D — Expert / Skill / Connector / Mode contract

#### Expert

新增前必须先定义简单、可审计的 Session-level `ExpertProfile`；一个 Session 最多一个 primary Expert。

Expert：

- 可以贡献 behavior/system instruction；
- 可以“建议” Skill/Connector/Mode；
- 不能自动提升 permission；
- 不能绕过 model selection / policy；
- 不 retroactively 修改历史 Turn。

若实现需要角色市场、第三方角色包格式、复杂 persona memory，则拆独立 HXA，不扩大本任务。

#### Skill / Connector

- 当前 Session 可多选已安装/已配置项；
- 完整安装/账号/OAuth/更新继续 deep-link Extensions；
- enablement != Tool effect approval。

#### Mode

继续使用 `CHAT / PLAN / ACT / GOAL`；change 只影响 future Turn snapshot，active Turn immutable。

### E — Reference snapshot

Other conversation reference：

- 选择 bounded messages / available summary；
- composer 显示 reference chip；
- submission acceptance 时 materialize immutable bounded content snapshot；
- 禁止 active Turn 持有 live session pointer。

Memory reference 只有 HXA-230 的真实 memory backend 存在时才显示；HXA-228 不实现长期 Memory，也不用空 UI 假装 Memory 已存在。

### F — Session Permission preset clean-slate

当前 `READ_ONLY` 的 mutation/command 实际为 ASK。实现前必须更新 ADR-PERMISSIONS-001，不允许只换 UI 文案。

优先方案：

- `APPROVAL_REQUIRED`：承接当前旧 READ_ONLY 的 ask-before-change 语义；
- `WORKSPACE_TRUSTED`：workspace 内 read/write allow；外部/command/system/remote mutation 默认 ask；
- `FULL_ACCESS`：尽可能 allow，但不突破 global hard-deny / credential / special destructive rule；
- `READ_ONLY`：真正 mutation/command/remote write/system mutation deny；
- `CUSTOM`：显式 per-effect ALLOW/ASK/DENY。

必须重新裁决当前 WORKSPACE 对 `REMOTE_BUSINESS_MUTATION=ALLOW` 的规则是否符合“Workspace trusted”用户心智。

### G — Message action iconization

保留现有 Copy icon + copied check feedback。

改：

- Edit & resend → pencil/edit icon；
- Fork → branch/account-tree/git-fork 风格 icon；
- 48dp touch target，20～24dp glyph；
- 完整 TalkBack contentDescription；
- 保留现有 `chat-edit-*` / `chat-fork-*` 行为 identity 与 HXA-215/213 durable semantics。

### H — 不变量

- UI 不持有 Turn durable owner；
- active Turn / ModelCall 不因 Session config 编辑改变；
- permission tighten/loosen 按已有线性化；
- Queue/Steer/Stop 保持；
- Tool approval/effect truth 保持；
- Expert/Skill/Connector binding 不等于批准；
- reference 是 submit-time bounded snapshot；
- process death 继续 successor-Turn recovery，不恢复旧 open Turn。

## 验证入口

主机：

```bash
./gradlew \
  :app:testConsumerDebugUnitTest \
  :app:testDeveloperDebugUnitTest \
  spotlessCheck detekt

./gradlew \
  :app:assembleConsumerDebugAndroidTest \
  :app:assembleDeveloperDebugAndroidTest

./scripts/check-all.sh --source
git diff --check
```

模拟器/设备重点：

- cold launch restore/new draft；
- Drawer recent/search/all history；
- Session config recreation/process reopen；
- active Turn 下修改 Mode/Model/Permission 不改变当前 snapshot；
- `+` 的 message/session 两组；
- camera/photo/file picker cancel/success；
- other-session reference snapshot；
- 320/360/412dp × 1.0/1.3/2.0；
- IME/横屏/TalkBack；
- Stop + Queue/Steer Send；
- Edit/Fork icon 48dp + accessibility；
- Permission preset actual ALLOW/ASK/DENY 与 UI 一致。

设备 CI 仍不加入 GitHub Actions；所有者/小模型按显式授权手工模拟器或真机验证。
