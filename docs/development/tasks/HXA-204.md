# HXA-204：跨执行域错误与恢复交互

分类：待实现。当前是否执行见[实施状态](../status.md)。

前置条件：202入口；复用200/208及现有对账。

本次复核：恢复展示和显式操作是增量；不重做Goal/审批状态机，不用统一resume覆盖不同副作用状态。

核对依据：[源码或有效证据](../../completion-records/HXA-200.md)。本轮只审查，不新增测试通过或完成声明。

## 范围与验收要求

本任务属于应用恢复交互，底层复用已有宿主对账机制；不新增通用 recovery/resume Tool，不让模型自行批准恢复、重放未知调用或更改用户授权。已有 Goal/预算工具按原契约保留，恢复按钮和模型工具不是同一个入口。 规划规则见[实施指南](../implementation-guide.md#应用能力与-agent-工具的规划规则)。

- 允许app恢复/文件/Provider适配、必要现有repository及测试，保持各执行域对账协议。
- 展示已完成动作、可用产物、待核查副作用、阻塞原因和下一动作。操作区分重新连接/查询结果/补充权限/继续Goal/新调用重试，不能统一叫resume。
- 错误按认证、网络、能力缺失、用户拒绝、预算、执行失败、结果未知分类；不解析任意错误字符串猜状态，使用现有结构化结果，必要时局部补类型。
- 认证修复或网络恢复不自动重放写入；旧任务结果查询不重新提交。已完成文件动作不重做，用户取消后不自动继续。
- 验收：P1+P3；新增 `RecoveryJourneyDeviceTest`，主/Runtime死亡、断网、过期认证fixture、权限撤销、恢复按钮重复点击和未知结果。真实账号另记，不借fixture宣称账号验收。

### 分工与收口

复用现有审批恢复、Goal disarm与文件/Runtime对账。新的等待输入或恢复摘要是UI投影，不扩成第二套恢复状态机；认证修复不得隐式恢复旧批准。

### 顺序实施切片

每个切片可以独立提交，全部通过才关闭本 HXA；同一执行者顺序完成，避免多人改恢复入口。

1. **事实与操作映射**：核对 Tasks、Turn、Goal、文件及 Runtime 已有结构化状态，建立错误类别与允许操作的只读投影。覆盖未知结果、取消、预算及缺失记录；不根据异常文案猜测副作用。
2. **用户恢复入口**：从已有任务详情展示已完成动作、产物、阻塞与下一操作；复用现有服务实现重连、查询、补权限、继续或新调用重试。每个按钮绑定稳定身份并在执行时重新检查准入，覆盖重复点击和迟到结果。
3. **与现有继续语义集成**：保留 ADR-AGENT-006 的普通预算失败“从已有结果继续”及大结果只读分页；它创建新有界 Turn，不改为恢复旧调用。Goal 继续、未知副作用对账、用户取消各自保留独立条件，不新增统一 resume。
4. **设备旅程与收口**：实现并执行 RecoveryJourneyDeviceTest 及相关现有回归，API29/36 × consumer/developer；进程死亡验证持久事实与 PID 变化，Runtime 专属场景仅 developer。记录真实入口、按钮结果和未重放断言，完成 P1/P3 与全量主机门禁后更新完成记录和当前状态。

不在本任务实现 JSONL 导出、输入队列、同 Turn 转向、子 Agent、PTY 或第二套恢复账本。HXA-205 仅在本任务完整验收后开始；HXA-193 的外部 CI/账号缺口独立记账，实际影响本任务的初始化/构建故障必须先解决。
