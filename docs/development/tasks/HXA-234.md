## 范围与验收要求

按 [Harness R2-A](../../architecture/harness-refactor-plan.md#5-r2core-解耦与统一上下文编译) 实施：先建立中立领域值和窄存储/模型/执行端口，复用真实事务；再迁移唯一 Loop、消息物化及事件；最后等价提取上下文选择/容量。优先使用既有 core:agent/core:model/provider:api，不引入框架、第二执行循环、可写状态镜像或远程服务。

1. R2-A1：领域命令和 Applied/AlreadyApplied/Conflict/Unavailable 结果；生产存储适配与纯规则测试。检查会话/Turn/ModelCall 归属、预期 phase/step、重复回执、取消优先级及事务失败。
2. R2-A2：Loop 不再依赖 App R、刷新函数、Room 实体或 ProviderService；执行网关不携带 TurnCoordinator 或历史编码方法；原有取消、UNKNOWN、Goal 和调用顺序不变。
3. R2-A3：冻结上下文 fixture，分离事实读取、纯容量/选择、压缩编排和物化。唯一生产入口；本次不改变 Prompt、预算策略、排序或摘要模型。

## 验证入口

共享 host slot 下运行受影响 core/app JVM 测试及完整适用主机 gate，双渠道 lint/APK/AndroidTest APK、spotlessCheck、detekt、source/artifacts 和 git diff --check。pure Core 测试必须没有 App/Android/Room runtime；实际 Room 集成独立编译并记账。测试编译不等于设备执行。本轮没有指定设备/账号输入，不使用设备或真实模型，也不提交/推送/发布。

正常、失败、重复、取消、旧步骤/错归属、终态幂等和事务回滚分别检验；不删弱断言。新增规则若改变行为，应记录具体反例而不是以重构名义隐藏变化。
