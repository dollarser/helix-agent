# HXA-273：Skill 用户与模型调用资格及显式激活

日期：2026-10-11。状态：已排期，未开工。优先级：P1。依赖：HXA-272 的统一内容身份与读取路径。

Owner request：依据 Agent 插件架构调研、Helix 优化方案与当前代码拆分开发任务并更新计划；所有者追加要求按合理目标架构设计，不兼容旧版。本卡登记未来实现范围，本轮只完成计划，不代表代码或功能验收。执行顺序由 [status](../status.md) 维护。

共同设计基线：单一目标实现，旧入口随对应切片直接替换；不做旧版本、旧数据库、旧会话或旧工具批准迁移，不留双写、双注册与兼容 adapter。开发期存储沿用现行 baseline 重建规则；历史证据仍按原版本解释。原执行身份、权限、取消结算和渠道边界继续有效。

## 当前代码与缺口

[SkillDocument](../../../extensions/skills/src/main/kotlin/com/helix/extensions/skills/SkillDocument.kt) 将扩展字段保存在 `additionalFields`；[SkillLoader](../../../extensions/skills/src/main/kotlin/com/helix/extensions/skills/SkillLoader.kt) 未将调用资格归一化为执行规则。[SkillRepository.read](../../../extensions/skills/src/main/kotlin/com/helix/extensions/skills/SkillRepository.kt) 目前核对启停，没有区分模型调用与用户显式激活。现有会话选择不是“本次用户调用”的证明。

## 范围与验收要求

1. 为明确支持的当前格式归一化用户/模型调用资格：缺省两者均可调用；`disable-model-invocation=true` 禁止模型自行激活，`user-invocable=false` 隐藏用户调用入口；两者均禁止时仅管理预览可见。四种组合和严格布尔类型按 Skill ADR 的已接受表格执行，字段不导入工具批准。
2. 区分管理预览、模型发现/读取、用户本次显式调用：管理入口可检查内容，模型列表和 read/resource 都执行相应资格，用户菜单按用户资格展示。
3. 复用会话输入接受路径，绑定准确 Skill 身份/hash 与本次参数；用宿主记录的用户操作来源识别显式激活，不能让模型参数、网页、工具结果或 Skill 自声明 `userInvoked=true`。
4. 安装/会话选择与本次激活分别记录；队列等待、fork、取消及版本变化后重新核对当前范围，旧激活不得绑定到同名新内容。普通 Turn 和 Goal 使用同一规则。
5. 在真实读取入口实施检查，避免仅在 UI 隐藏；不支持的执行语义（如 `context: fork`）给出明确诊断。兼容矩阵和安装预览由 HXA-275 消费同一规则。
6. 更新纯流程作者样例和 Skill 使用入口；直接替换旧未区分调用方的执行读取接口，不保留宽松备用通路。

## 契约与范围边界

2026-10-11 已同步 accepted [ADR-SKILLS-001](../../adr/skills/001-authoring-and-installation.md) 的调用资格表、可信用户激活及 Decision history，实施按该契约执行。资格是内容调用约束，不产生 capability、approval 或外部写入许可；`allowed-tools` 不转为批准。已有上下文中的内容不会因停用从模型记忆中消失，但后续发现、读取和执行必须按当前有效状态处理。生产子 Agent、任意 slash-command 引擎和后台自动回复不在范围内。

## 验证入口

实施时运行本卡涉及的现有主机回归、全仓 source/JVM/静态检查及双渠道 Debug lint、APK、AndroidTest APK 编译，具体命令沿用[公共验收](../verification-matrix.md)。下列设备/模型场景是后续验收要求，本次均为 **not requested**；只能在当轮明确授权后执行，缺少输入不伪报通过，也不阻塞无依赖的主机工作。

- 扩展 SkillLoader/Repository/Tools 与会话输入回归：资格四组合、默认值、错误类型、用户显式入口、模型伪造、外部内容诱导、同名来源、取消、排队后撤销和版本变化。
- “仅用户调用”的 Skill 不能由模型自行读取；管理查看不构成执行激活；一次显式调用不变成永久授权。
- 后续设备验收覆盖中英文菜单、窄屏/大字体及参数输入，使用合成内容；后续模型对照核对真实调用来源。
- 完成时 UI、上下文与实际 read/resource 使用同一资格判断，错误调用有可解释结果。
