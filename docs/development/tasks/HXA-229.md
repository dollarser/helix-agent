# HXA-229：Model-authored Agent Activity Presentation

分类：已规划。建议在 HXA-228 冻结 Conversation/Session input-config contract 后推进，并在 HXA-227 trajectory baseline 之前完成。详细调研见 `docs/research/agent-memory-and-activity-presentation-2026-09-26.md`。

## 背景

当前 Helix 已有 compact `ToolTimelineItem`、request/result/approval identity、result preview 和 `ToolPurpose` deterministic summary，但第一层仍以 toolName + “读取/运行/检查”这类功能描述为主，不能表达模型真实目的。

例如：

```bash
cat /tmp/helix-hxa226/isolated/summary.tsv
echo "=== classes ==="
cat /tmp/helix-hxa226/classes.txt
```

当前只能接近：

```text
Tool: bash
运行
```

目标是：

```text
✓ 查看隔离运行进度汇总
  bash · 0.4s
```

点击后才展示完整 command/result。

## 范围与验收要求

本任务只新增 model-authored ToolCall presentation metadata、对应持久化与对话展示；不改变 Tool executor、effect classification、permission/approval、result truth 或 AgentLoop owner。验收要求是：模型 intent 能稳定显示并在重启后恢复，缺失时安全 fallback，原始命令/参数/结果仍可审计，任何失败/审批/UNKNOWN 状态都不被自然语言摘要掩盖。

## 核心原则

1. **模型负责 intent，Harness 负责 truth。**
2. model intent 是 display metadata，不参与 Tool execution / effect / permission。
3. status、success/failure、UNKNOWN、approval/review 永远由 durable Harness fact 决定。
4. raw args/result/audit 必须可展开查看。
5. `ToolPurpose` 保留为 fallback，不再是未来主要语义来源。
6. 不用 UI 邻接 heuristic 猜多个 ToolCall 是否属于同一个 Activity。

## A — Internal presentation contract

新增类似：

```text
ToolCallPresentation
  modelIntent: String?
```

必要时未来扩展：

```text
activityKey
activityTitle
```

第一阶段只交付 per-call `modelIntent`。

要求：

- 长度有界；
- 单行；
- 不允许控制字符；
- 经过 secret/redaction boundary；
- 允许中英文；
- 描述目的而不是结果；
- 不允许用 pre-execution intent 宣称成功。

## B — Model-facing schema augmentation

因为 OpenAI/Anthropic/MCP 等 ToolCall 没有统一 display-intent 标准字段，Provider/Harness 在暴露工具 schema 给模型时注入 reserved optional metadata，例如：

```text
__helix_intent
```

约束：

- reserved key 不进入 executor args；
- schema validation 前后边界明确；
- MCP/Skill/custom tools 不需要修改业务 schema；
- 原始 schema 占用 reserved key 时 fail closed；
- provider adapter 统一提升到内部 presentation field；
- 模型没填 intent 时不拒绝合法 ToolCall。

System/tool guidance 要求模型在调用时生成简短目的说明。

## C — Persistence

`modelIntent` 与 ToolCall identity 一起持久化或可由 durable model event 重建，使 process reopen/history/detail 都能显示同一个原始 intent。

它是“模型声明的意图”，不是 verified result。

## D — UI

collapsed：

```text
✓ 查看隔离运行进度汇总           0.4s
  bash
```

running：

```text
◌ 查看隔离运行进度汇总
  bash
```

approval：

```text
! 修改发布配置
  bash · 需要确认
```

expanded：

```text
Intent
查看隔离运行进度汇总

Tool
bash

Command / Arguments
...

Result
...

Status / duration / call identity
...
```

原始 request/result bounded preview 可复用。

## E — Fallback

优先级：

```text
valid modelIntent
→ ToolPurpose.text(...)
→ generic tool label
```

不允许为了缺少 model intent 再发一个额外 LLM 请求。

## F — Result narrative

第一阶段不新开“LLM 二次总结每个结果”的额外调用。

同一 Agent 在消费 ToolResult 后自然生成的 progress/assistant text 可以解释结果；若未来需要绑定回 activity，再设计显式 structured update，而不是 UI 猜测。

## G — Activity grouping（后续 slice）

只有模型提供 explicit stable activity identity/title 时才允许聚合。

FAILED / DENIED / PENDING_APPROVAL / UNKNOWN / NEEDS_REVIEW 必须逐项可见，不能被绿色 group summary 掩盖。

## 验证入口

- bash example 默认显示 model intent，展开显示 command/result；
- structured tool 同样支持 model intent；
- missing intent fallback 不影响执行；
- intent 字段不进入 executor/MCP args；
- permission/effect classification 与无 intent 时完全一致；
- process reopen 后 intent 可恢复；
- malicious/超长/control-char/secret-like intent 被 sanitize/fallback；
- provider 不支持时完整回退；
- approval/UNKNOWN/review presentation 不被 intent 覆盖；
- Android 320/360/412dp + TalkBack 可读。

## 交付

- `ToolCallPresentation.modelIntent`（或等价 typed contract）；
- model-facing reserved presentation metadata 变换与 strip 边界；
- durable ToolCall presentation persistence/reconstruction；
- intent-first `ToolTimelineItem` UI 与 deterministic fallback；
- provider/structured-tool/bash/MCP representative tests；
- process reopen、approval/UNKNOWN、secret/control-char 边界测试；
- 完成时写 `docs/completion-records/HXA-229.md` 并更新 status/roadmap/index。

## 非目标

- 不改变 ToolCall effect truth；
- 不重写 Dispatcher；
- 不做新 Tool runtime；
- 第一阶段不做多 Tool activity grouping；
- 不做额外 per-result LLM summarizer；
- 不让模型生成 success/failure state。
