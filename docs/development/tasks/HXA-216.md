# HXA-216：普通 Turn 与 Goal 统一排队和转向

分类：进行中（P1，所有者已授权设计与核心开发，独立 `codex/hxa-216-input-delivery` 分支实施）。实施同步收敛 proposed [ADR-AGENT-008](../../adr/agent/008-user-input-delivery.md) 与 Goal/Turn 有效契约；[HXA-214](../../completion-records/HXA-214.md) 发送回执与稳定取消已完成。不要求217先完成。

## 用户结果与范围

运行中普通发送默认 Queue，等本轮正常结束后发送；显式 Steer 才在当前 Turn 安全边界交付。两者均不自动取消 Goal/普通 Turn。独立停止保留队列但暂停交付，用户可以继续、编辑或撤回。页面展示“待交付/已纳入请求/需要处理”，不把写入队列称为模型已读取。

允许模块：`core/model`、`core/agent`、`core/storage` 的输入身份/迁移，`app/chat`、`app/agent`、`app/goal`、`app/ui` 及测试；Provider adapter 仅为 USER 尾消息兼容及请求验证，不能顺带重写传输/登录。复用工具 Dispatcher 与现有恢复，不新增 Tool、Workflow、常驻服务、Worker 或远端执行目标。

## 实施切片

1. **持久输入**：有界内容引用、队列顺序/revision、预期目标、接收/待处理/历史追加/撤回映射；迁移、并发 CAS、事务去重、附件引用及会话删除。32 项/1 MiB 待处理文本上限按ADR，拒绝不丢稿。
2. **Queue 完整闭环**：终局后 FIFO，用户输入优先于 Goal 自动续跑；出网/配置重新校验、明确停泊原因、停止后不自动发旧队列。故障与进程重启不绕过恢复。该切片可独立验收，但不能关闭216。
3. **Steer 完整闭环**：整批工具结算之后、下一模型请求前追加 USER；与最终终局竞争线性化；目标过期不悄悄转投新 Turn；取消中不交付。压缩、上下文容量、原 Turn/Goal 预算均保留。三类 Provider 接受合法的工具结果后 USER 尾消息。
4. **Goal 收敛**：去除“普通发送即 pause/cancel/revoke”专用分支；排队让位只影响调度，不自动暂停/更改目标。保留明确停止、死亡、预算/未知副作用对旧激活的撤销。补充用户来源按新 message/input ID 绑定，不给自动轮新授权。
5. **UI/恢复/验收**：显示队列、编辑/撤回、明确选择 Steer；切会话、进程死亡、后台衔接和旧数据升级。中间切片状态必须诚实标注，不提前宣称支持全部交互。

## 范围与验收要求

新增 `SessionInputQueueDeviceTest`、`TurnSteeringDeviceTest`、`GoalInputSchedulingDeviceTest`、`SessionInputRecoveryDeviceTest` 及核心并发测试；名称是待实现要求。

- 同一场景分别在普通 Turn 与 Goal 跑：enqueue 不调用 cancel/pause，不取消当前流；Queue 等终局、Steer 在整批结果之后交付。
- 同时结束/enqueue、停止/consume、编辑/consume、撤回/consume、两个连续提交和重复回执；稳定 ID、FIFO、恰好一条历史追加及一次本地 Turn 创建。
- 工具批内多个调用、拒绝/失败/取消结果、等待审批；USER 不穿插破坏调用配对，补充文本不代替审批决定。
- final text 与 Steer 到达竞争；过期 expectedTurnId、取消中、双会话隔离；没有静默掉消息、投错 Turn 或忙等。
- 同 Turn token/工具轮/模型调用上限不重置；超上下文与压缩失败保持准确交付状态，不丢消息或重复追加。
- Goal 有合法激活时队列优先，正常用户后继结束再评估原目标；停止/暂停/完成/blocked/死亡后不能被队列复活。普通排队不创建第二个 Goal。
- Provider/模型目标改变、附件 hash 失效、确认失效时保留待处理，不静默改目标出网；Plan 仍只读。
- loopback 覆盖 OpenAI Responses、Chat Completions、Anthropic Messages 请求次序；与实际 USER/TOOL 内容一致。
- 实际普通主进程分别在已入队、已追加历史未启动请求、请求在途、取消结算中死亡；新 PID 恢复保留意图、不盲重发/重放。Room 重开只算存储层测试。
