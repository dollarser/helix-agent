# 终端恢复与历史模型绑定修复

本轮由 Owner 报告的两项问题触发：不可确认的旧终端没有明显恢复入口；历史会话的模型来源删除或修改后，被统一提示为未完成测试。仅实现代码及主机验证，没有操作真机、模拟器、真实账号或实际清除数据，没有提交、推送或修改版本。

## 终端行为与删除范围

终端页面、原 shell 的连接、新 shell 的创建和原执行结果核对分开处理。首次进入页面时能连接原 shell 就连接；原 shell 不可连接且仍有容量时直接创建新身份的空白 shell，旧 UNKNOWN 保留。再次进入不重试不确定的自动启动，原命令从不自动重发。异常空态同时保留明确的新建入口。

- **清空当前显示**：只重建本地显示解析器，保留输出游标；不发送 `clear` 命令，不清理 shell history，不停止进程或改写审计。
- **停止并关闭终端**：明确确认后按原身份停止，得到真实停止证明并 ACK 后移除会话入口；工作区不删除，未知结果不改成成功。十五秒内无法证明停止会显示未确认，并保留身份。
- **删除并重新准备 Linux 环境**：运行环境维护页的独立操作，沿用共享维护准入与停止证明。只清理 `filesDir/runtime`，包括展开环境、环境内安装的软件与文件、尚未收取的 Job 结果；该目录外的聊天、账号、Provider 和工作区保留。删除不跟随符号链接越界。存在未经证明已停止的终端/作业时不会先删环境再报成功。
- **停止并重置所有终端**：明确确认后停止捕获到的全部旧终端，仅移除有真实停止证明的会话入口，清理连接和显示；全部旧会话已结束才新建空白 shell。有任何未确认身份时显示重置未完成，保留身份并提供重启后恢复路径。聊天、账号、Provider、模型及工作区文件保留，必要执行凭据保留。不会调用全应用清除 API。

UNKNOWN 占满名额时不删除元数据来绕过物理上限。保留数据的恢复出口是设备重启后的停止证明：正常 Runtime 日志已有重启证明；日志缺失时，`TerminalBootRecovery` 先持久记录精确 execution/generation 和当前系统启动次数，严格更晚一次设备启动后才释放同一旧绑定并保留独立恢复凭据，命令结果仍为 UNKNOWN。只在原日志确实 NOT_FOUND 时使用该宿主证明，不伪造 Runtime ACK。若首次观察已在重启后，需一次后续重启；读取不到启动次数或证据损坏时不猜测。同一次开机内无法可靠结束的旧身份，必须等待退出证明或重启后的证明，不能靠删除元数据冒充停止。用户已明确排除全应用清除，该实现及入口已移除。

没有宣称存在“身份丢失时仍可无损一键杀掉全部旧子进程并立即重建”的普通 Android API。不会根据旧 PID 猜杀其他进程。不通过开放权限、root、全应用清除或反射绕过平台限制。

关键实现为 `ManualTerminalViewModel`、`DeveloperManualTerminal`、`TerminalBootRecovery`、`ManualTerminalViewport` 与 `ProotRepairActivity`。沿用 [ADR-RUNTIME-002](../adr/runtime/002-terminal-and-jobs.md)。采用了 Termux 的页面与新 shell 分离思路，没有复制其代码。

现有 Runtime 模型已经将 `PtySessionRecord.phase` 与 `stopProof` 分开：例如 `phase=UNKNOWN` 同时有 `DEVICE_REBOOT` 停止证明，表示本地进程已停止、原命令结果仍未知。UI 的 `canSettle` 来自停止证明，`TerminalInfo` 将这种情况显示为“旧终端已结束 · 原命令结果未知”，不会继续显示成仍在运行。缺日志的宿主启动凭据保持同样语义；没有为了回收名额改写命令结果。

停止保证只针对这个本地 Runtime 管理的终端进程树。通过 SSH 已交给远端服务器的任务、外部 App 已接收的工作和已经产生的文件/网络副作用，不因本地 shell 退出、环境重装或手机重启被宣称停止或回滚。修复 Linux 文件和确认进程退出是两件事。

## 历史 Provider / model 绑定

根因是多个发送/计划/重试路径仅用 `chatSelectable` 的布尔结果，统一显示未测试；Provider 删除后，Room 外键将历史会话的 providerId 置空但保留 modelId。`currentSession()` 本来就重新读取 Room，不将“内存缓存旧会话”作为已确认根因。

`ProviderBindingValidation` 在发送、出站确认、执行计划和重试前重新读取当前持久来源；只要确实删除，就算残留 Passed 状态也不允许复活。界面投影区分来源删除、配置变化待重测、缺少有效模型、认证不可用、网络失败、其他测试失败与真正未测试，提供就地选模和模型设置入口。草稿不清除，也不自动替换 Provider/model；选模或重测恢复后清除对应旧错误提示。

连接变化会持久标记“配置已更新”，新测试提供新的结果后替换标记；显示名或选模偏好变化保留有效绑定。隐藏于新选模菜单不代表历史模型失效。内置模型只有新鲜且成功的账号目录能证明已退目录；失败或过期目录不能撤销原绑定。普通自配 API 的目录仍是展示证据，不能将任意 HTTP 错误猜为模型不存在；已知认证、网络和其他错误保持各自类别。

原传输/认证/能力校验及出站目标绑定继续生效。能力默认值和原手动视觉声明存储逻辑抽到 `ProviderDefaults`，保持原 mutation gate；未扩大工具权限。设计记录在 [ADR-PROVIDER-001](../adr/provider/001-models-and-connection.md)。

## 验证边界

新增主机测试 20 项：终端动作 9 项、缺失日志的启动证明与精确身份释放 4 项、Provider 分类及持久标记/目录边界 7 项。包括新 shell 不重放/不接管、物理容量不绕过、无证明不删除、证明后关闭、只清显示、已证明退出的重置与未知退出拒绝、同启动次数/更早启动次数/替换身份不释放、跨宿主实例保留证明、删除来源优先于残留成功证据，以及认证/网络/配置变化的区分。补充部分重置只关闭已证明会话，以及停止中取消不清身份、不启动其他 shell。

`HistoricalProviderBindingDeviceTest` 补充真实 Room/服务的两项合成回归：历史会话删除来源后的 FK 恢复、来源修改保留精确绑定并在重测后恢复；本轮仅编译，未在设备执行。它们不访问真实账号或模型服务。

./gradlew :app:assembleConsumerDebugAndroidTest :app:assembleDeveloperDebugAndroidTest --max-workers=1 -Dorg.gradle.parallel=false

完整门禁覆盖主机脚本、文档/ADR/国际化/秘密扫描、格式/Detekt、双渠道 Debug/Release lint、JVM 测试、Debug/Release/R8 构建、release-smoke 测试 APK 编译及最终产物边界。Consumer Debug 单测共 1,434 项，Developer Debug 共 1,582 项，各有 5 项既有条件跳过，均零失败和错误；20 项本轮新增测试均执行通过。两渠道设备测试 APK 编译通过。四个最终主 APK 的 DEX 均未包含已撤回的全应用清除 API 引用；生产源码与资源中该调用及入口检索为零。

初轮格式/复杂度检查曾失败，按职责拆分校验/确认 UI 和保守能力默认值后重跑，没有新增 lint/Detekt 豁免或弱化安全边界。首次进入策略改为新 shell 后，回归断言相应覆盖新身份、不重复自动启动、不重放与原未知身份保留。执行连接曾断开，恢复后先读取原进程结果，再运行必要检查，没有把不确定结果记为通过。用户明确限定终端数据后的最终代码已重新完成上述门禁，撤回方案的早期构建不作为当前验收证据。

主机日志、源码/产物绑定及哈希在忽略的 `build/terminal-only-provider-*` 本地证据中。设备状态为 **not requested**：未启动或连接真机/模拟器，未实际执行 STOP/数据删除/环境重建/设备重启，也未验证手机上的交互和视觉效果。真实系统停止与重启回收、OEM 启动次数可用性、环境重建效果，以及真实 Provider/账号服务的请求恢复，仍需另行明确授权的设备/服务验证；不将主机通过、测试 APK 编译或早期其他任务的设备记录当作这些检查通过。源码仍为本地未提交改动，没有推送、发布或修改版本。
