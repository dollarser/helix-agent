### HXA-286 应共同明确的最小语义

这些是需要对齐的事实，不要求再造统一执行服务、固定字段数量或让每个同步工具拥有 Job。

- **身份与归属**：区分 turnId、toolCallId、jobId/executionId、实例 generation、执行资源句柄、artifactId 与 MCP 内容 URI；明确各自由谁创建、保存、引用及清理。句柄本身不授予控制权。
- **四个完成条件**：调用结算、实际执行退出、输出已经收尽、结果/产物已持久化各有判据；输出截断或尚未收取不能悄悄转成完整成功。
- **取消语义**：取消请求已受理、后端确认、实际物理退出分别表达；停止等待不自动停止原 Job，超时不立即释放尚占用的容量。
- **崩溃窗口**：开始屏障前失败、实际执行后落盘前崩溃、落盘后通知前崩溃分别对账；未知结果不得通过重放业务动作来“补齐”。
- **资源清理**：原调用/Job/插件引用与活跃消费者决定生命周期；迟到旧 generation 不影响新实例，页面关闭不等于所有资源无主。
- **上下文正确性**：冻结模型输入来源、授权投影与 call/result 配对；恢复后从同一持久事实重建，不依据当前页面或全局可变上下文。

### 每片需要的反例，不能留到 294

| 反例 | 应证明的行为 |
| --- | --- |
| 取消后 executor 迟到回调，物理资源仍存活 | 原调用只结算一次；新调用不被覆盖；实际退出前不误释放资源 |
| 外部效果已发生、持久结果尚未写入时崩溃 | 重载为可对账/UNKNOWN，不伪造零副作用，不再次点击、提交或运行命令 |

| 插件缺失/更新/撤权发生在排队、批准、开始之间 | 根据原 Binding 和当前权限拒绝；不按同名插件重新绑定，不消费不适用的旧批准 |
| 两个普通运行交错、恢复时切换页面或模型 | 历史、权限、结果、用量和 Memory 快照不串扰；不需要先实现子 Agent 才能验证 |
