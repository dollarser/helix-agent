Date: 2026-10-16
Owner: Project owner（要求调研、现在实现必要首版、同时补充后续重构；不兼容旧内部方案）

源码基线：`6bbff42d`，开始时 `main` 工作区干净。本文记录研究和取舍；实施/验收归 [HXA-295](../../development/tasks/HXA-295.md)，长期契约归 [ADR-AGENT-001](../../adr/agent/001-turn-coordination.md#17-会话查询与管理)。没有由本次请求推导设备、真实 Provider、提交或发布授权。

## 1. 结论

Helix 需要会话能力，但需要分开三个对象：会话保存对话，Turn 表示一次执行，终端/插件资源有独立生命周期。读取旧记录、开始新 Turn、给活动 Turn 插话分别是不同操作；不新增含混的通用 `execute(action,args)`，也不为了桌面产品对齐而增加远程主机。

现在最有确定性价值的是让模型找回当前会话已保存但已离开上下文窗口的信息、重新读取用户已经分享的引用，并整理当前标题。用户界面已经具备创建、分支、重命名、归档/恢复和搜索，不重复制造按钮或另一套会话表。首版采用这条完整功能路径；跨会话列表/历史授权、创建和消息投递统一承接后续应用宿主重构，不能直接把宽 `ChatService` 暴露给模型。

## 4. 现在交付的首版

| 工具 | 行为 | 硬边界 |
| --- | --- | --- |
| `session.status` | 读取当前会话 ID、标题、归档标记及原 Turn ID | 不启动/恢复执行，不返回 Provider 密钥、内部目录或其他会话列表 |
| `session.history` | 从新到旧翻阅已保存 USER/ASSISTANT TEXT 元数据，包括压缩前仍保留的正文和引用入口 | 排除被修订替代的消息、系统提示与工具执行轨迹；每页有明确旧消息游标 |
| `session.search` | 对上述正文与已保存引用做大小写不敏感的字面搜索，返回来源及短片段 | 有界扫描，空页仍可继续；不可读/超限明确计数，不把“没找到”说成“没有” |
| `session.read` | 按消息 ID、内容哈希和可选引用序号读取正文，以 Unicode 字符分页 | 校验原调用与本会话归属；引用只读已保存字节，绝不回源；不重新打开附件或截图 |
| `session.rename` | 带旧标题条件修改当前标题 | 正常 LOCAL_MUTATION 授权；Chat/Plan 不获得新豁免；SQL 同时核验原活动 Turn/call，仅更新 title |

工具由宿主贡献，两个渠道共用正常发现、Schema、Dispatcher、Policy、结果与审计路径。Mobile Use 继续拥有其手机操作实现；会话工具不是其插件功能，也不能修改其授权。无需新增常驻配置提示；模型需要历史时按需发现工具，日常界面仍使用已有入口。

`SessionHistoryDao` 只查询既有表；`SessionHistoryRepository` 复用 ContentStore 和 Room 身份事实。分页是有效历史的有界视图，不声称整个多页结果在并发修订期间是不可变快照；继续翻旧页不因新追加消息漂移，读取时重新核查有效消息与内容身份。正文超过单次读取上限时明确不可用，首版不承诺任意大消息全文搜索。保存历史中的“已完成”仍只是历史陈述，工具结果另沿已有结果/任务入口核实。

本轮没有提供模型可调用的全库 `session.list`、任意会话 `create/send/archive/restore`。这些属于下节已排期扩展；既有用户 UI 能力仍可使用。没有先做临时全库放开、再计划未来补权限。

## 5. 后续目标契约

目标保持进程内应用命令与查询，类型/命名可在重构中直接替换，不保留旧别名、双实现或永久桥。以真实行为和测试接续首版，不以首版内部类名限制终态。

### 查询和授权

- `session.list/status/history/search/read` 仅返回当前会话和用户明确授予的目标。目录元数据同样有数据边界；同项目、同目录、同模型、知道 ID 或曾分享快照均不等于读取授权。
- 跨会话读取、元数据修改、投递任务分别授权。宿主保存调用方、目标集合、操作集合、版本和必要披露绑定；授权只能由用户动作/已有用户规则产生。界面使用现有会话选择和授权呈现，一次选择可按用户范围持续生效、可撤销，不逐消息反复确认。
- 列表、分页、搜索在查询前过滤范围，发布前复检撤权；游标绑定查询、目标、方向和有效版本，不能换会话复用。读历史不能开启目标运行或获得原附件访问权。引用仍是独立快照，不自动升级成持续读取许可。

### 创建和整理

- 创建只建立本机新会话/必要工作区关系，返回稳定 ID；不隐式运行模型。新会话使用用户的新会话设置，插件选择值和能力授权分开；不从来源复制 Mobile Use grant、审批 proof、取消句柄或 node/frame。
- 需要开始工作时再经有身份/配置绑定的 submit。创建重试用持久 receipt 去重；创建已提交但通知丢失可查回同一对象，不因没收到响应再建一个。
- 重命名、归档、恢复使用目标身份和并发条件。归档只是组织状态，不代表停止、删除或撤权；如不能发送到归档目标，明确返回原因，不能偷偷恢复。永久删除暂不加入模型工具面。

### 消息投递和继续任务

- 原应用命令接受可信用户输入与获准委托输入两种来源，后者保留源 session/Turn/call、目标与授权引用。接收方能看出是转发内容；文本不能自己声明 `user`、批准范围、启用 Skill 或复制父权限。
- Queue 等目标可接收后开始新 Turn；Steer 明确绑定活动 `expectedTurnId`。目标已结束/变更时拒绝 stale steer，不能静默附到后来运行；用户明确选择的 Queue 按现有准入顺序消费。
- 已结束会话可接收新任务，但旧 Turn 终态不改写。历史 UNKNOWN 不重放，按现有 successor/恢复规则执行。停止、审批、配置和模型选择仍属于原宿主 owner。
- 回执分清 accepted、queued、appended、running、terminal/rejected；受理不是执行成功。采用持久输入 receipt、CAS 和重载对账；取消等待者不撤回已接受的输入，同 key 同内容返回原回执、不同内容冲突。
- 发送权不等于目标拥有任意执行权；运行必须满足目标当前授权以及用户允许的委托范围。不能把源会话的 FULL_ACCESS 或目标既有较宽授权当成转发任务的无限升级路径。
- 首个产品范围不建立递归派生或自动相互唤醒循环。多 Agent 的父子图、并发/汇合和递归预算仍归独立委托主题；远程电脑/环境、账号和连接认证不在本单手机任务中。

## 6. 验收与收益判据

首版覆盖当前身份、已压缩历史仍可定位、旧消息分页、新追加不污染旧页、外会话 ID/错误哈希拒绝、引用源变更/删除不回源、Unicode 边界、缺失/过大正文、取消/过期、并发修订、标题 CAS 以及通知失败不改写已提交事实。SQL 编译、JVM 替身测试、实际 Room/进程重建和真实模型遵循分别报告。

扩展另须测试撤权后搜索不泄漏元数据、跨项目/同名会话混淆、审批后目标变更、重复创建与重复输入、Steer 竞争终态、A 停止不影响 B、投递后进程死亡、收件方不能消费发件方授权、归档不停止和 UNKNOWN 不重放。三种 Provider 的消息配对、无页面完整 Turn、真实 Room 及设备恢复沿任务逐层验证，不能从主机通过推导。

后续真实模型任务至少比较：多次压缩后查回用户纠正、从已分享会话查回决定、后台任务追加约束再回收结果。记录定位准确性、越界拒绝、用量和延迟；不把新增工具数或一次演示当成完成率提升。
