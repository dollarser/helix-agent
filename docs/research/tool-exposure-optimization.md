# Agent 工具曝光与能力复用优化建议

日期：2026-09-18。性质：优化方向建议，尚未立项或实现；不改变有效 ADR、工具授权或现有契约。实施遵循[能力规划规则](../development/implementation-guide.md#应用能力与-agent-工具的规划规则)。

## 问题与证据

Helix 已区分应用服务与 Agent 工具，业务扩展可通过 MCP/Connector/Skill 复用现有执行管线。当前最值得优化的是工具曝光，而不是重写执行引擎。

- `McpToolDiscovery.visible` 对 MCP 提供搜索和有界窗口；非 MCP 工具通过模式与禁用检查后仍整体参与曝光。
- `ChatRequestAssembler.modelTools` 组装后按固定优先级排序，最终 `take(ModelRequest.MAX_TOOLS)`；工具可调用、当前相关和容量限制尚未充分分离。存在截断风险，不代表已测得当前模式必然超限。
- `DefaultAppContainer` 注册 Skill/Connector 预览安装等管理工具；这些具有真实辅助安装用途，但普通任务未必需要完整 schema。
- Plan 是用户审阅工件，Todo 是轻量进度投影，Goal 是持久目标执行，当前不能仅因名称相似判定重复状态机。

上述为源码检查；尚未测量各模式实际schema token、工具选择准确率或延迟收益，不能以推测百分比承诺优化效果。

## 建议方向

| 优先级 | 建议 | 保留的边界 |
| --- | --- | --- |
| 1 | 测量各模式/预设的候选、曝光、被截断工具数及schema字节/估算token；区分内置、MCP、A2A | 使用合成配置，估算标来源，不采集用户正文或凭据 |
| 2 | 评审将现有按需发现机制扩展到内置/其他已注册工具；少量核心工具常驻，专业能力按需加载 | 加载不授权；禁用即时作用于发现、请求与执行；不造第二套Registry |
| 3 | Skill/Connector安装管理工具按明确任务需要曝光 | 不删除现有工具；安装不自动连接、启用或授予范围；用户管理入口保持可达 |
| 4 | 优先完善207的扩展实际使用闭环，新增业务复用MCP/Connector/Skill | Android原生动作或现有协议无法表达时可新增原生工具，需说明理由 |

核心工具集合、分组、窗口容量与淘汰策略先由真实任务矩阵验证，不在本建议硬编码。禁止按自然语言猜测权限；相关性选择只影响可见性，不改变授权。已加载工具在多轮任务、压缩、重启、模式切换后的行为需明确定义。超容量须有可诊断、可重新发现的路径，不能继续静默丢失唯一所需工具。

## 不建议的改造

不把所有端侧能力包装成本机MCP服务；不以bash替代Standard可用的原生文件/浏览器/系统接口；不删除Turn、审批、持久结算、取消、未知副作用对账和资源限制。普通任务不强制启动Goal/PRoot。Plan/Todo/Goal先约束职责，不新建统一工作流账本。生产子Agent、同Turn转向、通用hooks不是本优化前置。

## 实施顺序与验收

1. **只读基线**：固定少工具、大MCP目录、混合来源、禁用、模式切换等配置，记录实际曝光与截断；固定文件处理、浏览器、扩展安装、纯问答场景。先决定收益是否足够，不预先批准重构。
2. **契约评审与独立立项**：明确核心集、发现范围、窗口生命周期、失效与诊断；若改变跨模块契约按ADR规则评审。不要夹入191/193/204/205，不增加这些任务的前置条件。
3. **最小实现**：复用现有Registry/发现路径和Dispatcher；不新增规划器、业务专用循环或并行授权来源。
4. **功能及资源验收**：禁用后不可发现/曝光/执行；模式收紧、分页/重复发现、切换会话、压缩、重启与过期schema；任务中途能够找到所需工具；比较同fixture任务成功率、误选/重试、模型调用次数、schema体积和延迟。优化不得只凭工具数下降判成功。

应用搜索、主题、设置、准备和手动导出继续属于应用能力；Agent使用这些能力需要独立用户场景和授权设计，不因有页面便增加工具。
