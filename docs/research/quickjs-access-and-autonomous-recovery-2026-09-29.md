# QuickJS 访问配置与自主恢复：当前讨论边界

日期：2026-09-29。本文记录所有者追加需求与尚待选择的设计，不是生产交付或验证证据。实施仍以当前 ADR、status 和正式任务为准。

## 已确认需求

- QuickJS 需要访问网络、文件和 Android 能力。所有者先选择直接原生 API，随后要求重新考虑权限可配置性。
- 异常恢复交由模型：不把“确认已发生／确认未发生／接受未知／手动重试”作为用户必须完成的恢复步骤。模型检查当前状态、判断剩余任务，在原有权限内修复、改用其他方法并继续；确认无法解决时说明原因并停止。
- UNKNOWN 仍是持久执行事实，不能因为取消、超时、模型推测或放弃而改写成成功或未发生。模型核查结论必须标明来源与依据，不能伪造用户确认。未确认的外部提交不能盲目重放。
- 用户主动停止始终优先。权限授予、Android 系统授权、原有审批及预算不会由恢复过程自行扩大；缺少必要条件且无法绕开时如实停止，不把任务伪装为完成。

## 仍待选择的访问契约

1. 三类独立权限：网络域名、文件目录与读写、指定 Android 能力。要使禁止项不可绕过，必须保留隔离进程，经受控原生接口访问，不能同时提供任意 Java 反射。
2. 任意原生 API：脚本与应用共享 UID，只能提供可信的整体访问开关；网络／文件小开关无法约束任意 Java/Android 调用，不能作为安全承诺。

所有者尚未回答这两个方案的选择。原生访问原型尚未提交，主机编译与单测已有执行，格式／静态检查尚有失败；没有设备验收结论。当前任务已获得独占 API36 定向验证授权，未使用真机或真实外部账号。

## 恢复实现要求

沿用 TurnEngine 唯一生命周期 owner、不可变原 ToolCall 事实、successor Turn 和现有权限路径。需要新增自动恢复激活及模型核查接线，不能仅隐藏现有人工按钮；当前生产仍有人工核查路径，本需求尚未实现。

恢复必须携带原始目标、精确未决调用、已完成步骤、可查询身份和执行记录。先确认旧 executor 是否仍在运行，避免与其竞争；有必要时完成终止／对账。模型可做只读检查；新的补救副作用仍经当前权限和执行准入。平台保存模型结论及其证据来源，不将推测提升为 executor 回执。

UI 展示“正在自动检查／恢复”及最终结果。模型判断无法解决时报告已完成部分、停止原因和仍未知的效果，不要求用户承担副作用核查。缺少模型服务、权限或设备条件时展示实际未完成原因；不得空转、自动扩权或假装恢复成功。

验收至少覆盖：提交已生效但响应丢失、确定未开始、部分文件写入、executor 尚未退出、连续恢复无进展、用户停止、权限撤销、重复恢复通知、进程重开、模型放弃及恢复过程再次失败。自动恢复本身也需要持久去重和用量记账，不能重放原调用或复活旧 Turn。
