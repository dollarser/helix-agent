# Helix UI 与交互优化方案

初始审查日期：2026-09-22。本分支已实施[HXA-218第一批UI重构](../completion-records/HXA-218.md)与[HXA-219产物就地预览](../completion-records/HXA-219.md)；`@`/`/`及其余建议仍是后续设计范围，未接受新ADR。下文源码判断记录实施前的审查快照，不能当作重构后的现状。

核验基线：本地 checkout `645fa680` 的源代码、状态、路线及有效ADR；实施后的[当前状态](../development/status.md)与[路线](../development/roadmap.md)另行维护。竞品依据为当日读取的官方公开资料，未安装同版本APK做并排实测；本文不提供竞品性能排名、屏占比实测或已完成的用户测试结论。后续实施前重新核对基线。

## 1. 结论与设计目标

原审查的方向合理：降低常驻信息密度、让结果靠近对话、统一状态和恢复入口，适合 Helix。问题诊断有部分过时：当前已经存在会话详情弹窗、胶囊工具栏、工具摘要折叠，不应按“全部平铺”的前提重写。

建议目标表述为：**在保留完整能力与执行可追溯性的前提下，让用户随时知道正在做什么、需要自己做什么、结果在哪里，并能顺畅继续输入。**

Helix 首要服务开发者与效率用户。借鉴消费级产品的易用性，不意味着隐藏所有运行信息、削减 Standard 能力，或把终端与文件管理变成聊天附属品。视觉轻量和任务可控应同时成立。

## 4. 信息架构：全局导航与会话工作台分开

首版推荐保留抽屉并分组，减少导航迁移成本。抽屉不是问题本身，平级堆放配置页和工作页才是问题。

| 分组 | 入口及职责 |
| --- | --- |
| 会话 | 最近会话、搜索、新建；运行/待处理标记能定位具体会话 |
| 工作 | 任务、文件与产物、已有 Git 变更；浏览器保持可独立使用 |
| 扩展 | 市场与已安装能力；复用现有支持的安装、连接、启停行为 |
| 设置 | 模型与连接、权限、能力与开发环境就绪、外观、审计、关于 |

“权限”在全局设置维护默认/管理入口，在会话上下文中提供当前授权预设的快捷入口；两处使用同一状态源。“需要处理”从当前任务直达问题，不要求用户先找到设置里的 Readiness。历史审计进入二级页，待审批操作仍留在工作流内。

工作区内复用“文件、任务、终端、变更”分段入口，遵循[任务与工作区体验](../product/task-experience.md)。浏览文件不依赖 Provider，终端入口按渠道和实际能力呈现。文件管理权限不自动授予 Agent。

底部导航作为后续 A/B 原型候选：对话、工作台、扩展三项，设置放入菜单；仅当跨主区域切换的用户测试明显获益才采用。若采用，进入专注会话/键盘展开时收起全局底栏，保留稳定返回入口。不能同时常驻 Tab、工具栏和产物底栏来实现所谓减负。

## 5. 会话布局与组件规范

### 5.1 顶部：一个标题、一个上下文入口

默认排列：导航/返回 → 会话标题 → 会话上下文按钮。根据实际路由只出现一种主要返回语义。新建会话放历史面板，导出与重命名放上下文面板；保留标题点击重命名的现有行为，避免同一手势既改名又开详情。

普通字号头部高度目标 56～64dp，不把 56dp 当作硬上限。大字体允许增长；所有操作有不小于 48dp 的独立触摸区域，不用“极小浅灰字”承载必要信息。Android 对触摸目标的建议见[Compose accessibility defaults](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)。

上下文面板按顺序展示：当前模型与连接 → 会话模式/授权摘要 → 当前目录和附件/上下文信息 → 导出、重命名等管理动作 → 技术详情。模型选择只设一个主要入口，建议与 Composer 控制合并，顶部不再重复放模型副标题。

手机用可滚动 Bottom Sheet，短横屏或大字体用全屏面板；迁移现有 AlertDialog 的呈现层即可。保持数据去向披露、当前授权范围可查，不能以减负为由删除必要的实际发送确认。

### 5.2 状态：常驻只显示需要注意的事情

状态分为三个位置：

- 全局：导航入口显示其他会话的待处理数量，点击打开有会话归属的列表。
- 当前会话：只有运行、待审批、暂停、阻塞等需要关注时，显示一行可点击状态摘要；空闲时不留空位。
- 当前 Turn：消息流内展示阶段、工具、结果和对应恢复动作。

Goal 管理/TaskLedger 合并为一条真实状态摘要，例如“目标进行中 · 已完成 2 项检查”，点击看检查点、预算、暂停/继续。未知总步骤时不用百分比。历史失败留在对应 Turn；当前阻塞给出一句原因与一个主动作，同一错误不在顶部、工具卡和底部重复三遍。

### 5.3 输入区：一个编辑面、按需控制

默认输入框 1～5 行随内容增长；超过上限内部滚动。附件按钮、输入、发送/停止有稳定位置。语音转文字先进入可编辑草稿，沿用已有显式发送行为。

将现有常驻多胶囊行压缩为一个“模式 · 模型”控制入口，打开设置面板调整推理强度等参数。普通上下文占用和手动 Compact 放面板；接近容量限制时才显示清楚标为“估算”的紧凑提示。不得把模型上下文容量、Turn 预算、Goal 预算合并成一个百分比。

附件仅在存在时显示横向卡片：名称、类型、暂存/可发送/失败状态、移除操作；移除只移除本次引用，不删除源文件。附件多时显示数量与展开入口，不让无限横向滚动成为唯一访问方式。

HXA-214 验收前不承诺重建后草稿保留；HXA-216 验收前不显示可用的 Queue/Steer 控件。运行中草稿编辑、发送和停止是不同动作。216 落地后的设计为：普通发送“排队发送”，显式次操作“转向当前任务”，停止保持独立可发现，不能随输入非空而消失。

### 5.4 `@` 引用与 `/` 指令：独立功能切片

`@` 首版仅检索当前会话可引用的工作区文件及已存在产物；不扩张为全盘索引。键入触发有界候选列表，支持中文输入法 composing、光标中间编辑、无结果、重名与权限失效；邮箱、代码等普通文本可以不选候选直接输入。附件按钮提供同样入口，避免快捷语法成为唯一方式。

选择后复用[附件快照契约](../adr/agent/003-attachments.md)：捕获明确文件身份，创建/复用适用的不可变快照，校验大小、类型及哈希，再进入待发送附件。列表显示名不是授权，选择附件不授予目录访问。未支持的文档/音视频说明无法用于模型输入，不能静默当作已理解。外部来源仍走既有 Picker/导入路径。

`/` 首版是封闭的 UI 动作注册表：`/plan` 打开模式选择并明确应用，`/export` 打开现有导出面板，`/new` 新建会话。取消候选保留字面文本。暂不采用语义不清的 `/clear`；若增加“清空草稿”，明确只影响草稿，不删除消息、压缩上下文或终止 Goal。快捷命令不直接运行 bash、授予权限或启动新工作流。

这两项包含搜索、解析、上下文绑定与恢复契约，属于功能开发，优先级低于发送可靠性及就地查看结果。

### 5.5 执行流：状态摘要、工具组、结果卡

默认层级：

1. 正在进行：一行真实阶段，例如“正在生成回复”“正在读取文件”“等待你确认”。仅当前活跃项使用轻量动效。
2. 已结算操作：按 Turn 聚合为“完成 4 项操作 · 1 项失败”，展开后按原调用顺序呈现；失败、待审批、未知结果不能被成功摘要掩盖。
3. 单工具：动作名称、对象简述、状态和可用耗时；展开复用现有 3 行参数/5 行结果摘要，再进入完整详情。
4. 结果：正文后的 Artifact/Diff 卡，直接预览、查看来源、导出或打开已有支持的查看器。

动作描述以确定性模板读取既有结构化结果。只有存在真实变更证据时才写“修改了 2 个文件”，不能根据工具参数、模型自述或 exit code 推算成功修改数量。聚合仅改变显示，不改变工具并发、结算或上下文回放顺序。

“思考”组件改称“处理过程/推理摘要”：只有 Provider 返回允许展示的内容才提供展开；只有活动信号时展示处理中，没有正文就不显示空折叠箭头。等待网络的时间不标成思考耗时，不要求模型输出隐藏推理。ReasoningEffort 仍是配置项。

不采用持续大面积 Shimmer；尊重系统动画设置。屏幕阅读器只播报阶段变化，不能每秒播报计时。代码与 Diff 优先保证等宽、复制、横向滚动/换行切换与大输出截断标记，语法高亮随后优化。

### 5.6 就地工作台：预览优先，完整页面仍可用

Artifact 卡是首要入口；有本轮产物时可在状态摘要显示“查看产物（2）”，不增加常驻悬浮球。短文本、图片、有界 Diff 用底部面板；长文件、长日志和终端编辑用全屏，平板/宽窗口可使用并排面板。终端不塞进半高、无法有效输入的抽屉。

复用命令详情、产物和文件的应用服务及只读投影。预览和全屏是同一内容的两种容器，不另建结果仓库。HTML/网页交给既有浏览器所有权边界，不引入带主机权限的永久 WebView bridge。

打开面板保存 session/turn/call/artifact 身份、消息锚点、草稿和来源位置；关闭回到原消息，不能跳到最新回复。结果过期、源文件变化、权限丢失按既有四态可用性处理，不用同名文件替换。打开预览不重跑工具，关闭终端页面不等于结束终端进程。

同一时刻仅一个模态工作面板。若审批到达，显示可发现的待处理提示，用户可收起预览去审批；不自动叠三层弹窗、不自动确认。返回键先交给当前输入/模态层，依 Android 焦点行为消耗一次，再回来源页面；关闭后恢复可访问性焦点。

## 6. 关键状态与操作语义

| 场景 | 用户看到的内容 | 主动作/恢复行为 |
| --- | --- | --- |
| 尚未配置模型 | 空态一句说明；草稿可编辑，文件等独立能力可用 | 选择/添加模型，完成后返回原草稿 |
| 请求准入失败 | 输入旁显示具体原因，不清空输入 | 修正配置或重发；不把失败稿显示成已发送 |
| 等待发送确认 | 明确“待确认”，绑定本次内容与目标 | 确认或取消；旧确认不能清掉新版草稿 |
| 执行中 | 实际阶段与独立停止入口 | 可准备草稿；排队/转向依216，不提前启用 |
| 等待工具审批 | 展开操作、目标及实际影响 | 沿用当前允许/拒绝路径，不因卡片折叠隐藏审批 |
| 取消中 | “正在停止”，关联目标稳定 ID | 防重复点击；未知副作用显示待核查，不能提前写已取消 |
| 中断/断连 | 已确认结果与待核查结果分开 | 优先查询/恢复；不盲目重放有副作用操作 |
| Goal 暂停/阻塞 | 原因、检查点和下一步 | 区分继续、补充条件和停止；发消息不冒充授权 |
| 部分成功 | 已完成产物及失败项分别可见 | 查看可用结果，再处理失败项 |
| 结果不可用 | 过期/变化/缺失/权限问题的真实原因 | 现有恢复或返回来源动作；不制造空白预览 |

上述目标与214/215/216/217对齐，状态来自已有应用服务；视觉组件不另存“执行成功”或授权状态。编辑重发依215创建分支，不回滚工作区；上下文清单依217，不用静态 UI 假装当前请求已经包含某个文件。

## 7. 视觉、可访问性与内容规则

- 采用现有主题体系与语义色：正文、中性辅助、进行中、待处理、失败；不让每个系统状态都变成红条。状态必须同时有文字/图标，不能只靠颜色。
- 建议使用 4/8dp 间距节奏、16dp 页面边距和少量统一圆角；连续正文不逐段包厚卡片，卡片留给操作对象和交付物。
- 主要正文建议 16sp 起，辅助信息建议 12～14sp 起；以大字体、对比度和中英混排验证后定稿，不能以字号小换屏占比。
- 消息流在用户靠近底部时跟随；用户正在阅读历史时保持锚点，显示“新内容”入口。折叠/展开工具不把阅读位置拉到尾部。
- 长按可提供复制、分支等次要动作，但同样提供可访问的显式菜单；中文输入法候选、长路径、Emoji、代码块、链接和错误文案纳入验证。
- 离线、加载、空列表、无结果、权限失效都有短说明和适用动作；不为被渠道排除的功能提供无效“开启”按钮。
- 应用内术语优先“模型与连接、文件、运行记录、开发环境”；Provider/PRoot/Binder/CAS 等进入技术详情。Standard/Advanced 与会话授权预设是不同维度，不混成一个安全等级。

## 10. 验收与收益度量

以下是建议验收目标，尚未测量通过。U0记录原始值，后续同一设备、数据集、字号和窗口复测。

| 维度 | 验收目标与口径 |
| --- | --- |
| 常态空间 | 360×800dp、字体1.0、无IME/附件/告警时，消息视口至少占可用内容高度70%；系统状态栏与导航栏从分母排除 |
| 键盘状态 | 同设备扣除IME后的可用内容高度中，消息视口目标至少50%；大字体优先保证输入、停止/审批可操作，不硬套比例 |
| 基本可达性 | 当前会话模型选择≤2次操作；产物打开预览≤1次；返回对话≤1次且原锚点不变；全局现有功能≤3次，外部系统选择器另计 |
| 稳定性 | 固定场景中草稿丢失、重复发送、串会话回执、误停新任务、预览触发重执行均为0；按214等实际交付范围验收 |
| 执行可理解性 | 用户能区分生成中、工具中、待审批、取消中、已失败及待核查；不能把动画当状态证据 |
| 可访问性 | 320/360/412dp、字体1.0/1.3/2.0、中英、明暗主题、横屏、TalkBack及减弱动画；无关键控件裁切、重叠触区或不可到达动作 |
| 性能 | 同基线数据复测长会话/大量工具/大输出滚动；帧时间、内存与首开延迟不得显著退化，U0先固定测量方法和容差，不编造毫秒结论 |
| 真实任务 | 5～8位目标用户完成发附件、审批、停止、看Diff、导出、切会话继续输入；记录完成率、误触、耗时及无法解释的状态，作为小样本形成性研究 |
