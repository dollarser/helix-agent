## 失败、续跑与独立事实

1. 首次任务输入采用 ADB 按键注入，与已启用拼音输入法组合后文本变形。该轮无抖音安装；中断及恢复 Turn 保留，不算业务验收。后续改用公共 UI 的 `ACTION_SET_TEXT`，发送前从新鲜层级精确比对完整中文输入；旧缓存导致的夹具断言失败亦保留。
2. Turn `ec9fca118cdf9ff0e83f174974db670b` 完成官方来源下载/安装，打开抖音后模型请求经本机中转失败；原状态 `FAILED/SERVER_ERROR`。下一续跑 `8e034a99af0bfa92d42c8ca478815d38` 同样失败。中转只记录 `URLError` 类型，无法据此判定远端服务根因。更换同一 Provider 为 Owner HTTPS 地址直连后，连接/能力测试和后续模型请求成功；不抹去原失败，也不宣称网络问题根治。
3. 最终业务 Turn `6cd9a2e4de713a392928c3ebaf3605b9` 完成启动同意、拒绝无关通知权限、尝试视频核验、卸载及返回。48 次工具调用；4 次 `ui.screenshot` 均为 `TARGET_CHANGED`，语义观察也多次拒绝。结束后无活动 Turn，抖音不存在。
4. 独立样本 `journey-4/0030` 与 `0050` 相隔约 84 秒，同一视频页面出现不同画面；AudioFlinger 中抖音 UID 的同一活动音轨仍在推进。因此播放已被触发，但画面严重损坏。只读主机取证没有回填给模型作为其视觉观察。
5. 模型最终回复把观察失败归因为 `FLAG_SECURE` / 登录阻挡，这一归因**不受证据支持**：同期 WindowManager 的可见抖音主窗口没有 SECURE 标志，主机截图也显示公共推荐视频。这里只确认观察/渲染失败，不推导保护或账号要求。
6. 当前 Shizuku 实现为 `deviceTarget()` 对完整语义树计算 revision；快照和截图仍要求完整 frame 一致，符合现行 [权限 ADR](../../adr/permissions/001-session-authorization.md)。动态内容可能使这些检查频繁失配，但本轮未采集前后 revision 的字段差异，不能宣布精确根因已定位。没有为通过视频测试删除目标校验或放行旧 gesture/frame。
7. 模拟器日志记录 SwiftShader 不支持扩展及 `bad color buffer handle`；这是渲染方向线索，不是已证明的唯一原因。[Android 官方图形说明](https://developer.android.com/studio/run/emulator-acceleration)提供不同 GPU 模式及兼容性边界。后续应把 GPU 对照与固定窗口内动态文本的观察诊断分开，不重复已经通过的安装/卸载，也不据 GPU 切换预报修复成功。
