## 当前证据

### 新手机连接失败：DNS 路径已定位

后续所有者授权实现应用内手动映射，已通过 [订阅网络设置](subscription-dns-overrides.md) 迁移现有地址；旧系统 hosts 挂载已撤销，普通应用 UID 的 HTTPS 对照通过，不再需要 Root。以下解析路径对照保留为原始诊断证据。

OnePlus 6T 系统将 `chatgpt.com` 解析到无法建立 TCP 443 的地址；电脑普通 DNS 查询返回另一组地址且 TLS 正常。仅在单次无凭据 curl 请求使用 `--resolve`、保持原域名与证书校验，新手机订阅 UID 对两个对照地址均完成 TCP/TLS 并返回 HTTP 401。因此这次连接失败可定位到系统 DNS 返回地址，不能归为模型参数或跨 APK 传输。

手机有效网络状态为 `UsePrivateDns: true`、验证服务器 `223.5.5.5`；即使 settings 中没有显式保存私人 DNS 模式，也不能据此宣称私人 DNS 未启用。电脑普通 UDP DNS（路由器与两个配置的 DNS 服务器）返回可连接地址，而对同一服务器的已校验证书 DoT 查询返回异常地址。已证明两条解析路径结果不同；普通 DNS 是否被网关重定向未进一步核实。未修改手机 DNS、代理或应用配置，未硬编码产品 IP。建议先在新手机关闭私人 DNS后人工重试。此发现不关闭旧手机长回复中断的根因调查。

复用脚本：`compare-phone-dns.py`、`verify-phone-dns-route.py`、`compare-dns-transports.py`，均在 `scripts/debug/2026-09-10/`；不含账号凭据，不发起模型生成。

- Runtime 真实账号诊断 4 项通过；其中 productionRequestContract 使用正常网络客户端，不再通过 peekBody 提前缓冲响应。目录、工具回填、low/high 参数的成功不替代主 App 链路验收。
- 主 App 完整探测出现流式阶段 TRANSPORT、180 秒外层超时；另一轮流式通过后在工具阶段 TRANSPORT。视觉和全部推理档位尚未完整通过，未继续对话验收。
- 一次请求在 Runtime journal 中约 5 秒后已 SUCCEEDED，但主 App 仍等待 Binder 返回。成功 journal 仅表示结果持久化，不等于 UI 已收回或能力测试已通过。
- 前台 Runtime 对照中，主 App 的 Android process state 为 FGS，isFrozen=false、virtualFreeze=false；内核 UID 层 cgroup.freeze=1，子进程 cgroup.events 中 frozen=1。进程级 freeze=0 不排除祖先 UID 冻结。切回主 App 后测试恢复并报告失败。
- 这证明冻结影响本轮时序，但尚未确认是 OEM 策略还是第三方冻结器，也不能把此前全部网络中断归为同一个原因。未改冻结、电池或锁屏配置；用户已确认未使用冻结工具，不能以第三方工具豁免作为前置。
