## 修复与审查

- 搜索匹配会规范化 query，但旧应用服务将规范化结果回写编辑框，导致输入中的前后空格丢失。现在保留用户原始输入，仅用规范化值检索；主机回归采用实际裁剪行为的查询替身，设备回归等待真实检索结果后核对空格。
- 旧搜索测试把仅在截断时显示的范围提示当作所有搜索的就绪信号，反复重置界面并超时。改为核对实际 query 和清除按钮，保留标题/正文/归档/空结果/取消/重建断言，并确认完整结果不显示截断提示。
- 旧 Turn 测试将工具前进度当作 TEXT。按已接受的工具响应契约分别验证 TOOL_PROGRESS、原 TOOL_CALLS 中的 assistantText，以及第二次模型失败保留的 TEXT；没有放宽生产存储或回填行为。
- 独立 Release UI 测试先等待屏幕外的应用选择按钮再滚动，英文布局下超时；两处改为先滚动定位，保留范围、重启和手动撤销断言。API33+ 读取前刷新无障碍缓存，避免把已写入的草稿误判为空。实际候选上的完整 Mobile Use 方法随后 1/1。
- 审查集中于工具原调用归属、搜索事务与版本、GC 发布协调、插件共享元数据锁、导入目标/revision 和端点认证重绑定。既有分派、审批、取消及安装事务保持。

## 抖音实际旅程

首轮不是成功：持续约 701 秒，107 次工具调用（96 成功、9 失败、2 次 schema 拒绝），104 次模型调用完成、1 次取消；模型尚未安装抖音。测试人员通过浮窗“接管”结束反复尝试，Room 确认原 Turn 为 `CANCELLED`，未改数据库终态。304 份消息/结果对象及 8 份工具截图已按持久哈希导出。

独立读取[抖音官方入口](https://m.douyin.com/app_download)的当次响应，`appInfo.BaseResp.StatusCode=-1`，应用标题/图标为空，与 Chrome 页面一致；这是已确认的外部页面故障，不能把所有手势失败一并归因于它。首轮还有 `ACTION_NOT_DISPATCHED`、失效 frame、歧义目标、不支持输入与模型额外参数拒绝，原始调用完整保留，不放宽执行/授权约束。

官方页面自身的 `channelConfig.zlink` 给出 [官方跳转入口](https://n.douyin.com/d4PBJ)。主机 Android User-Agent 的有界 GET 实际经官方配置的分发地址返回 APK 类型；HEAD 返回 404 的失败也保留，没有只据 HEAD 判定 GET 不可用。测试人员将这项已核实事实作为新用户消息补充到原会话；因此后续结果属于有提示复测，不是首轮全自主成功。

准备补充消息时，独立 UI 宿主与 Shizuku 的单个 UiAutomation 连接冲突，测试宿主失败。确认无活动 Turn 后仅 force-stop 自有实例的 Helix，重新启动后 UI 驱动通过；复测保留原会话与授权，实际重新发现目标/节点，不复用上一进程 token。

补充入口后的 Turn 约 540 秒完成：模型通过 Chrome 下载、系统来源授权及安装页安装抖音 40.7.0，跳过登录、拒绝通知，观看公开视频后通过系统应用信息页卸载。安装/卸载均由模型公共 UI 操作，独立只读包查询确认实际安装及最终不存在，未用 ADB 替模型完成业务步骤。最终工具的可信来源、前台包和截图均为 Helix Advanced，截图可见本 Turn 的进度文字；Room 的 sessionId 与首轮相同，终态 `COMPLETED`。210 份内容对象及 5 份唯一工具截图通过持久哈希核验。

独立观察到连续 28 份采样覆盖约 95.8 秒，均为抖音前台、实际安装 UID 的活动 AudioFlinger 音轨，视频区域有 28 个不同画面；首/中/尾原图及两张模型截图人工检查可辨，没有此前严重画面损坏。满足本轮至少 20 秒播放检查。约 3 秒采样不是逐帧测时，模拟器禁用宿主音频输出，不能宣称实际听到了声音。最后独立复核包已卸载、Advanced 前台且两渠道均无活动 Turn。

本轮剩余可靠性边界是外部下载页故障时的自主发现与有界恢复：首轮耗时和重复失败不能由有提示成功抹去，手势拒绝也尚不能归为单一生产缺陷。本轮没有放宽目标/帧检查或新增按站点硬编码；后续可基于保留调用对照定位动作失效及恢复策略，但不将普遍完成率记为已验证。
