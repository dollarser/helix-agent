#137的前一Gradle分析已完整通过，取消时正在第二个构建调用的Release lintVital依赖，尚不能据此删除lintVital或断言它与完整Lint完全重复。日志中最长任务输出间隔约256秒，夹在native构建与JNI合并输出之间；输出时间不等于精确单任务执行时间。取消导致Gradle profile及诊断上传步骤跳过，缺CPU/内存/线程采样，所以未进一步宣称GC、swap或死锁根因。verify拒绝cancelled是正确行为，不应放宽。

## 本地修改及验证边界

保留60分钟job上限、全部检查、内存预算和host-only边界。full拆出分析、测试构建、Debug/Release制品步骤，退出即停。门禁监督器保留原始输出和退出码，周期报告最后输出任务及资源快照；临近第57分钟主动失败，尝试有界JVM线程诊断并终止本次进程组，给上传留时间。失败/取消也尝试上传已有profile和诊断，不能保证平台硬终止后仍能上传。

语音缓存键仅排除无构建用途的README，仍验证实际内容；可信main/dev非PR可写Gradle与已验证资源缓存，其他分支/PR只读。新键可能需要一次冷准备，不能许诺首次运行节省14分钟。依据为 [Gradle action缓存文档](https://github.com/gradle/actions/blob/main/docs/setup-gradle.md)及 [GitHub缓存范围说明](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching)。

本机CI相关28项测试通过，覆盖门禁任务集合/退出传播、真实子进程正常与失败、超时、信号取消、过期预算不启动。工作流YAML解析及shell语法检查通过；完整source检查结果见本地 `build/ci-optimization-source.log`。未执行远端Gradle性能复测、不改服务器/制品/标签/设备、不推送。

建议获准后在dev手动执行一次full，核对各阶段、语音键、诊断上传和实际总时长；首次新键建立缓存后，应复用下一次正常full观察暖缓存，避免为数字额外连续刷CI。若仍慢，依据新线程/资源/profile再决定并行度或构建图调整，不先扩大堆、加机器或放宽上限。

## 本地 hooks 分层收口

后续按所有者要求保留 index-only pre-commit，并把 pre-push 扩展为真实远端 OID 范围的 source/纯 JVM 两档；共享构建逻辑、未知文件、新分支和重写历史保守处理。新分支等无法直接确定安全范围时仍需要已验证祖先，不能确认则阻断，不静默跳过。临时仓库覆盖脏工作区、部分暂存、多 ref、标签、删除、未知对象、非快进及缓存后失败；真实 `git push` 验证文档推送成功、JVM 失败阻止远端 ref 更新。启用方式与责任见 [scripts/README](../../../scripts/README.md#本地提交与推送钩子)。

GitHub main/dev 的 PR/push 保留独立 source/Debug 和 `verify`，完整 Release/R8 由显式 full/发版门禁承担。只读 API 查询时 main 未配置 branch protection，仓库 rulesets 为空；工作流中的汇总状态不等同于平台强制合并保护，本轮未修改该配置。已有 hooksPath 保持不变，未修改全局 Git 配置。
