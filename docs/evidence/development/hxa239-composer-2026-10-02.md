# HXA-239：会话输入与权限快捷切换

日期：2026-10-02。所有者要求先提交前置修改，再修复未选模型发送、斜杠指令光标和输入框底部权限切换。前置 HXA-238 已保存为 `9d0ab5c0`；提交前复核源码指纹与原通过候选一致。无推送/发布、设备或真实账号使用。FFmpeg 等并行文件未混入提交。

## 实现与原因

- **未选模型发送**：原 Composer 只依据草稿/发送状态控制按钮，没有选模前置判断。现在实际会话 provider/model 必须均存在，发送禁用但保留可编辑文字、附件和引用；提醒打开原模型选择器，选好不会自动发送。本地 help/clear/纯模式命令仍可使用。服务在创建 Turn、排队或物化发送草稿之前再次检查，返回明确 `NO_MODEL_SELECTED`，已接受请求的幂等回执仍先恢复。不把 provider 的默认模型冒充当前会话已选模型，也不绕过真实连接、权限或附件检查。
- **指令光标**：原 applySuggestion 返回 text/cursor，但调用者丢弃 cursor；String 输入框只更新文本。现使用 TextFieldValue 同步保存 text/selection/composition，采用补全返回的实际插入位置，回焦原编辑器；普通回显保持选区和输入法组字，外部草稿变更把光标收敛到新文本范围。草稿持久层仍是原 ConversationDraftBuffer，没有第二份聊天历史。
- **权限入口**：原入口藏在 Composer 的更多选项中。现位于输入框内底部左侧，右侧仍为模型；直接选择四个现有预设，自定义回原会话设置。经 SessionPermissionEditService 保存、读取实际值后更新显示；仅修改原会话，不改新会话默认、工具禁用、待审批卡或已启动任务。用户真正更改新会话配置时才实体化，打开菜单本身不写配置。保存异常提示结果未确认，不宣称失败一定回滚。

## 回归与集成

新增 8 项独立 JVM 场景：模型/Provider 缺失、输入与本地指令资格、其他发送约束、补全光标、UTF-16 后缀、普通选区/IME 回显、外部替换和清空。consumer/developer 共享测试不重复计数。

新增/扩展设备场景：实际输入框补全后继续打字、未选模型时保留输入并打开模型选择、选好后不自动发送、本地 clear、底部布局和权限失败反馈、原会话持久化与新会话默认隔离。真实 ChatService 测试检查无模型时没有新增用户消息/Turn，且直接调用仍得到精确原因。设备测试仅构建，不作为手机已通过。

第一轮全主机整合未出现单测失败，detekt 报 4 项新 UI 条件复杂度问题；整理前置条件与显示条件，并沿用原复杂 picker 的局部 Compose DSL 标注，没有关闭检查或放宽业务断言。最终重验结果另列。
