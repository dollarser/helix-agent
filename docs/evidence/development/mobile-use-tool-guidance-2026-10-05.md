# Mobile Use 工具呈现与结束诊断

日期：2026-10-05。范围：所有者要求优化安装任务暴露出的默认工具、描述、恢复提示和结束信号诊断。沿用 ADR-AGENT-001 与 ADR-TOOLS-001；不改变权限、业务验收归属或自动恢复准入。

## 依据与实现

上一轮[抖音与酷安安装记录](douyin-coolapk-model-install-2026-10-05.md)证明工具具备完成安装的能力，但需要人工续行，不能当作无人干预完成率。酷安首次安装的历史请求清单有 64 次调用，每次 32 个工具；并非工具上限导致整个 Mobile Use 丢失。

- 默认暴露 `ui.wait`，将 `http.fetch` 留给原有工具搜索；仍保留 URL 打开及视觉工具，保持默认集合和两个发现窗口的总预算。
- 语义工具描述分别解释观察、查找、等待、点击、输入、滚动和导航；不再逐个重复整套后端/视觉说明。保留自动后端选择和显式精确点击的现有契约。
- 共用操作指导从全局 base 移到 `env.mobile-use`，由每次实际工具清单中是否有 `ui.*` 决定是否注入，覆盖首次构建、续行和重建路径。提供通用等待、失效目标、安装核查示例；不授予权限，不按特定应用编排步骤。
- 等待超时返回恢复提示：条件未观察到不代表先前动作失败；先观察，不能盲目重放。更具体的截断/授权提示仍优先。
- 持久请求结果诊断新增白名单化 finishReason、streamCompleted、toolCalls、hasText，不保存回答正文或供应商任意字符串。保留取消和输出截断优先级，不用未来时措辞触发自动续问。

## 协议检查与边界

Chat Completions 解码已有 stop/tool_calls/length 区分、未结束流拒绝、开放工具调用拒绝和 reasoning/content 分离。Responses 解码将完成响应映射为工具调用或结束；当前中立事件不包含完整的 commentary/final 消息阶段。此次没有足够原始供应商消息证据将 Qwen 提前结束归因于丢失阶段，因此不把诊断补充宣称为提前结束根因修复，也不新增推测性的第二套循环。

后续真实模型比较应固定模型、初始安装状态、权限和任务，比较旧基线与新候选的一次指令完成率、人工续行次数、参数错误、无效观察、最终核查、耗时与调用量。发生安装等副作用后先核查，不用重复安装凑样本。其他模型作为独立对照，不与提示优化混为同一个变量。
