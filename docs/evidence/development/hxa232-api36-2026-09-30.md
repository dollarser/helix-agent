## 首轮失败与修复

Consumer r1：48 项，43 通过、5 失败。原始证据保留在 `build/hxa232-api36-r1-consumer/`。

- 原生权限拒绝和超大返回的 Java 异常越过 JNI string channel，变成 execution-thread failure，脚本无法按普通 API 异常处理。改为有界错误 envelope，由 JavaScript 抛出 Error；致命 Error 仍交给执行器结算。原生脚本的既有副作用仍不能视为回滚，Harness 的 UNKNOWN 门控不因此解除。
- Standard 的 `HttpURLConnection` 明文请求正确受到渠道网络策略拒绝。夹具改为断言当前渠道策略；增加两渠道真实 loopback Socket 通信，验证已授权原生网络能力，不为通过测试放宽 Standard 明文配置。
- 重新生成失败不是单纯呈现延迟：r2 及单项诊断显示 fixture 在正常对话继续返回能力探测用 echo，导致六次拒绝和无进展终态，长恢复卡片将按钮移出 LazyColumn 可见范围。改为探测完成后脚本化普通文本回复，并滚动到实际按钮点击；增加两次 Turn 均 COMPLETED 的断言，保留旧回复 superseded、单一原用户消息断言。
- 审批夹具假定临时注册的可选工具会默认曝光。改为通过现有发现窗口加载两个测试工具，仍验证 schema intent、整批顺序、拒绝后无写副作用和 Harness 结果权威。

补充执行中“关闭再开启”权限的测试，检查旧执行不能续用新授权，并保留已写文件。补充自由回答 UI 与独立输入缓存、会话重开后的回答去重测试。

Consumer r2：51 项，50 通过、1 失败（重新生成）。单项 diagnose/diagnose3 保留定位证据；diagnose2 因旧端口尚不可绑定，在启动前安全拒绝，没有执行测试。诊断日志中的 UI/会话内容均为本地合成夹具。

Consumer `final` 为扩充范围后的中间批次（目录名不是通过声明）：57 项、53 通过、4 失败。重新生成已通过。其余为：

- 原生超时夹具的 1.5 秒包含冷启动；主机负载下在执行前已过期，正确返回 REQUEST_REJECTED。改为 10 秒执行额度、30 秒阻塞调用，并用文件 marker 证明实际开始，超时后无迟到写入；不接受 REQUEST_REJECTED 作为超时通过。
- Stop 后 Room 终态先于 live execution lease 释放。夹具改用正常 composer 模式变更入口，有界等待准入，不再直接调用要求空闲的同步接口；继续验证队列停泊、无自动复活。
- 附件编辑按钮在 LazyColumn 视口外；先滚动到对应节点，再实际点击。
- 合成的旧式已接收附件 Turn 只存用户文本，缺少当前格式的附件上下文，无法通过历史回执匹配。使用 AttachmentContext 生成真实格式并绑定同一 fingerprint，显式断言存在回执，再测试 UI 恢复。未放宽生产匹配或清理条件。
