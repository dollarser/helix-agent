# v0.0.5 开发预览发布记录

日期：2026-10-06。所有者授权合并有效工作、清理工作树，在 main 上执行模拟器和真实模型验证，待本地验证及 GitHub CI 通过后重发 v0.0.5。继续使用双渠道 debug 签名、versionName=0.0.5、versionCode=1，不作商店正式发行声明。

## 来源与范围

整合基线为 `304f6361`，包含 Mobile Use/宿主权限分工、模型与订阅配置、会话与扩展交互、项目与文件流程和原生客户端共享 hosts 解析。CI 将 debug/release 静态分析分开并行，但最终门禁仍要求两者通过；GitHub CI 不运行模拟器或设备测试。

本轮保留 main、public-benchmark-eval、BioHelix 三个工作树；未将评测与 BioHelix 的独立工作强行并入 main。已吸收的 CI 工作树归档，相关冗余分支删除。此前的 v0.0.5 制品不是此次验证对象，最终来源以发布页 `BUILDINFO.json` 的精确提交和 `SHA256SUMS` 为准。

## 本轮修复

- 早期开发库 version 9 覆盖到当前 v1 时缺少迁移导致启动失败。按既定开发库可重建契约启用 Room destructive fallback；API29/API36 各 3 项专项证明旧版本及同版本 identity 不兼容库重建、兼容重开与数据库外文件保留。其他打开错误仍原样失败。

- 前台数据传输服务在密集启停时重复发布通知，API36 系统日志出现通知 enqueue 限流。现在每个服务实例只首次提升前台通知，普通空闲停止合并 250ms 内的抖动；显式停止和系统超时仍立即处理。新增重复启动测试，并保留启动/停止竞争、旧停止不得取消新任务等检查。
- 设备回归使用已落地的插件/导航/模型选择界面、合法 Turn 状态和当前任务范围；移除测试中额外的嵌套滚动容器，改用可确定关闭的 ActivityScenario 生命周期。文件导入导出测试改用 Compose v2 测试规则，避免旧规则的跨线程 Snapshot 观察异常。
- Root 断连检查针对实际 Binder、服务进程及其子进程，不再要求销毁宿主供其他消费者复用的授权 shell。高层工具仍检查断连后拒绝执行、原 scope 和失效引用。
- PRoot 测试通过未关闭的输入管道建立确定的待启动状态，不再假设串行执行容量；CLI 取消测试等待物理执行器完成后确认最终 CANCELLED。没有将取消请求等同于执行已结束。
- 明确区分缺少授权测试 profile 与失败：无 profile 的真实模型/微信旅程跳过，已提供但格式错误的 profile 失败。完整扫描不会隐式访问微信或调用真实模型。
- Mobile Use 强停测试等待 Android 发现刚安装的无障碍组件，并使用当前通知所属包；输入恢复驱动改为当前队列消息呈现，仍核对持久状态及精确模型请求次数。诊断保存原始 logcat 字节，防止非 UTF-8 内容遮蔽首个错误。

## 本地验证

输入恢复的合成标记改用固定数字，避免中文 Gboard 将连字符转成全角、为英文单词自动添加空格造成夹具不匹配；仍比较完整持久化文本、真实进程身份和模型请求次数。真实模型追加复测曾在来源授权后进入桌面并耗尽预算：测试来源 Activity 立即关闭，缺少普通下载页的重新安装入口。测试 APK 现保留明确安装按钮，返回后是否继续仍由模型决定，不自动重放安装。独占输入验收实例在 seed 前显式清空目标 App 数据，避免 AVD 残留的 1-token 开发配置污染新会话；日常实例不执行清空。并行 API36 的系统 ANR 属于环境失败，保留原记录并降低并行后重跑。

原始证据保存在忽略目录 `build/main-release-2026-10-06/`。初次失败、修复后的定向重测及环境失败分别保留；不是删掉失败后重算一次全绿。

## 边界与升级

- versionCode=1 是所有者明确要求。已安装内部编号 4/5 的设备仍受 Android 降级限制，不能常规覆盖安装；正式升级策略需使用更高编号。
- prerelease、debug 签名、Android 10+；未验收 OEM/真实手机、真实账号、所有模型/连接器、24h 运行及所有第三方 App。`FirstSuccessJourneyDeviceTest` 需要独立本地模型权重 profile，`MainAppCombinedSoakDeviceTest` 的正式 2h/长期矩阵未运行，13 类多阶段清单不能全部记为通过。真实模型本轮测的是合成测试 APK，不能写成抖音或酷安安装成功。
- 普通无障碍不能保证操控系统安装器的受保护目标；截图可见不等于 Android 接受无障碍注入。当前 Shizuku 旅程通过不能替代普通无障碍、所有 Root/OEM 路径的验收。
- 升级前导出重要内容并备份文件。开发期数据库不兼容时会清空会话、配置等数据库记录，保留数据库外文件；导出诊断不是完整可恢复备份。签名冲突时不要直接卸载或清除数据。
