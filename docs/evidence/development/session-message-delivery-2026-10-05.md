# 会话级消息发送方式

Date: 2026-10-05
Scope: 所有者要求将 Queue/立即发送从单条草稿选择改为本会话持久默认设置。

## 行为与边界

- 更多菜单始终显示“本会话发送方式”，无须有活跃任务或排队消息。新会话默认排队。
- 设置存入 `session_run_controls.immediateMessages`，应用的会话 RunControl 投影读取该事实；更新发送方式可以在任务运行中进行，不修改任务执行快照。
- 选择立即发送时，新消息在点击发送时冻结当前可接收 Turn 的身份；空闲时走正常 Queue 准入。正在取消或需要核查的任务不会被当作可接收目标。
- 设置只影响未来的新输入，队列项不被批量迁移；单项立即发送、编辑、删除仍保留。已提交 Steer 不随下一轮任务静默改绑。
- 输入配置指纹排除该未来消息偏好，防止切换设置导致已接受的队列配置失效；模型、模式、预算等实际执行配置仍参与原校验。
- 会话切换和进程重建从持久记录恢复；其他会话保持独立。分支按既有会话配置复制规则获得独立快照。

## 验证

主机覆盖会话偏好持久化与隔离、不同发送的目标冻结、空闲降为普通发送，以及切换偏好不改变已接受输入配置指纹。运行 app Developer、core storage、core agent 单元测试，双渠道构建、AndroidTest 编译、格式与 Detekt。日志在忽略目录 `build/session-delivery-final.log`、`build/session-delivery-verified.log`。

设备和真实模型 not requested，未安装或启动模拟器。Room 开发基线新增列，旧安装覆盖升级可能触发仓库既有的数据库重建策略；本轮未修改设备数据，不声称旧数据升级保留已验证。
