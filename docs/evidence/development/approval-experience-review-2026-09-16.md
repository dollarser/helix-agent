# 审批体验复核与后续边界

日期：2026-09-16。基线：`1cd1c137` 加现有并行工作树；本轮先修复已知全套设备失败，本文不代表下列新增能力已经实现或验收。HXA-200/201专项完成记录保留。任何下一HXA先清理必过本地门禁的已知失败；真实账号/外网profile仍为显式选择，缺参数跳过不能伪称实测。

## 判断

采纳“降低重复确认、后台可发现、结果可理解、恢复不重放”的产品方向，不采纳“骨架已经超越竞品”这类没有同任务设备证据的排名。工具级偏好和用户/项目规则并非完全同构；Android执行域、动态风险与文件scope有自己的语义。

| 建议 | 复核与决定 | 交付边界 |
| --- | --- | --- |
| L2卡频 | 确实存在高频写入摩擦。约束来自有效ADR-PERMISSIONS-003/0052，ADR-PERMISSIONS-001已废止；不是一个旧注释锁死了产品 | 保持当前授权语义。先统计真实任务中按风险/工具/原因的卡频，复核普通文件写入的实际风险分类，并产品化ADR已许可的精确批次。需要可复用L2授权时另提ADR，不能把工具级ALLOW直接放大 |
| 参数规则 | 当前偏好键不表达文件路径或命令参数模式；这会限制可解释的精细授权 | 候选只做类型化约束：规范scope+路径、操作种类、契约版本、到期/撤销。shell不能靠字符串前缀证明实际副作用，复合命令/重定向/动态展开不自动获权。不预存没有执行语义的万能JSON字段 |

| 拒绝理由 | 有价值但低于通知与恢复 | 后续可选短理由，绑定该次拒绝，模型视为用户反馈；不自动写偏好，不保存敏感输入到通用日志 |

| Hook/分类器自动放行 | 当前无明确需求 | 不为了竞品功能表新增插件执行或模型授予权限 |

当前生产`StorageApprovalBroker`仍为每次申请创建独立卡片等待。本轮未发现可据以宣布“完整批量审阅UI已交付”的生产入口；底层精确proof测试不能充当免卡产品证据。因此降低L2确认频次是有效待办，既不能称已解决，也不必立即扩大未来任意调用授权。

## 不改变权限的实现顺序与验收

1. 本轮清理已知基线失败并记录新设备证据；修正过时卡片注释。不得将待做体验项写成200/201缺陷或重开已验收迁移。
2. HXA-202：任务中的待审批入口、通知打开准确卡片、Plan执行授权说明。API29/36双flavor验证后台/前台、通知拒绝、重复点击和终态失效；UI不能直接调用DAO或生成proof。
3. HXA-203/201后续：文件审批diff，验证内容变更、Unicode、大文件、缺失文件、取消和实际执行版本一致。
4. HXA-204：真实进程死亡后的中断审批与副作用对账，不能只做Activity recreation；保留旧审计，并证明旧通知/旧卡不能授权新调用。
5. 用相同的“读资料→修改文件→打开结果”和“取消→重启→继续”任务比较操作数、卡频、成功率及重复副作用，再决定是否值得引入可复用L2授权。

扩大L2授权的ADR至少明确：用户可理解的路径/操作范围、动态风险上限、外发与任意shell排除项、到期与撤销、契约变化失效、排队/执行中撤销、审计、迁移默认及真实设备失败测试。未接受前小模型不得实现宽泛L2免卡。
