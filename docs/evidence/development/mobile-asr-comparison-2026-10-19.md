# 移动端 ASR 候选对照（2026-10-19）

本记录对应 Owner 追加的“候选都测准确率、速率，再真机测试”，承接 [ADR-PLATFORM-004](../../adr/platform/004-offline-voice-input.md) 和[离线语音输入实施证据](offline-voice-input-2026-10-19.md)。本轮只增加可选评测代码与证据，不替换产品默认模型、不增加云端或 TTS、不升级版本、不发布。ConsumerDebug 独立验证主应用保持 0.0.6 / code 1，原渠道应用与用户数据保留。

## 固定范围与方法

候选为当前中英小 Zipformer、中文 Zipformer 14M、中文小 CTC、2025 中文大 Zipformer、Streaming Paraformer 中英 INT8、SenseVoice INT8、Whisper Tiny ONNX INT8、Moonshine Mandarin Tiny Streaming、Vosk Small 中文，以及具体落实到 WSYue U2++ 中英粤 INT8 的 WeNet 路线。GB 级生成式模型不在 Owner 认可的手机默认体积范围内，本轮不运行它们。SenseVoice 选用 2024-07-17 通用 Small INT8；官方说明 2025-09-09 是 21.8k 小时粤语微调版，本轮没有混作同一个检查点的测量，也未做该版本或全模型目录遍历。WeNet 以 sherpa 的离线 CTC API 比较，不把该适配器称为流式输入。

共用语料为 31 段、363.4 秒：

- [Google FLEURS](https://huggingface.co/datasets/google/fleurs) `cmn_hans_cn/test` 前 20 行，保留官方参考转写；CC-BY-4.0。
- 前五段的确定性白噪声派生，目标 SNR 10 dB；不是现实噪声录音。
- whisper.cpp 的公开 JFK 英文演讲片段一段。
- 前三段中文与上述英文片段拼接，中间 0.5 秒静音；是人工构造的语言切换，不是自然中英混说。
- 全零、低幅白噪声各五秒的静音探针。

完整 FLEURS Parquet 通过官方 LFS SHA-256；Arrow 解码的前 20 段 WAV 与最初准备的样本逐字节一致，每段帧数与官方元数据一致。冻结 PCM、模型与实际设备文件分别校验哈希。权重归一为所需运行文件的未压缩 MiB，区别于下载包、APK 或运行内存。

评分使用语料微平均：中文 CER、英文 WER、构造混合样本 MER（中文按字、英文按词/数字），越低越好；静音单列非空输出数。Unicode NFKC、大小写及标点/空白归一，`<unk>` 算一个未知单位；同时保留严格字形与 OpenCC 简繁统一后的错误率。不把“十二”和“12”等价，因此数字格式也会影响 CER。英文只有一段、混合样本只有三段，不代表这些能力的总体准确率；20 段中文也不足以确立小差距的统计优势。最长夹具 25.36 秒，本矩阵不覆盖模型层 120 秒极限、连续热稳、GPU/NPU、其他 OEM 或自然技术词口述。

Sherpa CPU 双线程、greedy；Moonshine/Vosk 使用各自 SDK 支持的默认线程配置。Whisper 自动检测语言。本轮测量的是 sherpa 导出的 Whisper ONNX 权重，不是 whisper.cpp 性能；Moonshine 用其原版 SDK 运行库的独立 test APK，不能据此归纳所有模型的框架排名。

每段新建识别器，模型加载与解码分开计时；原生库及系统文件缓存不强制清空，不能叫设备冷存储启动。100 ms PCM 块尽快喂入得到吞吐 RTF；Android 处理耗时仅累计 accept/finalize 调用，不包括文件读取、内存查询及等待。RTF 为处理耗时/音频时长，低于 1 表示快于音频播放速度。主机计时包含 Python 包装开销，只作同平台对照。

首字测试另取前三段中文，按真实音频时间喂入；从音频起点计时，包含文件前导静音，不含模型加载/权限弹窗。音频结束到最终文字按实时轮次的处理总时长减原音频时长计算，包含最后块解码；原始 `finishMs` 只代表 finalize 调用，不叫 UI 停止按钮到显示的实测。最终计时版将 PSS 查询放在音频时钟之前，避免测量操作打乱初始节奏。离线引擎没有增量首字输出。PSS 只在解码前后采样整个测试进程，不是连续峰值或模型独占 RAM。

JUnit 通过表示该轮执行和记录完整，质量由错误率与静音输出衡量，不设一条统一 CER 达标线。

## 环境与证据边界

- 日常 Helix_API_36 ARM64 模拟器：API 36，未重新启动 AVD、未改变中文输入法，未开启宿主麦克风路由。
- OnePlus 6T：`ONEPLUS A6013`，SDM845，API 34，ARM64，系统报告总内存约 7.46 GiB。没有关闭既有未知应用或会话，没有清数据、重启手机或清系统缓存。
- 主应用为此前冻结并通过 ASR 功能检查的独立验证 APK；两台设备实装文件哈希一致。该矩阵不等价于新模型已经集成进正式语音 UI。
- 测试 APK 直接将公开/合成 PCM 输入真实原生识别器；没有调用 AudioRecord、授予手机录音权限、录制现实环境、上传音频或发送消息。真实麦克风说话、自然混说、口音及现实噪声仍需另外验收。

维护入口为[评测说明](../../../scripts/experiments/asr-benchmark/README.md)与同目录固定输入锁。生成的权重、PCM、完整 JSONL 假设、APK、设备哈希回执、计分结果及日志保留在忽略的 `build/asr/benchmark/`，不入 Git。十个候选的主机和两台设备完整语料结果均已完成；两台设备各十模型、前三段中文的实时节奏轮次也完成。共 930 条完整语料结果及 60 条节奏结果，均核对模型、参考文本、样本身份与音频长度。

## 测量实现核查

准备阶段真实出现过的失败均未算作通过：AGP 内建 Kotlin 需要显式 Kotlin 测试源目录；Moonshine 使用 sherpa ORT 时 JNI 符号加载失败，改用独立的官方 SDK ORT；其不支持的线程选项已移除；Vosk 允许部分结果为空 JSON，对齐其 SDK 语义后重跑；Whisper 改为自动语种后重跑。HTTP/2 中断通过续传、文件长度/来源哈希及完整 Arrow 对照解决。

静态检查最初发现新增脚本 Kotlin 的格式、包路径与复杂度问题，已整理为按引擎分开的适配器和单段测量方法，通过检查；没有禁用或削弱规则。性能原始 APK 与相应 Kotlin 快照保留，最终计时/维护版本另行冻结，模型与线程配置保持相同。Moonshine 原生返回空指针按失败处理，不能用上一份文本冒充成功；该边界修正后，已在两台设备重新执行其完整 31 段语料，并核验结果回执所用 APK 确为修正版。

## 结论与当前产品选择

- 几十 MiB 的优先候选是 Moonshine 中文 Tiny Streaming：启动和包体有明显收益，中文小样本质量接近基线；其中文 RTF 和进程 PSS 比基线高，独立英文片段退化明显。进入中文使用场景的自然技术词、真实口述与仅 ASR SDK 集成验证更合理，不能直接替换中英默认。
- 小 CTC 在本组中文/人工噪声中有竞争力，但英文/混合能力不足，且新建加载没有随体积同比缩短；14M 的质量代价更明显。
- 大中文 Zipformer 的质量收益伴随较长初始化；Paraformer 的体积和处理成本未体现足够默认替换收益。SenseVoice 可继续作为结束后质量候选，须解决静音/VAD、体积和无增量输出。
- 本轮这份 Whisper Tiny ONNX 配方的中文、静音表现不优先；不据此外推所有 Whisper 权重或 whisper.cpp。Vosk/WeNet 也没有显示当前普通话草稿输入的整体替换优势，不评价它们未测的语种/受限词表场景。

保留已交付的双语 Zipformer 默认。实际用户口述、自然技术词混说和现实噪声仍待 Owner 手动触发验收；本轮没有擅自打开现实环境麦克风。模型名、年份、单个 WER 或少量百分比差异不被当作全场景最优结论。

## 验证与产物

具体入口与本地证据：`scripts/experiments/asr-benchmark/`、`build/asr/benchmark/{host-summary.json,result-tables.md,paced-tables.md}`，各设备 `throughput/` 与 `paced-final/` 中的 JSONL、outcomes、summary、输入文件回执，以及冻结 APK/Kotlin 快照、`device-environment.json` 和最终 provenance。没有把失败下载或预检失败当作模型测试通过，也没有把旧 APK 用作失败构建的证据。矩阵只证明上述范围，不等于发布版、所有 OEM、真实账号或完整产品验收。
