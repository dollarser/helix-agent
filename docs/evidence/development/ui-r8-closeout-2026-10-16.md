## 实际阻塞与修复

新安装 Runtime 并验证成功后，非调试终端两次启动均在读取新子进程 `/proc/<pid>/stat` 时收到 ENOENT，进入 UNKNOWN / RUNTIME_LOST，未形成可操作终端。Runtime 服务进程仍存活；这不是构建成功可以替代的运行验收。

同一模拟器上的独立 native 诊断移除 readproc 附加组、降为测试应用 UID，并控制 fork/exec 时序：子进程继承 dumpable=0 时，exec 前不可见、errno=2，exec 后可见；dumpable=1 时前后都可见。设备 procfs 为 hidepid=invisible。该结果解释 Debug 测试未暴露的启动窗口；不是单凭 R8 标签认定混淆规则有错。机制参考 [Linux procfs 文档](https://www.kernel.org/doc/html/latest/filesystems/proc.html) 与 [PR_SET_DUMPABLE 手册](https://man7.org/linux/man-pages/man2/PR_SET_DUMPABLE.2const.html)，未复制外部实现。

修复仅在原已 fork、未 reap 的子进程上有界等待身份可见，最长 5 秒，每次检查退出；不重新执行命令、不改变 dumpability/设备安全配置、不伪造 PID 身份或停止证明。持续不可见、提前退出、其他 I/O 失败、错误身份和中断继续失败并保留原有 UNKNOWN/清理语义。

新增 6 项 JVM 回归通过，覆盖暂时不可见后恢复、超时、等待前/等待中退出、错误身份/其他 I/O 以及中断。修复后完整 `check-all.sh --all` exit 0：Runtime 应用 JVM 19/19，App Consumer 1270、Developer 1391 通过，两渠道各 4 项既有条件跳过；全仓测试、静态检查、构建、依赖锁和制品边界通过。修复后最终 R8 复验尚待完成，首批候选的终端验收仍为 failed，不能作为最终发布通过包。
