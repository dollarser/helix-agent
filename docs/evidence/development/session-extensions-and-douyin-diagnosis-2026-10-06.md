# 会话扩展入口与抖音安装中断诊断

日期：2026-10-06。所有者要求中文命名调整、会话开启 Mobile Use 时默认用于新会话，并分析当前模拟器安装失败。本轮只读取 API36 / emulator-5554 / Developer 的记录和系统状态，没有重新调用模型、启动安装或修改设备配置。

## 界面与默认值

- 中文 Expert 统一为“专家”，原“本次可用能力”为“扩展”，覆盖插件与独立技能。
- 会话 UI 手动开启 Mobile Use 时，在同一存储事务中写入当前会话选择和新会话默认值；配置校验失败不留部分选择。
- 其他已有会话不变。关闭当前会话只撤销当前选择；可在全局插件管理单独关闭新会话默认值。内部注册、修复和测试选择不隐式修改默认值，也不申请或授予系统权限。

## 当前失败的事实

读取的最新安装请求为“帮我重新安装抖音”，处于原 `eval-trial-3/keyboard` 会话中，但这是用户后续任务，不属于前面的合成评测 15/15。模型为 Qwen3.8-27B，10 次模型调用、10 次工具调用，约 38.5 秒；持久 turn 为 COMPLETED、无 errorCode。系统包查询确认抖音当前未安装。

1. `ui.launch(com.coolapk.market)` 被 `CAPABILITY_NOT_GRANTED: ACCESSIBILITY_AUTOMATION` 拒绝。设备无障碍服务设置为 null；当前实现的 launch 仍从无障碍 service lease 执行，所以不能仅将权限声明改为 MOBILE_USE。
2. 模型改用 `android.open_uri` 打开酷安的抖音页面，进入首次隐私条款流程。屏幕观察返回 backend=shizuku；这条链路不是普通无障碍，也不是 Root。
3. `ui.find("同意")` 未找到；模型随后使用旧观察 token 滚动，返回 TOKEN_UNKNOWN。重新 snapshot 后看到了“同意协议并继续”，点击成功。
4. 后续 wait 返回 redacted 的 Protected field。记录不足以认定该区域的具体内容，也不能推断截图一定可用。
5. 最后模型只输出“屏幕显示受保护区域，我截图查看实际内容”，没有发出截图调用，随后 turn 正常结束。没有到达 PackageInstaller，也没有下载或安装成功证据。COMPLETED 在这里表示模型轮次结束，不能作为任务目标完成的独立证明。

## 后续修复方向与边界

启动应用应在现有执行边界内获得独立于无障碍的实现，再调整能力声明；不能用“Shizuku 已就绪”掩盖未接线的动作。失效 token 应重新观察，受保护页面应如实反馈并在需要时请求用户处理，不绕过保护。模型最终只描述下一步却不调用工具的问题需经新的真实模型复测确认；本轮未加关键字强制续跑。
