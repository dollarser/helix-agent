# 项目功能与工作组织

项目用于持续推进一件事：例如维护代码库、整理旅行资料、撰写报告。它把相关会话、共享指令、记忆和文件入口放在一起。会话仍可独立使用，文件管理器首页也不随项目或会话切换。本文描述本机项目设计；实现与验收以 [HXA-246](../development/tasks/HXA-246.md) 为准。

## 竞品参考与取舍

| 参考产品 | 官方资料中的相关能力 | Helix 的取舍 |
| --- | --- | --- |
| [ChatGPT Projects](https://learn.chatgpt.com/docs/projects?surface=app) | 项目组织会话、文件和共享指令 | 项目拥有明确身份和共享上下文；会话保留独立历史，避免自动灌入全部项目聊天 |
| [Claude Cowork Projects](https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-claude-cowork) | 持续工作组织、项目指令与目录关联 | 支持新建独立目录或选择已有目录；移动会话归属时不偷偷移动文件 |
| [Manus Projects](https://manus.im/blog/manus-projects-self-updating) | 可持续复用的项目上下文与资料 | 共享记忆可检查、可编辑；自动维护由用户显式开启 |

桌面文件夹不能直接等同于 Android 项目。手机文件来源还包括系统文档目录，不一定提供本地路径、Git 或终端能力。Helix 复用真实文件来源及其能力检查，不复制一份目录来伪装支持。

## 对象关系

| 对象 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 项目 | 长期工作名称、说明、共享指令、成员会话、主目录与项目记忆 | 不授予工具权限，不是执行沙箱 |
| 会话 | 模型选择、对话历史、权限、执行过程及自己的当前工作目录 | 不占有项目内所有文件 |
| 任务 | 某个会话的执行进度、等待审批、失败与恢复 | 不另建一份项目任务副本 |
| 成果 | 已完成结果及实际生成文件的引用，可返回来源会话/任务 | 不把失败任务当交付物，不复制文件 |
| 文件管理器 | 浏览、查找和管理真实文件，包含用户文件与工作目录入口 | 不依赖当前会话，也不等于清理中心 |
| 应用存储 | 应用占用、内部记录和允许清理的数据 | 不代替日常文件管理 |

同名项目是两个项目；使用同一目录也不自动合并项目。一个会话最多属于一个项目，可以无项目。项目主目录为新会话提供默认工作位置；已有会话允许保留自己的目录。

## 页面与操作

侧栏顶层顺序为“会话、项目、模型、扩展、终端、工作、设置”；“项目”是会话下方的独立入口，“文件管理器”保持独立功能入口。模型与扩展管理资源，设置管理应用行为，项目页不复制一套 Provider、插件和权限配置。渠道不支持的终端入口不显示。

项目列表提供新建、名称/说明搜索、归档列表与恢复。点击项目进入详情，包含四个视图：

1. 会话：创建新会话、加入已有会话、打开或移出成员。归档会话仍能查看。
2. 文件：直接进入项目主目录，复用文件管理器的预览及常用操作；仍能主动切换文件来源。
3. 任务：显示成员会话的执行、Goal 和关联运行任务；没有会话归属的全局计划不推测属于项目。
4. 成果：显示成员会话的完成结果及生成文件；按真实会话读取，不受全局首页最近记录窗口截断。

项目设置可编辑名称、说明、共享指令和主目录。名称最多 120 字符，说明 2000，共享指令 16000。指令适合写目标、术语与输出偏好，不能替代授权。并发编辑冲突提示重新打开，不覆盖别人刚保存的内容。

创建时默认提供一个独立的本地目录，也可以选择已有目录。主目录不可用时保存或新建会话会报告失败，用户可重选；不会以一个新空目录冒充原项目目录。既有会话打开时的目录恢复行为仍遵循[工作目录规则](workspace.md)。

## 关键用户流程

新工作：创建项目 → 填写目标/指令 → 选择目录或保留默认 → 新建会话 → 选择模型开始工作。未选模型时保留现有模型选择提示，不猜测一个默认模型。新会话采用当前新会话权限默认值。

整理旧工作：进入项目加入已有会话，或从会话设置修改归属。界面提醒“只变更上下文归属，不移动文件”。若需要统一文件位置，再由用户通过文件管理器整理。活动执行、待发送输入、未完成 Goal 或未解决的工具调用会阻止转移和删除，先完成或处理这些工作。

结束项目：归档后从主列表收起，仍保留会话、记忆和文件；归档本身不停止正在运行的工作。恢复后可继续创建会话。删除需要确认，只删除项目记录与成员关系，保留会话和真实文件。残留项目记忆不自动归入其他项目；同名重建使用新身份。

从会话创建分支：保留已有目录复用语义，来源项目未归档时继承项目成员关系；权限仍采用新会话默认值，不继承来源会话的特殊授权。来源项目已归档时新分支为独立会话。

## 从文件开始工作

独立文件管理器首页提供收藏、最近打开、常用文件夹和存储位置。“Helix 文件”保存在应用内；“工作目录”用于按项目或会话找到真实位置。切换会话不会改变文件管理器首页。最近打开是本应用文件管理器的访问记录，不代表全盘文件索引。

| 操作 | 实际行为 |
| --- | --- |
| 收藏文件或目录 | 保存原位置引用，不复制文件、不授予 Agent 权限 |
| 添加到当前会话 | 将所选文件交给原附件流程，保持当前会话，等待用户填写要求并发送 |
| 在新会话中处理 | 打开新草稿并准备附件；沿用当前模型，没有模型也能先准备 |
| 在此目录开始任务 | 验证受支持的 Workspace/SAF 目录后创建草稿，使用该目录；不自动读取其全部内容 |
| 成果中的“在文件管理器中打开” | 按成果记录的原位置定位，不因会话后来换目录而重定向 |
| 分享 / 分享预览文本 | 分别分享完整文件和当前可用的文本预览；另存为沿用后端实际支持的导出流程 |
| 移除最近或收藏记录 | 仅删除导航记录，原文件不受影响 |

附件是副本交接，不表示已允许 Agent 修改原文件。最近和收藏条目失效时明确提示，可移除记录；不会猜测同名文件的位置。目录任务不因路径相同而自动加入某个项目；需要项目指令和共享记忆时，从项目的“新会话”入口创建。

当前成果仍是交付文件视图，不能当成完整修改清单。“恢复本次修改”须在修改前快照、冲突检查和实际恢复能力完成后提供。实现范围与主机/设备边界见 [HXA-247](../development/tasks/HXA-247.md)。

## 共享记忆与模型可见内容

项目说明和指令在后续请求中作为用户配置加入，既有请求快照保留原版本和内容来源。不会把所有成员会话历史自动发给模型。显式启用记忆且会话读取权限允许时，项目摘要和全局摘要可能发送给当前 Provider。

“使用记忆”“允许 Agent 维护全局记忆”“允许 Agent 维护项目记忆”分别控制，默认关闭。项目记忆按稳定项目 ID 存储，重命名、共享目录不会造成串用。记忆工具还校验真实运行的 session/turn/tool call；历史或错配调用不能仅凭当前会话归属重新定位目标。详见[长期记忆](memory.md)。

## 当前边界与后续演进

本次实现 Standard/Advanced 共用的本机项目生命周期。主目录通过资源 ID 和相对路径引用，项目内容使用修订号，成员关系与审计在事务内写入。遵照所有者要求，不保留旧接口兼容层，不迁移旧开发数据库；数据库重建不删除数据库外真实文件。

正式稳定版本之后应围绕这些明确身份做版本化迁移。云同步、多人协作、多个主目录、项目级模型覆盖、Git worktree 和文件版本回退需各自明确冲突、凭据、授权与恢复规则后再加入。当前 Git 检查不能宣称提供文件自动快照或一键回退。

设备交互、进程重开及不同文件提供者的实际表现需要单独设备验收。主机通过、APK 构建和设备测试编译均不能代替实际设备通过。
