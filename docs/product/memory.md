# 长期记忆

入口：会话 `+ → Reference → Memory`。无需模型连接即可手动管理 Markdown。

“使用记忆”和“允许 Agent 维护全局记忆”默认关闭。开启使用记忆后，允许读取的摘要可能进入当前模型请求；这意味着相关内容会发送给选定的 Provider。目录外读取仍遵守会话权限：默认需要审批的会话通过 `memory.read` 等工具申请读取，不在后台绕过审批注入摘要。自动维护开关也不替代写入审批，Chat/Plan 不允许模型写长期记忆。

全局记忆适合稳定用户偏好、反馈和一般参考信息。项目经验不要混入全局。当前项目入口暂不可用，因为生产尚未提供显式登记的稳定 Project identity；不会凭目录名、路径或 Git remote 自动归并项目。

可以创建、搜索、编辑和删除 Markdown。推荐使用 `memory_summary.md` 保存短摘要，`MEMORY.md` 保存索引，再把具体知识分到 `user.md`、`feedback.md` 或其他主题文件。摘要有界注入，其他文件由模型按需搜索和读取。记忆不会自动生成，也不把聊天历史、执行状态或压缩摘要转存为长期知识。

工具写入的 frontmatter 包含 type、source、trust、updated_at。source 是来源声明，不是事实证明。所有记忆都可能过时，不可据此扩大权限；当前用户指令与 Harness 执行结果优先。

导入通过系统文件选择器读取单个 Markdown，先在编辑区预览，点击保存后才写入。导出创建用户指定的单个 Markdown 文档；不自动上传或提交 Git。保存遇到并发修改会提示冲突并保留当前编辑，请重新读取最新内容后合并。删除需要确认。

文件名使用字母、数字、下划线、连字符及 `.md` 后缀；单文件最多 32 KiB，每层最多 128 文件、总计 1 MiB。识别到凭据模式时拒绝保存/导入/读取/导出，请勿存放密钥、密码或令牌。模式扫描不能识别所有敏感信息。

Markdown 是唯一正文，索引每次从文件重建。关闭记忆不删除文件，也不移除此前已进入会话历史的内容；需要清除时在管理界面逐个删除。记忆不会随删除某个会话自动消失。

设计见 [ADR-AGENT-013](../adr/agent/013-markdown-memory.md)，实施与验证边界以[当前状态](../development/status.md)为准。
