## 1. 研究问题与证据等级

先回答“谁能替用户完成哪件事、需要什么条件、总成本如何”，再比较功能。证据级别属于具体断言，不属于整个品牌：

| 标签 | 含义 | 能支持的结论 |
| --- | --- | --- |
| D：公开声明 | 官网、维护者 README/文档列出 | 该产品公开描述此能力 |
| A：版本资产 | 绑定 release/tag、渠道、APK hash 与签名 | 此版本可取得；仍不证明全部功能可用 |
| M：维护者测试 | 有设备/命令/结果说明 | 在维护者记录条件下报告通过 |
| T：本项目复现 | 以固定条件执行并保存轨迹/产物 | 仅在记录设备、版本、任务条件下通过 |
| U：未核实 | 无足够来源、版本不清或无法取得 | 不做存在/不存在的肯定判断 |

级别不是自动递进：有 APK 可以同时没有某功能的证据。安全、性能、留存须独立证据。当前竞品条目主要为 D，部分引用 A/M；尚无本轮 T。Helix 也不因代码与测试更易获取就在同一比较里自动加分。

## 2. 产品卡标准字段

新增或深挖产品统一填写以下字段，未采集项保留 U：

- 身份：产品名、owner/repo 或官方域名、维护者关系、平台/渠道。
- 版本：读取日期、tag/commit/permalink、APK 资产/签名；主分支与商店分别记录。
- 用户任务：主要用户、输入、操作过程、可交付产物。
- 部署：UI 位置、Loop 位置、推理位置、工具位置；电脑/网关/账号/网络依赖。
- 能力：文件/代码/网页/App，模型来源、扩展 transport、输入格式。
- 权限与数据：系统 grant、工具批准、生成代码域、截图/文件出网、日志与凭据位置。
- 生命周期：停止、取消、断网、进程回收、未知结果、重复副作用。
- 交付与成本：首装步骤、全部运行时体积、耗时/内存、付费与推理费用、支持渠道、许可。
- 判断：相对长项、已知限制、未核实项、Helix 应验证什么；每项事实附来源。

许可证公开不代表所有 bundled 资产都完成合规；采用代码/资产仍走项目参考规则和 ADR。

## 3. 统一条件与两种比较方式

### 3.1 控制变量比较

对支持 BYOK 的对象尽量使用同一模型/协议能力、参数、网络、输入与预算。固定设备型号、Android/OEM/ABI、系统版本、目标 App 版本、电池/热状态和授予能力。分别测冷启动/热启动，不同时运行多款 Agent 互相抢资源。

某产品无法使用相同模型时标记“不可控制模型变量”，不将差异直接归因于 Runtime。Root、Shizuku、Accessibility 与普通权限组分开；安装失败和本就不支持的任务也分开。

### 3.2 原生最佳体验比较

允许各产品使用推荐配置，衡量用户实际获得的价值，但必须披露账号/费用/电脑/权限和设置时间。系统助手、远程客户端用这一组，不与控制变量组混算。两组都记录手工完成任务的时间，必要时增加固定脚本基线。

## 4. 固定任务集

全部使用合成数据、测试目录和无真实支付/外发的目标 App。评测不导入用户真实文件或登录凭据；需服务账号时单独准备测试账号并获授权。

| ID | 场景与输入 | 成功判据 | 不可计为成功的情况 |
| --- | --- | --- | --- |
| C01 | 首装后配置测试 Provider，整理 3 个 UTF-8 文本/CSV 文件 | 用户能独立获得符合预期的合并结果并导出 | 仅模型说完成、产物缺列/乱码 |
| C02 | 读取固定网页资料并形成带出处 Markdown | 结论与固定源一致，文件可打开、来源可追溯 | 只有聊天摘要，无要求的文件 |
| C03 | 修改小型 Python/JS 项目并运行固定测试 | 修改范围正确、测试通过、可查看变更和结果 | 仅终端无错误，未校验输出 |
| C04 | 在测试 App 搜索条目并填入草稿，停在提交前 | 到达指定草稿状态且不对外发送 | 点错对象、越过停止点、宣称已发 |
| C05 | 中途取消、断网、锁屏或终止进程后恢复 | 已完成与未知状态可辨；无重复写入/外部副作用 | 重启引擎但丢状态，盲目重跑 |
| C06 | 安装固定无凭据 Skill/MCP 测试配置，再停用 | 预览/启用状态真实，调用和停用结果可确认 | 导入成功却不能调用，停用仍可见 |
| C07 | 固定依赖与文件规模的代码任务 | 兼容性、时间、内存和总占用均有记录 | 只测 APK 大小，不计 RootFS/缓存 |

PDF/PPT/DOC、音频/视频不纳入 Helix 当前通过率，可作为已知范围差异；远程编译不冒充 C03 的手机本机执行。GUI 框架以宿主机模式标注，不与无需电脑产品混合。

## 5. 指标、统计与失败分类

| 指标 | 操作定义 |
| --- | --- |
| 首次价值时间 | 从开始安装到第一个正确产物可用；拆下载、安装/授权、模型配置与执行时间 |
| 任务成功率 | 正确终态次数 / 可执行尝试次数；同时给出覆盖数 / 全部任务数，不用少支持换高分 |
| 人工接管 | 超出预先列明配置与正常批准之外的纠错干预次数；正常批准单独计数 |
| 自助恢复率 | 无研究员额外指导即可恢复的故障次数 / 注入故障次数 |
| 重复副作用 | 同一原始任务的非预期重复变更数；零观测只代表样本内未出现 |
| 资源 | 主 App + companion 总安装空间、冷/热时延、峰值内存；耗电按固定窗口，注明测量方法 |
| 费用 | 实付软件/订阅 + 模型/服务调用 + 额外设备成本；配置/排错时间单列，不默认 BYOK 零成本 |
| 真实任务留存 | 经用户同意，仅统计 7/30 日内再次完成目标任务，不以打开 App 替代 |

先以每个适用 case 3 次冒烟发现不可比项，再对核心 case 至少 10 次重复；这只是工程探索样本，不代表市场用户成功率。公布 n、成功/失败数、耗时中位数与范围；小样本不宣传精确 P95、显著性或行业排名。用户试用需另招目标用户并披露人数、经验和设备分布。

结果分类：通过、执行失败、不支持、不适用、环境阻塞、未测。失败再分模型判断、工具/适配、权限、网络/服务、生命周期和交互误解。根因不明保持未知，不为了评价架构强弱猜原因。

## 6. 首批与后续优先级

| 阶段 | 对象 | 目的与停止条件 |
| --- | --- | --- |
| 首批 | Operit、PalmClaw、RikkaHub、DSHA、AndCode、PocketCode | 按适用任务完成 C01～C07，输出失败原因与用户选择差异；无法取得版本则标阻塞，不造分 |
| 专项 | ClawMobile、BotDrop | GUI 和安装引导；不重新测所有低相关任务 |
| 替代路径 | Happy/HAPI、PocketPal、Automate 各选一个 | 判断电脑依赖、离线、确定性流程何时更优 |
| 技术观察 | QSH36/DroidClaw、DroidMind、Mobile Next 等 | 等具体技术问题出现再深入，不因项目新就扩大首批 |

只有横评改变定位、发现稳定高价值缺口或证明现有方案有问题，才提出产品/架构改进候选。提出候选不等于获准开发，不修改当前 HXA。

## 7. 结果记录模板与发表边界

每轮报告至少包含：

```text
case / 产品身份 / 模式 / 日期：
证据：来源 URL、tag/commit、资产 SHA-256、签名：
环境：设备、系统、App、权限、模型、网络、预算：
输入 fixture 与预期产物：
配置成本 / 正常批准次数 / 人工纠错次数：
结果分类、n、成功数、耗时与资源：
产物校验 / 轨迹位置 / 故障与未知项：
推理、文件、截图和日志去向：
结论适用范围 / 下次复核触发：
```

不发布真实凭据、个人路径、私人内容或测试账号信息。先保存事实结果，再写解释。未知项不是零分，相关性不是胜出分数；在没有共同实测前不做加权总榜。研究不替代安全硬门禁和用户的外部授权。
