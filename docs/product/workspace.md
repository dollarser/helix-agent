# 会话工作目录

本文说明 HXA-210 已交付的工作目录行为；验证状态以 [开发状态](../development/status.md) 和 [HXA-210](../completion-records/HXA-210.md) 为准。

## 选择目录

新会话持久化时会获得自己的应用私有目录，不需要先创建项目，也不要求 input/work/output 文件夹。会话设置中的“工作目录”入口可选择文件管理器已经提供的目录来源，或回到自己的独立目录。多个会话可以显式选择同一个外部目录。

选目录不授予文件权限、不启动终端，也不执行目录中的脚本。Agent 仍遵守会话权限、工具启用状态和系统实际授权。独立目录不是代码沙箱；FULL_ACCESS 的实际访问范围由权限和执行域决定。

切换只影响后续模型请求。已经发出的请求、排队调用、审批和运行任务仍指向原资源；旧产物也不会被新目录的同名文件替代。执行前仍检查当前权限，目录切换不延续已经撤销的授权。

## 不同目录支持什么

| 来源 | 文件操作 | Git 与终端 |
| --- | --- | --- |
| 应用管理的本地目录 | 通过现有文件工具原位读写 | Git 检查使用所选目录；developer 手动终端使用受支持的私有目录映射 |
| 已授权本地外部目录 | 按真实系统权限原位读写 | Git 需要可访问的本地目录；没有 Runtime 映射的目录明确拒绝终端启动 |
| 系统文档目录（SAF） | 依文档提供者能力枚举、读取、写入、新建和受限重命名 | 不当作本地 cwd，不支持本地 Git/终端，不静默复制为另一个项目 |

Linux Agent 工具继续使用现有每任务暂存执行域。`files` 输入快照和 `output` 目标按请求目录固定；`cwd` 仍是任务内部的子目录。它不等于把任意 Workspace 直接挂进 Runtime。

文档提供者可能只支持删除而不能覆写，也可能临时失联。界面可以提供入口，但每次操作仍按具体文件能力检查。覆写前的哈希检查是乐观版本检查，不能保证外部程序在检查和写入之间不修改文件。部分写入或无法确认的重命名需要 review，失败不表示已经回滚。

整文件操作和可恢复备份目前限 32 MiB；较大文件使用分段读取。文档目录不提供原子替换承诺、通用跨目录 move 或本地路径专用的归档操作。分享是用户显式发起的有界传输副本，不改变工作目录身份。

## 删除与恢复

已绑定 Workspace 的可恢复文件删除会先保存并校验应用私有备份，再检查源版本并删除。目录或超出备份能力的文件会拒绝操作，不降级为永久删除。Shell 删除不经过此回收站。

中断后的备份会保留，系统不自动重放删除。恢复前检查备份哈希；原位置已有文件时返回冲突，不覆盖它。尚未确认删除结果的备份不能直接清空。删除会话记录和归档会话都不自动删除外部文件；当前也保留独立目录文件，避免误删其他引用或仍被任务使用的数据。

资源不可用时重新选择来源会建立经过检查的绑定。旧引用不会自动改指向同名的新目录。创建中断留下但无法证明身份的目录会保留，新的默认目录使用新身份。

不再被引用的应用私有目录可以在文件管理器的来源选项中选择“清理未使用的私有目录”，确认后永久删除。此操作不进入回收站。仍有关联会话、模型请求、排队调用、产物、备份或运行任务时拒绝清理；外部目录不提供此入口。入口显示只是当前状态提示，执行时会重新检查。

清理先持久化禁用新引用的状态，再把原目录移入私有隔离位置，然后删除。中断后不会在启动时自动继续；再次显式确认才恢复清理。目录身份改变或隔离位置不匹配时停止，保留文件供检查。已完成清理的来源从列表移除。

## 开发期数据边界

按所有者决定，Room 继续维护可重建的 v1 baseline，不提供旧开发数据库的 v1→v2 migration。旧文件保持原位置，不自动搬迁或删除；旧会话行、产物索引与审计记录不承诺升级兼容。重建数据库不能通过清除整个应用数据来冒充“保留文件”。新 baseline 自身的关闭重开与恢复仍须验证。
