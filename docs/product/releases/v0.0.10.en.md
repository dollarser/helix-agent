# v0.0.10 development preview

[Release and actual verification results](https://github.com/dollarser/helix-agent/releases/tag/v0.0.10) · [简体中文](v0.0.10.md) · [Source comparison](https://github.com/dollarser/helix-agent/compare/v0.0.9...v0.0.10)

This preview focuses on connected conversation/project workflows, sustained mobile interaction, files, sources and recovery. VersionName is 0.0.10; versionCode and Helix-owned internal versions remain 1. Standard (consumer) and Advanced (developer) ARM64 Release/R8 APKs use the existing development certificate, not store-production signing.

## Highlights

- **Conversations and projects:** choose/create a project when starting a conversation. Project and file-question entry points retain context in drafts, including text and attachments. Working directories are separate from private conversation storage; assigning an existing conversation to a project does not silently change its directory. Menus and capability selection remove duplicate actions; results remain in conversation management.
- **Mobile Use:** whole-phone default or selected applications, configuration on selection and rechecking on return. Semantic observation, screenshots and input depend on actual capabilities rather than task-screen presence alone. Root backend, retained task screens across turns, preview sizing/quality and original-task recovery improve continuity. Reobserve old frames/nodes; stale and unrecognized tokens have distinct recovery guidance.
- **Browser and files:** input, page ownership and explicit restoration fixes; persistent SAF grants, bounded complete text readers, verified write receipts and result sharing. Directory synchronization and in-place execution keep their separate authorization scopes.
- **Knowledge and rendering:** lazy selected-source retrieval, Chinese search, scanned-PDF/visual access and located citations; offline math, Mermaid and SVG previews. Continuous dictation appends to editable drafts, with improved read-aloud and speech lifecycle handling; transcription is never auto-sent.
- **Extensions:** unified plugin/skill/expert management and expert associations with existing capabilities. Imported configuration neither installs dependencies nor grants permission. Clearer skill resource and authoring/install guidance.
- **Backup, startup and diagnostics:** allowlisted portable application backups, retained rollback material after interrupted restoration and no automatic replay of external actions. First-launch notice runs alongside initialization; database preflight precedes old-data consumers and optional permissions can be skipped. Fixes cover failed database reinspection and interrupted cleanup. Bounded diagnostic history, audit search and client timing information improve inspection.
- **Development:** staged-snapshot and exact-push-snapshot hooks complement retained CI, channel boundaries and Release/R8 gates. Pinned third-party resource bytes are preserved.

## Before upgrading

- **An upgrade does not inherently wipe the database.** The Room schema is unchanged from v0.0.9. Incompatible databases require a separate impact preview and explicit confirmation; rejection preserves them. Rebuilding database records is not a whole-app wipe. Preview data is not guaranteed to remain compatible: save important material separately.
- **Old expert-library payloads are incompatible.** v0.0.9 stored plain instruction text; this version requires closed JSON. Room identity checks cannot detect that payload difference. Save expert names/instructions and remove old library entries in v0.0.9 before upgrading, then recreate them. Otherwise expert-list loading and related backups can fail. There is no silent conversion, skipping or deletion. Existing conversation snapshots are independent records, not migrated library entries. Do not clear the whole app to solve this narrow issue.
- Dedicated application backups restore their stated conversation/configuration/attachment and optional file scope. Static credentials are separately encrypted and default off. Account/OAuth sessions, system grants, directory permissions and running processes do not transfer; restored schedules are paused and unknown effects remain for review. Diagnostic exports are not restorable application backups. See the [backup contract](../../adr/workspace/008-content-backup.md).
- The existing development certificate is retained. Android may reject an older code-2 installation as a downgrade; this does not authorize uninstalling or clearing data. Retained source files do not imply recoverable indexes or conversations.

## Limits and evidence

The computer-started ADB helper remains a **Developer Debug / Android 12+ prototype**, absent from these Release APKs. In-app wireless pairing, task association across Helix process restarts and a pure-accessibility independent task screen are not implemented. Root, Shizuku and accessibility have distinct system limits.

The release body lists the exact source SHA, full CI, APK checksums, certificate and actual artifact runtime checks. Host checks, emulator results and historical physical-device evidence remain distinct. This release task does not test a phone and does not establish all-OEM compatibility, long-term stability, microphone/headset quality or store approval.
