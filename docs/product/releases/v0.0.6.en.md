# Helix v0.0.6 development preview notes

[简体中文](v0.0.6.md) | **English**

A development preview for sideloading, not a production app-store release. Use the [v0.0.6 Release](https://github.com/dollarser/helix-agent/releases/tag/v0.0.6) body for downloads, exact build commit, CI and APK SHA-256. Version assets consist of APKs and GitHub's automatic tag-based source archives. Pushing source alone does not publish a release.

## 2026-10-18 reissue

This reissue replaces the assets and tag target on the existing v0.0.6 preview page. The owner explicitly requires both the original and reissue to keep versionCode 1. The Release body records the exact build commit and reissue time. Package names and the development certificate stay the same for in-place installation within each edition. Manually download and install this APK over the original; an unchanged versionCode does not promise an automatic upgrade notification. Plugin/tool declarations remain version 1; installation revisions and process identities are independent, without clearing grants or user data. Subsequent attachment organization preserves these APKs, signing, versions and tag target.

## Packages and upgrades

Requires Android 10+ on ARM64. Release APKs are built from the clean commit recorded in the Release body. Both use R8 optimization, are non-debuggable, retain `versionName=0.0.6` and `versionCode=1`, and use the existing development certificate. This is not a production-signing or long-term upgrade commitment. Installations with a versionCode above 1 remain subject to Android's downgrade restriction.

| Package | Scope |
| --- | --- |
| `helix-v0.0.6-consumer-arm64-v8a.apk` | Standard, the complete base product: conversations, API/on-device models, files and channel-supported plugin tools; excludes PRoot and third-party subscription runtimes |
| `helix-v0.0.6-developer-arm64-v8a.apk` | Advanced adds a Linux environment, terminal and experimental subscription adapters, subject to the current mode, system capabilities and conversation authorization |

Check the APK SHA-256 in the Release body before installation. Matching R8 mappings and concise build identity are retained as developer archives rather than version assets. Development signing does not make an APK debuggable, and an unchanged versionCode does not establish database compatibility. Model weights are not bundled; select the built-in service in conversations, configure your own API, or prepare an on-device model.

This preview does not promise migration of older database schemas. An incompatible upgrade asks for confirmation before normal startup and task recovery: it clears database conversations, tasks, settings and authorization records while retaining files outside the database. Cancelling exits and preserves old data. Diagnostic exports are not restorable full backups. If signatures conflict or the data must be preserved, keep the existing installation and resolve the upgrade conditions before proceeding; do not bypass them by uninstalling.

## Highlights

- **Built-in models:** a dynamic directory in the conversation picker, with no key or Provider configuration card. Cached discovery preserves selected targets on failure and never sends inference probes when opening the picker. The public, revocable Client ID is not a user secret; shared limits and availability are managed by the gateway.
- **Model selection and reasoning:** model and effort edits are staged until Save; Cancel discards them. Known Qwen low/medium/high maps to low/medium/xhigh, while Default omits the parameter. Accepted requests do not prove differences in reasoning behavior. Model-source and plugin layouts adapt consistently; conversations omit the built-in transmission reminder.
- **Plugin identity:** unchanged native startup and healthy repair avoid redundant database writes and revision increments while rebuilding process tool projections. Content, enablement and necessary repairs retain CAS protection.

- **Plugins and interaction:** clearer Installed, Market and Import entry points, consistent setup/readiness feedback, and on-demand skill loading. Imported content and required components are distinguished; importing a package does not authorize accounts, scripts or device actions. Mobile Use remains a plugin using host authorization and runtime management.
- **Conversations and files:** clearer progress, tool and final-answer presentation. File-tool titles emphasize the filename; directories and full details remain available when expanded. Display paths do not retarget submitted calls, and conversations, projects and working directories keep distinct identities.
- **Reliability:** improved incompatible-preview confirmation, budget persistence, call recovery and review states; fixed missing stdout during Linux job collection. Execution, durable results and actual model consumption are verified separately.
- **Linux environment:** Advanced prepares bundled resources for the first authorized new job or manually opened terminal. Opening Settings, passive queries and recovery of old jobs neither install resources nor replay commands. Damaged or mismatched installations require explicit maintenance.
- **Maintenance:** the Linux environment shows actual installation state, with inspection, repair, reinstall, removal and licenses available on demand. Historical maintenance receipts are distinguished from current state. Directory cleanup no longer follows symbolic links into external files.
- **Everyday interaction fixes:** restored browser page layout and preserved source-page snapshots when external app navigation is rejected; automatic titles respect manual naming. Voice, text, add and send remain inline; Full access uses colored text without a background. Short progress stays visible and blank content no longer creates a disclosure.
- **Phone gestures:** validate the initial frame, then allow valid window transitions while the touch continues. This fixes notification-shade cancellation while preserving scope, display mapping, lock, cancellation and unknown-outcome boundaries.

The built-in cloud service receives messages, context, tool results and selected images, subject to shared limits and service availability. Unknown retention or training policies are not promised; you may select your own model.

PRoot uses a non-exported private process but shares the host UID; it is not a complete security sandbox for malicious code. System permissions, conversation authorization and execution limits still apply.

## Remaining boundaries

Release acceptance does not cover physical phones, other API/OEM combinations, x86 devices, two-hour/24-hour stability, other providers/accounts, or full FFmpeg/PRoot media end-to-end behavior. The 15-minute browser resource check does not replace those checks. Visual recognition and task quality depend on the model and target app; emulator success does not establish all phone-backend compatibility.

Third-party licenses and exact sources are retained in the existing [runtime asset Release](https://github.com/dollarser/helix-agent/releases/tag/runtime-assets-20260917): `helix-v0.0.6-third-party-notices.zip`, `alpine-corresponding-source.tar.gz`, `alpine-source-manifest.json` and `media-corresponding-source.tar.gz`. The application Release body directly links these materials. Existing Termux sources and runtime assets remain unchanged; no separate materials Release is created. Helix's Apache-2.0 license does not replace third-party licenses.

The broader harness refactor, remote execution platform and per-call change review remain planned work, not delivered features of this preview. See [release readiness](../../development/release-readiness.md) for production-signing and channel requirements.
