# v0.0.11 development preview preparation

[简体中文](v0.0.11.md) · [Acceptance record](../../evidence/development/v0.0.11-preparation-2026-11-13.md)

Status: the final UI-integrated candidate passed both channels of Debug/R8 core-conversation acceptance. The complete final host gate and ordinary ARM64 distribution build also passed. The application preview is not published; final distribution signing, commit, CI and artifact identities belong to the actual release record.

Compared with v0.0.10, this preview focuses on service and model settings, cross-session collaboration, web and file tools, and long-running task recovery. The product version is **0.0.11**. Android versionCode and Helix-owned internal versions remain **1**. The planned artifacts are Standard (consumer) and Advanced (developer) ARM64 Release/R8 APKs.

Helix has not reached a formal release. Development previews do not guarantee in-place installation or preservation of existing data, even if installation succeeds. Save important content separately before upgrading.

## Main changes

- **Ordinary conversations and required checks:** Fixed the production Room store rejecting a bounded `tools.cost` diagnostic before the model request. Unknown types and payload limits remain enforced. Every candidate requires actual conversation, successful tool backfill, persisted history after process restart, cancellation, no replay and continuation checks.
- **Tool details:** Compact conversation summaries lead to grouped, copyable details. Business content and internal diagnostics are presented separately without replacing stored tool results, model records or audit values.

- **Services and models:** API connection fields and model selections share one editor with a single save action. Add multiple models and display names without leaving it. Connection, model-generation and capability checks keep separate results. Conversation model pickers group models by service; subscription sign-in retains its own management flow.
- **Cross-session collaboration:** Explicit, separate grants control history access, management, creation and task delivery. Query sessions, create them idempotently, queue work or steer a specific active Turn. Model-origin messages retain provenance and do not copy file grants, create user Goals or bypass the target's approvals.
- **Web and search:** Bounded public-page fetching, browser search and form actions, plus page text that retains usable source links. API search and supported Responses native search require explicit enablement and do not silently activate paid services.
- **Files and granted directories:** Stronger native glob and literal grep behavior with real system SAF providers, readback, revocation and cancellation checks. Fixes cover directory-to-conversation handoff, long directory names and refresh state.
- **MCP and skills:** Bounded text and binary MCP Resources are delivered through host-managed artifacts. Binary bytes are not inserted directly into model text. Skills retain plugin ownership, with atomic composer tokens and slash discovery.
- **Long tasks and recovery:** Changes to compaction preflight, tool discovery and schema projection, stable cache prefixes and observed cache accounting. Goal coordination, tool settlement and process recovery retain explicit unknown-effect states rather than automatically replaying them.
- **Advanced media and mobile use:** FFmpeg continues through the existing PRoot/Job path for media, subtitles, fonts and multiple outputs. A MediaCodec initialization patch removes the encoder-flush path. The computer ADB helper supports non-debuggable Advanced builds on Android 12+ through app-issued, one-use, process-bound handoff tickets. Standard has no helper entry.

## Before upgrading

- This candidate's database structure differs from the earlier v0.0.10 build, including new cross-session grant and idempotency-receipt tables. Keeping the internal schema version at 1 does not imply compatibility or lossless upgrades.
- An incompatible database requires a specific impact notice and independent confirmation. Canceling must not clear it. Rebuilding the main database is distinct from clearing all application data; release preparation does not authorize clearing a daily installation.
- An application backup is not a copy of account/OAuth sessions, Android permissions, directory grants or running tasks. An older backup is not evidence of restore compatibility.
- versionCode remains 1. Automatic system/store update discovery is not promised. Package, signature, installation and retention claims depend on the exact final APKs.

## Limits

- Search, subscription, MCP and model support depend on the configured provider. Integration is not universal service or model acceptance.
- MediaCodec encoding depends on the device. No x264, x265 or AV1 software encoder is included; codec coverage and performance are not universal.
- Cross-session controls are not remote computers or production subagents, and do not grant file, device or external-service access automatically.
- Host, emulator, physical-device and real-model checks will be listed separately. Old candidate results are not current acceptance. No claim is made for every OEM, 24-hour soak testing, 16 KiB physical devices or microphone/headset quality.

## Final core acceptance and historical evidence

- The final UI-integrated source passed real-Room Debug core batches on exclusive API36 emulators: 9 classes and 35 executed methods per channel, with no failures, skips or missing methods. A separate isolated tool-details UI batch passed 28 methods; these counts are not combined into a product-coverage score.
- Both ARM64 R8 channels were built from the same final production and Release-test inputs, using isolated package IDs, a test certificate and non-debuggable applications. All four source-enumerated default smoke methods passed per channel. The conversation journey reaches a real loopback HTTP provider, executes a real read-only tool and returns its successful result, verifies process exit and a different PID after restart, reads persisted history into the next request, closes a cancelled connection, avoids replay after restart and continues successfully. Installed APK hashes match the frozen copies; exact fixture-package removal and owned-instance closure are recorded.
- The same strengthened test APK rejected the retained broken candidate before the first ordinary request reached its provider and passed a repaired intermediate candidate. This establishes a useful regression control; the intermediate result is not final two-channel acceptance.
- The final complete `check-all.sh --all` host gate, both ordinary ARM64 distribution builds and artifact-boundary checks exited successfully with an unchanged full-file inventory. Only result documentation was updated afterward, followed by another source gate. Normal Gradle cache reuse is not described as reexecuting every task, and host success does not replace actual device acceptance.
- Earlier ONEPLUS_A6013 / API34 / ARM64 / 4 KiB-page runs covered 30 Debug checks and 8 R8 entry checks. The phone/API36 media reruns repeat a three-method subset. That batch did not exercise the ordinary-conversation production Room chain and did not detect the later reported defect; it is not final-candidate core acceptance.
- Historical media evidence supports only the tested OnePlus 320×240/NV12 synthetic H.264/HEVC sync/async cases with 8 frames and actual decoding. The rejected 96×64/yuv420p input remains recorded; no universal Qualcomm rule or minimum size follows. Reusing this evidence requires checking the unchanged media payload in the new artifacts.
- Earlier phone and daily-emulator cover installs retained data for those exact installations, not every public v0.0.10 upgrade. Final core acceptance used exclusive test instances without touching the daily foreground or physical phone.
- Test signing is not final public distribution signing. A 16 KiB ZIP-alignment check is not 16 KiB hardware execution. These core fixtures make no external model calls and do not cover API29, other OEMs, real-model media workflows, prolonged thermal/background stress or microphone/headset quality.
