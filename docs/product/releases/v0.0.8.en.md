# Helix v0.0.8 candidate

[中文](v0.0.8.md). **Preparation only; not published.** There is no published download link or release tag. Source changes are committed locally; the accepted APKs retain their actual pre-commit workspace build identity and must not be presented as rebuilt from a later SHA.

## Changes

- Knowledge, notes, imported originals and attachments use shared open documents under `Documents/Helix/library/` as authoritative content. Rebuildable indexing is separate. Credentials, Agent memory, conversations, approvals and execution facts remain private. Existing libraries require explicit restore/access; a common directory does not grant access to another package's files.
- Knowledge categories and conversation references support explicit saves, selection/cancellation and frozen historical content. Editable shared state cannot authorize automatic extraction or deletion on startup.
- Advanced manual terminal creation is independent of historical UNKNOWN/stopped records. Readiness requires a real new PTY and shell prompt. Old commands are not replayed; Linux contents are not automatically erased. Arbitrary OS/runtime corruption is not claimed repaired.
- Signed-in default online speech, explicit offline choices and first-use consent are kept distinct. Offline ASR uses pinned ModelScope artifacts downloaded on demand; inference remains bundled, model weights do not. Download/cancel/failure/resource feedback is concise.
- File, Git, knowledge and speech guidance is shorter, retaining permissions, destructive consequences and accurate failure classification.

## Identity and limits

The owner confirmed version name 0.0.8 and versionCode 1. All Helix-owned internal versions also remain 1. Devices with v0.0.7 / code 2 may require uninstall/reinstall; removing the old release page does not remove Android downgrade restrictions. Uninstall deletes that package’s local data and requires concrete target authorization. Data must never be silently cleared, and no old-format compatibility/migration chain is added. The owner will handle v0.0.7; the agent will not delete its Release, tag or assets.

ARM64 Standard and Advanced candidates retain the existing development-preview certificate, R8 optimization and non-debuggable packaging; this is not production store signing. Final identity, acceptance and remaining risks are recorded in the [candidate record](../../development/v0.0.8-candidate.md). No push, tag, Release creation or upload is authorized by preparation alone.

Full host gates and both-channel Release/R8 passed. Emulator acceptance includes 50 functional checks, three isolated Release smoke cases per channel, and exact signed normal-candidate installation/hash/conversation-start checks. Initial fixture failures and corrections remain recorded.

Emulator tests do not resolve the original phone terminal/Mobile Use reports. Real microphone/cloud calls, paid models, production signing/store review, all-OEM soak and arbitrary historical lossless upgrades are not accepted here. Model discovery/log-reading variability and existing server ASR quality limitations remain visible.

See [third-party notices](../../../THIRD_PARTY_NOTICES.md), [ASR dependency lock](../../../config/asr/dependencies.lock.json) and packaged notices. Publication must verify exact source/license obligations for the actual candidate.
