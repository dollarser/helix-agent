# 任务与工作区体验

本页定义用户路径和可用性目标，不维护实现状态或任务命令。职责与验收见[任务索引](../development/roadmap.md)；未完成的功能不可在 UI 伪装可用。

## 2. 工作区作为操作起点

保留聊天、文件管理、浏览器独立入口，不要求先创建Goal或配置模型。工作区详情提供“文件、任务、终端、变更”四个直接入口；小屏用可见的分段导航，不要求增加四个全局底栏。没有Git的目录仍可查看工具已记录的文件变更，不显示伪造Git状态。

| 用户当前位置 | 直接动作 | 目标及返回行为 |
| --- | --- | --- |
| 工作区文件 | 在终端中打开所在目录 | 进入关联会话选择；没有会话时由用户明确新建，不能打开页面就执行命令 |
| 工作区任务 | 查看过程/结果 | 定位精确Turn或Goal，返回保留列表位置 |
| 命令输出 | 查看生成文件/变更 | 只使用实际Artifact或验证后的文件引用；日志中的任意路径不是可信导航目标 |
| 文件变更 | 查看差异/打开文件 | 使用已有有界diff/预览；返回保留选中文件与滚动位置 |
| 产物 | 查看来源任务/所在位置 | 同scope、同文件身份；权限失效显示恢复入口，不跳到同名其他文件 |
| 任务/聊天 | 打开所属工作区 | 保留会话草稿，不自动改变当前会话的文件授权或工作目录 |

导航参数由应用层生成，包含现有workspace/session/turn/job/artifact身份中所需最小集合。UI不传裸路径绕过resolver。跨工作区切换只改变显示；需要重新绑定会话或改变终端cwd时用户明确操作，既有shell不被静默cd。

可用性验收目标（待测试）：同工作区“输出→产物→来源任务”每段不超过两次操作；返回不丢位置/草稿；重名工作区与同名文件不串；断开或缺权限有明确解释。点击数不包含系统文件选择/授权等外部界面，统一记录口径。

落位：HXA-194/197/198负责终端入口；HXA-202负责导航和任务；HXA-203负责产物与变更。新增场景加入现有TaskJourneyDeviceTest、ArtifactDeliveryDeviceTest和终端设备类，不新建平行页面体系。

## 3. 开发环境初始化、修复和会话

用户入口统一叫“开发环境”，默认说明“在手机上运行命令和项目工具”。PRoot、UID、Binder、ABI只在技术详情；共享应用数据的可信执行边界仍需用清楚短句说明，不因隐藏术语隐瞒权限。

准备页从实际状态投影，不另存一套Ready枚举：

| 用户可见状态 | 主动作 | 结果要求 |
| --- | --- | --- |
| 尚未准备 | 准备环境 | 显示下载/校验/配置的实际步骤；有总量才显示百分比 |
| 正在准备 | 查看进度/取消 | 重开页面观察原操作，不发第二次安装 |
| 可以使用 | 打开终端 | 用户明确新建或连接现有会话 |
| 需要修复 | 查看问题/修复 | 显示已识别失败步骤；优先修复缺项，不默认清数据重装 |
| 此版本不提供 | 查看版本能力说明 | consumer不出现无效安装按钮，不暗示系统权限能开启被排除模块 |

修复前说明会保留和影响的用户数据。只在确实需要丢弃数据的方案中披露具体影响并取得该操作授权；普通校验/修复不叠加无关确认。取消后保留已确认可复用的资源，不把部分下载称为可用。没通过既有自检不显示“可以使用”。

会话列表首屏显示标题、工作区/目录、连接状态和最近活动，可切换、重命名、关闭；打开已有会话不创建第二个shell。关闭页面与关闭会话使用不同文案和动作。等待Agent冲突时提供“返回任务”及关闭会话入口；按ADR-RUNTIME-002执行互斥，不把prompt出现当作子进程已停止。

只有真实进程状态可显示“运行中”；断连可显示“正在核查”，确认死亡后显示“已中断”。明确重新打开新会话不声称恢复原进程。最多两个会话和资源限额沿ADR-RUNTIME-002，不为视觉上的多标签提前放开并发。

落位：HXA-205对齐190/191/193已有配置与修复；HXA-197/198交付交互。验收覆盖离线、空间不足、下载中取消、校验失败、重开、进程死亡、双会话切换，以及软键盘和小屏遮挡。

## 4. 扩展能力的完整使用路径

首版入口为“添加能力”，分“已添加”和“添加来源”；可按名称、用途和提供方搜索已有受支持条目及已启用目录。支持现有Skill/Connector导入、MCP配置来源，不假装已有在线市场。MCP/Skill名称保留为详情类型，列表以用途和真实可用条件说明。

路径：发现或导入来源 → 查看用途/来源/需要访问什么 → 添加或连接 → 验证 → 启用 → 在任务中使用 → 查看结果 → 设置/停用/修复。

- 状态分别展示已添加、待配置、待连接验证、未启用、可使用、需处理；它们来自各服务的事实，不能用一个“安装成功”覆盖全部阶段。
- Skill显示实际启用范围；当前只有全局能力时就写“所有会话”，不得做看似工作区限定、后端却全局启用的假设置。新增会话scope留HXA-129。
- MCP连接测试不自动启用全部工具；保留用户选择工具及授权摘要。Skill安装后也不自动扩大Agent文件范围。
- “试用”由用户点击，优先受支持的无副作用样例。实际工具调用仍走Dispatcher和当前会话授权；没有可用样例就提供使用说明，不能随意试发消息/创建文件验证连接。
- 可使用后提供“在当前任务使用”或“新建任务”，只带入能力选择/草稿，不自动发送模型请求。首次实际调用成功与仅连接成功分别标记。
- 失败原地给出配置、重新验证、停用或返回任务；重试只作用于明确的配置/查询步骤，不盲目重放原任务。卸载/更新只暴露已有可靠后端动作，不以UI先行绕过HXA-129。
- OAuth登录、在线签名索引、任意本地MCP进程、新市场或版本回滚不在本切片；已有Bearer等配置仍用安全别名，不在日志或截图显示密钥。

## 5. 用户语言和渐进展开

| 默认呈现 | 技术详情才呈现 | 行为要求 |
| --- | --- | --- |
| 允许、询问、禁止 | ALLOW/ASK/DENY、规则revision | 设置必须真实影响调用；本次允许与未来偏好分开 |
| 允许访问的文件夹 | scope引用/规范路径解析 | 用户看得见具体范围，不只显示“已授权” |
| 在手机上运行命令 | PRoot、进程名、ABI | 保留可信开发环境的数据访问说明 |
| 需要确认、等待结果、已中断 | Turn/Job状态、执行ID | 只在状态真实支持时显示，可展开诊断 |
| 添加能力、连接服务、使用说明 | MCP、schema、Skill manifest | 不隐藏服务来源、网络外发或实际启用范围 |

审批摘要用动词+目标+影响，例如“修改工作区中的2个文件”；没有可信变更数量时显示已知操作，不猜测shell内部效果。外发摘要明确接收服务和数据种类；完整参数可展开。不要在普通界面显示Policy/Approval Proof等内部词，但保留“范围内自动执行，高风险操作仍需确认”的真实说明。

错误文案包含问题、已完成结果、下一动作，不只显示堆栈或内部错误码；“详细信息”提供脱敏诊断。禁用按钮旁解释原因，不用连续弹窗代替状态。三语言资源、屏幕阅读标签、大字体和软键盘遮挡纳入验收。

落位：HXA-201统一权限表达，202/204统一状态和错误，205/207统一能力说明；不重新设计全局主题或重复191。
