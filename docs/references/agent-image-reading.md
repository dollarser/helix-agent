# Agent 自主读图：使用与需求边界

更新：2026-09-29。实现归 HXA-225，长期契约见 [ADR-AGENT-011](../adr/agent/011-tool-multimodal-vision-feedback.md)。本文针对包含该源码变更的新构建，不表示此前发布或已安装的 APK 自动更新；主机、设备与真实模型证据分别记账。

## 1. 从附件看图到自主看图

用户仍可通过相册、文件选择或拍照把图片加入消息。新增能力是不必再次手工附图：Agent 可在已授权工作目录发现图片后调用 `view_image`，图片作为真正视觉输入加入后续模型请求。普通 `read` 的二进制/base64 文本不是这条链路。

典型任务：

> 查看当前目录里的 chart.png，说明图表展示了什么；不要只根据文件名猜测。

> 读取刚才脚本生成的 result.png，检查图例和标题有没有互相遮挡。

> 截取当前 Helix 浏览器页面，检查布局是否溢出，先说明发现再决定下一步。

前提是会话当前模型确实支持视觉，文件位置可访问，相关工具未被禁用。模型能力声明不是给纯文本模型添加视觉编码器；图片进入请求也不保证识别准确。

## 2. 实际调用与流程

模型可使用：

```json
{"path":"chart.png"}
```

这是 `view_image` 的参数，相对路径使用当前请求冻结的工作目录。也支持已有授权范围内的 `scope:` 引用，不接受任意绝对路径、URL 或目录越界。工具通常由 Agent 自己选择，用户无需输入 JSON。

```text
文件/图表路径 → view_image → 文件读取权限与 scope 检查
                             ↓
                     有界快照与图片归一化
                             ↓
                 typed VisualArtifact + TOOL 结果绑定
                             ↓
                 当前模型能力、图片窗口和请求预算
                             ↓
                   对具体图片和目标的数据披露
                             ↓
                 校验实际字节 → Provider 图片内容
                             ↓
                         模型继续分析
```

`browser.screenshot` 保存图片后使用同一准备管线；已有图表/截图文件通过 `view_image` 进入。没有新增录屏、整机截屏或 OCR 服务，也不替代 Mobile Use 的 Accessibility 语义树。

## 3. 用户可能看到什么

| 状况 | 行为 |
| --- | --- |
| 图片可读且模型有视觉能力 | 准备归一化副本；必要时显示图片发送确认，允许后供模型观察 |
| 文件读取需要批准 | 先经过原工具批准；这与像素发送确认是不同权限 |
| 用户拒绝发送像素 | 原读取/截图事实保留，模型得到明确未展示说明，不宣称已经看见 |
| 文件缺失、变更、格式伪装或损坏 | 明确失败，不发送不匹配载荷，不返回伪造成功图片 |
| 模型没有视觉能力 | 明确不可用；不启动第二个未配置的视觉模型，也不把 Base64 当替代 |
| 图片过大 | 在既有 VisionLimits 内尝试归一化；仍无法满足则拒绝，不无限读取 |
| 早于当前窗口的工具图片 | 保留文本来源与未展示说明；需要细看时再次调用 view_image |
| 取消任务或切换目标期间有待发送图片 | 重新校验绑定，不能把旧批准用于另一个目标/新 Turn |

同一会话、Turn、图片内容、消息、模型及连接配置的短期有效确认可复用，不在每轮重新询问；这不是任意图片或永久上传许可。若用户退出页面而确认无人处理，不会默认同意。文件本地读取和模型出网授权不能互相替代。

## 4. 当前支持范围

- PNG、JPEG、WebP、GIF 等由现有图片探测/归一化器支持的栅格格式；GIF 等动态输入按原归一化行为处理，不提供视频理解。
- consumer/developer 使用同一图片能力；不要求 PRoot、Root 或另一个设备。
- Responses 使用原生图片工具输出；Anthropic 使用工具结果内图像；Chat Completions 在完整工具批次之后生成仅存在于线上的观察消息。
- 现有订阅 Runtime 的图片入口复用逐请求校验后传输快照；受其既有协议、数量和字节限制。没有新增供应商/账号支持承诺，本轮不代表真实账号验收。
- 内置设备端本地推理仍是无视觉路径；远端/局域网自建视觉端点则按已支持协议与实际能力使用。

Helix 首版复用原图片资源限制：源图最多 10 MiB，归一化后边长最多 4096、总像素最多 12,288,000、单张归一化文件最多 2,850,000 字节；总请求图片预算也覆盖用户附件。Provider 的实际限制仍可能更严格。每次请求只保留当前 Turn 最新两张工具图像是本次策略，不代表只看两张足以解决全部任务。

没有强制“所有截图压成 1280px/500KiB”，也不保证细小文字在缩放后可辨认。模型应明确不确定性，必要时由用户选择更清晰输入，而不是自动编造丢失信息。

## 6. 与当前实现相比的改进

| 旧行为 | 新行为 |
| --- | --- |
| 仅用户消息挂 images | 可信 TOOL 观察也可挂真实图片 |
| screenshot 返回文件路径，模型看不到像素 | 保存的截图可进入后续视觉请求 |
| 想读已有图片只能让用户重新附图 | Agent 调用 view_image 读取已授权路径 |
| 普通二进制 read 结果无法证明模型看图 | 专门类型化副产物、持久消息绑定与协议图像块 |
| 旧草案把全部 OpenAI 工具输出视作文本 | 三协议独立适配，Responses 使用原生能力 |
| 全局 session 指针容易造成异步来源混淆 | 每个请求携带确切消息/会话/哈希/目标绑定 |
| 文件先算哈希再整读可能错配或内存无界 | 对实际要发送的同一份有界字节复核 hash/MIME/长度 |

不增加数据库表、不恢复已删除 composer_drafts，不为此重做 Core/Node/插件系统。工具返回的任意字符串、MCP 内容或图片内文字都不能授予执行权限。

## 7. 验收口径

单测与编码 fixture 证明原始事实、权限、预算、字节和消息格式符合预期；真实像素的 Android fixture 另行编译，执行需要当前设备授权。它们不能替代真实模型识别质量测试。

后续真实验证应使用不把答案泄漏在文件名/文本输出中的图像：例如随机色块/图表标签，要求 Agent 通过读取工具回答；另外验证取消发送、模型不支持、过期图片、工作目录切换及多轮窗口。历史截图出现、Base64 出现或模型自称“看到了”都不能单独算视觉验收成功。
