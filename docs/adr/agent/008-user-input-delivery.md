# ADR-AGENT-008: 统一用户输入交付与停止语义

Status: accepted
Date: 2026-09-22
HXA: HXA-214, HXA-216
Deciders: Project owner（2026-09-22 明确授权按既定顺序开发，并要求不等待前批验证完成直接启动后续216；接受设计不表示实现或验收）

## Context

运行中输入框禁用、异步发送先清空草稿、聊天与 Tasks 取消路径不同，使用户难以纠正输入。Goal 的新输入路径还会先解除激活并取消当前 Turn。用户要求普通 Turn 与 Goal 具有一致的交互：发送不自动停止，停止是显式操作。桌面产品同时存在 Turn 后 Queue 和 Turn 内 Steer，不能把二者混称“排队后总等到最终回答”。源码与官方证据见[研究记录](../../research/conversation-context-and-steering.md)。

## Decision

### 统一交互

- 普通发送默认 **Queue：本轮结束后发送**，所有 Chat/Act/Plan/Goal 使用同一交付入口；模式仍决定工具与执行能力。
- 用户可显式选择 **Steer：调整当前任务**，进入当前 Turn 的下一安全模型请求边界；不取消正在进行的模型流或工具。首版不增加全局偏好、自动语义分类或“输入关键词即中断”。
- **停止**独立可见，绑定点击时的 sessionId/turnId，持久化取消意图后再取消。正常停止使该会话已排队输入进入待用户继续状态，防止停止后立刻又发请求；保留内容、可编辑/撤回。停止后的新一次显式发送可启动新请求，不隐式释放旧队列。
- 运行中可编辑草稿，队列显示“待发送”“等待接入当前任务”“已纳入请求”“需要处理”等真实状态，不显示未经证实的“模型已采纳”。正常后继按 FIFO，一项对应一个新 Turn，不静默合并多条指令。
- 只从应用可信用户入口接收；MCP/Skill/模型内容不能创建同等级用户输入或改变交付类型。

### 接收、草稿与身份

提交带 sessionId、inputId/clientRequestId、草稿 revision、附件引用及目标 Turn。返回持久接收、待确认或拒绝回执；仅持久接收成功后清空对应 revision，晚到回执不得清空新草稿或其他会话草稿。待确认/拒绝保留输入；并发双击同一 ID 不重复提交，ID 对应内容不同则冲突。

复用现有消息正文和附件存储，增加小型会话输入表，不另建消息正文数据库或事件溯源框架。至少保存版本、输入 ID、会话、顺序、交付类型、预期 Turn、正文/附件引用、配置/目标绑定、revision、状态、消费 Turn/message IDs、阻塞原因和时间。Steer 要求 expectedTurnId 匹配，不能在旧 Turn 完成后静默变成另一个 Turn 的指令。

状态区分待交付、待处理、已追加历史、撤回；“已追加历史”不等于请求已发出。更新/撤回与消费通过事务及 revision 竞争，只有未消费输入可编辑。USER 消息和消费映射原子落库；队列到新 Turn 与既有 clientRequestId 去重衔接，崩溃不得生成第二条 USER/第二个 Turn。模型请求在途结果未知仍走现有恢复，不承诺网络 exactly-once。

首版每会话最多 32 条未消费项，未消费文本合计最多 1 MiB UTF-8；单条继续受既有输入限制，附件沿用现有快照和配额，不另读大文件进入内存。满额明确拒绝并保留草稿；这只是端侧存储界限，不新增模型累计预算。已消费辅助记录可按既有会话生命周期清理，队列查询必须有界。数据库迁移和外键删除/引用计数必须验收。

### Queue 与 Steer 的消费点

| 当前阶段 | Queue | Steer |
| --- | --- | --- |
| 无活动 Turn | 通过正常准入启动下一 Turn | 返回目标已结束/不存在，保留输入，由用户选择下一轮发送 |
| 模型流中 | 等待当前 Turn 结束 | 不修改在途请求；在流完成及工具批结算后的下一请求边界消费 |
| 工具批运行/等待审批 | 等待，不代答审批 | 等整批完整结算；仍需审批时显示等待，用户可独立停止 |
| 准备正常终局 | 终局提交后按 FIFO 调度 | 与终局在同一协调边界竞争；先接收则继续当前 Turn，否则明确目标过期 |
| 错误、预算停止、未知副作用或系统中断 | 保留并标记待处理，不跳过原恢复门禁 | 不重置预算、不切换新 Turn 隐式继续；保留尚未消费项 |
| 用户停止 | 队列停泊，不自动发送 | 不再投递给取消中的 Turn；保留待处理 |

正常终局释放会话执行槽后，用户队列优先于自动续跑；并发 enqueue 与终局提交不能丢失唤醒。已排队不代表提前获得任何工具审批。入队前完成当前需要的出网确认并绑定确切内容/目标；实际消费重新校验目标、附件、能力与现有门禁，配置变化不得静默发给另一个 Provider。需要重新确认时就地待处理并保留 FIFO，不跳到后项。

工具 assistant calls 与 TOOL results 始终成批配对；不能将 USER 插入中间。Steer 可使回填请求末尾是 USER，需调整现有最终角色假设并覆盖三类 Provider adapter，不伪造 TOOL 来规避校验。上下文准备时一并纳入压缩/容量校验；已追加消息若因容量失败未发请求，必须如实记录“不曾纳入已启动请求”，重试不得重复追加。

### Goal 仅在调度层区分

普通 Queue/Steer 不发 pause request、不取消 Turn、不仅因新消息就撤销既有 Goal 激活，也不修改目标或预算。Goal Driver 在同一会话调度点先让已就绪用户输入取得执行槽，再复查旧激活是否仍合法。普通后继输入默认是一轮用户请求，不因为页面处于 Goal 模式自动创建第二个 Goal；新建/替换目标是明确操作。

Steer 使用原 Turn 模式、模型和预算；其中的直接用户来源绑定新 input/message ID，不冒充原始目标原文，不给自动轮或旧重试伪造用户授权。Goal 编辑若明确需要，仍经过原有 revision、批准 Plan、权限及结算机制。

用户队列正常处理完且旧激活仍有效时，Driver 才可继续旧目标；明确停止/暂停、目标已完成、阻塞、预算不足、未知副作用和进程死亡均按现有规则撤销资格，不被队列“复活”。停止 Goal Turn 同时阻止它自动续跑。停止某个 Turn 不批量杀死无关后台 Job 或手动 PTY。

### 与现行决定的关系及接受动作

本决定替换 [ADR-GOAL-001](../goal/001-lifecycle-and-completion.md) 中“停止和新输入先解除旧激活，再安全结算当前轮”的**新输入**部分；显式停止和进程死亡规则保留。同时补充 [ADR-AGENT-001](001-turn-coordination.md) 的批次边界输入与终局竞争契约。本次同一文档提交收敛这两份有效 ADR 与 Goal/Agent 主题入口。HXA-216 在独立工作树实施，交付前仍须完成各切片和联合验收；不把设计接受或前批局部通过记为功能已实现。

HXA-214 只修复草稿回执和停止一致性，不提前改变 Goal 新输入行为，不要求先接受新增队列表。它可先作为现有已接受契约的修复实施。

## Alternatives considered

- 发送即取消 Goal、普通 Turn 拒绝：用户交互不一致且丢失连续工作，不继续扩展。
- 所有消息均等最终回答：可作为 Queue 默认，但不能满足长 Turn 中及时补充；提供显式 Steer。
- 所有消息自动转向：用户下一项任务可能被错误并入当前任务；默认 Queue，显式 Steer。
- Steer 靠取消并启动新 Turn：改变预算/结算语义，不采用。
- 停止后立刻自动发送旧队列：部分桌面产品这样做，但手机端“停止”应可预测地停下；首版停泊队列并展示继续入口。

## Consequences

增加一个有界输入实体与协调入口，不新增 Agent Tool、Worker、WorkManager 自动执行或常驻服务。复杂度集中在并发事务、现有终局/Goal 调度和进程恢复；UI 不需要理解 Goal run 内部形态。排队不会让 Android 获得无限后台存活资格。

## Verification

[HXA-214](../../development/tasks/HXA-214.md) 与 [HXA-216](../../development/tasks/HXA-216.md) 定义实现、切片与验收。必须覆盖 Turn 结束竞争、审批等待、批次配对、FIFO、撤回消费竞争、容量失败、稳定身份取消、Goal 续跑优先级和真实主进程死亡，loopback 核对实际请求；仅有队列 UI 或 Room 重开不算完成。当前无新增功能验收。

## Reconsider when

确有需求将默认改为 Steer、增加偏好、跨会话调度、定时发送或 Provider 原生流中注入时，以独立证据评审；不扩展本决定。
