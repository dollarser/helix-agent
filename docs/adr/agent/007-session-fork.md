# ADR-AGENT-007: 用户主动创建会话分支

Status: accepted
Date: 2026-09-22
HXA: HXA-213
Deciders: Project owner（2026-09-22 明确授权实现 fork 机制）

## Context

用户需要以相同历史探索不同工作，也需要绕过无法恢复的后续消息在新会话继续。重试 Turn 不能表达任意消息边界；删除原会话后半段会损失审计。分叉是应用能力，不是子 Agent 或新工作流。

## Decision

- consumer/developer 的已持久化消息提供“从这里新建分支”。建立新 session 与新 message IDs，保留原 session，不自动发出模型请求。不为未持久化的流式文本提供分叉。
- 在单个 Room 事务中读取截至指定消息的前缀并复制引用、附件绑定、来源记录及默认权限。源会话后续追加消息不进入该快照。事务失败/取消不得留下半个可见分支。
- 工具调用与结果必须完整配对。边界落在未完整批次时退到该批之前；前缀已有损坏协议则明确拒绝，用户可以选更早完整消息。分叉不执行或补造工具结果，不把未知副作用当作未发生。
- 仅可复用分叉点之前已发布的最新压缩检查点，重映射覆盖序号和保留消息 IDs。后续摘要不得泄漏未来上下文。原始历史仍复制为引用，正文不重复写入。
- 继承历史的 `turnId` 为 null，不复制 Turn、ModelCall、ToolCall 执行实体、Goal/run、Job、审批、权限 proof 或用量账本，不伪造新的成功执行。原工具 wire IDs 只用于历史协议配对。
- 使用已有 messages 表的 `SYSTEM / SESSION_FORK` 元数据记录保存版本 1、来源 session、请求与实际边界 message IDs、源/新消息 ID 映射。该记录不进入模型上下文和聊天正文；来源操作另有有界审计事件。无需 Room schema 迁移。
- 复制现有 ContentRef；为绑定附件创建归属新会话的 Artifact 元数据引用，保留路径/hash 与绑定时 hash，不复制文件、不回滚外部操作。删除原会话不能级联删除分支附件绑定，现有全局引用计数保护仍被引用的正文/文件。后续附件物化仍经过原有 hash/可用性验证；共享文件发生变化仍会明确失败。会话级工作目录不自动继承，用户可在新会话设置。
- Provider/模型选择延续来源；系统提示、工具目录与能力状态按新请求时的当前配置生成，因此承诺相同历史上下文，不承诺字节完全相同的历史 wire request。新会话授权按 ADR-PERMISSIONS-001 使用用户选定的新会话默认值。
- 元数据按 256 条分页，本次前缀最多 8192 行；需验证的活跃正文累计最多 8 MiB。超过范围明确失败并保留来源，不静默截断或自动用模型重写。检查点已覆盖的大正文只复制引用。
- 来源分支的来源链通过稳定 session/message IDs 保留。继承历史仍可沿现有压缩机制压缩，不能因没有本地 Turn 身份而永远不可压缩。

## Alternatives considered

- 删除后半段实现回滚：破坏来源审计且不能撤销真实副作用，不采用。
- 复制执行实体和审批：会把历史资料冒充成新执行，污染恢复与用量，不采用。
- 持久分支树加动态父链查询：每次组装依赖祖先状态，增加恢复及删除边界；首版选择原子引用快照。
- 自动摘要救援：需要模型可用和额外语义取舍；本次只提供确定性完整前缀，不悄悄改写历史。

## Consequences

分叉不需要网络、Runtime 或新增 Agent Tool，适合端侧。元数据复制有成本，但正文和附件不重复分配。分支保留聊天与协议历史，原执行详情仍属于原会话；这不是工作目录隔离、完整备份或外部效果回滚。

## Verification

HXA-213 验证完整前缀、无未来摘要、工具批边界、损坏后缀救援、附件引用、权限默认值、取消原子性、数据库重开、嵌套分叉及后续压缩；页面点击后通过 loopback Provider 检查实际请求。执行完整主机门禁及 API29/36 × consumer/developer 独占设备矩阵。accepted 不代表验收已通过。

## Reconsider when

需要自动摘要救援、可编辑历史、分支树可视化、独立文件快照或超出当前端侧上限的归档迁移时，单独明确数据与体验边界。
