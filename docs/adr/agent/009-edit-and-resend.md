# ADR-AGENT-009: 最新用户消息在会话内修订重发

Status: accepted
Date: 2026-09-22
HXA: HXA-215
Deciders: Project owner（明确授权最新已发送消息在原会话修订；更早消息以后按修改位置 fork）

## Context

用户经常只需修正最后一条输入。每次编辑都新建独立会话会增加管理负担。已有213支持显式fork，214提供提交回执和按会话持久草稿；会话内修订应复用这些基础，但不能覆盖执行证据或将错误输入留在后续模型上下文中。

## Decision

本期仅支持当前有效历史中最后一条 USER 消息的“编辑并重发”，新 Turn 和替代 USER 仍属于同一个 sessionId。该 USER 后可以已有回答、工具结果或压缩摘要；这些内容属于被替代的后缀。更早 USER 的编辑以后从其之前创建新会话，本期不新增历史编辑入口；既有显式 inclusive fork 行为保留。

编辑为独立的修订意图，携带稳定 clientRequestId、目标 messageId、revision、文本和原附件身份，沿214草稿持久化和回执。取消编辑、取消出网确认、准入失败都不改变有效历史。发送重新经过现有 Provider、附件快照、出网和 Turn 准入，不复制原授权，也不自动再激活原 Goal。

新 Turn 接收事务中重新检查目标仍是最后一条有效 USER、会话所有旧 Turn 已终结；将目标及后续当前有效消息标记为 supersededBy=本次请求ID，并原子写入替代 USER、附件绑定、新 Turn、ModelCall 和幂等回执。正文及旧执行账本不删除、不覆写。任何落库失败整体回滚；同一请求重驱只返回已有 Turn，不再次截断或发送。修订目标参与输入指纹，不能换目标复用请求ID。

普通对话、模型上下文、最新压缩检查点和搜索只读取有效消息。旧后缀的摘要及工具协议不再参与构造，新摘要由正常压缩准入产生。旧 Turn 的迟到消息同样继承 supersededBy，不把旧结果重新混入有效历史。JSONL 导出仍保留所有版本和真实执行结果，消息增加可选 supersededBy 字段以解释有效性；原始 ID、内容引用、用量及终止原因保留。

修订保持会话身份、目录、用户选定的配置和权限。运行时可以准备编辑稿，但重发须先由用户明确停止并等真实结算；不因编辑自动取消普通 Turn 或 Goal，不重放未知结果。原来发生的文件、网络、独立 Job/PTY 副作用不撤销。工具/恢复记录继续可从 Tasks 和导出追溯。

附件保留原绑定，发送重新校验并确认，不静默丢弃。旧消息将用户前缀与附件块合存时只识别唯一的生成块边界；无法确定、文件缺失或快照不一致时保留原历史并明确拒绝。第一期支持修改文本并保留原附件；附件替换/增删与更早消息编辑另行交付。

## Alternatives considered

- 所有历史编辑都新建会话：原提案复用fork简单，但最新消息纠错会制造多余会话；本次按所有者要求调整。
- 原地UPDATE正文并删除后缀：破坏回答、工具副作用及审计关联，不采用。
- 修改正文但保留后续摘要：错误输入仍会污染模型，不采用。
- 完整分支DAG、文件快照和版本切换面板：当前只需线性最新修订与有效性标记，不引入。

## Consequences

Room新增消息有效性与修订草稿目标字段，保留旧版本引用直到用户删除会话。当前页面显示有效修订版本，导出保留所有版本；不承诺文件回滚、零成本重生成或请求字节复刻。HXA-215 本期验收以最新修订为准，更早历史编辑及版本切换不得冒充已实现。

## Verification

[HXA-215](../../completion-records/HXA-215.md) 覆盖最新边界、旧后缀/摘要排除、原子回滚、重复提交、并发追加、附件确认取消、普通应用进程死亡及实际Provider请求。accepted表示本次设计授权，结果以任务证据为准。

## Reconsider when

需要编辑更早消息时实现exclusive fork；需要原会话版本浏览/切换时另行限定恢复与并发边界。不将新需求扩展为端侧通用版本控制系统。
