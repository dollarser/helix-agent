# ADR-AGENT-009: 编辑用户消息并在新分支重发

Status: proposed
Date: 2026-09-22
HXA: HXA-215
Deciders: Project owner（授权本轮需求设计；未声明功能交付）

## Context

用户可能发送错误内容，需要基于修改后的上下文继续。现有 retry 不保证回到历史时点，HXA-213 的 fork 是包含目标消息的前缀快照。直接修改旧 USER 会使后续回答、摘要、工具副作用与审计失去对应关系。

## Decision

已持久化 USER 消息提供“编辑并重发”。先把原文与附件加载为独立编辑草稿，允许取消；确认后从目标 USER **之前**的完整历史创建新会话，再追加修改后的 USER，使用正常发送入口。原会话、原消息、原执行记录不变。界面明确新分支身份，不伪装成原地覆盖。

基于 [ADR-AGENT-007](007-session-fork.md) 扩展 exclusive boundary；原有“从这里新建分支”的 inclusive 行为保留。支持第一条 USER 的空前缀和继承消息；不能用 inclusive fork 加一条修正来冒充替换。目标消息、对应回答、后续工具结果和覆盖它们的摘要均不得进入新上下文。

只使用目标之前合法检查点。若错误消息已被后来的摘要覆盖，退回此前检查点及原始前缀，按现有资源上限/压缩准入处理；不删改摘要里的词句假装去除了影响。完整工具批边界、损坏协议、8192 行/8 MiB 物化上限和附件 hash 规则沿用 fork。资源不足明确保留编辑稿，不静默截断。

以稳定 editRequestId 绑定 sourceSessionId、sourceMessageId、编辑 revision 与输入指纹；一次编辑提交只创建一个分支。分支、来源映射及可恢复的待发送输入原子持久化；Provider 请求在事务外。提交后遇到出网确认、Provider 错误、取消或进程死亡，保留已创建分支/草稿并展示真实状态；重试同一意图复用分支而非再建一个。不同内容复用同一 ID 返回冲突。

未消费队列项直接按 revision 编辑/撤回，不创建分支；已持久成历史后才用本功能。已消费且进入在途请求的 USER 不可原地替换。新会话配置、默认权限、内容引用、附件所有权和目录处理沿用 fork，不复制 Goal 激活、Job、用量或审批。

源任务运行时允许编辑已持久化 USER，读取快照只到选定边界。源任务独立继续，并明确显示这一点；不隐式停止来源，也不回滚其文件或外部副作用。用户需要停止时使用统一停止入口。新分支不继承活动 Goal 身份，首次重发为显式用户请求，不自动再创建原 Goal。

## Alternatives considered

- 原地 UPDATE USER 并删除后续：损失历史及真实副作用关联，不采用。
- 修改正文但保留后续摘要：仍携带错误信息，不采用。
- 调用 retry：重试语义与历史前缀不同，不采用。
- 引入分支 DAG 和文件快照：本需求可通过有界引用快照满足，不增加端侧维护成本。

## Consequences

复用已有 fork，新增编辑草稿与幂等映射。用户会得到新会话，不承诺文件隔离或历史请求字节复刻。新旧会话可引用同一文件，删除源会话不得误删新分支附件。

## Verification

[HXA-215](../../development/tasks/HXA-215.md) 覆盖首条/中间/继承 USER、压缩前后边界、无未来信息、附件、源会话删除、源任务继续、取消、错误和真实进程死亡。loopback 请求中必须排除旧文本和未来摘要。当前仅设计，无新增验收。

## Reconsider when

需要原会话内分支切换、历史修订展示或文件版本恢复时另行设计，不借本任务加入不可逆历史删除。
