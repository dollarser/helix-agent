# ADR-PERMISSIONS-001: 会话授权预设、自定义权限与工具禁用

Status: accepted
Date: 2026-09-16
HXA: HXA-020, HXA-028, HXA-033, HXA-066, HXA-093, HXA-094, HXA-209
Deciders: Project owner（当前有效决定；授权按需求合并重编，不新增功能接受范围）

## Context

会话需要完全免确认、工作目录与联网、只读与联网及自定义四种授权选项。工具可用性与操作授权分开，统一 resolver 负责判定。

## Decision

### 1. 三个会话预设与一个自定义模式

| 预设 | 自动执行的范围 | 仍需审批 |
| --- | --- | --- |
| 完全免确认 FULL_ACCESS | App 当前已具备且产品已实现的全部操作和可访问文件范围，包括联网、工作目录外操作、命令及设备操作 | 命中 rm -rf dir 命令规则 |
| 工作目录与联网 WORKSPACE | 当前用户绑定工作目录内的文件读取、新建、覆盖、编辑、移动、删除；联网；能证明本地副作用不越出工作目录的操作 | 工作目录外文件访问、其他设备或系统操作、不能确定副作用范围的命令；命中 rm -rf dir 命令规则 |
| 只读与联网 READ_ONLY | 当前有效读取范围内的本地只读操作；联网查询、浏览与读取 | 本地文件修改、远端业务写操作、命令或设备修改等其余操作；命中 rm -rf dir 命令规则 |
| 自定义 CUSTOM | 用户为操作类别与范围明确选择“允许”的操作 | “询问”的操作需审批；“禁止”的操作直接拒绝，不出审批卡 |

只读预设同样放开联网，不因建立连接、访问新 origin、发送查询参数或读取网络响应而单独审批；访问本地数据仍受有效读取范围限制。只读描述的是操作效果，不是 HTTP 方法：远端发帖、修改或删除等业务写操作仍需审批，不能因为走网络就变成只读。下载到响应缓冲或受控临时缓存可免确认，保存或覆盖用户文件仍属本地写入。封闭的必要运行元数据结算不作为用户文件写入，但不能借 METADATA 扩大业务副作用。

完全免确认不是仅 L2 豁免。风险等级继续用于展示、审计及异常分析，不能仅因 L3 或敏感出网而再次询问或默认拒绝已被该会话模式授权的操作。工作目录预设的联网同样免确认，包括用户任务所需的上传、下载及远端写操作；本地文件来源仍须满足工作目录范围或已有精确授权。网络许可不授予读取其他本地文件的权限。

### 1.1 工具可用性只有启用与禁用

工具层只存储 ENABLED/DISABLED，不保留 ALLOW/ASK/DENY，也不保存“禁用前的 ASK”。启用仅表示工具可参与会话，是否询问完全由当前预设或 CUSTOM 操作规则决定。可复用可信工具身份、scope、持久化、曝光过滤和执行复检；旧三态模型若不适合则直接替换，不能保留两套有效授权源。

- 会话“可用工具”入口默认修改当前会话；如提供全局/Workspace 禁用，其适用范围内仍优先禁用并显示来源，会话启用不能暗中覆盖外层禁用。
- 禁用工具从模型 schema、tools.search 结果和会话曝光窗口移除，别名绑定同一可信身份。历史上下文无法撤回，执行入口仍拒绝直接构造的旧调用。
- 禁用不卸载能力，不影响其他会话或人工操作。重新启用后重新加入符合能力条件的曝光集合，按当前模式判定，不恢复旧 ASK/ALLOW。
- 排队、pending 且尚未开始的调用在禁用后拒绝并持久结算；迟到审批或旧 proof 不覆盖禁用。已开始任务独立停止，不伪称回滚。
- 单次审批卡“拒绝”不改变工具启用状态。禁用 write 只涵盖其可信身份与别名，不等于禁止 edit/Shell 写入；后者由操作权限约束。

### 1.2 自定义权限：允许产生哪些效果

CUSTOM 使用封闭、版本化的数据配置，不提供可执行策略 DSL。用户从任一预设复制出配置，再对操作类别选择 ALLOW/ASK/DENY（界面为允许/询问/禁止）；复制生成固定配置，不动态继承以后变动的预设。未定义的新类别默认 ASK；无法排除触犯既有 DENY 时直接拒绝。

| 操作类别 | 范围与说明 |
| --- | --- |
| 文件读取 | 工作目录内 / 工作目录外；只在 App 实际有权限且产品支持的范围内 |
| 文件修改 | 工作目录内 / 工作目录外；新建、覆盖、编辑、追加、移动、重命名、删除、修改权限或链接均包含在内，不能仅匹配 write 工具名 |
| Agent 工具联网 | 工具触发的查询、浏览、上传/下载及 Shell/脚本/MCP/A2A/浏览器网络操作；不自动授予本地文件读取、保存或远端业务写权限 |
| 远端业务修改 | 发帖、提交、创建、修改、删除等服务端业务副作用；需要同时满足联网权限 |
| 设备与系统修改 | 已实现的设备、设置、应用交互等修改；依旧需要实际系统能力 |
| 命令与代码执行 | Shell/PRoot/脚本的执行准入；允许执行不覆盖上述读、写、网络、设备效果限制 |

文件删除属于文件修改。只有第 3 节的 rm -rf dir 命令规则额外要求精确审批；文件修改 DENY 时直接拒绝，CUSTOM 也不能把命中该规则的调用设为免确认。其他删除方式按实际文件修改规则判定，不额外套用“递归删除必询问”。

例如从“只读与联网”复制，设“文件修改（目录内/外）=禁止，联网访问=允许，命令执行=允许”：文件阅读和联网查询可执行；write、edit、Shell 重定向、tee、sed -i、Python 文件写入、删除、解压覆盖等均不得修改用户文件。Shell 只有在可信执行约束能保证禁止项，或平台能完整判定该调用不触犯禁止项时才可运行。用户批准一条命令不能绕过 DENY，必须先由用户修改权限配置。

“文件修改”不禁止宿主必要的 Room、审计和受控临时缓冲写入；这类例外不可被模型指定成任意路径、不可写回用户文件，不能成为脚本自由写入主应用私有数据的接口。

多效果调用先合并全部效果：任一 DENY 则整条调用拒绝；无 DENY 但存在 ASK 则为整条调用进行一次精确审批；全部 ALLOW 才免确认。复制同时检查源读取与目标修改，移动还检查源修改；上传检查源读取与网络，下载保存检查网络与目标修改。不得先执行允许部分再检查剩余效果是否被禁止；执行失败仍如实结算已发生的副作用。

工具曝光是静态辅助，不替代参数级判定。确定所有用途均被禁止的专用工具可隐藏；同时提供读写能力的工具可保留可用用途，但必须在实际调用时判定效果。MCP readOnlyHint、工具名和模型描述不能证明没有写入；远端实现无法约束且无法确定效果时，适用禁止写入的调用不放行。

“禁止联网”仅针对 Agent 工具及其委托的网络操作，不禁止模型 Provider 推理/流式请求、必要认证或用户手动发起的设置操作。工具不能把请求伪装成 Provider 流量来绕过限制；远端 MCP/A2A 工具调用本身也属于工具联网。禁止工具联网不代表“离线运行”，模型上下文仍可发送给用户选定的 Provider，界面必须明确这一点。

远端业务修改按可信适配器契约分类，不能仅依据 GET/POST。CUSTOM 禁止远端修改而通用网络请求效果不明时直接拒绝；需要 ASK 时说明未能确定的效果。前三个预设已授权的普通联网不因新 origin 或重复风险提示再次出卡。

### 2. 授权、禁止与能力的优先级

统一决策顺序：

1. 检查工具合法性、实际系统能力、可用执行域、数据完整性、运行预算及停止状态。缺失 Android 权限或未安装/未提供的能力不能由审批模式制造。
2. 命中工具禁用或 CUSTOM 操作 DENY 时拒绝，不弹卡、不消费旧 proof；选择模式的界面清楚展示仍生效的禁止项。用户需自行修改设置，不能用单次批准覆盖 DENY。
3. 命中第 3 节 rm -rf dir 规则时至少要求精确一次性审批，模式不得豁免；已披露的精确批量审批可以满足该调用。
4. 三个预设和 CUSTOM 编译为同一种操作权限配置，共用一个 resolver，不建立四条 Dispatcher 分支。全部效果依第 1.2 节合并：任一 DENY 则拒绝；否则任一 ASK 则询问；全部 ALLOW 才免确认。工具层没有 ASK/ALLOW 参与优先级。
5. 其余合法且可执行的操作进入精确审批，批准后执行。范围外不等于永久禁止，单次批准不扩大后续模式范围。

必须区分不可执行事实与历史产品默认限制：L3 默认拒绝、高敏出网逐次询问、应用自设 scope 不能被重新包装成硬禁止，从而使 FULL_ACCESS 名不副实。FULL_ACCESS 授权范围可覆盖 App 实际可访问的用户数据，但不代表向模型泄露应用自身的认证凭据、关闭 TLS 校验、取消 schema/审计或允许未知副作用自动重放。认证材料仍由专用客户端使用，不能作为普通工具结果或上传内容。模式不会自行启用尚未实现的支付、远程 Worker 等产品功能。

既有 Chat/Plan 的工具与只读执行边界不因审批预设放开；Act/Goal 使用所选预设。

三个预设及自定义模式属于主产品会话设置，consumer/developer 均可提供，不再绑定 ADVANCED 专属入口。各变体只展示和执行实际具备的能力；本决定不把 PRoot/Subscriptions 加入 consumer，也不自动启用系统权限或 Runtime。需要同步处理与既有 Profile 门禁的交互，不能因旧 Profile 风险默认值再次拦截已授权的现有能力。

### 3. 目录与命令必须依据实际副作用

Workspace 绑定使用稳定 ID、规范根及版本；路径包含性必须处理符号链接、重命名、SAF URI、跨根移动和执行前变化。没有有效工作目录时不能以全盘替代。工作目录修改后旧排队调用重新判定，不继承旧根授权。

删除专项暂定为**命令规则**，只拦截提交给 Agent Shell 执行入口的显式 `rm -rf dir`，拦截结果为精确审批而不是永久拒绝。以解析后的命令名 `rm`、参数 `-rf` 与非空目标操作数匹配，不把 echo/注释/字符串中出现的文本误判成执行；目标不确定是否为目录时也询问。复合命令中可明确解析的该子命令同样检查。路径引号、空白和多个目标须测试；无法解析的其他命令按所选模式的常规未知效果规则处理，不能借此把 FULL_ACCESS 变成所有命令都询问。

本轮不要求递归检查脚本内容、识别变量展开、别名、选项变体、包装器、逐文件循环、其他语言或原生工具的等价删除。它是有限命令提醒规则，不是目录树防删除沙箱，不承诺防止目录内容丢失。将来扩大匹配集合需明确修改契约，不能由实现者自行添加门禁。

这一范围缩减只适用于删除专项。CUSTOM 的“禁止文件修改”仍是跨工具效果限制：脚本或其他删除方式仍属于修改，不因没有匹配 rm 规则而放行。工作目录内外约束同样保留。执行域可行性验证先于 UI；不能以正则或 cwd 当作可靠的文件写入隔离。

自定义 DENY 不能降级为 ASK。执行域不支持可靠限制时拒绝潜在违规调用，并给出“当前执行环境无法保证所选限制”的具体原因。并发调度的效果 footprint 只可复用平台分类，不自动构成操作系统隔离证据；PRoot 的 cwd 或同 UID 私有进程不提供只读保证。

### 4. 生命周期与切换

只有用户 UI 动作可选择模式；模型、网页、MCP、Skill、脚本不得修改模式、根目录绑定或自身审批规则。模式可作为只读运行上下文告知模型。

安装初始默认 READ_ONLY，用户可设置“新会话默认模式”（CUSTOM 使用配置快照）。默认变更只影响以后新建会话，不修改现有会话。复制、分叉、导入会话不继承来源会话的授权，使用当前用户选定的新会话默认；明确由用户设定 FULL_ACCESS 默认时无需每次再询问。

授权结构转换采用单一新模型，不维护兼容审批模式。转换默认 READ_ONLY，只保留仍有效的工具禁用意图；结果可见。保留用户文件、会话历史、凭据与审计，数据库转换可恢复并有验证。

CUSTOM 保存版本、来源预设及各范围规则；切换到预设后自定义草案不生效，重新选择 CUSTOM 才恢复。工具启用状态独立于模式，切换模式不重新启用工具。持久化的是设置，不是可复用的逐调用 proof。

进程重启恢复设置不恢复 Goal 激活，继续遵守 [ADR-GOAL-001](../goal/001-lifecycle-and-completion.md) 的用户显式恢复、不重放未知副作用。切换会话不修改其他会话设置。

模式切换默认影响后续与排队未开始调用，不自动取消已展示审批卡。提供“切换并继续当前操作”动作：重新验证该待执行调用，以当前模式作新决定，保持原调用身份并结算旧等待；命中 rm -rf dir 规则仍须精确批准。晚到旧卡决定不得重复执行。已开始调用不回滚；用户停止仍可取消执行。

模式与自定义规则版本、Workspace 绑定、工具可用性与执行开始需要共享明确的线性化契约。降级后尚未开始的调用重新解析并按需询问；已有有效精确 proof 在未命中新的禁止项时可继续使用，不制造第二次相同审批。等待审批不得持有模式写入锁。设置收紧后 UI 显示“后续操作已生效；仍有 N 个此前启动任务”，提供精确停止入口。后台进程及延迟 Job 必须归属会话与任务，尚未实际开始的 Job 重新判定；不声称新设置能撤销运行中任务已经发生的副作用。

### 5. 审计与交互

持久记录会话模式、版本、用户变更时间及绑定；切换产生独立审计事件。逐调用记录实际模式版本、授权来源、规范目标与审批原因，自动授权不得伪装为用户点击 APPROVED。保留取消、失败、未知副作用及恢复结算。

审批原因采用结构化集合，不匹配描述字符串。范围、风险、工具网络、操作 ASK、rm 命令规则与硬拒绝分别表达，以同一 resolver 在展示和执行开始时判定。

会话持续显示“完全免确认”“工作目录与联网”“只读与联网”或“自定义”；自定义旁显示实际权限摘要。首次扩大授权说明具体可执行范围、rm 命令确认例外和被禁用的工具；不以每轮警告抵消免确认。四种模式均有直接切换及停止入口；“可用工具”独立显示，不将工具禁用混入权限级别。UI 经服务操作，不直接写 DAO。

## Alternatives considered

- 仅豁免 L2，保留所有联网询问：不能满足所有者明确的三级联网要求，拒绝。
- 不询问时一律拒绝：适合 CI 的 DSH never/dontAsk，不是此处免确认语义，可将来独立增加。
- 关闭所有 Policy 与审计：不必要；显式模式是授权来源，工具仍经统一执行管线。
- 用命令匹配保证工作目录/禁止写入边界：不能成立；rm -rf dir 匹配只承担有限删除提醒，不作为其他效果约束的证据。
- 保留旧工具 ASK 与兼容模式：所有者明确不要求兼容，拒绝双轨授权；直接按新契约重构。
- 自动分类器决定放行：不是三个预设与自定义规则的必要条件，本次不引入。

## Consequences

前两级可支持长任务的连续文件与网络操作。完全免确认是实质授权扩大，会持久保存会话选择，不能再宣称“不新增授权面”。代价包括 Policy 原因分类、执行域边界、并发切换、迁移和恢复测试；尤其禁止写入和工作目录约束的执行域可行性是实施依赖，不能当作纯 UI 开关交付。

产品模式不改变 Android 自身权限或进程存活限制。决定已接受，代码与架构规范仍需 HXA-209 同步迁移；不得把旧实现的全绿证据用作新模式验收。

- 同一操作分别得到免卡、精确卡、明确禁止；工具禁用与 CUSTOM DENY 优先，精确 proof 不覆盖新禁止项。
- 禁用工具在请求 schema、tools.search、曝光窗口和别名调用中一致生效；跨会话不串扰，继承禁用不能被本会话启用覆盖，重新启用仅改变可用性，不恢复 ASK/ALLOW。
- 自定义禁止文件修改覆盖 write/edit、重定向、tee、sed -i、脚本、删除、复制/移动、解压、下载保存与插件路径；允许读取和联网仍可用。未知效果且可能违反 DENY 的调用直接拒绝，不出卡；同时验证提示注入不能修改配置。
- 目录逃逸、符号链接、跨根移动、根切换与未知范围测试；rm 命令规则按第 3 节有限集合验收，不要求拦截所有等价删除。
- 禁止工具联网时 HTTP/Shell/MCP/A2A 等工具请求被阻止，模型 Provider 仍可用；混用入口不得绕过限制。
- 自定义禁止写入时既验证没有写入，也验证可用的只读命令与联网任务，不以一律拒绝代替产品可用性。
- 模式降级与执行开始竞态、排队复查、等待卡切换、旧决定迟到、停止、同会话连续 Goal 与跨会话隔离。
- 新配置持久化、旧授权结构清理与数据保留、新会话默认值、真实进程重启、设置恢复但 Goal 未激活、未知副作用不重放。
- API29/36 × consumer/developer 设备证据；缺失权限不放行、已有权限不重复申请、变体能力保持真实。
- 项目现有三语言资源与窄屏/大字体界面；模式、范围与 DENY 可见，审计能追溯实际执行授权。
- 同步架构、安全、产品、AGENTS 与 HXA 任务文档；执行任务规定的主机及设备门禁。未解决执行域限制必须列为阻塞，不能写整体完成。

## Reconsider when

需要扩大 rm 命令规则为通用目录树删除保护，或用户需要新的网络/目录预设时，另行明确产品取舍与执行域保证。需要定时/Channel 自动激活时另行更新 Goal 唤醒契约。
