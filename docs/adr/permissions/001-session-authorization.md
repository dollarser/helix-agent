# ADR-PERMISSIONS-001: 会话授权预设、自定义权限与工具禁用

Status: accepted
Date: 2026-09-16; revised 2026-10-04
HXA: HXA-020, HXA-028, HXA-033, HXA-066, HXA-093, HXA-094, HXA-209, HXA-228, HXA-239
Deciders: Project owner（当前有效决定；授权按需求合并重编，不新增功能接受范围）

## Context

HXA-228 重新校正会话权限名称与实际 ALLOW/ASK/DENY 语义。旧 `READ_ONLY` 实际允许用户逐次批准写入，与“只读”名称冲突；旧 `WORKSPACE` 又自动放行远端业务写，与“只信任工作区”心智不一致。项目尚未发布，因此直接采用 clean-slate v2，不保留旧枚举名、旧字符串解析或迁移别名。工具可用性与操作授权继续分开，统一 resolver 负责判定。

## Decision history — 2026-10-03：Mobile Use 显式全机许可

HXA-243 按所有者要求将无障碍操作限制收敛为真实工具授权、用户选择的设备范围、Android 系统权限、资源与效果真实性。用户可开启当前全手机许可或指定应用；不根据动作文本/应用类别额外硬拒绝。默认直到停止且不限动作数，用户可设置额度；模型不能生成或扩大许可。完整到期时间和 grantId 纳入 Scope 匹配，旧许可不跨会话复用。熄屏/锁屏、撤销/停止、服务断开仍撤销执行资格，原操作可能产生的效果不因此被认为回滚。

截图及多指手势由既有 Dispatcher 执行，观察事实由模型处理，不增加自动规划、隐式重试和任务验收器。截图复用会话/Turn 产物及视觉来源/披露；坐标和语义入口服从同一用户范围。平台保护、只读 DENY 和工具禁用不能借全机模式绕过。详细实现边界见[Android 平台能力](../../architecture/android-platform-capabilities.md#5-accessibility-自动化)，实际验收见 HXA-243。

## Decision history — 2026-10-03：应用选择与端侧图片边界

所有者要求以应用选择替代包名输入：Advanced 本地选择器列举 Android 当前可见的用户/系统应用，包括没有启动入口的组件；应用列表不属于模型授权来源。选择、取消和刷新不扩大活动范围，开始时仅绑定明确勾选的包；全手机仍需显式选择。较长包集合的审计引用采用规范化全值的摘要，实际授权与完整 Codec 不截断集合。

图片前置确认是网络目标绑定，而非相册许可：真实 OnDeviceLocal 不需要网络确认；Network 即使为局域网/loopback 也不因此视为端侧。工具授权、图片来源/哈希/会话和最终目标检查仍执行；Mobile Use 的重复确认按下面的追加决定收敛，普通附件与其他工具图片规则不扩权。

## Decision history — 2026-10-03：Mobile Use 屏幕共享初稿（后由 HXA-244 调整）

所有者要求尽可能减少重复授权。Mobile Use 的“开始并授权”在显示当前聊天会话接收模型与目标服务后，一并允许本次设备许可范围内后续原生截图交给该模型，不逐张弹窗。未选模型不阻止开始手机操作；首次交给网络模型或实际接收模型/Provider/连接/路由头/聊天会话改变时，复用原数据披露弹窗确认一次该 Mobile Use 范围。相同范围的并发请求共用一张卡；拒绝后不随新截图反复询问。

共享状态跟随真实进程内 AutomationSessionScope、grantId、完整范围与到期时间，不使用单张图片回执的十分钟作为屏幕共享有效期。停止、锁屏、服务撤销、过期、进程结束或新许可替换后失效；迟到确认不复活旧许可。采集时的范围身份通过可信发布接口绑定到规范化图片，不能用当前新许可冒领旧截图，也不能根据工具 JSON、文件名或模型参数生成授权。最终图像字节读取继续复核归属、活动 Turn、哈希、接收方和 live grant。尚未发送的像素可停止交付，已外发数据不声称撤回。

端侧视觉模型不弹网络外发确认，但 Mobile Use 来源和有效许可仍校验；普通图片文件/浏览器图像不借此共享许可免除原确认。工具启用状态、READ_ONLY/CUSTOM DENY 和其他会话授权规则不变；FULL_ACCESS 内不另设 Mobile Use 逐动作审批，APPROVAL_REQUIRED 仍按用户选择审批工具操作。

## Decision history — 2026-10-03：HXA-244 Conversation 持久授权

所有者进一步明确：Mobile Use 是 Conversation 配置，不是全局或进程内短期许可。用户在本会话选择应用/全手机并保存后，观察、操作和后续截图共享持续有效，直到显式关闭或修改范围。配置同步持久化；锁屏、系统服务断开/被撤销、应用/设备重启、调用失败及计数不清除配置，只暂停物理执行。用户重新开启 Android 服务或恢复设备条件后，下一个原会话工具调用可从配置重建运行态，不重放旧动作或恢复旧节点/frame。

开启界面明确告知：截图可供本会话当前及以后用户选择的模型处理，显示当前接收 Provider/模型和网络 origin；真实本地模型在本机处理。截图、换 Turn、用户切换模型/Provider 均不再次弹 Mobile Use 图片确认。每次请求仍产生实际内容和接收方绑定的 proof，字节读取检查其一致性；此 proof 是实现校验而非新的用户审批。普通附件、浏览器图片等不得借用原生截图共享权限。

持久配置按 Conversation ID 隔离，Dispatcher 将原会话及批准的 Scope 身份传入每个 executor；旧审批不能匹配范围修改，B 不借用 A 的配置。范围改变生成新 grant 身份；原生截图来源持久记录采集 Scope、会话、Turn、哈希和媒体类型，不给旧截图重新贴新范围标签。配置与来源可恢复，但不跨 Conversation 恢复或复制。通知停止仅取消其绑定的运行任务，不修改插件选择；旧通知不能影响后来运行的另一会话或同会话新 Turn。关闭保存失败须显示错误，当前进程不继续使用该未确认配置，不把失败伪装为已持久撤销。

无额外产品 TTL、动作数或逐图卡；现有会话工具模式仍有效。FULL_ACCESS 不增加 Mobile Use 逐动作确认，APPROVAL_REQUIRED 和明确 DENY 不绕过。Android 系统权限、受保护窗口、实际不可重入资源和结果真实性是执行边界，不是擅自撤销用户意图的理由。既有 HXA-243 临时许可/接收方确认初稿不再作为生产授权合同。

## Decision history — 2026-10-04：Mobile Use 按功能开放

所有者进一步明确：不要求权限全部开启，只要部分功能可用就允许开启。开启条件按具体操作判断；Root/Shizuku、通知和普通悬浮窗权限不作为统一门槛。应用查询 `ui.apps` 通过应用 Context 的 PackageManager 执行，不依赖无障碍；只返回原会话授权范围内、Android 可见的可启动应用。

点击“保存并开启”保存明确选择的会话范围，无障碍未连接时显示“已开启 · 仅应用查询”，主动提示系统设置入口，但不强制跳离页面。语义节点、应用启动和系统动作仍要求无障碍服务连接；Root/Shizuku 的精确点击及屏幕工具可独立运行，见下述决定。系统版本、受保护窗口等进一步限制仍由具体操作检查。

插件按工具判断可用派发范围。应用查询在读取前后检查原会话、精确 scopeRef、取消与截止时间，撤销或变更授权后不返回结果。服务断开停止依赖该服务的操作，保留其他可用后端、查询能力与配置；恢复服务不重放动作。无任何可用操作时不得报告开启。

实现和验证见[开启门槛修复](../../bug-fixes/2026-10-04-mobile-use-enablement.md)，设备未请求。

## Decision history — 2026-10-04：高权限精确点击独立于无障碍服务

所有者要求继续解除 Root/Shizuku 点击对 Helix 无障碍服务的依赖。保持现有封闭 `ui.click_match` 协议：精确 packageName、viewId、text 三字段才可使用高权限后端，该精确点击工具不接受任意 shell 或坐标；截图和手势使用下述独立屏幕工具协议。

无障碍未连接时，高权限进程负责读取并复查精确目标、活动应用、旋转、窗口及覆盖点击位置的其他窗口。宿主逐次复查原会话持久 scopeRef、应用范围、取消、截止时间和锁屏。无障碍可用时保留原有观察及呈现路径；所有输入路径共享物理占用票据，不在服务重连时创建新的独立输入槽。

自动选择仍为 Root → Shizuku → 无障碍，仅 READY 可参与；一次调用选择后失败或结果未知均不跨后端重放。工具 scope 和用户界面按实际操作能力开放，不将高权限连接视为所有屏幕功能可用。当前屏幕树观察依赖平台 UiAutomation，但不要求用户开启 Helix AccessibilityService；这不是绕过应用检测能力。

主机检查与安装边界见[独立点击记录](../../bug-fixes/2026-10-04-mobile-use-independent-click.md)。Android/OEM 运行时兼容性须以单独设备验证为准。

## Decision history — 2026-10-04：独立屏幕观察、截图与手势

所有者授权继续将 `ui.device`、`ui.screenshot`、`ui.gesture` 接入 Root/Shizuku 独立后端。复用原插件、Dispatcher、权限和审计，不增加 Agent 执行域。观察按 Root → Shizuku → Accessibility 选择已授权可用后端；高权限观察形成原会话、scopeRef、目标窗口、旋转、界面树版本及后端绑定的 frame。新观察使旧 frame 失效，手势消费 frame，失败/UNKNOWN 不跨后端重放。

宿主入口增加 `MOBILE_USE` 能力，表示原生插件已启用并发布工具。它不代表任何系统高权限已授予；应用查询、精确点击、三项屏幕工具及下述后续接入的语义节点工具通过此能力入口，再由操作适配器核查实际后端/范围。应用启动和系统动作仍保留 `ACCESSIBILITY_AUTOMATION`。consumer 解析 Mobile Use 为 unavailable；能力名称变化不降低 per-call Policy/Approval 或发布图片前的复核。

高权限整屏截图只用于全手机授权且无排除应用的范围，且须允许屏幕共享。单应用范围不通过整屏截图后裁剪冒充窗口隔离，而是在 API34+ 且无障碍已连接时使用既有窗口截图路径；否则明确报告该能力不可用。图片通过有大小上限的只读 SharedMemory 传输，不在 Binder 内复制大图片，不创建临时图片文件；映射和内存在失败/取消时关闭，仍走既有图像发布、范围来源记录与模型披露。

高权限手势支持默认显示、最多 10 指、每次总时长不超过 10 秒的有界轨迹。注入前复核 frame 的窗口、方向、界面树版本和覆盖窗口；执行中允许自身动作改变内容，但持续检查窗口身份、方向、遮挡、原授权、锁屏、取消及截止时间。取消/失败后尝试发送 ACTION_CANCEL，保留未知结果语义，执行器退出前不释放共享物理占用。UiAutomation 和平台反射仅在 shell/root 服务中运行；不能进入主应用进程。

这不承诺检测纯像素动画或画布变化，也不规避受保护画面。实际 Android/OEM、截图/多指触控与服务中断能力须由设备矩阵验证。实现、主机门禁与边界见[独立屏幕工具记录](../../bug-fixes/2026-10-04-mobile-use-privileged-screen.md)。

## Decision history — 2026-10-04：语义观察使用可用高权限后端

2026-10-05 动态页面回归追加：语义节点动作以原观察保存的节点指纹校验文字、描述、标识、层级、边界、可用性及操作状态，并继续绑定包、窗口、显示器、尺寸、方向和授权。远程重新采集后先校验该指纹，再通过原动作执行器重新获取节点、校验路径/指纹及遮挡；无关节点变化不再因为全树 revision 不同拒绝本目标。缺少指纹、目标属性改变、撤权、窗口改变仍拒绝；不重新匹配相似节点或跨后端重放。截图与坐标手势保留原完整 frame 校验；截图目标变化返回 TARGET_CHANGED，不隐藏成通用传输失败。

2026-10-05 追加：采集深度上限从 16 调整为 64，以覆盖深层布局中的文件名；节点数量和文字预算仍有界。快照和查找结果公开 DEPTH_LIMIT、NODE_LIMIT、TEXT_LIMIT、FIELD_LIMIT，区分采集不完整与工具结果分页。默认快照省略结构字段、空值和默认 false，保留可点击父节点标识、可见文字、位置及复选控件的明确 checked 状态；详细查找结果仍保留完整字段。截断时给出通用视觉观察路径，不推断遗漏内容、不自动执行动作或为安装添加状态机。没有工具调用的最终回复仍由模型决定结束，不能用措辞匹配擅自重启外部操作或冒称任务已完成。

所有者要求修复默认观察仍固定在普通无障碍的问题，并卸载抖音后使用当前模型自主安装。`ui.snapshot/find/wait` 默认按已就绪且支持该能力的 Root → Shizuku → Accessibility 选择；结果报告实际后端。`ui.click/long_click/set_text/ime_enter/set_progress/scroll` 使用当前观察绑定的后端，不能把高权限节点交给普通服务。自动 `click_match` 的通用筛选也走相同观察链，显式 accessibility 仍固定普通服务。

复用现有 shell/root 私有服务、封闭 Binder 协议、语义脱敏/动作校验与物理资源租约，不新增执行域。远程节点编号不直接暴露给模型；宿主签发临时节点标识，绑定原会话、批准范围、grant、目标窗口/方向/树版本和后端。新语义观察废弃旧标识，动作尝试消费标识；撤销、锁屏、取消、超时、窗口变化或后端丢失拒绝后续执行，UNKNOWN 不跨后端重放。模型仍决定任务流程，不提供安装专用状态机或静默安装接口。

高权限不授予新应用范围或读取受保护字段的权限。远程服务复用普通语义引擎的密码/敏感字段脱敏及动作约束，宿主在读取前后复核当前授权；IPC 传输有界结构化节点。节点动作重新获取根节点、核对树版本和遮挡，在实际动作前再次调用授权 guard。应用启动和全局返回/主页仍按已实现的无障碍能力开放，不将未实现操作冒称为高权限能力。

同一应用进程复用存活的私有 Binder 服务和 UiAutomation 连接，避免每次观察重建连接导致窗口身份变化及绑定超时；每次调用仍重新检查授权，连接复用不缓存授权结论。默认快照省略无标签且不可操作的布局容器，完整树仍用于筛选、可点击父节点解析和版本校验。视觉手势明确区分短按与长按，不擅自改写模型提交的时长或坐标。

## Decision history — 2026-10-04：Mobile Use 接入 Shizuku（首版）

所有者明确选择接入 Shizuku，不自建 ADB 后端。Advanced/developer 的 Mobile Use 增加可选 Shizuku v13+ client；系统服务由用户自行通过 ADB/Root 启动，Helix 仅在设置按钮的显式操作后请求 Shizuku 授权。Standard/consumer 不引入 Shizuku provider、授权 Activity 或依赖；维持当前 Mobile Use 渠道边界。

首版复用 `ui.click_match`，增加显式 `backend=shizuku`，只接受精确 packageName/viewId/text；默认仍为 Accessibility，不因失败自动提权、切后端或重放。两条路径共享原 Conversation 范围、Dispatcher/Policy/Approval/Audit、无障碍物理租约、锁屏与接管控制。Shizuku 系统授权不等于工具或目标授权，不开放任意 shell、静默安装或权限自授。

UserService 使用不抑制已有无障碍服务的 UiAutomation 观察，以及固定点击命令；唯一节点匹配并重复观察，主进程在注入前通过回调复核原调用的取消/截止时间、权限、范围、窗口/显示/旋转与坐标。Binder 只接受本包 UID，Host guard 只接受 shell/root；断连/撤销停止后续动作，注入后的失败和不确定结果要求核查而非自动重试。点击派发后的正常页面变化不要求保持原目标，但原调用有效性仍检查。观察与注入之间仍存在平台竞态；实际安装成功必须另验。首版只支持默认显示的点击补充，无障碍服务仍需连接；不宣称替代完整 UI 后端。

## Decision history — 2026-10-04：Root 验证与后端优先级

所有者要求先验证 Root，再接入 Mobile Use，并按已取得的可用权限选择 Root → Shizuku → Accessibility。自动选择发生在执行之前，仅在后端支持本次参数/能力时参与；显式指定后端固定该路径，失败、撤权或 UNKNOWN 不触发跨后端重放。精确节点点击首版之外的截图、手势、节点 token 操作继续使用实际已实现的后端，不能把“首选 Root”显示为所有操作都已迁移。

Root 复用既有 libsu，不将 shell 的 `su 0`、文件存在、模型输出或 Profile 切换当作应用 Root 授权。Mobile Use 设置提供独立显式授权/断开入口，连接允许跨目标应用存续；原 `root.*` 的前台失权规则不变，两者不借用业务 scope。两种高权限传输复用同一有界观察/点击协议、原会话 scope、租约、取消和审计；不开放 `root.exec` 或静默安装。查询/自动路由不得冷启动 Root shell；断连后下一新调用可以选择其他可用后端，原调用不得重放。

Root manager 删除未来 `su` 授权不一定终止已运行的 UID 0 服务，不能将 cached grant 声称为即时撤权证明。设置必须提示这一平台边界并提供显式断开；用户停止/接管、关闭或替换会话范围、锁屏和调用取消仍通过逐动作 live guard 阻止后续输入。独立连接指生命周期与业务准入，libsu 的进程/缓存仍共享，不声称凭此隔离凭据。

## Decision history — 2026-10-04：有界点击扰动

所有者授权为精确点击增加小幅随机扰动，视觉点击保持精准或较小扰动。Root/Shizuku 精确节点点击在两次层级观察确认目标不变后，在中心附近抽取一次实际落点：每轴偏移上限为该轴尺寸的 5% 向下取整，且不超过 4 屏幕像素；尺寸小于 20 像素的轴保持中心。落点必须留在目标内，并将这个实际坐标送入原 live guard 检查；拒绝后不得重抽、回中心或跨后端重试。视觉 `ui.gesture` 保留模型提交且经 frame 校验的原坐标，不叠加扰动；无障碍语义动作仍使用控件 ACTION_CLICK，不改为坐标注入。这是有界落点策略，不增加授权范围，也不是反检测保证。

## Decision history — 2026-10-04：有界模拟短按

所有者追加模拟点击能力。Root/Shizuku 精确点击沿用第 29 节研究中已落地的单次落点采样和实际坐标 guard，在同一个固定输入命令内执行起终点相同的 touchscreen 短按，持续时间每次仅采样一次，范围 60–120 ms。固定默认显示，不增加移动轨迹或任意命令参数；无障碍语义 ACTION_CLICK 和视觉手势的原始坐标/时长不变。

持续时间是请求值，不保证系统调度下的实际时长；平台兼容性须另行设备验证。沿用取消/截止时间检查、物理占用及注入后的 UNKNOWN，无自动补点、重抽或换后端重放。此变更不隐藏 Root、无障碍、输入来源或修改设备身份，也不是不可检测承诺。

## Decision history — 2026-10-04：配置入口归属

按所有者菜单分类与去重要求，全局“权限与安全”管理新会话默认权限、全局工具可用性及系统安全设置；当前会话授权编辑和 Mobile Use 操作集中到会话设置，全局页仅跳转到该入口。服务、持久配置、逐次授权与审计保持同一来源；导航和分组展开不改变权限，也不启动设备许可。

## Decision

### 1. 四个会话预设与一个自定义模式

| 预设 | ALLOW | ASK | DENY |
| --- | --- | --- | --- |
| 需要批准 APPROVAL_REQUIRED | 工作区内读取 | 工作区外读取；所有文件修改；远端业务修改；命令；设备/系统修改 | 无额外 preset DENY |
| 信任工作区 WORKSPACE_TRUSTED | 工作区内读取与文件修改 | 工作区外读取/修改；远端业务修改；命令；设备/系统修改 | 无额外 preset DENY |
| 完全访问 FULL_ACCESS | 当前 App 实际可执行的普通 operation effect | 仅命中独立硬规则（如第 3 节 `rm -rf dir` 精确提醒） | 仍受不可绕过的能力、完整性、凭据、未知副作用等 hard invariant |
| 只读 READ_ONLY | 工作区内读取 | 工作区外读取 | 工作区内/外文件修改；远端业务修改；命令；设备/系统修改 |
| 自定义 CUSTOM | 用户显式 ALLOW | 用户显式 ASK | 用户显式 DENY |

普通联网查询、浏览、读取网络响应本身不因为建立连接或访问新 origin 额外产生 session-permission 卡；本 ADR 的 `REMOTE_BUSINESS_MUTATION` 表示服务端业务副作用。`READ_ONLY` 描述真实操作效果：远端发帖、修改、删除、保存用户文件、Shell/脚本执行以及设备修改都不能通过一次批准绕过 DENY。下载到响应缓冲或受控临时缓存不等于写用户文件；封闭运行元数据结算也不借机扩大业务副作用。

`WORKSPACE_TRUSTED` 只信任工作区文件边界，不再自动授权远端业务修改或任意命令。`FULL_ACCESS` 不是关闭 Policy：风险仍用于展示/审计，Android 能力、schema、凭据隔离、effect truth、UNKNOWN fail-closed 与独立 destructive-command 规则继续有效。

### 1.1 工具可用性只有启用与禁用

工具层只存储 ENABLED/DISABLED，不保留 ALLOW/ASK/DENY，也不保存“禁用前的 ASK”。启用仅表示工具可参与会话，是否询问完全由当前预设或 CUSTOM 操作规则决定。可复用可信工具身份、scope、持久化、曝光过滤和执行复检；旧三态模型若不适合则直接替换，不能保留两套有效授权源。

- 会话“可用工具”入口默认修改当前会话；如提供全局/Workspace 禁用，其适用范围内仍优先禁用并显示来源，会话启用不能暗中覆盖外层禁用。
- 禁用工具从模型 schema、tools.search 结果和会话曝光窗口移除，别名绑定同一可信身份。历史上下文无法撤回，执行入口仍拒绝直接构造的旧调用。
- 禁用不卸载能力，不影响其他会话或人工操作。重新启用后重新加入符合能力条件的曝光集合，按当前模式判定，不恢复旧 ASK/ALLOW。
- 排队、pending 且尚未开始的调用在禁用后拒绝并持久结算；迟到审批或旧 proof 不覆盖禁用。已开始任务独立停止，不伪称回滚。
- 单次审批卡“拒绝”不改变工具启用状态。禁用 write 只涵盖其可信身份与别名，不等于禁止 edit/Shell 写入；后者由操作权限约束。

### 1.2 自定义权限：允许产生哪些效果

CUSTOM 使用封闭、版本化的数据配置，不提供可执行策略 DSL。用户从任一预设复制出配置，再对操作类别选择 ALLOW/ASK/DENY（界面为允许/询问/禁止）；复制生成固定配置，不动态继承以后变动的预设。未定义的新类别默认 ASK；无法排除触犯既有 DENY 时直接拒绝。

| 操作类别 | 范围与说明 |
| --- | --- |
| 文件读取 | 工作目录内 / 工作目录外；只在 App 实际有权限且产品支持的范围内 |
| 文件修改 | 工作目录内 / 工作目录外；新建、覆盖、编辑、追加、移动、重命名、删除、修改权限或链接均包含在内，不能仅匹配 write 工具名 |
| 远端业务修改 | 发帖、提交、创建、修改、删除等服务端业务副作用；仍需实际联网能力，不自动授予本地文件权限 |
| 设备与系统修改 | 已实现的设备、设置、应用交互等修改；依旧需要实际系统能力 |
| 命令与代码执行 | Shell/PRoot/脚本的执行准入；允许执行不覆盖上述读、写、网络、设备效果限制 |

文件删除属于文件修改。只有第 3 节的 rm -rf dir 命令规则额外要求精确审批；文件修改 DENY 时直接拒绝，CUSTOM 也不能把命中该规则的调用设为免确认。其他删除方式按实际文件修改规则判定，不额外套用“递归删除必询问”。

例如从 `READ_ONLY` 复制到 CUSTOM，再把“命令执行=允许”而文件修改保持 DENY：文件阅读和普通联网查询可执行；write、edit、Shell 重定向、tee、sed -i、Python 文件写入、删除、解压覆盖等仍不得修改用户文件。Shell 只有在可信执行约束能保证禁止项，或平台能完整判定该调用不触犯禁止项时才可运行。用户批准一条命令不能绕过 DENY，必须先由用户修改权限配置。

“文件修改”不禁止宿主必要的 Room、审计和受控临时缓冲写入；这类例外不可被模型指定成任意路径、不可写回用户文件，不能成为脚本自由写入主应用私有数据的接口。

多效果调用先合并全部效果：任一 DENY 则整条调用拒绝；无 DENY 但存在 ASK 则为整条调用进行一次精确审批；全部 ALLOW 才免确认。复制同时检查源读取与目标修改，移动还检查源修改；上传检查源读取与网络，下载保存检查网络与目标修改。不得先执行允许部分再检查剩余效果是否被禁止；执行失败仍如实结算已发生的副作用。

工具曝光是静态辅助，不替代参数级判定。确定所有用途均被禁止的专用工具可隐藏；同时提供读写能力的工具可保留可用用途，但必须在实际调用时判定效果。MCP readOnlyHint、工具名和模型描述不能证明没有写入；远端实现无法约束且无法确定效果时，适用禁止写入的调用不放行。

本轮不提供统一的“Agent 工具禁止联网”或离线 Shell 设置。所有者明确选择：isolated UID 方案不能承载现有 PRoot 时，保留当前 Runtime，不强求禁网。API29/36 可行性验证确认 isolated UID 无网络权限，但现有 PRoot 无法访问 RootFS/工作目录；单个 PFD 不等于可用文件系统，详见[验证与范围决定](../../evidence/development/isolated-proot-feasibility-2026-09-16.md)。因此 CUSTOM 暂不包含工具联网 DENY 配置，不能显示一个实际上不能约束 Shell 的通用禁网开关，也不因这项已撤下的要求一律拒绝 Shell。

现有各工具网络策略、系统能力与审批检查保持原义；可禁用具体网络工具，但禁用 HTTP/MCP 工具不等于阻止 Shell 联网。Provider 推理、认证与工具调用仍是不同来源。文件读取/修改、远端业务修改的权限限制继续成立，不因撤下统一禁网而放开。

远端业务修改按可信适配器契约分类，不能仅依据 GET/POST。CUSTOM 或 READ_ONLY 禁止远端修改而通用网络请求效果不明时直接拒绝；需要 ASK 时说明未能确定的效果。普通联网读取不因新 origin 或重复风险提示额外出 session-permission 卡。

### 2. 授权、禁止与能力的优先级

统一决策顺序：

1. 检查工具合法性、实际系统能力、可用执行域、数据完整性、运行预算及停止状态。缺失 Android 权限或未安装/未提供的能力不能由审批模式制造。
2. 命中工具禁用、任何 preset DENY 或 CUSTOM DENY 时拒绝，不弹卡、不消费旧 proof；用户需自行修改设置，不能用单次批准覆盖 DENY。
3. 命中第 3 节 `rm -rf dir` 规则时至少要求精确一次性审批；但若同一调用已经命中 DENY，则 DENY 优先，提醒规则不能把拒绝降级成 ASK。
4. 四个预设和 CUSTOM 编译为同一种操作权限配置，共用一个 resolver，不建立五条 Dispatcher 分支。全部效果依第 1.2 节合并：任一 DENY 则拒绝；否则任一 ASK 则询问；全部 ALLOW 才免确认。工具层没有 ASK/ALLOW 参与优先级。
5. 其余合法且可执行的操作进入精确审批，批准后执行。范围外不等于永久禁止，单次批准不扩大后续模式范围。

必须区分不可执行事实与历史产品默认限制：旧等级默认拒绝、高敏出网逐次询问、应用自设 scope 不能被重新包装成硬禁止，从而使 FULL_ACCESS 名不副实。FULL_ACCESS 授权范围可覆盖 App 实际可访问的用户数据，但不代表向模型泄露应用自身的认证凭据、关闭 TLS 校验、取消 schema/审计或允许未知副作用自动重放。认证材料仍由专用客户端使用，不能作为普通工具结果或上传内容。模式不会自行启用尚未实现的支付、远程 Worker 等产品功能。

既有 Chat/Plan 的工具与只读执行边界不因审批预设放开；Act/Goal 使用所选预设。

四个预设及 CUSTOM 属于主产品会话设置，consumer/developer 均可提供，不绑定 ADVANCED 专属入口。各变体只展示和执行实际具备的能力；本决定不把 PRoot/Subscriptions 加入 consumer，也不自动启用系统权限或 Runtime。

### 3. 目录与命令必须依据实际副作用

Workspace 绑定使用稳定 ID、规范根及版本；路径包含性必须处理符号链接、重命名、SAF URI、跨根移动和执行前变化。没有有效工作目录时不能以全盘替代。工作目录修改后旧排队调用重新判定，不继承旧根授权。

删除专项暂定为**命令规则**，只拦截提交给 Agent Shell 执行入口的显式 `rm -rf dir`，拦截结果为精确审批而不是永久拒绝。以解析后的命令名 `rm`、参数 `-rf` 与非空目标操作数匹配，不把 echo/注释/字符串中出现的文本误判成执行；目标不确定是否为目录时也询问。复合命令中可明确解析的该子命令同样检查。路径引号、空白和多个目标须测试；无法解析的其他命令按所选模式的常规未知效果规则处理，不能借此把 FULL_ACCESS 变成所有命令都询问。

本轮不要求递归检查脚本内容、识别变量展开、别名、选项变体、包装器、逐文件循环、其他语言或原生工具的等价删除。它是有限命令提醒规则，不是目录树防删除沙箱，不承诺防止目录内容丢失。将来扩大匹配集合需明确修改契约，不能由实现者自行添加门禁。

这一范围缩减只适用于删除专项。CUSTOM 的“禁止文件修改”仍是跨工具效果限制：脚本或其他删除方式仍属于修改，不因没有匹配 rm 规则而放行。工作目录内外约束同样保留。执行域可行性验证先于 UI；不能以正则或 cwd 当作可靠的文件写入隔离。

自定义 DENY 不能降级为 ASK。执行域不支持可靠限制时拒绝潜在违规调用，并给出“当前执行环境无法保证所选限制”的具体原因。并发调度的效果 footprint 只可复用平台分类，不自动构成操作系统隔离证据；PRoot 的 cwd 或同 UID 私有进程不提供只读保证。

### 4. 生命周期与切换

只有用户 UI 动作可选择模式；模型、网页、MCP、Skill、脚本不得修改模式、根目录绑定或自身审批规则。模式可作为只读运行上下文告知模型。

安装初始默认 `APPROVAL_REQUIRED`。用户可设置“新会话默认模式”；默认变更只影响以后新建会话，不修改现有会话。复制、分叉、导入会话不继承来源会话的授权，使用当前用户选定的新会话默认；明确由用户设定 `FULL_ACCESS` 默认时无需每次再询问。

项目尚未发布，本次采用 clean-slate v2：旧 `WORKSPACE`、旧 `READ_ONLY=ASK`、旧 configVersion=1 不提供运行时兼容、别名解析或数据库迁移。开发期旧数据库直接重建；所有当前 fixtures、默认行和审计断言统一写 v2 枚举名与 `configVersion=2`。

CUSTOM 保存版本、来源预设及各范围规则；切换到预设后自定义草案不生效，重新选择 CUSTOM 才恢复。工具启用状态独立于模式，切换模式不重新启用工具。持久化的是设置，不是可复用的逐调用 proof。

进程重启恢复设置不恢复 Goal 激活，继续遵守 [ADR-GOAL-001](../goal/001-lifecycle-and-completion.md) 的用户显式恢复、不重放未知副作用。切换会话不修改其他会话设置。

模式切换默认影响后续与排队未开始调用，不自动取消已展示审批卡。提供“切换并继续当前操作”动作：重新验证该待执行调用，以当前模式作新决定，保持原调用身份并结算旧等待；命中 rm -rf dir 规则仍须精确批准。晚到旧卡决定不得重复执行。已开始调用不回滚；用户停止仍可取消执行。

模式与自定义规则版本、Workspace 绑定、工具可用性与执行开始需要共享明确的线性化契约。降级后尚未开始的调用重新解析并按需询问；已有有效精确 proof 在未命中新的禁止项时可继续使用，不制造第二次相同审批。等待审批不得持有模式写入锁。设置收紧后 UI 显示“后续操作已生效；仍有 N 个此前启动任务”，提供精确停止入口。后台进程及延迟 Job 必须归属会话与任务，尚未实际开始的 Job 重新判定；不声称新设置能撤销运行中任务已经发生的副作用。

### 5. 审计与交互

持久记录会话模式、版本、用户变更时间及绑定；切换产生独立审计事件。逐调用记录实际模式版本、授权来源、规范目标与审批原因，自动授权不得伪装为用户点击 APPROVED。保留取消、失败、未知副作用及恢复结算。

审批原因采用结构化集合，不匹配描述字符串。范围、风险、工具网络、操作 ASK、rm 命令规则与硬拒绝分别表达，以同一 resolver 在展示和执行开始时判定。

会话持续显示“需要批准”“信任工作区”“完全访问”“只读”或“自定义”；自定义旁显示实际权限摘要。首次扩大授权说明具体可执行范围、`rm` 命令确认例外和被禁用工具；`READ_ONLY` 明确展示为硬拒绝写操作而不是“会询问”。五种模式均有直接切换及停止入口；工具可用性独立显示，不将工具禁用混入权限级别。UI 经服务操作，不直接写 DAO。

## Alternatives considered

- 仅豁免 L2，保留所有联网询问：不能满足所有者明确的三级联网要求，拒绝。
- 不询问时一律拒绝：适合 CI 的 DSH never/dontAsk，不是此处免确认语义，可将来独立增加。
- 关闭所有 Policy 与审计：不必要；显式模式是授权来源，工具仍经统一执行管线。
- 用命令匹配保证工作目录/禁止写入边界：不能成立；rm -rf dir 匹配只承担有限删除提醒，不作为其他效果约束的证据。
- 保留旧 `WORKSPACE` / 旧 `READ_ONLY` 枚举、字符串别名或迁移适配：产品未发布且所有者明确不要求兼容，拒绝双轨授权；直接按 v2 契约重构。
- 仅凭 seccomp socket 过滤宣称共享 UID PRoot 完整禁网：探针已发现继承 FD 与进程委托缺口，不能作为保证；同 APK isolated UID 又不直接支持现有 RootFS/工作目录路径。本轮按所有者决定保留现状，不新增独立 Runtime APK 或文件代理。
- 自动分类器决定放行：不是四个预设与自定义规则的必要条件，本次不引入。

## Consequences

`WORKSPACE_TRUSTED` 与 `FULL_ACCESS` 可减少长任务中的重复批准；`APPROVAL_REQUIRED` 是默认交互安全线；`READ_ONLY` 提供真正不可用一次性批准绕过的写入禁止。代价包括 Policy 原因分类、执行域边界、并发切换和恢复测试；禁止写入和工作区约束必须由实际 effect classification/执行域保证，不能当作纯 UI 文案。

产品模式不改变 Android 自身权限或进程存活限制。决定已接受，代码与架构规范仍需 HXA-209 同步迁移；不得把旧实现的全绿证据用作新模式验收。

## Verification

HXA-209 的四态实现是历史基线；HXA-228 D2 以本 ADR v2 覆盖其 preset 语义。HXA-209 完成记录仍作为历史实现证据，不再代表当前 preset 名称/默认值。

HXA-228 v2 至少按以下验收矩阵提供：

- 四个预设及 CUSTOM × 内置/MCP/执行域 × 读写/远端业务修改/目录外操作/`rm` 命令矩阵；`APPROVAL_REQUIRED` 的写操作出精确卡，`WORKSPACE_TRUSTED` 的工作区写免卡但远端业务修改仍询问，`READ_ONLY` 的 mutation/command/remote write/system mutation 直接 DENY 且无审批卡。
- 同一操作分别得到免卡、精确卡、明确禁止；工具禁用与 CUSTOM DENY 优先，精确 proof 不覆盖新禁止项。
- 禁用工具在请求 schema、tools.search、曝光窗口和别名调用中一致生效；跨会话不串扰，继承禁用不能被本会话启用覆盖，重新启用仅改变可用性，不恢复 ASK/ALLOW。
- 自定义禁止文件修改覆盖 write/edit、重定向、tee、sed -i、脚本、删除、复制/移动、解压、下载保存与插件路径；允许读取和联网仍可用。未知效果且可能违反 DENY 的调用直接拒绝，不出卡；同时验证提示注入不能修改配置。
- 目录逃逸、符号链接、跨根移动、根切换与未知范围测试；rm 命令规则按第 3 节有限集合验收，不要求拦截所有等价删除。
- 不提供统一禁网设置或离线承诺；保留现有 Runtime 的联网能力，不将禁用某个网络工具解释为 Shell 禁网。Provider 与已有普通任务不得因实验过滤器受影响。
- 自定义禁止写入时既验证没有写入，也验证可用的只读命令与联网任务，不以一律拒绝代替产品可用性。
- 模式降级与执行开始竞态、排队复查、等待卡切换、旧决定迟到、停止、同会话连续 Goal 与跨会话隔离。
- v2 新配置持久化、新会话默认 `APPROVAL_REQUIRED`、真实进程重启、设置恢复但 Goal 未激活、未知副作用不重放；不验证旧开发数据库迁移，因为本版本明确 clean-slate 重建。
- API29/36 × consumer/developer 设备证据；缺失权限不放行、已有权限不重复申请、变体能力保持真实。
- 项目现有三语言资源与窄屏/大字体界面；模式、范围与 DENY 可见，审计能追溯实际执行授权。
- 同步架构、安全、产品、AGENTS 与 HXA 任务文档；执行任务规定的主机及设备门禁。未解决执行域限制必须列为阻塞，不能写整体完成。

## Reconsider when

需要扩大 rm 命令规则为通用目录树删除保护，或重新要求跨执行域禁网、用户需要新的网络/目录预设时，另行明确产品取舍与执行域保证。需要定时/Channel 自动激活时另行更新 Goal 唤醒契约。

## Decision history — 2026-10-03：插件悬浮交互

所有者授权 HXA-245 首版，并明确 Mobile Use 是插件。窗口、文案及控制策略由 `extensions/mobile-use` 拥有；宿主通用任务接口只提供原 Conversation/Turn 的状态、停止和返回会话，不向插件开放 DAO 或绕过 Dispatcher 的执行入口。复用自动化服务的可选 presentation 接口，不把插件 UI 搬入宿主聊天功能。

半透明状态窗不可触摸、不抢焦点；独立小控制窗允许用户接管或返回原会话。接管只停止原任务（Goal 按已有暂停协议），不撤销 Conversation 授权；已发出的动作继续按事实结算。截图和手势期间暂时隐藏窗口，无法确认隐藏则拒绝本次执行。此进程内展示/拦截状态不是持久任务事实、授权或恢复凭据；服务重建继续遵守现有节点/frame 失效契约。前台服务不构成永久保活保证。

## Decision history — 2026-10-05：插件全局配置与会话选择分离

所有者明确要求 Mobile Use 配置归属插件、全局生效，会话只选择是否使用。应用范围与截图共享说明移入扩展 → Mobile Use → 插件设置；保存范围本身不启用任何会话。用户开启某会话的插件时保存通用插件选择；执行范围由该选择与全局配置推导，关闭即不再取得执行范围。首次安装不自动选择所有会话或新会话默认值；未配置应用范围时开启失败并指向插件配置。

有效授权身份组合该会话启用身份和当前全局范围身份。全局范围改变立即影响已启用会话，并使旧观察/审批/截图 proof 失配；未启用会话不会取得授权。关闭再开启产生新身份，不能复活旧审批。全局设置写入失败时当前进程 fail closed，不能回落到先前更宽范围。原有按实际调用检查 Android 权限、锁屏、有效后端、图片归属/接收方及未知结果的规则保持不变。此决定替代 HXA-244 中“应用范围分别在会话配置”的产品界面与设置归属；会话授权隔离仍保留。

授权管理集中展示无障碍、Shizuku、Helix Root、通知/日历/通知读取和文件授权入口。Root 诊断工具的独立许可在同页次级展开，不与 Mobile Use 后端混为同一许可。系统权限不自动创建 Agent 范围；查看插件内容不触发任何授权或工具调用。

### 同日补充：系统授权与执行连接分别呈现

授权管理区分 Helix 的系统授权、Mobile Use 执行服务连接，以及当前可优先尝试的后端。Root 管理器授权按应用复用；libsu 的被动缓存只作为“上次已获准”提示，不将它提升为当前服务就绪或实时管理器授权事实。已有授权时连接按钮表示复用授权建立服务；没有确认授权时，用户显式点击才可能向管理器申请。轮询状态、打开插件设置或自动选择后端均不得主动请求 Root/建立 Root 服务。

Root 诊断连接与 Mobile Use 连接继续分离：诊断保留前台生命周期和独立会话范围；Mobile Use 保留跨应用执行的既有生命周期。断开执行服务不声称撤销管理器授权。Shizuku 已获授权时明确执行服务在调用时建立，不能将权限/主服务存活误称为用户执行服务已连接。后端摘要只反映可优先尝试的路径，各工具仍按能力、范围和实时检查执行；无可用屏幕后端不关闭已有部分功能。


## Decision history — 2026-10-05：系统权限供插件复用

Helix 通过 `tools/device-access` 统一管理系统授权。Mobile Use 停用或会话取消只能阻止该插件继续动作，不调用系统权限撤销，也不结束其他使用方连接。平台授权、服务连接、插件启用、会话选择及操作范围分别检查；授权存在不保证该后端支持特定操作。执行中的 Mobile Use 在派发实际输入前重新读取插件有效性及当前范围，已发出的外部效果不假设回滚。

## Decision history — 2026-10-05：系统授权页与插件执行设置分离

所有者要求彻底拆开通用系统权限与 Mobile Use 权限/配置。授权管理由宿主 `DeviceAccessModule` 渲染，不再调用 `AutomationModule.Permissions` 或创建自动化后端。无障碍页项从应用声明的系统服务查询授权，Shizuku 页项从宿主权限 API 查询，Root 页项使用独立的宿主授权访问对象；打开页面只查询状态，不申请权限或建立插件连接。

Mobile Use 插件设置独立展示后端选择、无障碍引擎连接状态、专用 Root 连接及应用范围。缺少系统授权时只跳转宿主授权页，Root 连接按钮在已有应用授权时才可用。断开只释放 Mobile Use 连接；页面跳转、修改配置和系统授权本身均不选择会话，也不建立 Agent 操作范围。

## Decision history — 2026-10-05：单一会话选择与停止语义

按所有者要求精简重复状态。`session_connectors` 的持久选择标识是唯一会话启用事实；Mobile Use 只存全局范围与截图共享配置，不再另存会话 grant。派发范围身份由会话 ID、选择标识及全局配置身份推导。重复开启保持身份，关闭再开启产生新标识；范围变化、停用及会话删除均不能复活旧操作凭据。全局写入失败在当前进程拒绝继续使用配置。

通知停止与接管通过既有 PluginTaskHost 取消原任务，不关闭会话插件。通知同时匹配会话、范围与运行实例；不同 Turn 使用不同运行实例，迟到停止不能取消新 Turn。停止后的已发出动作继续如实结算，不声明外部效果回滚。

执行前仍检查当前选择、实际系统能力、取消、范围与观察新鲜度。这些是使用现有授权的校验，不是要求用户重复授予系统权限。验证见[架构精简记录](../../evidence/development/plugin-architecture-simplification-2026-10-05.md)。
