# ADR-WORKSPACE-007: 系统分享收集与本机知识库

Status: accepted
Date: 2026-10-19; revised 2026-10-25
HXA: HXA-308, HXA-311
Deciders: project owner（开始执行收集/知识库第一阶段）；实现 Agent（有界实现取舍）

## Context

旧系统分享入口仅将材料放入会话草稿，没有独立知识管理。Owner 要求从 X、微信及其他应用收集文字、链接、图片/文件，先保存原件与来源，再提取、检索、选择引用和可选分析。此领域不同于人格 Memory，也不以 HXA-286～294 的整体重构为前置。

## Decision

收集记录明确是 **原始来源资产**，并非已经确认的知识。`CollectedSource` 保存原文/原件、提取正文和来源附属笔记；`KnowledgeNote.kind` 区分笔记与知识，保存状态及核对状态不决定内容类型；`KnowledgeNoteSource` 保存用户选择的多对多引用快照。来源库长期保留材料，提炼后不搬走或清空，不强制走“清空收集箱”流程。不将每次分享或自动摘要固化为一个知识，不按语义相似自动合并。

### 笔记、知识与会话引用

- 随手记保存后是笔记；新建编辑器未保存的内容不入库。知识由用户直接创建，或将已保存笔记整理为可编辑候选，再明确保存为独立、未核对的知识。原笔记和资料保留；不是改一个审核标签就升级类型，也不要求调用模型才可整理。
- 知识库展示知识、笔记、资料；新问答统一使用现有会话；旧资料问答仅保留只读历史和明确保存为笔记，不再提供独立模型调用入口。不新建聊天引擎，不将人格 Memory 与知识存储合并。
- 输入框原有＋菜单新增知识库引用，保留独立的会话引用。选择、预览、取消、添加与移除不发送、不清草稿、不改变知识工具开关或权限。资料阅读页使用相同结构化引用进入原会话草稿。
- 聊天引用最多八项，仅保存类型、资源身份、标题、来源修订摘要、可读字符数及提取完整性，不保存或首轮注入正文。纯文本修订为正文 SHA256；有原件时绑定正文、原件清单和派生提取报告，不能以未变的预览替代原件身份。旧清单离开上下文时可用本会话 session.history/read 恢复，元数据目录不授予全库权限。本地预览/分页及复制全文不等于发送，复制后显式粘贴仍可作为普通文本输入。无可读提取文本的原件不伪装成空文档；不自动上传 PDF、图片或二进制原件。
- 发送前及确认时核对来源修订。来源变化须重新选择，不保留旧聊天正文快照或静默读新正文；来源删除明确不可用。已发送引用的读取权限归属接受该输入的目标会话，后续 Turn 可继续读取；原 USER 绑定删除/被替代则失效，不授权来源编辑或其他资料。
- 引用复用现有敏感文件文本披露与凭据扫描，原有 Provider、权限、取消与执行身份不变。首轮模型仅接收明确标记的引用清单，工具取回正文仍是不可信资料；不能由引用内容授权工具。“本条附带”不承诺会话历史中的已发送内容自动遗忘。
- 上线前主库和当前文档格式固定内部版本 1；资料正文不再使用独立 Room 库，不保留 App 内历史迁移链。来源、类型、引用和正文结构仍严格校验；旧测试库不冒充当前身份，按外部一次性处理或明确目标后干净安装处理，不自动清库。

- Standard 与 Advanced 提供相同的独立收集页；系统分享使用明确的“收集到 Helix / Helix Advanced”目标标签，Advanced 应用名也区分渠道，避免同机安装时误投。Android SEND/SEND_MULTIPLE 指向收集 Activity，不自动创建 Turn。微信内部转发不等于系统分享；没有入口时提示复制文字/链接或保存文件后分享。
- 当前 Owner 决定采用文档优先：资料原件、笔记和知识固定共享保存，不提供私有／共享切换，不首次强制 SAF，不逐次询问；正文不再以 `library.db` 为权威。应用自有 MediaStore.Files 文件固定放在 `Documents/Helix/library/`，使用开放 Markdown／原格式，目录和搜索可重建；回答历史、会话来源身份及内部快照保持私有。目录授权和共享位置不自动授予模型权限。此替换已接通并完成当前主机及有界模拟器验收，其他设备和真实授权边界见[存储记录](../../development/document-first-storage.md)；不得用设计 accepted 宣称完整交付。不新增向量数据库、账号或同步基础设施；可选嵌入接入见下文。
- 收集 Activity 在临时 URI 授权有效期间保持存活，应用作用域进行有界物化：最多八文件、单文件 16 MiB、文字 200000 字符。只接收 content URI，不让外部调用者借用本应用 FileProvider 路径。文件名仅展示，不参与存储路径。按文字和实际文件字节摘要去重；相同材料保留首次来源/时间。
- IMPORTING/QUEUED/EXTRACTING 是持久状态。每个完成文件登记后再继续；进程中断后 IMPORTING 明确标不完整并要求重分享，排队/提取项从本机原件重试。不宣称临时 URI 可永久恢复或断电事务。失败不得显示完成，已接收资料不丢弃。
- 本机 PDF/DOCX/HTML 提取复用现有有界文本提取器；图片及未知文件只保存原件，不冒充 OCR 或完整 PDF 理解。用户需要视觉识别时，复用会话图片及文档逐页查看功能，经原披露与权限边界交给当前视觉模型；不新增本地 OCR，不自动上传或把结果当作已审核知识。链接只通过现有公开网络 SSRF/TLS/重定向防护 transport 抓取，不携带浏览器 Cookie/登录态、不执行脚本、不绕过登录。保留分享 URL 与公开页面原始快照；通用可见文字提取不能证明正文完整，页面明确标注未核验，失败/登录/超限均标不完整。
- 原始资料、提取内容和来源附属摘要独立，来源附属摘要不是已确认知识。用户可直接写知识笔记，从单源提炼，或选择最多八份来源综合。笔记引用保存有界片段、来源身份/时间/完整性与内容摘要；来源重新提取不静默更新笔记或引用。
- 模型处理统一进入既有会话：用户选择引用，确认实际发送内容与目标后提问。知识库不持有第二套模型配置、生成确认或请求状态机。普通回复可显式保存为笔记，绑定会话/消息/正文摘要和当时引用；重复保存不重复创建，也不覆盖后续用户编辑。保存不等于核对或知识提炼。
- 旧记录中的模型建议仍可查看并明确载入编辑器，旧问答的冻结来源、正文及状态保留；中断恢复只标 INTERRUPTED，不重放模型请求。旧 READY 问答可原子保存为笔记并登记 savedNoteId，失败记录不得伪装可保存成功。删除被替代的独立问答/笔记生成 transport 与旧 UI，而非只隐藏入口。
- 来源选择、候选编辑与明确保存相互分开：打开候选和取消不写入空笔记；保存时重核所选来源版本，来源变化拒绝静默替换。多源候选为本机可编辑整理内容，不伪称已经模型综合；需要模型总结时使用正常会话。
- 普通笔记编辑使用整页无边框标题与 Markdown 正文画布，正文单页滚动，保存保持显式。标题可留空并在保存时使用本地化未命名标题；标题与正文都为空不能保存。未保存文字与光标/选择可恢复，失败不离开编辑页；不引入富文本往返、自动保存或隐式模型请求。
- 知识库主界面复用 Shell 的唯一标题，内容依次为搜索、知识/笔记/资料分类、数量与问答记录、平面列表、底部当前分类主动作。笔记提供写笔记，知识提供直接写知识，资料提供导入；不在其他分类复用笔记空态或主按钮。管理及恢复在更多，资料多选仅在资料类提供。搜索无匹配与分类无内容分开，清除搜索不改变分类。阅读正文优先，编辑为独立状态，保存仅明确动作；必要来源管理、核对和删除确认在二级入口。新问答不再要求先走一个重复的知识库向导。
- Agent 全库读取默认关闭；明确附加的引用独立允许 `knowledge.search/read` 在所选范围内有界检索与读取；移除的是独立问答专用的片段窗口拼装，不是现有 Agent 搜索能力。不自动注入全库或写入人格记忆。

### 管理与 Agent 只读访问

来源删除仅由当前明确用户动作清理所选资料及所属共享原件。共享 `DELETING`／`QUEUED` 等状态不是授权，启动时仅标为未完成，不自动续跑删除或提取；用户明确重试需重新核对内容身份和版本。固定引用不级联删除。笔记删除原子清理索引/引用并解除问答 savedNoteId；保留问答及其他资料。来源更新不改写笔记正文，用户明确刷新引用时核对版本、清除旧生成建议并改回草稿。Markdown 导出仅含已保存正文和固定引用，不是整库原件备份。

`knowledge.search/read` 复用同一注册/Dispatcher/策略链。未附带引用时仍需独立、默认关闭的全库读取开关；显式 `referenceInputId/referenceHash` 始终只读该会话已接受的所选清单，即使全库开关开启也不扩范围。服务端以持久输入→USER 消息绑定与运行中的原工具调用核验身份，模型 ID/路径不是权限。只读工具在 Plan/Agent 及启用工具的 Chat 中可见；不支持工具的模型、关闭/禁用读取工具时发送前明确提示，不全文回退。

### 按需文本读取

PDF 原件可用 `knowledge.read` 的 `fileIndex/page` 逐页读取，`offset/limit` 是该页 Unicode code-point 半开区间，返回 `nextOffset`、真实页码、总字符及截断；原件模式的 `contentHash` 绑定来源修订。正文摘录分页的 `contentHash` 仍绑定提取正文。原件字节须匹配清单 SHA256，清单/报告/正文变化使已选修订失效；缺少已核实原件身份须明确重新提取，不猜路径或默读新文件。所选资料的原件页不会授权其他来源或全库。关键词搜索只覆盖当前可读提取文本，不等于搜索过所有原件页，无命中不能声称整份 PDF 没有答案。

导入复用既有 `:document_reader` 隔离解析与共享物理容量，不另建执行域或 OCR 后端。API35+ 保存实际总页数、处理页数、每页文本状态、范围和截断原因；文本不包含图片/扫描字/复杂版式，因此不宣称视觉全文完整。旧 Android 的简易预览明确有限、页覆盖未知。派生报告可重建，不改变公开源文档为事实源的原则；提取报告内的正文位置标明 UTF16 单位，既非 PDF 字节偏移，也不能与工具的 code-point 偏移混用。

返回引用链接仅驱动用户点击后的本地片段预览，不自动读库、发送消息或执行工具；知识链接核对当前正文/原件修订，会话链接核对真实会话、消息及内容哈希。来源变化/删除不静默定位到新版本。HTTP 链接保持原行为，内部引用不交给任意外部 App 处理。

- `knowledge.search` 对明确引用采用本地大小写不敏感子串检索，返回最多16个命中片段、正文哈希、字符偏移和出处。`nextCursor` 绑定接受输入、引用清单哈希与查询；不可跨范围或修订沿用。字面结果不声称语义命中；明确启用索引后，另返回受控的 related 候选。全库搜索仍是有界目录检索，不冒充全文遍历。
- `knowledge.read` 默认2048、最多4096个 Unicode 字符，返回 `offset/endOffset/nextOffset/totalCharacters`、正文哈希及逻辑出处 URI。后续页必须携带正文哈希；每次执行前后重核授权、修订、取消及截止时间。完整总结需要继续读取，单页/搜索命中不等于全文。
- 所选来源仅在同一内容哈希仍可读取时提供，不增加历史版本库。笔记显式保存时的有界冻结出处摘录是独立事实，不授予聊天工具权限；来源已不可用时保存其出处元数据，不能伪造旧摘录。资料内容永远是不可信证据，不能授权后续动作；敏感凭据内容沿既有守卫拒绝发布。

### 可选本机语义索引

知识库设置中的语义检索默认关闭。用户从实际嵌入目录选择内置账号模型并明确选取资料，授权所选文本、后续修订和查询发送至既有 `/v1/embeddings`；不上传原始二进制或未选资料，不自动收集聊天或记忆。前缀与部署修订可按服务器合同配置，不从模型名字猜用途、前缀处理或服务限额。对话模型选择仍排除专用嵌入模型。

正文文件仍是唯一事实源。本机私有缓存只保存有界分段位置、资料修订与归一化向量，按账号、端点、模型及参数隔离，单文件完整性校验与原子发布，容量有界，可删除重建且不进入应用备份。修改/删除立即使旧结果不可用；观察到选中资料修订后增量重建，新资料不会自动加入。重新应用会生成独立缓存世代并重建，晚到结果不能回写或参与新检索；取消编辑不保存；关闭会撤销请求并停止更新。远端复用相同模型名且不公布修订时，客户端无法自动检测权重变化，需更新部署修订或手动重建。

向量余弦与已有词法排名通过 RRF 合并，不将分数伪装为同一量纲。断网、模型/维度异常或缓存损坏保留原有词法搜索，状态明确，不宣称完成语义检索。结果仅是有出处的候选片段，不代表全文总结。来源修订绑定原件与提取状态，正文哈希绑定分段读取和文本回链；二者分别返回，原 PDF 页回链仍绑定来源修订，不混用身份。Agent 仍复用 `knowledge.search/read`：显式引用即使全库关闭也可读取，但语义索引的外发授权是另一项明确设置；全库开启不会扩大带引用的查询范围。命中回到当前正文重新核验、重建片段，缓存/模型输出都不能创造权限，取消与 deadline 传到网络请求。

参考 [OpenAI embedding 请求合同](https://developers.openai.com/api/reference/resources/embeddings/methods/create)、[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)和 [RRF 定义](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)。不复制参考项目代码，不新增向量数据库或编排框架。

## Alternatives considered

不沿用只填聊天草稿作为收藏：其会话生命周期和来源/原件管理不能满足知识库要求。不引入向量数据库、自托管爬虫或独立编排框架：嵌入复用既有 Wire/AccountSession，派生缓存不复制正文权威。会话来源身份与公共文档正文分开维护，派生索引不成为新权威。

## Consequences

原件先落地，网络/模型失败不丢掉资料；分析有明确的内容发送边界。通用网页提取不能保证文章完整，扫描 PDF、图片及任意二进制也不因文件已收藏而变成可读文本。模型建议与已核对笔记分离，保留可编辑保存和引用追溯；没有自动知识确认。
