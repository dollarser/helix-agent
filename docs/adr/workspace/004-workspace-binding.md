# ADR-WORKSPACE-004: 独立会话工作目录与外部资源绑定

Status: proposed
Date: 2026-09-16
HXA: HXA-209, HXA-210
Deciders: pending

## Context

新会话需要独立默认工作面，也需要直接操作用户选择的项目；目录身份、权限与 Path/SAF 能力必须分开。

## Decision

本方案为 proposed，尚未获得实施接受。

### 1. 明确四项职责

| 事项 | 归属与边界 |
| --- | --- |
| 相对路径从哪里开始 | 本 ADR 的主工作目录绑定 |
| 某个操作允许、询问还是禁止 | [ADR-PERMISSIONS-001](../permissions/001-session-authorization.md) 的统一操作权限及工具启用状态 |
| 文件实际如何读写 | Path/SAF 后端能力与真实系统授权 |
| Shell 是否被限制在目录内 | HXA-209 与执行域的实际约束，不能由目录布局保证 |

“私有工作目录”指 App 管理、归属于某个会话的数据位置，以及默认按会话过滤的发现入口，不是每会话独立 UID 或任意代码沙箱。普通目录内操作以当前绑定为准；显式访问其他根仍需当前模式判定。

与 FULL_ACCESS 的拟议交集：其他会话的用户文件不是自动获得的默认上下文，但在 App 实际可访问且工具支持时按 [ADR-PERMISSIONS-001](../permissions/001-session-authorization.md) 的 FULL_ACCESS 可访问；Workspace/CUSTOM 则执行目录外访问规则。应用凭据与内部控制元数据不作为用户文件暴露。若所有者希望“即使 FULL_ACCESS 也绝不访问其他会话”，需要明确改变授权范围，不能同时声称无限制全权与绝对会话隔离。

### 2. 单一目录身份与会话绑定

逻辑模型至少表达：稳定 workspaceId、后端类型、资源定位、管理类型（会话拥有/外部绑定）、可用状态，以及 sessionId 对 workspaceId + 相对子目录 + bindingRevision 的绑定。可演进现有 directory_ref 与仓库接口，不另建平行路径解析器。

- workspaceId 为持久稳定 ID；唯一性由存储约束保证，不依赖截短 ID 不碰撞或难猜测。
- Path 后端通过规范根身份处理等价路径；SAF 通过 Provider authority、tree/document 标识与实际授权定位，不猜测真实磁盘路径。
- 相同可确认资源复用身份，多个会话可绑定同一外部项目。无法证明不同 URI 指向同一资源时不虚构等价关系，也不承诺跨 Provider 的全局去重。
- 主目录可以是已授权根内的子目录。权限匹配包含该子目录边界，不能只比较 scopeId，把整个 SAF tree 或公共目录都当作当前工作目录。
- 原生文件工具、项目指令、产物、编辑器、终端与 Git 的目录来源一致；执行域不能消费该后端时明确报告不支持。

### 3. 默认私有目录与外部绑定

未选择目录的新会话获得独立的 App 管理目录，两种变体均支持。用户工作区是普通目录，不强制 input/work/output 布局；可由用户或任务创建这些目录。审计、执行日志、回收站索引与授权元数据放在独立的 App 管理位置，不混入项目文件树。

目录创建和 Room 绑定不能假装是一个跨文件系统事务：使用可恢复的创建状态，失败后重试/清理只处理本次拥有的资源。会话不应显示“就绪”而目录尚未建立，恢复不得误删已写入的用户文件。

用户选择外部目录后，支持的文件操作直接在所选资源上执行，不默认复制成另一个权威工作面。绑定不自动改变审批模式，不启动 Runtime，不申请额外权限；按需引导用户取得实际系统授权。consumer/developer 提供各自实际具备的目录来源，不借目录方案增添缺失 Runtime 或绕过渠道能力边界。

外部目录不创建 Helix 内部布局，不以整个项目大小计算 App 私有工作区 quota。仍检查单次操作限制、暂存空间与磁盘失败；私有缓存和备份计入自身预算，不能因外部目录豁免 quota 而无限增长。

### 4. 后端能力必须如实表达

复用现有文件管理器的 SAF 授权和操作适配，向 Agent 暴露同一逻辑文件面，但每个后端返回真实能力：枚举、读取、新建、覆盖、删除、重命名、移动、随机访问、条件写入及原子替换等。不能把统一接口解释为每个 Provider 都支持全部操作。

| 后端 | 文件工具 | Shell/Git/构建 |
| --- | --- | --- |
| App 私有或已授权本地 Path | 按实际能力直接操作 | 仅在 Runtime 有可用映射和权限时直接运行 |
| SAF 文档树 | 按 Provider 能力直接操作；不支持的动作明确报告 | 不把 content URI 当 cwd；独立验证后才宣称支持 |

允许用户显式选择“复制到本地处理，再导回”，但必须显示副本身份、源版本与导回冲突；不能把这一路径静默冒充 SAF 原位开发。完整 Git/构建不作为每个 SAF Provider 必须提供的能力。

授权、Provider 能力与资源可用性在执行前复检；移动、删除、撤销授权或 Provider 失联可能使引用不可用。失败不切换到私有目录，不自动猜测新 URI。操作已部分发生时记录部分写入/未知状态，不能仅返回权限错误就宣称没有副作用。

SAF 可能由远端文档服务提供。对 [ADR-PERMISSIONS-001](../permissions/001-session-authorization.md) 的“禁止 Agent 工具联网”，不能将 content URI 一律当作本地 I/O；后端无法保证离线访问时说明原因并拒绝该 Agent 调用，不阻止用户手动管理目录。Provider 内部网络不受 Helix socket 门禁自动约束，需要独立能力判定与证据。

### 5. 共享项目与并发修改

多个会话可以使用同一项目，不复制出隐含的会话副本。路径归一化后按资源协调 Helix 内部冲突操作，并沿用已有版本/hash 检查；复制、移动同时考虑源与目标。

外部编辑器和 Provider 也可能修改文件：执行前检查读取版本；支持条件写/原子替换时使用它。不支持时明确记录保证等级，不能把“先算 hash 再写”描述为完全避免外部竞态。失败或冲突返回可恢复信息，不盲目覆盖或重试。

产物引用固定 workspaceId、文件引用和必要版本信息，不随会话切换目录重新解释。目录暂不可用时仍可展示来源和恢复入口；不能错误地把新目录同名文件当作旧产物。

### 6. 目录切换与模型上下文

目录切换更新 bindingRevision 并产生审计事件。每个调用在解析参数时绑定具体目录身份与版本：

- 新调用使用新绑定；旧排队/pending 调用不重定向路径，开始前依据最新 [ADR-PERMISSIONS-001](../permissions/001-session-authorization.md) 规则复检。旧 proof 只证明原调用，不能覆盖新的禁止或不可用状态。
- 已启动 Job/终端保持原 cwd，界面标明旧目录及运行状态，提供精确停止。新的 Job 使用新绑定；切换不迁移运行中的进程或隐式复制文件。
- 新模型请求加载新主目录的项目指令，失效旧目录的活动指令与发现缓存；不删除历史对话来伪装没有切换过。
- 项目指令保留来源和 PROJECT 信任级，不因用户选择目录升级为系统指令；不自动执行项目脚本或启用其中声明的工具/权限。

模型通常使用工作目录相对路径，跨目录引用使用稳定 scope 身份。Path 执行域提供一致的逻辑 cwd/映射说明，不要求模型猜 Android 内部路径。SAF URI 不伪装成 POSIX 路径。宿主内部路径不主动注入通用上下文；Shell 输出可能包含执行域路径，不能承诺任意进程输出永远不含真实路径。审计使用稳定资源引用，不记录凭据或未经处理的敏感 URI。

### 7. 删除、回收站与目录生命周期

本 ADR 不新增删除审批规则，遵循 [ADR-PERMISSIONS-001](../permissions/001-session-authorization.md)：文件修改 DENY 跨工具生效，删除专项暂只匹配 rm -rf dir。文件工具的可恢复删除是独立产品能力，不声称 Shell 删除也会进入回收站。

外部目录不能统一假设可原子移入 App 回收站。后端支持原位回收时使用真实能力；需要跨后端备份后删除时，先校验空间、复制完整性和源版本，备份失败不删除源。持久记录准备/备份完成/源删除结果，以便进程恢复对账；不盲目重放删除。源变更、删除失败、恢复同名冲突均返回具体结果。后端无法满足可恢复删除契约时报告不支持，不静默降级为永久删除；若要另设永久删除功能，须在产品契约中单独定义。

- 解除外部绑定、删除会话或删除 Workspace 注册，不删除外部项目与其文件。
- 会话拥有的私有目录可在显式清理会话数据时回收，但先处理运行任务、跨会话引用及用户保留的产物。归档不等于清理，产物保留/导出应有入口。
- 引用计数或等价关系须覆盖目录、产物与备份；不同会话共享的资源不能由其中一个会话的删除清走。
- quota、备份保留和清理针对 App 管理数据；不得为了腾空间偷偷删除外部文件。

### 8. 转换与实施边界

不为了代码兼容维持全体新会话共用 app 根、固定布局或旧授权三态。可重构存储和接口；已有用户文件、会话、产物引用与审计仍必须保留。

历史共享目录作为普通的已存在资源登记，不继续当作新会话默认，也不猜测其中每个文件属于谁。旧产物保留原资源引用；用户可以显式绑定该目录或将选定文件转移到新目录。转换要可恢复、可重复验证，不静默大规模搬迁或删除数据。

首版一个主目录，但资源身份与会话分离，为未来附加目录和 Git worktree 留接口，不预建空模块。HXA-210 与 HXA-209 共用目录绑定和授权输入，不各写一套范围逻辑；目录后端、生命周期可独立实现，审批集成验收必须依赖新授权契约。

## Alternatives considered

- 独立目录或随机 ID 就等于沙箱：不成立，拒绝；实际执行隔离须由执行域证明。
- SAF 全面模拟本地 POSIX：会虚构能力、损害一致性；采用能力驱动的文件接口和明确的执行域支持面。
- 所有 SAF 工作默认复制进出：不符合直接操作项目的要求；保留为用户显式选择的兼容路径。
- 每个会话都复制项目或自动创建 worktree：增加存储与合并成本，首版支持共享外部项目，worktree 后续独立设计。
- 外部删除无条件复制到 App 回收站：缺少容量与失败协议；采用后端能力和可恢复流程，不能一行 move 抹平差异。
- 永久保留旧共享默认根：不是实现约束；保留旧数据引用即可，不保留旧默认行为。

## Consequences

提供无需选目录即可工作的手机体验，同时支持外部项目原位文件操作。主目录不等于权限边界，独立目录不等于进程隔离；界面与文档必须使用准确表述。

主要成本是能力驱动的文件后端、引用生命周期、并发冲突与中断恢复。SAF 文件能力和完整开发环境分开验收，不能以文件读取成功宣称 Shell/Git 可用。FULL_ACCESS 与私有目录的拟议关系见第 1 节，接受本稿前需按这一明确语义评审。

## Verification

2026-09-16 本方案尚未实施；以下是验收要求，不是通过记录。

设计接受与实现完成分开。HXA-210 关闭前必须提供：

| 验收面 | 必须覆盖 |
| --- | --- |
| 默认目录 | 会话分别拥有稳定目录，创建失败/重启恢复，不强制布局，不靠 ID 难猜保证访问控制 |
| 与 [ADR-PERMISSIONS-001](../permissions/001-session-authorization.md) 组合 | 四模式、目录内/外、工具禁用、CUSTOM 写入禁止、FULL_ACCESS 交集；无 L2 恒出卡残留 |
| SAF | 可读/只读/可写、缺少 rename/move、Provider 失联、授权撤销、引用失效、部分写入与工具禁网 |
| 执行域 | 本地 Path 的真实 cwd 与映射；SAF 不支持 Shell/Git 时明确显示，不静默使用副本 |
| 并发与切换 | 两会话共享项目、外部修改冲突、子目录边界、旧队列/卡片/Job、指令刷新与旧产物定位 |
| 生命周期 | 删除会话不删外部目录；私有目录/产物/备份清理、归档保留、共享引用不误删 |
| 回收站 | 空间不足、复制中断、源变更、源删除失败、真实进程中断、恢复目标冲突，无盲重放 |
| 数据转换 | 旧共享数据与产物保留、新默认目录、重复启动与中断对账，不要求保留旧授权行为 |
| UI | 目录类型、支持能力、不可用原因、运行中旧目录任务、三语言与窄屏/大字体 |

实现任务须登记准确命令：完整主机门禁 `./scripts/check-all.sh --all`，API29/36 × consumer/developer 独占设备专项，涉及 schema 时验证 Room 转换与真实重启。SAF 测试覆盖能力不同的可控测试 Provider 和实际系统文档入口，不依赖真实云账号作为默认门禁。通用 SAF 通过不代表所有云 Provider 或 OEM 已验收。

## Reconsider when

需要 FULL_ACCESS 之外仍绝对隔离会话、SAF 完整 POSIX 执行、附加目录、Git worktree、自动永久删除或云 Provider 离线保证时，明确新增范围与验收，不从目录绑定中隐含推导。
