# ADR-WORKSPACE-005: 本机项目与跨会话工作组织

Status: accepted
Date: 2026-10-04; revised 2026-10-17
HXA: HXA-246, HXA-286, HXA-287, HXA-295
Deciders: project owner（本轮要求完整项目设计与重构）

## Context

项目是长期工作的组织和上下文边界；会话是一次对话/任务线程；Workspace 是真实资源身份，不能互相替代。当前仅有会话目录绑定与 Project Memory 的未接入身份接口。

竞品参考：[ChatGPT/Codex 项目](https://learn.chatgpt.com/docs/projects?surface=app)区分项目共享资料与具体会话；[Claude Cowork](https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-claude-cowork)支持已有目录和项目指令；[Manus](https://manus.im/blog/manus-projects-self-updating)将经过用户授权的长期资料与单次任务分离。只采纳产品关系，不复制代码、云端架构或自动授权行为。

## Decision

### 产品与交互

- 会话下方提供独立“项目”入口。项目列表支持创建、搜索、归档查看和恢复；详情组织会话、文件、任务、成果及项目设置。
- 项目包含稳定 ID、名称、说明、共享指令、主目录、版本、创建/更新时间及归档时间。一个会话最多属于一个项目，也可以不属于项目。
- 创建项目可使用独立托管目录或显式选择已登记的目录；目录使用既有 Path/SAF 身份和能力，不复制文件、不创建另一套文件系统。
- 从项目创建会话默认使用项目主目录，新会话仍继承现有模型选择规则和新会话权限默认值，不自动复制其他会话的权限、Mobile Use 授权或工具许可。
- 加入/移出/转移已有会话仅修改组织归属，不搬文件、不改原目录、不复制历史。界面明确提示。成员仍可拥有不同工作目录。
- 会话中的项目入口双向链接项目详情；文件管理器保持独立，项目文件进入真实目录，不建立影子成果目录。
- 项目任务和成果是原会话记录的过滤视图，保留原 session/turn/file 身份。没有会话归属的计划不能猜测属于某项目。
- 项目归档只影响列表组织，不停止执行、不撤销授权、不删除内容。删除项目须二次确认，只删除项目元数据/成员关系，保留会话、目录和文件；有未完成执行时不得移除上下文归属。

### 上下文、记忆与授权

项目指令以 PROJECT 级来源加入每次模型请求的现有 PromptRegistry，并由现有快照记录版本内容；不能授予权限、执行脚本或启用扩展。项目记忆复用 MarkdownMemoryStore，以显式 projectId 为唯一身份，不按路径、名称、Git remote 合并。保持用户已有记忆开关及自动写入开关，默认不自动开启。不会自动把其他会话完整历史注入当前会话。

成员关系变更在同一数据库事务内检查活动 Turn/待发送输入，拒绝执行中的迁移，避免后续工具轮和恢复跨项目读取记忆。文件目录变更继续遵循原请求绑定，项目主目录编辑仅作用于新建会话，不重写既有会话或在途请求。

### 存储与数据保留

新增 Room projects / project_sessions，以 FK 约束项目成员和主目录。项目引用纳入 Workspace 清理保护，归档项目同样保留目录。删除项目不删除项目记忆文件，重新创建同名项目获得新 ID，旧记忆不自动继承。

所有者随后明确无需兼容旧接口和旧开发数据。本轮继续采用当前 Room v1 baseline，不新增旧库迁移或接口兼容分支。开发库 identity 不兼容时沿用现有重建行为，数据库外用户文件保留；禁止隐式搬移或删除目录。新模型使用稳定 ID、显式引用、修订号和事务边界，为正式稳定版本后的增量迁移提供清晰契约。

### 实施范围

两渠道支持本机项目完整管理、成员生命周期、共享主目录、指令、显式项目记忆、会话/文件/任务/成果导航。模型和扩展仍由既有入口管理，项目不建立第二套开关。云同步、团队协作、多主目录、自动 Git 分支/worktree、文件修改快照与回退不属于本轮项目生命周期，不能用只读 Git 冒充版本恢复。

后续目录重构区分项目/材料来源与实际执行工作副本；多个副本可明确关联同一项目，但不同副本不自动同步文件，不复制 grant、审批或终端控制权。项目与资源分别拥有稳定身份，现有 projectId/Workspace 的具体表示和存储可按目标替换，不为未来远程预建 Host/Node/Device 目录；Git worktree/diff 与非 Git 副本/导出是实际任务选择，不改变项目成员关系的权限含义。责任与接续见 [Harness 第 23.3.1 节](../../architecture/harness-refactor-plan.md#2331-目录资源与执行环境)。

## Decision history

- 2026-10-17，原则澄清：按 Owner 要求消除“必须沿用现有身份表示”的歧义。目标保留项目/资源职责及权限边界，旧内部设计和实现不构成兼容约束。

- 2026-10-17：按 Owner 目录架构研究追加项目来源与执行副本边界，由 286/287/295 接续；不启用云同步、自动 worktree 或远程会话，不更改既有项目能力完成范围。

- 2026-10-10：HXA-254 将项目会话列表改为 ProjectService 提供的窄读模型（ID、标题、归档标记），通过 Room invalidation 与页面生命周期订阅刷新。加载、读取失败及成功空列表分别呈现，失败允许重新订阅；取消与致命错误继续传播。页面不持有 SessionEntity，不另建持久状态或授权 owner；切换项目及项目归档重置临时加入状态，成员转移与在途保护沿用既有事务。

- 2026-10-04：所有者调整抽屉顺序，并进一步明确项目独立放在会话下方；最终顺序为会话、项目、模型、扩展、终端、工作、设置。

- 2026-10-04：所有者要求参考竞品设计完整项目并重构；采用本机持久项目，保留独立文件管理器，项目与 Workspace 身份分离，按所有者最新要求不兼容旧开发数据或接口，继续 v1 baseline。

## Verification

项目生命周期、空项目过滤、成员转移与运行中拒绝、目录保留、来源隔离、输入边界、新数据库重开和失败回滚都需验证。主机检查与双渠道制品不替代设备验收。初始设计阶段设备状态为 not requested；后续验收按实际候选、渠道和设备分别记录，不继承为其他 API/OEM 或 Release 的通过。

## Alternatives considered

按目录或名称合并项目会混淆组织身份和文件身份；项目独立复制模型、扩展和权限开关会形成第二套配置。因此沿用上述稳定 projectId、真实目录引用与既有配置入口。

## Consequences

多会话可共享项目资料与指令，成员变更不移动文件。项目成员、工作目录和授权仍分别持有身份，执行中变更必须遵守既有事务检查。

## Reconsider when

所有者要求云同步、团队协作或多主目录等超出本机项目范围时重新评审；本决定不预先授权这些能力。

### 2026-10-05 抽屉工具分组

所有者要求终端、文件管理器、浏览器合为一级“工具”分组，放在扩展与工作之间；应用存储、诊断与审计移到工作。当前顺序为会话、项目、模型、扩展、工具、工作、设置。仅调整导航归属，不合并执行模块或改变已有路径/权限。

### 2026-10-21 抽屉账号与固定设置入口

Owner 采纳 HTML 原型先行、Compose 实现的方案。账号独立固定在顶部；滚动内容为新会话、当前会话、全部会话、项目、模型、扩展、工作、工具；底部固定设置与权限模式。全部六个设置分类保留在有界底部面板，选择后返回原导航职责，不增加设置权威或修改项目、会话的归属。宽度与账号生命周期边界见 [Provider 决策](../provider/001-models-and-connection.md#decision-history--2026-10-21账号入口与原生-ui-设计流程)。

### Decision history — 2026-11-04：统一项目与新会话草稿

Owner 要求普通新会话可选或创建项目，项目内新建和项目文件问答保留项目、目录并统一草稿。普通入口默认不选项目；项目入口预填明确的 projectId 与主目录，项目文件“新会话”沿用该项目及目录，“当前会话”不更改原归属或目录。不按文件路径猜测项目，也不扩大文件/工具授权。

项目选择在原会话身份上更新，保留输入、附件、模型和控制设置；取消选择或取消新建项目不替换草稿。显式保存项目可以先持久化项目本身，空会话仍不因此保存。会话元数据、成员关系、目录与控制配置在首次需要持久状态时同事务保存；除发送外，现有附件、设置和非空输入缓存也可能触发保存，不声称一律延迟到首次发送。项目修订、归档、删除和目录可用性在草稿持久化时重验，失败保留草稿，不自动改用另一目录。

输入缓存保存后的空会话仍允许通过新会话项目选择预填目录，但必须在同一事务确认从未有消息或 Turn；已有会话的加入/移出项目仍只改组织归属。运行中成员变更继续由既有持久忙状态拒绝。未发送的项目会话遇目录失效时，打开或发送不自动换目录；已有实际对话的目录恢复沿用原 Workspace 契约。持久化后的项目、目录、输入缓存和附件按原身份恢复，重启不自动发送。项目与工作目录在会话设置中查看和选择，可由项目选择器进入项目详情；聊天输入区域不常驻这些次要元数据。

### Decision history — 2026-11-04：会话次要信息按需披露

Owner 明确拒绝聊天页常驻“不属于项目”、工作目录和空成果等信息，要求沿用已有设置、详情和三点菜单。先前把项目及目录写为聊天输入区常驻内容是实现者未落实 AGENTS 精简规则的判断错误，本次修订该条，不归因模型或样例不足。项目选择／创建与目录选择统一留在会话设置；顶部详情提供设置入口及固定成果入口，空成果在打开后的面板中说明，不重复展示目录及其选择入口。底部输入选项不重复项目和目录；未知上下文不显示问号占位，详情可在输入选项中按需查看，实际上下文比例和持续风险仍可保留必要可见性。草稿身份、输入附件保留、目录授权和已有会话归属的行为契约保持不变。

### Decision history — 2026-11-04：统一会话设置与稳定成果入口

Owner 指出隐藏空成果时连导航入口一并隐藏，随后要求统一优化设置、层级与重复入口。成果入口固定保留于会话管理，包含空草稿；打开后显示实际列表或空状态，关闭后不在聊天页新增汇总。会话设置按会话、工作上下文、权限与扩展组织，使用带当前值的设置行；会话模型选择器只保留来源配置入口，模型目录管理留在来源管理页面，目录技术说明按需查看，具体失效和只读事实仍可见。权限由摘要进入现有完整编辑器，草稿持久化与打开编辑器在一次操作内完成；失败原地提示，不报告成功。项目和目录保留原身份、授权与草稿约束。重命名统一到管理菜单，保留未发送草稿改名；任务进度归入本会话任务，保留原条目和执行／回收行为。

### Decision history — 2026-11-05：消息添加入口按作用域归类

Owner 要求删除会话模型选择页的“管理对话模型”，合并图片与文件，并明确保留模型尚未配置时的首次使用快捷入口。会话选择器保留通用来源配置和未配置来源的上下文快捷配置；前者用于主动管理来源，后者缩短首次使用路径，不删除全局来源页的模型目录管理。添加菜单合并为单一“图片或文件”选择器，继续使用系统文档选择、原私有附件处理和来源会话校验，取消与迟到结果不发送消息、不跨会话附加。按 Owner 明确偏好，专家和插件保留加号入口，删除会话设置内的重复入口；已选状态上的快捷修改保留。技能的“使用技能”加入当前消息，不修改启用状态；设置中的“会话技能开关”控制该会话持续可用性，两者不合并。连续转写归入麦克风，见语音 ADR，本会话成果入口维持固定。

### Decision history — 2026-11-05：项目默认目录与会话目录分开编辑

Owner 要求统一会话目录体验。项目目录仅是新会话的默认起点；同一项目下允许会话使用独立目录或其他已登记目录，已有会话加入／退出项目继续仅改变组织归属。会话目录选择器支持显式使用当前项目目录；此选择不意味着后续跟随项目设置变化，项目编辑不改绑已有会话。项目编辑也从已选目录打开，并明确使用“更改目录”动作。目录说明和身份保持在会话设置／详情；具体资源与切换契约见 [ADR-WORKSPACE-004](004-workspace-binding.md#decision-history--2026-11-05工作目录的用途与显式切换)。


### Decision history — 2026-11-05：删除完成回复下的重复成果入口

Owner 再次指出任务完成后回复底部的成果按钮与会话管理重复。此前精简验收只覆盖项目、目录及会话级成果标签，没有覆盖旧逐轮成果组件，是实现与验收遗漏。移除聊天时间线的逐轮成果入口及专用加载／刷新实现，成果统一从既有会话管理进入，保留任务管理的原任务成果查看、资源身份和预览／交付能力。实际产生成果的会话验收同时检查正文无逐轮按钮、管理入口可打开实际产物并预览；不以无成果场景或菜单入口存在代替该检查。
