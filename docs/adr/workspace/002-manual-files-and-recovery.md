# ADR-WORKSPACE-002: 独立文件管理与传输恢复

Status: accepted
Date: 2026-09-16
HXA: HXA-173, HXA-180, HXA-182
Deciders: Project owner（当前有效决定；授权按需求合并重编，不新增功能接受范围）

## Context

文件管理需要独立可用，外部存储权限与中断恢复必须如实表达。

## Decision

- 手动文件管理入口不经过 Agent Loop。两变体按实时 Android 授权访问 Workspace、共享目录和可写 SAF；拒绝/撤销提供恢复入口和 SAF 替代，不承诺访问其他 App 私有目录。
- 手动 resolver 与 Agent resolver 分离；手动授予的共享范围不自动扩大工具权限。UI 不直接访问存储基础设施。
- 支持浏览、预览、分享及实际后端允许的新建、重命名、复制、移动、删除。API29 写入和 API30+ 共享访问按对应平台能力检查；Provider 声明与执行结果共同决定可用性。
- 复制流式写入临时兄弟节点，验证大小/哈希后发布；移动在目标确认后删除源。同名不默认覆盖，显式覆盖先保存可恢复旧目标。目录批量操作和取消返回逐项部分结果，不宣称跨文件事务。
- Workspace 使用回收站；手动共享/SAF 的永久删除必须明确告知并确认。不允许修改存储根或内部控制状态。拟议的 Agent 可恢复外部删除是另一契约，不能把手动永久删除包装成可恢复。
- app-private noBackup 保存版本化、同步后原子替换的传输 journal，含 scoped 路径、操作 ID、阶段和内容指纹。操作与恢复串行，不能清理正在运行的操作。
- 恢复由用户发起，重验授权和资源。发布前回退旧目标并清理本次暂存；发布后校验目标、清理已验证备份、保留源剩余部分。不自动重放移动源删除，冲突/损坏/未知版本保留记录供核查。此机制不承诺字节断点续传或持久后台队列。

## Decision history — 2026-10-04：稳定文件首页与会话辅助入口

所有者明确要求文件功能作为独立文件管理器。首页以手机存储、固定常用文件夹和用户添加的位置为主，不将每个会话工作目录投影成一个首页存储位置；位置切换菜单遵循同一分类。Helix 本地文件是稳定的独立文件区，不能随当前会话改指向。

会话工作空间集中在单一辅助入口的可搜索列表中，保留真实目录身份、不可用状态和原清理保护。新建或切换会话不得改变当前浏览目录。默认会话目录的创建、绑定、工具授权与文件保留规则保持有效；本决定仅调整手动发现与导航，不删除或合并会话数据。

常用文件夹入口指向共享存储实际目录（下载、文档、相机、图片、视频、音乐），不是全盘 MIME 分类索引。授权不足按既有平台流程请求，拒绝或撤销显示失败并提供添加指定文件夹的替代；不得静默切换到会话目录。手动导入明确标出稳定的 Helix 本地文件目标。

## Decision history — 2026-10-04：文件交接与位置引用

所有者要求按竞品实践优化文件与会话流程，实施归入 [HXA-247](../../development/tasks/HXA-247.md)。文件首页保留独立存储定位，显示“Helix 文件 / 保存在应用内”；最近打开和收藏仅保存 scoped 位置及文件/目录类型，打开时重新验证真实位置。移除记录不删除文件，路径移动或撤权后不猜测替代位置。记录有界、版本化，写入成功后才发布新状态，未知版本/损坏不静默覆盖。

“添加到当前会话 / 在新会话中处理”明确为附件副本入口，沿用分类、大小限额、导入和发送前检查；不会自动发送或赋予模型原文件写权限。SAF/工作空间分享允许按现有后端生成有界运输副本，向附件保留原显示文件名。新会话沿用当前精确模型，无模型时仍能准备附件。

“在此目录开始任务”仅向原绑定器支持的 Workspace/SAF 位置开放；先验证目录，再创建草稿。手动手机存储与 Root 浏览权限不能作为 Agent 权限。捕获原会话身份，异步阶段切换会话后拒绝重定向。

成果仍引用原文件；会话、任务和成果页共用真实可用性检查与交付操作，文件管理器定位使用成果原始 scoped 路径。分享完整文件与分享预览文本分开表达；预览或记录引用都不承诺可恢复修改。全局修改清单、修改前快照与冲突恢复仍需独立的正确性设计。

参考 [ChatGPT projects and chats](https://learn.chatgpt.com/docs/projects?surface=app) 的可选项目和资料交给具体会话、[Claude Cowork projects](https://support.claude.com/en/articles/14116274-organize-your-tasks-with-projects-in-claude-cowork) 的本地目录组织（2026-10-04 查阅官方文档，未逐家实机验收）。Helix 按 Android 实际存储授权落地，不照搬桌面权限模型。

## Decision history — 2026-11-03：执行回执与文件恢复分离

所有者要求复核主流 Agent 实践并优化文件结果保留。采用“持久执行事实、真实文件、可选备份分别管理”：`write` / `edit` 的成功回执记录目标、写后 `sha256` 和字节数，带哈希前置条件的写入额外返回经发布检查的 `previousSha256`；未检查旧版本的写入不虚构旧哈希。回执不是文件内容副本，哈希也不保证文件之后未再变化。模型重试、任务失败或取消不回滚已经发生的修改。

按任务需要保留可恢复版本时复用 `files.copy`：复制到明确的用户文件路径，确认返回哈希与接下来修改的 `expectedSha256` 一致，再执行修改；冲突则重新观察，不能把不一致的备份当作修改前版本。备份是普通持久文件，按实际目录授权、空间与清理规则管理，不随当前 Turn 结束自动删除。不新增默认全盘快照或另一套执行器。

恢复须由用户意图触发并重新走正常工具授权。文本可读取备份后用带当前 `expectedSha256` 的 `write` 恢复；若当前内容已不同于修改回执的写后哈希，先报告冲突，不擅自覆盖。现有 `files.copy(overwrite=true)` 没有调用方指定的目标版本条件，不能冒充冲突安全恢复。二进制版本回滚、跨文件事务及自动检查点 UI 本轮未实现。新建文件的删除同样是独立工具动作，不是取消的隐含后果。

直接修改源文件、执行副本和成果引用继续遵循 [Workspace 绑定](004-workspace-binding.md)：发布成果不代表源文件写回，临时执行材料也不代表持久备份。终端/脚本或外部工具的任意写入不在文件工具备份保证内。

依据：[Claude Agent SDK file checkpointing](https://code.claude.com/docs/en/agent-sdk/file-checkpointing) 将可选写前备份与会话回退区分，且有工具覆盖边界；[LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence) 将会话状态检查点与其他持久存储区分。这里只采用分层与显式恢复原则，不宣称这些产品提供统一的外部副作用事务。实现证据为文件工具主机回归；不代表所有存储 Provider 或设备均已验收。

## Decision history — 2026-11-04：文件浏览与首页入口

所有者要求调整文件管理器布局：收藏和最近打开置于存储位置之后，双向同步归入导入与传输；首页提供明显的 Helix 文件回收站入口，其他工作空间仍使用原有位置内回收站。回收站仅适用于现有可恢复存储边界，不扩展为手机共享存储或 SAF 的全局回收站。

目录三点选项收纳收藏位置、顺序与视图。顺序支持名称、时间、大小、类型；类型按扩展名分组、同类型按名称，目录始终在前。新建文件创建空文件，拒绝同名覆盖，沿用手动后端的实时权限、路径与区域约束；不授予模型权限。

点击文本或图片进入全屏只读查看器，关闭后保留目录及滚动位置；文本可选择复制。查看器统一对本地、共享存储、Root 与 SAF 使用 1 MiB 文本和 8 MiB 编码图片边界；超过文本上限明确提示只显示开头，图片超限不解码并提示通过分享打开。SAF 图片须读取完整字节，不能把前缀当完整图片。文本按有界块惰性布局，图片先读尺寸再采样到不超过 2048 × 2048 像素；损坏或不支持的图片明确显示解码原因。不宣称文本编辑器或无限制大文件支持。此调整不改变公共目录和 SAF 原件访问、分享副本及会话附件语义。

交互参考 [Files by Google 的查看与排序说明](https://support.google.com/files/answer/9765314?hl=en) 和 [GNOME Files 的类型排序说明](https://help.gnome.org/gnome-help/files-sort.html)，仅采用交互原则，不复制实现。实际验证以本轮主机与指定模拟器回归记录为准。

## Alternatives considered

让手动文件操作经过模型会增加不必要依赖；启动时自动重放移动可能重复删除；把 SAF 当 POSIX 会夸大原子性。均不采用。

## Consequences

同一主题使用一份有效契约，避免并行实现各自解释权限和生命周期。代价是实现、UI、数据与恢复需要一起验证；accepted 表示决定，不代表相关任务全部完成。

## Verification

本次为现行决策整理，不新增功能通过结论。实现范围与实际命令结果以[实施状态](../../development/status.md)、对应 HXA 及完成记录为准；修改本契约后须覆盖成功、失败、取消、边界和恢复，不能用文档门禁代替设备/功能验收。

## Reconsider when

产品所需能力超出本决定边界，或平台、依赖、资源和设备证据证明当前方案不可行时重新评审；普通实现修复不另造一套决策。
