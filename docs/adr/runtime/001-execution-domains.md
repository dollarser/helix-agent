# ADR-RUNTIME-001: 执行域、打包、生命周期与结果对账

Status: accepted
Date: 2026-09-16; revised 2026-10-17
HXA: HXA-083, HXA-084, HXA-085, HXA-086, HXA-103, HXA-110, HXA-111, HXA-112, HXA-113, HXA-117, HXA-190, HXA-193, HXA-286, HXA-288
Deciders: Project owner（2026-10-15 要求按评审更新目标设计和任务；接受范围见 Decision，实施另计）

## Context

单应用体验需要清晰区分进程崩溃边界、UID 权限边界和模块凭据所有权。

## Decision

- developer 是单 APK，Subscriptions 与 PRoot 为 Android library，分别在 non-exported :subscriptions/:proot 私有进程中按需运行。consumer 的依赖、manifest、dex、assets/native 制品排除两模块。模块名不决定是否独立 APK。
- 本轮 isolated UID PRoot 验证未能承载现有 RootFS/工作目录模型；按所有者选择保留共享 UID 架构，不增加统一禁网开关、离线 Shell 或独立 Runtime APK。证据见[可行性记录](../../evidence/development/isolated-proot-feasibility-2026-09-16.md)。
- 私有进程共享应用 UID、文件系统权限和网络能力。PRoot 是可信开发者执行环境，不是恶意代码沙箱，不保证离线、只读工作区或订阅凭据隔离。QuickJS 使用 isolated UID；生成代码不在主进程执行。
- 凭据由订阅模块管理，正常 API 不返回 token；同 UID 代码仍可能访问应用数据。可用模式不能虚构运行时隔离，限制写/网络须有真实机制或拒绝无法约束的调用。
- 冷绑定只由用户验证、修复、登录或获准执行发起，启动应用、切换 Profile、被动 Registry 不启动执行。Runtime 进程不执行主应用 AppContainer/Room 的启动恢复。
- 私有 Binder/PFD 传输有界、校验完整性并绑定 Job ID、generation、目标与 owner。主应用拥有任务和授权，Runtime 拥有执行及退出事实，UI 仅发出用户意图与观察。
- 同步 Job 在 owner 丢失后遵守取消与结算；明确获准的 detached Job 由有期限 Runtime owner 管理，不把所有命令默认为持久后台任务。仅在 Android 实际允许的运行窗口启动/保活，系统拒绝、超时、停止后如实释放。
- Binder 断开、超时和进程死亡查询原 Job；未知副作用进入待核查，不盲目重放。终态、取消、失败、EOF 和未知结果都持久化，导回输出经身份、哈希、scope 与冲突检查。
- 安装/修复/更新必须对应真实当前环境，不沿用旧验证记录作为可用或授权证明。数据转换保留用户文件和结果；无需维护跨 APK 的安装与兼容执行路径。
- Advanced 内置 Linux 环境默认可按需使用：首次已获准的新作业或人工终端启动自动准备缺失资源，注册/设置/查询/恢复不触发安装。已有损坏或不匹配环境由用户明确维护；自动准备不授予命令执行权限，不改变原调用身份、预算、取消或容量结算。
- 安装事实来自当前激活记录、版本和必要文件；不保留手动验证记录、新基线确认或独立 APK 的双重删除流程。检查安装与真实任务执行分开表达；维护只在无相关执行占用时进行，取消确认不改变安装状态。

### 执行、观察与产物接缝（HXA-288）

按[统一执行任务](../../development/tasks/HXA-288.md)收敛直接调用、观察、启动后观察；共同契约不将文件操作变成 Job，也不将所有工具拉进一个 Runtime。Runtime 负责原执行和物理退出，应用负责调用结算、授权和产物引用。

身份/归属及完成语义沿 [HXA-286](../../development/tasks/HXA-286.md#共同契约与退出条件)与现行 ADR/实现；2026-10-24 后续计划以已有执行/Engine/Room 为基线，288 仅按真实缺口局部收敛，与 287 实际命令改动联验，不重建执行核心。调用返回、实际退出、输出收尽、结果落盘分别有证明；Runtime 负责执行/输出通道事实，应用原子命令负责持久结果。MCP/HTTP 和原生回调保留实际语义，不伪造 POSIX 退出码，不要求每个工具创建 Job。

原执行句柄、generation、owner、lease 与取消事实保留；等待到期、停止观察、请求取消、终态和真实退出不能相互替代。已退出证明之外不释放物理容量，收取/ACK 复用原身份，不重放原命令。结果与产物用途类型化后接入现有导入/发布路径，不建立第二 journal 或执行注册表。

cancel requested 与 confirmed 分开，确认受理不证明已退出或效果回滚。进程退出时仍未收尽的输出继续由原通道 owner 处理并标完整性，不能靠进程终态提前删除输出。每片验证迟到回调、大输出/截断、外部效果后落盘前崩溃及插件缺失；这些反例不留到最终冻结才验证。

共享 UID、隔离 UID、Binder、Root/Shizuku/无障碍和平台前台运行窗口仍按真实机制定义；ExecutionTarget 名称不证明隔离或授权。

### 调用与长期资源身份

HXA-286 定义、288 实现的公共接缝分别表达 turnId/toolCallId、jobId/executionId、长期 ExecutionResource 的 resourceId/实例 generation、控制权与生命周期 owner，产物沿原 artifactId/引用关联。资源可由其真实会话、项目或获准后台 owner 持有，实际适用类型由消费者决定；不得强迫所有资源以当前 ToolCall/Turn 作为存活上限。共享引用、物理容量和租期独立，停止一项观察或释放一个消费者不结束其他有效使用；句柄不是可转让权限。

恢复先按原实例对账，进程死亡可以使资源失效，不重建 shell 内存、不重放输入或把“有持久句柄”当“进程仍存活”。当前执行形态不是永久封闭的能力枚举，未来长期服务的控制仍可经普通受治理调用实现。本轮用已有 Job/原生共享资源证明边界，不新增服务管理平台或空 LSP/终端后端。

当前版本重启 reconcile 由既有主应用恢复入口协调，Runtime 提供原实例查询/输出/ACK；查不到或结果未落盘不证明零副作用，UNKNOWN 不盲重放。资源 owner 在真实使用结束且最后有效引用释放后清理，产物库按原持久引用/GC 回收；清理失败保留诊断，不误删其他消费者或复活旧 Turn。

### 目录与环境适配（2026-10-17 目标契约）

Runtime 环境、RootFS、Workspace 工作副本和产物分别归属；适配报告实际 environment/generation、cwd、live/snapshot 模式及输入映射。PRoot 快照是文件准备方式，不提供额外 UID/凭据隔离，不能称为恶意代码沙箱。2026-10-21 Owner 授权的 Job 原位切片按 [终端与 Job 决策](002-terminal-and-jobs.md) 接线：支持的真实目录默认原位，显式快照与 SAF 边界保留；不把本轮主机结果外推为 286/288 全部资源及设备验收通过。

未来新增远端后端须先有具体执行旅程，再验证 endpoint 认证、环境身份核验、传输授权、租期、去重回执和原实例对账；断连不证明未执行，不自动换实例重跑。保持一个 Turn 持久 owner，不预建远程服务/节点注册平台。共享契约见 [Harness §23.3.1](../../architecture/harness-refactor-plan.md#2331-目录资源与执行环境)，不能用远程产品 VM 恢复能力推断本机 shell 内存可恢复。

## Alternatives considered

多个独立 Runtime APK 增加安装与升级成本，不作为当前形态；把 PRoot 改成 isolatedProcess 不能自动提供可用 RootFS/文件访问；把生成代码放主进程不符合执行边界。官方 CLI 原生/PRoot 候选不单独保留为当前必做要求。

## Consequences

同一主题使用一份有效契约，避免并行实现各自解释权限和生命周期。代价是实现、UI、数据与恢复需要一起验证；accepted 表示决定，不代表相关任务全部完成。

## Verification

本次为现行决策整理，不新增功能通过结论。实现范围与实际命令结果以[实施状态](../../development/status.md)、对应 HXA 及完成记录为准；修改本契约后须覆盖成功、失败、取消、边界和恢复，不能用文档门禁代替设备/功能验收。

## Reconsider when

产品所需能力超出本决定边界，或平台、依赖、资源和设备证据证明当前方案不可行时重新评审；普通实现修复不另造一套决策。
