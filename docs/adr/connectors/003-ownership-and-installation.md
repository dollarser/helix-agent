# ADR-CONNECTORS-003: Connector 安全替换、安装归属与会话启停

Status: accepted
Date: 2026-09-22; revised 2026-10-11
HXA: HXA-129, HXA-235, HXA-272, HXA-274, HXA-275, HXA-276, HXA-277
Deciders: Project owner（2026-10-11 要求将插件优化任务同步为 ADR，采用单一目标实现、不兼容旧版）

## Context

Connector 安装同时涉及 Skill 快照、注册记录、端点配置和凭据。决策时 MarketplaceService 在不同 hash 的替换中先卸载再安装；ConnectorService 先注册 Skill，再原子发布 Connector JSON。单文件 ATOMIC_MOVE 不能把这些操作变成同一个事务：后续失败或进程死亡可能丢失旧配置，或留下已注册但未归属的 Skill。

决策时 remove 会保护其他 Connector 引用的 Skill，但不能完整表达独立用户安装的归属。问题需要解决，但不需要因此建设通用安装事务引擎、代码 Diff 页面或新的会话权限系统。本记录已获授权；设计接受不是实现或验收证据。

## Decision

采用“完整准备、一次发布、可重试清理”实现端侧安全替换。优先复用现有存储和安装入口，不新增场景执行引擎。

本文按现行 Plugin 领域维护包、组件、会话选择与原生资源的契约，保留 ADR 编号以维持主题归属。HXA-272～277 的新增条款为已接受、待实施的目标；既有 HXA-129/235 的交付不能证明本轮增量完成。

### 1. 稳定身份与最小归属记录

区分稳定 Connector 身份、不可变内容 hash 和显示名称。市场条目身份包含可信来源及 packageId；本地导入保留独立安装身份。不得仅凭同名或相同内容认领另一个安装。相同目标身份、相同 hash 的重复安装返回已有结果；替换请求绑定预期旧版本，旧版本变化时重新计算目标，不能覆盖并发用户修改。

清单引用准确 SkillKey（source/name/snapshotHash），最小引用记录区分独立用户安装与包引用。移除包只撤销它自己的引用和启用意图；不得禁用或删除仍属于独立用户或其他包的内容。内容缺失或归属不一致时明确诊断，不按名称猜测所有者或批量清除资产。

端点不因 URL 相同而跨包共享账号。安装归属不是 Tool Approval，实际调用继续通过现有 Dispatcher、Capability、Policy 和授权解析。

### 2. 每个会话独立启停 Connector

设备安装回答“有哪些包”，会话选择回答“本会话使用哪些包”。每个会话持久保存按稳定 connectorId 标识的启用集合；用户可在会话能力面板独立开关，不影响其他会话。复用已有会话设置和组件启用基础，不另建通用 scope 框架。

新会话创建时复制用户默认集合，随后独立保存；更改默认集合不追溯修改已有会话。外部包不因安装自动加入会话；产品捆绑默认集合显式包含 Browser，用户可在现有入口取消，不能用产品默认覆盖用户已保存的选择。删除会话只清除它的选择，不卸载包或删除凭据。复制/fork 复制选择值，不共享可变设置或活跃调用身份；目标包不存在时显示不可用，不自动安装。本轮不转换旧版会话选择或批准。

会话开关控制该包提供的 Skill、MCP 与 native 工具。可用性按组件核对已提交引用、当前会话选择及各自规则；一个未配置 MCP 不使独立可用的 Skill 失效，纯 Skill 包不要求 published tools。内容读取与调用资格由 [ADR-SKILLS-001](../skills/001-authoring-and-installation.md)定义；工具显式禁用及现有授权规则仍生效。打开插件不强行启用被单独禁用的工具，不自动登录、提升授权预设或修改其他来源。面板区分“已选择”和“需配置/不可用”，并提供现有修复入口。

关闭 Connector 撤销的是本会话的这一来源。相同准确 SkillKey 若仍由独立用户安装或其他已选 Connector 有效提供，可以继续可用，界面说明剩余来源；单独全局启用一个包内 Skill 不得绕过该包的会话开关，必须有独立安装归属。不同端点身份不按 URL 自动合并。用户要完全禁用某个工具时使用既有工具禁用项，不创造新的权限优先级。

选择变更在下一次上下文构建生效：不再注入关闭来源的 Skill 指令、目录和工具 schema；Skill list/read 与实际工具调用均按可信 sessionId 校验，不能只在 UI 隐藏。已经进入历史消息、摘要或正在发送的请求中的内容不会因此被擦除，也不能承诺模型忘记它；保留历史及审计，不靠删除历史实现启停。

运行中切换不要求取消整个 Turn，普通 Turn 与 Goal Turn 适用同一规则。尚未发送或正在等待批准的调用在执行前重新检查会话选择，失效则按现有失败/取消结算路径返回明确结果，不能因旧 schema 或旧审批继续执行；连接前校验一次，并在tools/call前最后一次同步校验；该校验通过是本地发送准入的线性化点。用户关闭若先完成则取消调用；若发送准入先完成则按已获准发送继续结算，不承诺关闭返回后网络绝不会再发出字节。已经发送的调用继续结算，不盲目重发，不承诺撤回远端效果。恢复后的会话重新读取持久选择，模型及扩展内容不能修改这些开关。

会话绑定稳定安装身份，普通更新保留选择并解析到当前已提交版本；目标或认证变化仍按下一节处理，不能借保持选择跳过配置。卸载后相关选择标为不可用或移除；新安装身份不能仅凭同名继承选择。此任务不提供每会话固定不同版本或独立账号副本。

### 3. 更新体验与凭据绑定

更新页只需作者更新说明、版本及简短组件变化摘要；没有说明时如实显示。无需逐行 JSON/Markdown Diff，不新增每次更新都要通过的独立审查弹窗。用户点击更新即表达对所展示目标版本的安装意图；安装不自动批准后续工具执行。

摘要绑定旧、新内容 hash。新增或改变的网络目标、认证要求在现有配置/启用入口明确展示；需要重新配置或登录时直接引导修复。目标及认证绑定完全未变时保留现有配置和凭据；URL 路径、origin、OAuth issuer/resource/client 等实际绑定变化时不得盲目复制 token，受影响端点保持未激活直至完成相应配置。其他未变端点不要求重复登录。

复用既有 Skill 与端点启用契约，包括市场独立 Skill 的显式安装流程。HXA-235 增加单一包停用事实：只收紧新准入，不撤回在途效果、不扩大审批；重新启用不能复活旧绑定。该事实位于原安装清单，不新增平行状态系统。签名仅证明来源，不能替代用户更新操作、启用或工具授权。

### 4. 最小提交与恢复协议

先在暂存区完整验证候选包及所有组件；提交前不卸载旧版本、不删除旧凭据，也不让候选组件通过独立 Registry 扫描提前生效。准备失败、取消、低空间或写入错误均保留旧的有效安装。

优先使用不可变候选内容及单一权威已提交清单/指针发布目标版本，再幂等清理无引用旧内容。所有相关列表、启用和执行入口必须依据已提交版本，不能只保证 Connector 页面看起来完整。文件方案须说明同卷原子替换、持久写入和平台支持边界；原子 rename 不等于断电持久性证明。

采用 Room 作为唯一已提交安装事实源，保存稳定安装身份、来源身份、revision、完整组件清单、最小 Skill 归属和会话选择。不可变文件内容在 SQL 事务外准备；所有生产可用性入口依据已提交引用。旧 Connector JSON 导入及旧存储迁移不再是目标实现，不保留双写或备用事实源。仅在无法由提交清单和引用推导恢复动作时增加最小恢复记录；不强制 PREPARING 等多阶段 journal、全局 generation 或通用 WAL 框架。

提交前进程死亡：旧版本仍有效，只清理可证明未提交且无引用的暂存内容。提交后进程死亡：按已提交事实恢复并重试清理；重复请求返回既有安装结果，不重放网络或工具调用。清理失败不得使完整的新版本不可用；确实缺失有效内容时仅标记受影响组件待修复。Secret 不写入清单或恢复记录。

更新不把未发送的旧配置调用静默改投新端点；调用前核对版本/目标及现有授权。已发送调用继续按原配置结算，相关引用释放后才清理；不声称更新能撤回远端副作用。不为此引入新的通用执行调度器。

### 5. 单一目标实现与支持范围

本轮直接替换旧 Skill 注入、Browser built-in 发布及受影响内部接口；不安排旧数据库、旧会话、旧精确批准迁移，不保留双注册、双写或兼容 adapter。开发期存储沿用现行 baseline 规则；设计变更不授权删除用户文件、凭据、产物或审计，也不在文档更新时操作数据。

当前外部包格式的互操作支持独立于旧 Helix 兼容。用户明确重装或选择其他包版本时，仍须通过当前支持矩阵和同一安全替换路径；不恢复被撤销凭据或旧审批。不建设历史版本浏览器、无限快照保留或一键回滚系统；暂存及旧内容清理有空间边界，且不能清理仍有归属或运行中引用的内容。

HXA-235 保留持久安装、共享快照、取消更新、卸载和进程死亡的验收归属；HXA-272/274/275/276/277 各自承接内容、状态、诊断、Browser 贡献和原生资源增量。新接口进入现有 ToolRegistry/Dispatcher/Policy/Approval/Audit，契约变化直接失效旧绑定，不建立旧批准转换通路。

### 6. Plugin 统一领域（HXA-235）

包导入、安装、版本、组件归属和会话选择归入 Plugin，继续使用原 Room 表及提交点；Connector/MCP 只承担连接组件职责。Host Native 的源码注册表是已提交安装的投影，不是第二个安装事实。原生组件只能由 APK 内可信 composition root 登记，远程 manifest 数据不能加载宿主代码。插件用户启停由会话选择控制；内部停用事实保留故障隔离和旧状态恢复用途，不再展示全局启停按钮。内置包允许修复，代码更新随 APK，不冒充能够单独卸载 APK 内代码。

Mobile Use 的宿主调用 context 按该可信插件实际声明的完整 descriptor 匹配，不凭 `ui.*` 前缀分配会话范围。这个匹配只提供路由事实；已发布 binding 身份、会话选择、实时权限、取消与审计仍由原 Dispatcher 路径执行。插件不建立第二个 AgentLoop，`extensions/mobile-use` 拥有自动化引擎、工具、内置 skill 与运行交互；`tools/device-access` 只提供 Helix 持有的系统授权查询/申请及按使用方隔离的 Root 连接，不依赖插件。

### 7. 用户入口与安装后使用（2026-10-04）

扩展统一从“已添加 / 发现”进入，添加、导入和技能创作收进添加入口；MCP JSON 是高级接入方式，不是与插件平行的安装领域。已添加卡片显示组件配置状态，详情承载更新、修复、组件配置、默认新会话启用和卸载，不展示插件全局启停。安装后的使用操作进入会话能力面板；Mobile Use 卡片的使用入口仅展示自身。安装本身不登录、不授予执行权限，也不自动影响其他会话。

会话面板同时呈现包与独立技能。仅由包拥有的技能在包内管理；同时有独立归属的技能保留独立入口。默认集合、会话选择、组件配置及执行权限继续是不同事实。组件配置完整不表示 Android 系统权限全部可用；Mobile Use 仍按功能判断和补充授权。不新增专家执行引擎或伙伴领域。

### 8. 就绪原因与配置生效（HXA-274）

UI、模型目录和诊断使用同一只读投影，表达准确来源及原因：组件不支持、待配置、未连接、宿主不可用、当前会话未选择或当前请求能力不可用。区分安装 revision、已保存配置、实际加载/握手事实及请求绑定；“下一请求生效”“连接未重建”等反馈必须有对应事实，hash 等实现身份只放详情。

复用 HXA-271 的 Mobile Use 配置预检查、授权状态与先解释再进入设置的恢复入口，补齐 Skill/MCP/Browser 的同源投影。被动打开、搜索和状态读取不申请系统权限、不发起 OAuth、不连接 Root、不重启 Runtime 或运行模型。执行前仍由 Dispatcher 重新准入，投影快照不作为授权证明。相似能力显示实际提供方、目标/后端和账号标识，不按同名或 URL 自动合并；诊断不含凭据。

恢复动作以目标类型、必要会话/来源身份和原因数据交付当前 UI，由用户点击后导航；服务不保留页面导航闭包。重订阅、旋转、页面替换或状态重新发布不能自动导航、授权或执行；旧目标失效不能作用于另一个会话。HXA-274 迁移实际消费者并删除所涉旧回调，保持 HXA-271 原解释/取消行为；应用命令和表现职责归 [ADR-AGENT-001 §1.2](../agent/001-turn-coordination.md)。模型可以读取就绪事实，不能借恢复目标数据取得用户动作权限。

### 9. 组件支持矩阵与作者样例（HXA-275）

当前实现与格式子集见[作者指南](../../development/plugin-authoring.md)：Agent Plugins 1.0.0及列出的既有外部入口只承诺受支持组件；标准包不等于Standard渠道。必要/可选依赖仅报告声明，optional外部扩展不宣称Claude标准；运行时条件单列，未实现依赖求解。外部native清单不能提供工厂；已知native示例复用APK自有Chat Reply的零工具内容路径。

同一包解析结果提供组件/字段路径、支持级别、原因及现有恢复动作，供预览、安装摘要、readiness 和模型结果使用，替换字符串前缀与 UI 重复推断。矩阵区分“可用、需配置、仅保留元数据、不支持”；识别字段不能被解释为执行承诺。矩阵列出当前格式的 Skill、HTTPS MCP、APK 已知 native、注册 app 映射、stdio/桌面依赖、hooks、Agent 定义、命令、LSP、依赖、配置 schema 和 Skill 调用字段的实际支持级别。

包安全校验失败整体拒绝；格式允许隔离的组件失败只影响该组件。必要/可选依赖与实际运行条件分别诊断，不自动下载运行时或创建占位 server。未知执行语义不能作为主 Agent 指令执行；任意 hooks、LSP、子 Agent、Code Mode 或导出 MCP server 不由矩阵登记取得执行资格。

纯 Skill、宿主已知 native、远程 MCP 三种作者样例使用生产解析、安装、选择和调用路径，MCP 用受控服务替身完成协议验收。支持矩阵每项有成功或明确拒绝 fixture；真实 OAuth/账号验收继续由 HXA-125/126 承接。样例随能力交付，不另造 SDK 或市场平台。

### 10. 原生贡献与 Browser 默认选择（HXA-276）

插件是交付及能力贡献单元，传输按真实执行边界选择；原生、进程/IPC 适配和 MCP 均进入同一工具治理链。Mobile Use 保持 native，不为对齐参考产品增加 MCP 回环。宿主保有系统授权、连接服务与 Agent 执行所有权；插件不拥有第二个 ModelClient/AgentLoop。

Browser 由 APK 已知的 `:extensions:browser` 贡献 manifest、现有 12 个工具及网页任务 Skill，App 注入已有 bridge/视觉服务。工具仅以该插件的 PluginOrigin 原子发布，直接删除旧 built-in 注册，不做来源或批准转换。Browser 在两个渠道的产品新会话默认集合中提供，用户选择仍按 §2 独立保存；会话选择不拉起 WebView 或批准网站访问。Activity/WebView 与手动浏览的具体边界见 [ADR-PLATFORM-002](../platform/002-browser-lifecycle.md)。

### 11. 原生实例、共享资源与释放（HXA-277）

本节是 HXA-277 的通用资源决策归属。对实际使用的后端连接、监听器、任务呈现及原生实例，明确宿主服务、插件贡献、会话和调用各自 owner；可释放注册句柄只属于它实际创建或借用的资源。纯 Skill 不创建空 runtime；只提取 Browser/Mobile Use 两个实际消费者所需的最小 port，不引入通用服务定位器或依赖求解框架。

实现前列出 Turn live owner、Scheduler 调度/观察槽位、Executor/Runtime 容量及原执行身份、插件共享引用四类事实的来源与释放条件。原 Runtime 仍是执行退出/结果权威，插件消费原事实，不建立第二份 execution registry、Job/Turn 状态机或取消协议。观察返回、Turn 结算和页面销毁都不能单独推导实际执行结束；仍被使用的资源按其真实 owner 继续持有。

来源撤销先阻止新准入；在途调用按原身份执行停止或结算，executor 真正退出后才释放其使用引用与物理容量；共享资源仅在最后引用释放后由 owner 清理。取消信号、业务等待释放或超时都不能冒充 executor 退出。关闭一个消费者不能关闭其他会话/消费者仍使用的后端，也不撤销宿主系统权限。安装持久状态仍由 HXA-235 的原提交事实决定。

注册、初始化失败与宿主重建必须可追踪到准确实例；迟到回调不能修改替代实例。部分初始化失败只清理本次拥有的资源，重复撤销/释放不会再次生效。必要的类型化结束/撤销通知定义顺序、有限等待及错误传播；清理失败或超时保留未释放事实及诊断，不返回成功、不伪报外部副作用回滚，也不释放仍占用的容量。实际资源最终退出后才结算引用，不另建通用脚本 hooks 或每插件 server 管理器。

跨插件流程由 Skill/Agent 调用各自原工具。可信共享服务复用可以通过宿主注入的最小 port，但必须保留原会话、目标和调用上下文；复合工具调用其他工具仍经 Dispatcher，不直接执行另一插件 executor，不通过接口复用取得新的批准。Browser 的 View/等待引用边界归平台 ADR。

## Alternatives considered

- 所有内置能力先包成 MCP server：当前本机执行边界没有对应收益证据，会增加连接及运行时归属，采用统一治理链和适配器选择。
- 每插件独立容器、任意生命周期脚本或通用依赖框架：超出已有消费者需求，采用真实资源 owner、可释放句柄与最小类型化通知。
- 按工具数量决定 Skill 激活，或将安装/连接/选择合为一个 ready：不能覆盖纯内容和部分可用组件，分别投影且共享诊断来源。
- 先卸载再安装，加 catch 补偿：无法覆盖进程死亡，并会提前删除旧配置或凭据，不满足安全替换。
- 多阶段 journal、独立 owner/scope ledger 与全局 generation：预先锁定过多机制；仅保留实现正确提交和归属所需的最小状态。
- 每次更新要求审查代码 Diff：手机端操作成本高；采用简短更新摘要和实际变化的配置引导。
- 仅展示作者 Changelog：不能解决共享归属、失败保留及凭据绑定，不能替代上述底层保证。

## Consequences

组件状态能区分内容可用、配置保存和真实执行条件，原生资源有明确释放责任。代价是原生贡献必须实现准确引用与失败诊断，UI 需投影多种事实；通过同一数据来源和最小资源接口控制复杂度，不为每插件创建进程或容器。

用户获得失败时保留旧安装、未变配置免重设和共享内容不被误撤销的行为。每个会话能独立选择 Connector，选择与实际曝光、调用保持一致。维护成本集中在提交边界、引用归属及会话可用性读取；不增加多层 scope 继承、插件规划器、版本管理 UI 或重复审批。

## Verification

HXA-129 的最小 Room 提交及会话启停有[历史交付记录](../../completion-records/HXA-129.md)，Plugin 统一归属由 HXA-235 接续；当前整合和开放边界查 status。HXA-272～277 的本轮增量尚未实施，接受本 ADR 不继承旧任务的绿色结论。已有成功重装及安装后重启不能证明安装途中强杀安全。

实施时先记录唯一提交点及所有可用性读取入口。安装验收覆盖候选部分准备失败、提交前取消/强杀、提交后清理前强杀、写入失败/低空间、提交响应丢失后重复请求、同名不同身份、两包共享、独立安装与包共存、未变凭据保留和目标变化重新配置；旧版数据迁移不再是目标要求。

会话验收覆盖 A 开/B 关、默认配置复制后互不影响、重启恢复、会话删除及复制/fork 路径、共享 Skill 的剩余来源、工具单独禁用、更新保持选择但改变目标需配置，以及运行中关闭后的旧 schema/待审批调用不得执行。确认历史保留、后续请求不再注入、已发送调用正常结算，普通与 Goal Turn 行为一致。

HXA-274/275 验收部分可用、配置保存但未加载、过期投影、无 host、无被动副作用及支持矩阵的真实样例。HXA-276 验收单一 Browser owner、默认值/会话选择独立和手动浏览；HXA-277 覆盖两个消费者共享、在途取消未退出、迟到回调、并发启停、部分初始化及清理失败。相交 fixture 只维护一份，不能用新增原生资源验收关闭 HXA-235 的完整安装矩阵。

HXA-274 同时覆盖无订阅与页面重建、重复读取不自动导航、旧恢复目标失效及取消不改变选择/配置；HXA-277 分别断言等待已结束但原 Job 运行、Turn 已结算但 executor 未退出、UI 销毁但其他消费者仍有引用时的容量与资源事实。用原执行 fixture 扩展断言，不重复 HXA-238/236/248 已有执行机制。

确定性故障测试与 API29/36 × consumer/developer 的独占设备恢复验收互补；强杀必须发生在指定提交边界并观察新进程恢复，不以普通安装后重启替代。具体入口归对应 HXA；设备和真实账号在获得当轮授权后执行，文档检查通过不代表功能验收。

## Reconsider when

不能用单一提交事实覆盖现有 Registry 入口、必要恢复状态显著增长，或真实用户需要历史版本、每会话版本固定或多层 scope 继承时，单独审查具体需求和端侧成本，不提前扩建框架。

## Decision history — 2026-10-05：授权归宿主，自动化归插件
