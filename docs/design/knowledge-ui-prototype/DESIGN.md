# Helix 知识库与对话引用设计

2026-10-25，设计提案与离线原型。Android 已接入融合表现层，真实能力与验收以[接入记录](../../development/knowledge-conversation-integration.md)为准，不能把演示交互当作后端交付或权限变更。产品主体仍是对话。

## 调研与采用的取舍

本次读取官方资料，不复制产品源码，不将网页功能概括成所有移动端均支持。

| 官方依据 | 已确认的交互 | Helix 的取舍 |
| --- | --- | --- |
| [NotebookLM / Gemini Notebook：来源选择与引用](https://support.google.com/gemininotebook/answer/16179559?hl=en) | 用户指定来源；引用可跳回原文核对；回答可独立保存为笔记。官方同时提示移动端功能可能受限 | 采用显式来源范围、历史引用和独立保存；不自动把回答变知识，也不声称自动全库理解 |
| [Notion AI：限定来源与页面 mention](https://www.notion.com/help/guides/everything-you-can-do-with-notion-ai) | 可缩小来源范围，使用 @ 指定页面 | 先做好＋选择、搜索、多选与预览。@ 是后续快捷入口，和选择器复用同一引用身份，不复制成第二种机制 |
| [Obsidian：链接、标题/段落定位与嵌入](https://obsidian.md/help/links) | 文件链接、标题/块定位和嵌入用途不同 | “内容有链接”不等于正文已发送。展示本次具体文字、范围与版本；历史不随原文更新而改变 |
| [Readwise Reader：阅读批注](https://docs.readwise.io/reader/docs)、[Ghostreader](https://docs.readwise.io/reader/docs/faqs/ghostreader) | 原始阅读材料与批注并存；其全库 AI 是显式功能且平台存在差异 | 保留原件和记录，不把每条收集自动归纳为知识；本轮不引入自动全库搜索、同步或付费功能 |

这些来源支持局部交互，不证明本提案的效果或 Helix 已具备同样后台。保存版本快照、发送授权和资源范围取自 Helix 自身契约；不是竞品已经保证的行为。

## 内容模型

- **笔记**：用户写下的想法、摘录、过程和待办。保存后就是普通笔记，无需成为“草稿知识”，也不默认要求核对。
- **知识**：用户决定长期复用的概念、方法、经验或结论。可以直接写，也可从笔记、资料或问答整理而来。它是用途，不是正确性认证。
- **资料**：原始来源资产，保留原件、来源与提取状态。原件、可读正文和摘要各自不同；没有正文的扫描件不能假装可以文字引用。
- **问答**：讨论过程，不是第四种静态文档。对话保留在会话历史，知识库提供相关记录入口；已有独立资料问答仍保留可访问入口与原只读分析语义，不在 UI 改版时擅自并库、转换成可执行 Agent 或删除历史记录。

知识与笔记共享 Markdown 阅读、编辑、搜索、来源和导出能力，以用途字段区分；核对状态独立。`KnowledgeNote.state` 是 DRAFT/核对状态，不能拿它兼任类型，更不能把历史未核对记录直接判为“未保存”。Android 接入已更新同一知识库 ADR 并采用加法迁移，保留既有内容与核对状态，不重置数据。

保存状态（修改未保存/已保存）、用途（笔记/知识）、核对状态（未标记/已核对）、处理状态（正文未提取等）互不冒充。核对只在需要事实核验的知识页按需出现。编辑已核对正文应解除核对标记；转为知识不自动标核对。

“整理为知识”创建独立可编辑草案，预览/关闭不保存；用户显式保存才创建知识并保留来源关系。原笔记、资料和问答不被替换或删除。可以手动整理，不强制调用模型。真正模型整理复用现有选择目标、发送范围和取消接口，不伪造后台任务。

## 信息架构

知识库顶部只有知识、笔记、资料三个内容分类，初次默认笔记，后续记住用户当前分类/搜索。写笔记是主要添加动作，直接写知识和导入资料为次级动作。主列表显示标题、正文片段、更新时间与实际来源；笔记不挂“未经审核”的常驻负面标签。

阅读页优先正文，底部保留“基于此内容提问”和编辑；来源按需查看，删除/导出进入更多操作。移动端列表→阅读→编辑逐层返回，宽屏增加导航和来源区域，不把桌面三栏硬塞手机。不加独立的全应用知识底部导航。

问答记录从知识库或会话进入，不为每篇笔记自动生成空会话。普通回答“保存为笔记”；用户之后可整理为知识，不自动升级。

## 对话中选择引用

1. 输入框＋→引用内容，打开搜索/多选面板。默认全部，可切知识/笔记/资料；最多八项与 24000 字符沿现有知识发送边界设计，字符不是 token，最终仍要校验实际模型上下文容量。
2. 面板使用临时选择集合，取消返回原引用和原草稿。确认添加只修改会话草稿，不发送、不开启全库访问，不申请额外权限。
3. 引用条显示标题，可展开看到**当前实际选定**的全文或片段、版本和字符数，移除入口始终可见。长文默认片段必须清楚标明；可以改全文，超限时阻止发送并让用户缩小范围，不静默切掉内容。
4. 笔记/知识关联的原始资料不递归带入。用户需要原件或其他来源时单独选择。资料没有正文时说明原因，不把标题或文件名当完整内容；视觉理解沿用已有显式附件/模型路径。
5. 发送前在已有目标与外发确认机制中呈现模型、目标、引用及范围，不叠加第二套权限审批。本原型用确认页集中演示这项信息。真正接入时可与已有发送 UI 合并，不能只剩一个泛化“允许”按钮。
6. 点击发送后，将不可变引用快照和原请求绑定。引用只是不自动附带到下一条输入，**不表示模型以后忘记**：已发送文字可能随会话历史参与后续上下文，也不能撤回已完成的云端发送。
7. 用户消息里保留引用条；可看当时文字和版本。引用在消息中出现不证明模型确实阅读或输出已验证；原型预置回答始终标注演示，不将假引用当真实生成证据。

从阅读页“基于此内容提问”走同一个草稿引用接口，不立即提交。若已有问题或引用，先保留草稿并去重追加；引用上限明确反馈，不悄悄替换。@ 快捷引用、自动资料推荐和会话常驻引用不在首版。

## 版本、失败及权限

| 状态 | 行为 |
| --- | --- |
| 已选内容更新 | 不改写草稿；提示用户“保留所选版本/更新引用”。完成选择前不发送，范围变化重新校验预算 |
| 已发送内容后来更新或删除 | 消息保留既有合法快照和版本，不改写历史。原件删除不冒充关联快照已删除；访问历史仍按现有权限与生命周期处理 |
| 待发送引用无权限/不可用 | 不靠缓存绕过当前访问判定；阻止发送该项，允许移除/重新选择，原问题保留。已撤权的快照不可被自动复用 |
| 目标模型/Provider 变化 | 复用真实绑定校验，重核可读范围/外发目标，不默默切服务或自动重发 |
| 超限 | 显示实际选择和超限，要求减少内容或明确片段；不把字符上限当模型 token 容量保证 |
| 网络/生成失败或取消 | 保留问题、引用和原调用身份，已发送结果未知不重放；资源恢复与业务后续沿既有机制 |
| Agent 搜索知识 | 与用户手动选引用分开；当前默认关闭的开关与 Dispatcher/Policy/Approval 不变。引用不允许模型越权扩大范围或执行来源中的指令 |

安全/权限仍由应用层的真实资源身份、版本和授权规则判定；UI 不从标题、文字内容或引用标记授予能力。引用内容永远是不可信数据。人格/项目 Memory 与知识库不合库，也不因“整理为知识”就自动进入长期记忆。

## 与当前 Android 的映射及缺口

| 设计 | 当前事实 | 实施边界 |
| --- | --- | --- |
| 阅读/编辑、来源、核对、删除、导出 | KnowledgeScreen、KnowledgeNoteEditor、KnowledgeNoteService、KnowledgeNoteMaintenance 已存在 | 复用能力与服务，做页面交互整合 |
| 笔记与知识独立用途 | KnowledgeNote.kind 已区分 NOTE/KNOWLEDGE，核对状态独立 | 加法迁移保留内容；验收见接入记录 |
| 来源版本/引用快照 | KnowledgeNoteSource、KnowledgeAnswer 与 SessionInput 保存各自固定的引用事实 | 会话走受控快照命令和原准入接口，不直接拿 app-private 路径给 UI |
| 从知识库带入对话 | MainActivity 调用 stageKnowledgeReferences，固定内容进入原会话草稿 | 已替换粘贴式入口；引用条/版本核对通过既有 SessionInput 投递 |
| 选择会话引用 | ChatScreen 的 referenceOpen 和 ConversationReferenceResolver 面向既有会话引用 | 不把会话引用身份误当知识来源，UI 可整合选择器，底层保持准确资源类型 |
| 旧资料问答 | KnowledgeAnswer 保存历史正文/冻结证据，KnowledgeAnswerHistory 只读及显式保存 | 新提问统一走现有会话与结构化引用；删除独立生成服务，保留历史数据 |

应用契约：草稿引用用资源类型/稳定 ID/内容版本/选定范围/不可变文字/完整性，显示名称与真实身份分开；读取和发送重验由知识/权限服务完成，UI 只调用查询与命令。应用提交将所选快照绑定原输入和 Turn；不改 Agent 核心循环、工具协议或创造第二个消息事实来源。实际字段和验收见接入记录，本原型自身不承诺后台交付。

## 原型验收

交互：创建/编辑/放弃笔记，整理草案取消及独立保存，分类搜索，取消引用保留草稿，多选/预览/范围/预算，版本保留/刷新，不可用阻止，显式演示发送，历史快照与保存为笔记，删除确认及 HTML 转义。

视觉：窄屏、较大字体、宽屏暗色与版本面板，检查横向溢出、可达性与触控区域。原型的单文件脚本没有文件/网络/账号/模型访问，内容只在内存；浏览器检查不冒充 Android/设备/真实模型通过。结果见 README。

## 与当前会话界面融合

以实际 Compose 为准，不把原型对话改成第二个聊天产品：

| 当前组件 | 原型采用的结构 | 仅新增部分 |
| --- | --- | --- |
| AdaptiveConversationHeader | 导航、会话名、搜索、新建、更多 | 无知识库专用标题栏 |
| ComposerToolbar / ComposerPermissionMenu | 输入框上方共享紧凑行：模式、权限、状态/上下文、更多 | 引用不切换权限 |
| ConversationComposer | 正文输入和下方＋、模型、语音、发送 | 正文上方可预览/移除的知识引用条 |
| ComposerAddSheet | 原附件/会话引用和配置入口 | 独立“引用知识库”，不覆盖已有“引用会话” |
| ConversationMessage / Timeline | 用户消息、助手回答和原操作规则 | 历史消息的知识快照引用与保存为笔记 |

模型、语音、权限、上下文、消息操作继续调用各自已有接口；原型不伪装已经重新实现这些能力。当前模型/权限放置来自源码，不沿用前版原型的自创底栏。接入时只扩充草稿引用状态与选择器，并复用原发送命令；不能为视觉统一改变审批、模型协议、流式输出或取消语义。
