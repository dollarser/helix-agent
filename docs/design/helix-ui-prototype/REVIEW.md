# 真实功能、历史意图与竞品启发复审

本轮不是把旧界面完整抄进 HTML。先区分真实业务边界、历史产品意图和可重新设计的呈现，再直接优化原型。应用源码与 ADR 未修改；新提案不能代表接受了新的后端/平台能力。

## 依据与判断

| 输入 | 发现 | 采用的设计判断 |
| --- | --- | --- |
| 当前 GroupedNavigation / DrawerSettingsNavigation / DrawerEntry | 会话优先；设置含六类权威入口；子页需要关联主入口 | 抽屉设置打开分类面板；子页高亮所属模块，避免“进入详情后迷路” |
| SettingsScreen / AdvancedProfileAvailability | 安装构建与安全 profile 不是同一个概念 | 构建选择移到画布外；Standard 不显示终端入口，不允许设置变成 Advanced；Advanced 构建仍须明确确认 profile |
| ProjectDetailScreen / ProjectEditor / ProjectSessions / SessionProjectSection；ADR-WORKSPACE-005 | 项目并非只有名称和目录：会话、文件、任务、成果、指令、显式记忆、归档与迁移边界都存在 | 项目工作台分区；归档不停止任务；成员迁移与删除重验忙碌，目录/权限不随组织变更移动；删除仅元数据 |
| SessionPermissionSection / ADR-PERMISSIONS-002 | 新会话默认与当前会话预设分开；Act 默认、模式命令显式提交 | 新会话清除旧专家/扩展选择，读取新会话权限默认；项目新会话用主目录，但不继承原权限 |
| 当前 ExtensionsScreen / ConnectorSection；ADR-CONNECTORS-003 §7 | “已添加 / 发现”统一 Plugin 领域；MCP 属高级接入；不存在插件用户全局启停开关 | 删除原型的全局插件开关；添加入口汇总导入/创作/MCP；卡片按配置/提示与工具/详情组织 |
| 同一 Connector ADR 的所有权与更新条款 | 内置代码随 APK 更新，独立技能归属需保留；更新不应额外重复批准工具 | 内置不显示独立卸载；外部卸载保留独立技能；作者更新说明后直接更新，不把更新当工具许可 |
| ADR-GOAL-001 / 当前 GoalDialog | Goal 与 Run 分开，已有运行不能制造重复继续 | 运行中“继续”解释已有运行，不创建新 attempt；未知效果保留核对路径 |
| KnowledgeScreen / KnowledgeQuestionScreen / ADR-WORKSPACE-007 | 有界来源选择与冻结引用是可信度入口，来源不是已经核对的知识 | 问答先展示确切来源与处理模型；无来源禁止生成；返回选源保留问题；只显示实际冻结的引用，避免虚构第二条 |

历史 Git 只用于理解取舍，不恢复旧行为：`7a9355bb`（模型/导航/权限简化）、`cc6d1f3e`（扩展与工作分组）、`73be3752`（项目/文件/设备范围）。当前源文件及最新 ADR 优先于历史布局；accepted 设计不自动证明整项已实施。

## 竞品参考与不照搬的取舍

查阅于 2026-10-21，仅参考官方产品说明，没有下载或复制代码/样式。它们解释工作流，不作为像素级界面截图证据。

| 官方来源 | 可借鉴点 | 对 Helix 的适配 |
| --- | --- | --- |
| [ChatGPT Projects](https://help.openai.com/en/articles/10169521-projects-in-chatgpt) | 同一项目聚合会话、资料与指令，便于持续工作 | 采用项目工作台分区和上下文归属；目录仍是本机真实资源，组织变更不搬文件、不复制授权。没有加入云同步、共享成员或跨设备服务 |
| [Claude Artifacts](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them) | 可持续编辑/使用的成果与会话相邻，减少离开对话寻找输出 | 新增聊天“成果”侧览：宽屏并排，手机临时底部阅读区，保留草稿和当前模型。只演示已有成果预览，不增加云端发布或协作编辑引擎 |
| [Notebook 来源选择](https://support.google.com/gemininotebook/answer/16215270?hl=en) | 用户明确选择本次资料集合，而不是模糊全库提问 | 知识问答展示所选来源 chips、模型去向与引用核对；无来源不生成。继续采用 Helix 原件/笔记/冻结引用的本地数据语义，不引入自动同步或额外搜索服务 |

以上竞品做法只是设计依据。我判断值得采用的是“项目上下文清楚”“成果靠近对话”“引用范围可见”，而不是它们的订阅结构、团队功能、品牌外观或全部导航项。

## 相较第二版直接改变的交互

1. 构建渠道与 profile 分离；渠道/问题样例控制留在评审目录，产品页不出现评审开关。
2. 抽屉设置先选分类；主导航保留子页选中关系。
3. 项目增加完整工作台、指令/独立记忆、归档恢复、成员迁移及删除保护。
4. 新会话从默认权限开始，清除旧会话专家/技能/连接器选择；已有草稿保存在历史模拟记录。
5. 插件改为已添加/发现/添加流程，移除全局启停；内置与外部维护方式分开。
6. 聊天内成果侧览保留当前草稿/模型/会话；手机与宽屏使用不同阅读布局。这是本轮新的视觉交互提案，尚未移植 Compose。
7. 知识问答精确显示本次所选范围，不再用“默认两条来源”掩盖未选择，也不产生不存在的引用。
8. 运行中 Goal 不重复“继续”，更新/卸载不假装取得工具授权，场景复位同步评审选择器。

## 验证与后续判断

新增 15 项有意义的状态/交互检查，共 76 项；多文件与单文件入口分别运行同组断言。覆盖目录/草稿保留、项目隔离与忙碌保护、渠道门控、插件所有权/更新、侧览与精确来源引用。

仍没有浏览器截图、真实 CSS 计算布局或 Android 视觉对照。没有更换浏览器、启动转发或绕过既有限制。侧览宽度、手机遮挡、长标题/键盘、字体与圆角的实际观感需在允许环境继续视觉验证。下一步 Compose 实施应先落导航/共同 tokens/会话与成果阅读，再迁项目和插件结构；业务状态仍由现有领域服务提供。

## 手机与宽屏分别设计

| 区域 | 手机 | 宽屏 |
| --- | --- | --- |
| 主导航 | 遮罩抽屉，不常驻占宽；关闭回到原内容 | 常驻侧栏，子页保留主模块选中 |
| 成果阅读 | 底部模态阅读区，遮罩关闭，背景 inert，Tab/Esc/关闭返回；不同时误触发送 | 与聊天并排；正文和 composer 继续可编辑；独立滚动 |
| 长表单 | 单列，16px 输入文字，底部确认区贴住面板底部且可换行 | 限制表单宽度，面板居中，避免字段无限拉长 |
| 项目分区 | 可横向滚动标签，单区阅读，不缩小文字硬塞五列 | 标签保持横向，正文可利用更宽空间 |
| 输入与操作 | 44px 触控下限；模型名称可截断，图标和发送入口保留 | 同一任务语义，使用更多正文宽度，不放大所有控件 |

这里的“宽屏”是 Android 大屏/浏览器评审画布，不代表新增桌面客户端。手机侧览模态语义、遮罩和 inert / 返回已做 DOM 检查；真实触控命中、软键盘、刘海/安全区、横屏及截图仍待允许环境验收。

中等宽度（761–1050px）采用可唤出的抽屉，保留 280px 成果侧栏，让聊天获得剩余宽度；不沿用常驻导航再叠一个悬浮侧栏。≤760px 使用手机模态成果阅读；>1050px 同时显示导航、聊天与成果。CSS 使用 safe-area inset 补充底部留白；真实软键盘仍需要浏览器/Android 验收。
